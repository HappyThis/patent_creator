# 技术方案需求

当前项目希望增强 ByteRover context tree 的团队协作和长期维护能力。

用户希望把项目知识作为可共享、可版本控制的上下文资产来维护，但在日常使用中，系统又会不断产生一些与本机运行、检索命中、知识使用频率、排序权重或成熟度判断有关的动态信息。用户不希望这些频繁变化的运行时信息反复改写共享的 Markdown 知识文件，导致版本控制状态变脏、团队合并冲突增多，或者让真正的知识内容变化被噪声淹没。

同时，用户也不希望简单丢弃这些动态信息，因为它们对知识检索、排序、清理和自动整理仍然有价值。

请生成一个可用于专利交底书的软件技术方案草稿。方案应说明系统如何在保持知识文件可共享、可审阅的同时，继续利用运行时产生的动态信号，以及相比现有方式能带来什么技术效果。

## 补充约束

方案不能只是删除动态信号，或把全部知识内容迁移到一个不可审阅的数据库。请说明哪些字段适合继续留在共享 Markdown 中，哪些运行时信号应迁出；同时覆盖读取融合、迁移期兼容、并发更新、失败隔离、归档/剪枝/合并时的清理一致性。
