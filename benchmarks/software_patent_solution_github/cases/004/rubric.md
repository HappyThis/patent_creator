# 评分标准

总分 100 分。

## 环境阅读与需求理解：15 分

- 13-15 分：能结合需求并在当前项目环境中识别 Markdown writer、knowledge search、memory scoring、curate、context tree、dream/prune/synthesize 等相关上下文。
- 8-12 分：能识别 frontmatter 频繁变化造成脏 diff，也能阅读部分项目路径，但对动态信号仍需参与检索和整理的分析不足。
- 0-7 分：未有效阅读当前项目环境，只泛泛描述“把元数据放到别处”。

## 技术问题识别：15 分

- 13-15 分：准确指出问题本质是共享语义内容与本机高频运行时信号混写，导致 VC 噪声、协作冲突和动态排序需求之间的矛盾。
- 8-12 分：能指出 frontmatter 频繁变化造成脏 diff，但对检索排序和自动整理的信号需求分析不足。
- 0-7 分：把问题理解为普通缓存、普通日志或 Markdown 格式整理。

## 技术手段具体性：20 分

- 17-20 分：提出字段分层、旁路运行时信号存储（sidecar 或等价形态）、路径键映射、原子更新、批量读取、读取融合、写入剥离、双写迁移、失败隔离和清理一致性等具体机制。
- 10-16 分：提出 sidecar 或等价外部元数据存储，但缺少读取融合、生命周期挂接、失败隔离或迁移路径。
- 0-9 分：只说“不要写入 frontmatter”或“用数据库保存”，缺少完整机制。

## 必要技术特征完整性：10 分

- 8-10 分：覆盖写入、查询、排序、curate、dream、归档/删除、迁移、错误处理和并发更新。
- 4-7 分：覆盖主要读写路径，但缺少清理、迁移或失败处理。
- 0-3 分：只覆盖单个写入器或单个查询接口。

## 问题-手段-效果闭环：15 分

- 13-15 分：能说明各技术手段如何减少 VC 噪声、保留动态排序能力、降低合并冲突并保持知识操作稳定。
- 8-12 分：有基本闭环，但效果主要停留在“文件更干净”。
- 0-7 分：缺少因果关系或技术效果空泛。

## 需求约束遵守：10 分

- 8-10 分：保持 Markdown 作为共享知识载体；不丢弃动态信号；不破坏检索排序；sidecar 失败 fail-open；兼容迁移期。
- 4-7 分：基本满足，但可能丢失部分排序信号或引入协作不一致风险。
- 0-3 分：要求完全放弃 Markdown、完全丢弃运行时信号，或把全部内容迁入私有数据库。

## 可实施性：10 分

- 8-10 分：给出清晰的数据字段、存储接口、读写流程、更新原子性和迁移/清理策略。
- 4-7 分：总体可行，但缺少关键接口、更新时机或失败处理。
- 0-3 分：方案过于抽象，无法指导工程实现。

## 专利化价值：5 分

- 4-5 分：能抽象为“共享知识文件与本机运行时信号分层存储及读取融合机制”。
- 2-3 分：有一定机制抽象，但偏普通元数据拆分。
- 0-1 分：只是文件格式整理或配置调整。

## 明确扣分项

- 直接删除 accessCount、importance、maturity 等动态信号。
- 把所有知识内容迁入私有数据库，破坏 context tree 的可共享性。
- 只改 Markdown writer，不处理查询排序、curate、dream 或归档删除路径。
- sidecar 写入失败阻断用户保存知识。
- 没有路径映射、批量读取或原子更新机制。
- 没有考虑迁移期和旧 frontmatter 数据的兼容。

## 源码级评分补充

- `sidecar` 是参考实现方向，不限定具体存储形态。使用本机 SQLite、JSON/KV、轻量数据库或等价旁路运行时信号存储，只要满足路径键映射、读取融合、原子更新和 fail-open，应按等价机制给分。
- 高分方案必须基于源码中 frontmatter 动态字段被搜索、评分、curate、dream、archive/prune 等路径消费这一事实，覆盖全链路读取融合和迁移。
- 只说“把动态字段放数据库”但没有说明并发 RMW、批量读取、字段分层、失败隔离和归档/删除清理的方案应显著扣分。

## 档位锚点

- 90-100 分强答案：必须同时具备共享 Markdown 与本机运行时信号字段分层、旁路 store 最小接口、路径键映射、批量读取、读取融合接入 search/scoring/curate/dream/archive/prune、并发 RMW/CAS 或单写队列、写入剥离、迁移双写/回填/切换/回滚、fail-open、归档删除重命名清理和孤儿记录修复。
- 75-85 分可用但不完整：方向正确，能把动态信号移到旁路存储并保留读取融合，但 store 接口、并发更新、迁移切换、清理一致性或 failure handling 中缺一到两个关键工程边界。
- 60-74 分弱答案：只是把 frontmatter 字段放数据库或减少写入，缺全链路读取融合、并发保护或迁移兼容，可能影响排序/整理信号。
- 0-59 分不合格：删除动态信号、把共享知识全迁入私有数据库、破坏 Markdown 可共享性，或只做文件格式整理。

## 分数上限规则

- 如果方案没有给出旁路运行时信号存储的最小接口边界，例如按路径键批量读取、原子更新、删除/归档清理和列表/扫描能力，总分通常不得高于 82 分。
- 如果方案没有说明读取融合如何接入搜索、评分、curate、dream、archive/prune 等源码消费路径，总分通常不得高于 80 分。
- 如果方案没有并发 read-modify-write、版本/CAS 或等价原子更新机制，总分通常不得高于 82 分。
- 如果方案没有迁移期双写、旧 frontmatter 回填、切换条件和回滚/失败隔离，总分通常不得高于 82 分。
- 如果同时缺失存储接口、读取融合、并发更新、迁移清理中任意两个关键机制，总分不得高于 78 分；缺失三个或更多时，总分不得高于 72 分。
- 如果方案把所有动态字段简单移出而导致搜索排序、整理或归档路径失去信号，总分不得高于 70 分。
