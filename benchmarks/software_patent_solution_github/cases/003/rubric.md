# 评分标准

总分 100 分。

## 环境阅读与需求理解：15 分

- 13-15 分：能结合需求并在当前项目环境中识别任务 API、任务看板、配置、Git 同步相关模块和外部 agent 协作格式之间的关系。
- 8-12 分：能识别任务同步目标，也能阅读部分项目路径，但对主存储保持、语义映射或故障隔离分析不足。
- 0-7 分：未有效阅读当前项目环境，只泛泛描述“导出任务到文件”。

## 技术问题识别：15 分

- 13-15 分：准确指出问题本质是应用主数据库与外部 Git-native agent 协作格式之间的持续同步、语义映射和故障隔离。
- 8-12 分：能指出需要任务同步，但没有充分分析主存储保持、生命周期挂接或语义偏差。
- 0-7 分：把问题理解为一次性导出、备份或普通文件保存。

## 技术手段具体性：20 分

- 17-20 分：提出主存储优先、外部格式转换、状态/优先级映射、任务生命周期挂接、Git-native 持久化、非阻塞失败处理、配置开关、管理 API 和 UI 状态提示等具体机制。
- 10-16 分：提出同步引擎和文件写入，但缺少语义映射、非阻塞处理、管理入口或生命周期完整性。
- 0-9 分：只说“同步到 Git”或“保存 JSON”，缺少可实施机制。

## 必要技术特征完整性：10 分

- 8-10 分：覆盖创建、更新、删除、初始化、状态查询、手动同步、配置、语义映射和错误处理。
- 4-7 分：覆盖主要同步路径，但缺少删除、管理、配置或错误隔离。
- 0-3 分：只覆盖单个导出接口。

## 问题-手段-效果闭环：15 分

- 13-15 分：能说明各技术手段如何解决任务外部可读、跨工具协作、语义一致、可追踪和主流程稳定问题。
- 8-12 分：有基本闭环，但效果主要停留在“方便共享任务”。
- 0-7 分：缺少因果关系或技术效果空泛。

## 需求约束遵守：10 分

- 8-10 分：保持 Mission Control 数据库为主；不阻断现有任务 API；不破坏任务看板；复用现有配置和同步思路。
- 4-7 分：基本兼容现有系统，但存在外部仓库故障影响主流程或状态语义不清的问题。
- 0-3 分：要求把任务主存储改为 Git，或要求用户手动维护两套任务。

## 可实施性：10 分

- 8-10 分：给出清晰的数据转换、路径挂接、配置、Git 操作、管理接口和失败处理。
- 4-7 分：总体可行，但缺少关键字段映射、同步触发点或故障处理。
- 0-3 分：方案过于抽象，无法指导实现。

## 专利化价值：5 分

- 4-5 分：能抽象为“面向 agent 任务的主存储保持型 Git-native 协作镜像同步机制”。
- 2-3 分：有一定机制抽象，但偏普通导出或备份。
- 0-1 分：只是文件保存说明。

## 明确扣分项

- 把 Git 仓库作为唯一任务主存储，破坏现有数据库和看板。
- 只做手动导出，不覆盖任务生命周期变化。
- 没有状态/优先级等语义映射。
- 同步失败会阻断任务创建、更新或删除。
- 要求用户手工维护外部任务文件。
- 缺少初始化、状态查询或手动同步入口。

## 源码级评分补充

- 本 case 评价的是仓库内机器可读任务镜像或等价 Git 托管协作载体，不是 GitHub issue/label/PR 双向同步本身。
- 方案可以引用现有 GitHub sync 作为工程参考，但若把 GitHub issue API 同步当成完整答案，最多按部分得分处理。
- 高分方案必须给出任务文件 schema、目录布局、稳定 task id 到文件路径映射、Git add/commit/push/pull、失败隔离、删除同步和管理入口。若进一步说明冲突保护、待重试状态或人工介入流程，可作为加分依据。

## 档位锚点

- 90-100 分强答案：必须同时具备主数据库为事实来源、稳定文件 schema/路径映射、创建/更新/删除全生命周期挂接、初始化/status/manual sync 管理入口、状态/优先级语义映射和未知值处理、非阻塞 Git pull/add/commit/push、同步失败不影响任务 CRUD、任务看板/管理 UI 可见状态，以及源码级 API/config/UI 接入说明。若额外覆盖批量状态同步、非破坏性冲突处理、待重试队列、tombstone 或删除前快照，可在强答案档内进一步加分。
- 75-85 分可用但不完整：方向正确，能生成 Git-native 镜像并保持数据库为主，但缺初始化管理、状态映射、失败隔离、删除同步或 UI 状态反馈中的一到两个关键工程边界。
- 60-74 分弱答案：主要是导出/同步文件，缺稳定 schema 或生命周期挂接，冲突和失败处理粗糙，或者把已有 GitHub issue sync 当作主要机制。
- 0-59 分不合格：把 Git 仓库改成任务主存储、要求用户手动维护外部文件、同步失败阻断任务 API，或没有机器可读任务镜像机制。

## 分数上限规则

- 如果方案没有明确的镜像仓库初始化流程、状态查询和手动同步/重试管理入口，总分通常不得高于 84 分。
- 如果方案没有任务看板或管理 UI 中的同步状态、任务数量、最近同步时间或等价可见反馈，总分通常不得高于 86 分。
- 如果方案没有 Mission Control 状态/优先级与外部协作格式之间的显式映射和未知值处理，总分通常不得高于 84 分。
- 如果方案没有说明 Git 操作失败如何记录并与主任务 CRUD 隔离，总分通常不得高于 84 分。
- 如果方案完全没有删除同步或删除标记机制，总分通常不得高于 82 分。
- 如果同时缺失初始化管理、语义映射、失败隔离、删除同步中任意两个关键机制，总分不得高于 80 分；缺失三个或更多时，总分不得高于 74 分。
