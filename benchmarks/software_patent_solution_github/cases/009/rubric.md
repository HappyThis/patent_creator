# 评分 Rubric

总分 100 分。

## 1. 环境阅读与场景理解（15 分）

- 结合当前项目环境识别 workspace read 从纯文本扩展到多模态文件的需求：5 分
- 结合现有 workspace 工具和模型输出边界，识别图片/PDF 应尽量进入模型，而普通二进制需要降级描述：4 分
- 识别大文件、token 成本和模型上下文限制：3 分
- 识别多种 workspace 后端兼容需求：3 分

## 2. 文件类型识别机制（20 分）

- 使用文件状态或元数据获取基础信息：4 分
- 在元数据不足时读取字节进行内容嗅探：5 分
- 覆盖图片、PDF、文本、普通二进制等类别：5 分
- 说明文本判断和泛化 MIME 的处理：3 分
- 返回媒体类型、文件名、大小等结构化信息：3 分

## 3. 文本读取策略（10 分）

- 支持 offset/limit 或等价分页读取：3 分
- 支持行号化输出：3 分
- 支持长行和超多行截断：2 分
- 保留总行数和读取范围等元信息：2 分

## 4. 多模态模型输出转换（20 分）

- 设计普通工具结果到模型可消费内容的转换层：5 分
- 图片转换为模型图片内容块或等价结构：5 分
- PDF/文件转换为模型文件内容块或等价结构：4 分
- 在输出中附加文本说明，便于模型理解来源：3 分
- 处理字节读取失败或转换失败：3 分

## 5. 限制与降级（15 分）

- 设置最大可传入模型的文件大小：4 分
- 超限时返回清晰错误而不是截断二进制：3 分
- 对不支持二进制返回结构化 JSON/描述：3 分
- 区分目录、不存在、不可读等错误：3 分
- 避免无控制地 base64 填充上下文：2 分

## 6. 后端抽象与工程落地（10 分）

- 抽象 read/stat/read bytes 等最小操作接口：4 分
- 支持真实 workspace、共享 workspace、自定义后端：3 分
- 与现有 workspace 工具集保持兼容：3 分

## 7. 专利技术方案表达质量（10 分）

- 技术问题、技术手段、技术效果闭环清晰：4 分
- 方案体现类型识别、输出转换、限制降级的组合机制：3 分
- 避免只写“支持上传图片/PDF”的产品描述：3 分

## 扣分项

- 只按文件扩展名判断类型：最多扣 10 分
- 未设计模型输出转换，只返回路径：最多扣 18 分
- 将二进制文件一律作为文本读取：最多扣 15 分
- 未考虑大小限制：最多扣 12 分
- 未考虑多 workspace 后端：最多扣 8 分

## 源码级评分补充

- `readFileBytes` 是当前 shell workspace 中已有能力名，但评分接受任何等价字节读取接口；关键是 Think workspace 工具层的后端抽象必须能获取字节、stat/mime/size，并兼容自定义或共享 workspace。
- 高分方案必须说明普通 read tool result 与模型输出转换层的分层关系，例如 text/image/file/binary/error 普通结果如何转换为 model text、image-data、file-data 或结构化错误。
- 只说“读取 base64 传给多模态模型”，但没有 `WorkspaceLike/ReadOperations` 兼容升级、MIME/魔数探测、大小限制和错误分类的方案应显著扣分。

## 档位锚点

- 90-100 分强答案：必须同时具备 stat/mime/size 基础信息、字节读取抽象、MIME/扩展名/魔数/文本嗅探、文本分页和行号保持、图片/PDF/文件转模型内容块、普通工具结果到模型输出转换层、多模态来源说明、大小限制、转换失败降级、目录/缺失/不可读/二进制结构化错误、多 workspace 后端兼容和避免无控制 base64。
- 75-85 分可用但不完整：能分流文本/图片/PDF/二进制，保留文本体验和大小限制，但模型输出转换层、泛化文本嗅探、多模态来源说明或 provider/file-part 降级中缺一到两个关键边界。
- 60-74 分弱答案：只是在 read tool 中返回 base64/dataUri 或按扩展名分类，缺模型输出边界、文本嗅探或错误降级，模型未必真正看到多模态内容。
- 0-59 分不合格：把二进制当文本、只返回路径、无大小限制、无后端抽象，或破坏现有文本 read 行号/分页体验。

## 分数上限规则

- 如果方案没有明确普通工具执行结果到模型可消费 text/image-data/file-data 或等价内容块的转换层，总分通常不得高于 80 分。
- 如果方案只是把 base64、dataUri 或 modelContent 放进普通 JSON 返回对象，而没有说明 AI SDK/模型输出边界如何消费，总分通常不得高于 78 分。
- 如果方案没有泛化 MIME 或缺失 MIME 下的文本嗅探机制，例如空字节、UTF-8 解码质量、replacement ratio 或等价判断，总分通常不得高于 84 分。
- 如果多模态输出没有附加来源、媒体类型、大小等简短文本说明，总分通常不得高于 86 分。
- 如果 PDF/文件内容块依赖模型能力但没有降级路径、大小限制和转换失败处理，总分通常不得高于 82 分。
- 如果同时缺失模型输出转换层、泛化文本嗅探、多模态来源说明、转换失败降级中任意两个关键机制，总分不得高于 78 分；缺失三个或更多时，总分不得高于 72 分。
