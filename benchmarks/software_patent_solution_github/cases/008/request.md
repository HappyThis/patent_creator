# 技术方案需求

当前项目中有一个 experimental codemode 能力：LLM 可以不再逐个调用工具，而是生成一段代码，由系统在隔离环境中执行这段代码，并在代码中调用应用提供的工具。现有能力更偏向服务端或 Worker 侧执行。

现在希望支持另一类场景：有些工具只存在于浏览器页面中，例如读取当前页面选择内容、访问页面状态、调用前端组件暴露的能力、组合浏览器中的动态客户端工具等。开发者希望仍然能让 LLM 生成代码来编排这些工具，但不希望把浏览器私有能力全部搬到服务端，也不希望让生成代码直接污染主页面环境。

期望能力包括：

- 在浏览器侧执行 LLM 生成的编排代码，使其可以调用浏览器页面提供的动态工具。
- 执行环境应与主页面隔离，避免生成代码直接访问或修改主页面对象。
- 工具调用需要在隔离执行环境与主页面之间安全传递，主页面负责真正执行已注册工具。
- 支持根据当前可用工具生成适合 LLM 使用的工具描述和输入输出结构。
- 每次执行应有明确生命周期，包括准备、执行、返回结果、返回错误、超时和清理。
- 方案应尽量减少额外依赖，并能与现有 codemode / agent chat / client tool 体系协作。
- 需要考虑工具名规范化、非法工具调用、异常传播、日志收集、执行后资源释放等问题。

请基于上述场景，为该项目设计一份软件专利技术方案草稿，重点说明浏览器侧隔离执行、工具调度协议、安全控制和结果回传机制。

## 补充约束

方案不能只停留在“用 iframe 执行代码并 postMessage”。请说明动态工具的命名空间/来源标识、工具名规范化和冲突处理、输入输出 schema、隔离环境 ready/error/timeout/cleanup 生命周期、主页面实际执行工具的代理边界，以及生成代码不能直接访问或污染主页面对象的安全控制。
