# 技术方案需求

当前项目提供了 Durable Object 风格的 agent、chat agent、Think agent、workspace、MCP 工具连接、子 agent 路由等能力。现在希望构建一个更接近真实使用的多会话 assistant。

目标用户不是只和一个单一聊天窗口交互，而是可以在同一个账号下创建多个聊天会话。每个会话应保持自己的消息历史、分支、个性化配置、扩展和记忆等上下文；但用户也希望不同会话之间共享一些长期资源，例如项目文件、外部 MCP 工具连接、OAuth 授权结果，以及文件变化带来的前端刷新信号。

期望能力包括：

- 一个用户可以拥有多个聊天会话，并在侧边栏中创建、切换、重命名和删除。
- 每个聊天会话是独立的 agent 执行上下文，不应把消息历史和会话配置混在一起。
- workspace 文件应按用户维度共享，不同会话都能看到和修改同一批文件。
- MCP 服务器连接和 OAuth 授权应按用户维度共享，用户授权一次后多个会话都能使用相同工具。
- 共享资源的真实状态应由一个统一位置管理，子会话通过受控方式访问。
- 文件变化需要能通知多个打开的浏览器标签页或会话面板，减少轮询。
- 系统应防止用户通过猜测会话 id 访问或创建未登记的子会话。
- 定时任务、跨会话摘要等全局任务应由合适的上层实体负责，而不是散落在每个子会话中。
- 方案应尽量复用现有 agent、workspace、MCP、chat recovery 和工具调用体系。

请基于上述场景，为该项目设计一份软件专利技术方案草稿，重点说明父子 agent 结构、会话隔离、共享资源代理、访问控制、实时同步和定时任务调度机制。
