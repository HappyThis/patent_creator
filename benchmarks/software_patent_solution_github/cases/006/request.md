# 技术方案需求

当前项目希望改进 `useAgentChat` 在长时间 agent 对话和浏览器连接变化场景下的控制体验。

用户希望在浏览器刷新、组件卸载、页面切换或网络短暂断开时，正在服务端执行的 agent 对话不要被轻易中断，因为这类对话可能已经在 Durable Object 中持续运行并支持后续恢复。另一方面，用户也需要一个明确的“停止”能力：当用户真的想取消本次 agent 回答时，系统应能把取消意图传达到服务端，而不是只关闭本地显示流。

该能力应兼容现有的流式响应、断线重连、工具调用继续执行和多标签页场景。不同应用可能对“客户端断开是否代表取消服务端任务”有不同偏好，因此系统也应给开发者留下可配置空间。

请生成一个可用于专利交底书的软件技术方案草稿。方案应说明系统如何区分客户端本地清理与服务端 agent turn 取消，以及相比现有方式能带来什么技术效果。

## 补充约束

请明确区分浏览器刷新、组件卸载、reader cancel、网络断开等本地生命周期清理，与用户点击“停止”或应用主动取消服务端 turn 的语义。方案应覆盖默认 durable 模式和可选 request-lifetime 模式，并说明它如何与恢复、工具 continuation、多标签页观察和迟到服务端消息处理兼容。
