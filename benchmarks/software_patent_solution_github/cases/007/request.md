# 技术方案需求

当前项目提供了基于 Durable Object 的 agent 框架，已经支持 chat agent、Think agent、子 agent 路由、WebSocket 流式输出、重连恢复等能力。

现在希望进一步支持一种更复杂的 agent 协作场景：用户仍然只和一个主 agent 对话，但主 agent 在处理一次请求时，可以按需调用一个或多个专门的子 agent 来完成研究、规划、比较、总结等任务。用户界面需要能看到这些子 agent 的执行过程和结果，而不是只能看到主 agent 最后的文本。

期望能力包括：

- 主 agent 可以把子 agent 作为一种可调用能力来使用，既适合模型自动决定调用，也适合服务端确定性流程主动调用。
- 子 agent 应保持独立执行上下文，适合长任务、并行任务和后续查看。
- 子 agent 的执行进度、输出片段、完成、失败、取消等状态，应能回到主 agent 所在的同一会话视图中。
- 用户刷新页面或网络短暂断开后，仍能恢复看到已经发生的子 agent 执行过程。
- 多个子 agent 可属于同一次主 agent 工具调用，也可能是没有父工具调用的后台执行。
- 系统需要考虑重复请求、并发执行、访问控制、清理保留结果、取消正在运行任务等问题。
- 方案应兼容现有 chat/Think agent 体系，尽量不要要求应用开发者重写整个 agent 框架。

请基于上述场景，为该项目设计一份软件专利技术方案草稿，重点说明系统组件、数据流、状态管理、恢复机制和异常处理。
