# 评分 Rubric

总分 100 分。

## 1. 环境阅读、场景理解与问题抽象（15 分）

- 结合当前项目环境识别主 agent 与子 agent 是同一会话中的协作关系，而不是普通页面跳转或独立聊天：5 分
- 结合项目中的流式、恢复和工具调用上下文，识别核心问题是子 agent 执行过程需要可观察、可恢复、可保留：5 分
- 能说明长任务、并行任务、刷新重连、取消清理等约束之间的张力：5 分

## 2. 系统组件完整性（20 分）

- 设计父侧调用/工具包装层：4 分
- 设计子运行持久注册表或等价状态索引：5 分
- 设计独立子 agent 执行上下文：4 分
- 设计父连接事件转发或复用通道：4 分
- 设计客户端聚合渲染层：3 分

## 3. 数据流与状态机（20 分）

- 覆盖启动、运行、输出、完成、失败、取消、中断等状态：6 分
- 描述父工具调用与多个子运行之间的关联关系：4 分
- 说明流式事件如何带回主会话视图：4 分
- 说明最终结果如何返回父 agent 或父模型：3 分
- 说明并行子运行如何隔离和排序：3 分

## 4. 恢复、幂等与一致性（15 分）

- 支持刷新或断线后的历史恢复：4 分
- 支持实时事件与重放事件去重：3 分
- 使用运行 id 或等价机制防止重复启动：3 分
- 能处理父侧转发中断、子侧失败等异常：3 分
- 清楚区分保留结果与清理删除：2 分

## 5. 访问控制与安全边界（10 分）

- 通过父侧归属关系校验子 agent 访问权限：4 分
- 避免猜测子 agent 地址造成越权或误创建：3 分
- 说明不同用户、会话、子运行之间的隔离：3 分

## 6. 兼容性与工程可落地性（10 分）

- 兼容现有 chat/Think agent 架构：3 分
- 不要求应用重写全部 agent 框架：2 分
- 能说明服务端工具与客户端工具的边界：2 分
- 方案中的数据结构、接口、事件协议具备可实现性：3 分

## 7. 专利技术方案表达质量（10 分）

- 技术问题、技术手段、技术效果闭环清晰：4 分
- 方案具有一定机制组合和架构创新性：3 分
- 避免只写产品功能或 UI 描述：3 分

## 扣分项

- 将子 agent 简化为普通函数调用，未考虑独立执行上下文：最多扣 20 分
- 未设计恢复或重放机制：最多扣 15 分
- 未设计父侧运行记录或等价索引：最多扣 15 分
- 未考虑取消、失败、清理：最多扣 12 分
- 将多个子运行混入父消息而无身份隔离：最多扣 10 分
- 过度复述源码 API 名称但缺少技术原理：最多扣 8 分
