# 2026-05-17 工作进度与后续计划

本文档记录今天围绕 `software_patent_solution_github` benchmark 做过的改动、已经得到的结论、无效结果，以及下一步继续工作的入口。

## 今日目标

本轮工作的核心不是挑高分 case，而是确认这个 benchmark 是否能可靠地区分 agent 能力。

判断标准包括：

- case 是否要求源码级理解，而不是只靠泛泛方案也能拿高分。
- judge 是否按照源码机制、缺陷和风险评分，而不是按参考答案相似度评分。
- case 是否能稳定跑出 subject artifact。
- 分数是否能暴露当前 agent 的真实缺陷。如果当前 agent 明显有缺陷但仍普遍高分，benchmark 就不合格。

## 已完成工作

### 1. case 源码级加固

已对 `cases/001` 到 `cases/010` 做过源码级复核和加固。

主要变化：

- 每个 `request.md` 增加了补充约束，要求 answer 贴合实际源码结构。
- 每个 `rubric.md` 增加了源码级评分补充和档位锚点。
- 每个 `reference_solution.md` 增加了等价机制说明，避免 judge 把参考答案当作唯一正确答案。
- `cases/002/metadata.json` 和 `cases/004/metadata.json` 做了去硬编码化调整，降低对固定命名的依赖。

### 2. judge 校准

已更新 `judge.md`，明确：

- 先按档位锚点判断整体能力层级，再给维度分。
- 90+、75-85、70 以下分别对应不同质量门槛。
- 不能因为答案接近参考答案就直接高分，也不能因为实现路径不同就直接低分。

同时更新了 `evaluator/codex_judge.py`，让 Codex judge 在 prompt 中显式遵循：

- `judge.md` 的分数校准规则。
- case 自身 `rubric.md` 的封顶规则。
- 超过封顶时必须解释依据。

## 已知待处理问题

### 1. 额度恢复前不要跑全量

在 key 额度恢复或替换前，不建议继续跑：

```powershell
backend\.venv\Scripts\python.exe benchmarks\software_patent_solution_github\evaluator\run_all.py --repeats 2 --workers 2
```

否则大概率继续生成无效 run。

### 2. report 中文显示仍可能乱码

`case_selection_report.md` 在 PowerShell 输出里出现过中文乱码。

这不是本轮失败主因，但后续可以单独修：

- 确认 report 写入统一使用 UTF-8。
- 确认 PowerShell 读取时使用 `Get-Content -Encoding UTF8`。
- 必要时在 report 生成器中显式 `encoding="utf-8"`。

### 3. 暂缓事项

用户已明确暂缓：

- 增加文件工具。
- 输出截断治理。

这些不应混入当前 benchmark 稳定性工作。

## 下一步建议

### Step 1：先验证真实 subject 单 case

等 key 额度恢复或换 key 后，先只跑一个 case，不跑 judge：

```powershell
$env:PYTHONIOENCODING='utf-8'
$env:OPENAI_BASE_URL='https://token-plan-cn.xiaomimimo.com/v1'
$env:OPENAI_API_KEY='<your-key>'
$env:OPENAI_MODEL='mimo-v2.5-pro'
backend\.venv\Scripts\python.exe benchmarks\software_patent_solution_github\evaluator\run_case.py --case 001 --skip-judge --round-timeout 180
```

如果这个仍然 `429`，不要继续全量。

### Step 2：单 case 成功后再跑小并发

建议从 `workers=2` 开始：

```powershell
$env:PYTHONIOENCODING='utf-8'
$env:OPENAI_BASE_URL='https://token-plan-cn.xiaomimimo.com/v1'
$env:OPENAI_API_KEY='<your-key>'
$env:OPENAI_MODEL='mimo-v2.5-pro'
backend\.venv\Scripts\python.exe benchmarks\software_patent_solution_github\evaluator\run_all.py --repeats 2 --workers 2
```

如果稳定，再考虑 `--workers 3`。

### Step 3：如果只想验证 judge 稳定性

可以复用已有 subject artifact，只跑 judge。

目标是检查同一个 artifact 多次 judge 是否分数稳定、理由一致。

后续可以补一个专门的 judge-only 批处理命令，避免每次重新跑 subject agent。

### Step 4：稳定性复核维度

下一轮有效 run 出来后，不按高分优先筛选，而按以下维度复核：

- subject success rate。
- 同一 case 多次 artifact 是否都能生成。
- 同一 case 多次 judge 分数方差。
- judge 是否准确抓住源码事实。
- 高分 case 是否真的有足够区分度。
- 低分 case 是否是 case 设计问题，而不是 agent 或运行环境问题。
