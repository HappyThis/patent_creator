# 运行任务说明

你需要基于一个软件项目环境和一段用户需求，将软件专利技术方案落实到当前交底书文档中。

文本输入：

你将收到以下文本输入：

1. 本运行任务说明。
2. 一个基于某个软件项目提出的技术方案需求。

除上述文本外，系统可能通过当前工作目录或“项目环境路径”告知你已准备好的项目环境位置。

运行环境：

- 系统已经提前准备好项目环境。
- 你的当前工作目录就是该项目环境目录；或者系统会明确告诉你项目环境路径。
- 你可以自行搜索和阅读当前项目环境中的源码、文档、测试和配置。

任务：

基于需求和当前项目环境，只充实当前交底书文档中的“技术方案”章节。

要求：

- 起草前应自行搜索和阅读当前项目环境。
- 如果需求中没有给出具体源码路径，应自行在当前项目环境中定位相关模块。
- 可以提出需要后续确认的风险点，但不要编造当前项目环境中不存在的文件、类名、接口或 PR 实现。
- 不要生成完整专利交底书。
- 不要修改当前项目环境中的源码、文档、测试或配置。
- 技术方案应写入交底书文档的“技术方案”章节，不要只放在最终聊天回复中。
- 本轮只允许编辑“技术方案”章节；不要编辑“技术领域”“背景技术”“现有技术方案”“现有技术缺陷”“要解决的技术问题”“技术效果”等其他章节。
- 技术方案应尽量具体，包含可实施的软件机制，而不是只描述产品功能。

技术方案内容建议覆盖：

- 技术问题，可以作为“技术方案”章节内部的说明，不要写入“要解决的技术问题”章节。
- 核心技术方案。
- 必要技术特征。
- 关键模块或处理流程。
- 技术效果，可以作为“技术方案”章节内部的说明，不要写入“技术效果”章节。
- 与项目环境和需求场景的对应关系。
- 风险或待确认问题。
