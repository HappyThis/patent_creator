# 评分标准

总分 100 分。本 case 评价“共享知识文件与运行时动态信号分层存储及读取融合”技术方案质量。

## 技术问题与改进目标：15 分

- 13-15 分：准确抓住共享语义内容与本机高频运行信号混写导致版本噪声、协作冲突和动态排序需求之间的矛盾。
- 8-12 分：能说明 frontmatter 高频变化造成脏 diff，但对动态信号价值或读取融合分析不足。
- 0-7 分：只理解为普通缓存、日志或 Markdown 格式整理。

## 核心技术构思：20 分

- 17-20 分：提出字段分层、sidecar 存储、路径映射、原子更新、读取融合、写入剥离、迁移兼容和失败隔离的组合构思。
- 10-16 分：有外部元数据存储构思，但读取融合、迁移或清理不完整。
- 0-9 分：只说不要写入 frontmatter 或用数据库保存。

## 技术手段深度与必要特征：25 分

- 21-25 分：覆盖字段分层、sidecar 接口、路径键、批量读取、并发更新、检索排序融合、新旧兼容、fail-open 和清理一致性。
- 13-20 分：覆盖主要读写路径，但缺少并发、迁移、失败隔离或清理策略。
- 0-12 分：只有单个写入器或单个查询接口变化。

## 要素协同与运行机理：15 分

- 13-15 分：清楚说明 Markdown、sidecar、检索排序、自动整理、归档删除和迁移流程如何协同。
- 8-12 分：流程大体清楚，但 sidecar 与排序或清理关系不清。
- 0-7 分：只列组件，缺少运行机理。

## 技术效果因果闭环：10 分

- 8-10 分：能从字段分层、读取融合和失败隔离推出减少版本噪声、保留排序价值和降低协作冲突的效果。
- 4-7 分：有效果描述，但偏“文件更干净”。
- 0-3 分：效果空泛。

## 可实施性与可变形实施方式：10 分

- 8-10 分：达到交底书可实施粒度，含字段、接口、更新、迁移和清理策略。
- 4-7 分：总体可实施，但关键更新时机或异常处理不够。
- 0-3 分：无法据此实施。

## 交底书表达适配度：5 分

- 4-5 分：体现可保护的分层存储与读取融合机制。
- 2-3 分：技术内容存在，但偏普通元数据拆分。
- 0-1 分：文件格式说明。

## 扣分和上限

- 直接删除动态信号，总分通常不高于 70 分。
- 把全部知识内容迁入私有数据库，破坏共享 Markdown，总分通常不高于 65 分。
- 没有读取融合，总分通常不高于 78 分。
- 没有迁移兼容或缺省策略，总分通常不高于 84 分。
- sidecar 故障会阻断知识内容读写，总分通常不高于 78 分。
