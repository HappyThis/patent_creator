# 隐藏参考方案

## 技术问题

现有分层近邻图搜索以固定的候选宽度或结果数量控制基层遍历。搜索循环同时负责图遍历、候选队列维护、结果截断和终止判断，因而默认假设“结果价值等同于向量数量”。这一假设在两类场景下失效：距离范围查询的结果数量由数据密度和查询半径共同决定；多向量对象查询中，多个向量可能属于同一逻辑对象，向量数量不能代表不同对象数量。

若把固定结果数量设得很大再过滤，会产生多余距离计算和内存占用；设得较小又可能过早终止，遗漏半径内结果或不足指定数量的不同对象。若直接修改原有循环，还可能让删除、标签过滤和普通近邻查询进入额外的虚调用与分支路径，损害高频基础接口的性能。

## 核心技术构思

方案把“如何遍历 HNSW 图”与“什么结果足够、什么候选值得继续搜索”分离。分层图的上层仍执行逐层贪心下降，以较低成本找到基层入口；在第 0 层的最佳优先搜索中，引入结果目标策略。策略能够接收结果加入和移除事件，并分别回答：当前最近待展开候选是否已经足以结束、一个新邻居是否仍值得进入候选队列、结果集合是否超出策略容量，以及搜索结束后如何执行最终过滤。

核心搜索循环继续维护两个不同语义的集合：待展开候选集合保存尚未访问其邻居的近距离节点；暂存结果集合保存目前可返回的节点，其最差距离形成下界。图遍历模块只负责访问标记、邻接扩展、距离计算和两个集合的同步，结果目标策略只维护与业务目标有关的计数和约束。这样可用同一遍历骨架实现距离范围策略、不同逻辑对象数量策略及后续其他策略。

为避免通用化拖慢普通查询，应保留无删除、无标签过滤且无自定义停止策略时的精简模板路径，使编译器消除策略、删除判断和过滤分支。只有需要删除检查、标签过滤或目标策略时才进入完整路径。

## 数学关系与变量定义

以平方欧氏距离为例，查询向量 \(q\) 与候选向量 \(x\) 的距离为：

\[
d^2(q,x)=\sum_{i=1}^{m}(q_i-x_i)^2
\]

调用方给出的半径为 \(\varepsilon\) 时，结果必须满足：

\[
d^2(q,x)\leq \varepsilon^2
\]

实现若直接使用平方距离函数，则策略参数也必须是 \(\varepsilon^2\)，不能把欧氏距离和平方距离混用。其他距离空间可以替换距离函数，但阈值必须与该函数的量纲和“距离越小越近”的排序语义一致。

设 \(c\) 为待展开候选集合中最近候选的距离，\(b\) 为暂存结果集合中最差结果的距离，\(n\) 为当前暂存结果数，\(n_{\min}\) 为保证探索深度的最小候选数，\(n_{\max}\) 为容量上限。距离范围策略可采用：

\[
\operatorname{stop}_{\varepsilon}=
\bigl(c>b\land n=n_{\max}\bigr)
\lor
\bigl(c>\varepsilon^2\land n\ge n_{\min}\bigr)
\]

新候选继续参与搜索的条件为：

\[
\operatorname{consider}_{\varepsilon}=
\bigl(n<n_{\max}\bigr)\lor\bigl(c_{new}<b\bigr)
\]

搜索结束后删除所有 \(d^2>\varepsilon^2\) 的暂存项，并保证结果数不超过 \(n_{\max}\)。\(n_{\min}\) 不是必须返回的结果数量，而是近似图搜索的探索下限；即使半径内没有足够向量，也不得返回范围外结果来填满它。

多向量对象场景中，设每个向量 \(x\) 关联逻辑对象标识 \(g(x)\)，当前暂存结果为 \(R\)，则不同对象数量为：

\[
D(R)=\left|\{g(x)\mid x\in R\}\right|
\]

策略为每个对象维护引用计数。当加入或移除向量使对象计数从 0 变 1 或从 1 变 0 时，才改变 \(D(R)\)。搜索阶段可维持 \(E\) 个候选对象，其中 \(E\ge K\)；当 \(c>b\) 且 \(D(R)=E\) 时停止继续扩展，最终从最差结果端移除向量，直至只保留 \(K\) 个不同对象。\(E\) 控制召回率与搜索成本之间的权衡，不能误写成向量条数上限。

## 必要技术特征

1. 通用结果目标接口：至少包括结果加入、结果移除、停止判断、候选考虑判断、容量判断和最终过滤六类能力，且生命周期由搜索循环统一驱动。
2. 分层搜索解耦：上层贪心下降保持不变，目标策略只接入第 0 层的最佳优先扩展，避免不同目标重复实现整套 HNSW 遍历。
3. 双集合语义：待展开候选集合按最近距离取出节点，暂存结果集合能快速取得最差距离；不能用一个队列同时承担两种顺序。
4. 范围策略：同时维护距离阈值、最小探索量、最大容量和当前数量；最终返回必须再次按阈值过滤。
5. 多向量数据布局：向量数据除坐标外保存逻辑对象标识，距离函数只读取向量坐标，策略能够从数据记录取得对象标识。
6. 对象引用计数：同一对象的多个向量加入结果时只增加一次不同对象数，移除最后一个向量时才减少。
7. 过滤与删除协同：被删除或不满足标签过滤的节点不得进入返回集合，但在不破坏连通性的前提下仍可作为图遍历的中间节点。
8. 普通查询快路径：无删除、无过滤、无目标策略时不承担策略回调成本；指标采集也应可关闭，避免原有热点路径退化。
9. 结果契约：空索引直接返回空结果；结果按近到远输出；参数要求 \(0\le n_{\min}\le n_{\max}\)，并处理容量超过索引规模、负阈值和重复对象标识。
10. 并发与生命周期：策略实例属于单次查询，不在并发查询间共享可变计数；索引只读搜索沿用项目已有并发安全边界。

## 运行流程

查询首先从最高层入口开始，对当前节点的邻居计算距离，只要发现更近节点就继续移动，直至本层不能改进，再下降一层。到达第 0 层后，系统初始化待展开候选集合、暂存结果集合、访问标记和目标策略状态。

每轮取出最近待展开候选，先把候选距离和当前最差结果距离交给目标策略判断是否结束。若继续搜索，则遍历其未访问邻居并计算距离。策略判断新距离是否值得进入候选集合；符合条件的节点进入待展开集合。若节点未删除且通过标签过滤，还进入暂存结果集合，同时触发结果加入事件。策略认为结果超量时，从暂存结果集合反复弹出最差项并触发移除事件，随后更新最差距离。

循环结束后，目标策略执行最终过滤。距离范围策略删除阈值外节点；多向量策略按照距离从差到好移除多余结果，直到不同对象数量满足请求。最后把结果转换为外部标签并按近到远返回。

## 验证方式

距离范围检索应与同一数据上的暴力搜索对照：所有返回距离均不超过阈值，并在给定探索参数下达到约定召回率；极小阈值查询自身时应返回距离为 0 的自身。还应覆盖半径内无结果、结果超过容量、不同查询使用不同阈值以及删除和过滤条件。

多向量检索应构造同一对象具有多个向量的数据，验证最终不同对象数等于请求值，而非向量数等于请求值；再与暴力排序得到的前若干不同对象对照召回率。性能测试应分别比较普通固定近邻快路径、启用过滤的路径和启用目标策略的路径。

## 技术效果

结果目标与图遍历解耦后，可以在不复制 HNSW 核心算法的情况下扩展新的搜索语义。范围策略依据距离和探索下限提前停止，减少“超大固定 K 后过滤”的无效计算，同时保证不返回范围外结果。多向量策略依据不同对象数控制搜索，避免单一对象占满结果。普通查询快路径保留后，新增能力不会把策略分派和额外判断强加给所有查询。

## 高质量深度标尺

高分方案应明确上层下降和基层搜索的职责边界、两个优先集合的不同排序语义、最差结果距离如何参与终止、策略在加入和移除时如何保持计数，以及范围结果数和多向量不同对象数为何不能由固定 K 代替。还应给出距离量纲一致的阈值关系、可判定的停止条件、过滤与删除协同、快路径和验证方法。

## 常见弱方案

- 把 K 设置成索引总量后全量过滤，没有解决搜索成本和提前终止问题。
- 只在最终结果阶段按半径过滤，基层搜索仍可能因固定 K 过早结束。
- 把 \(n_{\min}\) 当成必须返回数量，用范围外结果填满结果集。
- 多向量检索只按向量条数截断，没有维护不同对象数和对象引用计数。
- 用同一个队列同时表示待展开节点和当前结果，导致最近扩展与最差淘汰语义混乱。
- 对所有普通查询加入虚调用、删除检查和指标采集，造成热点路径性能回退。
- 公式使用欧氏距离阈值，但代码比较平方距离，导致范围边界错误。

## 等价机制说明

本参考方案不限定接口类名、堆实现或对象标识在记录中的具体布局。策略也可以使用函数对象、模板参数或状态机实现。只要方案能够让搜索循环根据结果目标维护独立状态，在不牺牲普通查询快路径的前提下正确实现距离范围和不同对象数量语义，并说明终止条件、边界与验证方式，即可视为等价方案。
