# 隐藏参考方案

## 技术问题

智能工作台已经能够派发 agent 任务、记录部分执行历史并展示任务结果，但一次 agent 执行的来源、状态、输出、错误、成本、评估结果和外部查询能力分散在不同对象中。系统难以稳定回答一次执行从哪个任务或会话产生、由哪个 agent 完成、是否成功、是否经过评估以及能否被其他工具复用。

如果只增加普通日志，运行过程无法被结构化查询、评估附着或排行榜聚合；如果另建完全独立的记录系统，又会与既有任务、会话和 agent 编排割裂。因此，需要一种将 agent 执行过程抽象为统一运行记录的技术方案。

## 核心技术构思

方案建立“统一运行对象、来源溯源、生命周期桥接、评估附着、事件通知和工具化访问”组合机制。每次 agent 执行被抽象为一个运行记录对象，该对象关联任务、会话、agent、触发来源、输入摘要、输出摘要、成本、错误和状态。系统在既有执行入口创建、更新或结束时自动维护该运行记录，并允许评估系统将评分或评审结果附着到指定运行记录上。运行记录还通过查询接口、事件流或工具入口提供给界面、评测系统和外部 agent。

## 必要技术特征

1. 统一运行对象：为一次 agent 执行生成稳定标识，并记录 agent、任务、会话、来源、状态、开始结束时间、结果、错误和成本等字段。
2. 来源溯源：记录运行来源、触发者、关联对象、输入摘要和产物引用，使运行记录可追踪到其产生背景。
3. 生命周期桥接：在既有任务派发、agent 启动、完成、失败或取消路径上自动创建和更新运行记录，而不是依赖人工补录。
4. 评估附着：允许评估结果、分数、通过状态、评估说明和维度信息绑定到运行记录。
5. 聚合统计：基于运行状态、成本和评估结果形成 agent 维度、任务维度或时间维度的统计和排行。
6. 事件通知：运行创建、状态变化、完成和评估附着时发布事件，供前端、监控或自动化流程订阅。
7. 工具化访问：提供运行列表、运行详情、来源溯源、评估附着和排行查询能力，使外部工具或 agent 能稳定访问。
8. 向后兼容：运行记录作为现有任务、会话和执行历史之上的结构化层，不替代既有任务系统和会话系统。

## 关键流程

执行触发时，系统根据任务、会话或外部调用信息创建运行记录，并写入初始状态和来源溯源。执行过程中，运行记录可随状态变化更新进度、成本或中间产物引用。执行完成时，系统写入终态、输出摘要、错误信息和耗时，并发布完成事件。评估系统或人工审查随后可针对运行标识附着评估结果，聚合模块据此更新统计和排行。外部工具查询时，只需以运行标识或筛选条件读取统一运行对象，而不必跨多个内部表推断。

## 技术效果

该方案把分散的 agent 执行过程转化为可查询、可追踪、可评估和可订阅的结构化运行记录。来源溯源提升审计和复盘能力；生命周期桥接避免重复上报和人工补录；评估附着使质量评测与具体执行稳定绑定；事件和工具访问能力使运行结果可被监控、排行榜和外部 agent 复用。

## 高质量深度标尺

高分方案应说明运行对象包含哪些必要字段，如何与任务、会话、agent 和既有执行历史关联，运行状态何时写入，来源溯源如何形成，评估如何附着到运行，事件如何通知，外部工具如何查询，以及该机制为什么不是普通日志表。只提出“记录执行日志”或“新增历史页面”的方案深度不足。

## 常见弱方案

- 只保存文本日志，缺少结构化运行对象和生命周期状态。
- 只展示历史页面，不能进行评估附着、溯源或工具化查询。
- 运行记录与任务、会话、agent 执行历史完全割裂。
- 评估结果只以文本备注保存，无法稳定绑定到一次运行。
- 让外部工具直接推断内部任务表，缺少统一访问契约。

## 等价机制说明

本参考方案不限定运行对象的具体命名。只要被评估方案能形成统一运行记录契约，并覆盖来源溯源、生命周期自动桥接、评估附着、事件通知和工具化访问，即可视为等价深度方案。
