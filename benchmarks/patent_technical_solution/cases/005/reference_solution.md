# 隐藏参考方案

## 技术问题

应用内部任务数据库适合任务看板、权限控制和 agent 调度，但不利于 Git-native agent 工作流、仓库协作和外部工具直接读取。若只做一次性导出，任务变化无法持续追踪；若将 Git 仓库作为主存储，又会破坏现有任务入口和状态流转；若同步失败阻断主流程，会影响日常任务操作。

因此，需要一种以应用数据库为事实来源、以 Git-native 仓库为可选协作镜像的任务同步方案，在保持主流程稳定的同时，为外部 agent 工具提供机器可读、可版本化的任务表示。

## 核心技术构思

方案建立“主存储优先、机器可读任务镜像、语义映射、生命周期挂接、非阻塞 Git 同步和管理观察入口”组合机制。系统继续将应用数据库作为任务事实来源，在任务创建、更新和删除后，将任务对象转换为仓库内机器可读文件，并通过 Git 提交记录外部镜像变化。同步过程以后台或非阻塞方式执行，失败时记录状态和告警，不回滚主任务操作。用户可通过管理入口初始化镜像仓库、查询同步状态或手动触发同步。

## 必要技术特征

1. 主存储保持：应用数据库仍是任务事实来源，Git 仓库仅作为可选镜像和协作出口。
2. 稳定路径映射：以任务标识生成稳定文件路径，避免任务标题变化导致外部引用失效。
3. 任务文件结构：将任务标题、描述、状态、优先级、负责人、标签、项目、时间戳和来源标识写入机器可读文件。
4. 语义映射：建立应用内部状态和优先级到外部协作格式的映射，并处理未知值或不完全对应值。
5. 生命周期挂接：任务创建、更新、删除或关闭时触发镜像写入、更新、删除或标记。
6. Git 持久化：对任务文件变更执行 add、commit 和可选 push，使外部镜像具备版本历史。
7. 非阻塞失败处理：Git 操作失败只记录同步错误、待重试状态或告警，不影响主任务 API。
8. 管理入口：提供镜像仓库初始化、状态查询、手动同步和错误查看能力。
9. 状态可见性：在任务看板或管理界面展示最近同步时间、错误状态、任务数量或镜像启用状态。

## 关键流程

初始化时，系统根据配置创建或检查镜像仓库，生成协议版本文件、任务目录和必要说明，并提交初始结构。任务创建或更新时，主数据库先完成写入，随后同步模块将任务转换为外部格式并写入稳定路径，再提交 Git 变更。任务删除时，系统删除对应任务文件或写入删除标记并提交。同步失败时，主流程仍返回成功，同步模块记录错误和待处理状态。手动同步时，系统读取仓库状态、提交未同步变更并尝试推送远端，同时返回可观察状态。

## 技术效果

该方案使任务数据能够被 Git-native agent 工作流和外部工具持续读取，同时不破坏应用数据库、任务看板和调度流程。稳定文件映射和语义映射减少外部协作歧义；Git 提交历史提供任务变化追踪；非阻塞同步避免外部仓库故障影响主流程；管理入口提升同步状态的可观察性和可恢复性。

## 高质量深度标尺

高分方案应说明主存储和镜像仓库的事实来源关系，任务如何映射为机器可读文件，状态和优先级如何转换，创建/更新/删除如何挂接生命周期，Git 操作失败如何隔离，用户如何初始化、观察和手动恢复同步。只提出“导出任务到仓库”或“同步成 issue”的方案深度不足。

## 常见弱方案

- 将 Git 仓库改成任务主存储，破坏现有任务入口。
- 只做一次性导出，没有持续生命周期同步。
- 同步失败直接导致任务创建或更新失败。
- 不做状态和优先级语义映射，导致外部表示失真。
- 只保存自然语言 Markdown，缺少机器可读任务结构和稳定标识。

## 等价机制说明

本参考方案不限定目录名、文件扩展名或 Git 操作封装方式。只要被评估方案能保持主存储优先、提供机器可读镜像、稳定路径映射、语义转换、非阻塞同步和管理观察能力，即可视为等价深度方案。
