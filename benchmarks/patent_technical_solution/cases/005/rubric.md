# 评分标准

总分 100 分。本 case 评价“主存储保持型 Git-native 任务协作镜像同步”技术方案质量。

## 技术问题与改进目标：15 分

- 13-15 分：准确抓住应用主数据库与 Git-native 协作镜像之间的持续同步、语义映射和故障隔离问题。
- 8-12 分：能说明任务需要外部同步，但对主存储保持、生命周期或语义偏差分析不足。
- 0-7 分：只理解为导出、备份或普通文件保存。

## 核心技术构思：20 分

- 17-20 分：提出主存储优先、任务镜像、稳定路径映射、语义映射、生命周期挂接、非阻塞 Git 同步和管理入口的组合构思。
- 10-16 分：有同步引擎和文件写入构思，但缺少语义映射、失败隔离、删除或管理入口。
- 0-9 分：只说同步到 Git 或保存 JSON。

## 技术手段深度与必要特征：25 分

- 21-25 分：覆盖任务文件结构、路径映射、状态/优先级映射、创建更新删除、Git 提交、错误记录、手动同步、状态可见和主流程兼容。
- 13-20 分：覆盖主要同步路径，但缺少删除、初始化、错误隔离或状态观察。
- 0-12 分：只有单个导出接口或手工同步。

## 要素协同与运行机理：15 分

- 13-15 分：清楚说明任务 API、主数据库、同步模块、Git 仓库、配置和管理界面如何协同。
- 8-12 分：流程大体清楚，但失败隔离或语义映射与主流程关系不清。
- 0-7 分：模块堆叠，缺少运行机理。

## 技术效果因果闭环：10 分

- 8-10 分：能从主存储保持、镜像同步、Git 版本化和非阻塞处理推出跨工具协作和主流程稳定性。
- 4-7 分：有效果描述，但偏“方便共享任务”。
- 0-3 分：效果空泛。

## 可实施性与可变形实施方式：10 分

- 8-10 分：达到交底书可实施粒度，含文件结构、状态、配置、同步时机和错误处理。
- 4-7 分：总体可实施，但关键字段映射或故障处理不够。
- 0-3 分：无法据此实施。

## 交底书表达适配度：5 分

- 4-5 分：体现可保护的任务镜像、语义映射和非阻塞同步机制。
- 2-3 分：技术内容存在，但偏普通导出或备份。
- 0-1 分：产品说明。

## 扣分和上限

- 把 Git 仓库作为唯一任务主存储，总分通常不高于 60 分。
- 没有生命周期挂接，只做一次性导出，总分通常不高于 70 分。
- 没有状态/优先级语义映射，总分通常不高于 84 分。
- 同步失败会阻断任务主流程，总分通常不高于 75 分。
- 没有初始化、状态查询或手动同步入口，总分通常不高于 84 分。
