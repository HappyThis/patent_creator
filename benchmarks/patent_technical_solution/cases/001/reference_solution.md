# 隐藏参考方案

## 技术问题

既有智能工作台已经能够管理多种本地 agent runtime 的工作记录。新增 runtime 时，难点不只是增加一个入口，而是不同 runtime 的本地状态来源、会话结构、历史消息格式和可继续能力均可能不一致。若系统在未确认格式和能力的情况下直接展示会话或开放操作入口，容易产生三类问题：历史记录解析不可信、继续会话等操作被错误承诺、以及新增 runtime 的异常影响既有 runtime 的稳定管理流程。

因此，需要一种面向异构本地 agent runtime 的接入方案，使系统能在未知或变化的本地格式条件下发现会话、抽取可信信息、以统一形态展示，并对未确认能力进行显式限制或降级。

## 核心技术构思

方案建立“运行时适配单元、统一会话视图、解析可信度标记、能力声明和降级控制”组成的接入机制。每类 runtime 由独立适配单元负责本地状态发现和格式解析；适配单元不直接驱动上层展示，而是输出统一会话视图对象。统一会话视图同时携带会话元数据、解析完整性、能力声明和错误诊断信息。上层工作台仅依据这些声明展示详情、继续会话、导出或其他操作，从而避免把未知能力当成可用能力。

## 必要技术特征

1. 运行时独立适配：为新增 runtime 配置独立适配单元，使其与既有 runtime 的发现和解析逻辑隔离，避免复用错误格式或覆盖既有语义。
2. 状态来源发现：适配单元支持显式配置路径优先，并可按运行环境特征查找候选状态位置；不可访问或不存在时输出诊断状态，而不是抛出不可控异常。
3. 版本化兼容解析：解析器按已知格式版本读取会话；对未知字段保留原始载荷或扩展区，对无法完整解析的会话输出部分元数据。
4. 统一会话视图：将不同 runtime 的会话映射为统一结构，至少包括会话标识、来源 runtime、标题或摘要、更新时间、关联工作区、消息规模、解析状态和可用操作声明。
5. 解析可信度分级：将会话标记为完整解析、部分解析、仅元数据或不可解析，并将该标记传递给上层展示和交互控制。
6. 能力探测与声明：继续会话、查看完整转录、终端附着等能力需由适配单元探测或依据可确认条件声明；未声明能力不展示入口。
7. 操作前复验：对依赖本地环境的操作，在执行前重新验证必要条件，失败时返回可诊断原因，而不是伪造成功。
8. 异常隔离：新增 runtime 的目录不可读、格式未知或命令不可用，只影响该 runtime 的会话，不影响既有 runtime 的会话列表和操作。

## 运行流程

运行时发现阶段，系统加载 runtime 注册信息，逐一调用适配单元检查本地状态来源，生成可用、不可用或需配置的 runtime 状态。会话读取阶段，适配单元枚举本地会话记录，对每条记录进行版本识别、字段解析和可信度标注，并输出统一会话视图。展示阶段，上层按统一视图渲染会话列表和详情，同时依据能力声明决定哪些操作可见。操作阶段，系统根据会话来源路由至对应适配单元；适配单元复验本地环境、执行操作并返回结果或诊断失败。

## 技术效果

该方案使工作台能够接入新的本地 agent runtime，而不要求预先完全掌握其所有文件格式和交互能力。通过适配隔离、统一视图和可信度分级，系统可以展示可确认信息并明确未知边界；通过能力声明和操作前复验，系统减少误导性入口和错误承诺；通过异常隔离，新增 runtime 的失败不会破坏既有 runtime 的管理流程。

## 高质量深度标尺

高分方案应说明：不同 runtime 的状态发现如何隔离；未知格式如何部分解析和保留诊断信息；统一会话视图有哪些必要字段；能力如何从探测结果进入上层控制；继续会话等操作如何避免伪造成功；新增 runtime 失败时如何不影响既有 runtime。只提出“增加 runtime 支持”或“读取本地文件并展示”的方案深度不足。

## 常见弱方案

- 只增加一个 runtime 入口，没有会话解析和统一视图机制。
- 默认新 runtime 的所有历史会话都可完整解析或继续。
- 把未知 runtime 伪装成已有 runtime，导致品牌、能力和解析语义混乱。
- 遇到未知格式直接失败，不保留可确认元数据或诊断状态。
- 没有能力声明和降级控制，导致用户看到不可用操作。

## 等价机制说明

本参考方案不限定适配单元、统一会话视图或能力声明的具体命名。只要被评估方案能够通过独立适配、可信度分级、统一展示对象和操作能力控制来解决异构 runtime 接入问题，并能解释未知格式和未知能力下的降级行为，即可视为等价深度方案。
