# 评分标准

总分 100 分。本 case 评价“异构本地 agent runtime 的会话归一化与能力边界控制”技术方案质量，不评价实现路径或验证材料完整度。

## 技术问题与改进目标：15 分

- 13-15 分：准确抓住本质是异构 runtime 的状态来源差异、会话格式未知、能力差异和误导性能力承诺问题。
- 8-12 分：能说明需要接入新 runtime 和统一展示，但对未知格式或能力边界分析不足。
- 0-7 分：只理解为增加一个工具入口、配置项或页面选项。

## 核心技术构思：20 分

- 17-20 分：提出适配层、统一会话对象和能力声明/降级控制的组合构思。
- 10-16 分：有适配或统一展示构思，但能力边界、降级或兼容解析不完整。
- 0-9 分：只说读取文件或调用外部命令，缺少整体解决构思。

## 技术手段深度与必要特征：25 分

- 21-25 分：覆盖状态发现、配置化候选位置、兼容解析、统一会话字段、解析降级、能力声明、继续能力检测和既有 runtime 兼容。
- 13-20 分：覆盖主要会话发现和归一化，但缺少能力声明、诊断性失败或未知格式处理。
- 0-12 分：只有单一读取流程或 UI 展示描述。

## 要素协同与运行机理：15 分

- 13-15 分：清楚说明发现、解析、归一化、能力声明、操作入口控制之间如何协同。
- 8-12 分：有流程描述，但各单元之间因果关系不够清楚。
- 0-7 分：堆模块名，缺少运行机理。

## 技术效果因果闭环：10 分

- 8-10 分：技术效果能由适配、降级和能力控制自然推出。
- 4-7 分：有效果描述，但偏“支持更多工具”等结果性表述。
- 0-3 分：效果空泛。

## 可实施性与可变形实施方式：10 分

- 8-10 分：达到交底书可实施粒度，含必要实施条件和可变形方式。
- 4-7 分：总体可实施，但关键边界仍需大量补充。
- 0-3 分：无法据此实施。

## 交底书表达适配度：5 分

- 4-5 分：表达像技术方案章节，强调技术手段和保护点。
- 2-3 分：技术内容存在，但偏工程任务或产品说明。
- 0-1 分：明显不是交底书技术方案。

## 扣分和上限

- 默认声称新 runtime 的本地格式、继续能力或附加能力已经完整确定，且该声明没有材料依据，总分通常不高于 75 分。
- 没有能力边界声明或降级机制，总分通常不高于 80 分。
- 没有会话归一化机制，只是读取文件或增加入口，总分通常不高于 70 分。
- 不要求列出实现路径、验证材料、接口清单或具体文件名；缺少这些内容不得单独扣分。
