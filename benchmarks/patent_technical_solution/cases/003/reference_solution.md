# 隐藏参考方案

## 技术问题

多会话 assistant 需要同时满足两类相反要求：每个会话应保留独立消息历史、上下文、短期状态和执行过程，避免不同会话互相污染；同一用户下的工作区文件、外部工具连接、授权凭据和跨会话调度能力又应保持连续，避免每个会话重复配置资源。若只在一个 agent 中增加多个 chat id，容易造成上下文隔离不足；若每个会话独立持有全部资源，又会导致用户级资源不连续、凭据重复、删除边界不清。若浏览器或子会话能绕过统一控制直接访问共享资源，还会带来越权和生命周期失控风险。

因此，需要一种在会话级隔离与用户级共享之间建立清晰边界的多会话 assistant 技术方案。

## 核心技术构思

方案建立“用户级父实体、会话级子实体、共享资源代理、会话注册表门禁和共享变更广播”组成的分层机制。用户级父实体持有用户范围内长期存在的工作区、外部工具连接、授权凭据、会话索引和跨会话调度状态；每个会话级子实体持有自身消息历史、上下文、短期执行状态和配置。子实体不直接持有共享资源，而是通过父实体提供的受控代理访问文件、工具和授权能力。父实体在路由和代理调用前检查会话注册表，确保只有合法子会话能访问对应共享资源。

## 必要技术特征

1. 用户级父实体：按用户建立长期实体，维护会话索引、共享工作区、工具连接、授权凭据、广播通道和跨会话调度状态。
2. 会话级子实体：每个会话拥有独立消息历史、上下文、执行状态、分支或临时配置，切换会话不会混用这些私有状态。
3. 会话注册表：父实体记录由其创建的子会话标识、状态和更新时间；未知或已删除会话在唤醒前即被拒绝。
4. 共享文件代理：子会话发起文件读取、写入、列表、搜索或删除时，经代理转发到父实体执行，由父实体统一维护真实工作区。
5. 共享工具与授权代理：外部工具连接和授权凭据由父实体持有；子会话在需要时获取可用工具描述，并通过父实体代理完成真实调用。
6. 生命周期边界：删除子会话时只清理该会话私有状态和索引，不默认删除用户级共享工作区、工具连接和授权凭据。
7. 访问门禁：浏览器或子会话不能直接绕过父实体执行共享资源操作；所有共享资源访问都经过注册表和用户身份校验。
8. 变更广播：父实体监听共享资源变化，向同一用户的多个会话或客户端广播版本变化，使不同视图能刷新共享状态。
9. 跨会话调度：跨会话提醒、后台任务或资源维护由父实体统一调度，再按策略选择目标子会话执行。

## 运行流程

用户进入系统后，请求先定位到用户级父实体。创建会话时，父实体生成子会话标识、写入注册表并创建子实体。用户切换会话时，请求经父实体路由到对应子实体；子实体处理对话时只读取自己的私有上下文。模型或工具需要访问共享文件、外部工具或授权资源时，子实体调用代理，父实体完成门禁校验后执行真实操作并返回结果。共享工作区或工具状态变化后，父实体广播变更版本。删除会话时，父实体移除注册表项并清理子实体私有状态，同时保留用户级共享资源。

## 技术效果

该方案在同一用户下实现多个会话的上下文隔离和资源连续性。父子实体边界避免消息、短期记忆和执行状态互相污染；共享代理避免工作区和工具连接在每个会话中重复持有；注册表门禁防止猜测会话标识或绕过统一控制访问共享资源；删除边界避免误删用户级资源；广播机制保证多会话、多客户端视图对共享资源变化保持一致。

## 高质量深度标尺

高分方案应说明父实体和子实体分别持有哪些状态，子会话如何经代理访问共享文件和工具，注册表如何阻断未知会话，删除会话时哪些资源被清理、哪些被保留，共享资源变更如何同步到多个会话，以及跨会话调度为何应由父实体统一负责。只实现多个聊天列表、多个 chat id 或前端切换，不足以构成完整技术方案。

## 常见弱方案

- 所有会话共用一个上下文，导致消息历史和执行状态污染。
- 每个会话各自复制工作区和授权资源，导致资源不连续和删除风险。
- 子会话或浏览器可直接调用共享工具，绕开父实体门禁。
- 删除某个会话时误删用户级共享工作区或凭据。
- 没有共享变更广播，多会话视图无法保持一致。

## 等价机制说明

本参考方案不限定父实体、子实体、共享代理或注册表的具体命名。只要被评估方案能够清楚划分会话私有状态和用户级共享资源，并通过受控代理、访问门禁、删除边界和变更同步解决多会话 assistant 的隔离与共享矛盾，即可视为等价深度方案。
