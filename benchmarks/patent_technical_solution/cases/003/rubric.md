# 评分标准

总分 100 分。本 case 评价“多会话 agent assistant 的父子实体与共享资源代理”技术方案质量，不评价具体框架细节。

## 技术问题与改进目标：15 分

- 13-15 分：准确抓住多会话私有上下文隔离与用户级资源共享之间的矛盾，以及访问绕过和删除边界风险。
- 8-12 分：能说明多会话和共享资源需求，但对隔离、门禁或删除边界分析不足。
- 0-7 分：只理解为侧边栏多个聊天记录。

## 核心技术构思：20 分

- 17-20 分：提出用户级父实体、会话级子实体、共享资源代理和注册表门禁的组合构思。
- 10-16 分：有父子或多会话构思，但共享代理或门禁不完整。
- 0-9 分：只是多 chat id 或消息分组。

## 技术手段深度与必要特征：25 分

- 21-25 分：覆盖父实体职责、子实体私有状态、用户级共享资源、资源代理、工具/授权代理、注册表门禁、变更广播、跨会话调度和删除策略。
- 13-20 分：覆盖父子结构和部分共享资源，但缺少代理链、门禁、广播或删除策略。
- 0-12 分：只有会话列表或 UI 管理。

## 要素协同与运行机理：15 分

- 13-15 分：清楚说明父实体、子实体、代理层、注册表、广播和调度之间如何协同。
- 8-12 分：流程大体存在，但共享与隔离之间关系不够清楚。
- 0-7 分：只列组件，缺少运行机理。

## 技术效果因果闭环：10 分

- 8-10 分：能从父子隔离、代理访问、门禁和广播推出上下文不污染、资源复用和安全一致性。
- 4-7 分：有效果描述但因果不足。
- 0-3 分：效果空泛。

## 可实施性与可变形实施方式：10 分

- 8-10 分：达到交底书可实施粒度，并说明资源保留/清理、版本广播或代理接口可变形。
- 4-7 分：总体可实施，但关键边界不够。
- 0-3 分：无法指导实现。

## 交底书表达适配度：5 分

- 4-5 分：体现可保护的父子实体、共享代理和门禁组合机制。
- 2-3 分：偏系统设计说明，但技术方案仍成立。
- 0-1 分：产品交互说明。

## 扣分和上限

- 未区分会话私有状态和用户共享资源，总分通常不高于 72 分。
- 没有共享资源代理，子会话或浏览器可直接访问共享资源，总分通常不高于 78 分。
- 没有注册表门禁或防猜测访问机制，总分通常不高于 80 分。
- 删除会话会误删用户级共享资源，或完全没有删除边界，总分通常不高于 82 分。
- 不要求列出完整接口、具体框架名称、实现路径或验证材料；缺少这些内容不得单独扣分。
