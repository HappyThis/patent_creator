# 评分标准

总分 100 分。本 case 评价“durable agent chat 中客户端清理与服务端取消解耦控制”技术方案质量。

## 技术问题与改进目标：15 分

- 13-15 分：准确抓住客户端本地生命周期与服务端 durable turn 生命周期被错误耦合的问题，以及显式取消与本地清理需要分离。
- 8-12 分：能说明刷新或断线不应取消服务端任务，但对显式停止、配置策略或恢复兼容分析不足。
- 0-7 分：只理解为普通断线重连、loading 状态或停止按钮。

## 核心技术构思：20 分

- 17-20 分：提出生命周期解耦、活动 turn 标识、显式取消通道、可配置 abort 策略、迟到消息处理和恢复兼容的组合构思。
- 10-16 分：有取消策略和显式停止，但活动标识、恢复或 continuation 边界不完整。
- 0-9 分：只说 abort 时不取消服务端或加一个 stop。

## 技术手段深度与必要特征：25 分

- 21-25 分：覆盖本地清理、显式取消、取消消息关联、active id 保留、配置矩阵、迟到消息过滤、resume、continuation 和多观察者边界。
- 13-20 分：覆盖主要发送和停止路径，但缺少恢复、迟到消息或 continuation。
- 0-12 分：只有单个按钮或单个 abort handler。

## 要素协同与运行机理：15 分

- 13-15 分：清楚说明客户端 transport、本地 stream、服务端 turn、取消消息、恢复和观察者如何协同。
- 8-12 分：流程大体清楚，但取消和恢复关系不清。
- 0-7 分：模块堆叠，缺少状态机运行机理。

## 技术效果因果闭环：10 分

- 8-10 分：能从解耦、显式取消和恢复兼容推出避免误杀长任务、支持明确停止和减少 UI 污染的效果。
- 4-7 分：有效果描述，但偏“刷新后还能继续”。
- 0-3 分：效果空泛。

## 可实施性与可变形实施方式：10 分

- 8-10 分：达到交底书可实施粒度，含状态、消息、配置、清理时机和异常边界。
- 4-7 分：总体可实施，但关键状态或边界条件不够。
- 0-3 分：无法据此实施。

## 交底书表达适配度：5 分

- 4-5 分：体现可保护的生命周期解耦和取消控制机制。
- 2-3 分：技术内容存在，但偏普通取消策略。
- 0-1 分：UI 按钮说明。

## 扣分和上限

- 把普通客户端 abort 一律映射为服务端取消，总分通常不高于 65 分。
- 没有显式服务端取消能力，总分通常不高于 78 分。
- 没有活动 turn 标识，总分通常不高于 82 分。
- 没有配置行为矩阵，总分通常不高于 80 分。
- 没有恢复、迟到消息或 continuation 边界处理，总分通常不高于 85 分。
