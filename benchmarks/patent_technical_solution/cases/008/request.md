# 技术方案需求

给定项目快照中的 agent 框架已经支持基于服务端持久对象的 chat agent、子 agent 路由、流式输出和恢复能力。现在需要支持更复杂的 agent 协作方式：用户仍然只和一个主 agent 对话，但主 agent 在处理一次请求时，可以调用一个或多个专门的子 agent 来完成研究、规划、比较、总结等任务，并把子 agent 的执行过程和结果带回同一主会话视图。

子 agent 应保持独立执行上下文，适合长任务、并行任务和后续查看。刷新页面或网络短暂断开后，用户仍应能恢复看到已经发生的子 agent 过程。系统还需要考虑重复请求、并发执行、访问控制、取消、清理保留结果，以及无直接父工具调用的后台子运行。

请探索给定项目快照，生成一个可用于专利交底书的技术方案草稿。方案应围绕保留式流式子 agent 工具编排提出合理、深入且可实施的解决方法，不要只描述“主 agent 调用子 agent 后汇总结果”。
