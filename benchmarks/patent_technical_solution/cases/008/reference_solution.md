# 隐藏参考方案

## 技术问题

主 agent 调用子 agent 不应退化为普通函数调用或只返回最终摘要。真实协作场景中，子 agent 可能长时间运行、并行执行、产生流式过程、失败或被取消；用户需要在主会话中观察这些过程，并在刷新或断线后恢复查看。若没有稳定的子运行身份和父侧注册表，系统无法重放、清理、访问控制或处理没有直接父工具调用的后台子运行。

因此，需要一种把子 agent 作为保留式、可观察、可恢复运行实体的编排机制。

## 核心技术构思

方案建立“父侧工具包装与命令式入口、子运行注册表、独立子 agent 上下文、父连接事件回流、重放去重、访问门禁和保留清理”组合机制。主 agent 可以通过模型工具调用或服务端流程启动子 agent；每次子运行获得稳定运行标识并登记到父侧注册表。子 agent 在独立上下文中执行，其输出片段、状态变化、完成结果、失败或取消事件通过父会话连接回流到同一主会话视图。断线重连后，客户端可根据注册表和事件日志重放历史，并对实时事件去重。

## 必要技术特征

1. 父侧调用入口：支持模型把子 agent 当作工具调用，也支持服务端确定性流程主动启动子运行。
2. 子运行身份：为每个子运行生成稳定标识，并记录父会话、父工具调用、显示顺序和触发上下文。
3. 保留注册表：父侧维护子运行状态、输入摘要、输出摘要、错误、时间和保留策略。
4. 独立执行上下文：子 agent 拥有独立消息、状态和流，不直接污染父会话上下文。
5. 事件回流：子输出 chunk、状态、完成、失败、取消和中断事件通过父连接返回主会话。
6. 重放去重：事件携带序号或事件标识，使刷新重连后 replay 与 live 事件不会重复展示。
7. 幂等与并发：重复 run id 不应启动第二个子运行；多个子运行可并行并按稳定顺序展示。
8. 访问门禁：drill-in 或直接查看子运行时必须校验父注册表和用户归属，未知标识不得唤醒新子实体。
9. 取消与清理：运行中清理前应先取消子运行；已保留结果可按策略删除、归档或 tombstone。
10. 后台子运行：没有直接父工具调用的子运行仍应归属父会话或父实体，并可展示、恢复和清理。

## 运行流程

主 agent 决定调用子 agent 时，父侧包装器生成子运行标识并写入注册表，随后启动子 agent 独立执行。子 agent 的流式输出被封装为带运行标识和序号的事件，经父连接发送到主会话。父模型需要继续推理时，可接收子运行最终摘要或结构化失败作为工具结果。用户刷新后，客户端读取父侧注册表和历史事件重建子运行面板，并用事件标识去重实时补发。用户取消或清理时，父侧根据注册表定位子运行，先发送取消或停止信号，再更新保留状态或删除记录。

## 技术效果

该方案使子 agent 从普通同步调用升级为可观察、可恢复、可并行和可保留的运行实体。父侧注册表提供身份、恢复、访问控制和清理依据；事件回流让用户在主会话中看到子任务过程；重放去重保证断线恢复一致；独立上下文避免子 agent 状态污染父会话；最终摘要或失败结构保证父 agent 能继续完成主任务。

## 高质量深度标尺

高分方案应说明子运行身份如何生成，父侧注册表保存什么，子 agent 如何独立执行，流式事件如何回到主会话，刷新后如何 replay 和去重，并行、幂等、取消、清理和 drill-in 访问如何处理，以及无父工具调用的后台子运行如何归属。只说“主 agent 调用子 agent 并汇总结果”的方案深度不足。

## 常见弱方案

- 将子 agent 简化为普通函数或一次性工具调用。
- 子 agent 直接把消息写入父会话，缺少身份和事件隔离。
- 刷新后只保留最终摘要，丢失子 agent 过程。
- 没有父侧注册表，无法恢复、访问控制或清理。
- 未处理并行子运行、重复请求、取消和后台子运行。

## 等价机制说明

本参考方案不限定子运行、注册表或事件协议的具体名称。只要被评估方案能通过稳定身份、父侧保留索引、独立执行上下文、流式事件回流、重放去重、访问门禁和保留清理解决主子 agent 协作问题，即可视为等价深度方案。
