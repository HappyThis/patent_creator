# 评分标准

总分 100 分。本 case 评价“保留式流式子 agent 工具编排”技术方案质量。

## 技术问题与改进目标：15 分

- 13-15 分：准确抓住子 agent 需要可观察、可恢复、可保留、可访问控制，而不是普通函数调用。
- 8-12 分：能说明主子 agent 协作和过程展示，但对恢复、保留或访问控制分析不足。
- 0-7 分：只理解为主 agent 调用子 agent 并汇总文本。

## 核心技术构思：20 分

- 17-20 分：提出父侧调用入口、子运行注册表、独立子上下文、事件回流、重放去重、访问门禁和保留清理的组合构思。
- 10-16 分：有父子运行和事件回流，但注册表、恢复、取消或门禁不完整。
- 0-9 分：只说调用子 agent 或增加多个助手。

## 技术手段深度与必要特征：25 分

- 21-25 分：覆盖模型工具调用、命令式启动、run id、父子关联、流式事件、最终返回、并行、幂等、replay、取消、清理、后台运行和 drill-in 门禁。
- 13-20 分：覆盖主要运行和展示流程，但缺少后台运行、去重、清理或访问控制。
- 0-12 分：只有同步调用或最终摘要。

## 要素协同与运行机理：15 分

- 13-15 分：清楚说明父 agent、子 agent、注册表、事件通道、客户端聚合和清理入口如何协同。
- 8-12 分：流程大体清楚，但恢复或父模型返回契约不清。
- 0-7 分：模块堆叠，缺少运行机理。

## 技术效果因果闭环：10 分

- 8-10 分：能从注册表、独立上下文和事件回流推出过程可见、刷新可恢复、并行可控和上下文不污染的效果。
- 4-7 分：有效果描述，但偏“能看到子任务”。
- 0-3 分：效果空泛。

## 可实施性与可变形实施方式：10 分

- 8-10 分：达到交底书可实施粒度，含状态、事件、身份、访问和清理策略。
- 4-7 分：总体可实施，但关键协议或异常边界不够。
- 0-3 分：无法据此实施。

## 交底书表达适配度：5 分

- 4-5 分：体现可保护的子运行保留、事件回流和恢复控制机制。
- 2-3 分：技术内容存在，但偏框架使用说明。
- 0-1 分：产品功能说明。

## 扣分和上限

- 子 agent 只是普通函数调用，总分通常不高于 60 分。
- 没有父侧注册表或等价索引，总分通常不高于 78 分。
- 没有恢复和 replay 去重，总分通常不高于 82 分。
- 没有取消、失败或清理策略，总分通常不高于 84 分。
- 没有访问门禁，未知子运行可被直接访问或创建，总分通常不高于 80 分。
