# 评分标准

总分 100 分。本 case 评价“插入与合并顺序无关的概率基数估计草图”技术方案质量。

## 技术问题与改进目标：15 分

- 13-15 分：准确识别共享基值、残差截断和重定基的有损历史依赖，以及它对分布式插入顺序和归并树顺序的影响。
- 8-12 分：理解顺序无关需求，但只分析插入或只分析合并。
- 0-7 分：把问题误解为线程安全、固定随机种子或普通输入排序。

## 核心技术构思：20 分

- 17-20 分：提出规范绝对状态、幂等插入、可交换/可结合合并、稀疏并集、精度化偏差校正和版本迁移的组合机制。
- 10-16 分：有逐寄存器最大值或规范化构思，但稀疏转换、校正或兼容不完整。
- 0-9 分：依赖保存全量元素、全局排序或集中式单节点归并。

## 技术手段深度与必要特征：25 分

- 21-25 分：覆盖哈希拆分、绝对寄存器、最大值插入/合并、精度校验、稀疏并集、稀疏—稠密转换、估计校正、序列化版本、深拷贝和性质测试。
- 13-20 分：覆盖主要稠密机制，但缺少稀疏混合、旧格式或误差校正。
- 0-12 分：只说使用标准 HyperLogLog 或改用更大寄存器。

## 要素协同与运行机理：15 分

- 13-15 分：清楚说明元素插入、稀疏累积、确定性转稠密、同精度合并、估计、序列化和旧格式读取的完整链路。
- 8-12 分：主要流程存在，但表示转换或版本兼容衔接不清。
- 0-7 分：只列数据结构和公式，缺少运行过程。

## 技术效果因果闭环：10 分

- 8-10 分：能由最大值代数性质推出顺序无关和重复幂等，由偏差校正与精度关系推出误差可控，由版本转换推出升级连续性。
- 4-7 分：有效果描述，但没有对应到具体机制或性质。
- 0-3 分：只宣称更准确、更快或更稳定。

## 可实施性与可变形实施方式：10 分

- 8-10 分：达到可实现粒度，含状态字段、精度约束、转换阈值、格式版本、旧数据恢复和测试方法，并允许有依据的等价编码。
- 4-7 分：总体可实施，但缺少兼容、异常输入或验证细节。
- 0-3 分：无法据此实现或验证。

## 交底书表达适配度：5 分

- 4-5 分：体现规范概率状态、代数合并和精度化校正的可保护组合关系。
- 2-3 分：技术方案成立，但偏代码重构或算法论文复述。
- 0-1 分：仅为 API 或测试说明。

## 扣分和上限

- 只对输入排序，未解决不同局部草图的合并顺序，总分通常不高于 62 分。
- 保存全部原始元素或哈希值作为主要方案，破坏有界内存目标，总分通常不高于 60 分。
- 没有可交换、可结合、幂等的状态合并机制，总分通常不高于 72 分。
- 只处理稠密—稠密合并，未覆盖稀疏并集、混合合并或确定性转换，总分通常不高于 82 分。
- 不校验精度便逐位置合并，总分通常不高于 68 分。
- 更换状态或二进制布局却没有旧格式读取/迁移策略，总分通常不高于 78 分。
- 没有估计误差校正或把一组固定系数无条件用于全部精度，总分通常不高于 80 分。
- 不要求采用八位寄存器或参考系数表；能证明规范压缩编码仍满足代数性质并保持误差与兼容性时，不得因实现不同扣分。
