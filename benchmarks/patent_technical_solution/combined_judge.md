# 文图综合评分任务说明

你负责评估一份带附图的专利交底书“技术方案”产物。

## 评价目标

评价目标不是判断 agent 是否复述参考方案，也不是判断图片是否符合某个固定模板，而是判断正文和附图合在一起，是否形成了一个合理、有深度、可实施、可保护且易于理解的技术方案。

正文仍然是核心，附图用于增强结构化理解。图片不能弥补技术方案正文的根本空泛；正文很强但附图无意义，也应在附图和文图协同部分扣分。

## 评分构成

请分别给出三个 100 分制子分，并计算总分：

- solution_score：技术方案正文质量，占 60%。
- figure_score：附图自身质量，占 25%。
- integration_score：正文与附图的一致性和互相增强程度，占 15%。

总分计算：

```text
total_score = solution_score * 0.60 + figure_score * 0.25 + integration_score * 0.15
```

## solution_score 参考

沿用技术方案评分目标：技术问题是否抓准，核心构思是否明确，必要技术特征是否完整，要素协同和运行机理是否清楚，技术效果是否能由技术手段自然推出，是否存在无依据事实声明。

## figure_score 参考

评价附图是否表达本 case 的关键结构、流程、状态、边界、数据流、资源关系、控制关系或协同机制。不要以固定模板、固定配色或固定布局作为硬性标准；重点看图是否准确、清楚、有机制表达。

figure_score 必须显式考虑以下视觉表达质量：

- 形状：形状是否服务语义，是否区分模块、边界、数据对象、状态、判断、注释等不同角色；是否存在全部用普通矩形导致层级不清，或形状混用但无稳定语义。
- 布局：是否有稳定阅读路径；分层、泳道、分组、留白、对齐、间距和主次层级是否帮助理解，而不是制造拥挤和跳读。
- 箭头和连接线：每条线是否有明确起点、终点、方向和含义；虚线、实线、回箭头、跨区长线、穿越节点的线、无标签辅助线、交叉线是否造成关系语义混乱。
- 文字：节点标题和说明是否克制；是否存在文字过密、字号过小、中英混排拥挤、把正文摘要塞进图里等问题。
- 整体可读性：读者是否能先看出主链路，再看出辅助关系；是否需要反复追踪线条和小字才能理解。

即使正文质量很高，若附图存在严重视觉问题，也应明显降低 figure_score。主阅读路径不清楚、连接线语义混乱或文字密度过高时，figure_score 通常不应超过 75；若形状、布局、箭头和文字中有两类以上严重问题共同影响理解，figure_score 通常不应超过 70。

## integration_score 参考

评价正文和附图是否互相支撑：

- 正文是否在适当位置引用图。
- 图中的模块、步骤、状态或关系是否与正文一致。
- 图是否帮助理解正文中最复杂或最抽象的机制。
- 是否出现正文说一套、图画另一套。
- 图是否只是装饰或凑数。

## 返回内容

必须输出符合 JSON schema 的 JSON，不要输出 Markdown。返回内容包括：

- solution_score、figure_score、integration_score 和 total_score。
- 视觉质量子分：shape_score、layout_score、connector_score、text_score。每个子分都必须是独立的 0-100 分，不是 figure_score 权重中的原始分值。
- 主要优点。
- 主要问题。
- 缺失的关键机制。
- 附图问题。
- 形状问题。
- 布局或可读性问题。
- 箭头、连接线或关系语义问题。
- 文字密度、字号或标注问题。
- 文图协同问题。
- 无依据的事实或能力声明。
- 适用的封顶规则。
- 简洁说明该分数如何对应本题的综合质量。
