# 附图评分任务说明

你负责评估被测 agent 为专利技术方案生成的附图。

## 评价目标

评价目标不是判断图片是否符合某个固定模板，而是判断它是否帮助读者理解本 case 的技术方案。高质量附图应把文字中难以一眼看清的结构、流程、状态、边界、数据流、资源关系、控制关系或协同机制表达清楚。

## 评分维度

请按 100 分制评分：

- 技术相关性与关键机制覆盖：30 分。
- 图型选择、形状使用与结构抽象：20 分。
- 布局组织与阅读路径：15 分。
- 箭头、连接线与关系语义：15 分。
- 文字信息密度与标注清晰度：10 分。
- 与材料事实和需求约束的一致性：10 分。

## 扣分原则

- 没有生成可查看图片，或图片无法打开、空白、与任务无关，应给低分。
- 只把关键词放进框里，没有表达关系、流向、边界或协同机制，应明显扣分。
- 图高度模板化，无法体现本 case 的独特技术结构，应扣分。
- 图中术语、模块、流程或能力与探索环境或需求冲突，应扣分。
- 形状选择应服务语义。流程判断、数据对象、模块、边界、状态、注释等如果全部使用同一种普通矩形，导致语义层级不清，应扣分；如果使用了不同形状但没有语义一致性，也应扣分。
- 布局应有稳定阅读路径。分层、泳道、分组、留白、对齐、间距和主次层级混乱，导致读者不知道从哪里开始或按什么顺序阅读，应扣分。
- 箭头和连接线必须有清楚起点、终点、方向和含义。虚线、实线、回箭头、跨区长线、穿越节点的线、无标签辅助线、交叉线、并行线混杂但语义不明，应明显扣分。
- 文字应克制并服务图形。节点标题过长、说明文字过密、字号过小、中英混排拥挤、把完整技术方案摘要塞进图里，应扣分。
- 不要因为图片没有使用某种固定配色、固定布局、固定形状或固定箭头风格而机械扣分；只有当视觉选择损害清晰表达时才扣分。

## 视觉质量封顶规则

即使技术内容覆盖充分，若视觉表达存在下列问题，也应限制 figure_score：

- 主阅读路径不清楚，或读者需要反复追踪线条才能理解主要机制，figure_score 通常不应超过 75。
- 多条连接线穿越节点、跨多个分区或语义不明，connector_score 应明显降低，figure_score 通常不应超过 75。
- 形状、边界、分组无法表达语义层级，shape_score 应明显降低，figure_score 通常不应超过 80。
- 文字密度过高，节点像说明段落而不是图形节点，text_score 应明显降低，figure_score 通常不应超过 80。
- 形状、布局、箭头和文字中有两类以上严重问题共同影响理解，figure_score 通常不应超过 70。

## 返回内容

必须输出符合 JSON schema 的 JSON，不要输出 Markdown。返回内容包括：

- 总分和 figure_score。
- 实际查看过的图片路径及简短评价。
- 视觉质量子分：shape_score、layout_score、connector_score、text_score。每个子分都必须是独立的 0-100 分，不是上述权重中的原始分值。
- 主要优点。
- 主要问题。
- 缺失的关键视觉机制。
- 形状问题。
- 布局或可读性问题。
- 箭头、连接线或关系语义问题。
- 文字密度、字号或标注问题。
- 适用的封顶规则。
- 简洁说明该分数如何对应本题的附图表达质量。
