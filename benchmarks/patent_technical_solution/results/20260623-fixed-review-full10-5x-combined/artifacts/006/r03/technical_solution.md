## 技术方案

本方案面向以 Markdown 知识树保存共享知识的知识管理系统。下文将该可读、可版本控制、可同步的 Markdown 文件集合统一称为“共享知识文件层”，将本机保存的访问次数、检索命中、排序热度、近期使用时间、衰减值和临时成熟度证据统一称为“本机运行时信号层”。本方案解决的核心问题是：高频运行时信号不应污染共享 Markdown 的版本差异和合并结果，同时动态反馈仍需参与检索排序、知识整理和清理一致性判断。

### 核心不变量与术语约定

本方案遵循四个不变量：第一，共享知识文件层只保存稳定知识正文、层级关系、来源说明、稳定重要度和经审阅成熟度等低频字段；第二，本机运行时信号层只保存高频运行反馈，运行时事件不得直接写回共享 Markdown；第三，读取、检索和排序时以稳定条目标识 $K_i$ 将两层数据融合；第四，清理和迁移时以共享知识文件层的有效条目集合为准，本机信号只能跟随有效条目迁移、降权、归档或删除。

共享层的“经审阅成熟度”是人工或规则化审阅后写入 Markdown 的稳定结论，可取 draft、validated、core 等离散状态；本机层的“临时成熟度证据”是由命中、引用、近期使用和衰减得到的本机证据，只能在查询排序和生成审阅建议时参与计算，不得覆盖共享层经审阅成熟度。记录状态统一采用 active、conflict、orphan、pending-migration、tombstone、archived、deleted 等状态名表示。

### 分层存储结构

本方案将知识管理系统的数据划分为共享知识文件层和本机运行时信号层。共享知识文件层对应项目中的 Markdown 知识树，用于保存人可读、可审阅、可提交和可同步的知识条目，包括知识正文、目录层级、条目之间的显式引用、来源信息、稳定重要度以及经审阅成熟度。该层的变更必须能够解释为知识内容、知识结构或审阅结论的低频变化，而不能由单次访问、单次检索命中或单次排序计算触发。

| 层级 | 保存内容 | 写入触发 | 共享方式 |
| --- | --- | --- | --- |
| 共享知识文件层 | Markdown 正文、层级路径、显式引用、来源、稳定重要度、经审阅成熟度 | 人工整理、审阅确认、知识内容或结构变化 | 进入普通版本控制、同步和团队共享 |
| 本机运行时信号层 | 访问次数、检索命中、排序热度、近期使用时间、衰减值、临时成熟度证据 | 查询、点击、引用、排序反馈、定时衰减和清理任务 | 默认仅本机保存，不进入共享 Markdown diff |

### 条目标识与动态信号记录

每个 Markdown 知识条目首次进入索引时生成稳定条目标识 $K_i$，生成过程为“归一化—选主键—校验—冲突处理”。归一化时，来源根路径转换为固定来源标识，文件路径统一为相对来源根的路径、统一分隔符并消除“.”、“..”和符号链接跳转，文件编码转换为统一字符序列，标题变化不单独改变标识。选主键时，若 frontmatter 中存在唯一稳定标识，则 $K_i=sourceId:frontmatterId$；若不存在稳定标识，则 $K_i=sourceId:normalizedPath:contentDigest$，其中 $contentDigest$ 由去除空白差异和易变 frontmatter 字段后的正文摘要得到。不同来源根即使路径或摘要相同，也因 $sourceId$ 不同而隔离。

校验阶段在同一来源快照内检查 $K_i$ 是否唯一。若 frontmatter 标识重复、路径相同但内容摘要不一致、内容摘要相同但路径不同且无法确认是同一条目，系统不合并运行时信号，而是为冲突条目生成带序号或摘要后缀的次级标识，并将记录状态置为 conflict。conflict 状态的条目可以参与文本检索，但其历史热度不向其他条目迁移，直到人工确认或后续快照形成明确迁移映射。来源别名变更时，系统优先用来源根的规范化绝对路径或远程标识恢复 $sourceId$；无法恢复时按新来源建立新 $K_i$，旧记录进入 pending-migration。

| 字段 | 类型/范围 | 默认值 | 参与排序 | 写入位置 |
| --- | --- | --- | --- | --- |
| $K_i$ | 字符串，来源标识与条目标识组合 | 首次索引时生成 | 是 | 本机状态库，可由共享层稳定标识派生 |
| accessCount | 非负整数 | 0 | 间接参与热度 | 仅本机 |
| hitCount | 非负整数 | 0 | 间接参与热度 | 仅本机 |
| lastAccessAt | 时间戳或空值 | 空值 | 参与近期性 | 仅本机 |
| hotness | $[0,1]$ 浮点数 | 0 | 是 | 仅本机 |
| tempMaturityEvidence | $[0,1]$ 浮点数 | 0 | 是，但不得覆盖经审阅成熟度 | 仅本机 |
| confirmedMaturity | draft/validated/core | draft | 是 | 共享 Markdown，经审阅后写入 |
| decayHalfLife | 正数时间长度 | 系统默认值 | 影响热度衰减 | 仅本机或本机配置 |
| sourceType | local/shared-readonly/external | local | 影响来源权重和写入权限 | 本机记录及来源配置 |
| recordState | active/conflict/orphan/pending-migration/tombstone/archived/deleted | active | 决定是否参与检索 | 仅本机 |

运行时事件以 eventId、eventType、$K_i$、eventTime、sourceId、queryId 和可选反馈值作为输入。更新前先确认 $K_i$ 在当前共享层快照中存在且记录状态不是 tombstone、archived 或 deleted；若本机无记录，则以访问计数和命中计数为 0、热度为 0、临时成熟度证据为 0、状态为 active 初始化空记录。相同 eventId 或同一 queryId 下同一 $K_i$ 的重复点击在去重窗口内只计一次。访问事件使 accessCount 加 1 并更新 lastAccessAt；检索命中事件使 hitCount 加 1 并更新 lastHitAt；点击或引用事件在命中基础上增加较高反馈权重；排序反馈事件按用户停留、引用或忽略结果增减 feedbackWeight；定时衰减事件按半衰期降低 hotness 和临时成熟度证据。


其中，$H_i(t)$ 为事件更新后的热度，$T_h$ 为热度半衰期，$w_e$ 为事件类型权重，检索命中小于点击，点击小于实际引用；$clip_{[0,1]}$ 表示将结果钳制在 0 到 1。临时成熟度证据按相同方式累积引用、重复命中和审阅前正反馈，但其上限用于排序折算，不改变共享 Markdown 中的 confirmedMaturity。清理事件不增加热度，只改变 recordState、orphanSince、tombstoneSince 等状态字段。

高频事件先进入以内存哈希表为主体的缓冲队列，键为 $K_i$ 和时间窗口编号。同一窗口内同一 $K_i$ 的多个访问、命中和反馈事件被合并为计数增量、最大时间戳、最高反馈等级和去重后的引用集合。缓冲队列在达到事件数量阈值、时间窗口结束、进程空闲或显式关闭时批量落盘；每批落盘以本机状态库事务为边界，先写入批次号和聚合增量，再更新记录版本。落盘失败时保留缓冲批次并按退避策略重试；进程崩溃时允许丢失尚未落盘的低价值瞬时事件，但不得因此改写 Markdown，已提交批次通过批次号避免重放。

### 读取融合与排序计算

检索输入包括查询词、候选来源集合、共享层快照版本、索引版本以及本机运行时信号版本；输出为一次查询上下文中的排序列表和反馈更新事件。系统先从共享知识文件层解析 Markdown 条目并建立全文索引、路径索引和引用关系索引，按文本相关度得到候选条目。候选条目仅存在于共享层而本机无记录时，排序阶段使用零热度、默认近期性和默认临时成熟度证据，并可在查询结束后惰性创建空记录；本机有记录但共享层有效集合中不存在的条目不得进入检索候选，只能进入迁移或清理判断。

参与融合的各项指标先归一化到 $[0,1]$。$BM25_i$ 在本次候选集合内按最大最小值或排序分位归一化；$I_i$ 由共享层稳定重要度映射得到，缺省为中性值；共享层经审阅成熟度映射为 draft、validated、core 对应的离散分值，临时成熟度证据只在该离散分值基础上提供不超过预设上限的加成；$H_i$ 由热度衰减公式得到；$R_i$ 根据距离 lastAccessAt 或 lastHitAt 的时间间隔按半衰期衰减，缺省为 0；$P_i$ 在条目解析失败、来源不可用、记录处于 conflict、orphan、pending-migration 或来源超过有效期时触发，并按严重程度取值。


其中，$BM25_i$ 表示共享 Markdown 内容与查询的文本相关度，$I_i$ 表示共享层稳定重要度，$M_i$ 表示经审阅成熟度与本机临时成熟度证据的合成值，$H_i$ 表示访问、引用和命中形成的热度，$R_i$ 表示近期性，$P_i$ 表示失效、孤儿、来源不可用、冲突或只读源过期等惩罚项，$\alpha$ 至 $\zeta$ 为非负可配置权重并可归一化为总和不超过 1。公式输出只用于本次查询排序、本机缓存和反馈事件生成，不写入共享 Markdown。

排序裁决按固定顺序执行：先排除 tombstone、archived、deleted 和有效路径不存在的条目，再按文本相关度门槛过滤明显不相关条目，然后计算综合得分并排序。若共享层稳定重要度较高但本机热度较低，条目仍保留稳定重要度贡献；若本机热度高但文本相关度低于门槛，则不能仅凭热度进入结果。得分相同时，依次按来源权重、经审阅成熟度、较低惩罚项、较近使用时间和规范化路径字典序进行 tie-break，以保证排序稳定。

当系统存在多个知识来源时，先在各来源内部完成文本检索、指标归一化和本机信号融合，再进行跨源合并。跨源合并时将来源权重乘入来源内综合得分，来源权重由来源类型、用户配置、是否只读、最近可用性和同步状态确定；只读属性主要限制写入路径，也可在来源过期或不可访问时形成惩罚。若多个来源返回同一稳定标识或同一来源根下等价内容，系统保留得分最高的主结果，并将其他来源作为辅助来源附加；若只是摘要相同但来源不同，则不自动去重。来源暂时不可用时，只能使用带快照版本且未过期的本机索引缓存，并在结果中施加来源不可用惩罚；缓存过期时不返回该来源结果，避免引用失效位置。

### 写入隔离与审阅触发

本方案设置两条相互隔离的写入路径并通过写入守卫执行。运行时信号更新接口只持有本机状态库和内存缓存的写权限，其输入仅为运行时事件和 $K_i$，不能打开共享 Markdown 的写句柄；Markdown 写入接口只接受知识整理、审阅确认或版本控制路径提交的低频结论。提交或同步前，系统检查共享 Markdown diff 中是否出现 accessCount、hitCount、hotness、lastAccessAt、lastHitAt、feedbackWeight、tempMaturityEvidence 等禁止字段；发现禁止字段时拒绝提交、回滚对应写入或将其转为本机信号记录。

审阅建议由观察窗口触发而非由单次事件触发。系统按日、周或固定事件数量形成观察窗口，连续多个窗口满足阈值时才生成建议：命中和引用持续升高且热度衰减后仍超过阈值时，生成提升成熟度或补充核心说明建议；长期未命中、来源多次不可用或惩罚项持续升高时，生成降权、核验或清理建议；同一条目的重复建议在冷却期内合并为一条，并累积证据摘要。建议状态包括 pending、confirmed、rejected、expired；pending 状态可随新信号重新计算，confirmed 后仅允许把经审阅成熟度、稳定重要度或结构调整等低频结论写入共享层，rejected 后进入冷却期，expired 则仅保留本机审计记录。人工审阅结论优先于规则化审阅结论。

### 清理、迁移与一致性维护

清理机制以共享知识文件层的快照构造有效条目集合 $S$：系统解析当前来源根下可读 Markdown，完成标识生成和冲突校验，排除解析失败且无有效标识的文件，得到可检索条目集合；本机运行时信号层的记录集合 $R$ 由当前来源、已登记共享源及其未过期迁移映射范围内的本机记录组成。若 $R$ 中某条记录的 $K_i$ 不存在于 $S$ 且没有匹配到迁移目标，则该记录由 active 转为 orphan，记录 orphanSince、lastSeenSnapshot 和原路径，并立即从检索候选中排除或施加最高惩罚。

| 状态 | 进入条件 | 参与检索 | 可迁移 | 退出条件 |
| --- | --- | --- | --- | --- |
| active | $K_i$ 存在于有效集合 $S$ 且无冲突 | 可以 | 可以 | 删除、冲突、迁移或清理触发 |
| conflict | 同一快照内标识重复或来源归属不确定 | 受惩罚参与 | 需确认后迁移 | 冲突解除或转为新标识 |
| orphan | 本机记录存在但共享层无对应有效条目 | 不作为正常候选 | 可以 | 匹配迁移目标、转 tombstone 或归档 |
| pending-migration | 存在低置信度迁移候选或来源别名变化 | 不直接参与或带高惩罚 | 待确认 | 确认迁移、降权保留或转 orphan |
| tombstone | 确认条目删除或来源长期不可用 | 不参与 | 仅保留删除证据 | 保留期满后归档 |
| archived | 保留期满但仍需压缩审计 | 不参与 | 不可自动迁移 | 压缩包过期后删除 |
| deleted | 归档过期或明确无需保留 | 不参与 | 不可迁移 | 物理删除完成 |

对于移动或重命名的 Markdown 条目，系统按稳定标识、迁移映射、内容摘要相似度和路径相似度的顺序匹配旧 $K_i$ 与新 $K_i$。内容摘要相似度高于迁移阈值且候选唯一时，历史热度、成熟度证据和近期性转移到新条目；多个新条目竞争同一旧记录时，若能识别拆分关系，则按新条目文本覆盖比例或引用关系分配历史信号，否则进入 pending-migration；多个旧条目合并为一个新条目时，仅合并经确认来源相同或迁移关系明确的记录。匹配置信度低于阈值时，不转移热度，只保留旧记录并降低权重或等待人工确认。

在分支切换、远程拉取、共享源更新或清理任务执行后，系统为共享层快照、派生索引和本机信号记录分别记录版本号，并要求检索时使用同一共享层快照对应的索引版本；运行时信号可采用不早于该快照的最近可用版本。若切回旧分支后某 $K_i$ 重新出现在有效集合中，未归档的 tombstone 或 orphan 记录可恢复为 active，并重置保留期限；若索引重建失败，系统不得返回可能失效的新候选，可以降级为使用仍与当前快照匹配的旧索引，或返回空结果并提示需要重建。来源短暂不可用时保留本机记录但施加惩罚，超过保留期限后转为 tombstone。

清理任务与检索任务并发时采用快照读和版本化写入。检索开始时固定共享层快照和索引版本，生成候选后在返回前二次校验候选 $K_i$ 的 recordState 和有效路径；若清理任务在检索期间将记录置为 tombstone，则该候选被移除或重新排序。孤儿记录压缩归档时保存 $K_i$、原路径、来源标识、最后热度、最后使用时间、状态变更时间和迁移候选摘要，不保存完整访问日志；归档期满后才物理删除，以减少本机状态库噪声并保留必要恢复依据。

### 异常与边界处理

Markdown 解析失败时，系统不把该文件作为正常候选；若能从路径和历史记录恢复 $K_i$，则以惩罚项参与必要的诊断结果，否则只记录解析错误并等待下次索引。本机状态库损坏时，系统先隔离损坏文件并从共享层重建空信号记录和派生索引，检索仍可依赖文本相关度运行，但热度、近期性和临时成熟度证据降级为默认值；损坏库恢复后按记录版本合并未过期记录。

文件锁定或权限不足时，运行时信号更新仍只写入本机缓冲；若本机状态库也不可写，则在内存中保留有限大小的最新聚合事件，超过容量后按低权重事件优先丢弃。系统时间异常时，近期性计算采用单调时钟或事件序号保证相对顺序，检测到时间回拨时不增加近期性奖励。缓存、索引和本机状态库版本不一致时，以共享层快照版本为检索边界，缓存结果必须在返回前重新校验 $K_i$、recordState 和有效路径。
