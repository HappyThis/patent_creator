## 技术方案

### 分层存储总体架构

本方案将知识管理系统中的数据划分为共享知识文件层和本机运行时信号层。共享知识文件层仍以 Markdown 文件作为团队协作的知识载体，用于保存标题、标签、关联关系、摘要、正文叙述、事实片段等低频且需要被审阅、同步和版本控制的知识内容；本机运行时信号层用于保存访问次数、检索命中、排序权重、近期使用、成熟度调整、清理候选状态等会随查询和后台整理频繁变化的运行信号。二者不以同一个 Markdown frontmatter 作为唯一状态源，而是通过稳定的知识标识建立关联，从而使共享文件的内容变更和运行反馈变更在存储层面分离。

知识标识按确定性规则生成：先取得来源标识 $source\_id$、规范化相对路径 $path\_norm$、节点类型 $node\_type$ 和工作区维度 $workspace\_id$，再计算 $knowledge\_id=hash(workspace\_id + ':' + source\_id + ':' + node\_type + ':' + path\_norm)$。其中，$workspace\_id$ 用于区分不同项目或分支工作区，缺失时取当前项目根路径的规范化哈希；$path\_norm$ 统一采用相对 context tree 根的 POSIX 分隔符、去除 `.` 和重复斜杠、去除首尾斜杠，并按预设策略进行大小写归一；$source\_id$ 对本地来源取固定值 `local`，对共享来源取来源 URL、仓库标识或配置路径的规范化哈希，缺失时生成本机隔离的临时来源标识并标记为不可跨设备合并。内容版本指纹 $content\_fingerprint$ 由去除运行态字段后的 Markdown 稳定内容计算得到，不参与主键生成，而用于判断同一知识标识下是否发生内容版本变化。

同一路径来自不同来源时，由于 $source\_id$ 不同而形成不同的 $knowledge\_id$，本机信号互不覆盖；若两个共享来源规范化后得到相同 $source\_id$，系统将配置顺序、实际根路径哈希或来源别名纳入冲突后缀，生成隔离来源标识，并在运行态结果中保留来源信息。若本地知识与共享知识具有相同符号路径，检索时可以并列展示或按来源优先级排序，但访问反馈只写入用户实际选择或结果返回项对应的 $knowledge\_id$。

对于已经存在于 Markdown frontmatter 中的评分字段，例如重要性、近期性、成熟度、访问次数、更新时间和更新次数，可以在首次读取或迁移时作为本机信号层的初始值；后续由查询、排序、衰减或清理流程产生的高频变化优先写入本机信号层。只有当知识正文、标题、标签、关联关系、摘要或经人工确认的稳定属性发生变化时，才更新共享 Markdown 文件。

### 核心数据对象与迁移规则

本方案使用如下核心数据对象。来源标识 $source\_id$ 表示知识所属的本地或共享来源；内容指纹 $content\_fingerprint$ 表示去除运行态评分字段后的 Markdown 稳定内容版本；符号路径 $symbol\_path$ 表示面向用户和检索树的层级路径；摘要节点表示目录或主题层级的聚合视图；归档桩节点表示原知识被归档后的轻量入口，包含原路径、归档目标和归档时的重要性等稳定引用信息。

本机信号记录以 $knowledge\_id$ 为主键，并至少包含 $source\_id$、$content\_fingerprint$、$access\_count$、$last\_hit\_at$、$importance\_delta$、$recency\_score$、$maturity\_level$、$maturity\_lock$、$cleanup\_state$、$last\_keep\_at$、$branch\_id$、$updated\_at$、$schema\_version$ 和 $migration\_version$。其中，$access\_count$ 为非负整数，$importance\_delta$ 和 $recency\_score$ 被限制在预设范围内，$maturity\_level$ 在 draft、validated、core 中取值，$cleanup\_state$ 由清理状态机限定。无论底层采用结构化文件、轻量数据库还是追加日志，均要求支持按项目目录和来源隔离、按 $knowledge\_id$ 原子追加或事务更新、按 schema 版本迁移以及按知识标识删除、迁移和标记状态。

运行态知识视图在索引构建、查询执行或上下文注入前创建。其输入为已解析的 Markdown 稳定内容、本机信号记录、来源配置、当前分支或工作区状态以及 schema 兼容性校验结果；输出为包含正文、符号路径、来源、内容指纹、融合评分和清理状态的临时对象。运行态知识视图可以被索引和缓存序列化，但不得反向覆盖 Markdown；其中由查询产生的增量只能写回本机信号层，由人工确认或稳定整理产生的内容变化才进入共享 Markdown。

首次迁移 frontmatter 评分字段时，系统按知识标识读取 Markdown 中的重要性、近期性、成熟度、访问次数、更新时间和更新次数，并映射为本机信号记录的初始人工重要性、初始近期性、初始成熟度、初始访问基线、内容更新时间和迁移版本。若本机信号记录不存在，则创建记录并写入 $migration\_version$；若记录已存在且迁移版本相同，则跳过以保证幂等；若记录已存在但 Markdown 中的稳定字段发生团队同步更新，仅允许刷新人工重要性、人工成熟度和内容更新时间，不覆盖 $access\_count$、$last\_hit\_at$、$importance\_delta$ 等本机累计反馈。

人工稳定字段、迁移初值、运行反馈增量、后台衰减结果和清理决策状态之间采用分层优先级：人工锁定的成熟度和人工确认的重要性优先于后台推断；迁移初值仅在没有本机记录或迁移版本升级时作为基线；访问反馈只形成增量并受上限约束；时间衰减仅更新运行态近期性或本机衰减字段；清理状态只能由清理状态机转移，不得被一次普通查询命中直接清除。

### 运行时信号的本机化采集

运行时信号由检索服务、查询执行器、后台整理任务和生命周期管理任务在本机侧采集。一次查询返回结果后，系统以本次结果列表中的 $knowledge\_id$ 去重生成访问增量；同一查询中同一知识多次出现只计一次命中，父摘要节点和其子正文节点同时出现时分别记录候选命中，但在评分传播阶段去重。缓存命中若实际向用户返回了知识结果，则计入访问次数；失败查询和无结果查询不增加知识访问次数，但记录查询日志、未命中词和执行状态，用于后续判断知识缺口。

内存合并表以 $knowledge\_id$ 为键，保存本轮未落盘的 $hit\_delta$、$last\_hit\_at\_max$、$query\_sample$、$importance\_delta\_add$ 和待转移的 $cleanup\_state$。触发落盘的条件包括达到时间窗口、增量数量超过阈值、索引重建前置步骤、进程正常退出或后台任务提交。落盘时访问次数执行加法合并，最近命中时间取最大值，重要性增量按上限截断累加，近期性取当前衰减值与命中增强值的较大者，清理状态按状态机优先级转移，成熟度按带滞回规则处理。

并发写入通过单项目互斥锁、乐观版本号或事务日志控制。每个批次分配 $batch\_id$，先写入包含批次号和增量明细的写前日志，再执行本机信号记录更新，最后写入提交标记；采用文件实现时使用临时文件加原子替换，采用数据库实现时使用事务提交。进程异常退出后，系统扫描未完成批次：已提交但未清理日志的批次不重复应用，未提交批次按 $batch\_id$ 和增量幂等键重新应用或回滚，从而避免访问次数丢失或重复累加。

后台整理任务写入的信号按事件类型合并：被判定为清理候选时进入 $cleanup\_candidate$，人工或模型保留结论写入 $kept$ 并记录 $last\_keep\_at$，待合并对象写入 $merge\_candidate$ 并记录目标知识标识，完成归档后写入 $archived\_attached$ 并关联归档桩，来源不可用或文件缺失时写入 $orphan$ 或 $pending\_confirm$。这些状态不通过修改共享文件时间戳表达，而是保存在本机信号记录中。

该层的写入不触发共享 Markdown 文件的内容变化，也不应更新共享文件的修改时间作为使用状态标记。对共享来源或只读来源中的知识，运行反馈同样写入本机信号层，并在信号记录中保留来源标识；本机用户可以获得个性化排序和清理提示，而不会把个人查询行为反向写入团队共享知识文件。

### 读取融合与评分排序

检索或上下文注入时，系统先读取共享 Markdown 文件并解析其中的稳定内容与可迁移的初始元数据，再按知识标识加载本机运行时信号，合成为一次查询中的运行态知识视图。该运行态视图只存在于索引、缓存或查询执行上下文中，不直接覆盖 Markdown 文件。对于缺失本机信号的知识，系统使用默认评分或从 Markdown frontmatter 迁移得到的初值，以保证新增知识和历史知识均可被检索。

排序时，系统将文本相关性、综合重要性、运行态近期性和成熟度合成为综合评分。文本相关性 $R$ 由 BM25 或同类全文检索分值归一化到 $[0,1]$；综合重要性 $I$ 由人工重要性基线与本机访问、更新、整理反馈增量相加后截断到 $[0,100]$，再归一化到 $[0,1]$；运行态近期性 $T$ 由内容更新时间和最近命中时间共同计算，取二者衰减得分的加权最大值或加权和并截断到 $[0,1]$；成熟度 $M$ 在 draft、validated、core 中取值，并映射为成熟度系数。缺失字段按默认值处理：$R=0$，人工重要性为中值，近期性为初始值，成熟度为 draft。

近期性衰减可以采用指数函数 $T=e^{-d/\tau}$，其中 $d$ 为距离内容更新或最近命中的天数，$\tau$ 为衰减周期。访问反馈对重要性的增量设置单次上限和总上限，例如同一查询去重后仅增加一次命中，单位时间窗口内的累计增量不超过预设阈值，防止热门但低质量的短期访问压倒人工重要性。成熟度系数表可设置为 draft 小于 1、validated 等于或接近 1、core 大于 1，使核心知识在相关性接近时优先进入结果和上下文。

成熟度采用带滞回的状态转移规则。draft 升级为 validated 需要满足人工确认、稳定命中次数或整理任务验证条件中的至少一类，并且评分连续超过升级阈值；validated 升级为 core 需要更高的重要性、持续命中或人工锁定条件。降级只有在连续低命中、内容长期未更新、清理任务判定质量不足或来源失效等条件持续超过降级窗口时发生；升降级之间设置最小保持时间。若 $maturity\_lock$ 被人工设置，则后台访问波动和衰减不得覆盖该成熟度，只能生成待确认建议。

摘要节点向父级传播时，以命中的子节点列表作为输入，以父级摘要候选及其传播分数作为输出。传播分数按子节点评分的最大值与前若干高分子节点的截断加权平均合成，传播深度限制在当前查询范围内的有限层级，归档桩节点默认只传播到归档入口，不继续放大到更高层级。若父摘要和子正文同时命中，系统保留分数较高或更适合上下文容量的一项，并在访问增量中按 $knowledge\_id$ 去重，避免同一知识链路重复加分。

结果竞争和上下文注入采用稳定裁剪规则：先按综合评分降序排列，再依次按成熟度、人工重要性、最近内容更新时间、来源优先级和 $knowledge\_id$ 排序。同分时优先保留人工重要性更高、成熟度更高且来源更接近当前工作区的结果；成熟度低但相关性显著高的结果可以进入候选，但在上下文容量不足时位于已验证或核心知识之后；父摘要与多个子正文竞争时，若容量较小则保留摘要，若容量足够且子正文相关性更高则保留子正文并剔除重复摘要。

### 写入边界与清理一致性

本方案为共享 Markdown 文件设置明确的写入边界：内容新增、内容修改、人工整理后的稳定摘要、关系调整、归档桩生成等会改变团队知识表达的操作，可以写入共享知识文件；访问次数累加、检索命中、排序权重微调、近期性衰减、缓存命中、个体使用偏好以及仅用于清理判断的临时状态，不写入共享 Markdown。通过该边界，版本控制系统看到的差异主要对应真实知识内容变化，而不是查询次数或后台评分的噪声。

| 操作或信号 | 写入位置 | 判定规则 |
| --- | --- | --- |
| 内容新增或正文修改 | 共享 Markdown | 知识正文、标题、标签、关联关系等稳定内容发生变化时写入。 |
| 人工整理后的稳定摘要 | 共享 Markdown | 经过人工确认或低频整理确认可被团队复用时写入摘要或索引文件。 |
| 关系调整或归档桩生成 | 共享 Markdown | 改变团队知识结构、归档入口或引用关系时写入。 |
| 访问次数、检索命中、缓存命中 | 本机信号层 | 由查询产生，按 $knowledge\_id$ 去重累加，不修改 Markdown。 |
| 近期性衰减、排序权重微调 | 本机信号层或运行态视图 | 由时间和反馈计算产生，不更新共享文件 mtime。 |
| 清理候选、人工保留、待合并 | 本机信号层 | 作为 $cleanup\_state$ 状态转移保存。 |
| 临时评分、上下文裁剪结果 | 运行态视图 | 仅服务本次索引或查询，不持久化到 Markdown。 |

清理和整理流程先扫描共享 Markdown 文件、摘要节点和归档桩节点，生成当前有效知识集合，再与本机信号记录进行一致性校验。清理状态机包括 $active$、$cleanup\_candidate$、$kept$、$merge\_candidate$、$archived\_attached$、$orphan$、$pending\_confirm$ 和 $deleted$。有效知识默认处于 $active$；重要性低、长期未命中或整理任务判定可清理时进入 $cleanup\_candidate$；人工或模型确认保留时进入 $kept$ 并记录保留时间；需要并入其他知识时进入 $merge\_candidate$；归档完成且存在归档桩时进入 $archived\_attached$；知识文件缺失或来源暂不可达时进入 $orphan$ 或 $pending\_confirm$；保留窗口届满且无可恢复关联时进入 $deleted$。

状态转移遵循优先级和禁止覆盖规则：$deleted$ 为终止状态，除人工恢复外不得被普通查询命中重新激活；$archived\_attached$ 只影响归档入口排序，原知识信号不再参与正常正文检索排序；$merge\_candidate$ 在合并完成前不得被自动删除；$kept$ 在最小保留期内不得因短期衰减重新进入清理候选；$pending\_confirm$ 表示置信度不足，禁止将旧信号自动附着到新文件。普通访问命中只能更新访问类字段，不能越过清理状态机直接清除归档、删除或待确认状态。

孤立信号按固定顺序处理。首先检查是否存在显式重命名映射或合并目标，存在时将信号迁移到新 $knowledge\_id$ 并保留原标识别名；其次比较内容指纹、标题和关键片段相似度，置信度达到阈值时迁移，否则进入 $pending\_confirm$；再次检查归档桩是否指向原路径或原指纹，存在时将信号附着到归档入口；再检查共享来源是否只是临时不可用，若是则保留为 $orphan$ 并暂停参与排序；最后在保留窗口届满且无恢复依据时删除。新文件复用旧路径但内容指纹完全不同的，禁止继承旧访问热度，除非存在人工确认或显式重命名映射。

对于版本回退、分支切换或团队同步导致的文件集合变化，系统重新计算共享内容指纹、来源文件指纹和索引缓存指纹；若指纹不一致，则使旧索引和查询缓存失效并基于当前有效知识集合重建。本机信号记录保留 $branch\_id$ 或工作区维度：与当前分支匹配的记录直接参与融合；不匹配但来源和内容指纹可恢复匹配的记录在切回原分支时恢复；不匹配且无法确认的记录降级为 $pending\_confirm$ 或 $orphan$，不参与正常排序。不同分支对同一知识产生的运行反馈默认隔离，只有在内容指纹或人工合并确认一致时才合并访问和重要性增量。

通过上述机制，高频访问、检索命中、近期性衰减和排序微调只更新本机信号层或运行态视图，不写入共享 Markdown，也不更新共享文件的修改时间；共享内容指纹和索引缓存指纹只依赖稳定 Markdown 内容、来源配置和摘要/归档等稳定结构，不把本机运行信号纳入共享内容差异；运行态视图失效时只重建索引或查询上下文，不触发摘要、manifest 或共享文件重写。由此，版本控制系统中的变更主要对应真实知识内容和结构变化，减少脏状态、合并冲突、噪声差异以及由非内容性运行反馈引发的缓存无效化。
