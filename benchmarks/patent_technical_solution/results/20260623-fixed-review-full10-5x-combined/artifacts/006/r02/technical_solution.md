## 技术方案

### 总体分层架构

本方案面向以 Markdown 文件承载项目知识、同时在本机持续产生检索命中、访问、点击、排序反馈和文件变化信号的知识管理系统。系统输入包括 Markdown 知识文件、外部或共享知识源清单、用户检索与访问事件、人工整理操作以及文件系统变化快照；系统输出包括可提交和审阅的共享 Markdown 知识文件、本机运行时状态库、检索索引、融合排序结果以及清理或迁移后的信号状态。本方案解决的问题是：高频运行时反馈不再反复改写共享 Markdown，版本控制只呈现真实知识内容变化，同时本机排序仍持续利用动态反馈。

本方案将知识管理系统中的知识文件划分为“共享知识层”和“本机运行时信号层”。共享知识层以 Markdown 文件及其 YAML frontmatter 承载可被团队共享、审阅和版本控制的稳定内容，包括标题、摘要、标签、关联路径、关键词、正文事实、推理说明和人工确认的成熟度等低频字段；该层作为 Git 或类似版本控制系统中的可读知识源，只有在知识内容、人工审阅结论或稳定元数据发生实质变化时才产生文件写入。

本机运行时信号层设置在用户设备或项目工作区的本地状态库中，统一保存访问累计值、检索命中累计值、最近使用时间、热度、近期性衰减基准、临时排序权重、文件轻量签名和反馈事件处理状态。该状态库的底层载体可以是 SQLite、JSONL、LevelDB 或键值缓存，但必须满足按知识标识原子更新、按事件标识幂等去重、按来源和状态批量扫描的语义，并被配置为不随共享 Markdown 知识文件提交到团队仓库。

系统在知识整理、检索和跨来源查询时同时识别本地可写知识源、只读共享知识源和外部 Markdown 来源。来源一旦被标记为只读，普通检索、访问反馈和本机排序更新均不得写回来源文件；来源从可写变为只读时，未落盘的反馈事件只允许写入本机状态库；来源从只读变为可写时，历史本机反馈仍不自动回灌到 Markdown，除非发生明确的人工整理或稳定元数据迁移操作。由此，知识内容的协作边界与运行时排序反馈的个性化边界相互分离。

### 数据模型与术语约定

本方案中，“知识源”表示一个本地上下文树、共享上下文树或外部 Markdown 文件夹；“知识文件节点”表示可被索引的一份 Markdown 原始知识文件；“段落节点”表示同一 Markdown 文件内可独立引用的标题段、事实段或片段；“目录节点”表示领域、主题或子主题目录；“派生摘要节点”表示由原始知识生成的摘要、概览或索引文件。动态信号默认绑定到知识文件节点；当系统启用段落级检索时，段落节点的标识在文件节点标识后追加段落定位信息，目录节点和派生摘要节点只参与聚合展示，不作为普通访问反馈的独立累计对象。

| 数据对象 | 所属层 | 关键字段 | 更新规则 |
| --- | --- | --- | --- |
| 共享 Markdown frontmatter | 共享稳定数据 | title、summary、tags、related、keywords、manualMaturity、stableImportance、schemaVersion | 仅在知识内容、人工审阅或稳定元数据变化时写入 |
| 知识标识表 | 本机映射数据 | knowledgeId、sourceId、relativePath、nodeType、nodeLocator、stableFingerprint、lastLightSignature、version | 索引构建或文件变化扫描时生成或更新 |
| 运行时信号表 | 本机动态数据 | knowledgeId、hitCount、openCount、clickCount、lastHitAt、lastOpenAt、hotness、recencyBaseAt、localMaturityDelta、status、rowVersion | 反馈事件聚合时事务更新，检索时按快照读取 |
| 反馈事件队列表 | 本机动态数据 | eventId、knowledgeId、eventType、eventTime、delta、sourceId、status、retryCount | 事件产生时追加，落库成功后标记已处理 |
| 迁移映射与悬空表 | 本机一致性数据 | oldKnowledgeId、newKnowledgeId、reason、confidence、state、expiresAt | 文件移动、复制、删除或来源不可达时写入 |

本方案统一区分“轻量签名”和“稳定内容指纹”。轻量签名由相对路径、文件修改时间和文件大小组成，用于快速判断索引缓存是否需要复用或重建；稳定内容指纹由规范化后的标题、稳定标签集合、稳定关键词集合、正文主体和人工成熟度等字段计算，用于判断路径变化后的知识连续性。访问次数、命中次数、热度、近期性、临时排序权重、动态 frontmatter 迁移标记和本机更新时间不参与稳定内容指纹计算；标签和关键词在计算前按字典序排序，换行统一为同一换行符，连续空白归一化，以降低非语义格式变化对迁移判断的影响。

### 知识标识与动态信号绑定

知识标识按照确定的规范化顺序生成：先将来源根目录或 provider 别名规范化为 `sourceId`，再将 Markdown 文件相对路径统一为小写或平台无关大小写形式、以 `/` 作为路径分隔符、移除 `.` 和 `..` 片段并解码重复转义，随后拼接节点类型 `nodeType`、节点内定位信息 `nodeLocator` 和稳定内容指纹 `stableFingerprint`，形成 `knowledgeId = hash(sourceId + "|" + relativePath + "|" + nodeType + "|" + nodeLocator + "|" + stableFingerprint)`。当同一文件包含多个段落节点时，`nodeLocator` 采用标题层级、段落序号和段落稳定摘要共同确定；文件级节点的 `nodeLocator` 为空值或固定值。

本机运行时信号层以 `knowledgeId` 为主键记录动态状态。`hitCount` 表示检索结果被展示或命中的次数，`openCount` 和 `clickCount` 表示用户进一步打开或点击的次数，`lastHitAt` 和 `lastOpenAt` 作为近期性衰减基准，`hotness` 为由近期事件累积并随时间衰减的本机热度，`localMaturityDelta` 只作为本机排序修正值参与计算，不覆盖共享 Markdown 中人工确认的成熟度，也不作为人工成熟度展示。目标节点已有较新 `rowVersion` 或较新的最近使用时间时，外部迁移或合并不得直接替换目标记录，只能按合并规则累加、取最大或保留较新值。

当知识文件发生移动、重命名或伴随轻微编辑时，系统按多级候选匹配算法保持标识连续性。第一优先级是在同一 `sourceId` 内进行精确相对路径匹配；第二优先级是在同一来源内进行稳定内容指纹完全匹配；第三优先级是在同一来源内计算标题、稳定标签、关键词和正文摘要的相似度，只有候选唯一且综合置信度达到预设阈值时才迁移动态信号。若多个旧信号匹配同一新文件、一个旧信号匹配多个新文件、复制文件导致指纹相同、或标题标签重复导致置信度不足，系统不自动迁移，而是将旧信号置为悬空状态并记录待确认映射。

### 反馈事件与批处理入库

反馈事件由检索展示、检索命中、用户点击、打开知识文件、复制引用、人工标记有用或人工标记无用等动作产生。每条事件写入反馈事件队列表时携带 `eventId`、`knowledgeId`、`eventType`、`eventTime`、`delta`、`sourceId` 和处理状态；其中 `eventId` 由设备标识、事件时间、递增序列或随机数生成，保证同一设备内唯一。检索结果仅展示但未点击时产生较小的 `hit` 增量，用户打开或点击时产生较大的 `open` 或 `click` 增量，人工正反馈增加热度和本机成熟度修正，人工负反馈降低热度或增加降权标记。

反馈队列批处理以事务方式执行。处理器先读取状态为 pending 或 retry 的事件，按 `eventId` 去重，再按 `knowledgeId` 聚合增量；落库前校验知识标识仍为 active 或 migrated，若已迁移则改写到新标识，若为 orphan 或 archived 则暂停累计并保留事件。事务内同时更新运行时信号表、事件处理状态和行版本；只有运行时信号更新成功后，事件才被标记为 processed。若进程崩溃发生在落库之后、标记之前，恢复时通过 `eventId` 幂等表识别已应用事件，避免访问次数重复累计。

队列聚合规则为：同一批次内的命中次数、打开次数和点击次数分别求和，最近命中时间和最近打开时间取最大时间，热度按事件权重累加后再按当前时间进行衰减，`localMaturityDelta` 被限制在预设上下界内。状态库不可用时，检索仍可基于静态索引返回结果，并将反馈事件保留为 pending 或写入本地临时日志；重试次数超过阈值后事件进入 failed 状态，但不写入共享 Markdown 作为补偿。

### 检索读取融合机制

检索时，系统首先扫描共享知识层中的 Markdown 文件，读取正文、标题、路径、标签、关键词、关联关系、稳定重要性和人工成熟度等静态特征，并根据轻量签名判断索引是否需要重建。派生摘要节点通过文件命名后缀、路径规则、frontmatter 中的生成标记、派生源 `sourceKnowledgeId` 或生成器标识识别；识别成功的派生摘要只参与摘要展示或父级聚合，不作为普通访问反馈的独立累计对象。若派生标记缺失或与文件命名冲突，系统将该文件按低优先级普通知识索引，但不自动继承原始知识的动态信号，避免错误累计。

在获得候选文档后，系统对文本相关度进行归一化，例如将 BM25 原始分转换为 `textScore = rawScore / (1 + rawScore)`，再读取对应 `knowledgeId` 的本机动态信号。最终排序分数按如下规则计算：`finalScore = sourceWeight × clamp(0.55×textScore + 0.15×stableImportance + 0.10×manualMaturity + 0.10×recencyScore + 0.10×hotnessScore + localMaturityDelta, 0, 1)`。其中稳定重要性、人工成熟度、近期性和热度均归一化到 0 至 1；动态信号缺失时，命中、打开和点击计数取 0，近期性取默认初始值，热度取 0，`localMaturityDelta` 取 0；来源不可达或来源权重缺失时使用默认来源权重，但只读标记仍阻止反馈写回 Markdown。

近期性和热度在查询时惰性计算。系统以 `lastHitAt`、`lastOpenAt` 或 `recencyBaseAt` 中最新时间为衰减基准，按照 `recencyScore = exp(-daysSinceBase / halfLife)` 或等价分段衰减规则得到近期性分数；热度先由历史事件权重累计，再按同一时间差衰减得到 `hotnessScore`。衰减结果只参与本次排序，状态库中可记录本次读取时间和行版本，但不因普通查询把新的近期性、热度或排序权重写回共享 Markdown；计算结果越界时按 0 至 1 截断。

对于树状知识目录，系统将叶子知识文件节点的 `textScore` 和 `finalScore` 沿父级目录节点传播。父级候选分数由其子节点中最高分、前若干个子节点平均分和命中子节点数量共同计算，例如 `parentScore = maxChildScore×0.6 + avgTopChildScore×0.3 + coverageScore×0.1`，并乘以目录层级衰减因子。父级候选与叶子候选进入同一排序队列竞争；当父级摘要与叶子节点同时出现时，若父级分数低于最高叶子分数的预设比例则只作为 relatedPaths 或 overview 展示。父级目录和派生摘要默认不累计普通访问反馈，用户明确打开父级摘要时才产生目录级反馈事件。

### 文件变化检测与信号迁移

文件变化检测由索引构建、文件监听或定期扫描触发。执行前，系统先获取知识源清单和来源标识，读取当前文件快照，生成每个 Markdown 文件的轻量签名和稳定内容指纹，并在一个扫描批次内保持快照一致。检索读取动态信号时采用快照读或行版本号；清理流程迁移或删除信号时采用事务或乐观版本校验，若发现行版本已变化则重新读取并重算，避免检索结果引用已删除索引或反馈写入旧标识。

系统将每个知识节点的动态信号状态划分为 active、migrated、orphan、archived 和 deleted。当前文件快照中仍能匹配到知识节点时为 active；路径或指纹变化但通过多级候选匹配确认连续时，旧标识进入 migrated 并指向新标识；文件在当前来源中缺失但来源仍可达且删除尚未确认时进入 orphan；超过保留期限仍未恢复或被人工确认删除时进入 archived；归档期满或执行确定删除补偿后进入 deleted。active 和 migrated 状态可参与反馈累计，orphan 和 archived 状态只保留恢复能力，不参与普通排序，deleted 状态从索引和动态信号表中清除。

删除判断区分真实删除、来源暂时不可达、Git 分支切换导致的短暂缺失和外部盘未挂载。若整个来源不可达，系统暂停清理并记录 source_unreachable，不改变单个知识节点状态；若来源可达但单个文件缺失，先置为 orphan 并保留轻量签名、稳定内容指纹和最近动态信号；后续扫描若文件恢复且匹配原标识，则恢复为 active；若在保留期限内出现高置信迁移候选，则转为 migrated；若保留期满且仍无恢复或迁移候选，则归档或删除。

### 写入隔离与清理一致性机制

写入侧采用内容写入与反馈写入隔离的规则。知识整理、人工审阅、合并、删除、更新和新增操作只有在知识正文、标题、标签、关联关系、关键词、摘要或人工成熟度等稳定内容发生变化时，才生成或改写 Markdown 文件；访问命中、排序提升、热度变化、衰减结果和临时反馈只更新本机运行时信号层。对于旧 Markdown frontmatter 中已经存在的 `accessCount`、`updateCount`、`importance`、`recency`、`updatedAt` 等动态字段，系统在迁移阶段按白名单读取一次并写入本机状态库，同时记录迁移版本；后续检索排序以本机状态库为准，普通查询不得再次更新这些旧字段。

若迁移后再次在 Markdown 中发现旧动态字段，系统按照“共享稳定字段优先、本机动态字段优先于旧动态字段”的读取优先级处理：标题、标签、关键词和人工成熟度继续从 Markdown 读取；访问次数、热度、近期性和临时排序权重从本机状态库读取；Markdown 中残留的动态字段只作为兼容输入或人工查看信息，不参与普通反馈写回。若用户通过人工整理明确修改稳定重要性或人工成熟度，该修改作为稳定元数据写入 Markdown；若只是检索访问导致的排序变化，则只更新本机状态库。

合并操作由人工整理、自动归并或审阅确认的操作记录触发，操作记录必须携带源节点稳定标识和目标节点稳定标识。多个源节点合并到同一目标节点时，访问次数、命中次数、打开次数和点击次数求和，最近命中时间和最近打开时间取最大，热度按各源节点在合并时刻的衰减后热度求和并截断到上限，创建时间取最早，更新时间取最新，`localMaturityDelta` 按加权平均或取绝对值较大的修正后再限制在上下界内。目标节点已有较新动态信号时，源节点信号不得直接覆盖目标记录，只能按上述规则并入。

删除操作采用补偿式清理。若 Markdown 删除成功但本机状态库清理失败，系统写入待清理补偿记录，后续扫描根据缺失文件和补偿记录继续将对应动态信号转为 archived 或 deleted；若本机状态库清理成功但索引删除失败，系统使索引缓存失效并在下一次索引构建前强制重扫文件快照。对于派生摘要、概览和引用索引，删除源节点时同步删除或解除派生关联；若派生删除失败，则记录派生清理任务而不恢复已删除的原始 Markdown。
