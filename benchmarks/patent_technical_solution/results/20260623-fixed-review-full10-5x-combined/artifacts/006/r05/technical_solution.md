## 技术方案

本方案面向如下技术约束：同一知识条目既要以 Markdown 文件形式在团队之间共享、审阅和版本控制，又要在本机检索过程中持续吸收访问、命中、近期使用和排序反馈等高频运行信号。若将上述运行信号直接写回共享 Markdown，会导致版本控制状态频繁变脏、分支合并冲突增多，并使真正的知识正文变化被噪声淹没；若完全丢弃运行信号，则检索排序、清理建议和本机个性化使用效果下降。因此，本方案将共享知识文件与本机运行时动态信号分层存储，并在读取和检索阶段按稳定知识标识融合，形成“共享文件不被高频事件污染、动态信号仍可参与本机决策”的处理链路。

### 端到端运行流程与术语边界

系统的端到端流程包括初始化、索引构建、候选检索、动态信号加载、融合排序、事件记录、批量提交、索引刷新和清理迁移。初始化时，系统扫描本地可写知识库、共享可写知识库、共享只读知识库和外部只读知识库，生成来源清单并确定每个来源的 Markdown 正文写入权限；索引构建时，仅从 Markdown 稳定内容和稳定元数据生成文本索引、层级索引和关系索引；候选检索后，系统按知识标识读取本机动态信号并计算融合分数；结果展示、用户打开或会话引用等事件先进入本机事件队列，再按阈值或事务周期批量写入本机动态信号层；索引刷新时根据文件集合和版本指纹变化执行迁移、孤儿记录标记和延迟清理。

本文中“局部重要度”表示本机根据访问、命中和引用事件累积并衰减得到的知识使用价值；“局部新近度”表示知识条目最近在本机被访问或命中的时间效应；“排序增益”表示由局部重要度、局部新近度、临时成熟度和来源权重共同产生的评分补充项；“临时成熟度”表示本机根据使用行为推断的排序特征，不等同于共享 Markdown 中经人工确认的生命周期状态。后续各段均按上述术语使用，避免将运行时字段误认为共享知识正文的一部分。

来源类型默认划分为 $localWritable$、$sharedWritable$、$sharedReadOnly$ 和 $externalReadOnly$。本机动态信号对所有来源均可写入当前机器的动态信号层；Markdown 正文写入仅允许在来源类型为可写且路径校验通过时执行。共享关系元数据、人工维护标签和经确认的生命周期状态属于可进入版本控制的稳定元数据；本机检索缓存、运行事件队列、派生分数、临时索引和动态信号数据库属于本机派生数据，应放置在忽略或同步排除位置。

### 共享知识文件层与本机动态信号层

共享 Markdown 知识文件层保存适合在团队之间流转的稳定知识，包括知识正文、目录层级、主题关系、人工维护的标签、来源说明以及经确认的生命周期状态。该层文件保持人可读格式，能够被代码审查、版本控制、分支合并和云端同步直接处理；对同一知识条目的低频内容修改仍通过 Markdown 文件完成，从而保证团队成员看到的是一致的知识主体。

本机运行时动态信号层保存高频变化但不适合直接进入共享文件的运行数据，包括访问次数、检索命中次数、最近访问时间、最近命中时间、排序增益、衰减基准、用户本机偏好以及由使用行为临时推断出的成熟度倾向。该层可以采用 SQLite、键值存储、JSON sidecar 或缓存目录实现，并位于本机工作区的忽略目录或同步排除目录中。系统将动态信号层视为对共享知识文件的本地增强视图，而不是共享 Markdown 文件的一部分。

| 数据类别 | 推荐存放层 | 写入触发 |
| --- | --- | --- |
| 知识正文、层级、关系、来源 | 共享 Markdown 知识文件层 | 人工整理、知识录入、结构调整或经确认的同步操作 |
| 访问次数、命中次数、近期使用时间 | 本机运行时动态信号层 | 检索返回、读取展开、会话引用或本机后台衰减 |
| 排序权重、临时成熟度、热度增益 | 本机运行时动态信号层 | 本机评分计算、使用反馈或定期重算 |
| 人工确认的核心/验证状态 | 共享 Markdown 知识文件层 | 审阅通过、知识治理或显式生命周期变更 |

### 稳定知识标识与动态信号记录

知识标识按确定性流程生成。系统先读取 Markdown frontmatter 中的固定标识 $fixedId$；若存在且格式合法，则主标识为 $sourceType:sourceAlias:fixedId$。若不存在固定标识，则对来源别名、规范化相对路径和正文摘要进行组合，生成 $sourceType:sourceAlias:normalizedPath:contentHash$。其中，路径统一采用正斜杠、去除冗余分隔符、解析工作区内符号链接并按预设规则处理大小写；摘要默认取稳定正文内容的哈希，不包含访问次数、命中次数、临时评分等运行字段。来源别名发生变化时，系统通过来源清单中的旧别名到新别名映射保持同一来源的标识连续性。

动态信号记录以知识标识为主键，默认由本机 SQLite 表保存；在无数据库环境下可退化为 JSON sidecar，但字段、事务和版本语义保持一致。每条记录至少包含：$accessCount$、$hitCount$、$lastAccessAt$、$lastHitAt$、$lastDecayAt$、$localImportance$、$localRecency$、$temporaryMaturity$、$versionFingerprint$ 和 $rowVersion$。其中计数字段为非负整数；$localImportance$、$localRecency$ 归一化到 $[0,1]$；$temporaryMaturity$ 可取 $draft$、$validated$、$core$ 或 $deprecatedCandidate$；$versionFingerprint$ 由文件修改时间、文件大小、稳定正文摘要和目录子节点摘要组成；$rowVersion$ 用于并发更新时的乐观校验。缺失记录时，系统创建默认记录，计数为 0，局部重要度为 0.5，局部新近度为 0，临时成熟度为 $draft$。

迁移仅在索引刷新或文件监听事件已经得到新旧条目集合后执行，并要求旧动态记录尚未清理、新条目实际存在、来源映射有效，且固定标识相同或内容相似度达到阈值。路径变更同时伴随正文修改时，固定标识优先于内容摘要；无固定标识时，系统结合旧路径映射、规范化路径相似度和正文相似度判断是否为同一条目。若仅文件修改时间变化而正文摘要不变，则保留动态信号并刷新版本指纹；若正文摘要变化但固定标识不变，则保留访问历史并重建内容索引；若固定标识缺失且正文相似度低于阈值，则视为新条目并初始化动态信号；若仅目录子节点摘要变化，则只刷新层级派生分数。

标识冲突不直接自动覆盖。若两个 Markdown 文件具有相同 $fixedId$、多个旧标识映射到一个新标识、一个旧标识匹配多个新条目、来源别名冲突，或不同来源出现相同正文摘要，系统将相关记录写入待确认队列，并暂停自动迁移。经确认需要合并时，计数字段求和，最近访问和最近命中时间取较新值，局部重要度取较高值或按访问占比加权，临时成熟度以共享 Markdown 中人工确认状态为上限，且保留迁移日志。该规则通过维持标识连续性减少重命名导致的信号丢失，同时避免冲突迁移误覆盖其他知识条目的动态历史。

### 动态信号事件处理与并发恢复

运行事件按噪声强度区分处理。检索阶段产生的大量候选不直接增加命中计数；只有实际展示给用户的前 $K$ 条结果才增加轻量命中权重。用户点击展开 Markdown 正文、由代理会话引用该知识或将该知识纳入回答上下文时，才增加主访问权重。同一会话、同一知识标识在去重窗口内只累计一次主访问，重复展示仅更新最近命中时间或累加较小权重，防止单次检索循环放大热度。

默认更新规则为：展示事件使 $hitCount$ 加一并更新 $lastHitAt$；打开或会话引用事件使 $accessCount$ 加一并更新 $lastAccessAt$；访问事件对 $localImportance$ 施加大于展示事件的增益；后台衰减事件根据 $lastDecayAt$ 到当前时间的间隔更新 $localImportance$ 和 $localRecency$。事件先进入内存队列，当队列达到数量阈值、时间阈值、会话结束或索引刷新前，系统以事务方式批量提交到本机动态信号层。提交成功后更新 $rowVersion$ 和相关版本指纹；提交失败时保留事件队列并降级为只读排序，不回写共享 Markdown。


其中，$\Delta t$ 为距离最近访问或命中的时间间隔，$\tau$ 为新近度半衰控制参数，$\Delta d$ 为距离上次衰减的天数，$\lambda$ 为每日重要度保留系数，$bonus$ 为本批事件产生的访问或展示增益，$clip$ 表示截断到 $[0,1]$。若检测到系统时间回拨、跨时区解析异常或文件修改时间不可靠，系统优先采用单调时钟记录事件顺序，并将异常时间差视为 0 或等待下一次可信时间戳再衰减；只有衰减事务成功提交后才更新 $lastDecayAt$。

并发写入通过事务、文件锁或乐观版本号保证不丢失更新。检索返回、用户点击、后台衰减和索引刷新同时发生时，每个批次提交前读取当前 $rowVersion$；若版本不一致，则重新读取最新记录并按计数求和、时间取新、重要度重新衰减后再提交。若本机数据库损坏或 sidecar 无法解析，系统将损坏文件隔离为备份，临时回退到纯内容相关性排序，并在后台根据 Markdown 索引重建默认动态信号记录。索引刷新中断时，未提交事件保留在队列或恢复日志中，下一次启动继续重放。

### 检索读取时的融合评分与排序

检索时，系统首先从共享 Markdown 知识文件层构建或复用文本索引、层级符号树和关系索引。文本索引用于得到 BM25 等内容相关性分数；层级符号树用于确定 domain、topic、subtopic 与 context 等节点之间的父子关系；关系索引用于处理显式引用、反向链接或一跳扩展。上述索引构建仅读取 Markdown 文件及其稳定元数据，不把访问命中等动态信号写回文件。

获得候选知识条目后，系统按知识标识从本机动态信号层加载对应记录，并将内容相关性、局部重要度、局部新近度、临时成熟度和来源类型进行融合。缺失、损坏或版本指纹过期的动态记录不阻塞检索，系统先使用默认动态记录或退回纯内容相关性排序，并在后台修复动态信号层。共享 Markdown 中人工确认的生命周期状态优先于临时成熟度；临时成熟度仅作为本机排序特征或待审阅提示，不得覆盖共享文件中的核心、验证或废弃状态。


其中，$BM25_n(d,q)$ 由原始文本相关性分数归一化到 $[0,1]$，$I_{local}(d)$ 和 $R_{local}(d)$ 由本机动态信号层提供并截断到 $[0,1]$，$M(d)$ 为成熟度权重，$S(d)$ 为来源权重。权重 $w_b$、$w_i$、$w_r$、$w_m$、$w_s$ 非负且默认归一化，使内容相关性权重保持最大；最终分数再次截断到 $[0,1]$。来源权重只在两个候选的内容相关性差值低于阈值时生效，避免本机来源或共享来源偏好压倒明显更相关的知识内容。

排序时先按融合分数降序排列；若分数相等或差值小于 $\epsilon$，则依次比较内容相关性、共享 Markdown 中人工确认的核心或验证状态、最近访问时间、来源优先级和规范化路径字典序。该稳定排序规则保证在动态信号缺失或多个候选得分接近时，系统仍能给出可复现结果，并避免由于微小运行时扰动导致结果顺序频繁震荡。

对于层级化知识，系统将叶子文档的内容相关性或热度按衰减系数向父节点传播，默认每向上一层乘以小于 1 的传播系数，并设置最大传播层数。父节点分数可取子节点传播分数的最大值、加权平均值或前若干高分子节点的聚合值；子树过大时采用增量更新或 top-$N$ 采样以降低计算成本。归档节点、废弃节点和权限不可见节点不参与向上增强；只读来源可以参与本机派生分数计算，但传播结果仅存在于本机索引或缓存中，不得反向修改父节点 Markdown 摘要。

### 写入隔离与版本控制边界

系统设置写入隔离规则，将“知识内容写入”和“运行信号写入”分离。默认写入路由为：若事件类型为检索展示、点击展开、会话引用、排序反馈或衰减更新，则始终写入当前机器的动态信号层；若事件类型为新增知识、修改正文、调整目录结构、补充关系注解或确认生命周期状态，则进入 Markdown 正文写入流程。Markdown 正文写入必须依次通过来源类型、路径归属、只读状态、权限和冲突检测校验；任一校验失败时，操作返回失败或进入待确认队列，不得改写共享文件，也不得回退写入到其他共享路径。

对于被配置为共享来源、外部来源或只读来源的 Markdown 知识库，系统在写入路由中执行来源检查和写保护校验。若一次操作只产生运行时动态信号，则无论目标知识来自本地还是共享源，均写入当前机器的动态信号层；若一次操作试图修改共享源 Markdown 正文，则必须满足可写来源、权限和路径校验。由此可以支持团队共享同一套 Markdown 知识，同时允许不同机器保留各自的使用热度、排序偏好和近期访问状态。

版本控制边界通过忽略规则和同步排除规则进一步限定。本机动态信号数据库、运行事件恢复日志、检索缓存、派生分数、临时索引和本机清理队列均放置在被忽略或被同步排除的位置；共享 Markdown 知识文件、稳定目录结构、人工维护关系和经确认的生命周期状态才进入版本控制。这样，普通检索和读取不会造成工作区持续出现未提交变更，合并冲突主要集中在真实知识内容调整上，代理人员和开发人员也更容易从版本差异中识别有效技术知识变化。

### 清理、迁移与一致性维护

清理一致性由索引重建、文件监听或同步结果驱动。系统在发现 Markdown 文件集合、文件修改时间、正文摘要、来源清单或目录子节点摘要变化时，先进行二次扫描确认变化仍然存在，再分别处理本机动态信号：仅修改时间变化而正文摘要不变的，刷新版本指纹；正文变化但固定标识不变的，保留访问历史并重建内容索引；路径变化但固定标识或内容相似度满足阈值的，迁移旧动态信号；文件被删除或共享源被移除的，将对应动态信号标记为孤儿记录并进入延迟清理队列；派生摘要或检索缓存变化的，仅刷新索引，不生成新的共享知识记录。

孤儿记录采用延迟清理而非立即删除。系统为孤儿记录设置恢复窗口 $TTL$，在窗口内若共享源重新挂载、同步延迟恢复或新条目通过固定标识、来源映射、旧路径映射或内容相似度重新匹配成功，则恢复原动态信号并刷新版本指纹；若 $TTL$ 到期仍无法匹配，清理前再次执行存在性校验和来源校验，确认无有效 Markdown 条目后才归档或删除本机动态记录，并写入清理日志。该机制能够避免因短暂离线、分支切换或同步延迟误删本机使用历史。

动态信号还可以作为清理候选的参考，而不是作为自动删除共享知识的唯一依据。系统可在连续 $N$ 天未命中、衰减后局部重要度低于阈值、临时成熟度处于低等级、正文版本指纹长期未变化且知识不属于人工确认核心状态时，生成待审阅列表。列表项至少包括知识标识、来源类型、规范化路径、最后命中时间、最后访问时间、衰减后局部重要度、临时成熟度和触发原因。人工确认前，系统不得自动删除或改写共享 Markdown 正文，只能降低本机展示权重或提示归档建议。

通过上述分层存储、稳定标识、读取融合、写入隔离和一致性维护机制，系统能够在保留 Markdown 知识文件可读、可审阅、可版本控制优点的同时，持续利用访问次数、检索命中、排序权重、成熟度和近期使用情况等动态信号。运行时高频变化被限制在本机层，不再反复污染共享文件差异；共享知识的真实内容变化则仍可被团队清楚审阅和合并。
