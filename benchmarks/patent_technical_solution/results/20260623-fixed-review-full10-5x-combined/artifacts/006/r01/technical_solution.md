## 技术方案

### 总体架构与分层边界

知识管理系统将项目知识保存为 Markdown 后，若把访问次数、检索命中、热度、近期使用、成熟度变化和衰减后分值等运行时信号也写入同一 Markdown 文件，会造成同一知识内容在每次查询后产生版本差异，进而带来提交历史噪声、多人合并冲突、云端同步频繁变更以及本机偏好与共享知识内容混杂的问题。本方案的核心约束是：共享层只承载可审阅、可合并、可同步的知识事实和稳定结构；运行时动态信号只作为本机派生状态参与排序、清理和整理判断，不作为普通知识修改直接进入共享 Markdown。

系统整体包括共享知识文件层、本机动态信号层、读取融合层和清理一致性层。本文中，“知识文件”指 context tree 中承载知识正文的 Markdown；“知识条目”指由稳定标识定位的一份知识内容；“节点”包括知识文件节点、目录摘要节点和派生摘要节点；“source”指本地或外部知识来源；“provider”指检索或写入该来源的适配器；“overlay”指为只读或外部 source 建立的本机动态记录。共享知识文件层保存知识正文、稳定元数据和人工可审阅关系；本机动态信号层保存随查询和整理变化的派生状态；读取融合层在搜索、问答和整理时按稳定标识合并两层状态；清理一致性层在文件移动、合并、删除、归档、分支切换或同步后修正映射、tombstone 和索引。

### 核心数据模型与稳定标识

本方案固定使用四类本机数据对象与共享 Markdown 关联。第一类为共享知识文件，保存正文、标题、摘要、标签、关键词、关联关系和经审阅确认的稳定标记。第二类为动态 sidecar 记录，以 `stable_id` 为主键保存运行时统计和排序状态。第三类为标识映射表，保存 `stable_id`、当前相对路径、上一相对路径、内容摘要、标题规范化值、source 标识、索引签名和别名关系。第四类为 tombstone 记录，保存被删除、归档或合并条目的历史标识、失效原因、目标标识、保留到期时间和审计摘要。派生摘要文件只从共享知识文件生成，不作为动态信号的主存储。

`stable_id` 的生成按确定优先级执行：优先读取 Markdown frontmatter 中经确认的稳定 ID；缺失稳定 ID 时，使用“source 标识 + 相对路径 + 内容摘要”生成临时 ID；相对路径变化但内容摘要一致时，保留原 `stable_id` 并更新映射表；内容摘要变化但稳定 ID 一致时，认定为同一知识条目的内容修订；标题规范化值只作为辅助匹配信号，不能单独覆盖已有稳定 ID。索引签名由相对路径、修改时间或文件大小、内容摘要等组合生成，用于判断全文索引和动态记录是否对应同一版本。

发生标识冲突时按以下规则处理：两个文件具有相同 frontmatter 稳定 ID 但内容摘要和路径均不同时，保留最早映射为主记录，后出现文件生成冲突记录并要求审阅确认；同一路径摘要变化且稳定 ID 不变时视为内容更新，不创建新动态记录；摘要相同但路径不同且 source 相同时视为移动或重复副本，优先将动态记录迁移到当前活动路径，并为旧路径建立别名；标题相同但稳定 ID 不同仅用于提示可能重复，不自动合并；内容摘要碰撞或一个旧记录匹配多个新文件时，系统标记异常并暂停动态状态迁移，避免运行时记录覆盖真实知识边界。

### 共享知识文件层

共享知识文件层以 Markdown 文件作为稳定知识载体。每个知识文件可以包含标题、摘要、标签、关键词、关联关系、事实、叙述内容、代码片段或其他结构化段落；文件夹、`context.md`、`_index.md`、`.abstract.md`、`.overview.md` 等派生或汇总文件用于表达 context tree 的层级、摘要和可导航视图。该层只保存适合由人阅读、审阅、合并和回滚的知识内容，以及相对稳定的前置元数据。

当 curate、review、merge 或 delete 等操作改变知识正文时，系统按知识内容变化更新 Markdown，并可在写入前备份旧文件、在合并时保留目标文件并删除源文件、在删除时移除对应派生摘要文件。该层的版本控制对象应限定为知识内容、目录结构和人工可解释的摘要关系，而不包含每次查询产生的访问计数、命中次数、热度或衰减后分值。这样，版本历史中的差异主要反映知识本身的新增、修订、合并、删除和结构调整。

### 本机动态信号层

本机动态信号层的 sidecar 记录以 `stable_id` 为主键，字段包括：`access_count` 和 `hit_count` 为非负整数，默认 0，分别由实际打开行为和有效检索命中事件更新；`last_access_at` 为时间戳，默认空；`recent_window_hits` 为按固定时间窗口维护的计数数组或滑动窗口摘要，默认空；`importance_score`、`recency_score`、`hot_score` 归一化到 0 至 1，默认分别为 0.5、1 和 0；`maturity_level` 取 `draft`、`reviewed`、`stable`、`deprecated`，默认 `draft`；`index_signature`、`source_id`、`schema_version`、`abnormal_flag`、`tombstone_flag` 和 `updated_at` 分别用于索引一致性、来源隔离、版本迁移、异常隔离、删除归档状态和并发判断。

本机动态信号层设置在共享 context tree 之外的 sidecar 状态库中，存储介质可为 JSON、SQLite、LevelDB 或嵌入式键值存储，但必须被 context tree 的提交、同步和审阅流程排除。动态信号写入经过事件缓冲：一次检索只在结果被选中、展开、打开或用于回答时生成命中事件，候选列表中未被使用的条目不增加 `access_count`；事件键由查询会话 ID、`stable_id`、事件类型和时间桶组成，同一时间桶内重复事件去重。内存计数器按 `stable_id` 聚合增量，在达到时间窗口、累计条数、索引重建、正常退出或显式刷新条件时批量落盘。

批量落盘采用本机事务或“临时文件写入—校验—原子替换”的方式。刷新失败时，未提交的增量保留在内存队列，并写入短期事件日志；进程异常退出后，下次启动先重放未确认事件日志，再按事件键去重，避免重复增加访问次数。若 sidecar 状态库权限不足或被锁定，系统进入只读降级模式：继续返回静态检索结果和内存内临时排序校正，但不承诺持久化动态信号，并在状态恢复后从新事件开始累积。

`recency_score` 和 `hot_score` 在读取时惰性计算。`recency_score` 按当前时间与 `last_access_at` 或最近内容更新时间的差值进行指数衰减，衰减后限制在 0 至 1；`hot_score` 按最近一个或多个时间窗口内的有效命中次数计算，并对突发重复命中设置上限。惰性计算得到的新分值仅在超过最小变化阈值或达到刷新周期时回写本机动态层，回写失败不影响本次检索结果。运行时 `maturity_level` 用于本机排序校正；只有经显式提升流程确认后的稳定成熟度标记才写入共享 Markdown。

### 读取融合与排序机制

检索融合流程按步骤执行：接收查询、scope、limit 和 source 约束后，先检查全文索引的 `index_signature` 是否与当前 Markdown 文件集合一致；不一致时重建索引或对受影响节点跳过动态记录并降级返回。随后系统使用标题、路径和正文等字段生成基础候选集，按候选 `stable_id` 批量读取 sidecar 记录；缺失记录填充默认动态状态，tombstone 或 abnormal 记录不参与正向加权。系统再计算归一化静态分、动态校正分和来源校正分，输出排序结果、来源路径和摘要，并仅对实际被打开、引用或用于回答的结果写入命中事件缓冲。

融合评分使用静态相关性优先的约束公式：`final_score = clamp(static_score * W_static + importance_score * W_imp + recency_score * W_rec + maturity_boost + heat_boost + provider_boost + propagation_score, 0, 1)`。其中 `static_score` 由 BM25 或同类相关性分归一化到 0 至 1，`importance_score`、`recency_score` 和 `hot_score` 均裁剪到 0 至 1，权重满足 `W_static` 大于任一单项动态权重；`maturity_boost` 由层级映射得到，`draft` 为抑制、`reviewed` 为中性、`stable` 为增益、`deprecated` 为强抑制；`provider_boost` 只用于本地与共享 source 得分接近时的微调。低于静态相关性最低门槛的候选不能仅凭热度进入高置信结果，动态校正总量设置上限，防止本机偏好覆盖文本相关性。

父节点传播只在 context tree 的父子关系图中向上执行，默认传播深度不超过两级，每级乘以小于 1 的衰减系数，并维护已访问节点集合防止环路。父子关系、`_index.md` 或 `.overview.md` 变化后，传播缓存随索引签名失效。摘要节点和正文节点同时命中时，系统保留正文节点作为主要结果，摘要节点作为聚合入口或次级结果；若摘要节点分数来自多个子节点传播，则只取最强传播信号或受上限约束的合成值，避免多子节点重复放大同一主题。对只读 source、共享 source 或外部 Markdown 文件夹，系统只建立本机 overlay 动态记录；权限失败时退化为纯静态相关性排序。

成熟度迁移分为运行时层级迁移和共享稳定标记提升。运行时层级可由有效命中、近期使用、curate 更新次数和低使用衰减触发，在 `draft`、`reviewed`、`stable`、`deprecated` 间按滞后阈值迁移，避免频繁震荡；其中从 `draft` 到 `reviewed` 可由多次有效命中和无异常标记自动触发，从 `reviewed` 到 `stable` 或从 `deprecated` 恢复为更高层级必须生成待审阅建议。待审阅建议包含 `stable_id`、当前路径、触发指标、建议层级、证据窗口和预期写入字段，只有用户确认或审阅规则通过后才写入共享 Markdown。

### 写入隔离与版本控制协同

写入隔离机制将知识内容写入通道和动态信号写入通道分离。知识内容写入由 curate、review、merge、delete、摘要生成和人工编辑触发，执行文件级事务锁、写入前备份、临时文件写入、校验、fsync 和 rename 原子替换；写入后进行结构损失检查，比较标题、摘要、事实、关联关系、代码片段等关键段落是否异常丢失。派生摘要文件重新生成失败时，正文写入不被运行时信号回滚，但派生文件标记为待重建；若正文校验失败，则恢复备份并保留失败审计。动态信号写入只进入本机 sidecar，不改写同一 Markdown frontmatter。

版本控制和同步流程只跟踪共享知识文件层的 Markdown 内容、目录结构和派生摘要文件；本机动态信号层通过忽略配置、独立数据目录或版本控制根目录之外的存储位置排除在提交和云端同步之外。执行 branch、checkout、pull 或 merge 后，系统重新扫描当前文件集合，比较映射表中的路径、摘要和索引签名：仍匹配的记录继续使用，路径变化的记录执行迁移，无法匹配的记录转为过期或 tombstone，全文索引按新签名重建。该流程使多人协作只合并知识内容变更，不合并各自的检索次数、访问时间和本机排序偏好。

显式提升流程只处理经过稳定证据支持的共享属性，不同步瞬时运行分值。触发条件包括：同一知识条目在多个时间窗口内持续高命中、被多次 curate 更新、无异常标记且静态相关性长期高于门槛，或被用户在 review 中标记为核心知识。建议记录包含建议写入字段、旧值、新值、触发指标和回滚依据；确认后仅写入稳定成熟度标记、人工重要度或摘要关系等可审阅字段。若分支合并后同一字段出现冲突，Markdown 中人工确认值优先，本机动态层保留为建议证据，不覆盖共享文件。

并发执行时采用固定锁顺序：先获取共享知识文件读写锁，再获取索引锁，最后获取 sidecar 事务锁。检索落盘动态信号前记录事件发生时的 `index_signature`；若落盘时发现知识文件已被 merge、delete、checkout 或 pull 改变，则按映射表重放到新 `stable_id`，无法确认的事件直接丢弃并写入审计日志。curate/review/merge/delete 持有写锁期间，检索使用上一稳定索引或等待索引锁；索引重建完成后再释放待处理事件，保证过期事件不会写入错误知识条目。

### 清理一致性与异常处理

清理一致性层按场景扫描共享知识文件层，跳过派生摘要、归档桩和非知识正文文件，并构建当前文件集合。判定矩阵如下：稳定 ID 匹配且路径变化时认定移动或重命名，迁移动态记录并更新路径；稳定 ID 匹配且内容摘要变化时认定内容修订，保留统计字段并更新索引签名；路径匹配但稳定 ID 缺失且摘要变化时认定同一路径替换，保留路径别名但重置与内容语义强相关的动态分；摘要匹配但路径不同且标题接近时认定移动副本，迁移到当前活动路径；仅标题匹配时不迁移，只生成重复提示；路径、稳定 ID 和摘要均不匹配时将旧记录标记为过期或 tombstone。

MERGE 场景必须由明确的合并操作记录、审阅确认记录或高置信清理扫描结果触发，不能仅凭标题相似自动合并。合并动态记录时，`hit_count`、去重后的 `access_count` 和时间窗口统计属于可累计字段；`source_id`、人工确认重要度、共享稳定成熟度标记和目标文件已有 frontmatter 字段属于目标优先字段，不被源记录覆盖；运行时 `importance_score` 可按目标权重优先的加权平均更新；`maturity_level` 只能在目标不低于源或经审阅确认时提升。源记录随后写入 tombstone，指向目标 `stable_id`，不再参与检索排序。

DELETE、归档和 tombstone 具有不同状态。DELETE 表示共享知识正文被移除，动态记录转为 tombstone 并停止排序；归档表示正文被移动到归档位置或替换为归档桩，动态记录保留最小审计字段并降低检索权重；tombstone 仅用于未来恢复匹配和审计，不作为正向搜索结果。若在保留期内同一稳定 ID 或高置信摘要重新出现，系统可恢复历史访问统计但重新计算 recency 和索引签名；超过保留期后仅保留聚合审计或彻底清除。动态信号只能产生归档或清理建议，真正删除、归档或合并仍由知识内容写入通道执行。

多个旧动态记录竞争同一新文件时，系统按稳定 ID 匹配、明确操作记录、内容摘要匹配、路径连续性、标题相似度的顺序确定主记录；其余记录作为别名或 tombstone 合入审计，不直接叠加热度。一个旧记录匹配多个新文件时，只有存在明确拆分操作记录时才按拆分比例分配统计字段；否则保留到最相似且静态相关性最高的文件，并将其他候选标记为需审阅，防止一次旧热度扩散到多个新知识条目。

动态状态库启动时先校验 `schema_version`、索引区完整性和事务日志。版本不兼容时先备份旧库，再执行迁移脚本；迁移失败时隔离旧库并创建新库，能保留的 `stable_id`、访问聚合和 tombstone 审计以只读方式导入，无法识别的字段丢弃。状态库损坏、权限不足或用户清空时，系统标记当前动态层不可用，重新索引 Markdown 以提供基础检索，并禁止把损坏状态回写到共享文件；恢复写入能力后从新的事件日志开始累积。
