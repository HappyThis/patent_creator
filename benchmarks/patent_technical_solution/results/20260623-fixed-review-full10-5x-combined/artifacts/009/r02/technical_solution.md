## 技术方案

### 技术问题与约束条件

本方案面对的核心技术矛盾是：模型生成代码需要一次性编排地理位置、剪贴板、页面选择内容、应用状态、第三方 SDK 会话等浏览器私有能力，但这些能力不宜迁移到服务端，也不宜把模型生成代码直接放在页面主线程运行。若在服务端执行，服务端需要持有本应由用户浏览器控制的授权对象和会话状态；若在主线程直接执行，生成代码可能污染 DOM、读取认证态、改写全局对象，并在多工具异步返回时造成结果错配、重复执行和异常恢复困难。

为解决该矛盾，本方案将浏览器侧能力分为三类边界：第一类是真实客户端工具及其权限状态，仅由页面主线程或授权宿主管理；第二类是模型生成代码，只能在隔离执行上下文中运行；第三类是二者之间的受控协议，负责工具描述冻结、名称映射、参数校验、权限确认、调用关联、结果回填、异常传播和资源释放。默认规则是不信任隔离上下文发出的任何工具请求，主线程工具网关必须基于当前执行会话、工具描述快照和权限状态重新校验后才执行真实处理函数。

### 总体架构与隔离边界

本方案在现有聊天代理和 code-mode 隔离执行模式的基础上，将模型生成代码的执行位置移动到浏览器侧的隔离执行上下文中，而不是在页面主线程直接执行，也不是把浏览器私有能力搬到服务端执行。页面主线程仅保留工具注册表、权限校验、用户态能力调用和结果回传逻辑；隔离执行上下文仅接收规范化后的工具描述、待执行代码和受控通信端口，不能直接访问主页面的全局对象、DOM、认证状态、浏览器原生授权对象或业务状态。

在一种实现中，浏览器侧包括模型响应接收模块、代码标准化模块、隔离执行模块、客户端工具网关和结果回填模块。代码标准化模块先剥离 Markdown 代码围栏，再通过 AST 解析或受限模板识别表达式、函数声明、默认导出函数、普通语句和顶层 await，并统一包装为带 strict mode 的异步入口函数；入口函数的输入仅为只读工具代理、日志代理和受控上下文，输出被限制为可序列化结果，入口函数内抛出的异常被转为结构化运行错误。默认规则是拒绝或改写 import、importScripts、eval、Function、动态 Worker 创建和未授权 self API；只有在工具描述快照或安全配置中明确声明允许的能力，才作为受限代理注入隔离上下文。

该隔离边界使生成代码只能通过受控工具调用获得页面侧能力。例如地理位置、剪贴板、页面选择内容、本地缓存、应用内状态或第三方 SDK 会话仍在用户浏览器内完成调用，服务端只看到工具描述、工具调用请求和工具结果，不需要持有这些私有能力的访问入口；同时，生成代码即使包含对全局变量、网络或页面对象的非预期访问，也被限制在隔离上下文中，避免污染主页面运行环境。

隔离执行上下文的 Web API 采用默认削减规则：默认禁止直接使用 fetch、WebSocket、IndexedDB、localStorage、BroadcastChannel、任意 postMessage、importScripts、第三方脚本加载和动态创建子 Worker 等能力；默认不得读取 opener、parent、top、document、cookie、storage、history 或主页面闭包对象。确需访问外部网络、页面存储、跨上下文通信或第三方脚本时，必须先注册为客户端工具或显式只读代理，并由主线程工具网关进行白名单、参数、权限和结果序列化校验。

### 动态客户端工具描述与命名映射

浏览器页面在每一轮对话或每一次工具集变更时生成客户端工具描述快照。每个工具描述至少包括工具名、自然语言说明、权限级别、以 JSON Schema 表示的参数结构，并为整组工具生成 snapshotId、版本号或内容哈希。工具描述快照与 executionSessionId、聊天轮次和后续 toolCallId 绑定；隔离执行开始后默认冻结该快照，执行期间新增、删除或修改工具不会影响本次会话。若收到的工具调用携带过期 snapshotId 或与当前会话绑定不一致，工具网关默认拒绝执行并返回工具集失效错误；在配置明确允许时，页面可重新生成快照并触发模型基于新工具集续写。

为降低模型生成代码与 JavaScript 运行时之间的名称不匹配，本方案在注册阶段建立“原始工具名—规范化工具名—真实处理函数”的映射表。默认规范化规则为：将横线、点号和空白替换为下划线，剔除不能出现在标识符中的字符，数字开头时增加前缀，对 JavaScript 保留字增加后缀，并按同一大小写规则生成比较键。隔离执行上下文只暴露规范化后的命名空间或代理对象，主线程工具网关根据映射表还原到真实工具函数；若两个原始名称规范化后得到相同比较键，默认拒绝后注册工具并保留先注册映射，以避免模型看到的工具签名在执行期间漂移。

当页面同时注册多个工具来源时，按 provider 命名空间组织工具，例如页面工具、会话工具、应用工具分别形成独立命名空间。注册时校验命名空间和工具名是否为合法标识符，禁止使用内部保留名，并执行确定性冲突规则：provider 命名空间冲突、内部保留名冲突、大小写折叠后冲突或同一命名空间内规范化重名，默认均拒绝本次注册并记录可诊断错误；只有配置显式声明允许覆盖且工具权限级别、参数结构和来源均满足覆盖条件时，后注册项才替换先注册项并生成新的 snapshotId。

### 隔离执行流程与受控调用协议

隔离执行流程开始于生成代码的装载和通信握手。主线程为本次运行生成 executionSessionId、snapshotId、单次 capability token 和 MessageChannel 端口，将其中一个端口交给隔离执行上下文；隔离上下文首次消息必须同时携带 executionSessionId、snapshotId、token 和从 1 递增的调用序号。若载体为 sandbox iframe，主线程还校验 iframe origin、sandbox 属性和消息来源窗口；若载体为 Worker 或等效上下文，主线程校验端口归属和初始化令牌。握手未完成、令牌不匹配、会话标识不匹配或调用序号非单调递增时，工具网关默认关闭端口并拒绝本次执行。

握手完成后，隔离上下文向入口函数注入只读工具代理对象和日志代理对象。工具代理对象不包含真实处理函数，而是通过 Proxy 或显式函数桩把每一次调用转换为协议消息；协议消息至少包含 executionSessionId、snapshotId、callSeq、规范化工具名、参数 JSON、工具调用超时时间和上下文标签。隔离上下文维护 pending promise 表，以 callSeq 绑定待决 promise；响应成功时解析为 output，响应失败时抛出带错误类型和 errorText 的异常。

主线程工具网关收到调用消息后，基于 executionSessionId、snapshotId、规范化工具名、权限状态和工具描述快照进行白名单校验，并在主线程重新执行 JSON Schema 校验，不信任隔离上下文代理的预校验结果。校验规则默认关闭 additionalProperties，按工具描述填充默认值，仅在配置声明时执行安全类型转换，并检查枚举、格式、嵌套深度、数组长度和对象大小；参数中的函数、Symbol、循环引用、不可克隆对象、undefined、NaN、Infinity 和超过大小上限的数据默认被拒绝。若工具名不存在、工具已注销、参数不符或权限未通过，网关不执行真实处理函数，而是返回结构化调度错误。

权限确认由工具元数据声明权限级别、影响范围、是否可持续授权以及是否可能产生副作用。需要用户确认时，确认界面展示工具来源、规范化工具名、关键参数、预期影响和授权时长；一次授权默认仅对当前 executionSessionId、snapshotId 和参数摘要有效，持续授权必须由用户明确选择。若工具描述、参数摘要、页面会话或用户身份发生变化，默认要求二次确认；确认超时、用户拒绝、授权撤销或页面卸载均产生 output-error，不执行真实处理函数。

对于需要继续驱动聊天代理的工具结果，页面结果回填模块使用与客户端工具一致的关联字段进行回传。模型产生工具调用时，聊天消息中携带 toolCallId；浏览器执行完成后发送类型为 cf_agent_tool_result 的消息，消息中包含 toolCallId、toolName、output、state、errorText、autoContinue 和可选 clientTools。服务端或本地代理根据 toolCallId 找到原工具调用部分，将其更新为 output-available 或 output-error；浏览器侧同时维护 executionSessionId、callSeq、toolCallId、pending promise、工具结果状态和聊天消息状态之间的映射表，确保隔离执行内部调用、客户端工具结果和聊天消息更新指向同一逻辑调用。

并发控制默认采用有限队列规则：每个 executionSessionId 设置最大并发数、最大排队数、最大总调用次数和允许工具集合；达到最大并发但未超过队列上限时，后续调用按 callSeq 排队，超过队列上限或总调用次数时返回非法调用错误。递归调用、批量调用展开后的每个真实处理函数调用均计入总次数；等待用户确认的调用默认占用并发额度，配置明确声明为可挂起确认时才从执行并发中移入确认队列。总执行超时、会话取消或页面卸载时，队列中的未开始调用统一标记为 cancelled，已开始调用按工具取消规则处理。

执行会话状态机包括 created、handshaking、running、waiting-tool、waiting-confirmation、completed、failed、cancelled 和 expired 等状态。状态只允许沿预定方向迁移：created 完成握手后进入 running；发送工具调用后进入 waiting-tool 或 waiting-confirmation；所有入口函数和待决工具完成后进入 completed；装载异常、运行异常、调度错误或工具业务错误进入 failed；用户取消或页面卸载进入 cancelled；总超时进入 expired。completed、failed、cancelled 和 expired 均为终态，终态之后到达的工具响应、日志或自动续写请求不得覆盖既有工具结果状态。

### 异常、日志、超时与资源释放

本方案将异常分为代码装载异常、隔离运行异常、工具调度异常和工具业务异常，并使用统一错误结构在各层之间传播。代码无法解析或无法包装为入口函数时，直接形成代码装载错误；隔离上下文运行入口函数抛出的异常被捕获为运行错误；工具名不存在、参数验证失败、权限拒绝或调用次数超限被记录为调度错误；真实工具函数内部抛出的异常被转换为工具业务错误。上述错误均携带 errorText、错误类型、调用序号和工具名，使聊天消息进入 output-error 状态，模型或用户界面据此给出后续处理。

隔离执行上下文中的 console.log、console.warn 和 console.error 被重写为日志代理，日志代理把日志级别、文本、时间戳和 executionSessionId 发送给主线程；主线程按会话聚合日志，并区分本地调试日志与可回传给模型或服务端的错误摘要。默认脱敏规则覆盖敏感字段名、参数路径、认证令牌、地理位置、剪贴板内容、URL 查询令牌、cookie、访问密钥和用户标识；超出长度上限的日志被截断并保留摘要哈希。只有脱敏后的错误摘要可进入 errorText 或聊天消息，完整调试日志默认留在本地诊断缓冲区。

每次隔离执行均设置总执行超时，每次工具调用设置单独超时。总执行超时优先级高于单工具超时，触发后主线程终止 Web Worker、移除沙箱 iframe或关闭等效隔离上下文，并将尚未完成的 pending promise、排队调用和确认请求标记为 expired；工具调用超时仅影响对应 callSeq，并按工具元数据判断是否发送取消信号。执行结束、失败、取消、过期或页面卸载时，资源释放模块统一清理消息监听器、MessageChannel 端口、计时器、待决 promise、日志缓冲区、幂等记录的可释放部分和工具快照引用，防止孤立回调继续访问已过期的页面状态。

为避免错误恢复过程中重复执行工具，工具网关以 executionSessionId 与 callSeq 为键维护幂等记录。相同键的重复请求默认不再次调用真实处理函数，而是返回已记录的终态结果或重复调用错误；若原调用仍在进行中，则重复请求只关联到同一待决结果。迟到响应不得覆盖 output-error、cancelled、expired 或 completed 等终态。对于需要用户授权的工具，授权被拒绝时默认生成 output-error；只有配置明确允许基于拒绝原因续写，且当前聊天轮次没有新的用户输入、没有更高优先级工具结果待处理时，才触发一次去重后的自动续写。

取消和副作用处理由工具元数据显式声明。默认将工具视为不可取消且可能产生副作用，因此超时或会话取消后不再重试该工具，也不以迟到成功结果覆盖已写入的错误状态；若工具声明可取消，网关发送取消信号并根据取消成功、取消失败或已产生副作用分别记录 cancelled、output-error 或 side-effect-unknown 状态；若工具声明幂等，后续恢复流程可用相同参数摘要查询既有结果而不是重新执行。该规则避免在网络请求、支付、写入剪贴板、修改页面状态等场景中因恢复逻辑造成重复副作用。

自动续写采用确定性优先级：同一聊天轮次内，用户新输入优先于自动续写；错误结果优先触发错误汇总而不是重复发起工具调用；多个工具结果同时到达时按 toolCallId 对应的消息顺序和 callSeq 去重合并；服务端流恢复中已处理过的 toolCallId 不再触发第二次续写；页面会话切换、snapshotId 失效或执行会话进入终态时，autoContinue 请求默认被抑制并记录原因。

### 可选实现与兼容边界

隔离执行上下文根据浏览器能力和安全要求选择，但必须满足最小安全配置后才能承载模型生成代码。Web Worker 默认使用专用 Worker，禁用 importScripts、外部网络和动态子 Worker，只保留受控 MessageChannel；SharedWorker 仅在能够按页面会话隔离端口、令牌和工具快照时启用；Service Worker 控制的临时执行单元不得持久化生成代码，不得拦截非本会话请求；sandbox iframe 必须去除 allow-same-origin、allow-top-navigation 和不必要脚本权限，并执行 origin 与来源窗口校验；浏览器扩展环境必须使用最小权限清单和独立内容脚本桥接。任一载体不能满足上述隔离、通信校验和资源释放条件时，默认不得作为模型生成代码执行载体。

本方案与服务端 code-mode 形成同构实现：服务端使用动态 Worker、RPC dispatcher、provider 命名空间、超时和日志收集执行云端工具；浏览器侧使用隔离上下文、消息协议 dispatcher、客户端工具注册表、超时和日志收集执行页面工具。两侧共享代码标准化、工具名规范化、参数验证和错误结构，但工具执行位置由工具能力归属决定：浏览器私有能力留在浏览器，服务端资源型能力留在服务端。

对于已有动态客户端工具协议，本方案不要求改变服务端模型工具的基本表达方式。服务端仍接收 clientTools，将其转换为无服务端 execute 的工具定义并在模型调用时暂停；浏览器侧在收到 tool-input-available 或等效工具调用事件后，默认由已注册真实处理函数执行单个工具调用；当工具描述快照声明允许代码化编排且隔离载体满足最小安全配置时，才把调用交给隔离执行上下文统一调度。该兼容边界使现有 onToolCall、addToolOutput、autoContinueAfterToolResult 和可恢复流机制继续工作，同时增加生成代码在浏览器侧安全调度多个动态工具的能力。
