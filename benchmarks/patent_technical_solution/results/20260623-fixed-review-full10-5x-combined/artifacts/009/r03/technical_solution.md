## 技术方案

### 总体架构与核心构思

本方案采用“模型生成编排代码、浏览器侧隔离执行、主页面受控调度真实工具”的结构。模型不直接操作页面对象，也不直接获得主页面的全局变量、DOM、前端组件实例或浏览器私有能力；模型仅生成用于编排工具调用的代码。该代码被送入浏览器侧的隔离执行容器中运行，隔离执行容器只暴露受控工具代理、日志代理和取消/超时信号，所有真实工具能力仍由主页面维护并执行。

主页面作为工具宿主，负责登记页面内可用的动态客户端工具，例如读取当前页面状态、调用前端组件提供的查询或操作能力、组合多个页面内工具得到中间结果等。隔离执行容器作为代码运行方，负责按照模型生成代码的逻辑发起工具调用请求，但不持有工具实现本体。二者之间通过结构化消息或等价的浏览器内 RPC 协议连接，从而在不把页面私有能力整体搬到服务端的情况下，使模型生成代码能够安全地使用页面内能力。

该结构的核心在于将“能力描述”“代码执行”和“真实能力调用”分离：工具描述用于约束模型生成代码，隔离执行环境用于承载不可信或半可信的生成代码，主页面调度器用于执行已经注册并通过校验的工具。由此，生成代码即使包含循环、组合调用或中间计算，也只能通过预设协议访问工具，不能污染主页面运行环境或绕过页面侧权限控制。

为统一术语，`sessionId` 表示用户页面或会话归属，用于限定工具注册表的可见范围；`executionId` 表示一次模型生成代码的独立执行，用于绑定隔离容器、消息通道、pending 请求表、日志和取消信号；`toolSnapshotVersion` 表示整份工具快照的版本，等同于调用消息中的 `toolVersion`；单个工具条目的描述版本属于快照内容，不单独决定一次执行可见的工具视图。

1. 主页面在当前 `sessionId` 下收集可用动态客户端工具，生成不可变工具快照，计算 `toolSnapshotVersion`，并由同一快照生成模型可读工具描述、规范化名称映射和隔离容器内代理定义。
2. 模型基于工具描述输出编排代码后，主页面或上层框架创建执行任务，登记新的 `executionId`，初始化执行状态、pending 请求表、已完成请求表、日志缓冲区、截止时间和取消信号。
3. 系统创建或重置浏览器侧隔离容器，建立专用消息通道，注入代理定义、`executionId`、`toolSnapshotVersion`、日志代理和取消信号，然后以包装后的入口函数启动模型生成代码。
4. 生成代码调用代理工具时，隔离容器产生包含 `executionId`、`requestId`、`toolName`、`arguments`、`toolVersion` 的请求消息；主页面调度器完成来源、状态、版本、名称、参数、权限、审批和并发限制校验后执行真实页面工具。
5. 主页面按 `requestId` 返回成功输出或结构化错误；隔离容器将对应 Promise 置为完成或拒绝，并继续运行生成代码，直至入口函数正常返回、未捕获异常、主动取消或执行超时。
6. 执行进入终态后，系统形成统一执行结果，冻结执行状态，拒绝新请求，清理 pending 请求，关闭消息通道并销毁或重置隔离容器，释放工具快照引用和临时资源。

正常执行结果包括生成代码入口函数的返回值、执行耗时、日志摘要和已完成工具调用摘要；异常执行结果包括错误类型、错误码、发生阶段、可裁剪诊断信息以及是否已存在部分成功工具调用。无返回值时以空输出和成功状态表示；若部分工具已成功但后续代码失败，则整次执行以失败为终态，同时保留已成功工具调用的只读摘要，避免后续错误覆盖已经完成的工具结果记录。

### 动态工具注册、描述生成与名称规范化

主页面维护动态客户端工具注册表。每个工具条目至少包括原始工具名、工具说明、输入参数模式、返回值模式、执行函数引用、权限或审批策略、工具级并发限制、读写属性、所属 `sessionId` 以及单个工具条目的描述版本。注册表是当前页面能力的实时集合，工具快照则是从该注册表在某一时刻派生出的不可变执行视图。

工具快照的数据结构包括 `sessionId`、`toolSnapshotVersion`、工具条目列表、规范化名称映射、参数与返回值模式、权限策略摘要、读写属性、工具条目哈希以及创建时间。`toolSnapshotVersion` 可以由递增序号、内容哈希或二者组合生成；用于生成模型提示、代理定义和调度校验的字段均来自同一快照。快照生成后不得原地修改，映射表也纳入快照签名，以保证模型看到的工具描述、隔离容器可调用的代理函数以及主页面校验依据三者一致。

当页面组件卸载、工具删除、工具重命名、权限撤销或用户登录态变化时，主页面生成新的工具快照供后续执行使用，已经绑定旧快照的执行不切换工具视图。若旧快照中的真实执行函数引用仍有效且当前权限仍满足，则调度器可以继续按旧快照执行；若执行函数引用失效、组件已卸载、当前权限被撤销或工具声明的有效期已过，则调度器对该请求返回 `TOOL_UNAVAILABLE` 或 `PERMISSION_REVOKED` 错误，而不是回退到新快照中的同名工具。

在向模型提供工具能力时，系统从工具快照生成模型可读的工具描述和隔离代码可调用的代理定义。每一项工具描述与一个规范化代理函数一一对应，二者共同引用同一个原始工具条目、参数模式、返回模式、权限策略、读写属性和 `toolSnapshotVersion`。工具描述用于引导模型生成只调用已登记工具的编排代码；代理函数则只负责构造协议请求，不包含真实页面逻辑。

工具名规范化采用确定性算法：先对原始工具名进行标准化处理并限制最大长度；将不适合作为代码标识符的字符替换为下划线，允许的 Unicode 字母可以保留或按实现策略转写；若名称为空、全为非法字符或清洗后为空，则使用 `tool` 加短哈希作为基名；若首字符为数字，则增加下划线前缀；若与语言保留字或运行时保留字段冲突，则增加后缀；若多个工具得到相同规范化名称，则按工具在快照中的稳定排序追加序号或短哈希。规范化名称区分大小写的策略在快照内固定，最终映射表在执行期间不得改变。

一次隔离执行必须绑定同一个 `toolSnapshotVersion`。隔离容器启动时接收该版本对应的工具描述、名称映射和代理定义；执行过程中即使主页面注册表发生变化，也不得将该次执行切换到新快照。对于需要使用新工具集合的后续请求，应创建新的 `executionId` 并绑定新的工具快照，以避免生成代码依据前后不一致的工具视图运行。

### 浏览器侧隔离执行环境与受控工具代理

隔离执行环境可以采用 sandbox iframe、Dedicated Worker、Worklet、Shadow Realm 或其他浏览器侧隔离执行单元实现。采用 iframe 时，应通过 `sandbox` 属性去除不必要权限，默认不授予表单提交、弹窗、顶层导航和同源脚本以外的能力，并结合 CSP、`allow` 属性和独立来源页面限制脚本来源、网络目的地、媒体、剪贴板、传感器和跨源资源访问。采用 Worker 时，应限制或替换 `fetch`、`WebSocket`、`importScripts`、动态 `import`、IndexedDB、缓存、存储和可用的 `navigator` 能力；采用其他隔离单元时，也应保证生成代码不能直接取得主页面 DOM、组件实例、浏览器扩展对象、Cookie、本地存储或未注入的全局对象。

隔离执行启动的前置条件包括：已生成不可变工具快照，已完成名称规范化，已生成代理定义，已建立专用消息通道，已登记 `executionId`，已初始化 pending 请求表和已完成请求表，已设置执行截止时间和取消信号。主页面仅向隔离容器注入这些最小运行材料以及日志代理；除受控入口外，隔离容器对外部网络访问、跨域资源访问、主页面对象访问和敏感浏览器 API 保持关闭或受限状态。

模型生成代码进入隔离容器前被包装为固定入口函数，例如接收工具代理、日志代理和取消信号的异步函数。系统可以先进行语法解析或轻量静态检查，拒绝无法解析的代码、非预期入口形式或明显访问禁用全局对象的代码；随后在隔离容器中加载包装代码并调用入口函数。入口函数的返回值通过 Promise 统一处理，顶层 `await` 被转换为入口函数内部的异步等待；语法错误、加载错误、未捕获异常和被拒绝的 Promise 均被捕获为统一执行错误，而不是直接冒泡到主页面上下文。

工具代理采用惰性拦截方式工作。系统按快照中的规范化名称生成代理函数集合；每次调用代理函数时，隔离容器先检查取消信号和本地并发限制，再生成新的 `requestId`，将该请求以 `pending` 状态写入 pending 请求表，并发送包含 `executionId`、`requestId`、`toolName`、`arguments`、`toolVersion` 和时间戳的调用消息。代理函数向生成代码返回 Promise，结果消息可乱序返回，但必须按 `requestId` 匹配对应 pending 项后才能完成该 Promise。

pending 请求表不得被同一 `requestId` 覆盖。若隔离容器或主页面发现重复 `requestId`，第二个请求被拒绝并记录为协议错误；若重复标识对应已完成请求，也不得覆盖 completed 记录。执行进入取消、超时或清理状态后到达的结果消息被识别为迟到响应，默认丢弃，必要时仅写入迟到诊断日志，不得重新唤醒已结束的 Promise 或改变执行终态。

### 主页面工具调度协议与结果回传

主页面设置工具调度器并监听来自隔离执行容器的结构化调用消息。工具调用被接受的前置条件包括：消息来源与已登记通道匹配，`executionId` 存在且处于运行中，`requestId` 未使用且未完成，`toolVersion` 等于本次执行绑定的 `toolSnapshotVersion`，`toolName` 存在于快照映射表，参数通过输入模式校验，工具权限或审批状态满足要求，且未超过工具级和执行级并发、频率或次数限制。任一条件不满足时，调度器不调用真实工具。

输入模式校验包括必填字段存在性、字段类型、枚举取值、数值范围、字符串长度、对象最大深度、数组最大长度和额外字段策略。额外字段可以按工具声明被拒绝、忽略或保留；默认值只能由工具模式显式声明后填充。参数必须可结构化克隆或可 JSON 化，函数、DOM 节点、Symbol、循环引用以及未声明的二进制对象默认拒绝；对 Date、BigInt、Blob、ArrayBuffer 等特殊值，应按工具模式声明转换为字符串、数字、二进制句柄或直接拒绝。

请求生命周期可以采用状态机管理。请求创建后进入 `created`，写入主页面请求表后进入 `pending`；若需要用户确认，则进入 `waitingApproval`；审批通过且再次校验仍满足工具快照、权限、组件可用性和执行状态后进入 `executing`；执行成功进入 `fulfilled`，执行异常或校验失败进入 `rejected`，用户取消进入 `cancelled`，超过工具级或执行级截止时间进入 `timeout`；结果已回传或无需回传且资源已释放后进入 `cleaned`。除明确允许的迁移外，终态请求不得回退到运行态。

真实执行函数运行在主页面上下文中，因此能够访问已授权的页面状态、前端组件方法、浏览器会话对象或客户端扩展能力。对于需要用户确认的敏感能力，调度器在执行前将请求置为 `waitingApproval`，隔离代码中的 Promise 保持等待。审批通过后，调度器必须再次校验执行是否仍在运行、工具快照是否匹配、组件引用是否仍有效以及权限是否仍满足；审批拒绝则返回 `APPROVAL_REJECTED`。审批超时、用户取消和执行超时发生竞争时，以最先进入终态的事件为准；已经进入终态的请求不得被后续审批结果覆盖。

并发调用按照快照或执行任务中的限制处理。系统可以设置执行级最大并发数、工具级最大并发数和频率窗口；超过限制的请求按工具声明进入队列、延迟重试或直接返回 `RATE_LIMITED`。只读工具可以并发执行；写页面状态的工具默认需要按照到达顺序串行化，或者按照工具声明的互斥锁、资源键、审批顺序或页面侧事务规则执行。读写混合操作中，写工具占用相关资源锁时，读取同一资源的工具可以等待或读取执行前快照，具体策略由工具声明固定。

工具执行完成后，主页面按 `requestId` 回传结果消息。结果消息包括 `requestId`、`ok`、`output`、`error`、`duration`、请求终态和可选诊断信息。返回值先按返回模式进行序列化：普通对象和数组采用结构化克隆或 JSON 化；Date 可转为 ISO 字符串；BigInt 可转为字符串；Blob、ArrayBuffer 等二进制值仅在工具声明允许时通过受控句柄或大小受限副本返回；DOM 节点、函数、含循环引用的对象、超大对象和包含敏感字段的对象默认拒绝或脱敏截断。隔离容器按 `requestId` 匹配等待中的 Promise，乱序到达不影响结果归属。

### 非法调用、异常传播、日志与资源释放

非法调用包括但不限于：工具名未登记或无法由规范化名称映射到原始工具名，参数不符合输入模式，工具不属于当前 `sessionId` 或当前 `toolSnapshotVersion`，调用来源不是本次隔离执行容器，执行已取消、超时或清理完成，工具需要审批但尚未批准，同一 `requestId` 被重复使用，以及请求超过并发、频率、次数或资源锁限制。调度器对非法调用返回结构化错误，并可按错误严重程度决定仅拒绝该请求或终止整次执行。

异常传播采用分层序列化方式。错误类型可以包括 `CODE_SYNTAX_ERROR`、`CODE_RUNTIME_ERROR`、`PROTOCOL_ERROR`、`UNKNOWN_TOOL`、`SCHEMA_VALIDATION_FAILED`、`PERMISSION_DENIED`、`APPROVAL_REJECTED`、`APPROVAL_TIMEOUT`、`TOOL_UNAVAILABLE`、`TOOL_EXECUTION_ERROR`、`SERIALIZATION_ERROR`、`EXECUTION_CANCELLED`、`EXECUTION_TIMEOUT` 和 `CHANNEL_CLOSED`。错误结构包括错误码、发生阶段、消息、关联 `executionId`、可选 `requestId`、是否终止整次执行、是否允许生成代码捕获后重试以及可裁剪诊断信息。主页面不向隔离容器暴露敏感对象引用或完整内部状态。

隔离环境拦截生成代码中的日志输出，并将日志转换为带 `executionId`、时间戳、级别和内容摘要的日志事件。日志处理应限制单条长度、累计条数和总字节数；超出限制时按采样、合并或丢弃策略处理，并记录被截断数量。日志内容在入库或展示前进行脱敏，过滤 token、Cookie、授权头、长 DOM 片段、文件内容、用户隐私输入和工具声明的敏感字段；对象日志只保留可序列化摘要，不携带主页面对象引用或未处理的用户隐私数据。

每次执行设置统一超时和取消机制。终态优先级以最先成功冻结执行状态的事件为准；取消、超时、审批拒绝、工具异常和隔离代码异常发生竞争时，后到事件只能作为诊断记录，不得覆盖已返回的终态结果。同一请求在超时后又收到工具成功结果时，以超时为终态并丢弃迟到成功结果；已经返回给隔离容器的请求结果不得被后续错误覆盖。

对于长耗时真实工具，工具声明中可以提供中止回调、取消信号或事务补偿函数。执行取消或超时后，调度器先向正在执行的工具传递取消信号；能够中止的工具应尽快停止并返回取消结果。若工具无法中止，其迟到结果不得写回已结束的隔离执行；对于会修改页面状态的工具，应通过工具级事务、幂等键、资源锁或补偿回调限制取消后的继续影响，无法保证安全的写工具应在执行前要求审批或禁止在可取消链路中运行。

执行结束后的资源释放按确定顺序进行：首先冻结执行状态并记录终态，其次拒绝新请求并向 pending 请求写入取消或超时结果，再通知隔离容器停止等待，然后移除消息监听器、关闭 MessageChannel 或等价通道，随后销毁 worker、移除 iframe 或重置可复用容器，最后释放 Blob URL、临时对象引用、日志缓冲区、取消信号和工具快照引用。清理完成后到达的工具结果、审批结果或日志事件按 `executionId` 识别为迟到消息，默认丢弃或仅作为诊断记录。

若消息通道断开、隔离容器崩溃、主页面刷新、审批 UI 被关闭或真实工具抛出不可序列化异常，系统将对应执行或请求转换为统一失败结果，并按同一清理流程释放资源。不可序列化异常先尝试提取错误名、消息和安全堆栈摘要；仍无法提取时返回通用 `TOOL_EXECUTION_ERROR` 或 `SERIALIZATION_ERROR`，避免因异常对象本身不可传输而阻塞 pending 请求。

### 可选实施方式与边界条件

在一种实现中，隔离执行容器以每次模型生成代码执行为粒度创建，一次执行结束即销毁；在另一种实现中，也可以在同一 `sessionId` 内复用容器。复用的前置条件是上一执行的消息监听器、pending 请求表、已完成请求表、代理对象、取消信号、日志缓存、临时全局变量和工具快照引用均已清理；若隔离载体无法可靠清除生成代码写入的全局状态，则不得复用该容器，应重新创建隔离容器以防止下一次执行读取残留状态。

动态客户端工具可以是页面内工具、浏览器能力工具或服务端已返回到客户端侧的临时工具描述。若某些工具需要服务端数据、模型续写或跨客户端同步，主页面可以在工具结果返回后交由上层对话框架继续处理；但在浏览器侧执行链路中，生成代码始终只与隔离容器内的代理接口交互，真实工具调度始终由主页面按 `executionId`、`sessionId` 和 `toolSnapshotVersion` 校验后完成。

本方案不要求将所有浏览器私有能力迁移到服务端，也不要求模型直接获得完整浏览器调试协议或完整页面对象。对于读取页面状态、调用前端组件能力、执行用户已授权的页面操作等场景，主页面只注册最小必要工具，并在工具描述中限制输入范围和返回内容。对于高风险能力，通过审批策略、只读模式、执行次数限制、资源锁、工具级超时和返回值脱敏收窄权限边界；执行期间快照不得切换，执行结束后迟到响应不得写回，取消后新工具请求必须拒绝。
