## 技术方案

### 总体架构与执行边界

本方案要解决的技术问题是：模型生成的代码需要编排浏览器主页面中的动态客户端工具，但这些工具往往依赖页面状态、用户授权、DOM 交互、剪贴板或浏览器会话等私有能力。若将真实工具函数或页面对象直接注入生成代码，容易产生工具名不合法、权限绕过、页面状态被污染、异常无法回传给模型、并发结果错配、超时后资源泄漏以及迟到消息继续触发副作用等问题。因此，本方案将“代码执行能力”和“真实客户端工具执行能力”分离，通过快照、代理、消息协议和主页面调度器建立受控调用链路。

本方案在现有 codemode“由模型生成异步 JavaScript 代码、在隔离执行环境中运行、通过代理对象回调宿主工具”的机制基础上，增加浏览器侧动态客户端工具执行链路。主页面不把真实工具函数、DOM、组件实例、剪贴板、浏览器会话等私有能力直接暴露给模型生成代码，而是在主页面维护客户端工具注册表，并向隔离执行环境仅暴露一个受控代理命名空间。模型生成代码调用代理命名空间中的规范化工具方法时，隔离环境只产生结构化调用请求；真实工具仍由主页面调度器在校验后执行。

该链路包括主页面工具注册表、动态工具描述生成器、浏览器隔离执行器、消息通道、主页面调度器和结果回填模块。工具注册表保存工具原始名称、输入输出 schema、描述、执行函数、权限条件、审批状态以及页面可见性条件；动态工具描述生成器从当前注册表生成供模型阅读的工具说明和类型声明；隔离执行器负责运行模型生成代码并捕获控制台日志；消息通道在隔离环境与主页面之间传递工具调用和调用结果；主页面调度器根据注册表执行白名单校验、参数校验、权限或审批校验，并调用真实客户端工具。

通过上述边界划分，模型仍可编写包含循环、条件分支、错误处理和多工具组合的代码，但该代码不能越过代理接口直接访问主页面状态。浏览器侧工具无需迁移到服务端或 Worker 宿主中，仍可在主页面上下文中使用既有 UI 状态、浏览器会话或用户授权能力；同时，生成代码被限制在浏览器 Worker 或带 sandbox 属性的 iframe 等隔离上下文中执行，从而降低对主页面全局变量、事件循环和页面对象的污染风险。

### 动态工具描述与工具名规范化

主页面在每次发起模型请求或执行代码工具前，根据当前已注册的客户端工具生成动态工具描述。该描述至少包含命名空间、每个工具的规范化可调用名称、原始工具名称、功能说明、输入 schema、输出说明和必要的字段级描述。对于使用 JSON Schema、Zod 或标准 schema 表达的输入结构，描述生成器将其转换为模型容易使用的类型声明和注释，使模型生成代码时能够按照对象参数形式调用工具，例如调用 `clientTools.safeName(input)`，而不是构造不受控的字符串命令。

为保证模型看到的工具能力与执行时调度器允许的工具能力一致，主页面在生成动态工具描述时同时冻结一个工具快照。工具快照包含唯一的 `toolSnapshotId`、递增的 `descriptionVersion`、命名空间列表、`safeName` 到原始工具名的映射、工具 schema 摘要和调度白名单。一次模型请求、该请求返回的代码、隔离执行器注入的 `clientTools` 代理命名空间以及主页面调度校验均绑定同一个 `toolSnapshotId`。若代码执行时页面权限或工具注册状态已变化，调度器仍先按该快照定位工具项，再按调用时门禁规则判断是否允许继续执行；不能定位或门禁失败时返回结构化错误，而不是临时改用新的工具描述。

工具注册项采用确定的数据结构。每个注册项至少包括：`namespace` 表示代理命名空间，默认可为 `clientTools`；`originalName` 表示注册时的原始工具名；`safeName` 表示规范化后的 JavaScript 可调用名称；`inputSchema` 和 `outputSchema` 分别限定入参与出参边界；`description` 和字段注释用于生成模型可读描述；`visibilityPredicate` 判断工具是否应出现在当前快照中；`permissionPredicate` 在每次调用时判断用户和页面状态是否允许执行；`approvalPolicy` 声明是否需要用户审批及审批超时；`executor` 指向主页面真实执行函数；`cleanup` 指向取消、补偿或资源清理回调；`sideEffectLevel` 标记只读、用户可见副作用或外部副作用；`timeoutMs` 设置单工具调用超时；`resultSizeLimit` 限制返回结果大小。生成工具快照时固化 `namespace`、`originalName`、`safeName`、schema 摘要、描述和可见性判断结果；调用时重新检查权限、审批、页面状态、超时和工具是否仍可执行。

工具名规范化采用与 codemode 等价的安全标识符规则：空名称映射为 `_`；连字符、点号和空白替换为下划线；其他不属于 JavaScript 标识符的字符被移除；数字开头的名称增加前导下划线；与 JavaScript 保留字冲突的名称增加后缀下划线。生成描述时同时保存 `safeName` 到原始工具名的映射，隔离执行环境只允许访问规范化名称，主页面调度器则使用映射表还原为真实注册项。

当多个原始工具名在同一命名空间内规范化为相同 `safeName` 时，默认策略为按照原始工具名、注册时间和注册序号形成稳定排序，保留第一个工具的基础 `safeName`，对后续工具依次追加 `_2`、`_3` 等稳定后缀，并将最终名称写入同一工具快照的动态描述和调度白名单。若系统配置为严格命名模式，则冲突项在注册阶段被拒绝并产生注册错误，不进入工具快照。无论采用默认改名策略还是严格拒绝策略，模型可见的名称、隔离环境代理方法和主页面调度映射均来源于同一快照，因此不会将两个原始工具调度到同一代理方法。

### 浏览器隔离执行与受控调度协议

一次浏览器侧运行会话的前置条件为：已经生成并冻结工具快照，已经创建全局唯一的 `runId`，已经为该 `runId` 绑定唯一消息端口，已经初始化待完成调用表、日志序号和运行状态，已经设置总超时定时器，并且注入的 `clientTools` 代理命名空间与 `toolSnapshotId` 完全一致。系统可以允许多个运行会话并行，但主页面必须以 `runId + 消息端口 + toolSnapshotId` 三元组定位会话；若配置为单会话模式，则新会话开始前应先取消或等待旧会话结束。端口不匹配、会话已结束或 `toolSnapshotId` 不一致的消息均被拒绝。

浏览器隔离执行器在一次代码执行开始时创建独立运行会话，并为该会话分配 `runId`、消息端口、待完成调用表和超时定时器。执行器将模型生成的代码规范化为可执行的异步函数，在隔离上下文中注入只包含代理命名空间、日志代理和有限运行时对象的执行模块。代理命名空间使用 `Proxy` 或等价方法拦截 `clientTools.safeName(args)` 形式的访问，将其转换为结构化消息，而不是在隔离上下文内保存真实工具函数。

`clientTools` 代理命名空间只对当前工具快照中的 `safeName` 返回可调用函数。访问未知属性时返回 `undefined`，实际调用未知工具时生成 `TOOL_NOT_REGISTERED` 错误；访问 `then` 返回 `undefined`，避免代理对象被 Promise 机制误识别为 thenable；访问 `constructor`、`prototype`、`__proto__`、`toString` 或 `Symbol` 属性时不暴露真实对象能力，必要时返回固定摘要函数或 `undefined`。重复读取同一 `safeName` 返回同一稳定代理函数，便于生成代码缓存引用。代理函数默认要求入参为可序列化对象；缺省入参按空对象处理，非对象入参、函数、DOM 节点或循环引用在序列化前被标记为参数错误。

隔离上下文采用默认拒绝、按需开放的能力策略。默认允许的全局能力限于异步函数执行、基础 ECMAScript 对象、定时器、`Promise`、结构化数据处理、受控日志代理和 `clientTools` 代理；默认不注入 DOM、组件实例、真实工具函数、剪贴板 API、`localStorage`、`indexedDB`、未授权网络 API、`XMLHttpRequest`、`WebSocket`、动态 `import`、`importScripts`、`eval` 和 `Function`。采用 Worker 或模块 Worker 时，通过创建受控脚本入口、限制 Blob URL 生命周期和内容安全策略约束模块加载及网络访问；采用 sandboxed iframe 时，默认不授予 `allow-same-origin`、`allow-forms`、`allow-popups` 等与工具执行无关的权限，仅在确有需要时加入最小 `sandbox` 权限。真实页面能力只能通过主页面调度器执行，不因隔离容器类型改变而直接暴露。

工具调用消息采用固定协议结构，至少包括 `type`、`runId`、`toolSnapshotId`、`callId`、`seq`、`timestamp`、`namespace`、`safeName` 和 `args`。其中 `type` 可为 `toolCall`、`toolResult`、`toolError`、`log`、`cancel` 或 `heartbeat`；`runId` 由主页面在会话创建时生成并保证全局唯一；`callId` 由隔离执行器在单个 `runId` 内单调递增生成；`seq` 用于检测重复消息和日志顺序。主页面只接受与当前会话三元组匹配的消息，并使用 `callId` 将异步结果回填到隔离环境中的待完成 Promise。重复 `callId`、未知 `callId`、端口不匹配、会话终态后的迟到消息或序号倒退消息均被拒绝并记录协议错误，不再触发真实工具执行。

参数、结果、错误和日志均通过结构化克隆或 JSON 序列化传输。默认规则为先尝试结构化克隆；若目标通道不支持，则转为 JSON 序列化；包含函数、DOM 节点、不可克隆对象、循环引用或超过大小限制的对象不得直接跨边界传递。参数大小超过工具注册项或系统默认上限时返回 `SERIALIZATION_FAILED` 或 `ARGUMENT_TOO_LARGE`；工具结果超过 `resultSizeLimit` 时按输出 schema 保留必要字段并生成摘要，仍无法摘要时返回 `RESULT_TOO_LARGE`。错误消息只传递错误类型、消息、字段路径和可恢复标记，不传递真实异常对象或主页面堆栈中的敏感引用。

在与既有客户端工具协议结合时，主页面调度器可以复用 `clientTools` 注册、`onToolCall` 执行入口、工具结果回填以及审批结果处理机制。对于一次 codemode 执行内部连续触发的多个客户端工具调用，主页面代表隔离执行器逐个完成真实工具调用，并按 `callId` 将结果或错误返回给隔离上下文；隔离上下文再将其还原为代理方法的返回值或异常。这样，单次生成代码可以组合多个浏览器侧工具，同时仍保持主页面对每次真实工具执行的控制权。

### 调用校验、异常传播与日志收集

主页面调度器对每一次工具调用按确定顺序执行校验，任一步失败即返回结构化错误且不继续调用真实工具。校验顺序为：确认 `runId` 对应会话处于运行态；确认消息端口与会话绑定端口一致；确认 `toolSnapshotId` 与会话快照一致；确认 `callId` 在本次运行内未重复且仍在待处理范围；用 `namespace + safeName` 在快照白名单中定位唯一注册项；确认工具在调用时未被注销且页面可见性条件仍满足；按 `inputSchema` 校验参数；检查权限条件和审批状态；检查并发限制、副作用等级和工具超时配置；最后调用真实工具执行函数。执行期间若权限或页面状态相对快照发生变化，调度器以调用时门禁为最终判断，返回 `TOOL_UNAVAILABLE` 或 `PERMISSION_CHANGED`，使生成代码可以捕获后切换到其他分支。

参数校验失败时，错误响应包含 schema 字段路径、期望类型、实际类型和失败原因。默认不进行隐式类型强制转换；额外字段默认剔除或按工具注册项配置拒绝；schema 中声明的默认值可在校验阶段填充，并将填充后的参数传递给真实工具。真实工具返回后，调度器按 `outputSchema` 执行输出校验；输出字段不符合 schema、包含不可序列化对象或超出 `resultSizeLimit` 时，返回 `OUTPUT_VALIDATION_FAILED`、`SERIALIZATION_FAILED` 或 `RESULT_TOO_LARGE`，并且不会把未校验的原始返回对象直接传给隔离环境。

审批机制采用状态机处理。`notRequired` 表示无需审批，校验通过后直接执行；`pending` 表示已向用户发起审批，隔离环境中的工具调用 Promise 保持挂起但受总运行超时和审批超时约束；`approved` 表示用户批准，调度器在真正执行前必须重新检查会话状态、工具快照、权限条件、页面可见性和参数有效性；`rejected` 表示用户拒绝，返回 `APPROVAL_REJECTED`；`expired` 表示审批超时，返回 `APPROVAL_TIMEOUT`。若审批等待期间运行取消、总超时、页面切换或工具被注销，则审批结果到达后不得继续调用真实工具，待完成 Promise 返回 `RUN_TERMINATED` 或 `TOOL_UNAVAILABLE`。

| 错误类型 | 触发条件 | 处理结果 |
| --- | --- | --- |
| TOOL_NOT_REGISTERED | 快照中不存在 `namespace + safeName` 或模型调用未知代理方法 | 拒绝调用并向隔离环境抛出错误 |
| TOOL_UNAVAILABLE | 工具被注销、页面状态不满足可见性条件或快照项不可执行 | 不调用真实工具，返回不可用错误 |
| PERMISSION_DENIED / PERMISSION_CHANGED | 用户权限不足或调用时权限相对生成阶段发生变化 | 不调用真实工具，返回权限错误 |
| APPROVAL_REJECTED / APPROVAL_TIMEOUT | 用户拒绝审批或审批等待超时 | 结束该次工具调用 Promise |
| ARGUMENT_VALIDATION_FAILED / OUTPUT_VALIDATION_FAILED | 入参或出参不符合 schema | 返回字段路径和校验原因 |
| TOOL_EXECUTION_FAILED / TOOL_CALL_TIMEOUT | 真实工具抛错或单工具调用超时 | 回填工具异常并触发清理规则 |
| RUN_TERMINATED / PORT_CLOSED | 运行已进入终态、消息端口关闭或隔离环境不可达 | 拒绝迟到消息并清理待完成调用 |
| SERIALIZATION_FAILED / RESULT_TOO_LARGE | 参数、结果或日志无法序列化或超过大小限制 | 返回摘要化或序列化错误 |

错误响应包含 `callId`、错误类型、错误消息和必要的可恢复标识。隔离执行环境收到错误响应后，将其转换为对应代理方法抛出的 `Error`，使模型生成代码中的 `try/catch`、条件分支或补偿逻辑能够处理失败；若生成代码未捕获该错误，则执行器将错误作为本次代码执行结果的 `error` 字段返回。由此，非法调用和真实工具异常在协议层被统一收敛，避免出现部分错误只在主页面控制台可见、模型侧无法感知的情况。

隔离执行环境同时重写或代理 `console.log`、`console.warn` 和 `console.error`，将日志记录为 `{runId, seq, level, timestamp, text, objectSummary}` 结构。`seq` 在单次运行内递增以保证展示顺序；`timestamp` 记录日志产生时间；`text` 保存字符串化摘要；`objectSummary` 默认只展开有限层级对象并截断数组和长字符串。系统为每次运行设置日志最大条数和总长度，超过限制后追加截断标记而不是继续无限缓存；对字段名匹配 token、password、secret、authorization、cookie 等敏感模式的内容进行脱敏。由于日志只跨边界传递可序列化摘要，真实 DOM 节点、函数引用和浏览器对象不会进入模型可见结果。

### 超时控制、资源释放与隔离容器等价实现条件

运行会话采用单向状态机管理，状态包括 `created`、`running`、`cancelling`、`finished`、`timedOut`、`failed` 和 `released`。会话创建后进入 `created`，隔离代码开始执行后进入 `running`；用户取消或上层请求终止时进入 `cancelling`；代码正常返回进入 `finished`；总超时进入 `timedOut`；隔离环境崩溃、消息端口关闭且无法恢复、协议错误不可继续时进入 `failed`；完成清理后进入 `released`。`finished`、`timedOut`、`failed` 和 `released` 为终态链路的一部分，第一个终态原因写入最终执行结果，后续迟到结果、迟到审批和迟到工具返回不得覆盖已有最终结果，也不得再触发真实工具。

每次浏览器侧代码执行均设置总超时时间，并按工具注册项设置单次工具调用子超时。执行器通过总执行 Promise、待完成工具调用 Promise、审批等待 Promise 和超时定时器之间的竞争确定最终状态。正常完成时返回代码结果、工具结果摘要和日志；发生总超时时，将会话迁移为 `timedOut`，向所有待完成调用返回超时或运行终止错误，并阻止后续同一 `runId` 的消息继续触发真实工具执行；发生单工具调用超时时，仅结束该 `callId` 对应的 Promise，并按工具副作用声明决定是否取消、补偿或继续等待清理完成。

真实客户端工具的副作用控制由注册项声明。注册项可声明 `cancellable`、`idempotent`、`allowConcurrent`、`requiresCompensation` 和 `cleanup`。当 `cancellable` 为真时，调度器在超时、取消或会话失败时向真实工具传递 `AbortSignal`；当 `allowConcurrent` 为假时，同一工具在同一会话或同一页面范围内存在未完成调用时，新调用返回重入错误或排队等待；当 `requiresCompensation` 为真时，工具异常、取消或超时后调用补偿清理回调；当工具声明为非幂等且具有外部副作用时，调度器在重复 `callId` 或重试场景下只返回既有状态，不再次执行真实工具。

运行结束后，资源释放模块按会话维度执行清理：终止 Worker 或移除 sandboxed iframe；关闭或解绑 `MessagePort`；清空待完成调用表；移除事件监听器；撤销临时代码 Blob URL；清除定时器；释放与本次动态描述和日志相关的临时缓存。若真实客户端工具内部还打开了浏览器会话、订阅或长连接，调度器可在工具注册信息中声明清理回调，并在运行结束、取消或异常路径中调用该回调。

消息通道异常按会话失败处理。若 `MessagePort` 关闭、结构化克隆失败、隔离上下文不可达或 iframe/Worker 非正常退出，主页面将会话迁移为 `failed` 或 `cancelling`，拒绝新的工具调用，清空待完成调用表，对可取消工具发送取消信号，并执行已登记的清理或补偿回调。若错误无法通过端口回传给隔离环境，则主页面在最终执行结果中记录通信错误；若端口恢复后出现迟到消息，仍按会话终态规则拒绝。

隔离容器可以采用浏览器 Worker、模块 Worker、带 sandbox 属性的 iframe 或其他具备脚本隔离和消息通信能力的容器，但不同容器必须满足等价实现条件：生成代码只获得 `clientTools` 代理、受控日志代理和有限 ECMAScript 运行时；网络、存储、DOM、剪贴板、动态加载和代码求值能力默认关闭或由宿主显式替换；跨边界通信只允许结构化工具调用、结果、错误和日志消息；运行结束后可确定地销毁容器、解绑端口并撤销临时资源。由于真实函数不被注入隔离上下文，调度时又以 `toolSnapshotId + namespace + safeName` 查找唯一白名单项，异常以结构化错误回填，终态后迟到消息被拒绝并清空监听器，因此能够分别降低页面污染、避免误调度、统一异常传播并实现资源确定释放。
