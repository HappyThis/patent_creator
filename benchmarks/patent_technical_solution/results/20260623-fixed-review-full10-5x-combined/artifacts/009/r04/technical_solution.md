## 技术方案

### 总体构思

本方案在浏览器侧设置面向模型生成代码的隔离执行层，并在主页面设置受控的客户端工具调度层。本文中，工具命名空间是模型代码中可见的调用入口，等同于实现中的 provider；`requestId` 表示一次模型代码执行请求，`toolCallId` 表示该执行请求内的一次具体工具调用，二者形成一对多关系。每次会话或模型回合开始前，主页面从当前页面状态、前端组件能力、浏览器能力或外部接入能力中收集可用客户端工具，将工具名称、说明、输入参数 JSON Schema、审批属性和执行约束组装为动态工具描述，再转换为模型可理解的代码调用接口，使模型不是直接访问页面对象或任意网络资源，而是生成调用受控工具命名空间的异步代码。

隔离执行层负责对模型生成代码进行归一化、校验和限时执行；受控调度层负责将代码中的工具调用转换为带有关联标识的协议消息，发送给主页面中的实际工具执行器，并把执行结果、拒绝原因或异常信息回传给隔离代码。通过该结构，模型可以在一次代码执行中组合多个动态客户端工具，同时主页面仍保持对工具集合、参数、审批、超时、日志和资源释放的控制。

### 系统组成

本方案可以包括动态工具注册与描述模块、工具名规范化模块、代码归一化与校验模块、隔离执行容器、隔离侧工具调用代理、跨上下文协议桥、主页面工具执行器以及结果与清理控制模块。动态工具注册与描述模块维护当前可用客户端工具清单，每个工具注册时必须提供工具命名空间、原始工具名、模型可读说明、输入参数 schema、执行入口、权限标识和可用性判断条件；缺少必要字段的工具不进入本轮快照。注册表更新采用原子替换方式生成新版本快照，同一 `requestId` 绑定一个确定快照版本，不在代码执行中途部分更新可见工具接口。

工具名规范化模块将原始工具名转换为合法的代码标识符：连字符、点号和空白字符转换为下划线，不能出现在标识符中的字符被去除，数字开头的名称添加下划线前缀，JavaScript 保留字添加下划线后缀。冲突处理采用确定性优先级：先以工具命名空间隔离不同来源的同名工具；同一命名空间内若规范化名称冲突，则在后注册工具的规范化名称后追加由“命名空间 + 原始工具名 + 注册来源”计算得到的稳定短哈希；若仍无法形成稳定唯一名称，则拒绝该工具进入快照。映射表按快照版本保存 `namespace`、`normalizedName`、`originalName` 和执行入口，模型看到的接口与主页面实际执行函数由该映射表单向关联。

隔离执行容器用于运行模型生成的异步代码，只向代码暴露白名单全局能力和一个或多个受控工具命名空间，不暴露主页面对象、DOM 节点、真实工具函数、浏览器私有 API 或任意网络访问能力。隔离侧工具调用代理在隔离环境内以 `Proxy` 对象拦截 `namespace.toolName(args)` 形式的属性读取和函数调用；跨上下文协议桥负责把代理产生的请求传给主页面；主页面工具执行器负责按快照映射表、当前页面状态和权限上下文进行二次校验并执行真实工具。由此将隔离侧代理、跨上下文通信和主页面校验执行三个层次分开，避免模型代码直接接触高权限对象。

协议桥用于在隔离执行容器、主页面工具执行器和会话服务之间传递代码执行事件、工具调用事件、工具结果事件和审批事件。每条消息均携带发送方标识、通道令牌、`requestId`、可选 `toolCallId`、`snapshotId`、消息序号和状态字段，接收方先校验来源、令牌和序号，再更新本地状态机。结果与清理控制模块统一收集最终返回值、工具异常、控制台日志、超时状态和待释放资源，并根据终态不可覆盖规则将工具结果写回对应会话消息。

### 核心数据结构

动态工具描述以 `snapshotId` 为版本标识，每个工具项包括 `namespace`、`normalizedName`、`originalName`、`description`、`inputSchema`、`outputSchema`、`approvalRequired`、`permissions`、`maxCalls`、`timeoutMs`、`availableWhen`、`sideEffectLevel` 和 `autoContinueAllowed`。其中 `availableWhen` 由页面组件挂载状态、用户权限、账号上下文和外部连接状态计算得到；`sideEffectLevel` 用于区分只读工具、可回滚工具和不可重复副作用工具；`autoContinueAllowed` 用于限制工具结果是否可以触发模型自动继续。

规范化映射表按 `snapshotId` 存储，每条记录包括工具命名空间、规范化名称、原始名称、稳定别名、执行入口引用、参数 schema 摘要、输出 schema 摘要、权限摘要、注册来源和注册序号。隔离代码只能看到规范化名称和类型描述，主页面执行器通过映射表反查真实工具。映射表在快照生成后只读，工具注册表发生变化时生成新的 `snapshotId`，不修改已经绑定到运行中 `requestId` 的旧映射。

协议消息采用统一封装结构，包括 `type`、`sender`、`channelToken`、`requestId`、`toolCallId`、`snapshotId`、`namespace`、`normalizedName`、`payload`、`state`、`errorCode`、`errorText`、`retryable`、`sequence` 和 `timestamp`。`type` 可表示代码执行开始、工具调用、审批请求、审批结果、工具结果、取消、超时和心跳；`state` 在工具调用生命周期中从 `created` 迁移到校验、审批、执行或终态。接收方以 `requestId + toolCallId + sequence` 进行关联和去重。

错误结果采用结构化封装，包括 `ok=false`、`errorCode`、`errorText`、`retryable`、`terminal`、`diagnosticId` 和可选 `safeDetails`；普通输出采用 `ok=true`、`output`、`outputType`、`truncated` 和 `contentRef`。日志记录包括 `requestId`、可选 `toolCallId`、日志级别、序号、时间戳和脱敏后的内容。执行上下文包括用户标识摘要、会话标识、页面实例标识、权限版本、账号上下文、快照版本、取消令牌和调用计数器，用于后续复核、限流、取消和资源清理。

### 运行流程

1. 主页面在模型请求前原子读取工具注册表，剔除缺少 schema、执行入口、权限标识或可用性条件的工具，按规范化规则生成 `snapshotId`、动态工具描述和只读映射表，并将该 `snapshotId` 绑定到本次 `requestId`。
2. 模型基于工具描述生成异步代码；代码执行请求携带 `requestId`、`snapshotId`、通道令牌、最大代码长度、最大执行时长、最大调用次数和自动继续上限。隔离执行层在校验通过后启动容器，并只注入与该快照对应的工具命名空间代理。
3. 代码执行期间，隔离侧代理把每次 `namespace.toolName(args)` 转换为包含 `toolCallId`、`requestId`、`snapshotId`、命名空间、规范化工具名和参数载荷的异步协议请求；同一 `requestId` 内的 `toolCallId` 单调生成或采用随机不可预测标识，保证不同并发调用可独立关联。
4. 主页面收到工具调用后按固定判断链处理：校验消息来源和通道令牌，确认 `snapshotId` 属于该 `requestId`，检查 `toolCallId` 未处于终态，反查命名空间和规范化名称，复核当前组件、权限和账号上下文，校验参数 schema，检查调用次数、并发数、频率和工具超时配置。
5. 无需审批且通过复核的工具进入执行状态；需要审批的工具进入等待审批状态，主页面发送审批请求并暂停真实执行。审批批准后再次执行当前状态复核，仍通过才执行工具；审批拒绝、等待超时或复核失败均返回结构化错误。
6. 工具输出经输出 schema、大小和可序列化性校验后封装为工具结果消息；普通对象直接返回，空输出标记为空结果，大对象或二进制数据写入受控临时引用并返回 `contentRef`，结构化克隆失败、输出超限或含敏感字段时返回截断、脱敏或错误结果。
7. 隔离容器按各 `toolCallId` 的 Promise 接收乱序返回；成功结果解析为函数返回值，错误结果在隔离代码内抛出普通异常。未被捕获的异常、代码语法错误、协议断开或执行超时被统一封装为本次代码执行失败。
8. 代码执行完成后，结果与清理控制模块结算所有挂起 Promise、写回会话消息、收集日志并释放临时资源。若工具结果满足自动继续条件，则使用最近有效且与会话上下文匹配的客户端工具描述触发后续模型生成。

### 关键控制规则

针对动态工具描述，本方案采用“执行前快照 + 调用时复核”的流程。执行前，主页面基于工具注册表、页面实例、用户权限和组件挂载状态生成 `snapshotId`，并将该快照绑定到 `requestId`；工具调用时，协议消息必须携带同一 `snapshotId`，主页面先按该快照的映射表定位工具，再按当前页面状态复核 `availableWhen`、权限版本、账号上下文、组件实例是否仍存在以及工具调用次数是否超限。复核失败时返回 `TOOL_UNAVAILABLE`、`PERMISSION_CHANGED`、`COMPONENT_UNMOUNTED` 或 `SNAPSHOT_EXPIRED` 等结构化错误，并标明是否允许自动继续。

针对非法工具调用，本方案在隔离环境和主页面两侧均设置拦截。隔离环境仅创建已注册工具命名空间的代理对象，代理的 `get` 拦截器在读取工具属性时返回异步函数，并禁止访问 `then`、`constructor`、`__proto__`、`prototype`、内部调度字段和未声明命名空间；该异步函数在调用时生成 `toolCallId`，序列化参数并发送协议请求。主页面再次检查工具名是否存在于映射表、参数是否为可解析 JSON、参数结构是否符合 schema、调用来源和通道令牌是否合法，以及调用限制是否满足；不满足任一条件时不执行真实工具，而是返回标准化错误结果。

针对参数和输出校验，本方案优先采用 JSON Schema 2020-12 或等效版本描述输入输出。输入校验默认不允许 schema 外额外字段，除非工具显式声明 `additionalProperties=true`；默认值可在校验阶段填充，字符串到数字、布尔值等隐式类型转换默认禁止，避免模型生成代码因宽松转换触发非预期工具行为。系统同时限制对象和数组嵌套深度、数组长度、字符串长度和总字节数；不可序列化对象、函数、DOM 对象、循环引用或结构化克隆失败的数据被拒绝并返回 `INVALID_ARGUMENT`。输出侧按 `outputSchema` 校验，大结果、二进制结果和敏感字段分别通过 `contentRef`、截断标记或脱敏规则处理，输出超限时返回 `OUTPUT_TOO_LARGE` 而非继续向模型暴露完整内容。

针对代码归一化、隔离和日志收集，本方案先剥离 Markdown 代码围栏及语言标记，将空代码归一化为空异步函数，将箭头函数直接作为执行体，将函数声明包装为调用表达式，将普通语句块包装为 `async () => { ... }`，并可将最后一个顶层表达式改写为返回值；顶层 `await` 保留在异步包装函数内，顶层 `return` 仅允许出现在函数体或包装后的语句块中。解析阶段发现语法错误、静态 `import`、动态 `import()`、访问危险全局或超出代码长度时，拒绝启动容器。容器仅开放白名单全局对象和受控工具代理，对 `fetch`、`XMLHttpRequest`、`WebSocket`、`importScripts`、`eval`、`Function`、`indexedDB`、`localStorage`、DOM 入口和浏览器敏感 API 进行删除、替换为抛错函数或通过 sandbox 权限禁用；同时包装 `console.log`、`console.warn` 和 `console.error`，按序号、级别和大小限制收集日志并执行脱敏。

针对超时、取消和资源释放，本方案为代码执行、单次工具调用、审批等待和协议心跳分别设置超时，并为每个 `requestId` 创建取消令牌或 `AbortController`。任一终止条件触发时，系统先停止隔离代码继续派发新工具调用，再向仍在执行的工具传递取消信号；支持取消的工具应停止外部请求、浏览器会话或定时任务，无法中止的工具被标记为隔离运行，其后续回调作为迟到结果丢弃并记录诊断日志。清理阶段按顺序结算挂起 Promise、关闭通道、移除监听器、清除定时器、释放 Worker、sandbox iframe 或 Worklet、断开外部连接、清除临时内容引用和快照映射；终态已经写回的 `toolCallId` 不再被迟到的成功、失败、取消或超时消息覆盖。

针对审批型工具，本方案为每个 `toolCallId` 维护状态机，状态包括 `created`、`validating`、`pendingApproval`、`approved`、`rejected`、`executing`、`succeeded`、`failed`、`timeout` 和 `cancelled`。工具调用创建后先进入校验状态；需要审批且校验通过时进入等待审批状态；用户批准后并不立即执行，而是再次复核快照、页面组件、权限版本和账号上下文，复核通过才进入执行状态；用户拒绝、审批超时、权限撤销或组件卸载均进入相应终态。`succeeded`、`failed`、`rejected`、`timeout` 和 `cancelled` 为终态，终态不可被后续非终态或迟到消息覆盖。

针对并发调用和消息去重，本方案允许同一代码执行内多个工具调用并发发出并乱序返回，隔离侧按各自 `toolCallId` 对应的 Promise 独立解析。主页面以 `requestId + toolCallId` 建立幂等记录：重复到达的工具调用若尚未执行则返回当前挂起状态，若已处于终态则返回已记录结果；对于 `sideEffectLevel` 标记为不可重复的工具，重复请求不得再次执行。重复结果、迟到结果或序号回退消息被丢弃并记录，协议断开、页面刷新、Worker 终止或服务端连接断开时，未进入终态的调用统一迁移为 `cancelled` 或 `failed`，除非通道在同一 `requestId`、同一令牌和未过期快照下恢复成功。

针对自动继续，本方案仅在工具结果为成功、工具描述仍与会话上下文匹配、`autoContinueAllowed` 为真、未发生用户拒绝或权限变化、连续失败次数未超限且自动继续次数未达到预设上限时触发。自动继续使用最近一次已持久化且与当前权限版本兼容的客户端工具描述；若工具不可用、参数错误、审批拒绝、协议异常、连续失败、快照变化超过兼容阈值或达到最大连续次数，则停止自动继续并将当前状态返回给用户或上层会话控制器，避免模型因工具错误或状态变化进入无限续写循环。

### 可选实施方式

无论隔离执行容器采用 Web Worker、带 sandbox 属性的 iframe、Worklet 还是浏览器扩展隔离上下文，均应满足共同约束：真实工具函数、页面 DOM、浏览器会话、网络连接、持久化存储和敏感 API 保持在主页面或受信任宿主侧；隔离侧只获得白名单全局能力、工具命名空间代理和带令牌的消息通道。在 Web Worker 中，可以通过预置启动脚本删除或替换危险全局并使用 `MessageChannel` 通信；在 sandbox iframe 中，可以通过 sandbox 属性、独立 origin 和 `postMessage` 来源校验限制脚本、表单、弹窗和同源访问；在 Worklet 或扩展隔离上下文中，可以利用其天然受限 API，并在宿主侧继续执行同样的来源、令牌、快照和权限复核。

客户端工具与服务端会话工具可以共同提供给模型，但二者执行位置和调用路径不同：服务端会话工具由服务端按服务端权限执行，客户端工具仅向模型提供 schema 和说明，真实执行函数保留在浏览器。模型生成代码调用客户端工具时，系统将调用转换为客户端工具事件；浏览器执行完成后发送包含 `toolCallId`、`toolName`、输出、状态和错误文本的工具结果消息。会话侧根据 `toolCallId` 定位原有工具调用片段，按幂等和终态不可覆盖规则更新消息状态并广播给其他连接；若工具结果满足自动继续条件，则使用最近一次兼容的客户端工具描述继续模型回合。

对于需要用户确认的客户端工具，可以在主页面工具执行器中启用审批状态机。审批期间若发生组件卸载、权限撤销、账号切换、工具 schema 更新或快照过期，批准动作不直接触发执行，而是先进入再次复核；复核失败时返回 `APPROVAL_STALE`、`PERMISSION_CHANGED` 或 `TOOL_UNAVAILABLE` 等错误。用户拒绝时返回带拒绝原因的错误结果，审批超时或通道断开时进入 `timeout` 或 `cancelled` 终态。该机制使审批型工具仍可纳入统一协议和异常传播流程，同时避免隔离代码绕过主页面审批逻辑直接执行高风险页面操作。
