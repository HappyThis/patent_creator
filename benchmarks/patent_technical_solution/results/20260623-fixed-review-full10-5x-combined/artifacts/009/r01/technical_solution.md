## 技术方案

### 总体架构

本方案在现有代码模式的“模型生成异步代码、隔离执行环境运行、工具调用经受控工具调度组件执行”的基础上，将浏览器主页面中的页面状态读取、前端组件能力、浏览器 API 和动态客户端工具纳入同一编排体系。为避免术语混用，本文中“主页面工具网关”指运行在浏览器主页面、负责工具注册、权限判断、协议校验和真实工具执行的组件；“隔离执行容器”指运行模型生成代码且只持有受限消息端口的 Web Worker、受限 iframe 或等价隔离环境；“执行管理器”负责生成工具快照、启动容器、维护运行状态、收集日志并执行清理；“代理命名空间”指注入容器内、把函数调用转换为协议消息的受限接口。

一次浏览器侧代码模式运行按如下顺序执行：1）主页面工具网关接收页面或组件注册的工具条目，记录原始工具名、命名空间、工具标识、参数约束、权限要求和清理回调；2）执行管理器基于当前会话生成工具快照，并据此生成供模型使用的接口描述；3）模型按照该接口描述输出模型生成代码，执行管理器将其包装为返回 Promise 的异步入口函数；4）执行管理器创建隔离执行容器，绑定 $sessionId$、$runId$、$snapshotId$ 和专用消息端口；5）容器内的代理命名空间把工具调用转换为携带 $callId$ 的请求消息；6）主页面工具网关按工具快照和当前权限规则校验消息后执行真实工具；7）执行结果、错误和日志经同一端口回传并按 $callId$ 解析到对应 Promise；8）运行完成、失败、取消或超时后，执行管理器按固定顺序释放容器、端口、句柄、快照和日志缓冲资源。

该架构的关键边界在于，隔离执行容器只拥有执行管理器显式注入的代理命名空间和专用消息端口，不持有主页面全局对象、组件实例、DOM 引用或未授权网络能力。主页面工具网关维护真实工具函数、页面状态、权限确认结果和受限句柄；隔离执行容器仅运行组合逻辑。通过工具快照和名称映射可以避免注册表突变导致非预期工具调用，通过端口、$sessionId$ 与 $runId$ 的组合校验可以避免跨容器消息注入，通过 $callId$ 与未决 Promise 表可以避免并发或乱序响应错配。

### 动态工具描述与名称映射

浏览器侧工具可以由页面、组件或嵌入应用在运行时注册。主页面工具网关为每个工具条目记录 $toolId$、原始工具名、命名空间、说明、参数 JSON Schema 或等价结构化约束、返回值说明、$executionTarget$、权限要求、可见条件、注册状态、运行状态以及可选清理回调。执行管理器只根据当前会话可见的工具条目生成接口描述，使模型能够按异步函数形式组合调用工具，而无需知道工具在主页面中的具体实现位置。

名称规范化以原始工具名、命名空间和 $toolId$ 为输入，输出规范化名称和双向映射项。具体规则为：先对名称进行字符归一化，将连字符、点号和空白字符替换为下划线；再移除或转义其他不能出现在 JavaScript 标识符中的字符；若结果为空则使用下划线作为兜底；若以数字开头则添加下划线前缀；若与 JavaScript 保留字相同则追加下划线后缀。随后在同一命名空间内进行碰撞检测，若多个工具得到相同规范化名称，则根据命名空间、$toolId$ 或其稳定哈希生成后缀，而不是根据临时遍历顺序生成后缀，以保证同一会话内多次提示生成和执行时映射稳定。

工具快照在提示生成前固化，并在隔离执行容器启动和主页面工具网关校验时使用同一 $snapshotId$。快照至少包含 $snapshotId$、$sessionId$、版本号、失效时间、工具条目版本、规范化名到原始名及 $toolId$ 的映射、参数约束、权限要求、可见条件求值结果、可调用状态、$executionTarget$、受限句柄集合和最大并发配置。执行开始后新增工具不进入本次快照；已被页面移除的工具在调用时返回 toolUnavailable 错误；可见条件和权限若声明为快照型，则以快照结果为准，若声明为实时型，则在每次调用前由主页面工具网关重新求值。

### 隔离执行容器与受控调用协议

隔离执行容器接收模型生成代码、工具快照、运行期限和专用消息端口。执行管理器将模型生成代码包装为异步入口函数，入口函数的返回值作为本次运行结果；普通表达式、函数体或带代码围栏的文本可以先被归一化为异步函数形式，完整的工具名规范化则只作用于工具接口，不与代码包装混同。容器启动时在局部作用域注入代理命名空间，代理命名空间可以通过 JavaScript Proxy 动态拦截工具名，也可以由工具快照静态生成函数表；两种方式均不得暴露主页面对象引用。

主实现优先采用 MessageChannel 建立主页面工具网关与隔离执行容器之间的一对一端口；采用 postMessage 或其他等价机制时，也必须满足端口绑定、来源校验和相同消息格式。协议消息包含 $type$、$sessionId$、$runId$、$snapshotId$、$callId$、$normalizedToolName$、$args$、$timestamp$、$deadline$、$payload$、$error$ 和 $logLevel$ 等字段。$callId$ 由容器内代理按运行内单调递增序列或随机唯一值生成，并与未决 Promise 表绑定；结果消息和错误消息均按 $callId$ 匹配，而不依赖返回顺序。

代理函数被调用时先检查运行状态是否仍为 running，再为本次调用登记未决 Promise、调用开始时间、截止时间和规范化工具名。主页面工具网关可按快照设置限制全局并发数和单工具并发数；超过限制的调用返回 concurrencyLimit 错误。重复 $callId$ 的请求被拒绝；未知 $callId$、重复响应或迟到响应只写入协议日志，不得改变已完成 Promise 的状态。若代码访问不存在的工具名、读取非函数属性、枚举未暴露属性或传入不可序列化参数，代理函数返回结构化错误或拒绝对应 Promise。

隔离执行容器的全局能力按最小授权原则配置。默认禁止或替换 import 动态加载、eval、Function 构造器、fetch、XMLHttpRequest、localStorage、IndexedDB、BroadcastChannel、SharedWorker、跨窗口访问和任意导航能力；确需开放的能力必须被封装为工具条目并经过主页面工具网关校验。对于 CPU 密集型死循环或微任务无限递归等不发起工具调用的情形，执行管理器不依赖子调用超时，而是基于总运行期限强制终止 Worker 或销毁 iframe，并将运行状态置为 timedOut 或 failed。

工具返回值采用结构化克隆或 JSON 可序列化格式传输。无法序列化的 DOM 节点、组件实例、事件对象、浏览器会话对象等页面对象，必须由工具函数在主页面内转换为摘要、稳定标识符或受限句柄。受限句柄包含 $handleId$、$sessionId$、$runId$、$snapshotId$、来源 $toolId$、允许调用范围、有效期、最大使用次数和释放状态；跨会话、跨快照、跨工具链路或超过使用次数的句柄调用均返回 invalidHandle 错误。

### 调用校验、异常传播与日志回传

主页面工具网关在执行工具前进行双端校验。隔离执行容器可先做轻量校验，用于提前发现不可序列化参数、未知规范化名称和本地长度限制；主页面工具网关再进行权威校验，包括端口来源、$sessionId$、$runId$、$snapshotId$、$callId$ 唯一性、工具映射、注册状态、可见状态、权限状态、运行状态和参数结构。参数 JSON Schema 校验默认不允许额外属性，除非工具条目显式声明允许；默认值可由网关按 Schema 补齐；类型转换默认禁止，只有安全转换策略声明后才可执行；数组长度、字符串长度、对象深度和字节大小均按快照中的资源限制检查。

校验失败时返回包含 $errorType$、$message$、$toolName$、$callId$、$schemaPath$、$receivedType$、$limit$ 和是否可重试字段的结构化错误。$errorType$ 至少区分 unknownTool、snapshotMismatch、validationError、permissionDenied、userCancelled、toolUnavailable、toolInternalError、browserApiError、serializationError、callTimeout、runTimeout、containerTerminated、protocolError、concurrencyLimit 和 invalidHandle。unknownTool、validationError、permissionDenied、userCancelled、toolInternalError、browserApiError、serializationError、callTimeout、concurrencyLimit 和 invalidHandle 通常只拒绝单个工具 Promise；snapshotMismatch、runTimeout、containerTerminated、端口来源不匹配或严重 protocolError 终止整次代码运行。

需要用户确认的工具在执行前由主页面工具网关生成确认请求，确认请求绑定 $callId$、规范化工具名、原始工具名、$toolId$ 和参数摘要。参数摘要可以由规范化序列化结果计算得到，用于防止一次确认被复用于不同参数或不同工具。确认结果仅对该 $callId$ 有效；用户拒绝返回 userCancelled 或 permissionDenied，确认超时返回 callTimeout，页面关闭或端口断开返回 containerTerminated 或 protocolError；重复确认请求若参数摘要一致可复用正在等待的确认界面，若摘要不同则作为新的确认请求处理。

日志由隔离执行容器和主页面工具网关分别采集并由执行管理器合并。日志记录普通日志、警告、错误、工具调用开始、工具调用结束、确认请求、取消事件和协议异常，并附加时间戳、$sessionId$、$runId$、$callId$ 与日志级别。日志缓冲区设置最大条数和最大字节数；超过容量时优先保留首部执行上下文和尾部错误上下文，中间日志以截断标记替代。工具参数和返回值默认不完整写入日志，只记录工具名、参数摘要、结果类型和大小；包含页面文本、用户输入、令牌、定位、剪贴板、组件私有状态等敏感字段时按字段级脱敏或禁止记录。

协议异常按影响范围处理。消息来源不匹配、$sessionId$ 或 $runId$ 不匹配、快照版本不一致、端口断开、响应无法反序列化或未知消息类型影响协议可信边界时，执行管理器将运行置为 failed 并拒绝全部未决调用；缺少必要字段、$callId$ 不存在、重复响应或迟到响应只记录 protocolError，并拒绝对应调用或丢弃该消息。该处理规则使协议错误不会被误认为工具业务错误，也避免异常消息覆盖已经完成的运行结果。

### 超时控制、取消与资源释放

执行管理器维护运行状态机和独立的清理标记。运行状态包括 pending、running、cancelling、completed、failed、cancelled、timedOut 和 released；容器启动前为 pending，异步入口函数开始后为 running，用户取消或总超时触发后进入 cancelling 并立即拒绝新工具调用，正常返回进入 completed，未恢复的协议级错误进入 failed，用户取消完成后进入 cancelled，总运行期限届满进入 timedOut，资源清理结束后进入 released。终态优先级按运行中断原因确定：总运行超时、容器被强制终止、用户取消和协议级失败均高于迟到的正常工具结果；同一运行一旦写入 completed、failed、cancelled 或 timedOut，后续消息只能触发清理或日志记录，不能改写最终状态或最终返回值。

超时分为单次工具调用超时和总运行超时。单次工具调用超时只拒绝对应 $callId$ 的 Promise，并将其从未决调用表移出；该工具的迟到结果只能写入日志，不得覆盖超时错误。总运行超时、用户取消或容器终止的优先级高于正常工具结果：一旦运行进入 cancelling、cancelled、timedOut 或 failed，后续到达的工具结果不得解析 Promise、不得修改最终返回值。若模型生成代码出现死循环或微任务无限递归，执行管理器按总运行期限强制 terminate 隔离执行容器，并将全部未决调用统一标记为 runTimeout 或 containerTerminated。

资源释放由执行管理器按幂等清理流程执行。清理开始时先为本次运行写入 releasing 标记并停止接收新请求；随后拒绝未决 Promise、向已发起的工具调用发送取消信号或关闭其可取消句柄、关闭消息端口、终止隔离执行容器、释放受限句柄、调用工具条目的清理回调、删除工具快照与映射缓存，最后截断或封存日志缓冲区。每个清理动作均记录已执行标记，重复进入清理流程时只跳过已完成动作，不重复释放同一端口、容器、句柄或页面资源。清理回调失败或超时仅生成清理错误日志并继续后续步骤，不得阻塞其他资源释放，也不得把已确定的 completed、failed、cancelled 或 timedOut 终态改写为新的业务结果。

在一种实现中，浏览器侧隔离执行可与既有服务端代码模式并存。工具快照中的 $executionTarget$ 用于声明工具由 client 或 server 执行：执行管理器对 client 工具建立到主页面工具网关的受控通道，对 server 工具沿用服务端隔离执行器或服务端工具调度器；同一次模型生成代码中的代理命名空间仍呈现统一异步函数接口。若客户端工具与服务端工具的原始名称或规范化名称冲突，优先通过不同命名空间隔离；仍发生碰撞时依据工具条目的显式优先级、$toolId$ 稳定后缀或稳定哈希后缀生成唯一名称，禁止后注册工具覆盖已进入快照的同名工具。两类执行目标均返回统一的结果封装、结构化错误、日志字段和超时语义，使模型侧无需关心真实工具位于浏览器主页面还是服务端环境。
