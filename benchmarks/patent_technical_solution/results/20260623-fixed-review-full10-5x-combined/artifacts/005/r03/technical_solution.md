## 技术方案

本方案要解决的是：智能工作台已经具有应用内任务创建、维护和展示能力，但开发者和 agent 还需要在不直接访问应用数据库的情况下，通过外部协作载体理解任务队列、任务状态和处理优先级。下文将“外部协作载体”统一指代码仓库或等价 Git 托管协作对象，例如 GitHub Issues、其他 Git 平台 issue 或仓库内结构化任务文件；“外部协作条目”指其中承载单个任务镜像的条目。本方案围绕任务主记录与外部协作条目之间的身份绑定、语义映射、双向同步、回环抑制、冲突处理和故障隔离建立可执行的同步机制。

### 主存储优先的同步总体架构

本方案以任务主记录为唯一可信源，应用数据库和任务看板仍承担创建、查询、拖拽流转、分配、优先级调整和质量门禁等主流程；外部协作载体仅作为可选镜像。同步链路不改变应用内事务边界：本地任务操作先完成并生成任务变更事件，随后由同步编排层决定是否把该事件转换为外部协作条目的创建、更新、关闭或冲突记录。由此，外部平台不可用时不会阻断本地任务流转。

任务变更事件的输入包括任务标识、项目标识、工作空间标识、变更字段集合、本地版本号、事件产生时间和操作者来源。同步编排层读取项目同步配置后输出四类动作：创建外部协作条目请求、更新外部协作条目请求、入站回写事务或同步失败记录。外部协作适配层负责把任务字段转换为外部标题、正文、开启/关闭状态和受控标签；同步观测层记录推送水位、拉取水位、外部最近观测时间、错误码和重试状态，使镜像健康情况可被查询和恢复。

### 任务主记录与外部协作条目的身份绑定和数据模型

任务主记录至少包括任务标识、标题、描述、状态、优先级、负责人、项目标识、工作空间标识、普通标签、创建时间、更新时间和本地版本号。为建立外部身份，还设置外部仓库标识、外部条目编号、外部最近更新时间、最近推送时间 $last\_pushed\_at$、最近拉取时间 $last\_pulled\_at$、外部最近观测时间 $last\_external\_seen\_at$、最近推送字段哈希和同步来源批次号等字段。项目同步配置记录项目级开关、仓库标识、默认分支、受控标签初始化标记和访问凭据状态。同步历史或同步任务记录方向、状态、错误码、错误信息、重试次数、下一次重试时间、拉取数量和推送数量。

身份绑定以工作空间标识、外部仓库标识和外部条目编号的组合为匹配键，并设置仅在外部条目编号非空时生效的唯一索引。外部条目尚未创建时不受该索引限制；解绑时清空外部条目编号并保留历史记录，原外部编号不得再自动回写到新任务；重绑或仓库迁移时先按新仓库标识和外部编号执行唯一索引冲突检查，冲突则进入待人工确认或冲突记录。仓库重命名时通过项目配置迁移外部仓库标识，迁移前后均以唯一索引防止同一外部协作条目对应多个任务主记录。

上述三个水位承担不同职责：$last\_pushed\_at$ 在外部创建或更新请求成功并完成本地写回后更新，用于识别本地刚推送的镜像回声；$last\_pulled\_at$ 或由其扩展出的拉取游标在一页或一批外部数据全部处理成功后推进，用于下一次增量查询；$last\_external\_seen\_at$ 记录最近一次从外部协作条目读取到的更新时间，用于判断外部是否存在新变更。失败重试期间不推进拉取游标，也不覆盖最近推送字段哈希，从而避免把未闭合的同步批次误判为已完成。

### 状态和优先级的语义映射机制

本方案通过受控标签将应用内状态和优先级映射为外部协作载体可理解的语义。受控状态标签采用 `mc:` 前缀，受控优先级标签采用 `priority:` 前缀；其他标签均视为非受控标签。同步时先读取外部标签集合，整体剔除受控状态标签集合和受控优先级标签集合，再写入由本地状态和优先级计算出的唯一状态标签和唯一优先级标签，非受控标签原样保留。通过“剔除受控集合后重建”的算法，既能保证状态语义唯一，又能避免仓库侧组件、版本、缺陷类型等非受控标签丢失。

| 应用内语义 | 外部载体表达 | 处理含义 |
| --- | --- | --- |
| inbox | mc:inbox，issue 保持开启 | 任务已进入队列但尚未明确承接 |
| assigned | mc:assigned，issue 保持开启 | 任务已有承接对象但尚未开始执行 |
| in_progress | mc:in-progress，issue 保持开启 | 任务处于开发者或 agent 执行过程中 |
| review | mc:review，issue 保持开启 | 任务进入结果检查或代码审阅阶段 |
| quality_review | mc:quality-review，issue 保持开启 | 任务进入质量门禁或更严格复核阶段 |
| done | mc:done，issue 关闭 | 任务在应用内被确认完成 |

| 应用内优先级 | 受控优先级标签 | 缺失或冲突处理 |
| --- | --- | --- |
| critical | priority:critical | 作为最高紧急程度处理 |
| high | priority:high | 作为高优先级处理 |
| medium | priority:medium | 无受控优先级标签时采用该默认值 |
| low | priority:low | 作为低优先级处理 |
| 未知标签 | 不回写为优先级 | 记录观测信息并保留为非受控标签 |
| 多个受控优先级标签 | 按 critical、high、medium、low 顺序选择一个 | 记录标签冲突并在下一次出站同步时重建唯一标签 |

入站解析外部标签时，若不存在受控状态标签，外部协作条目不直接覆盖本地状态；系统可仅记录观测信息，或在包含应用内任务标识锚点时作为待分类条目保存。若同时存在多个受控状态标签，系统优先进入冲突处理：可以按预设状态顺序选择一个临时解释结果，但不得自动覆盖本地状态，除非该解释结果与外部开启/关闭状态、外部更新时间和本地待推送状态均一致。对于 issue 开启/关闭状态与受控状态标签冲突的情形，以受控状态标签作为流程语义来源，开启/关闭状态作为一致性校验信号；能够自动修正时在下一次出站同步中重建外部标签和开启/关闭状态，不能自动修正时记录冲突。

### 出站与入站持续同步流程

出站同步采用事件驱动的步骤化流程。只有项目同步开关开启、外部仓库标识有效、访问令牌可用、受控标签已初始化或允许延迟初始化、任务未删除或未归档、任务状态可映射时，任务变更事件才进入外部创建或更新流程；否则该事件被标记为待同步、忽略或失败，并写入同步观测记录。

1. 读取任务主记录、项目同步配置和当前外部身份字段，生成包含任务标识、项目标识、变更字段集合、本地版本号、事件时间和操作者来源的同步载荷。
2. 根据本地状态和优先级计算受控标签，根据任务标题、描述、项目上下文和应用内任务标识锚点生成外部标题和正文；应用内任务标识锚点可作为后续补偿扫描和幂等识别依据。
3. 若任务尚未绑定外部条目，则以任务标识或同步批次号作为幂等键创建外部协作条目；若已绑定，则先读取外部标签集合，剔除受控标签后重建唯一受控标签，再提交更新请求。
4. 外部请求成功后，在同一数据库事务中写回外部仓库标识、外部条目编号、外部最近更新时间、$last\_pushed\_at$、最近推送字段哈希和同步来源批次号，并记录 succeeded 状态。
5. 若外部创建成功但本地写回失败，后续补偿扫描通过应用内任务标识锚点、幂等键或外部标题中的任务标记查找已创建条目，回填外部条目编号而不是再次创建，从而避免孤儿条目和重复条目。
6. 若网络超时、限流或临时服务错误导致请求失败，则记录错误码、重试次数和下一次重试时间并进入重试队列；若鉴权失败、权限不足、仓库不存在或状态不可映射，则暂停自动重试并进入 failed 或 dead_letter 状态。

入站同步由周期性轮询或人工触发执行，并采用更新时间加外部条目编号的组合游标。同步引擎为每个项目保存 $last\_seen\_updated\_at$ 与 $last\_seen\_issue\_id$；查询外部协作条目时，处理更新时间大于该水位的条目，以及更新时间等于水位但外部编号更大的条目。只有当前分页或当前批次全部解析、过滤和回写完成后才推进水位；分页中断、平台超时或单批失败时不推进水位，以避免相同更新时间、分页边界或平台时间精度不足造成漏拉。

1. 按项目读取已启用同步且仓库标识有效的配置，并从同步历史读取增量游标、最近错误和重试状态。
2. 从外部协作载体分页获取条目，过滤拉取请求、非指定仓库条目和不满足任务识别条件的条目；任务识别条件包括存在受控状态标签、存在应用内任务标识锚点，或标题/正文满足预设任务标记。
3. 对每个候选外部协作条目，按工作空间标识、外部仓库标识和外部条目编号查找任务主记录；未匹配时执行唯一索引检查后创建本地任务并写入外部身份字段，已匹配时进入字段级回写判断。
4. 字段回写只覆盖白名单字段：标题和描述在外部更新时间明确晚于本地更新时间且本地不存在待推送变更时可回写；状态和优先级必须来自受控标签且无未解决冲突时才回写；负责人仅在外部用户可映射且具备项目权限时回写；非受控标签作为普通标签合并保存。
5. 外部字段为空、格式非法、正文被人工改写导致应用内锚点丢失、负责人无法映射、外部用户无权限或本地同步任务处于 retrying 状态时，不直接覆盖本地标题、描述、状态或优先级，而是写入冲突记录或同步观测记录。
6. 当前页全部处理成功后，按最后处理条目的更新时间和外部编号推进游标，并记录 $last\_pulled\_at$、拉取数量和错误摘要。

外部协作条目的正文由任务描述、项目上下文、应用内任务标识锚点、最近同步批次和可选应用链接组成，使开发者或 agent 仅通过外部协作载体即可理解任务目标和当前状态。锚点不参与用户可见语义判断，但可用于识别条目来源、补偿创建成功但本地写回失败的场景，以及区分本地推送产生的镜像回声与外部用户真实修改。

### 冲突抑制、去重和故障隔离机制

回环抑制不只依赖时间窗口，而是同时使用来源标记、同步批次号、正文锚点、字段哈希和水位比较。出站成功时记录同步批次号和最近推送字段哈希；入站读取到外部协作条目后，若其正文锚点、批次号或字段哈希与最近一次出站记录一致，即使外部更新时间晚于短时间窗口，也可判定为延迟镜像回声并跳过回写。若外部条目在短窗口内发生变化但字段哈希不同，且变更来源不是本地同步账号，则按真实外部修改进入字段级冲突判断，而不是简单跳过。

| 字段或信号 | 冲突判定 | 自动处理规则 |
| --- | --- | --- |
| 标题、描述 | 本地和外部均在上一同步水位后变化 | 采用更新时间较新的值；无法判断先后时记录冲突且不覆盖本地值 |
| 状态 | 外部受控状态标签与本地未同步状态不同 | 应用内状态优先；若本地无待推送变更且外部状态合法，可回写 |
| 优先级 | 多个受控优先级标签或与本地待推送优先级不同 | 按优先级解析表选择临时值并记录冲突；本地待推送时不覆盖 |
| 负责人 | 外部用户无法映射或无项目权限 | 不回写负责人，仅记录观测信息 |
| 非受控标签 | 外部标签与本地普通标签不同 | 以外部非受控标签为主进行合并，受控标签不作为普通标签保存 |
| 开启/关闭状态 | 开启/关闭状态与受控状态标签不一致 | 以受控状态标签解释流程语义，下一次出站同步修正开启/关闭状态；无法修正时记录冲突 |

异步同步任务采用状态机进行故障隔离和恢复。pending 表示任务已入队但尚未执行；running 表示正在调用外部协作载体；succeeded 表示外部请求和本地写回均完成；retrying 表示网络超时、限流或临时服务错误后等待下一次重试；failed 表示鉴权失败、权限不足、仓库不存在、外部条目不存在或数据格式错误等需要配置修复的错误；dead_letter 表示超过最大重试次数、幂等补偿无法匹配或冲突长期未解决。状态机记录错误码、重试次数、下一次重试时间和最后一次载荷，使外部故障通过重试或人工处理恢复，而不回滚本地任务事务。

删除、归档、解绑和重新绑定也遵循主存储优先原则。默认情况下，本地删除或归档任务不物理删除外部协作条目，而是关闭该条目并追加归档类受控标签或写入归档说明；若用户选择仅解绑，则清空本地外部条目编号并保留历史同步记录，解绑后外部条目的后续入站变化不得自动覆盖任何新任务。重新绑定时必须先按工作空间标识、外部仓库标识和外部条目编号检查唯一索引及历史记录，确认没有既有任务占用后才允许绑定。通过上述索引和边界规则，可以直接防止重复导入、误覆盖和解绑后串写。

### 可选扩展和实施边界

外部协作载体可以按平台能力替换。GitHub Issues 是一种实现方式；在其他实现中，外部协作条目可以是其他 Git 托管平台的 issue、项目条目、合并请求，或仓库内结构化任务文件。只要该载体能够保存外部身份、更新时间、状态语义、优先级语义、受控标签或等价字段，并支持增量读取或可比对的变更游标，即可应用本方案的身份绑定、语义映射、同步水位和故障隔离机制。

评论、工时、分支、合并请求状态和质量复核结果属于可选扩展字段，可根据团队协作习惯设置为只出站、只入站、双向同步或不同步。若某一平台无法提供可靠的用户映射、权限校验或更新时间语义，则该字段不进入自动回写白名单，只作为外部协作载体中的参考信息或同步观测信息保存。
