## 技术方案

本方案在 Mission Control 任务看板和主任务存储之外，构建面向开发者与 agent 工作流的 Git-native 协作镜像层。本文中“主任务存储”统一指应用侧保存任务事实、版本和关联键的数据库记录；“协作镜像层”指代码托管平台中的 issue、label、issue state 等可被仓库工具直接读取的对象。任务内容、阶段和优先级分别由 issue 标题/正文、`mc:*` 状态标签、`priority:*` 优先级标签以及 issue open/closed 状态表达，使外部工具无需访问主任务存储即可理解任务队列。主流程先提交本地任务事务，再通过同步作业队列执行外部写入，并以同步审计与重试隔离外部异常。

### 总体架构与主从存储关系

总体架构包括主任务存储、项目同步配置、同步作业队列、同步引擎、协作镜像层和同步审计记录。主任务存储保存任务标题、描述、状态、优先级、所属项目、工作区、指派关系、普通标签、更新时间、任务版本号、最近出站内容哈希以及外部 issue 关联字段；项目同步配置保存仓库地址、同步开关、默认分支、标签初始化状态和访问权限检查结果；同步作业队列保存待执行的出站或入站任务；同步审计记录保存项目级增量游标、同步方向、成功/失败状态、错误码以及本轮推送和拉取数量。

主从关系上，主任务存储是任务事实源，协作镜像层是可选的外部协作出口和外部输入通道。只有项目处于活跃状态、已配置可解析仓库、同步开关开启且访问令牌具备 issue 读写和标签权限时，同步引擎才执行双向同步；未满足前置条件的项目仍按原有任务看板方式运行。外部平台不可用、令牌缺失、仓库权限变化或标签初始化失败时，系统暂停该项目的外部作业并记录原因，不影响主任务存储中的任务创建、更新、展示和删除。

### 核心数据结构与字段归属规则

同步作业队列中的单条作业至少包括 `sync_job_id`、工作区标识、项目标识、任务标识、外部仓库标识、同步方向、触发原因、目标任务版本号、待同步字段快照、内容哈希、重试次数、创建时间、最近执行时间、作业状态和错误码。对同一任务的出站作业，以任务标识、仓库标识和目标任务版本号或字段变更摘要作为幂等键；当同一任务在短时间内连续更新时，队列只保留最新版本的待推送作业，或在执行旧作业前比较目标任务版本号与当前任务版本号，若作业版本落后则直接标记为过期完成，避免旧状态覆盖新状态。

任务记录中的外部关联字段包括外部仓库标识、issue 编号、最近同步时间、最近出站内容哈希、最近出站同步操作标识和本地任务版本号。issue 正文中设置用户可编辑正文区和系统元数据区，系统元数据区写入稳定的本地任务标识、项目标识、工作区标识、同步来源标记和最近出站内容哈希；入站解析时仅从系统元数据区读取关联信息，不把该区域内容作为任务描述的一部分。该元数据区用于在本地关联键丢失或回写失败后进行幂等查找。

字段归属按字段类型确定：标题和描述允许由两端编辑，但更新时按字段级版本或字段最后更新时间选择较新值；状态和优先级由受控标签及 issue state 恢复，但不得被普通标签覆盖；普通标签采用集合合并，并在入站时排除 `mc:`、`priority:` 等受控命名空间，超长、空白、非法字符或重复标签经规范化后保存；指派关系仅在本地账号与外部平台账号存在映射时写入外部 assignee，无法映射时不强行设置 assignee，而是在 issue 正文元数据或评论中保留本地指派信息。

### 受控标签与状态判定规则

受控标签集合在项目同步前初始化。标签不存在时创建；标签已存在但颜色或描述不同，不改变其语义名称，可在具备权限时更新显示属性，在权限不足时降级为只读解析；标签创建失败时，项目同步状态标记为待修复，出站作业暂停重试，入站同步仍可解析已有受控标签但不得把不完整标签集合写回外部仓库。初始化失败不阻断项目在主任务存储中的使用，只阻断需要写入协作镜像层的同步动作。

入站解析时，单个 issue 原则上至多具有一个 `mc:*` 状态标签和一个 `priority:*` 优先级标签。若出现多个状态标签，系统按 `done`、`quality_review`、`review`、`in_progress`、`assigned`、`inbox` 的优先级选择阶段最高的状态，同时在同步审计记录中标记标签冲突；若出现多个优先级标签，按 `critical`、`high`、`medium`、`low` 选择最高优先级并记录冲突。未识别状态标签时，已存在本地任务保持原状态，新建任务使用 `inbox`；未识别优先级标签时，已存在本地任务保持原优先级，新建任务使用 `medium`，并记录可修复异常。

issue state 与受控状态标签不一致时采用固定判定规则：若 issue 为 closed 且不存在更高可信的本地新版本，则入站状态判定为 `done`，并在后续出站中补齐 `mc:done`；若 issue 为 open 但含 `mc:done`，则状态标签表示完成意图，入站状态判定为 `done`，后续出站关闭 issue；若 issue 为 closed 但含非完成状态标签且本地存在更新版本，则保留本地状态并在后续出站重新打开或重标记 issue。该规则使完成状态在外部工具中同时具备标签语义和开闭状态语义。

### 任务到 Git-native 镜像的出站同步

当用户或 agent 在 Mission Control 中创建或更新任务时，系统先在本地事务内完成项目票号分配、任务写入、任务版本号递增、活动记录和订阅通知；事务提交后，再写入或合并一条出站同步作业。出站作业的执行前置条件包括项目已启用同步、仓库地址有效、访问令牌具备 issue/label 权限、受控标签已初始化或允许懒创建、本地任务未处于删除或归档状态，并且作业目标版本不落后于任务当前版本。外部平台写入不参与本地事务提交，因此外部失败不会造成任务创建失败或任务编号回滚。

出站同步根据任务是否已有外部关联采用创建或更新路径。若任务尚无 issue 编号，同步引擎先根据 issue 正文系统元数据区中的本地任务标识和项目标识搜索既有 issue；若找到匹配 issue，则回写其编号和仓库标识而不再创建；若未找到，才创建新 issue，并在成功后回写 issue 编号、仓库标识、最近同步时间、出站同步操作标识和内容哈希。该幂等创建规则覆盖“外部 issue 已创建但本地关联键回写失败”的中断场景，后续重试可以重新定位既有 issue，避免重复创建。

若任务已有外部 issue 编号，同步引擎读取该 issue 的当前标签并按集合公式计算新标签集合：新标签集合 = 外部现有非受控标签集合 ∪ 本次计算出的单一 `mc:*` 状态标签 ∪ 本次计算出的单一 `priority:*` 优先级标签。同步引擎只删除并替换 `mc:*` 和 `priority:*` 受控标签，不删除缺陷类型、组件、版本等外部普通标签；随后更新 issue 标题、用户正文区、系统元数据区、开闭状态和受控标签。若执行时发现作业版本落后于当前任务版本，或内容哈希与当前任务快照不一致，则放弃该作业并由最新作业重新推送。

出站作业失败后进入待重试状态，重试次数和错误码写入同步作业及同步审计记录。网络超时、速率限制和临时服务错误按指数退避重试；鉴权失败、仓库不存在、权限不足或标签初始化失败使该项目的出站作业暂停，待配置恢复后继续；超过最大重试阈值的作业标记为需要人工干预，但不删除主任务存储中的任务。由此，外部平台异常被限制在同步作业层，不影响本地任务接口在本地事务成功后的返回结果。

### Git-native 镜像到主存储的入站同步

入站同步用于将协作镜像层中由开发者或 agent 修改的 issue 变化带回主任务存储。入站前置条件包括项目处于活跃状态、同步配置未被禁用、仓库标识可解析、访问令牌可读取 issues、上次同步游标可用或可初始化、外部 API 结果可分页读取，并且返回 issue 能够根据仓库、工作区和项目配置落到唯一项目。后台轮询器按预设间隔执行入站同步，用户也可以通过同步接口触发单项目或全部项目同步。

每次入站同步以项目级增量游标作为查询边界，并按外部 API 分页读取更新后的 issues。同步开始时记录本轮起始游标和页面位置；单条 issue 成功处理后记录该 issue 的更新时间和处理结果；若整轮成功，则将项目游标推进到本轮已成功处理的最大安全水位线。若某些 issue 处理失败，则项目全局游标不得简单推进到当前时间，而是推进到失败项之前的连续成功水位线，或保留原游标并记录失败 issue 编号，以便后续重试重新拉取失败项，避免漏同步。

对每个返回的 issue，同步引擎先以工作区、仓库标识和 issue 编号匹配已有任务；未匹配时，再解析 issue 正文系统元数据区中的本地任务标识进行二次定位；仍未匹配且该 issue 未带有归档或删除标记时，创建新任务。新任务继承当前项目和工作区，按项目票号规则生成任务票号，标题和描述来自 issue 标题和用户正文区，状态和优先级按受控标签与 issue state 判定，普通标签由外部非受控标签规范化得到，默认创建者为同步主体；创建后生成活动记录和必要通知，并写入外部关联键。

已匹配任务的入站更新采用字段级合并而非整条覆盖。本地与外部同时修改同一字段时，标题和描述按字段最后更新时间或任务版本选择较新值；状态和优先级在外部受控标签有效且外部更新时间新于本地对应字段版本时采用外部值，否则保持本地值；普通标签采用本地集合与外部非受控标签集合的并集；指派关系仅在外部账号可映射到本地成员时更新，否则保留本地指派并记录映射异常。本地与外部修改不同字段时，系统仅更新发生外部变化的字段，避免外部只改标签却覆盖本地刚修改的描述。

外部边界场景按可恢复和不可恢复分类处理。分页读取过程中遇到速率限制、网络超时或服务端临时错误时，保存当前页面游标并按退避策略重试；鉴权失败、仓库不存在或仓库转移导致标识不可解析时，暂停该项目入站同步并记录配置错误；issue 被关闭、重开或标签变更时，按状态判定规则更新本地状态；未通过关联键或元数据验证的 issue 不得更新已有任务，只能在满足项目归属条件时作为候选新任务处理。

### 状态语义与标签映射

为避免看板状态与仓库标签语义不一致，本方案设置受控标签命名空间。任务状态使用 `mc:` 前缀标签表示，任务优先级使用 `priority:` 前缀标签表示；仓库中不属于上述命名空间的标签不参与状态和优先级判定。出站更新时，系统保留外部非受控标签并替换受控标签；入站更新时，系统把外部非受控标签规范化为普通任务标签。通过前缀隔离，协作镜像层能够保持仓库既有缺陷类型、组件名称、版本里程碑等标签，同时向自动化工具暴露稳定的机器可读状态。

| 应用语义 | Git-native 表达 | 确定处理规则 |
| --- | --- | --- |
| `inbox` | `mc:inbox` | 任务已进入队列但尚未分派；无有效状态标签的新建入站任务默认使用该状态。 |
| `assigned` | `mc:assigned` | 任务已有执行主体；外部账号无法映射时保留本地指派。 |
| `in_progress` | `mc:in-progress` | 任务正在执行。 |
| `review` | `mc:review` | 任务进入评审阶段。 |
| `quality_review` | `mc:quality-review` | 任务进入质量复核阶段。 |
| `done` | `mc:done` 且 issue 为 closed | 任务完成；issue state 与 `mc:done` 不一致时按完成状态一致化处理。 |
| 低、中、高、紧急优先级 | `priority:low`、`priority:medium`、`priority:high`、`priority:critical` | 新建入站任务无有效优先级时默认 `medium`；已有任务遇到无法识别优先级时保持原优先级并记录异常。 |

受控标签的解析和写回均采用确定规则：出站时由主任务存储状态计算唯一状态标签，由优先级计算唯一优先级标签；入站时若多个受控标签并存，则按照既定优先级选择一个有效值并记录冲突，不让多个标签同时写入主任务存储。普通标签进入本地任务标签前，需要过滤受控前缀、限制长度和数量、去除空白与非法字符，并按大小写或规范化名称合并重名标签。

### 删除与归档同步规则

删除和归档场景采用确定的默认路径。主任务存储中的删除或归档操作先完成本地状态变更，并记录该任务对应的外部仓库和 issue 编号；若任务存在外部关联，则生成删除/归档出站作业，将外部 issue 关闭并添加 `mc:archived` 或等价归档标记，同时在系统元数据区写入本地删除/归档版本。外部关闭或归档失败不阻断本地删除或归档完成，失败作业按同步作业重试规则处理。

入站同步再次看到已归档或已删除标记的 issue 时，不自动重建本地任务。只有当 issue 同时携带明确恢复标记，且恢复操作版本晚于本地删除/归档版本，并通过工作区、项目和本地任务标识校验时，系统才将其作为恢复候选；否则该 issue 仅作为历史协作对象保留。该规则防止已删除任务因外部历史 issue 被增量拉取而反复复活。

### 幂等、冲突与故障隔离

回声识别不单独依赖时间窗口，而采用同步来源标记、最近出站内容哈希、同步操作标识、外部 issue 更新时间和本地任务版本号的组合判据。若入站 issue 的系统元数据区包含最近一次出站同步操作标识，且其可编辑字段哈希与本地最近出站内容哈希一致，并且外部更新时间处于该出站操作后的短时间窗口内，则判定为本地推送回声，不回写主任务存储；若哈希不同或外部 actor、字段版本显示存在真实外部编辑，则按字段级合并规则处理。

去重机制以工作区、仓库标识和 issue 编号构成唯一关联键，并辅以 issue 正文系统元数据区中的本地任务标识。入站同步必须先按唯一关联键查找已有任务，再按元数据区任务标识二次查找，最后才创建新任务。若并发入站创建同一 issue 时触发唯一索引冲突，当前事务回滚创建动作，重新读取已存在任务并转为更新流程；未通过关联键或元数据验证的 issue 不得覆盖已有任务。

故障隔离方面，同步审计记录区分项目级水位线和单次作业结果：同步开始时记录本轮起始游标和运行状态；单条成功时记录 issue 编号、处理方向和成功时间；单条失败时记录错误码但继续处理其他 issue；整轮结束时根据连续成功水位线推进项目游标，并汇总成功、失败和重试数量。出站作业和入站拉取均在项目维度、单条 issue 维度捕获异常，一个项目或一个 issue 的失败不阻断其他项目或其他 issue 的同步。

同步终止规则用于防止错误扩散：旧版本作业不得覆盖新版本任务；外部普通标签不得覆盖受控标签；删除或归档任务不得被普通入站同步自动复活；项目配置失效时暂停该项目同步但保留待处理作业；达到重试阈值后将作业标记为人工干预。上述规则把网络、权限、速率限制、数据冲突和并发写入问题限制在同步层，使主任务存储维持连续可用。
