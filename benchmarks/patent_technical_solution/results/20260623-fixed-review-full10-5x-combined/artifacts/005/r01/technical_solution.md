## 技术方案

### 总体构思与双层任务表示

本方案将智能工作台中的任务主记录与外部协作对象划分为双层表示。主存储是应用数据库和任务看板，负责任务创建、状态推进、质量门禁、通知、权限和完整审计；外部协作对象是代码仓库或等价 Git 托管载体中可被开发者和 agent 直接消费的任务镜像，例如 issue、带命名空间标签的工单，或结构化 Markdown/YAML 条目。外部工具只读取外部协作对象即可理解任务队列和任务状态，不需要直接访问应用数据库。

同步引擎位于主存储与外部协作对象之间，执行出站投影、入站回写、冲突判断、回环抑制和失败记录。同步记录表保存项目或仓库维度的同步水位、处理结果、错误状态和重试信息；平台适配器屏蔽 GitHub、GitLab、Gitea/Forgejo 或仓库文件等载体差异，向同步引擎提供统一的读取、创建、更新、列举变更和标签映射能力。数据流为：主存储产生任务变化，同步引擎形成镜像负载并经适配器写入外部协作对象；外部协作对象发生变化时，同步引擎按水位增量读取、解析语义并在满足回写条件时更新主存储。

### 任务数据模型与镜像身份绑定

在数据模型上，每个工作台任务至少包括任务标识、工作区标识、项目标识、标题、说明、状态、优先级、负责人、创建者、创建时间、本地更新时间、截止时间、工时估计、普通标签和扩展元数据。项目记录保存仓库标识、默认分支、是否启用同步、标签命名空间是否已初始化以及同步目标是否有效。同步引擎仅在项目同步开关开启、仓库标识有效、访问凭据可用、任务未删除或未归档且任务状态属于可投影状态集合时，才为该任务维护外部协作对象。

任务主记录与外部协作对象通过稳定关联字段绑定。在一种实现中，任务记录保存外部仓库标识、外部对象编号和最后镜像同步时间；数据库以工作区标识、外部仓库标识和外部对象编号建立联合唯一约束，防止同一 issue 或等价对象被多个任务重复绑定。出站创建外部对象成功后，系统在同一持久化步骤中回写外部编号、仓库标识和同步时间；若回写失败，则保留创建结果，记录“待绑定修复”状态，并在下一次重试时优先按新建对象编号补写绑定字段，而不是再次创建外部对象。

时间和水位字段分层保存：任务本地更新时间属于任务主记录，用于表示应用侧最后一次实质修改；外部对象更新时间来自 Git 托管平台或仓库文件提交时间，用于判断外部侧是否有新变化；最后镜像同步时间属于任务绑定字段，用于标记最近一次由同步引擎写入或确认的镜像时间，并参与回环抑制；项目同步水位属于同步记录表，可采用外部 `updated_at`、事件游标、提交时间或平台返回的分页游标，用于下一批增量拉取的起点。身份绑定字段解决对象对应关系，项目同步水位解决扫描进度，两者分离后，出站创建后回写、入站先匹配后创建以及联合唯一约束共同降低重复创建和漏同步风险。

### 出站同步与语义投影

出站同步按步骤执行：先把任务创建或更新事件写入异步同步队列，并以任务标识、项目标识和目标仓库标识去重，只保留同一任务的最新待同步负载；再检查项目同步开关、仓库标识、访问令牌、标签命名空间初始化状态和任务可投影状态；然后根据任务自身仓库字段或所属项目仓库字段确定目标仓库。若任务已有外部编号，则读取并更新对应外部协作对象；若任务没有外部编号且项目允许创建镜像，则创建新的外部协作对象；成功后回写外部编号、仓库标识、最后镜像同步时间和同步结果，失败则写入错误类型、重试次数和下一次重试时间。

| 内部字段 | 出站投影规则 | 入站回写规则 |
| --- | --- | --- |
| 标题 | 写入外部对象标题 | 外部标题较新且本地标题未在同一周期变更时回写 |
| 说明 | 写入系统维护的正文块或 issue 正文中的指定区域 | 只读取系统维护块或约定正文区域，不覆盖本地较新的说明 |
| 状态 | 映射为 `mc:` 命名空间标签，并可联动外部开闭状态 | 按冲突规则解析为内部状态，受质量门禁限制 |
| 优先级 | 映射为 `priority:` 命名空间标签 | 解析优先级标签后字段级回写 |
| 负责人 | 在平台支持时映射为 assignee；不支持时写入结构化正文块 | 无权限或无映射账号时不回写负责人 |
| 截止时间 | 在平台支持时映射为 due date 或 milestone；不支持时写入结构化正文块 | 仅在外部提供明确日期且较新时回写 |
| 工时估计 | 写入结构化正文块或保留在主存储 | 外部不支持时不回写 |
| 普通标签 | 保留为非系统标签集合或结构化块 | 与内部普通标签按来源合并，不以异常默认值清空 |
| 扩展元数据 | 默认保留在主存储，必要时写入结构化块 | 仅回写有明确定义的键值 |

语义投影层将工作台内部多阶段任务状态转换为仓库协作对象可识别的标签和开闭状态。示例映射包括：待收件映射为 `mc:inbox`，已分派映射为 `mc:assigned`，进行中映射为 `mc:in-progress`，评审中映射为 `mc:review`，质量评审映射为 `mc:quality-review`，已完成映射为 `mc:done`；优先级映射为 `priority:critical`、`priority:high`、`priority:medium` 或 `priority:low`。出站更新时先读取外部对象现有标签，移除全部 `mc:` 状态标签和 `priority:` 优先级标签，再加入当前任务状态和优先级对应的唯一标签；若外部对象原先存在多个旧状态标签，该清理步骤会把多标签冲突收敛为一个内部状态。

出站同步只维护本方案声明的命名空间和系统维护正文块，不覆盖开发者在外部对象中的非系统标签、评论、里程碑、非系统正文区域或平台侧协作字段。任务完成时可关闭外部 issue，其他内部状态保持打开；若外部 issue 已关闭但内部任务未完成，出站同步按照内部状态重新打开 issue 或记录需要人工确认的冲突，避免外部关闭绕过应用侧质量门禁。通过“移除本命名空间旧标签—加入当前唯一标签—保留非命名空间标签”的算法，外部仓库既有分类体系不会被同步过程污染。

### 入站同步与回环抑制

入站同步按项目执行：读取项目同步水位和失败重放队列，调用平台适配器按水位列举发生变化的外部协作对象，过滤 pull request、被系统标记忽略的对象以及仓库配置不匹配的对象；随后按工作区、仓库标识和外部编号进行身份匹配，匹配成功则进入字段级回写判断，匹配失败则在外部对象包含可识别任务语义时创建新的工作台任务。入站回写的前置条件包括仓库配置有效、水位可读取、外部对象可访问、对象格式满足最小解析要求，并且对象未处于需要人工介入的错误状态。

入站解析采用字段级合并而非整对象覆盖。外部只修改标签时，仅重新计算状态、优先级和普通标签，不覆盖内部标题和说明；本地修改说明而外部修改状态时，可以仅回写状态字段并保留本地说明；外部删除本系统状态标签时，不直接把内部状态回退为默认值，而是保留原内部状态并记录“缺失状态标签”提示，等待下一次出站同步修复；非系统标签作为普通标签与内部普通标签按来源合并，保留内部手工标签和外部协作标签，只有明确由外部删除且属于外部来源的标签才从外部标签集合中移除。对象格式异常时不得用默认值覆盖已有内部字段。

冲突裁决按字段来源和业务约束执行。本地任务和外部对象在同一同步周期内均发生变化时，标题、说明等内容字段采用字段级较新者优先，但不覆盖对方未变更字段；状态字段受内部状态机和质量门禁约束，外部关闭状态与 `mc:` 状态标签不一致时，先以 `mc:` 标签解析任务阶段，再把关闭状态作为完成意图处理。若内部质量门禁不允许完成而外部 issue 已关闭，则保持内部状态不变，记录冲突事件，并在下一次出站同步中重新打开或更新外部对象。

当外部对象同时存在多个 `mc:` 状态标签时，入站同步不随机选择状态，而是按预设状态序列进行确定性解析，并记录多标签冲突；在一种实现中，完成态和质量评审态优先于评审态，评审态优先于进行中，进行中优先于已分派，已分派优先于收件状态。多个 `priority:` 标签并存时按最高优先级解析，并记录需要出站清理的标签冲突。外部无可识别状态标签时，新建任务进入收件状态；已绑定任务则保持原内部状态，以避免因标签丢失导致任务阶段倒退。

回环抑制以最后镜像同步时间为中心设置短时间窗口，窗口阈值可由系统配置给出，例如数秒到数十秒，并按毫秒级时间戳比较。同步器对外部平台时间与本地服务时间保留容差，外部更新时间落在最后镜像同步时间前后容差范围内且变更内容与最近出站负载一致时，判定为出站同步回声并跳过回写；若外部平台异步更新时间滞后，则下一轮同步仍会再次读取该对象。只有当外部对象内容或标签相对最近出站负载出现真实差异时，才突破时间窗口进入字段级回写，从而降低误跳过开发者修改的概率。

同步水位采用“批次水位 + 失败对象重放队列”的推进规则。每批拉取按外部更新时间和外部编号稳定排序，处理成功的对象记录其对象水位；若整批成功，则项目水位推进到批次最大水位。若批次中部分对象失败，项目水位可以推进到已完整扫描的批次末尾，但失败对象的仓库标识、外部编号、外部更新时间、错误类型和原始游标被写入重放队列，下一轮在读取新变化前优先重放失败对象。同一更新时间下多个对象以外部编号作为次序键，水位保存时间戳加次序键或平台游标，分页中断时不推进到未确认页之后，以避免同时间戳对象或中断页对象遗漏。

### 故障隔离与可扩展同步目标

同步机制被设计为主任务系统之外的可恢复外设。任务创建、任务更新、活动记录、通知和实时广播先在应用内部完成，外部镜像更新通过异步队列触发；队列任务保存待同步任务标识、目标仓库、最近负载摘要、重试次数、下一次执行时间和错误状态。若重试期间本地任务再次更新，队列不发送旧负载，而是在执行前重新读取主存储并生成最新负载，因此后续更新会覆盖过期待发送内容，避免把旧状态写回外部对象。

失败恢复按错误类型分级处理。网络超时、API 限流和临时服务错误进入可重试状态，按固定间隔或指数退避重试，并在达到最大重试次数后转为需人工介入；认证失败、权限不足、仓库不存在、仓库迁移未确认或标签命名空间初始化失败会暂停对应项目同步并保留现有水位，待凭据或仓库配置修复后人工重放；外部对象删除、转移或无法读取时，不清空任务中的外部编号、内部状态、标签或同步水位，而是标记绑定失效或迁移待确认；单个对象格式异常只进入失败重放队列，不阻断同项目其他对象。

平台适配器提供统一接口，使 GitHub issue、GitLab issue、Gitea/Forgejo issue 以及仓库内 Markdown/YAML 清单遵循相同同步规则。该接口至少包括：`listChangedObjects` 用于按水位列举变化对象，`readMirrorObject` 用于按外部编号读取对象，`createMirrorObject` 用于创建镜像，`updateMirrorObject` 用于局部更新标题、系统标签和系统维护正文块，`mapLabels` 用于状态和优先级语义转换，`getObjectWatermark` 用于取得外部更新时间、事件游标或提交位置。不同平台只改变外部身份、更新时间、水位和字段承载方式，不改变主存储优先、身份绑定字段与水位分离、命名空间标签替换、字段级回写、回环抑制和逐对象故障隔离这些核心规则。
