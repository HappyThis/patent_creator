## 技术方案

### 技术问题与同步边界

本方案解决的核心矛盾是：工作台内部任务流转需要事务一致性、权限校验、质量门禁和通知机制，而 Git 侧开发工具、命令行 agent 或自动化脚本通常只理解 issue、标签、评论、分支、PR 或带结构化元数据的任务文件。为兼顾内部可靠性与外部可读性，本方案不将 Git 仓库作为任务主数据库，而是在任务主存储之外建立 Git-native 协作镜像层；应用数据库继续承担任务创建、看板流转、权限校验、质量审查和活动记录，Git 仓库或等价 Git 托管载体仅承载可被外部开发流程读取和有限回写的任务副本。

该镜像层采用“主存储提交、镜像异步收敛”的边界。任务的新增、修改、状态迁移、指派、审查结果和评论先在应用侧完成事务性写入；同一事务或紧随其后的可靠步骤产生同步作业，作业记录任务标识、变更字段集合、事件版本、幂等键、目标仓库、预期外部修订号和重试计数。同步 worker 取得项目级或任务级锁后执行作业，成功时回写外部对象编号、同步版本、同步时间、受管字段哈希和同步状态；失败时仅改变同步状态和错误记录，不回滚本地任务事务，从而避免 Git 平台不可用、鉴权失败或网络抖动影响工作台内部任务流转。

### 数据模型与版本记录

每个可同步项目维护仓库标识、默认分支、同步开关、项目 ticket 前缀和当前同步检查点。任务记录保留应用侧稳定标识、项目内 ticket、外部镜像类型、外部对象编号、文件键、最近同步版本、最近同步时间、原始外部状态、外部修订号和受管字段哈希。仓库标识用于区分不同 Git 托管位置；外部对象编号在 issue 形态下可以是 issue number，在文件形态下可以是路径、文件 sha 或 front matter 唯一键；同步检查点用于增量拉取，与同步历史审计记录分开保存，避免展示用历史被误用为游标。

映射记录以工作区、仓库标识和外部对象编号或文件键形成唯一约束，并在导入前先查找正式列和历史 metadata 中的旧映射，防止同一外部任务被重复创建。镜像内容是面向开发者和 agent 可理解的任务语义视图，至少包含标题、描述、状态、优先级、项目 ticket、负责人或候选 agent、标签、更新时间和来源信息；可选包含验收说明、质量审查状态、关联分支、PR、失败原因、重试次数和评论摘要。对于不提供稳定键、更新时间或修订条件的外部载体，本方案可以降级为只读导入、全量轮询或暂停双向同步。

| 同步状态 | 进入条件 | 允许动作 | 退出条件 |
| --- | --- | --- | --- |
| 未绑定 | 本地任务尚无外部对象编号或文件键 | 创建外部镜像、暂停同步 | 创建成功后进入已同步，失败进入失败待重试 |
| 待创建 | 本地事务已提交且需新建镜像 | 出站 worker 加锁创建 | 创建成功回写映射，条件不满足则暂停或失败 |
| 待更新 | 本地受管字段发生变化 | 计算 diff 并条件更新外部对象 | 更新成功进入已同步，条件失败进入冲突待处理 |
| 同步中 | 作业已被 worker 锁定 | 续租锁、提交更新、记录结果 | 成功、失败或超时释放锁 |
| 已同步 | 两侧受管字段哈希和版本一致 | 等待新事件或入站变化 | 检测到变化后进入待更新或冲突待处理 |
| 失败待重试 | 鉴权、限流、网络或解析异常 | 按类型退避重试或人工修复 | 重试成功进入已同步，超过阈值进入暂停同步 |
| 冲突待处理 | 同一受管字段两侧变化且值不一致 | 保留两侧值并提示人工选择 | 人工确认后生成回写作业或本地更新 |
| 暂停同步 | 项目解绑、鉴权失效或达到最大失败次数 | 禁止自动写入，允许人工恢复 | 配置恢复后重新校验映射并进入待更新 |
| 外部对象丢失 | issue 删除、文件移动或唯一键失效 | 重新发现、重建镜像或解除绑定 | 恢复映射后进入已同步，无法恢复则暂停同步 |

### 出站同步与入站同步流程

出站同步用于把应用侧已提交的任务变化投射到 Git-native 镜像，优先通过同步作业表或等价 outbox 机制承接本地事务后的变更。其处理步骤包括：1）读取本地任务、项目 Git 配置和既有映射记录；2）根据外部对象编号或文件键判断是创建还是更新镜像；3）读取外部对象的最新修订号、ETag、文件 sha 或更新时间；4）依据变更字段集合和受管字段哈希计算差异；5）渲染 issue 标题、正文、标签、状态或任务文件 front matter 与受管正文区块；6）携带预期外部修订条件提交创建或更新；7）成功后持久化映射、同步版本、同步时间、外部修订号和同步历史；8）失败后写入任务级同步状态并按错误类型决定重试或转人工。

入站同步用于把 Git 侧可接受的外部变化规范化为应用侧任务变化。其处理步骤包括：1）读取项目同步检查点和启用状态；2）按分页拉取检查点之后变化的 issue、评论或任务文件；3）根据仓库、路径、标签、目录、front matter 或项目白名单过滤导入范围；4）用仓库标识加外部对象编号或文件键匹配映射，必要时查重历史 metadata；5）把外部字段规范化为内部状态、优先级、标题、描述和普通标签；6）通过来源标记、受管字段哈希、外部修订号、同步版本和必要的时间窗口识别本地推送回声；7）应用冲突规则和质量门禁规则；8）在本地事务中创建或更新任务、映射和活动记录；9）当本地规则要求修正 Git 侧表达时生成回写作业。

事件触发、周期轮询和手动同步可以并存，但同一工作区、项目和外部对象在同一时刻只允许一个同步执行者持有锁。幂等键由任务标识、事件版本、方向和目标仓库生成，重复触发时合并为同一待处理作业或跳过已完成版本。周期轮询器定时扫描启用 Git 同步的活动项目，手动触发可同步单项目或全部项目；当分页拉取中断、项目级拉取失败或对象级处理失败时，仅在已完整处理的页或对象范围内推进检查点，未确认处理成功的外部变化保留在下一轮重新扫描范围内。

### 语义映射、受管字段与冲突判定

状态和优先级通过版本化映射表在应用模型与 Git-native 表达之间转换。应用侧看板状态映射为带命名空间前缀的互斥状态标签，优先级映射为独立优先级标签；Git 侧 issue 关闭态、文件归档目录或 front matter 状态可反向映射为完成、终止或待确认类状态。若出现多个互斥状态标签，按最近受管字段版本或预设优先级选择候选值并标记异常；缺少状态标签时使用外部对象状态或默认入口状态；未知优先级标签保留为普通标签并采用默认优先级；issue 关闭态与状态标签不一致、文件被移动或 front matter 关键键缺失时，进入冲突待处理或外部对象丢失状态。

受管字段与非受管字段按可验证边界区分。状态标签和优先级标签必须使用固定命名空间；Markdown 正文通过起止标记划分受管区块；任务文件 front matter 仅指定 key 可被覆盖；评论默认追加同步摘要或状态说明，不重写历史评论；未带命名空间的标签、受管区块外正文、开发者评论和外部工具附加元数据均作为非受管内容保留。回声识别不只依赖短时间窗口，而是综合来源标记、受管字段哈希、外部修订号和同步版本；时间窗口仅作为辅助，窗口长度和时钟容差可按部署环境配置，超过窗口但哈希和版本仍可匹配时仍判定为回声。

并发更新通过条件提交保护。出站更新 issue 时携带 ETag、更新时间或平台支持的条件头，更新任务文件时携带文件 sha 或提交基线；条件失败表示外部对象已被他方修改，同步引擎重新读取外部修订并按受管字段 diff 合并。若两侧仅修改不同受管字段，可以在同一映射版本下合并；若同一受管字段值不同，或者外部修订无法可靠比较，则不静默覆盖，改为冲突待处理并保留本地值、外部值、来源和修订号。

| 场景 | 判定依据 | 处理动作 |
| --- | --- | --- |
| 仅本地变化 | 本地事件版本大于最近同步版本，外部修订未变化 | 生成出站更新并回写同步版本 |
| 仅外部变化 | 外部修订号或更新时间晚于检查点，本地受管字段哈希未变化 | 按入站规则更新本地任务 |
| 两侧变化但字段不同 | 本地和外部均变化，但受管字段集合不相交 | 合并字段并记录一次双向同步历史 |
| 同一受管字段值不同 | 状态、优先级、标题或受管正文区块两侧值不同 | 进入冲突待处理，保留两侧原始值 |
| 外部只修改非受管字段 | 仅普通标签、受管区外正文或评论变化 | 保留外部内容，不触发本地覆盖 |
| 本地质量审查中而外部关闭 | 外部完成意图与本地门禁状态不一致 | 记录完成意图，保持或进入评审状态并等待审查 |
| 外部重新打开而本地已完成 | 外部状态与已完成任务不一致 | 创建重开意图或待确认活动，不直接撤销完成态 |
| 本地删除或归档而外部仍存在 | 本地任务处于删除、归档或解绑状态 | 关闭、标记归档、解除绑定或暂停同步，按项目策略执行 |

### 质量门禁状态闭环

对于应用侧存在质量门禁的状态迁移，入站同步不允许外部关闭 issue 或修改任务文件直接绕过内部审查。外部对象显示为完成时，同步引擎先写入外部完成意图、来源对象、外部修订号和受管字段快照，并将任务保持在评审、质量审查或待确认状态；内部审查通过后，再由出站作业把完成态、状态标签、关闭态或归档文件写回 Git 侧镜像。

若内部审查拒绝外部完成意图，系统生成修正 Git 侧状态的回写作业，将外部对象恢复为未完成状态、替换受管状态标签或恢复任务文件受管字段，并可追加一条说明评论或同步摘要。为避免开发者或机器人反复关闭造成循环同步，回写作业携带门禁判定版本和来源标记；后续入站若识别到相同完成意图的回声，则只更新同步历史，不再次推动状态迁移。

### 故障隔离、恢复与可观测性

同步故障通过作业级、项目级和对象级三层隔离处理。出站同步采用异步执行方式，任务主事务提交后即返回应用结果；外部创建或更新失败时记录错误类型、任务标识、项目、仓库、外部对象、外部修订号和重试次数，不影响后续本地任务操作。入站同步在项目鉴权失败、仓库不可访问或分页拉取失败时终止该项目本轮同步但不阻塞其他项目；在单个 issue 或任务文件解析失败时仅标记该对象失败并继续处理同项目中的其他对象。

同步历史记录与增量检查点分开维护。同步历史保存仓库、项目、方向、处理数量、拉取数量、推送数量、状态、错误信息和创建时间，用于界面展示、健康诊断和人工追溯；增量检查点保存已确认处理完成的外部时间戳、页游标、事件编号或提交 sha，用于下一轮拉取起点。项目级失败或分页中断时不推进未完成范围的检查点；对象级失败可以推进已成功对象之前的安全检查点，同时记录失败对象键，下一轮优先补偿扫描该对象，避免漏同步。

| 失败类型 | 隔离粒度 | 恢复策略 |
| --- | --- | --- |
| 鉴权失败 | 项目级 | 暂停该项目自动同步，提示重新授权或更换令牌 |
| 限流 | 项目级或作业级 | 按平台重置时间退避，保留作业并降低轮询频率 |
| 网络超时 | 作业级 | 指数退避重试，超过阈值转人工处理 |
| 外部 404 | 对象级 | 重新发现对象、检测仓库改名或文件移动，无法恢复时标记外部对象丢失 |
| 格式解析失败 | 对象级 | 保留原始外部内容，跳过本次入站更新并提示修正格式 |
| 条件更新失败 | 对象级 | 重新读取外部修订并合并，不能合并时进入冲突待处理 |
| 项目解绑仓库 | 项目级 | 停止新作业，保留历史映射并按策略解除绑定或暂停同步 |
| 默认分支变化 | 项目级 | 重新读取分支基线和文件键，校验后继续同步 |
| 达到最大重试次数 | 作业级 | 冻结作业状态，保留错误上下文并等待人工恢复 |

对于删除、重命名、解绑和迁移类边界，系统以映射记录为准进行恢复判断。外部 issue 删除、文件移动或 front matter 唯一键变更时，先尝试通过历史对象编号、文件 sha、项目 ticket 或受管字段哈希重新发现同一任务；仓库改名或默认分支变化时，先更新项目级仓库标识或分支基线，再校验映射是否仍可解析；项目主动解绑仓库时，停止出站作业和入站轮询，保留本地任务和历史同步记录，必要时将未完成作业置为暂停同步。
