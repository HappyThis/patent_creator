## 技术方案

### 核心构思与总体架构

本方案首先针对主 agent 调用子 agent 作为工具时容易出现的状态割裂问题设置统一处理规则：浏览器断线后子任务流片段不能丢失；父侧重启、网络重试或多标签页恢复不能重复触发同一模型调用；并行子任务在主会话中的展示不能因网络到达顺序而乱序；父侧登记状态、子侧聊天状态和客户端事件终态不能相互覆盖；$runId$ 被猜测或复用时不能绕过主会话身份、租户和归属校验。上述问题均通过持久化登记、子侧映射、单运行序号、幂等冲突检查、终态不可覆盖和路由前访问控制共同解决。

本方案在现有主 agent、子 agent 路由、可恢复流式输出能力之上，引入“保留式流式子 agent 工具编排”机制。用户侧仍只建立并感知一个主会话连接；主 agent 在一次用户请求或一次内部工作流中，可以把研究、规划、比较、总结等相对独立的任务派发给一个或多个专门子 agent，并将各子 agent 的执行过程、阶段性输出和最终结果以事件形式带回同一主会话视图。

子 agent 工具运行不是在主 agent 内部临时拼接的一段文本生成逻辑，而是由真实可聊天的子 agent 承担的一次持久化执行。主 agent 通过既有的子 agent 路由语义创建或取得以运行标识命名的子 agent 实例；该子 agent 具有独立会话、模型配置、工具集合、内存状态和 SQLite 存储，其自身的可恢复流式输出记录作为子任务执行过程的权威来源。主 agent 只负责登记、调度、观察和转发，不把子 agent 的完整流状态复制为主 agent 的第二套流。

该机制将“执行”和“观察”分离：子 agent 工具运行一旦启动，就成为由 $runId$ 标识的 durable work；主会话中的流式展示只是该 durable work 的一个观察者。浏览器短暂断开、页面刷新或原观察流丢失，不应自动取消子 agent 的执行；只有明确的取消信号才改变执行状态。由此，长任务、并行任务以及执行完成后的回看均可基于同一运行标识重新定位。

| 组成要素 | 主要职责 | 关键持久化或边界 |
| --- | --- | --- |
| 主 agent | 接收用户请求、登记子 agent 工具运行、派发子任务并把事件转发到主会话视图 | 维护父侧登记表、身份与租户边界、父工具调用分组和展示顺序 |
| 父侧登记表 | 记录每个 $runId$ 的来源、状态、展示位置、最后事件序号和清理状态 | 作为重放、取消、冲突检查和访问门禁的父侧依据 |
| 子侧适配器 | 把一次 $runId$ 映射为子 agent 的程序化聊天回合，并提供启动、检查、取消和读取片段接口 | 隔离聊天内部请求标识与公开编排标识 |
| 子 agent 及其流存储 | 执行具体研究、规划或比较任务，并持久化自身聊天片段和终态 | 作为子任务内容与可恢复流片段的权威来源 |
| 客户端事件视图 | 按事件序号、重放标记和分组键重建子 agent 面板 | 不直接驱动执行，只作为一个或多个观察者呈现同一运行 |

### 运行登记、幂等调度与子侧映射

主 agent 在启动子 agent 工具运行前，先在父侧持久化运行登记表中插入一条记录。该记录至少关联 $runId$、子 agent 类型、父工具调用标识 $parentToolCallId$、展示顺序、输入预览、状态、摘要、错误信息、开始时间和结束时间等信息。父侧登记表回答“该运行由哪次父侧工作触发、应在主会话的哪个工具调用位置展示、重放时如何合成生命周期事件”等问题；它不同于子 agent 注册表，后者只回答某个子 agent 实例是否存在。

在一种实现中，父侧登记表还包括 $tenantId$、$mainConversationId$、父消息标识、$parentToolCallId$、$runId$、$agentType$、$inputHash$、$stateVersion$、$lastEventSequence$、$cleanupState$、$lockOwner$、$heartbeatAt$、创建时间和更新时间等字段。表内以 $(tenantId, mainConversationId, runId)$ 建立唯一约束，并对 $(parentToolCallId, displayOrder)$、状态和清理状态建立查询索引；同一 $runId$ 的重复启动请求必须在同一租户和主会话作用域内命中同一登记行，才能进入幂等恢复路径。

$runId$ 可由主 agent 在启动时生成，也可由调用方提供幂等键后经规范化得到，但其作用域必须绑定租户、主会话、子 agent 类型和本次输入摘要。系统在创建或复用运行前比较 $agentType$、$parentToolCallId$、$inputHash$、租户和主会话归属；若同一 $runId$ 已存在但任一关键维度不一致，则返回冲突错误并拒绝复用既有子 agent 实例。通过该规则，$runId$ 既能支持安全重试，又不会把不同用户、不同工具调用或不同输入的任务错误合并。

启动过程采用先登记后执行的顺序：父侧将运行状态置为 starting，随后以 $runId$ 作为子 agent 名称或运行键创建对应子 agent，并通过子侧适配器发起一次程序化聊天回合。子侧保存 $runId$、请求标识、流标识之间的映射，使主 agent 即使在子任务启动后、尚未收到全部内部标识时发生重启，也可以仅凭 $runId$ 向子 agent 查询并恢复该次运行的请求和流记录。

启动流程可以拆分为可恢复的阶段：第一步，父侧在事务中写入 starting 登记行并取得排他启动锁；若此时崩溃，恢复时因没有子侧映射而标记 interrupted 或按显式策略重试。第二步，主 agent 以 $runId$ 创建或取得子 agent 实例并调用子侧适配器；若实例创建失败，父侧写入 error。第三步，子侧适配器写入 $runId$、子会话标识、请求标识、流标识和最后片段序号的映射后启动聊天回合；若父侧在此后重启，可通过 $runId$ 向子侧查询映射并继续重放。第四步，子侧先持久化首个聊天片段再通知父侧转发，父侧把状态推进到 running 并更新 $lastEventSequence$。

子侧映射表用于把公开编排标识还原为子 agent 内部执行对象，字段可包括 $runId$、子会话标识、请求标识、流标识、子侧状态、摘要、错误信息、$lastChunkIndex$、开始时间和完成时间。子侧适配器至少提供按 $runId$ 启动、取消、检查、读取片段的接口；检查接口返回子侧状态、流标识、最后已持久化片段序号和终态信息，使父侧无需知道聊天内部请求编号即可完成恢复、重放和终态协调。

$runId$ 同时作为幂等键。若重试、告警恢复或重复请求再次要求启动同一 $runId$ 的运行，系统先检查父侧登记和子侧映射：已完成、失败或已取消的运行直接返回既有结果；仍处于 starting 或 running 的运行不再创建第二个子 agent 回合，而是返回现有运行的检查结果或重放已存储片段。这样可以避免网络重试、页面重连或父侧恢复路径重复消耗模型推理资源并产生相互冲突的执行结果。

| 运行状态 | 进入条件 | 允许转移与禁止覆盖规则 |
| --- | --- | --- |
| starting | 父侧登记行已写入，子 agent 回合尚未确认开始 | 可转为 running、error、aborted 或 interrupted；恢复时若无子侧映射，默认 interrupted，不自动重跑 |
| running | 子侧已确认程序化聊天回合开始，且至少可检查到对应映射或流记录 | 可转为 completed、error、aborted 或 interrupted；重复启动只附着到既有运行 |
| completed | 子侧正常完成并可合成最终结果 | 终态，不得被迟到取消、错误或恢复检查覆盖 |
| error | 子侧抛错、流错误或结果合成失败 | 终态，不得被迟到完成、取消或恢复检查覆盖 |
| aborted | 用户或父工作流发出明确取消信号并由子侧确认或父侧确认取消路径成立 | 终态，不得被父侧重启后的 interrupted 覆盖 |
| interrupted | 父侧恢复时无法安全确认非终态运行，或观察流无法重新接入且不承诺实时追尾 | 终态，表示未得到可信完成结果，不再自动触发第二次模型工作 |

### 流式事件转发与同会话呈现

子 agent 执行期间，其自身的聊天流持续产生与普通聊天响应相同语义的增量片段，例如文本增量、推理片段、工具调用输入和工具调用结果。子 agent 在持久化自身流片段后，将该片段通过子侧适配器输出给主 agent；主 agent 不解析或改写片段内部词汇，而是将其封装为 agent-tool-event 事件并广播给主会话客户端。

agent-tool-event 事件至少包含事件类型、$tenantId$ 或主会话作用域、$runId$、可选的 $parentToolCallId$、$agentType$、单运行单调递增序号、展示顺序、重放标记以及事件体。事件类型包括 started、chunk、finished、error、aborted 和 interrupted；其中运行状态 completed 在对外事件中映射为 finished，其他终态状态与同名终态事件对应。started 和终态事件可由主 agent 根据父侧登记合成，chunk 事件携带子 agent 原始聊天流片段的 JSON 编码体。客户端按 $(parentToolCallId, runId, sequence)$ 去重和排序，并使用与主聊天响应相同的片段累积逻辑重建子 agent 的消息部件。

事件序号由父侧按单个 $runId$ 维护并持久化在 $lastEventSequence$ 中，started 通常占用该运行的起始序号，随后每个 chunk 按子侧片段顺序递增，终态事件占用最后一个序号。实时转发时，父侧只有在子侧片段已经持久化并成功分配事件序号后才广播；重放时，父侧保持原有序号并设置 replay 标记，而不是重新编号。若父侧只保存到某个序号但子侧已有更高片段序号，恢复流程先从最后已转发序号之后补发，避免重放期间产生重复或缺口。

客户端按每个运行维护已接收序号集合、最高连续序号和终态标记。对于重复事件，客户端直接丢弃；对于乱序到达的 chunk，可先缓存并在缺失序号补齐后再应用；对于长期缺口，可触发按 $runId$ 的重放请求以从持久化流中补齐。若终态事件重复到达且终态类型一致，客户端保持既有终态；若终态之后再到达 chunk、error、aborted 或 finished 等迟到事件，客户端不得覆盖已有终态，可忽略并记录为迟到事件。

当父侧一次工具调用并行派发多个子 agent 时，多个运行可以共享同一 $parentToolCallId$，但各自具有不同 $runId$ 和独立序号空间。父侧在登记表中保存 displayOrder，并在 started 事件中携带该展示顺序，使客户端在实时流和刷新重放时均按确定顺序展示多个子 agent 面板，而不是受网络到达顺序影响。未绑定父工具调用的命令式运行则以空 $parentToolCallId$ 或独立分组展示，适用于后台报告、HTTP 触发任务或 callable 触发任务。

### 恢复、查看与访问控制

主会话客户端连接或重连时，主 agent 先恢复自身聊天历史，再遍历父侧保留的子 agent 工具运行登记。对每个运行，主 agent 根据登记记录合成带原序号的 started 事件，随后通过 $runId$ 定位子 agent，并从子 agent 自身的可恢复流存储中读取对应流片段，再以 replay 标记逐条发送 chunk 事件，最后依据登记状态合成 finished、error、aborted 或 interrupted 等终态事件。运行状态 completed 只在父侧状态机中使用，对客户端表现为 finished 事件。客户端对 replay 与 live 事件使用同一去重键，因此刷新、短暂断网和直播窗口内重复到达不会造成文本重复累积。

在支持后到实时追尾的实现中，重连算法先读取父侧 $lastEventSequence$ 和子侧 $lastChunkIndex$，在一个短事务或租约内记录重放起点，然后发送不超过该水位的历史事件；随后通过子侧适配器订阅 $lastChunkIndex$ 之后的新片段，并继续按父侧序号分配规则广播。若重放期间子侧产生新片段，新片段因索引大于水位而进入追尾阶段，不会混入历史段；若订阅建立失败，则按运行时能力将当前 running 运行标记为 interrupted，避免向客户端承诺仍在实时观察。

主 agent 重启后，对父侧登记表中仍处于 starting 或 running 的运行执行协调检查。若找不到对应子 agent 或子侧运行映射，说明执行未能安全确认，父侧将运行标记为 interrupted 而不默认重跑；若子侧报告 completed、error 或 aborted，父侧读取已存储片段并更新为相同终态；若子侧仍在 running 而当前运行时不支持后到实时追尾，则父侧重放已有片段后标记 interrupted，并在错误信息中明确观察流无法重新接入。该策略保证恢复路径不伪造成功结果，也不在歧义崩溃后自动重复模型工作。

父侧与子侧状态不一致时，以可证明的子侧执行记录和父侧终态不可覆盖规则共同决定结果：子侧已持久化 completed、error 或 aborted 终态且父侧仍为非终态时，父侧更新为相同终态并补发对应事件；父侧已进入 completed、error、aborted 或 interrupted 任一终态时，后续协调不得把它改回 running，也不得把 aborted 改为 interrupted。子侧存在更多已持久化 chunk 但缺少可信终态时，父侧只补发片段并保持或转入 interrupted，不合成成功结果。

子 agent 工具运行可被用户或开发者进一步查看。查看路径仍通过主 agent 的身份和租户边界进入，例如先访问主 agent，再经子 agent 路由定位到特定 $runId$ 对应的子 agent；$runId$ 本身不作为可独立使用的访问令牌。主 agent 在子 agent 路由前执行登记表门禁，只有当请求中的子 agent 类型和 $runId$ 在父侧登记中存在并符合当前身份策略时，才允许请求到达子 agent，否则返回拒绝或未找到结果，从而避免通过猜测 URL 创建空子 agent 或跨租户读取子任务记录。

访问控制在子 agent 路由前完成，校验项可以包括当前身份、$tenantId$、主会话归属、子 agent 类型、$runId$、父侧登记状态和清理状态。校验失败时，系统使用统一的拒绝响应或不可见响应，不通过“运行不存在”“类型不匹配”“租户不匹配”等差异化错误泄露运行是否存在。清理中或已脱敏的运行不得建立新的查看或重放观察者，只允许已授权的管理路径读取必要审计信息。

### 取消、并发、后台运行与保留清理

取消控制只在存在明确取消意图或确定的父工作流终止信号时传播到子 agent 工具运行。浏览器传输层断开、页面刷新、重放连接失败或观察流被关闭，只表示观察者离线，不调用子侧取消接口；用户点击取消、父侧聊天请求被主动中止、父工具调用失败并声明其子任务不再需要、服务器超时策略判定必须终止工作时，父侧才按 $runId$ 调用子侧取消接口并断开观察流。子侧将取消转换为本次回合专用的 AbortController 信号，传入聊天执行方法，使推理循环、子工具调用和后续片段生成尽快终止。若运行已 completed 或 error，迟到取消不得覆盖既有终态；若取消成功，则父侧和子侧均记录 aborted 状态并向主会话发送终态事件。

并发控制分为父侧总体并发和子侧实例排他两层。父侧可以设置当前运行中的子 agent 工具数量上限，超过上限时直接产生清晰的 error 事件，避免一次主请求扇出过多模型调用。父侧通过唯一约束、事务插入和启动锁保证两个请求同时启动同一 $runId$ 时只有一个请求取得执行权；未取得锁的一方只能读取既有登记、附着观察或返回冲突。子侧对同一 $runId$ 或同一子 agent 实例持有框架驱动回合的排他声明，不能并发写入同一子 agent 会话。若用户通过查看面板向正在执行框架回合的子 agent 发送新消息，默认策略为拒绝并返回“工具运行中”的可恢复错误；可选排队实现应设置队列长度、等待超时和取消规则，超限时仍拒绝，以避免上下文交错污染。

迟到事件按终态不可覆盖原则处理。父侧在写入 completed、error、aborted 或 interrupted 之前递增 $stateVersion$ 并检查当前状态仍为非终态；终态写入后，来自子侧的迟到 chunk、error、完成通知或取消确认不得再改变父侧状态，也不得分配新的对外事件序号。系统可以把迟到内容记录为审计元数据或调试日志，但客户端视图以已发布终态为准，从而避免并发取消、网络延迟和恢复协调造成面板反复变更。

除由父侧大语言模型工具调用触发的 agentTool 形式外，本方案还支持 runAgentTool 形式的命令式派发。命令式派发可以没有 $parentToolCallId$，由主 agent 的确定性工作流、HTTP 处理器、callable 方法、定时恢复逻辑或后台报告任务直接启动；这类运行仍使用相同的父侧登记、子侧映射、流片段持久化、取消和清理机制，只是在客户端归入未绑定运行列表或由业务界面按 $runId$ 查询。这样，无直接父工具调用的后台子运行也能获得与聊天内工具运行一致的保留、重放和查看能力。

运行结果默认保留，以支撑刷新后的主会话重放、执行完成后的查看、调试和审计。清理时，系统通过显式清理接口按全部、时间范围或终态集合选择运行，并先把目标登记行标记为 cleanup_pending 或写入 tombstone；该标记阻止新的重放观察者和查看面板进入。对于仍处于 starting 或 running 的运行，清理流程先按 $runId$ 发起取消，若取消失败则保留 cleanup_pending 并等待重试或超时策略，不直接删除可能仍在执行的子侧实例；确认终止或已达可安全删除条件后，再删除或脱敏父侧登记行、子侧映射和对应子 agent 实例。清理聊天历史时优先清理相关子 agent 工具运行，再清理主聊天消息，防止其他连接在短暂窗口内依据旧登记重放已被用户清除的子任务面板。
