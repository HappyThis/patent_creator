## 技术方案

### 总体构思与运行对象

本方案在已有 chat agent、子 agent 路由、流式输出和恢复机制的基础上，引入“保留式流式子 agent 工具编排”机制。用户侧仍只连接一个主 agent 并在一个主会话中发起请求；主 agent 在处理该请求时，可以把研究、规划、比较、总结等子任务派发给一个或多个专门子 agent，并将各子 agent 的运行过程、阶段性输出和终态结果以内联面板或等效视图带回同一主会话。

每一次被派发的子 agent 工作被抽象为一个 agent tool run。agent tool run 不是主 agent 内部的临时函数调用，而是由真实的、可聊天的子 agent 承担的持久执行单元。该子 agent 具有独立会话、消息记录、工具集合、模型调用过程、可恢复流和本地持久化存储；主 agent 负责创建或定位该执行单元、登记其与主会话的关系、观察并转发其输出，而不复制子 agent 的完整执行状态。

主 agent 可通过两类入口派发子 agent：其一是命令式入口，适用于确定性工作流、后台任务、阶段性报告或非 LLM 编排；其二是工具化入口，适用于主 LLM 根据上下文自主选择是否调用研究员、规划员等子 agent。两类入口均复用既有子 agent 路由和持久对象语义，只是在父侧增加运行登记、事件转发、取消和清理等编排能力。

| 对象 | 含义 | 关联关系与读写主体 |
| --- | --- | --- |
| 主会话 | 用户直接连接并可见的父 agent 会话 | 承载用户请求、父 LLM 工具调用和子 agent 面板；父侧读取并展示子运行状态，不接管子 agent 内部消息流 |
| 父工具调用标识 | 主 LLM 一次工具调用的显示锚点 | 可为空；同一父工具调用可关联多个 $runId$，用于把并行子 agent 归入同一工具结果区域 |
| 运行标识 $runId$ | 一次 agent tool run 的稳定编排键 | 在父侧 registry、子 agent 名称或映射、重放、取消、钻取和清理中保持一致；同一主会话内应唯一 |
| 请求标识 $requestId$ | 子 agent 内一次 chat turn 或中止登记的标识 | 由子 agent 写入 child run 映射；父侧通常只通过适配器间接使用 |
| 流标识 $streamId$ | 子 agent 可恢复流片段集合的标识 | 由子 agent 持有并用于历史片段读取，避免后续钻取对话把重放目标漂移到最新流 |
| agent tool run registry | 父侧运行登记表 | 由父 agent 创建和更新，记录显示、状态、权限、重放、取消和清理所需的父侧事实 |
| child run 映射 | 子侧运行映射表 | 由子 agent 创建和更新，绑定 $runId$、$requestId$ 与 $streamId$，作为子侧幂等启动和片段定位依据 |

### 父侧登记与幂等启动

父侧设置 agent tool run registry，用于记录每个子 agent 执行单元与主会话之间的绑定关系。该登记表不同于子 agent 实例注册表：子 agent 实例注册表回答某个持久子对象是否存在，agent tool run registry 回答某次子任务由哪次父工作触发、应显示在主会话的哪个位置、刷新后如何重放以及后续取消或清理应作用于哪个子 agent。

在一种实现中，父侧 registry 至少保存运行标识、父工具调用标识、子 agent 类型、输入预览、脱敏输入标记、运行状态、摘要、错误信息、展示元数据、展示顺序、开始时间和完成时间。完整输入默认不作为二次副本长期保存，父侧可只保存输入预览；当业务确需持久化完整输入时，再通过显式配置开启，以降低敏感提示词、凭据或文件内容在父侧重复落库的风险。

| 字段 | 来源/写入时机 | 可变性与终态约束 | 用途 |
| --- | --- | --- | --- |
| $runId$ | 父侧创建运行时生成或接收调用方提供值 | 创建后不可变，并应受唯一约束 | 作为父子映射、重放、取消、钻取和清理的统一键 |
| parentToolCallId | 工具化入口由父 LLM 工具调用提供，命令式或后台入口可为空 | 创建后不可变；为空时以主会话或任务所有者绑定显示位置 | 用于分组显示和把子运行结果归回父工具调用 |
| agentType | 父侧根据允许列表选择子 agent 类型 | 创建后不可变；路由访问必须与该类型匹配 | 防止同一 $runId$ 被路由到错误类型的子 agent |
| owner/tenant/session | 由主 agent 连接上下文、租户或会话上下文写入 | 创建后不可变；清理前仍参与访问校验 | 限定可见范围和后台任务归属 |
| inputPreview/inputRedacted | 启动前由父侧从输入生成预览并标记脱敏状态 | 预览可在启动前确定；完整输入默认不复制保存 | 刷新后说明任务来源，同时降低敏感输入重复持久化风险 |
| status | 父侧插入 starting 或 running，随后按子侧结果或恢复对账更新 | 只能按状态机迁移；终态后不得被迟到事件覆盖 | 驱动面板状态、工具返回和恢复处理 |
| summary/errorMessage | 子侧终态或阶段摘要回写父侧 | 运行中可增量更新摘要；终态后仅由同一终态事件写定，错误不得覆盖成功摘要 | 供父 LLM 和用户快速理解结果或失败原因 |
| displayMetadata/displayOrder | 父侧创建时写入面板标题、顺序和展示配置 | 展示顺序创建后稳定；元数据可在不改变归属的范围内补充 | 保证并行子 agent 的可重复排序和呈现 |
| startedAt/completedAt | 创建运行和写入终态时记录 | 开始时间不可回退；完成时间仅终态写入 | 用于重放排序、审计和超时判断 |
| cleanupStatus/cleanupPending | 清理流程开始、失败或完成时写入 | 清理期间阻止新钻取；失败时保留以便幂等重试 | 避免删除不完整导致孤儿子 agent 或越权访问 |

运行标识作为跨父侧登记、默认子 agent 名称、子侧运行映射、重放、钻取查看、取消和清理的稳定关联键。父侧在启动子 agent 之前先插入 starting 或 running 状态的登记行，再以同一运行标识调用子侧启动接口；若调用方在重试、告警恢复或浏览器重连路径中携带既有运行标识，父侧按该标识幂等处理：已终态的运行直接返回既有结果，未终态的运行只允许附加观察或重放，不能重复启动第二个 LLM 执行过程。

幂等启动采用父侧条件插入和子侧按 $runId$ 检查相结合的事务边界。父侧启动前先校验主会话有效、子 agent 类型在允许列表内、$runId$ 未被其他父会话或租户占用、调用者权限上下文与登记字段一致；随后以 $runId$ 唯一索引或等效条件写入 registry。并发请求中只有一个请求能够创建 starting 或 running 行，其他请求读取既有行并按状态返回：已终态则返回既有摘要、输出或失败对象，未终态则只附加观察或重放，不能再次触发子 agent 的模型推理。

若父侧登记成功但调用子侧启动失败，父侧根据失败发生位置写入 error 或 interrupted，并保留输入预览、错误信息和开始时间，默认不沿用原 $runId$ 自动重跑任意 LLM 工作；显式重试应使用新的 $runId$，或由应用在确认不会重复产生副作用时声明重试语义。若子侧实际已经启动而父侧在确认响应前崩溃，恢复时父侧通过 $runId$ 调用子侧检查接口，补齐 $requestId$、$streamId$ 或按恢复对账规则更新状态，而不是再次调用启动接口。

### 子 agent 独立执行与流式桥接

子 agent 侧设置与运行标识对应的 child run 映射，用于关联本次 agent tool run、实际 chat turn 的请求标识以及可恢复流的流标识。运行标识面向编排层保持稳定，请求标识面向一次聊天轮次或中止登记，流标识面向持久化流式片段；三者分离后，可以避免把“一次子 agent 工具运行”等同于“一次聊天轮次”或“最新一条流”，并可防止用户后续钻取进入子 agent 继续对话时覆盖原始工具运行的重放对象。

子 agent 通过统一适配器向父侧暴露启动、取消、检查、读取历史片段和可选实时尾随观察等能力。启动接口按运行标识幂等：如果子侧已经存在该运行，则返回既有状态和关联标识，不重复创建聊天轮次。读取历史片段接口仅用于重放，不表示运行仍在实时执行；尾随观察接口即使被取消，也只表示观察者分离，不等于取消子 agent 的实际执行。

| 适配器接口 | 输入与输出 | 幂等条件和副作用 |
| --- | --- | --- |
| startAgentToolRun | 输入包括任务输入、$runId$ 和可选中止信号；输出包括状态、$requestId$、$streamId$、摘要或错误 | 若 $runId$ 已存在则返回既有 child run，不新建 chat turn；首次启动会创建请求、流和执行纤程 |
| cancelAgentToolRun | 输入为 $runId$ 和可选原因；输出为取消是否被接受及当前状态 | 仅作用于对应运行；终态运行返回既有终态，未终态运行触发对应中止控制器 |
| inspectAgentToolRun | 输入为 $runId$；输出为子侧状态、关联标识、摘要、错误和时间信息 | 不改变执行状态，用于父侧恢复对账、重复请求和访问前检查 |
| getAgentToolChunks | 输入为 $runId$ 与可选 afterSequence 或片段游标；输出为已持久化片段序列 | 只读取历史片段，不声明运行仍然实时可观察，也不取消或推进执行 |
| tailAgentToolRun | 输入为 $runId$、可选 afterSequence 和观察中止信号；输出为实时片段流 | 属于可选观察能力；观察流取消只分离该观察者，不取消子 agent 执行 |

当子 agent 产生模型文本、推理片段、工具输入、工具输出或错误帧等流式内容时，子 agent 先按自身 chat agent 的可恢复流机制持久化片段，再由父侧观察者把该片段封装为 agent-tool-event 转发给主会话客户端。父侧不重新定义文本、推理或工具调用等细粒度词汇，而是把子 agent 原始 UI 消息片段作为不透明体转发；客户端复用既有消息片段累积逻辑即可还原子 agent 的完整消息视图。

流式顺序以“子侧先持久化、父侧后编号转发”为原则。子 agent 先把 chunk 写入自身可恢复流或等效片段表，再通知父侧观察者或供父侧读取；父侧针对每个 $runId$ 生成统一事件序列，started、chunk、finished、error、aborted 和 interrupted 共享同一单调序号。序号可以来自父侧事件表，也可以来自父侧转发计数器；若需要映射子侧 chunk 索引，则应明确生命周期事件同样占用序号，使历史重放和实时广播对同一事件产生相同序号。

多个浏览器标签页、重连请求或父侧观察者同时存在时，不得分别生成各自的事件序列。父侧应让所有观察者共享同一 $runId$ 事件序列，并以相同序号接收 live 或 replay 副本；观察者断开只删除该观察关系，不修改 child run 状态。由此，重复请求、并发观察和刷新恢复都只改变可见通道数量，不改变子 agent 的执行次数和事件顺序。

### 主会话呈现、重放与后台运行

父侧向客户端发送的 agent-tool-event 包含运行标识、可选父工具调用标识、单调递增序号、是否为重放事件的标记以及具体事件内容。事件类型可包括 started、chunk、finished、error、aborted 和 interrupted。started 事件用于创建子 agent 面板并携带展示顺序、子 agent 类型、输入预览等元数据；chunk 事件携带子 agent 的不透明消息片段；终态事件用于把子 agent 面板稳定地收束为完成、失败、取消或中断状态。

客户端按父工具调用标识、运行标识和序号构造去重键，并按父工具调用标识分组、按展示顺序排序。这样，同一次父工具调用下可以并行显示多个同级子 agent，例如比较任务中的两个研究员；每个子 agent 都可以从序号零开始产生事件而不会相互覆盖。刷新或重连期间，如果同一事件同时来自历史重放和实时广播，客户端通过该去重键只应用一次，避免重复文本、重复工具结果或面板状态回退。

客户端应用事件时以 $(parentToolCallId/null, runId, sequence)$ 作为去重键。若同一序号收到相同内容的 replay 与 live 帧，只应用一次；若同一序号出现不同内容，客户端不自行合并，而以父侧已持久化事件和 registry 终态为准，可丢弃冲突实时帧并请求从最近连续序号之后重新重放。若发现序号缺口，客户端可将对应子 agent 面板标记为恢复中，并通过 afterSequence 请求补齐片段；无法补齐时显示 interrupted 或等效中断状态，但不得凭空生成缺失内容。

终态事件之后到达的迟到 chunk 按来源和序号处理：若该 chunk 的序号小于已见终态序号且属于同一 $runId$ 的已持久化历史片段，可作为历史内容补入对应位置，但不得把 completed、error、aborted 或 interrupted 回退为 running；若该 chunk 的序号大于终态序号，则只有在父侧事件表或子侧持久化流能够证明其属于同一运行且终态序号应后移时才可追加，否则应丢弃并触发重放校验。重放动作本身不改变 registry 状态，也不重新触发父 LLM 工具执行。

对于由命令式接口、HTTP 调用、定时任务或后台流程触发的子 agent 运行，父侧可以不提供父工具调用标识。此类运行仍然具有运行标识、序号、状态和可重放片段，客户端将其归入未绑定运行集合或后台任务区域，而不是强行挂载到某个父 LLM 工具调用下。由此，主会话既能展示 LLM 选择工具产生的子 agent，也能展示没有直接父工具调用的长期后台子运行。

当子 agent 作为父 LLM 的工具被调用时，父侧返回给父 LLM 的结果采用结构化对象而非空字符串。单个运行的结果至少包括 status、$runId$、summary 或 output、可选的钻取引用、errorCode、errorMessage 和部分结果策略；completed 返回经子侧确认的摘要或结构化输出，error 返回失败对象，aborted 返回取消对象，interrupted 返回中断对象。这样，父 LLM 能区分“没有结果”“被取消”“观察中断”和“成功但摘要为空”，避免基于静默空结果生成误导性结论。

### 并发、恢复边界与长任务处理

本方案允许主 agent 在一次用户请求中扇出多个子 agent，并可采用并行等待、部分成功汇总或分阶段串联等方式收敛结果。父侧为每个子 agent 分配独立运行标识和展示顺序；并行运行之间使用各自的持久对象、消息流和状态行隔离，某一分支失败时不会自动抹除其他分支已经产生的流式内容或成功结果。父 LLM 接收到的工具结果应明确区分完成、失败、取消和中断，避免把缺失结果误当作空摘要继续推理。

对于一次父工具调用扇出的多个子 agent，父侧可将工具结果组织为数组或以分支名为键的对象，每个分支保留独立 status、$runId$、summary/output 和失败信息。总工具调用可以按应用策略标记为全部完成、部分完成或失败，但父 LLM 只能把 completed 分支作为确定性依据；对于 error、aborted 或 interrupted 分支，应在汇总中保留其失败或中断事实，而不是用其他分支结果覆盖。

执行与观察相互分离。浏览器断开、父侧观察流取消或父 agent 被暂时驱逐，并不天然表示子 agent 工作应被取消；子 agent 仍可依赖自身持久化消息、可恢复流、逻辑调度和保持存活机制继续保存已经产生的片段。父侧恢复后，根据 registry 中 starting 或 running 的登记行与子侧运行映射进行对账：无匹配子运行时标记为 interrupted；子侧已完成、失败或取消时，先重放已存片段再写入相应终态；子侧仍运行但当前版本不能重新实时尾随时，先重放已存片段并把父侧观察状态标记为 interrupted。

终态一旦写入父侧 registry 即作为权威状态。迟到的取消请求、重复恢复任务或新的观察者不能把 completed 或 error 改写成 aborted。对于父 LLM 工具调用中的子 agent，若父会话本身在中途崩溃，子 agent 的会话和片段可以恢复，但父 LLM 轮次未必能够从工具结果处继续；此时以 interrupted 明确呈现恢复边界，使用户和上层模型知道已有可查看的子 agent 过程，但不能假定主 LLM 已获得完整工具输出。

| 当前状态 | 允许迁移 | 触发条件 | 约束 |
| --- | --- | --- | --- |
| starting | running、error、aborted、interrupted | 父侧登记后子侧启动成功、启动失败、启动前取消或恢复发现无法确认子运行 | 不得跳过登记直接暴露子 agent；失败后保留登记供审计和重放错误 |
| running | completed、error、aborted、interrupted | 子侧正常完成、执行异常、显式取消确认或父侧恢复无法继续观察 | 观察断开不触发 aborted；恢复对账不能重复启动同一 $runId$ |
| completed | 无 | 子侧产出终态摘要或结构化输出 | 成功摘要和完成时间不可被迟到错误或取消覆盖 |
| error | 无 | 子侧或父侧启动/转发发生不可恢复错误 | 错误信息不得覆盖已经写入的 completed 结果 |
| aborted | 无 | 显式取消被接受并作用于对应运行 | 迟到取消不得覆盖 completed 或 error |
| interrupted | 无 | 父侧恢复边界、观察丢失或无法确认子运行状态 | 表示父侧观察终态，不表示子 agent 自行声明执行中断；默认不恢复为 running，除非未来明确设计 live-tail 或重试语义 |

恢复对账还处理父子记录不一致的异常分支。父侧有 registry 行但子侧无对应 child run 时，父侧将该运行标记为 interrupted，保留 inputPreview 和错误说明，并允许用户以新 $runId$ 重新发起，默认不沿用原 $runId$ 自动执行。子侧存在运行但父侧无登记行时，不允许直接钻取暴露给当前主会话；系统可按租户策略补登记、隔离或清理孤儿子 agent，但必须先验证所有者、父会话和权限范围。重复恢复任务通过条件更新、版本号或终态检查保证只有一次写入终态，后续任务只读取既有状态。

### 访问控制、取消与保留结果清理

为了支持对子 agent 过程的钻取查看，子 agent 仍通过既有嵌套路由暴露连接入口；但路由入口必须由父 agent 的访问控制钩子进行登记表校验。请求的子 agent 类型和运行标识只有在父侧存在匹配的 agent tool run 行时，才允许路由到对应子 agent；否则返回拒绝响应。运行标识本身不作为能力令牌，租户身份、认证和授权仍继承自主 agent 连接上下文，避免攻击者通过猜测运行标识创建或访问任意子 agent。

访问控制判定至少同时匹配租户或账户标识、用户或权限范围、父 agent 标识、父会话标识、$runId$、agentType、清理状态以及可选的 parentToolCallId。对于同一租户下的不同用户，仍需校验其是否拥有该主会话或共享空间的访问权限；对于无父工具调用标识的后台任务，应绑定任务所有者、工作区或主会话上下文，而不是依赖空 parentToolCallId 放宽校验。处于 cleanupPending 或已清理状态的运行不得新建钻取连接。

取消从父侧活动操作显式传播到子 agent，而不是由普通观察断开隐式触发。父会话停止、父工具执行被中止或用户明确取消某个运行时，父侧按运行标识调用子侧取消接口；子侧中止该运行对应的每轮 AbortController，并把中止信号传入模型推理或消息保存流程，使推理循环及时停止。随后父侧分离观察流并写入 aborted 或错误终态；若子侧此前已经完成或失败，则迟到取消不改写既有终态。

取消竞态以条件更新和子侧实际请求状态共同裁决。普通观察断开只 detach observer，不写 aborted；显式取消只能从 starting 或 running 发起，可先设置取消中标记再等待子侧确认。若子侧已经完成并持久化 completed，取消请求返回既有完成状态；若 error 与 aborted 近似同时到达，以父侧首次成功写入的终态为准，或以子侧 inspect 返回的实际请求终态为准进行一次条件写入。任何迟到错误、迟到取消或恢复对账都不得把已写入的 completed 改为其他终态。

子 agent 运行默认在完成后保留父侧登记行和子 agent 持久对象，以支持页面刷新后的过程重放、失败原因排查、钻取查看和审计。清理由显式接口或应用生命周期策略触发；清理时先取消仍处于 starting 或 running 的运行，再删除父侧登记行以及对应子 agent 持久对象。仅删除父侧登记而保留子 agent 会造成不可重放、不可钻取的孤儿执行记录，因此默认清理动作应同时覆盖登记和子 agent 实例。

清理流程采用可幂等重试的分阶段顺序：先设置 cleanupPending 或禁止新观察、钻取的等效标记，并向已有观察者发送终止或清理提示；再对非终态运行显式取消并等待确认或记录待清理状态；随后按登记中的 agentType 和 $runId$ 删除对应子 agent 持久对象；最后删除或归档父侧 registry 行。若子 agent 删除失败，父侧保留 registry 行和 cleanupPending/error 以便后续重试；若父侧登记删除失败，访问控制 gate 仍以该行阻止未授权或已清理对象继续暴露。重复清理请求读取当前清理状态并继续未完成阶段，不因对象已不存在而抛出不可恢复错误。

通过上述机制，本方案使复杂 agent 协作在用户侧仍表现为一个连续主会话，同时在系统侧保持子 agent 执行上下文、流式片段、恢复状态、取消控制和保留结果的独立性。主 agent 不再把子任务视为一次性同步工具返回，而是把其作为可观察、可重放、可审计且可清理的持久协作单元，从而支撑长耗时研究、并行比较、后台规划和刷新恢复等复杂协作场景。
