## 技术方案

### 总体构思

本方案在既有智能工作台能够同时展示 gateway 会话和 Claude、Codex、Hermes 等本地 runtime 会话的基础上，增加一层可插拔的本地 runtime 适配机制。新增 runtime 不直接改写既有扫描器、会话接口或控制逻辑，而是以独立 adapter 的形式接入统一管线：先进行 runtime 探测和能力确认，再读取可验证的本地会话记录，随后映射为工作台统一会话模型，最后与既有 gateway 会话及其他本地会话合并展示。

该机制的核心不是预设新增 runtime 已经具备完整控制能力，而是把“能否发现”“能否解析会话”“能否读取 transcript”“能否继续会话或附着终端”等能力拆开验证和发布。对于状态目录、会话文件格式或继续会话命令尚未完全确定的 runtime，系统只把经证据确认的部分纳入工作台；未确认的能力保持不可用或只读状态，从而避免把推测能力展示为可执行能力，也避免影响已有 runtime 的会话管理流程。

### 核心对象与数据流

本方案统一使用“能力清单”表示 adapter 经探测后输出的动态能力结果；adapter 的静态声明只表示该 runtime 理论上可能支持的能力，会话级能力清单则是从探测记录和具体会话证据裁剪后的门控信息。adapter 至少提供 `detect(config)`、`scanSessions(probe)`、`readTranscript(sessionId, probe, options)`、`resumeSession(sessionId, prompt, options)` 和 `attachTerminal(sessionId, options)` 五类接口；各接口均返回 `{ok,data,diagnostics}` 结构，失败时返回 `{ok:false,code,retryable,diagnostics}`，其中空会话列表、无 transcript 源或能力未知属于可诊断结果，不作为全局异常抛出。

核心数据对象包括 profile、探测记录、标准化会话和诊断对象。profile 记录 `profileId`、适用版本范围、候选可执行文件、候选 `stateRoot`、文件 glob、数据库 schema 要求、字段映射、命令模板和能力验证规则；探测记录记录 `runtimeId`、`profileId`、`version`、`executablePath`、`stateRoot`、`signatureMatched`、`evidence[]`、`capabilities`、`diagnostics[]`、`detectedAt` 和 `expiresAt`；标准化会话记录记录 `nativeSessionId`、`dedupeKey`、`runtimeId`、`sourceRoot`、账号或项目标识、模型、时间、token、消息统计、transcript 源和会话级能力清单；诊断对象记录故障代码、证据来源、影响范围、是否可重试和恢复建议。后续扫描、展示和操作模块只消费这些对象，不重新猜测 runtime 状态。

数据流按候选路径生成、profile 匹配、签名验证、能力计算、会话源枚举、单源解析、统一模型输出、合并层去重排序的顺序执行。每一步只接受上一步的结构化输出：例如会话扫描必须以 `capabilities.scanSessions` 为 enabled 或 degraded 且具有有效 `stateRoot` 为前置条件；transcript 读取必须以会话记录具有可定位 transcript 源且 `capabilities.readTranscript` 为 enabled 为前置条件；继续会话必须以会话能够反向映射到 native id、runtime 版本仍匹配探测记录并且 `capabilities.resumeSession` 为 enabled 为前置条件。

### runtime 探测与能力分级

新增 runtime 的 adapter 包含 runtime 标识、显示元数据、候选安装探针、候选状态根目录、会话文件匹配规则、格式签名规则和能力清单。探测时，系统先按配置项、环境变量、常见本地目录和可执行文件路径形成候选集合，再对候选项进行逐项验证，例如检查可执行文件是否存在且能返回版本或帮助信息、状态目录是否存在、会话文件是否满足预期扩展名和必要字段、SQLite 数据库是否包含目标表及必要列。仅当候选项通过对应签名验证后，才记录为有效探测结果。

探测由系统启动、用户手动刷新、配置项或环境变量变化、可执行文件 mtime 变化、profile 版本更新、上一探测记录到达 `expiresAt` 等事件触发。探测命令采用参数数组而非拼接字符串，设置短超时和最大输出长度，预期输出通过版本正则、帮助文本关键字或 JSON 字段进行匹配；文件证据包括目录可读性、会话文件样本、数据库 schema、必要字段样本和权限检查结果。每条 evidence 记录包含类型、路径或命令、匹配规则、原始摘要、时间戳和可信度，供能力计算和诊断展示使用。

adapter 输出的能力清单至少区分安装状态、认证或配置状态、会话扫描、transcript 读取、继续会话、终端附着和控制操作等能力项。每一能力项均包含启用条件、验证证据、适用版本范围和失败原因；其中继续会话、终端附着和控制类能力必须同时满足命令可用、参数模式经验证、会话标识可安全传递和权限满足等条件。若只能确认本地记录存在但无法确认 resume 命令或交互协议，则该 runtime 仅发布只读的会话发现与展示能力。

| 能力状态 | 判定条件 | 处理结果 |
| --- | --- | --- |
| enabled | 版本范围、格式签名、权限、命令或数据源、会话 id 可逆映射均通过验证 | 允许扫描、读取或执行对应操作，并把证据随会话下发 |
| degraded | 核心数据可读但存在字段缺失、分页受限、部分文件损坏或辅助能力失败 | 输出可确认字段，同时标记降级原因并关闭依赖缺失字段的操作 |
| unknown | 证据不足、版本无法确认、格式样本不足或命令参数模式未验证 | 不开放执行类入口，仅保留待确认诊断或只读概要 |
| disabled | 明确未安装、认证失败、权限拒绝、版本不支持或安全校验失败 | 禁止调用对应 adapter 方法，并记录失败代码和恢复条件 |

探测结果不只返回布尔值，而是形成包含 runtime 版本、命中路径、格式签名、能力状态和诊断信息的探测记录。工作台后续模块依据该探测记录决定是否调用扫描器和开放操作入口；当多个候选路径同时存在时，优先选择签名完整、版本匹配且最近有会话活动的候选项，并保留其证据来源，避免仅凭目录名称或品牌名称误判 runtime 可用。

候选路径和 profile 竞争时采用分层比较。首先排除签名未命中或权限不足且不可恢复的候选；其次按用户显式配置、runtimeId 专属签名、版本范围精确度、schema 完整度、会话样本有效率、最近活动时间和路径优先级排序。当两个候选属于同一 runtime 但 `stateRoot` 不同时，若账号或项目根不同则可作为两个实例并存；若指向同一真实目录则只保留得分较高者。若两个 adapter 同时命中同一目录，则选择签名特异性更高、profile 优先级更高的一方，另一方记录为冲突诊断，避免重复扫描或错误归属。

### 本地会话解析与统一模型映射

会话解析阶段沿用既有本地会话接入思路，但将具体格式处理封装在新增 runtime 的 adapter 内部。对于 JSONL 类会话文件，解析器逐行读取并独立解析每条记录，从会话元数据、用户消息、助手消息、token 统计、模型信息、工作目录和时间戳等字段中提取可确认信息；对于 SQLite 或其他结构化状态文件，解析器先验证表结构或键集合，再以只读方式查询会话行及消息行。任一单条记录解析失败时只跳过该记录，不中断整个 runtime 或其他 runtime 的扫描。

JSONL 解析采用尾部安全和单行隔离策略。读取器限制单文件大小、单次读取字节数和解析耗时；文件正在写入时允许最后一行不完整并将其暂存为 pending，不参与本次统计；单行 JSON 损坏、字段缺失或角色未知时跳过该行并累加诊断计数；内容字段超过上限时截断并写入 `truncated=true` 标记；时间戳重复时按文件偏移量保持稳定顺序，时间戳倒序时仍保留原始顺序 evidence，并在输出排序时以规范化时间加原始序号作为排序键。编码异常或二进制片段不进入消息正文，只保留长度、哈希或诊断摘要。

SQLite 类状态文件以只读连接打开，并优先使用不会获取写锁的查询方式读取；连接前先检查文件存在、权限和大小，连接后先验证 schema 版本、目标表、必要列和索引可用性。查询按最近更新时间分页，单页数量和总行数受 profile 限制；遇到 WAL 文件、锁冲突或短暂 busy 状态时按短间隔有限重试，仍失败则返回 degraded 或 disabled 诊断。表缺失、列缺失、schema 版本不匹配或数据库损坏时，不尝试写入修复，也不阻塞其他 adapter，而是返回该 profile 不匹配或该能力不可用的局部结果。

解析得到的本地记录被映射为统一会话模型，该模型至少包含会话标识、去重键、runtime 类型、项目或 agent 名称、模型、token 摘要、消息数量、工具调用数量、工作目录、活跃状态、开始时间、最后活动时间、数据来源和能力状态等字段。对于新增 runtime 中无法可靠取得的字段，系统保留为空值、未知值或 evidence 元数据，不通过其他 runtime 的字段规则进行臆测；活跃状态也以会话文件时间、消息时间、进程或网关状态等可验证信号组合判断，并对未来时间、缺失时间和过期活动作容错处理。

统一会话模型的字段按来源可信度生成。`nativeSessionId` 优先取日志或数据库中的会话 id，其次取文件名中符合 profile 规则的片段，再次取 `stateRoot` 内相对路径哈希；`dedupeKey` 由 `runtimeId + normalizedStateRoot + accountOrWorkspace + nativeSessionId` 生成，避免同一 runtime 的不同安装实例中同名会话被误合并。开始时间优先取第一条有效消息时间，其次取会话元数据时间，再次取文件创建或数据库行创建时间；最后活动时间优先取最后一条有效消息时间，其次取会话结束时间、文件 mtime 或数据库更新时间，并记录实际采用的字段来源。消息数量、token 摘要、工作目录和模型只从本 runtime 的 profile 映射规则提取，缺失时置空并附带字段级 evidence，不使用其他 runtime 的经验规则补全。

活跃状态采用组合判定：先将消息时间、文件 mtime、数据库更新时间统一为毫秒时间并进行时区和未来时间容错，超过当前时间容差的时间戳钳制为当前时间并记录诊断；再取最后有效消息时间与存储更新时间中的较大者作为候选活动时间；最后结合进程或 gateway 仍运行、会话未显式结束、候选活动时间落入 runtime profile 规定活跃窗口等条件确定 `active`。若存在明确结束时间或进程已退出，则即使文件 mtime 较新也不直接判为活跃；若时间全部缺失，则 active 为 unknown 或 false，并保留可展示但不可执行的会话概要。

若新增 runtime 支持 transcript 读取，adapter 还提供独立的 transcript 解析器，把不同日志格式中的用户输入、助手输出、工具调用、工具结果和系统事件转换为统一消息片段。该解析器采用限量读取、按时间排序和内容截断机制，避免大文件或异常日志拖慢工作台；当 transcript 格式尚未确认时，工作台仅展示会话概要，不开放 transcript 详情入口或显示“格式待确认”的诊断状态。

transcript 读取只在会话具有可定位 transcript 源时执行。读取时按 profile 指定的文件数量、字节数量、消息数量和超时时间取最近片段，消息排序键为规范化时间戳、源文件序号、文件偏移量或数据库行号；同一时间戳下保持源内稳定顺序。工具调用和工具结果按 tool id 或相邻关系配对，配对失败时分别作为孤立工具调用或系统结果展示并记录诊断。若 transcript 源被删除、移动或轮转，概要会话仍保留，但 transcript 能力在该会话级能力清单中降为 disabled 或 degraded，不用空 transcript 覆盖旧的可用片段。

为避免重复全量扫描，adapter 为每个会话源维护轻量缓存，缓存键包含 `runtimeId`、`stateRoot`、profile 版本和文件或数据库标识。文件类源以 mtime、大小、inode 或相对路径哈希判断是否变化；数据库类源以 schema 版本、文件 mtime、WAL mtime、最大更新时间或分页游标判断是否需要重读。文件被删除、移动或轮转时，缓存项标记为 stale，合并层在保留最近一次概要的同时降低其 transcript 或 resume 能力，待下一次有效扫描确认后再更新或移除。

### 会话合并、展示与能力门控

新增 runtime 产生的统一会话记录进入与既有本地会话相同的合并层。合并层将 gateway 会话和各本地 runtime 会话按来源与会话标识组成去重键，保留同一来源同一会话中最后活动时间最新的记录，再按最后活动时间排序并限制返回数量。由于新增 adapter 只向合并层提交规范化后的记录，既有 Claude、Codex、Hermes 或 gateway 的扫描、同步和排序规则无需被替换。

合并层的去重不跨来源盲目覆盖。对于本地 runtime，会话来源粒度至少包含 `runtimeId`、规范化 `stateRoot`、账号或 workspace、项目标识和 `nativeSessionId`；对于 gateway 会话，来源粒度包含 gateway 标识、agent、session key 或 session id。若 gateway 会话与本地会话通过显式关联字段、相同 native id 映射或 adapter 提供的关联证据指向同一真实会话，系统建立关联关系并在详情中合并展示可互补字段；若证据不足，则两条记录分别展示，避免把本地日志和远端 gateway 状态错误合并。冲突字段按来源可信度选择：控制状态以 gateway 为准，本地 transcript、token 和工作目录以本地证据为准，冲突值保留诊断。

工作台展示层不再只依据 session kind 固定判断某项操作是否可用，而是读取会话记录随附的 capability manifest。列表和详情页可以展示新增 runtime 的会话来源、模型、token、活跃状态和工作目录等已确认信息；发送继续会话请求、打开终端附着、读取 transcript 或执行控制操作时，必须先检查对应能力是否为 enabled。能力为 disabled、unknown 或 evidence 不足时，相应入口被隐藏或置灰，并给出只读、待确认或版本不支持等状态说明。

能力门控同时在展示层和接口层执行。展示层根据会话级能力清单决定按钮、输入框和 transcript 入口是否显示；接口层在每次请求到达时重新读取未过期探测记录并校验能力状态、用户权限、会话归属和 native id 反向映射，任何一项不满足均返回统一错误码而不调用 adapter。这样即使前端状态滞后或被绕过，继续会话、终端附着和控制操作也不会越过能力清单直接执行。

对于继续会话能力，系统通过 adapter 提供的命令模板或 API 调用器执行，而不是复用其他 runtime 的固定命令。请求进入继续会话接口后，接口先校验会话标识、prompt 长度、用户权限和 runtime capability，再由对应 adapter 生成安全参数并调用本地 runtime；调用结果只更新该 runtime 对应会话的 transcript 或返回内容。这样可以在新增 runtime 版本差异较大时避免错误调用，同时保留既有 runtime 已验证的继续会话路径。

继续会话形成闭环执行流程。接口先校验 prompt 长度、字符集、用户角色、本地执行权限和会话级锁；adapter 将工作目录、环境变量白名单、native session id、prompt 和输出路径绑定为参数数组或结构化 API 请求，不进行 shell 字符串拼接。调用过程中设置超时和取消令牌，记录进程 id 或请求 id；退出后将 stdout、stderr、退出码、超时、取消或权限拒绝映射为统一结果。只有当 adapter 返回成功且重新读取 transcript 或输出片段通过格式验证时，才更新会话详情；若本地 runtime 已写入部分内容但命令失败，则重新扫描后把新增片段标记为 partial，不覆盖旧的完整 transcript；若无法确认写入结果，则保持旧记录并返回可重试诊断。

并发访问采用会话级互斥和只读快照配合处理。同一 `dedupeKey` 上同时只能有一个继续会话或终端附着写入类操作；扫描和 transcript 读取可以并发执行，但读取的是调用开始时确定的文件列表、数据库游标或缓存快照。若扫描发现会话正在写入，则降低本次统计的确定性并标记 pending；写入类操作完成后触发该会话的增量重扫。超时、取消或失败不会清空原会话记录，也不会把空输出覆盖为最新 transcript。

### 版本差异、降级与隔离保护

为适应新增 runtime 不同版本可能采用不同状态目录、日志格式或命令参数的情况，adapter 采用 profile 化配置。每个 profile 描述适用版本范围、候选 state root、会话文件 glob、必要字段、字段映射、transcript 解析规则和能力验证规则；探测时按照 profile 逐一匹配，并把未匹配原因记录为诊断信息。新增版本只需增加或调整 profile，不需要改动统一会话模型或既有 runtime 的 adapter。

profile 匹配失败会形成诊断链而不是单一失败信息。系统记录每个 profile 的版本不匹配、目录缺失、签名字段缺失、schema 不兼容、命令不可用、权限不足或样本不足等原因；当 runtime 升级、配置变更、目录权限恢复、profile 更新或缓存过期后，重新执行探测并基于新的 evidence 重新计算能力状态。新的 enabled 状态会替换旧的 unknown 或 disabled；旧诊断保留为历史记录但不再参与门控，避免一次失败永久阻断后续可用能力。

扫描和解析过程采用故障隔离策略。新增 runtime 的目录不存在、权限不足、文件过大、JSON 行损坏、数据库表缺失或命令探测超时，均被转换为该 runtime 的局部诊断状态；合并层收到空结果或降级结果后继续处理其他 runtime 的会话，不抛出会导致整体会话列表为空的错误。对于需要读取本地状态的文件，优先只读打开并设置扫描数量、文件大小和超时时间上限，避免与正在运行的本地 agent 产生锁冲突或资源争用。

资源边界按 runtime profile 独立配置并由统一扫描调度器执行，包括候选目录数量上限、单目录文件数量上限、单文件大小上限、单次读取字节上限、数据库分页大小、总解析耗时和命令探测超时。超过上限时优先选择最近修改或最近活动的样本，未读取部分记录为 coverage 诊断。目录为空返回 enabled 但无会话结果；权限不足返回 disabled 或 degraded；文件数量过多返回部分扫描结果而不阻塞其他 runtime。

通过证据驱动的能力发布，系统在证据不足时把能力计算为 unknown、disabled 或 degraded，展示层和接口层据此共同门控，直接避免把推测能力暴露为可执行操作；通过 adapter 隔离，新增 runtime 的探测、解析和命令执行失败只形成该 runtime 的诊断结果，合并层仍处理既有 runtime 的统一会话记录，因而不污染全局会话列表；通过文件、数据库、命令和 transcript 的资源上限控制，异常大文件、损坏日志或锁冲突只造成局部降级；通过 profile 化版本适配和重新验证机制，状态目录、日志格式和 resume 参数随版本变化时可以更新匹配规则并重新计算能力。上述手段共同使工作台能够识别和管理新增本地 runtime 的历史会话，同时保持既有 runtime 的发现、展示、继续会话和控制流程稳定。
