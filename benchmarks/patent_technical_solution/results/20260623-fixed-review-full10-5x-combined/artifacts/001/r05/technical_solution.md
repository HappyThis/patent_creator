## 技术方案

本方案在既有智能工作台的多运行时接入能力基础上，增加面向新本地 agent runtime 的适配层。该适配层不直接假定新运行时的状态目录、会话文件格式或继续会话命令已经稳定，而是以“运行时画像、只读扫描器、兼容解析器、统一会话映射器、能力门控器”的组合方式接入：先识别本机是否存在该运行时及其可读取状态，再将可确认的会话记录转换为工作台已有的统一会话对象，最后依据已验证能力决定是否允许查看转录、继续会话或执行控制动作。

### 总体架构与接入边界

工作台侧保持现有 OpenClaw 网关会话、本地 Claude Code 会话、本地 Codex CLI 会话以及 Hermes 会话的接入路径不变，在统一会话查询流程中为新运行时增加独立适配分支。该分支仅向上游输出标准化后的会话集合和能力状态，不反向修改既有运行时的检测逻辑、会话控制接口或继续会话接口，从结构上避免新增运行时对已有管理流程产生耦合。

该适配层包括运行时探测模块、状态源发现模块、会话解析模块、统一模型映射模块和动作能力判定模块。运行时探测模块负责给出安装、认证、可访问状态目录等基础状态；状态源发现模块根据可配置候选路径、环境变量或运行时返回的元信息确定可读取的数据源；会话解析模块在只读条件下提取消息数量、模型、时间戳、工作目录、token 统计等可确认字段；统一模型映射模块将结果转换为工作台现有会话字段；动作能力判定模块将继续会话、删除、标签、控制等动作标记为可用、不可用或未知。

### 统一状态与数据模型

本方案统一采用“运行时画像”作为新增运行时的内部适配描述。运行时画像是工作台内部保存的结构化配置，不等同于外部运行时本身；状态源是外部运行时产生的本地文件、目录或数据库；统一会话对象是工作台对不同来源会话记录的标准化表示；能力状态是工作台决定是否暴露查看、继续或控制动作的依据；诊断对象用于描述检测、扫描、解析或执行过程中的异常原因。

| 对象 | 主要字段 | 状态或取值 | 用途 |
| --- | --- | --- | --- |
| runtime_status | profile_id、runtime_name、evidence、selected_state_source、selected_parser、diagnostic | not_found、candidate、discovered、readable、executable | 描述运行时从未发现到可执行动作的阶段 |
| capability_status | capability_name、status、evidence_refs、verified_at、ttl、degrade_reason | available、unknown、unavailable | 决定工作台是否暴露转录、继续会话或控制动作 |
| scan_result | source_id、records、incomplete_records、cache_hit、scan_started_at、scan_finished_at、diagnostic | success、partial、empty、failed | 描述一次只读扫描的输入来源、输出记录和失败类型 |
| session_object | session_key、source、raw_session_id、fields、field_sources、capabilities、last_activity | confirmed、derived、cache_inherited、unknown | 承载统一展示、排序、去重和动作门控 |
| diagnostic_object | code、message、severity、runtime_source、stage、retryable、observed_at | info、warning、error | 向聚合层说明异常原因而不阻断其他运行时结果 |

上述对象在一次会话聚合请求中的流转顺序为：先由运行时画像生成 runtime_status，再由 readable 状态对应的状态源生成 scan_result，随后由解析器将 scan_result 中的原始记录转换为 session_object，最后由 capability_status 控制每个 session_object 可展示的详情和可执行动作。任一阶段产生的 diagnostic_object 都随该运行时结果返回给聚合层，但不改变其他运行时的状态对象。

### 新运行时的探测与能力建模

针对新运行时状态目录和版本差异尚未完全确定的问题，本方案将运行时接入信息抽象为运行时画像。运行时画像至少包括运行时标识、显示名称、候选可执行文件或探测命令、候选状态目录、候选会话存储类型、版本指纹规则、认证状态判断规则以及动作能力声明。探测时先按照运行时画像执行轻量检测，只有在检测到可执行入口、状态文件或运行时自描述信息中的至少一类可信证据时，才将该运行时标记为已发现。

| 字段 | 含义 | 来源优先级 | 默认处理 |
| --- | --- | --- | --- |
| profile_id | 运行时画像的内部唯一标识 | 内置配置、管理员配置、环境变量覆盖 | 必填，缺失时该画像不参与探测 |
| runtime_name | 工作台显示的运行时名称 | 内置配置或管理员配置 | 缺失时使用 profile_id |
| detect_commands | 候选可执行文件、版本命令或只读探测命令 | 环境变量覆盖优先，其次管理员配置，再次内置候选 | 为空时跳过命令证据 |
| state_path_candidates | 候选状态目录、状态文件或数据库路径 | 环境变量、管理员配置、运行时自描述、内置默认 | 为空时仅可形成候选状态 |
| storage_type_candidates | 文件型、JSONL 事件流、SQLite 或其他结构化存储候选 | 画像配置和自描述信息 | 未知时使用探测器识别，不强制解析 |
| version_fingerprint | 版本号、schema 版本、文件头或表结构指纹规则 | 命令输出、自描述文件、schema 查询 | 不可识别时标记为 unknown |
| parser_id | 与版本或数据形态匹配的解析器标识 | 版本指纹匹配优先，其次数据形态匹配 | 无匹配解析器时会话读取能力不可用 |
| capability_declarations | 只读展示、转录、继续会话、控制动作等能力声明 | 画像配置和验证结果共同决定 | 未验证能力默认为 unknown |
| risk_level | 动作改变外部运行时状态的风险级别 | 画像配置 | 缺失时按高风险处理 |
| cache_ttl | 探测结果、扫描结果和能力验证结果的有效期 | 管理员配置优先，其次内置默认 | 缺失时使用保守短周期 |

能力建模采用显式能力矩阵，而不是根据运行时名称推断功能。capability_status 为 available 的条件是：对应证据仍在有效期内、验证步骤成功、所需输入输出规则完整且风险级别允许暴露动作；capability_status 为 unknown 的条件是：存在候选命令、候选状态源或历史成功记录，但当前未完成验证、验证已过期或版本发生变化；capability_status 为 unavailable 的条件是：验证明确失败、缺少必要字段、动作不具备幂等性或无法确认回滚方式。能力从 available 降级为 unknown 或 unavailable 时记录 degrade_reason，并在运行时画像变更、版本指纹变化、用户手动重新验证、缓存 TTL 到期或前一次失败原因被修复后重新验证。

当检测到多个版本或多个候选状态源时，系统优先选择证据链更完整且解析器版本匹配的状态源；若证据不足，则仅输出诊断状态和只读展示所需的最小字段。由此可以在新运行时版本变化时保持接入弹性，同时避免把未经确认的状态目录、schema 或命令接口固化为必然可用的系统能力。

运行时探测按确定的状态转移执行：加载运行时画像后，若画像缺少 profile_id 或风险级别不明且未配置只读探测路径，则输出 not_found；若仅存在候选命令、候选目录或候选自描述文件之一但未完成读取校验，则输出 candidate；若可执行文件存在且版本命令返回成功，或状态源存在且可读，或自描述信息可解析，则输出 discovered；若进一步确认存在匹配解析器并能从状态源解析出最小会话字段集合，则输出 readable；只有在对应动作能力通过无副作用验证且未超过验证有效期时，才允许对该运行时或其中的会话输出 executable 能力。

证据列表按照证据等级和匹配完整度排序。命令返回的明确版本号、运行时自描述文件中的状态目录声明、数据库 schema 版本或事件文件头属于强证据；候选路径存在且可读、文件扩展名或目录命名符合画像规则属于中等证据；仅由历史缓存、默认路径猜测或不完整文件名得到的线索属于弱证据。选择状态源时先比较强证据数量，再比较解析器版本匹配度、schema 完整度、最近一次成功解析时间和最近修改时间；仍同分时，不合并互相冲突的记录，而是输出诊断对象并仅采用能形成最小字段集合的只读结果。

### 本地会话记录的只读扫描与兼容解析

新运行时的本地会话采集采用只读扫描方式。扫描器不启动或接管运行时进程，也不写入其状态目录；对于文件型记录，可按候选目录递归查找受支持扩展名并设置单文件大小、最近文件数量和扫描间隔上限；对于数据库型记录，可采用只读连接并先验证必要表或字段是否存在；对于目录缺失、权限不足、文件过大、数据库锁定或 schema 不匹配的情形，扫描器输出空集合或降级诊断，而不向外抛出导致整体会话接口失败的异常。

兼容解析器以版本指纹和数据形态为入口选择解析策略。若会话记录为 JSONL 或类似逐行事件格式，解析器逐条读取消息事件、元数据事件和 token 统计事件，并在解析失败的单行处跳过该行而保留同文件中已解析的有效事件；若会话记录为 SQLite 或其他结构化数据库，解析器先读取 schema 信息，再按存在字段提取会话标识、模型、开始时间、最近活动时间、消息计数、工具调用计数和标题等字段。缺失字段不以默认事实补齐，而是映射为空值、unknown 或由其他可确认字段推导的保守值。

解析后的会话活动状态不依赖单一字段判断，而是结合最近消息时间、会话结束标记、运行时进程或网关可达性等证据形成保守结论。对于无法确认仍在运行的会话，可以显示最近活动时间和历史记录，但不标记为可控制的活动会话。这样既能把新运行时已有本地会话纳入工作台，又能避免因日志残留、时间戳异常或版本差异导致错误的活跃状态展示。

#### 文件型状态源扫描规则

文件型状态源扫描以选定状态目录为根目录，按照运行时画像中的扩展名白名单、目录深度上限和最近修改时间窗口遍历文件。遍历时忽略常见缓存目录和无法读取目录；隐藏目录只有在其路径由运行时画像明确声明为状态目录时才进入；符号链接默认不跟随，确需跟随时记录真实路径并维护 visited 集合，避免循环目录导致重复扫描。

扫描器对候选文件先执行元数据筛选，再决定是否读取内容。元数据筛选包括文件大小阈值、修改时间、扩展名、inode 或等价文件标识以及可选的轻量哈希；若文件标识、大小和修改时间均未变化且缓存未过期，则复用上一轮解析结果并将字段来源标记为 cache_inherited。对于正在写入的文件，若连续两次元数据读取结果不一致，扫描器将该文件标记为 unstable，本轮只读取已稳定的前缀内容或延后到下一轮扫描，不以不完整内容覆盖旧缓存。

当候选文件数量超过上限时，扫描器按照最近修改时间、最近成功解析记录、强证据文件优先级和文件大小由小到大的顺序截取。被截断的候选文件不作为不存在处理，而是在 scan_result 中记录 skipped_count 和对应诊断码，使聚合层能够区分真实无会话与资源边界导致的未扫描。

#### 数据库型状态源扫描规则

数据库型状态源采用只读连接或只读事务访问。连接建立后先读取数据库版本、schema 版本或表结构摘要，再检查运行时画像声明的必要表字段集合。必要集合包括会话 id、至少一个时间字段以及能够区分会话记录的来源字段；增强集合包括模型、标题、消息数量、工具调用数量、token 统计和结束时间。缺少必要集合时不生成会话读取能力；缺少增强集合时仅生成字段不完整的 session_object，并在字段来源中标记 unknown。

数据库锁定、读取超时或 schema 变化时，扫描器执行有限次数的短间隔重试；重试仍失败则终止该状态源扫描，生成 retryable 的 diagnostic_object，并保留上一轮未过期的成功结果。只读查询不得执行写入、迁移、vacuum 或锁升级操作；若数据库只能通过写锁打开，则该状态源被标记为 unavailable，以防止接入过程干扰外部运行时。

#### 事件流解析与字段置信度

对于 JSONL 或其他逐行事件流，解析器按照事件类型将原始行归入元数据事件、用户消息事件、助手消息事件、工具调用事件、token 统计事件和结束事件。session_id 优先从元数据或事件字段读取；缺失时可由文件名、父目录和首条可解析时间组合推导，但该会话标识的来源标记为 derived。角色字段按运行时画像中的映射表转换为 user、assistant、tool 或 system，无法映射的事件不计入消息数量，只作为诊断保留。

事件归并时以 session_id 为主键，将同一会话的事件按规范化时间戳排序。时间戳统一转换为工作台内部时间表示；缺少时区的时间戳按状态源声明的时区或本机时区解析；明显早于会话开始时间、晚于扫描时间过多或相对上一事件异常倒退的时间戳不直接用于排序，而是标记为 suspect_time 并退回使用文件修改时间或邻近事件顺序。token 统计事件优先按事件引用的消息 id 关联到消息；无法关联时汇总到会话级 token 字段，并将字段来源标记为 derived。

单行解析失败不终止整个文件解析。解析器记录失败行号、失败类型和所在状态源，将对应会话标记为 incomplete；incomplete 会话可以参与只读展示和排序，但不获得继续会话、删除、暂停等会改变运行时状态的能力。若同一文件的失败比例超过画像阈值，scan_result 标记为 partial 或 failed，并保留已成功归并的会话对象，避免局部格式变化导致全部历史记录不可见。

### 统一会话模型映射与工作台合并展示

为使不同运行时的记录能够在同一工作台中管理，本方案将新运行时会话映射为统一会话对象。该对象以 source、profile_id 和 raw_session_id 组合形成 session_key，字段包括工作目录或项目标识、模型信息、用户消息数量、助手消息数量、工具调用数量、token 或成本统计、首次消息时间、最近活动时间、最后用户输入摘要、活跃状态、可用动作集合以及来源证据。每个字段同时带有 field_source，取值为 confirmed、derived、cache_inherited 或 unknown，用于区分直接读取值、解析推导值、缓存继承值和未知值，避免把缺失字段误认为真实空值。

会话合并管线依次执行输入收集、规范化、去重、字段级合并、排序和返回。输入集合包括网关会话、既有本地运行时会话、新运行时扫描结果以及未过期缓存结果；规范化阶段把各来源转换为 session_object；去重阶段以 session_key 为主，禁止不同 source 的相同 raw_session_id 互相覆盖；字段级合并阶段按照 confirmed 优先于 derived、derived 优先于 cache_inherited、cache_inherited 优先于 unknown 的顺序覆盖，新扫描结果中的 unknown 不覆盖旧缓存中的已确认字段。

异常空集合不直接删除上一轮成功扫描得到的会话记录。若本轮 scan_result 为空，系统先根据 diagnostic_object 区分真实无会话、目录缺失、权限不足、数据库锁定、schema 不匹配、扫描超时和解析失败；只有在状态源确认可读、解析器成功执行且结果明确为空，或缓存超过失效期限并连续多轮确认无记录时，才将旧会话标记为 expired。对于权限不足、锁定、超时或格式变化导致的空集合，旧会话保留为 cache_inherited，并禁用高风险动作。

同一来源同一会话出现多个候选记录时，先比较 confirmed 的最近活动时间；若最近活动时间缺失，则比较首次消息时间、文件修改时间和缓存解析时间；若时间戳出现未来值、异常倒退或时区不一致，则将该时间字段标记为 suspect_time，不作为唯一排序依据。重复 session_id 若来自不同工作目录或不同状态源且无法证明为同一会话，系统为其生成带状态源后缀的派生 session_key，并在诊断对象中记录冲突，避免错误合并不同项目的会话。

工作台展示层只消费统一会话对象、字段来源和能力状态，不直接理解各运行时的私有文件格式。只读列表可以展示 confirmed、derived 或 cache_inherited 字段，但排序优先采用 confirmed 的最近活动时间；转录查看仅在消息明细可解析、消息顺序可确定且角色字段可映射时暴露；若只能得到摘要、计数或 incomplete 会话，则保持为部分展示状态，不开放完整转录、继续会话或控制动作。

### 继续会话及控制能力的门控机制

继续会话属于会改变外部运行时状态的动作，本方案将能力验证流程与动作执行流程分离。能力验证只执行无副作用检查，包括命令或 API 入口是否存在、版本指纹是否匹配、会话 id 格式规则是否明确、参数转义规则是否存在、超时和输出读取规则是否完整以及操作者权限模型是否可映射；验证流程不得向运行时提交真实 prompt，也不得修改会话状态。只有这些检查均成功且 verified_at 未超过 TTL 时，continue 能力才标记为 available。

动作执行时，系统先校验 session_key、raw_session_id、prompt 长度、操作者权限、运行时来源和会话是否 incomplete；校验失败时不启动外部命令。通过校验后，执行器使用运行时画像中声明的参数数组或结构化 API 调用传递参数，避免将 prompt 拼接为未经转义的 shell 字符串；同一会话同一时刻仅允许一个 continue 执行，重复请求进入拒绝或排队状态。执行器在限定超时时间内收集 stdout、结构化输出文件或 API 响应，并将退出码、stderr、超时和空输出分别映射为受控错误码。

若 continue 执行超时，执行器按照运行时画像中的终止策略终止子进程或取消请求，并把执行状态标记为 timeout；若已产生部分输出且输出格式可验证，则返回部分输出并标记 partial_output，否则仅返回错误诊断。命令不存在、退出码表示参数错误、stderr 显示格式变化或输出解析失败时，continue 能力从 available 降级为 unknown 或 unavailable，并在下一次画像变更、版本变化、TTL 到期或用户手动重新验证时重新进入验证流程。

控制动作按照目标对象、预检查、执行后校验和失败处理四段定义。删除动作的目标对象为运行时明确支持删除的会话记录，预检查包括会话来源、幂等删除语义和备份或可恢复条件，执行后需确认该会话不再由状态源返回；暂停动作的目标对象为正在运行且可控的会话或进程，预检查包括活跃状态和进程归属，执行后需确认状态进入 paused 或等价状态；标签修改的目标对象为工作台内部标签时可直接回滚，为外部运行时标签时需确认写入接口和旧值；推理模式调整的目标对象为支持该参数的运行时会话，执行后需读取状态确认生效。任一动作若缺少幂等性、执行后校验或失败回滚策略，则对应 capability_status 保持 unavailable。

### 异常隔离与既有运行时兼容

为保证新增运行时不会破坏已有运行时管理流程，统一会话查询采用按运行时隔离的错误处理。每个运行时的检测、扫描、解析和映射在独立分支中完成，任一分支发生目录不可读、文件格式不匹配、数据库访问失败或命令超时，仅影响该运行时的会话集合和诊断状态；聚合接口继续返回其他运行时已经获得的会话结果，必要时将失败分支表示为空集合或降级状态。

诊断对象采用统一错误分类：NO_SESSIONS 表示状态源可读且确认无会话；PATH_MISSING 表示候选路径不存在；PERMISSION_DENIED 表示权限不足；FORMAT_UNMATCHED 表示文件或 schema 与解析器不匹配；DB_LOCKED 表示数据库被锁定且重试后仍不可读；SCAN_TIMEOUT 表示扫描超过时间上限；PARTIAL_PARSE 表示部分事件或字段解析失败；CAPABILITY_EXPIRED 表示能力验证超过有效期；ACTION_FAILED 表示外部动作执行失败。聚合接口将这些诊断附加在对应 source 下返回，其他 source 的会话数组不受影响。

扫描过程设置节流和资源边界，以降低本地状态源规模或损坏文件对工作台的影响。最近文件优先、单文件大小上限、最大扫描数量、扫描结果缓存和活跃窗口判定共同限制 I/O；局部解析失败保留已解析会话，异常空集合不覆盖未过期缓存，unknown 字段不覆盖 confirmed 字段。这样新增运行时的接入不会改变既有 Claude Code、Codex CLI、Hermes 或 OpenClaw 会话的排序、控制和继续会话边界。

通过上述机制，本方案在技术上形成“运行时画像加载—证据驱动探测—只读增量扫描—兼容解析—字段级合并—能力门控—异常诊断返回”的闭环。可靠性由按运行时隔离错误、只读访问、局部失败保留、缓存不被异常空结果覆盖和高风险动作门控共同产生；可扩展性由运行时画像、按版本指纹注册的解析器、统一会话对象和能力矩阵解耦产生；不破坏既有运行时管理流程则由独立适配分支、source 维度去重、动作通道隔离、未知能力不暴露按钮和异常分支不影响聚合接口共同保证。
