## 技术方案

### 总体构思与接入边界

本方案在现有智能工作台已经能够聚合 OpenClaw 网关会话、Claude Code 本地记录、Codex CLI 本地记录和 Hermes 本地记录的基础上，增加一层“本地运行时接入适配层”。该适配层不改变既有运行时的扫描、同步、控制和展示流程，而是把新的本地 agent runtime 作为一个并列的会话来源接入：每一类运行时均通过独立适配器输出统一的会话摘要、转录读取能力和可操作能力声明，聚合层只消费统一结果，不直接依赖某一运行时的私有目录或文件结构。

本方案中，“运行时种类”表示 agent 程序或 CLI 的类型，“来源标识”表示会话数据进入工作台的具体通道或适配器实例；同一运行时种类可以因当前目录、历史目录或用户配置目录不同而形成多个来源标识。本文中的“转录”指从本地事件流、JSONL 文件、数据库消息表或网关历史接口解析得到的 transcript 展示对象，其只读展示能力与继续会话、删除、标签设置等会产生副作用的操作能力相互独立确认。

针对新 runtime 的本地状态目录、会话文件格式和继续会话能力尚未完全确定的情况，本方案采用分阶段确认机制：先确认运行时存在性和版本指纹，再确认候选状态目录是否存在并可读，随后识别会话存储格式并抽取最小可用字段，最后再分别确认转录读取、继续会话、终端接入和控制类操作等能力。任一阶段未确认时，系统仍可保留已确认的只读会话元数据，但不得把未确认能力展示为可用操作。

接入后的数据流为：运行时探测器生成运行时状态和能力清单；会话扫描器以只读方式从候选本地状态源抽取会话摘要；标准化器把不同格式转换为统一会话对象；聚合器按来源和会话标识进行隔离去重、排序和限量返回；前端根据统一会话对象中的能力清单决定显示转录、继续会话、终端、删除或控制按钮。由此，新 runtime 的接入点被限制在新增适配器和能力声明中，避免影响既有 runtime 的管理链路。

### 统一数据模型与状态枚举

运行时描述符作为适配器的输入数据结构，至少包括：$runtimeId$，表示运行时种类；$displayName$，表示展示名称；$binaryCandidates$，表示可执行文件候选名及绝对路径候选；$pathCandidates$，表示状态目录候选集合，每个候选项包含路径、来源、优先级和是否允许递归；$detectors$，表示安装、认证、进程、格式和能力探测入口；$formatFamilies$，表示可识别的格式族及解析器版本；$capabilityRules$，表示各能力位的确认条件；$diagnosticPolicy$，表示错误分类、采样上限和是否可向前端暴露。除 $runtimeId$、$pathCandidates$、$detectors$ 和 $capabilityRules$ 外，其余字段可为空，但空值必须传递为未知状态而不是推断为可用。

运行时探测结果作为描述符的输出数据结构，包括 $runtimeStatus$、$versionFingerprint$、$formatFamily$、$confidence$、$missingItems$、$readability$、$capabilityMap$ 和 $diagnostics$。其中 $runtimeStatus$ 取值为未安装、已安装、已配置、状态源可读、可生成摘要、可读取转录、可执行副作用动作中的一个或多个阶段标记；$confidence$ 由格式评分归一化得到；$readability$ 表示候选状态源的读权限和锁状态；$capabilityMap$ 记录每个能力位的状态、关闭原因和最后确认时间。会话扫描器只消费达到“状态源可读”且格式置信度满足扫描条件的探测结果，前端只消费标准化后的能力状态。

能力位状态采用五态模型：$confirmed$ 表示确认条件满足且可展示或执行；$unconfirmed$ 表示缺少必要证据，默认隐藏操作入口；$unsupported$ 表示该格式族或版本明确不支持，前端不展示；$temporarilyUnavailable$ 表示能力原本支持但当前因进程未运行、文件锁、网络超时或认证过期而暂不可用，前端可显示禁用按钮和原因；$denied$ 表示用户权限或安全策略不允许，前端显示受限状态且后端拒绝执行。状态变化只能由探测器、能力确认器或副作用动作的执行前校验产生，不由会话摘要字段隐式推断。

统一会话对象包括 $sourceId$、$runtimeId$、$rawSessionId$、$stablePreferenceKey$、$projectPath$、$model$、$startedAt$、$lastActivityAt$、$userMessageCount$、$assistantMessageCount$、$toolCallCount$、$tokenSummary$、$activeState$、$transcriptState$、$capabilityMap$ 和 $diagnosticsRef$。$sourceId$ 用于跨运行时隔离，$runtimeId$ 用于展示运行时种类，$stablePreferenceKey$ 用于保存重命名、颜色等本地偏好，$diagnosticsRef$ 指向内部诊断对象而不覆盖可展示摘要。

诊断对象按发现、解析、标准化、转录、能力确认、缓存和副作用动作分类，记录错误码、候选路径、格式族、阶段、是否可重试和关闭原因。诊断不作为会话是否存在的唯一依据：当摘要已成功生成而转录读取失败时，会话摘要继续保留，$transcriptState$ 变为 $temporarilyUnavailable$ 或 $unconfirmed$；当摘要生成失败但候选状态源存在时，只记录诊断，不生成会话对象。

### 运行时描述符与能力探测

本方案为每一类本地运行时配置运行时描述符，描述符至少包括运行时标识、显示名称、可执行文件候选名、认证或配置检测规则、状态目录候选集合、会话格式探测器集合、支持的操作能力位以及能力确认条件。描述符中的状态目录不写死为单一路径，而是可以由环境变量、用户主目录下的约定路径、历史版本路径和用户配置路径共同组成候选集合，并为每个候选项记录来源和优先级。

描述符加载后先执行前置展开：解析环境变量、用户配置文件和主目录模板，得到绝对路径候选；对每个候选路径执行存在性、目录类型、读权限和是否符号链接越界检查；对候选命令解析为绝对命令路径并记录版本命令超时时间。候选路径优先级默认按用户显式配置、环境变量、当前版本约定目录、历史版本目录排列；优先级相同且均可读时，不立即互斥删除，而是进入同源合并流程。

运行时探测器按照“安装存在性、版本指纹、认证或配置状态、网关或后台进程状态、状态存储可读性”的顺序生成探测结果。版本指纹可以来自命令行版本输出、配置文件 schema 标记、数据库表结构、JSONL 事件类型集合或状态文件关键字段；当不同版本存在差异时，探测器不直接返回成功或失败二值结果，而是返回匹配的格式族、置信度和缺失项，使后续扫描器能够选择对应解析策略。

分阶段确认被实现为状态机：初始为 $unseen$；检测到命令或配置后进入 $installed$；认证文件、环境密钥或必要配置满足后进入 $configured$；至少一个候选状态源可读后进入 $stateReadable$；格式评分达到解析阈值后进入 $formatConfirmed$；成功生成至少一个摘要或确认空列表后进入 $summaryReady$；转录定位和消息边界确认后进入 $transcriptReady$；副作用命令、参数语义、会话 id 映射、权限和超时边界均通过后，相关能力进入 $actionReady$。任一阶段失败时保持上一稳定状态并记录缺失项；部分候选成功时只对成功来源继续推进。

能力位用于表达“能展示什么、能操作什么”，而不是由会话来源名称隐式推断。能力位可包括读取会话摘要、读取转录片段、继续会话、打开只读终端、发送网关消息、设置标签、删除会话、切换详细日志等。每一能力位均绑定必要确认条件，例如命令存在且参数语义已确认、会话标识可由本地记录稳定映射、状态库可只读打开、目标 API 返回可识别错误码、或权限角色满足要求。未满足确认条件的能力位默认关闭。

多个指纹来源不一致时，探测器按“明确 schema 标记、数据库表结构或 JSONL 事件集合、命令版本、路径约定、文件名模式”的优先级合成格式族。若最高优先级指纹与低优先级指纹冲突，以最高优先级确定候选格式族并降低置信度；若两个格式族评分差小于 10 分且均缺少最低必要项，则不选择解析器，仅记录候选诊断。该保守规则使未知版本不会被强行映射到已知格式。

### 只读扫描、格式识别与会话标准化

会话扫描器对新 runtime 的本地状态采用只读访问策略。对于文件型存储，扫描器只读取满足扩展名、文件大小、修改时间和目录深度约束的候选文件，并按最近修改时间限量处理；对于数据库型存储，扫描器使用只读连接并在表不存在、列缺失或锁冲突时返回空结果和诊断信息；对于网关或进程状态，扫描器先通过轻量状态检查确认进程存在，再读取有限范围的会话索引。该策略可避免因新 runtime 状态格式未知或正在运行而阻塞工作台。

只读扫描设置可执行边界：目录递归深度默认不超过 4 层，单次扫描候选文件默认不超过 120 个，单个文件超过 50MB 时跳过并记录诊断；数据库只读连接和轻量查询均设置秒级超时，发生锁冲突时按短退避重试不超过 2 次，仍失败则跳过该状态源；进程状态检查只读取 pid 文件或执行无副作用状态命令，超时即标记为 $temporarilyUnavailable$。单个运行时的扫描预算耗尽时返回已完成的部分结果，不等待全部候选源。

多个候选状态目录同时存在时，先按路径优先级分组，再在同一优先级内按目录指纹合并。目录指纹由规范化绝对路径、目录修改时间、会话索引文件修改时间和格式族组成。若当前版本目录和历史版本目录均包含同一原始会话标识，优先保留当前版本目录中最后活动时间更新且字段完整度更高的记录；若无法判定新旧或完整度接近，则保留一条摘要并在诊断中标记冲突来源，不把两条记录同时展示。

格式识别器不以单一字段作为判断依据，而是组合文件位置、文件名模式、记录分隔方式、首尾若干条记录中的事件类型、时间戳字段、角色字段、token 字段、工作目录字段和会话元信息字段形成格式评分。只有当评分达到预设阈值时，扫描器才把该候选源标记为可解析；评分不足但存在可疑记录时，仅输出“发现候选状态源”的诊断，不生成可展示会话，从而避免把其他工具的日志误识别为新 runtime 会话。

格式评分采用多特征加权规则，总分为 100 分：路径或目录约定 15 分，文件名或数据库名模式 10 分，记录分隔方式 10 分，事件类型集合 20 分，时间戳字段 10 分，角色或消息字段 15 分，会话元信息字段 15 分，token 或成本字段 5 分。原始会话标识、消息边界和时间排序字段属于最低必要项，缺少任一项时即使总分较高也不得生成会话摘要。评分达到 70 分且最低必要项齐全时进入解析；40 至 69 分仅记录发现诊断；低于 40 分忽略。

标准化器把不同版本的会话记录转换为统一会话对象。该对象至少包括来源标识、运行时种类、原始会话标识、稳定偏好键、项目或工作目录、模型、开始时间、最后活动时间、用户消息数、助手消息数、工具调用数、token 或成本摘要、活跃状态、转录可读性和能力位。对于缺失字段，标准化器保留空值或未知状态，不用推测值填充；对于时间戳异常，采用合理夹取或忽略策略，避免未来时间、时区偏移或损坏记录影响排序和活跃状态。

字段映射遵循确定来源优先规则：原始会话标识优先取显式 session id，其次取元信息 id，仍缺失时可由规范化文件路径和首条有效事件时间生成哈希，但该会话的继续和删除能力保持 $unconfirmed$；项目目录优先取 cwd 或 projectPath，缺失时允许为空；模型字段优先取会话级元信息，其次取最后一条助手事件；消息数和工具调用数从事件流逐条累计并对重复事件 id 去重；token 摘要只在字段语义明确时累计，否则置空并记录诊断。

异常字段按字段类型处理：开始时间和最后活动时间若落在当前时间之后的短容忍窗口内则夹取到当前时间，明显未来时间或无法解析时间则忽略该字段；时区缺失时按本地时区解析并记录诊断；损坏记录跳过但不中断文件解析；重复事件按事件 id、时间戳和内容哈希去重；无法解析的成本、token 或工具输入字段不参与累计。活跃状态不直接由运行时名称决定，而是由最后活动时间、是否存在未结束标记、网关或后台进程是否运行以及运行时描述符中的活跃窗口共同计算。

只读转录与继续会话能力之间保持隔离：转录能力只要求能够定位并解析历史事件，继续会话能力还必须确认恢复命令、恢复参数语义、会话 id 映射、当前认证状态和执行超时边界。因而，一个会话可以处于“摘要可见、转录可见、继续不可用”的中间状态，该状态不会阻止用户查看既有记录，也不会使系统执行未确认的恢复命令。

当新 runtime 支持转录读取时，转录解析器仅输出面向展示的片段结构，包括用户消息、助手消息、工具调用、工具结果和时间戳，并对单条消息、工具输入、工具结果和总返回数量设置上限。若只能确认会话摘要而无法确认完整消息格式，则该会话只进入摘要列表，不提供转录入口；若能够确认转录但不能确认继续命令，则仅提供只读 transcript 展示，不显示继续会话输入框。

转录读取以原始会话标识、转录文件或消息表位置、事件顺序字段和消息边界字段均已确认作为前置条件。解析时优先按事件时间排序，时间缺失或相同则按文件偏移或数据库自增顺序排序；分页参数包括起始游标和最大消息数，单页默认不超过 40 条、最多不超过 200 条；单条文本、工具输入和工具结果分别设置长度上限，超出时返回截断标记。损坏片段被跳过并记录诊断，不影响同一会话中其他片段展示。

### 聚合隔离、展示门控与降级处理

聚合层把新 runtime 输出的标准会话对象与既有 OpenClaw、Claude Code、Codex CLI 和 Hermes 会话对象合并，但去重键包含来源标识和原始会话标识，避免不同运行时产生相同会话 id 时互相覆盖。排序优先使用最后活动时间，并对返回数量设置上限；扫描结果可采用短时间缓存或节流同步，使大量本地记录不会阻塞工作台启动、面板切换或实时监控刷新。

同一来源内的重复会话按原始会话标识、规范化路径和首条事件时间进行归并，保留规则依次比较最后活动时间、文件或记录修改时间、格式评分、字段完整度和路径优先级；仍无法区分时保留最先解析成功的对象并记录诊断。不同来源之间即使原始会话标识相同也不互相覆盖，因为来源标识属于去重键的一部分。该规则同时解决历史目录迁移、同一会话被索引文件和转录文件重复发现、以及用户配置目录与默认目录并存的问题。

聚合缓存键由运行时标识、来源标识、候选目录指纹、格式族、能力位摘要和最近修改时间组成。缓存默认只在短时间窗口内复用；当目录修改时间变化、会话索引文件变化、能力位状态变化、用户手动刷新、描述符版本变化或副作用动作执行完成时立即失效。后台刷新失败时，接口可以返回带有 stale 标记的上一版只读摘要，同时把对应来源标记为刷新失败；若没有可用旧摘要，则仅返回其他来源的结果。

展示层依据 $capabilityMap$ 和权限角色进行门控。$confirmed$ 的只读能力显示入口并允许访问；$confirmed$ 的副作用能力在权限满足时显示可用按钮；$unconfirmed$ 和 $unsupported$ 默认隐藏操作入口；$temporarilyUnavailable$ 可显示禁用按钮和临时原因，便于用户刷新或启动运行时；$denied$ 显示受限提示但不暴露执行入口。若新 runtime 仅确认读取摘要能力，则工作台只展示会话卡片和基础元数据；若进一步确认读取转录能力，则允许打开转录面板；若确认继续会话能力，并且命令、参数、会话恢复语义和超时边界均已验证，则显示继续输入框。

降级处理遵循“局部失败、整体可用”的原则。新 runtime 的目录不存在、格式不匹配、数据库 schema 不兼容、单个文件过大、单条记录损坏、命令超时或权限不足时，适配器返回空会话、部分字段或受限能力，并附带内部诊断；聚合接口继续返回其他运行时会话，不抛出会破坏整个会话列表的异常。对于可能产生副作用的继续会话和控制类动作，系统在执行前再次校验会话 id、能力位和权限角色，执行失败时只返回该动作的错误，不修改已扫描的只读会话数据。

副作用动作执行前采用二次校验：继续会话需再次确认命令路径、版本指纹、恢复参数语义、原始会话 id 到运行时会话 id 的映射、操作者角色、认证状态、当前会话状态和执行超时；删除、标签、网关消息和模式切换等动作需再次确认对应能力位为 $confirmed$ 或当前可执行状态。任一校验失败时动作不得发起，返回关闭原因；动作执行失败时不修改只读扫描结果，最多使相关能力位短暂变为 $temporarilyUnavailable$ 并触发缓存失效。

通过上述机制，新 runtime 的接入可以在状态目录和格式尚未完全稳定时逐步启用：先以安全只读方式发现已有本地会话，再在格式置信度足够时展示摘要和转录，最后在恢复命令和交互语义确认后开放继续会话能力。该方案使工作台能够扩展新的本地 agent runtime，同时降低误识别、误操作和对既有运行时管理流程造成破坏的风险。

上述规则形成明确的因果链：多特征评分、解析阈值和发现阈值使低置信度状态源只产生诊断而不生成会话对象，从而降低误识别；能力位默认关闭、五态模型、权限门控和执行前二次校验使未确认或无权限的副作用动作无法展示或执行，从而降低误操作；来源标识、适配器独立输出和统一对象消费使新 runtime 异常局部化，不覆盖既有运行时链路；扫描数量上限、文件大小限制、只读连接超时、缓存节流和单 runtime 超时返回部分结果，使工作台启动和刷新不会被未知格式或锁冲突阻塞。
