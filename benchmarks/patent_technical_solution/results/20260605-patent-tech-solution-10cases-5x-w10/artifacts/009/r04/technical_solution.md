## 技术方案

本技术方案提出一种浏览器侧隔离执行生成代码并调度动态客户端工具的系统，包括：浏览器侧隔离沙箱、工具描述动态收集模块、受控调度协议、工具代理与分发层、以及执行保障机制。系统核心构思是：将模型生成代码的执行环境下沉至浏览器侧隔离沙箱（如 Web Worker），通过受控消息协议在沙箱与主页面之间完成工具调用分发；工具描述由主页面动态收集并注入沙箱类型声明，沙箱内的代码通过命名空间代理访问工具，实际执行始终发生在主页面侧，从而在不暴露浏览器私有能力、不污染主页面的前提下，实现模型生成代码对动态客户端工具的编排。

### 整体架构

系统由主页面、浏览器侧隔离沙箱、工具注册模块和调度协议层四部分组成。主页面负责注册浏览器侧工具（包括工具名称、参数 schema 和实际执行函数），并将工具描述注入模型上下文；模型根据工具描述生成编排代码；生成的代码在隔离沙箱中执行；沙箱中代码通过命名空间代理调用工具时，代理将调用请求序列化为协议消息，经受控通道发送至主页面；主页面侧的调度器解析消息、查找并执行对应工具，再将结果序列化后回传至沙箱。整个过程主页面仅暴露工具的输入输出契约，不暴露工具的实现细节或浏览器内部能力。

### 工具描述动态收集与类型生成

主页面在初始化阶段收集当前可用的客户端工具集合。每个工具包含三个要素：工具名称（原始名称，可包含连字符、点号等非标识符字符）、参数 schema（JSON Schema 或等效结构描述工具输入类型）和执行函数（在主页面上下文运行的实际实现）。系统将工具集合转化为类型声明块注入模型上下文中的系统提示，使模型在生成代码时获得完整的类型信息。类型声明将原始工具名称规范化为合法的 JavaScript 标识符：将连字符、点号及空格替换为下划线，去除其他非法字符，为数字开头的名称添加前缀，为 JavaScript 保留字名称添加后缀。例如工具名 'get-weather' 规范化为 'get_weather'，'3d-render' 规范化为 '_3d_render'，'delete' 规范化为 'delete_'。类型声明同时将参数 schema 转化为 TypeScript 风格的接口定义，声明为命名空间下可调用的异步函数签名，使模型能够以自然的方式编写编排代码而无需手动处理工具名的转义规则。

### 浏览器侧隔离沙箱

隔离沙箱是模型生成代码的实际运行环境。沙箱基于浏览器原生 Web Worker 机制构建，与主页面运行在不同的执行上下文，不共享全局作用域、DOM 访问权限或 JavaScript 对象引用。进入沙箱的代码先经过归一化处理：利用 AST 解析器（如 acorn）分析代码结构，自动剥离大模型常见的 markdown 代码围栏，将非箭头函数形式的代码（如命名函数声明、多语句程序块）统一包裹为标准异步箭头函数，确保执行接口一致。沙箱内不提供 DOM API、不注入主页面的全局变量，代码只能通过系统预设的命名空间代理与外部交互。沙箱内部署 console 拦截层，将 console.log、console.warn、console.error 的输出重定向到日志缓冲区，而非浏览器控制台，从而防止日志泄漏到主页面环境。

### 受控调度协议

沙箱与主页面之间的通信通过结构化消息协议进行，协议基于浏览器原生 postMessage 机制，不依赖网络请求或服务端中转。每次工具调用对应一组请求-响应消息对，消息包含以下字段：调用标识（唯一标识一次工具调用，用于请求-响应匹配）、命名空间（工具所属的命名空间，如 'codemode'、'state'）、工具名称（原始工具名或规范化后的工具名）、参数（JSON 序列化的工具输入参数）。主页面侧调度器收到请求后，先根据命名空间定位对应工具提供者，再以工具名称查找已注册工具；若工具不存在则返回结构化错误，包含错误码和错误描述。找到工具后，调度器在 try-catch 中调用工具执行函数，正常结果和异常均序列化为 JSON 回传。沙箱侧的代理层解析响应：若响应包含 error 字段则抛出异常，否则解包 result 字段返回给生成代码。

### 工具代理与分发层

沙箱内通过 JavaScript Proxy 对象为每个工具命名空间创建代理，拦截对命名空间下任意属性的访问。当生成代码调用如 codemode.getWeather({ city: 'Beijing' }) 时，Proxy 的 get 陷阱拦截属性访问，返回一个异步函数；该异步函数将工具名称和参数序列化为协议消息，通过 postMessage 发送至主页面。协议层支持两种参数传递模式：默认的对象参数模式（单对象参数，适用标准工具）和位置参数模式（参数展开为多参数，适用已有函数签名不统一的工具集）。主页面侧的调度器为每个命名空间维护一个工具注册表，键为规范化后的工具名，值为对应的执行函数。调度器通过 Workers RPC 或直接函数调用执行工具，执行结果同样经协议层回传。该架构确保工具实际执行始终在主页面受控上下文中，沙箱仅持有代理引用，无法绕过代理直接访问工具实现或浏览器能力。

### 执行保障机制

系统内置多层执行保障机制以确保隔离沙箱中代码的安全、可控运行。超时控制：沙箱侧通过 Promise.race 将用户代码执行与一个带 AbortController 的定时器竞争，若代码在配置的超时时间内（默认 30 秒，可配置）未完成，则抛出超时异常并终止执行，防止无限循环或长时间阻塞。非法工具调用处理：主页面调度器在接收到工具调用请求后，首先校验工具名称是否存在于当前命名空间的注册表中；对于不存在或未注册的工具调用，返回包含 'Tool not found' 错误的结构化响应，沙箱代理层将此错误转化为 JavaScript 异常抛出，使生成代码能够通过 try-catch 处理或自然向上传播。异常传播：工具执行函数中抛出的任何异常均由调度器捕获，提取异常消息后打包为 error 字段返回；沙箱代理层将 error 字段转为 Error 对象抛出，保留原始错误消息，不暴露调用栈等内部细节。日志收集：沙箱内重写的 console 方法将所有日志追加到内存中的日志数组，执行结束后日志数组随执行结果一并返回，系统可在结果中区分正常输出日志和异常日志，便于问题排查。资源释放：每次代码执行完成后，沙箱 Worker 实例被终止（terminate），释放其占用的内存和事件监听器；主页面侧的请求-响应映射表在收到响应或超时后清理对应条目，防止内存泄漏。此外，支持多命名空间工具提供者，每个命名空间独立校验和分发，命名空间名称须为合法 JavaScript 标识符且不可与保留名称冲突，进一步约束沙箱可访问的能力边界。
