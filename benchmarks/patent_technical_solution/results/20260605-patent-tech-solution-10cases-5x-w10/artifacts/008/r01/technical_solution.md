## 技术方案

本技术方案提出一种保留式流式子代理工具编排方法，用于在基于持久对象的智能体框架中实现主代理对多个子代理的受控调度、流式观察、持久化保留与可恢复访问。方案的核心构思是：子代理保持独立持久对象实例，拥有各自的存储、推理循环和可恢复流；主代理维护框架管理的运行注册表以追踪每次子代理调度的生命周期；通过定义统一的代理工具事件协议，将子代理执行过程中产生的聊天响应块以事件帧的形式转发至主代理的客户端连接；运行状态在子代理侧权威持久化，主代理侧通过注册表实现恢复协调。整体方案在保持子代理独立执行上下文的前提下，实现了跨主代理生命周期的流式事件保留与重建能力。

### 整体架构与核心构思

本方案的架构包含三类运行时实体：一个主代理（Parent Agent）、零个或多个子代理（Agent Tool Sub-Agent）、以及连接到主代理的一个或多个客户端。主代理是客户端唯一直接连接的对象，通过 WebSocket 或 HTTP 与客户端维持双向通信。子代理是主代理通过框架提供的子代理创建原语（subAgent）按需派生的子持久对象实例，每个子代理拥有独立的 SQLite 存储、大语言模型推理循环和可恢复流（ResumableStream）。

核心构思是将子代理的执行与观察分离：子代理的执行是持久化工作，由运行标识符（runId）唯一标识；事件转发到主代理的客户端是观察者的行为，断开观察者流不应自动取消执行。子代理的聊天响应块（UIMessageChunk）在其自身存储中持久化，主代理通过运行注册表追踪每次调度的元数据，使得页面刷新或网络断开后客户端重新连接时，能够从子代理存储中回放已产生的事件。

### 主代理侧的运行注册表

主代理在其 SQLite 存储中维护一个框架管理的代理工具运行注册表（cf_agent_tool_runs），用于记录每次子代理调度的元数据。该表以运行标识符 runId 作为主键，包含以下关键字段：父工具调用标识符（parentToolCallId），用于将该运行关联到主代理大语言模型推理循环中的特定工具调用；代理类型（agentType），记录子代理的类名；输入预览（inputPreview），存储安全的输入摘要而非完整原始输入；运行状态（status）；结果摘要（summary）；错误信息（errorMessage）；以及时间戳（startedAt / completedAt）。

运行注册表的关键设计原则是：框架负责注册表的机制（插入行、更新状态、协调恢复），应用负责注册表的策略（保留规则、垃圾回收、访问控制逻辑、显示元数据）。输入数据默认仅存储安全预览而非完整原始输入，避免将敏感数据（提示词、凭证、文件内容）存入编排表。该表与已有的子代理注册表分离：子代理注册表回答“此持久对象实例是否存在”，运行注册表回答“哪个父操作创建了此运行、其事件应在哪里呈现、重放时应合成什么状态”。注册表位于主代理存储中，因为重放是按主代理维度组织的——只有主代理知道哪个父工具调用触发了子运行、兄弟运行的呈现顺序以及重连后应合成的生命周期事件。

### 子代理侧的执行映射

子代理侧维护内部的运行映射表（cf_agent_tool_child_runs），用于将编排层的 runId 映射到子代理内部的聊天轮次标识符（requestId）和可恢复流标识符（streamId）。这种分离设计的关键理由是：runId 是面向编排和产品的标识符，requestId 是聊天轮次和取消注册表的标识符，streamId 是可恢复流的持久化标识符。将三者分离避免了“一次代理工具运行等于一次聊天轮次”的假设固化，为未来支持单次逻辑运行包含多个聊天轮次（多轮子代理）预留了演进空间。

子代理侧的映射必须是恢复的权威来源。如果主代理在子代理启动后、存储生成的标识符之前崩溃，主代理必须能通过 runId 向子代理查询恢复 requestId 和 streamId。启动操作按 runId 幂等：如果子代理已存在该 runId 的运行记录，则返回已有运行状态而不创建重复的聊天轮次。子代理适配器提供的核心接口包括：startAgentToolRun（按 runId 幂等启动运行）、cancelAgentToolRun（取消运行）、inspectAgentToolRun（查询运行状态和内部映射）和 getAgentToolChunks（按序列号获取已持久化的聊天响应块）。

### 代理工具事件协议与流式转发

本方案定义一套统一的代理工具事件协议，主代理通过该协议将子代理的执行过程转发至其客户端。事件类型分为生命周期事件和流式事件两类。生命周期事件包括：started（运行已创建并开始执行，携带 runId、代理类型、输入预览和显示顺序）、finished（运行正常完成，携带结果摘要）、error（运行因错误失败，携带错误信息）、aborted（运行被显式取消）、interrupted（运行因主代理恢复限制被标记为中断，仅由主代理在协调时产生）。流式事件为 chunk 类型，携带 JSON 编码的 UIMessageChunk 不透明体。

chunk事件的body字段采用JSON编码的UIMessageChunk不透明体，框架不为此发明第二套文本、推理、工具调用等词汇表。客户端可使用与主聊天响应相同的applyChunkToParts原语重建子代理的消息部件。每个事件帧包含序列号（sequence）、父工具调用标识符（parentToolCallId）和可选的重放标记（replay）。序列号在每个代理工具运行内单调递增，由主代理加盖。

流式转发的实现机制为：子代理在运行其推理循环时，通过重写广播方法将自身产生的聊天响应块同时写入一个RPC可读流（ReadableStream）。主代理通过持久对象RPC读取该流，将每个块包装为代理工具事件帧，通过WebSocket广播给其所有已连接客户端。这种设计的优势在于：子代理的聊天响应块在其自身存储中权威持久化（通过其自有的可恢复流），主代理仅负责转发而不保存副本；客户端去重键为（parentToolCallId, runId, sequence），正确支持同一父工具调用下并行子代理的独立序列。

### 运行状态生命周期与恢复协调

每次代理工具运行经历确定的状态生命周期。运行标识符 runId 携带一个逻辑状态，不同层次以不同方式观察该状态。框架维护的状态表保持真实。

| 状态 | 是否终态 | 可观察位置 | 含义 |
| --- | --- | --- | --- |
| starting | 否 | 主代理注册表、子适配器检查 | 行已插入，子代理尚未确认运行 |
| running | 否 | 主代理注册表、子适配器检查 | 子代理已启动聊天轮次 |
| completed | 是 | 主代理注册表、子适配器检查、观察者状态、runAgentTool返回值 | 子代理到达正常终止状态 |
| error | 是 | 主代理注册表、子适配器检查、观察者状态、runAgentTool返回值 | 子代理抛出异常、流错误或结果合成失败 |
| aborted | 是 | 主代理注册表、子适配器检查、观察者状态、runAgentTool返回值 | 运行被父代理取消信号显式取消 |
| interrupted | 是 | 主代理注册表、观察者状态、runAgentTool返回值 | 主代理协调了无法安全恢复的非终态运行 |

interrupted 状态是仅主代理侧的概念——子代理不声明自身为 interrupted，只有失去观察者或无法继续实时跟踪的主代理才能记录此判定。一旦运行在主代理注册表中到达终态，该状态即为权威：延迟的取消不得将 completed/error 覆写为 aborted，延迟的协调不得将 aborted 覆写为 interrupted。

当主代理因崩溃或被驱逐后重新启动时，执行恢复协调流程：遍历注册表中所有 starting 和 running 行。若无匹配的子代理或子运行记录，说明子代理从未启动或已被删除，标记为 interrupted。若子代理报告 completed，从子代理存储中回放已持久化的聊天响应块，读取最终输出，将主代理行标记为 completed。若子代理报告 running 而当前运行时不支持延迟实时重连，回放已存储块后标记为 interrupted。该设计保证了即使主代理观察者消失，子代理执行本身仍可以独立完成并保留结果以供后续检查。

### 取消传播机制

取消操作遵循从主代理到子代理的传播链。取消传播路径为：主代理的聊天轮次或工具调用被取消；取消信号通过 AbortSignal 传递给 runAgentTool；runAgentTool 按 runId 显式取消子代理运行；子代理取消其本轮次的 AbortController；子代理将该信号传入其推理循环（saveMessages({ signal })）；主代理分离该运行的任何实时观察者流；子代理终止推理循环并报告 aborted 结果。

关键设计区分：取消观察者流本身不构成取消运行的请求。浏览器断开连接、主代理重启或重放连接失败应仅分离观察。只有来自主代理活跃操作的显式取消信号才能终止执行。取消操作按 runId 幂等：若子代理已到达 completed 或 error 终态，延迟的取消不得将其覆写为 aborted。清理保留的历史记录时，若运行处于 starting 或 running 状态，应先取消运行再删除注册表行和子代理实例，避免留下无观察者且结果无法呈现的孤立大语言模型工作。

### 并发控制与幂等执行

主代理可同时调度多个子代理，支持同一父工具调用下的并行扇出模式：主代理大语言模型可在一次推理中调用多个代理工具，每个工具调用触发独立的子代理运行，各子代理在自己的持久对象实例中并行执行推理。主代理使用 Promise.allSettled 收集各分支结果，确保单个分支失败不影响其他分支的独立完成。客户端通过 parentToolCallId 和 displayOrder 将多个子代理运行关联到同一工具调用部件下并按指定顺序渲染。

为控制大语言模型调用成本，框架提供粗粒度的并发守卫：通过 maxConcurrentAgentTools 配置项限制当前正在运行的代理工具数量，超限时快速失败并发出明确的 error 事件。细粒度的配额、基于令牌的预算和计费集成可通过生命周期钩子（onAgentToolStart、onAgentToolFinish）在后续层次添加。

runAgentTool 按 runId 实现幂等执行。若调用者传入已存在的 runId：终态运行直接返回已有结果而不重新执行；非终态运行不启动重复工作——若调用者非原始实时观察者，回放已存储块并根据运行时能力返回当前状态或 interrupted。这使得 runAgentTool 可安全地从重试路径、定时告警和重连恢复中调用，而不会意外重复大语言模型工作。同时，框架在子代理实例上维护并发运行的排他声明：当框架驱动的代理工具轮次在子代理上运行时，对同一实例的并发 runAgentTool 调用返回已有检查结果而非启动第二轮次。

### 访问控制与钻入查看

子代理通过已有的子代理路由原语保持外部可寻址，钻入查看的 URL 形状为嵌套路径：/agents/{父代理类}/{父代理名}/sub/{子代理类}/{runId}。框架的代理工具机制应安装严格的 onBeforeSubAgent 门控：对 (agentType, runId) 的请求仅当主代理注册表中存在匹配的运行记录时才到达子代理，防止通过 URL 猜测任意 runId 生成新的持久对象实例。应用可自定义门控策略，但生产环境的默认行为不应允许未注册的 runId 生成新实例。

runId 本身不是能力凭证。钻入查看的 URL 始终通过主代理的已有身份（useAgent({ agent: parent, name: userId, sub: [...] })）到达，使得认证和租户隔离来自主代理。钻入查看的观察者可以自由读取子代理的聊天内容；但在框架驱动的代理工具轮次运行期间，钻入查看用户发送聊天消息应被推迟或拒绝，而非与进行中的轮次静默交错。具体策略由聊天基类负责，但框架至少应保证不破坏进行中的轮次。子代理可嵌套调用自身的子代理——底层通过持久对象面片（facet）的递归嵌套支持任意深度的代理树，但观察不默认向上桥接，嵌套运行仅对其直接父代理的客户端可见。

### 保留与清理策略

代理工具运行在完成后默认保留。默认生命周期为：runAgentTool 创建新的运行标识符（除非调用者主动提供）；框架在启动子代理前插入主代理侧注册表行；子代理实例在完成后保留；注册表行在完成后保留；清理历史记录、账户或工作区删除、或应用特定的清理操作显式删除保留的运行及对应的子代理实例。不默认在完成后自动删除的原因在于：完成后正是运行检查最有价值的时刻——刷新重放、钻入查看、失败运行调试和审计追踪都依赖于保留子代理实例及其注册表行。

本方案提供显式的清理接口 clearAgentToolRuns，支持按条件批量删除：按时间窗口（如删除7天前的运行）、按运行状态（如仅删除 completed 和 error 的运行）。该接口应同时删除主代理注册表行和对应的子代理持久对象实例——仅删除注册表行会留下无法通过重放或钻入访问的孤立子代理副本。自动的基于时间的存活期管理、基于数量的垃圾回收和单次运行的即时清理属于策略层面，可在框架提供可靠清理原语后由应用按自身生命周期调用。

### 编程接口设计

本方案提供两种对外的编程接口，共享同一底层机制。第一种是命令式接口 runAgentTool(Cls, { input, parentToolCallId, displayOrder, signal })，适用于确定性工作流、后台任务、非大语言模型编排以及需要 Promise.allSettled 的扇出/扇入场景。该接口返回 runId、执行状态、结果摘要和可选的结构化输出。第二种是工具工厂 agentTool(Cls, { description, inputSchema, outputSchema })，适用于大语言模型自主选择调度子代理的常见场景。工具工厂生成标准的 AI SDK 工具条目，内部调用 runAgentTool，并将子代理的结构化输出或文本摘要返回给主代理的大语言模型。

agentTool 返回给主代理大语言模型的结果取决于运行终态：completed 返回结构化输出（当设置了 outputSchema 时）或文本摘要；error 返回结构化失败信息 { ok: false, error } 使大语言模型可决定重试还是向用户呈现失败；aborted 返回取消信息；interrupted 返回无恢复输出的说明，防止大语言模型在缺失数据上虚构成功摘要。该设计确保大语言模型从不为非 completed 运行看到静默空结果。
