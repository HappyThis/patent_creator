## 技术方案

本方案提出一种面向共享知识管理系统的双层存储架构，将项目知识文件的静态内容与运行时动态信号进行物理分离存储，在读取时实现信号融合，并在文件清理时保证跨层一致性，从根本上解决高频运行时信号反复改写共享知识文件导致的版本控制污染问题。

### 1. 双层存储架构

系统将知识存储划分为两个物理上独立的层次：共享知识层和本机信号层。

共享知识层（Shared Knowledge Layer）：存储项目知识的结构化文件，采用人类可读、版本控制友好的标记文本格式（如 Markdown），存放于版本控制管理的目录中。共享知识层文件仅包含知识内容本身，包括标题、关键词、标签、正文摘要、正文内容、与其他知识文件的关系引用等。该层文件是版本控制的最小变更单元，可进行分支、合并、推送和拉取操作。

本机信号层（Local Signal Layer）：存储与知识文件一一对应的运行时动态信号数据，存放于版本控制忽略的本机专用目录中。动态信号包括但不限于：累计访问次数（accessCount）、检索命中后更新的重要度分值（importance）、基于时间的活跃度衰减值（recency）、成熟度分级（maturity，如草稿draft / 已验证validated / 核心core）、内容更新次数（updateCount）、最近更新时间戳、最近访问时间戳等。动态信号以每个知识文件为粒度独立存储，存储格式可以是结构化数据文件（如 JSON、YAML）、键值对数据库或嵌入式索引格式。

两层之间通过知识文件的相对路径建立关联映射。对于共享知识层中的每个知识文件（如 "auth/jwt-configuration.md"），本机信号层中对应存在一个信号记录（如 "auth/jwt-configuration.signal.json"），以相同的相对路径结构组织。新增知识文件时，系统在本机信号层自动创建对应的初始信号记录（默认重要性分值、默认成熟度草稿、访问次数为 0、活跃度为 1.0）。删除知识文件时，系统同步清理对应的本机信号记录。

### 2. 读取融合机制

在检索、排序、浏览和推荐知识文件时，系统执行读取融合流程，将共享知识层的文本内容与本机信号层的动态信号合并计算，产生融合后的检索结果或排序列表。读取融合是读时计算模式，不产生任何写回操作，因此不会修改共享知识层文件。

具体融合流程如下：（1）从共享知识层构建文本检索索引（如 BM25 倒排索引），索引内容仅来源于共享知识层的正文文本、标题、关键词和摘要，不包含动态信号。索引随共享知识层文件变更（新增、修改、删除）重建或增量更新。（2）接收查询请求后，在文本检索索引上执行关键词检索，得到候选文件集及各自的文本相关性得分（如归一化 BM25 分数）。（3）对每个候选文件，从本机信号层获取对应的动态信号，包括重要度分值、活跃度值、成熟度分级、访问次数等。（4）计算融合得分。融合得分由文本相关性分量、重要度分量和活跃度分量加权合成，并可进一步乘以成熟度分级系数。示例公式为：finalScore = (w1 × 文本相关性 + w2 × 归一化重要度 + w3 × 活跃度) × 成熟度系数。其中重要度先归一化至 [0,1] 区间，成熟度系数为核心类知识给予放大（如 1.15）、草稿类知识给予衰减（如 0.85）。（5）按融合得分降序排列，截取前 N 条结果返回。

在读取融合过程中，活跃度值（recency）基于信号记录中的最近访问或更新时间戳与当前时间的差值，按指数衰减函数实时计算，例如 recency = exp(-daysSince / decayFactor)。衰减计算在读取时执行，不需要预先写回本机信号层。重要度分值在读取融合时取信号层中已存储的最新值，该值仅由写入操作更新（见第3节）。这种读时衰减的策略确保活跃度信息始终反映最新时间状态，同时避免了周期性写回带来的 I/O 抖动。

### 3. 写入路由与信号更新

系统根据操作类型将写入请求路由至不同的存储层：知识内容变更（新增、修改、合并、删除知识文件）路由至共享知识层并纳入版本控制；运行时动态信号变更仅路由至本机信号层，不触及共享知识层文件。

触发本机信号更新的典型场景包括：（1）检索访问：当某个知识文件出现在检索结果中时，系统在本机信号层中递增该文件的访问次数计数器，并按固定增量（如 +3）提升其重要度分值。为减少高频写入，可采用批量累积策略——将多次访问计数暂存于内存缓冲区，在检索索引重建前或按固定时间间隔（如 5 秒）批量刷新至本机信号层。（2）知识内容更新（curate 操作）：当用户或代理对某知识文件执行内容更新时，系统在本机信号层重置该文件的活跃度值为 1.0（表示最近被关注），按较大增量（如 +5）提升重要度分值，递增更新次数计数器，并记录更新时间戳。（3）后台整理（dream/consolidate 操作）：当两个知识文件被合并时，系统在本机信号层对合并后的目标文件取两个源文件中重要度和活跃度的最大值，将访问次数和更新次数分别求和，并取较高成熟度级别。

成熟度分级的动态升降级也在本机信号层完成，不修改共享知识层文件。成熟度采用滞后阈值（hysteresis）机制防止在阈值边界频繁振荡：当重要度分值达到升级阈值（如 65）时，草稿可升级为已验证；达到更高阈值（如 85）时，已验证可升级为核心；降级阈值低于升级阈值（如核心降到 60 以下降为已验证、已验证降到 35 以下降为草稿）。重要度分值自身的衰减（长时间未被访问或更新时，按日衰减因子如 0.995 每日递减）在每次读取融合时按时间差实时计算并更新至本机信号层。这种滞后升降级机制保证了成熟度信号的稳定性。

### 4. 清理一致性保障

当共享知识层中的知识文件被删除、归档、合并或重命名时，系统必须同步维护本机信号层的一致性，防止出现悬空信号记录或信号丢失。

清理一致性机制包括以下策略：（1）删除同步：当共享知识层的知识文件被删除时，系统同步删除本机信号层中对应的信号记录。该操作在删除知识文件的同一事务或操作流程中执行，采用先删除信号记录、再删除知识文件的顺序，或将两者作为批处理在文件系统层面保证原子性（如在同一目录下操作、利用文件系统的原子重命名等）。（2）归档处理：当知识文件因成熟度下降（如重要度低于归档阈值）或时间过期被归档时，原知识文件从共享知识层移至归档目录，系统在归档目录中保留一个轻量存根文件（stub），存根文件仅包含指向完整归档内容的引用路径和归档原因标记，不含原知识正文。此时本机信号层中的信号记录保留但不随归档存根进入版本控制——归档存根本身也被排除在同步范围之外。（3）孤儿信号清理：系统定期或在检索索引重建时扫描本机信号层，对已无对应共享知识层文件的孤儿信号记录执行清理。（4）重命名处理：当知识文件被重命名时，系统在本机信号层中将原路径的信号记录迁移至新路径。

### 5. 版本控制分离策略

双层存储架构的核心工程收益之一是将版本控制系统（如 Git）的追踪范围限定在共享知识层，本机信号层完全不进入版本控制，从而彻底消除运行时信号更新导致的版本控制状态脏化。

具体分离策略包括：（1）目录级忽略：本机信号层存放于项目根目录下的专用隐藏目录中（如 .signals/ 或 .brv/signals/），该目录通过版本控制忽略规则（如 .gitignore）整体排除，确保所有信号文件的创建、更新、删除操作均不产生版本控制差异。（2）衍生产物排除：除信号文件外，由系统自动生成的衍生文件（如全文检索索引 _index.md、目录清单 _manifest.json、自动摘要 .abstract.md、目录概览 .overview.md 等）也存放于版本控制忽略目录或标记为排除路径，不在版本同步（sync）范围内，避免索引碎片和摘要更新污染提交历史。（3）同步快照过滤：当系统执行跨机同步或快照操作时，同步模块在收集文件变更列表时主动过滤本机信号目录和衍生产物路径，确保推送、拉取和合并操作仅涉及共享知识层的知识内容文件。（4）知识内容文件保持纯净：共享知识层中的 Markdown 文件不内嵌任何运行时信号字段（如 YAML frontmatter 中的 accessCount、importance、recency 等），其文件内容仅包含标题、标签、正文和知识间引用关系，保证每次版本控制提交仅反映知识内容的实际变更。

### 6. 多机协同场景下的信号隔离

在团队协作环境中，多个开发者或代理各自在本地机器上运行知识管理系统实例，共享同一套知识文件仓库。双层存储架构在多机场景下天然实现了信号数据的物理隔离，无需额外的分布式协调机制。

工作机制如下：（1）每台机器独立维护各自的本机信号层，信号数据不出现在版本控制中，不会被推送至共享仓库。当开发者 A 频繁检索某知识文件时，其重要性分值仅在 A 的本地信号层中提升，不会影响开发者 B 的本地信号层或共享知识层。（2）共享知识层通过版本控制进行协作：开发者对知识内容的增删改通过常规 Git 工作流（commit/push/pull/merge）在团队间传播。当开发者 A 拉取开发者 B 新增的知识文件后，A 的本机信号层自动检测到新的共享知识层文件，为其创建初始信号记录（默认重要度、草稿成熟度、零访问计数）。（3）不同机器的信号差异化是设计目标而非缺陷：信号层反映的是各机器上的本地使用模式和历史，不同机器因关注领域不同会自然形成不同的重要性排序和成熟度分级。例如安全工程师机器上的安全相关文件信号分值较高，而前端工程师机器上的 UI 组件文件信号分值较高，这使得每台机器上的检索排序更贴合本地使用上下文。（4）合并冲突仅发生在共享知识层：由于本机信号层不参与版本控制，合并操作仅涉及知识内容文件，不会因信号字段的并发修改产生误合并或冲突标记。
