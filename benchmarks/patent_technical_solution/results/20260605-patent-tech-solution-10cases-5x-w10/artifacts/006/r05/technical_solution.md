## 技术方案

本技术方案提出一种面向共享知识文件与运行时动态信号的分层存储与读取融合方法，解决知识管理系统中高频变化的运行时信号反复改写版本控制下的共享知识文件所导致的版本库污染、合并冲突增多及真正知识变更被噪声淹没的问题。方案的核心构思是：将知识内容的静态载体与运行时动态信号在物理存储上分离为两个独立层次，在读取路径上通过融合引擎将两者实时合并以支撑检索、排序与生命周期管理，并通过信号清理机制维持两层之间的一致性。

### 分层存储架构

系统将知识数据在存储层面划分为两个物理独立的层次：共享知识文件层和本机运行时信号层。

共享知识文件层（Shared Knowledge File Layer）：以 Markdown 文件为载体，存放于版本控制系统（如 Git）跟踪的目录树下。每个文件包含知识条目的标题、标签、关键词、关联关系、叙述性正文、事实列表等稳定的、由人工或智能体主动编辑产生的知识内容。该层文件作为团队共享、审阅和版本控制的基本单元，参与分支、提交、合并、推送和拉取等版本控制操作。该层文件的前置元数据（YAML frontmatter）中不再包含访问次数、检索命中计数、排序权重、成熟度等级、近因分数等运行时动态信号字段。

本机运行时信号层（Local Runtime Signal Layer）：以独立于版本控制目录的本地存储结构存放每台机器上产生的运行时动态信号。该信号层的存储路径被排除在版本控制跟踪范围之外（例如通过 .gitignore 或存放于版本控制根目录之外），确保信号数据的变更不会导致版本控制工作区变脏。信号层以知识文件的相对路径为主键，记录访问计数、最后访问时间戳、重要性分数、近因分数、成熟度等级、更新计数、最近更新时间戳及复合排序权重等字段。信号数据的更新采用先写内存缓存、再批量刷盘的方式，避免每次检索访问均产生磁盘 I/O。

### 读取融合引擎

读取融合引擎在检索、查询和排序路径上透明地合并两个存储层的数据，对外呈现统一的知识条目视图。

索引构建阶段：搜索引擎（如 BM25 全文检索引擎）仅扫描共享知识文件层的内容（标题、正文、标签、关键词等文本字段），构建纯文本倒排索引。索引构建过程不依赖信号层数据，也不触发信号层的写入操作。索引缓存的失效判断仅基于知识文件层的文件修改时间、文件大小或内容哈希指纹，信号层数据的变更不影响索引缓存有效性。

检索与排序阶段：当用户发起检索请求时，检索流程分三步执行：（1）在纯文本倒排索引上执行 BM25 文本匹配，获得每个匹配文件的基础文本相关性分数；（2）以每个匹配文件的相对路径为键，从本机运行时信号层读取该文件当前的重要性分数、近因分数和成熟度等级；（3）通过复合评分函数将文本相关性分数与运行时信号加权融合，得到最终排序分数。复合评分函数可表示为：最终分数 = f(BM25归一化分数, 重要性分数, 近因分数) × 成熟度层级系数。其中 BM25 归一化分数的权重、重要性分数的权重和近因分数的权重为可配置参数，成熟度层级系数对不同成熟度等级（如草稿、已验证、核心）赋予不同的排序加成。

访问反馈：检索完成后，对于被命中并返回给用户的匹配文件路径，读取融合引擎将对应的访问计数增量暂存于内存中的访问计数器映射表（path → 累积命中次数）。该计数器在后续的索引重建触发点或定时刷盘周期中，批量写入本机运行时信号层，一次性更新对应信号记录中的访问计数和重要性分数。一次检索操作即使命中多个文件，也只在内存中累积计数值，不触发对任何文件的写入，从而不会导致版本控制工作区出现变更。

### 信号清理与一致性维护

由于共享知识文件层受版本控制操作（拉取、合并、推送等）影响，文件可能被远程协作者新增、重命名、移动或删除，导致本机运行时信号层中出现孤立记录（即信号记录对应的知识文件已不存在）。系统通过以下机制维持两层之间的一致性：

孤儿检测：在每次索引重建或信号层批量刷盘时，系统遍历信号层中的所有记录，逐一检查对应共享知识文件层的文件是否仍存在。对于文件已不存在的记录，标记为“待清理”状态。检测操作可与索引构建中的文件扫描步骤合并执行，避免额外的目录遍历开销。

惰性清理策略：对于标记为待清理的孤儿信号记录，系统采用惰性清理而非立即删除。具体地，系统保留孤儿记录一段可配置的宽限期（例如 7 天），并在宽限期内如果对应知识文件因版本控制回退或分支切换而重新出现，则自动恢复该信号记录的有效状态并从待清理列表中移除。超过宽限期仍未恢复的记录，在下次清理周期中从信号层物理删除。该策略可防止因分支切换或临时合并冲突解析导致的信号数据丢失。

重命名追踪：当版本控制合并操作导致知识文件被重命名时，系统通过比对合并前后的快照差异，识别文件路径变更。对于检测到的重命名操作（旧路径→新路径），信号层执行对应的记录迁移：将旧路径下的信号数据复制到新路径，并标记旧路径记录为待清理。如果合并操作无法自动判定重命名关系（如同时存在删除和新增但不确定是否同一文件），则将新旧路径的信号记录均保留，交由后续孤儿检测和宽限期机制自然收敛。

### 信号驱动的生命周期管理

本机运行时信号层不仅要记录信号，还需要基于信号驱动知识条目的生命周期管理，包括成熟度升降级、重要性衰减和自动归档候选识别。这些操作同样在信号层内部完成，不修改共享知识文件。

重要性衰减：系统以知识文件的最近一次内容更新时间为基准，计算距离当前时间的天数。重要性分数按指数衰减模型自动递减：衰减后的重要性 = 当前重要性 × (衰减因子)^天数。近因分数按类似的指数衰减计算。衰减计算在信号读取时实时执行，信号层中持久化的衰减相关字段仅在索引重建或批量刷盘时更新为衰减后的值。

成熟度升降级：系统基于衰减后的重要性分数，采用带迟滞阈值的状态机判定成熟度等级。例如：重要性 ≥ 65 时从草案晋升为已验证，重要性 ≥ 85 时晋升为核心；反方向，重要性 < 35 时从已验证降级为草案，重要性 < 60 时从核心降级为已验证。迟滞区间可防止信号在阈值附近波动导致的频繁升降级。

自动归档候选生成：对于成熟度为草案且重要性低于预设阈值的知识条目，或超过预设天数未被访问的知识条目，系统将其路径记录在信号层中的候选清理列表中。自动清理操作（如 Dream 系统的 Prune 操作）读取该候选列表作为输入，但实际的知识文件归档（将文件移入归档目录并生成桩文件）仍在共享知识文件层执行，因为这些操作属于知识内容本身的变更，应纳入版本控制。

### 信号存储实现方式

本机运行时信号层的具体存储实现可采用以下方式之一或其组合，核心要求是该存储位置不被版本控制系统跟踪。

方式一——独立 JSON 信号文件：在项目根目录的版本控制忽略路径下（例如 .brv/signals/ 目录），为每个知识文件维护一个对应的 JSON 信号记录文件，或使用单一聚合 JSON 文件以路径为键存储所有信号。每次批量刷盘时重写聚合文件。该方式实现简单，便于调试和跨进程共享。

方式二——嵌入式键值数据库：使用轻量级嵌入式数据库（如 LevelDB 或 SQLite）存放信号记录，以知识文件路径为键，信号数据为值。数据库文件存放于版本控制忽略路径下。该方式支持高效的随机读写和范围查询，适合信号记录数量较大的场景。

方式三——操作系统级扩展属性：在支持扩展属性（xattr）的文件系统上，将信号数据存储为对应知识文件的扩展属性。这种方式天然实现了路径绑定，文件被删除或重命名时扩展属性随文件一同消失，从而消除了孤儿信号记录的问题。但该方式受限于文件系统支持和跨平台兼容性，可作为可选优化。

### 整体数据流与系统交互

以下描述一次完整的知识检索与信号更新流程，说明各组件如何协同工作：

（1）用户或智能体发起检索请求，指定查询文本和可选过滤条件（如范围路径、成熟度下限）。

（2）检索入口检查纯文本倒排索引缓存是否有效（基于共享知识文件层的文件变更指纹判断）。若缓存失效，触发索引重建：扫描共享知识文件层目录树，读取全部非衍生知识文件（排除 _index.md、_manifest.json、归档桩文件等系统生成文件）的标题和正文，构建 BM25 索引；重建过程中同时将内存中的累积访问计数刷入信号层。

（3）在有效索引上执行 BM25 文本匹配，获取候选文件路径及其原始文本相关性分数。

（4）对于每个候选文件路径，从信号层读取对应的运行时信号（重要性、近因、成熟度），计算复合排序分数并排序。

（5）将最终排序结果中的匹配文件路径累积到内存访问计数器映射表中（每个路径的命中计数加一）。

（6）返回排序后的检索结果给调用方。整个流程中，共享知识文件层未被写入任何数据，版本控制工作区保持清洁状态。

（7）当共享知识文件层的内容因人工编辑、智能体更新或版本控制拉取合并而发生变更时，快照服务检测到文件变更，触发索引缓存失效标记，下一次检索时自动重建索引。同时，信号层的孤儿检测和重命名追踪在此重建周期中执行。

### 技术效果与可选扩展

上述技术方案通过将运行时动态信号与共享知识文件物理分离，带来了以下技术效果：（1）版本控制工作区清洁——检索、排序、信号衰减等高频操作不再产生文件系统写入，Git 工作区不会因系统自动运行而出现意外变更，团队成员的合并冲突显著减少；（2）知识变更可辨识——版本控制历史中的每次文件修改均对应真实的知识内容变更（人工编辑、智能体更新、合并引入的新内容），评分字段的噪声被消除；（3）检索排序质量不降低——运行时信号数据仍在读取路径中通过融合引擎完整参与复合排序，检索效果保持不变；（4）信号数据可移植——信号层数据独立存放，可在本机备份、重置或迁移，不影响共享知识文件在不同机器间的一致性。

可选扩展方式包括：（1）多机信号同步——在多台机器上各自维护独立的信号层，通过可选的信号同步通道将各机器的访问统计汇总到云端，生成跨团队的聚合热度数据，供共享排序使用但不写回知识文件；（2）信号快照与回滚——信号层支持快照保存和回滚，在知识文件回退到历史版本时，可选择将信号也回退到对应时间点的快照状态。这些扩展均不影响核心的分层存储与融合读取机制。
