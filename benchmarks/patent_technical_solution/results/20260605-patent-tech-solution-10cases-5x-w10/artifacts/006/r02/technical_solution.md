## 技术方案

本方案提出一种面向共享知识文件的分层存储与运行时信号分离机制，将知识管理系统中以 Markdown 文件承载的共享知识内容与高频变化的运行时动态信号分离到不同存储层，通过读取融合、写入定向和清理联动三类机制，在保持知识文件可共享、可审阅、可版本控制的同时，使运行时信号能够持续累积并参与检索排序与生命周期管理。

### 1. 总体技术思路

本方案的核心构思是：将知识条目的存储拆分为"知识内容层"和"动态信号层"两个独立层次。知识内容层以 Markdown 文件形式存放于共享目录中，仅包含标题、摘要、标签、关键词、关联关系及正文等稳定知识字段，适合纳入版本控制与团队同步。动态信号层以本机私有存储（如本地信号数据库或信号文件）形式存放访问次数、检索命中计数、排序权重、成熟度级别、近期使用时间等高频变化信号，不参与版本控制和团队同步。在检索、排序、归档决策等需要同时使用知识内容和动态信号的场景中，通过读取时融合机制将两层数据合并为完整视图；在信号更新时，写入操作仅定向到动态信号层，不触碰共享 Markdown 文件。

### 2. 分层存储架构

本方案将知识条目的存储拆分为知识内容层和动态信号层两个独立层次，两者通过文件路径作为关联键进行映射。

知识内容层：沿用现有的 Markdown 文件体系，文件存放于项目目录下的 .brv/context-tree/ 路径中。每个知识条目对应一个 Markdown 文件，文件的 YAML 前置元数据仅保留稳定字段——标题（title）、摘要（summary）、标签（tags）、关键词（keywords）、关联关系（related）及正文内容。原有的动态评分字段——包括 accessCount（访问计数）、importance（重要性分数）、recency（近期度）、updateCount（更新计数）、maturity（成熟度级别）、createdAt（创建时间）、updatedAt（更新时间）——从 Markdown 前置元数据中移除，不再作为文件内容的一部分。这一改变使知识文件的 SHA-256 内容哈希仅随真实知识内容变化，不再因运行时访问或检索命中而被频繁改写。

动态信号层：在 .brv/ 目录下增设本机私有的信号存储（如 signal-store.json 或嵌入式信号数据库），以知识文件的相对路径为键，存储每个知识条目对应的运行时动态信号。每条信号记录包含：accessCount（累计访问次数）、importance（当前重要性分数，初始值为 50，范围 0-100）、recency（近期度，初始值为 1.0）、updateCount（累计更新次数）、maturity（成熟度级别：draft / validated / core）、createdAt（创建时间戳）、updatedAt（最近更新时间戳）。信号存储文件被标记为派生制品（derived artifact），通过现有的 isDerivedArtifact / isExcludedFromSync 机制排除在快照追踪（snapshot）、版本同步（CoGit push/pull）和合并（merge）流程之外。

### 3. 读取融合机制

在需要同时使用知识内容和动态信号的场景中——包括检索排序（compoundScore 计算）、清单构建（manifest 的 importance 排序和 lane 分配）、归档决策（基于 importance 阈值的低重要性条目归档）、以及前端展示——系统采用读取时融合机制。具体流程为：首先读取 Markdown 文件获得稳定的知识内容和基础元数据；然后以该文件的相对路径为键查询动态信号层，获取当前运行时信号；若信号层中存在该条目的记录，则将两组数据合并，形成包含完整评分信息的综合视图；若信号层中不存在记录（例如新建的知识条目尚未产生运行时信号），则使用默认初始信号值（importance=50，recency=1.0，maturity=draft，accessCount=0，updateCount=0）。

融合操作在内存中完成，不修改 Markdown 文件，也不生成新的中间文件。融合后的评分数据可用于：BM25 文本相关性分数与 importance、recency 的加权复合排序（如 W_RELEVANCE×bm25 + W_IMPORTANCE×normalizedImportance + W_RECENCY×recency，再乘以成熟度级别系数）；manifest 构建时按 importance 排序分配 summaries / contexts / stubs 三通道的令牌预算；以及归档服务判断条目 importance 是否低于归档阈值（ARCHIVE_IMPORTANCE_THRESHOLD）。时间衰减（applyDecay）在读取信号时按需计算：根据当前时间与 updatedAt 的天数差，对 importance 和 recency 施加指数衰减后再融合。

### 4. 信号写入与批量刷新

当运行时事件触发信号更新时，写入操作仅定向到动态信号层，不再回写 Markdown 文件。主要有两类写入路径：

检索命中写入：当用户执行知识检索（/query 或 search 操作）并获得匹配结果时，系统为每个命中条目的文件路径累积访问命中计数，存储于内存中的待刷新映射表（pendingAccessHits）。在索引重建（index rebuild）触发时，批量将累积的命中计数刷新到动态信号层：对每个受影响的文件路径，读取当前信号记录，调用 recordAccessHits 函数更新 accessCount（累加命中次数）和 importance（每次命中增加 ACCESS_IMPORTANCE_BONUS 分值，上限 100），通过 determineTier 重新判定成熟度级别，最后将更新后的信号记录写回信号层。每次访问命中不再触发 Markdown 文件的读写操作。

策展更新写入：当执行知识策展操作（ADD / UPDATE / MERGE / DELETE）并成功修改知识文件后，系统在动态信号层中更新对应路径的信号记录：调用 recordCurateUpdate 函数递增 updateCount，增加 UPDATE_IMPORTANCE_BONUS 分值，将 recency 重置为 1.0，更新 updatedAt 为当前时间戳。策展操作本身仍会写入 Markdown 文件（修改真实知识内容），但评分字段的更新仅写入信号层。对于 DELETE 操作，同时清理信号层中对应的信号记录。

### 5. 清理一致性机制

为避免动态信号层中出现指向已删除文件的孤立记录，方案提供两类清理机制：

联动清理：当知识条目被 DELETE 操作或归档操作（archiveEntry）删除/移走时，在操作成功后同步删除信号层中对应的信号记录。归档操作中，原始文件被替换为搜索桩（.stub.md）后，信号记录可选择性保留（以便归档条目在恢复到原位时继承历史信号）或根据配置清理。

周期性对账：系统在索引重建或清单构建等全量扫描环节，可对比信号层中的全部键与当前上下文树中实际存在的文件路径集合。对于信号层中存在但对应 Markdown 文件已不存在的孤立记录，执行惰性清理；同时可设置保护期（如文件被外部工具临时移走），在连续多次对账均判定为孤立后才执行删除，避免误清理。

### 6. 版本控制与同步隔离

动态信号层文件被标记为派生制品，纳入现有的 isExcludedFromSync 排除路径集合。具体效果包括：快照服务（FileContextTreeSnapshotService）在扫描上下文树目录时跳过信号文件，不计入 FileState 映射和 SHA-256 哈希对比，因此信号变化不会产生快照差异（ContextTreeChanges）；推送服务（CoGit push）在构建推送上下文时排除信号文件，不会将本机运行时信号上传至云端；拉取合并服务（CoGit pull + FileContextTreeMerger）不会将远程信号文件合并到本地，也不会因信号文件产生合并冲突。

由于 Markdown 文件不再包含动态评分字段，两个团队成员分别在不同机器上检索相同的知识条目时，各自的访问计数和重要性变化不会修改共享的 Markdown 文件。团队间的版本同步仅传输真正的知识内容变更——新增条目、修改摘要、更新正文、调整关联关系等。Git 工作区中 .brv/context-tree/ 下的 Markdown 文件仅在发生知识策展操作时产生变更，显著降低了因自动评分写回导致的版本控制脏状态和合并冲突。

### 7. 可选实施方式与边界条件

信号存储格式可选用 JSON 文件（便于调试和手动查看）或嵌入式键值数据库（如 SQLite，适合大规模知识条目下的高频写入）。信号层的具体存储格式不影响上述分层机制的核心逻辑，只要提供以文件路径为键的读写接口即可。在性能方面，读取融合引入了一次额外的信号层查询，该查询可通过内存缓存（如 LRU 缓存）将频繁访问条目的信号数据驻留在内存中，使融合开销降至亚毫秒级。在批量刷新场景中，每次索引重建时将 pendingAccessHits 中的累积计数一次性批量写入信号层，避免逐条文件写入带来的 I/O 放大。

对于已有知识条目从旧格式（评分字段嵌入 Markdown 前置元数据）向新格式（分层存储）的迁移，可在首次启动时执行一次性迁移：扫描所有 Markdown 文件，解析其前置元数据中的评分字段，将提取出的信号写入动态信号层，同时从 Markdown 文件中移除评分字段并写回。迁移后的文件哈希变化仅发生一次，后续不再因运行时信号而反复变化。
