## 技术方案

本方案提出一种面向共享知识文件的知识管理分层存储架构，通过将稳定的知识内容与高频变化的运行时动态信号分离存储，在保持共享知识文件适合版本控制、团队审阅和协同同步的同时，支撑检索排序、生命周期管理和自动清理等需要动态信号的功能。

### 整体架构

系统将知识管理数据划分为两个独立存储层：共享知识层（Shared Knowledge Layer）和本机信号层（Local Signal Layer）。共享知识层以 Markdown 文件形式存储于项目版本控制目录中，承载稳定的知识内容；本机信号层以独立于版本控制的本地数据结构存储，承载本机运行时产生的动态信号。两个存储层通过文件标识符建立一一映射关系。读取时，系统实时融合两个存储层的数据，向上层检索、排序和生命周期管理模块提供完整视图；写入时，系统根据变更类型分别路由至对应存储层——知识内容变更写入共享知识层，动态信号变更仅写入本机信号层。

### 共享知识层

共享知识层负责存储稳定的知识内容，以 Markdown 文件形式存放于项目版本控制目录（如 .brv/context-tree/）中。每个知识文件包含 YAML 前置元数据区和 Markdown 正文区。前置元数据携带标题（title）、摘要（summary）、标签（tags）、关键词（keywords）、关联文件路径（related）等结构化摘要信息；正文区承载原始上下文片段（snippets）、结构化叙述（narrative）、原始概念（raw concept）和事实陈述（facts）等内容。共享知识层仅包含知识内容，不存储访问次数、重要性评分、新鲜度、成熟度等级、时间戳等运行时动态信号。该层的文件内容仅在知识内容发生实质性变更（如新增知识、合并知识、编辑叙述）时才被改写，从而避免因信号更新造成的版本控制状态变脏和团队合并冲突。

### 本机信号层

本机信号层以独立于版本控制的本地数据结构存储每个知识文件对应的运行时动态信号，每条信号记录通过知识文件的唯一标识符（如相对路径的哈希值或规范化路径）与共享知识层中的对应文件关联。信号记录包含以下字段：访问计数（accessCount），每次检索命中时递增；重要性评分（importance），取值范围 0 至 100，受检索命中、知识更新和指数衰减的综合影响；新鲜度（recency），取值范围 0 至 1，按指数衰减模型随时间递减；成熟度等级（maturity），取值为 draft（草稿）、validated（已验证）或 core（核心），根据重要性评分按带滞回阈值的状态机自动流转；更新计数（updateCount），每次知识内容变更时递增；以及创建时间戳（createdAt）和最近更新时间戳（updatedAt）。本机信号层可以 JSON 文件、嵌入式键值数据库或结构化二进制文件等形式实现，存放于项目本机专属目录（如 .brv/signals/），该目录被版本控制系统忽略（通过 .gitignore 等机制排除）。信号层数据不参与团队同步和云端推送，不同团队成员各自维护本机的信号层，避免因不同成员的使用模式差异导致信号冲突。

### 读取融合机制

读取融合模块在系统执行知识检索、排序或生命周期管理操作时，实时合并共享知识层和本机信号层的数据。具体流程为：首先从共享知识层读取目标知识文件的 Markdown 内容并解析为结构化知识数据（包含标题、摘要、标签、关键词、关联关系、原始概念、叙述、事实、上下文片段等字段）；然后以该文件的标识符在本机信号层中查找对应的信号记录；若存在信号记录，则将信号字段（访问计数、重要性评分、新鲜度、成熟度等级、时间戳等）与知识数据合并，形成携带完整运行时信号的上下文数据对象供后续处理使用；若信号记录不存在（如首次访问），则为该文件初始化默认信号值（重要性 50、新鲜度 1.0、成熟度为 draft、访问计数 0）。融合操作在读取时执行，且不触发对共享知识层的任何写操作。对于检索排序场景，融合后的重要性评分和新鲜度与文本相关性评分（如 BM25）按加权公式组合为综合排序分数，并依据成熟度等级施加分级加权系数（如核心级 1.15、已验证级 1.0、草稿级 0.85），从而在维持文本检索精度的同时结合使用时序信号提升排序质量。

### 写入路由机制

写入路由模块根据变更类型将写入操作分发至对应的存储层。变更类型分为两类：知识内容变更和动态信号变更。知识内容变更包括新增知识文件、编辑知识内容（如更新叙述、补充事实、追加上下文片段）、合并多个知识文件、删除或归档知识文件等操作，此类变更写入共享知识层，并同时触发本机信号层的关联更新（如递增更新计数、重置新鲜度为 1.0、增加重要性评分）。动态信号变更包括因检索命中导致的访问计数递增和重要性加分、因时间流逝导致的新鲜度和重要性衰减、因重要性跨阈值导致的成熟度等级自动流转，此类变更仅写入本机信号层，不触发对共享知识层的任何写入。写入路由可通过变更类型枚举或操作来源标记实现：检索和排序操作产生的信号反馈自动路由至信号层；用户发起的知识编辑操作同时路由至两个层。通过上述路由机制，共享知识层的文件改写频率大幅降低，仅在实际知识内容发生变化时才产生新的版本控制提交。

### 清理一致性机制

当知识文件被删除或归档时，系统需确保本机信号层中的对应信号记录同步清理，避免孤立信号记录累积。清理一致性机制如下：系统在执行共享知识层的删除或归档操作后，同步删除本机信号层中对应的信号记录。对于归档操作，知识文件被移动至归档目录（如 .brv/context-tree/_archived/），系统可保留归档文件的信号记录以便归档检索，也可清空信号记录仅保留归档存根（stub）中的重要性快照（evicted_importance）。系统定期或按事件触发信号层巡检：遍历信号层中的所有记录，检查对应共享知识层文件是否仍存在；若某文件已被删除且信号记录未被同步清理（如因异常中断导致），则自动清除孤立信号记录。此外，系统可配置信号记录的过期策略：当某知识文件的重要性评分持续衰减至低于归档阈值（如 35），且新鲜度低于预设下限时，系统可自动将该知识文件归档并将信号记录重置为归档存根状态，防止长期不活跃的低价值知识占据存储和检索资源。

### 信号生命周期管理

本机信号层中的动态信号按以下规则自动演化：每次检索命中某知识文件时，访问计数加一，重要性评分增加预设增量（如 +3），上限为 100；每次对该知识文件执行内容编辑（curate）操作时，更新计数加一，重要性评分增加预设增量（如 +5），新鲜度重置为 1.0，更新时间戳更新为当前时刻。经过时间流逝，系统在读取信号时实时计算指数衰减：新鲜度按 exp(-days/衰减半衰期天数) 衰减（如半衰期 30 天），重要性按日衰减系数（如 0.995^days）衰减。成熟度等级根据衰减后的重要性评分，按带滞回阈值的状态机自动流转：draft→validated 的升级阈值为重要性 ≥65，validated→core 的升级阈值为重要性 ≥85；core→validated 的降级阈值为重要性＜60，validated→draft 的降级阈值为重要性＜35。滞回区间防止信号在阈值附近频繁振荡。上述所有信号演化计算均在本机信号层内完成，不涉及共享知识层的写入。

### 多用户协同与版本控制兼容

在多用户协同场景下，共享知识层的 Markdown 文件通过版本控制系统（如 Git）或专用同步机制（如 CoGit）在团队间共享和合并。由于共享知识层文件仅在知识内容发生实质性变更时才被改写，版本控制提交的粒度与知识演进的实际节奏一致，避免了因不同成员的检索、访问等低频操作产生的大量无意义提交。合并冲突仅发生在两个成员同时对同一知识文件的内容进行编辑时，而非因为双方的信号更新交叉干涉。每个成员各自维护本机的信号层，反映各自的使用模式和历史；不同成员的信号差异不影响共享知识的一致性。当新成员首次获取共享知识时，系统为其初始化默认信号记录；随后该成员的本地信号根据其自身使用行为独立演化。这种设计使得知识内容共享与个性化使用反馈解耦，兼顾了团队协同的版本控制友好性和个体检索体验的个性化优化。

### 可选实施方式与配置

本方案在存储实现方式上可灵活选择：信号层可采用 JSON 平面文件（每条信号记录一个 JSON 文件，以文件路径哈希命名）、单个聚合 JSON 文件（所有信号记录存于同一文件中）、SQLite 嵌入式数据库（以文件标识符为主键）或内存映射文件（兼顾读写速度与持久性）。信号衰减计算可采用延迟计算策略：不在后台定时触发衰减，而是在每次读取信号记录时根据记录的上次更新时间戳与当前时间的间隔，实时计算衰减后的新鲜度和重要性值并写回，从而避免后台轮询开销。对于大型知识库，读取融合模块可批量加载信号层数据并在内存中构建查找映射，以减少单次检索时的 I/O 次数。对于归档文件，可配置为保留精简信号（仅存储归档时的重要性快照和归档时间戳）或完全清除信号记录，以控制信号层存储空间。
