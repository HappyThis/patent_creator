## 技术方案

本方案提出一种面向智能体助手系统的两级会话架构，通过将用户级共享资源与会话级隔离上下文分别托管于独立的持久化对象（Durable Object），在保证各会话消息历史、执行状态和推理上下文严格隔离的前提下，实现同一用户下多会话对工作区文件、外部工具连接、授权凭据和跨会话调度能力的无缝共享。

### 整体架构

系统采用两级代理（Agent）组合架构：用户级目录代理（Chats）与多个会话级子代理（Think）。每一级代理均以独立的持久化对象（Durable Object，DO）实例运行，拥有各自的 SQLite 存储、单线程执行上下文和独立的生命周期。

Chats 代理负责维护用户下的会话索引（包括会话标识、标题、时间戳和最近消息摘要）、存储用户级共享上下文（如用户偏好、跨会话记忆）以及提供跨会话搜索能力。每个 Think 子代理对应一个独立的聊天会话，管理该会话的消息历史、会话级上下文块（Context Blocks）、压缩覆盖（Compaction Overlays）和推理执行循环。Chats 与 Think 之间通过持久化对象远程过程调用（DO RPC）实现跨 DO 的数据交换，客户端通过子代理路由机制（Sub-Agent Routing）可直接建立与 Think 子代理的 WebSocket 连接进行实时消息传输。

### 会话隔离机制

每个 Think 子代理实例化时，系统通过 DO Facet 机制为其分配独立的持久化对象标识（DO ID），该标识基于父代理的 DO ID 与子代理的复合键（类名 + NUL 字符 + 实例名）生成。不同的 Think 实例拥有各自独立的 SQLite 数据库文件，互不共享存储空间。

在该隔离模型下，每个会话具备以下独立资源：（1）独立的 SQLite 消息表（assistant_messages），存储该会话的树形消息结构，每条消息记录 parent_id 以实现分支与再生；（2）独立的压缩覆盖表（assistant_compactions），存储消息范围摘要，在读时非破坏性地替换原始消息区间；（3）独立的全文搜索索引（FTS5），仅覆盖本会话的消息内容；（4）独立的 Think 私有配置存储（think_config），包括客户端工具注册信息和动态配置。代理推理循环（Agentic Loop）中的工具执行、流式输出和中断控制均在各自 DO 的单线程内完成，不同会话的推理执行天然并行且互不阻塞。

### 用户级资源共享层

用户级共享资源统一托管于 Chats 父代理。Chats 代理维护一个会话索引表（chats_index），记录每个 Think 子代理的元数据（会话标识、标题、创建/更新时间、最近消息预览、软删除标记和代数计数器）。该索引支持本地标题全文搜索（chats_fts）。

共享上下文通过远程上下文提供者（RemoteContextProvider）机制实现。RemoteContextProvider 是一个通用的会话上下文提供者实现，在 Think 子代理中配置后，其 get/set/append 操作均通过 DO RPC 透明转发至 Chats 父代理执行，父代理的 SQLite 存储作为共享状态的唯一宿主。RemoteContextProvider 内置容错降级策略：当远程 RPC 调用失败时（如父代理处于冷启动、被驱逐或临时不可达），get 操作返回 null 而非抛出异常，确保子代理在共享内存暂时不可用的情况下仍可继续推理，下一轮对话时自动重试。

共享搜索通过 RemoteSearchProvider 实现。Chats 父代理暴露 searchShared 和 indexShared 两个可远程调用（@callable）方法。跨会话消息搜索由父代理的 searchMessages 方法实现，它通过并行 DO RPC 向各活跃 Think 子代理发送搜索请求并合并结果；各子代理的搜索在其本地 FTS5 索引上执行，无需将消息内容复制到父代理。

对于可写共享上下文，系统优先推荐追加式写入（appendSharedContext），利用 DO 单线程执行特性避免读-改-写竞态条件导致的数据丢失。全量替换写入（setSharedContext）在需要对共享状态进行整体替换时使用，调用方应了解该模式下最后一次写入胜出（last-writer-wins）。

### 子代理路由与连接管理

系统通过嵌套 URL 路径实现客户端对子代理的直接可达性，路径格式为：/agents/{父代理类名}/{父代理实例名}/sub/{子代理类名}/{子代理实例名}[/...]。该路由方案支持递归嵌套，即子代理下可进一步嵌套孙代理。

路由机制的关键特性包括：（1）WebSocket 升级穿透。客户端通过父代理的 fetch 处理器发起 WebSocket 请求，父代理的 onBeforeSubAgent 中间件钩子完成认证和权限检查后，通过 ctx.facets.get(facetKey).fetch(req) 将请求转发至子代理的 Fetcher；101 升级响应沿调用链反向传播至客户端后，后续 WebSocket 帧直接在客户端与子代理之间传输，父代理退出热路径。（2）父级中间件关卡。onBeforeSubAgent 钩子接收原始请求及子代理的类名和实例名，可返回 void（放行原请求）、修改后的 Request（转发修改后的请求）或 Response（短路返回，不唤醒子代理），用于实现认证门控、速率限制、请求改写和重定向。（3）客户端侧的 useChats 钩子封装了目录代理连接与活跃会话连接的组合逻辑：目录代理通过广播状态（broadcast state）实时同步会话列表变化；活跃会话切换仅需更新 useAgent 的 sub 参数，框架自动管理连接的生命周期。

当某一会话的 WebSocket 消息到达 Think 子代理后，消息首先通过会话层（Session）的 appendMessage 方法以幂等方式（按消息 ID 去重）写入树形消息表，自动关联至最新叶节点作为父节点。随后系统进行上下文组装：冻结系统提示词（含所有上下文块的当前快照）→ 获取会话历史（递归 CTE 从叶到根遍历树，应用压缩覆盖）→ 截断旧消息中过长的工具输出和文本 → 将消息转换为模型格式并裁剪过旧的工具调用记录。最终将组装好的系统提示词、消息列表和工具集（包括服务端工具、客户端工具和会话上下文工具）传递给语言模型进行推理。

### 会话生命周期与删除安全

会话创建由 Chats 父代理的 createChat 方法原子完成：在会话索引表中插入新记录（含唯一标识、默认标题和代数计数器初始值），通过 subAgent 方法懒创建对应的 Think 子代理 DO。subAgent 调用在父代理的子代理注册表（cf_agents_sub_agents）中记录创建关系，并通过内部 RPC（_cf_initAsFacet）将父代理的祖先路径（parentPath）传递给子代理，子代理据此建立对父代理的反向引用能力。

会话删除采用软删除 + 代数计数器策略以防止竞态问题。（1）目录代理将目标行的 deleted_at 字段置为当前时间戳，通过广播状态通知所有连接的客户端该会话已移除；客户端侧 useChats 钩子检测到会话消失后主动断开活跃连接。（2）子代理 DO 不会被立即删除——此时可能有正在进行的推理写入尚未完成。子代理 DO 自然进入休眠状态，由平台的标准 DO 垃圾回收机制按 TTL 清理。（3）代数计数器：重新创建相同标识的会话时，系统清除旧记录并写入新行，代数递增。该机制防止旧 WebSocket 连接在新会话创建后仍向已废弃的 DO 实例发送数据——连接握手时校验代数计数器，不匹配则拒绝连接。（4）删除操作对共享资源无影响：共享上下文存储于 Chats 父代理中，子代理仅通过 RemoteContextProvider 远程读写；工作区文件和授权凭据以 Chats 父代理或独立服务为宿主，不受子代理删除影响。

### 工作区文件与凭据共享

工作区文件共享可通过以下方式实现：（1）将 Workspace 实例托管于 Chats 父代理，Think 子代理通过 DO RPC 调用父代理暴露的文件操作接口（读写、列表、搜索等）间接访问共享工作区。Workspace 的命名空间隔离机制（不同 namespace 对应独立的 SQLite 表）可进一步区分共享工作区和会话私有临时文件。（2）利用子代理路由的多级嵌套能力，可引入独立的 WorkspaceAgent 作为 Chats 的另一个子代理（与 Think 同级），Think 子代理通过 subAgent 获取 WorkspaceAgent 的 RPC 桩（Stub）进行文件操作。此方式的优势是文件操作 IO 完全在 WorkspaceAgent 的独立 DO 中执行，不阻塞 Chats 或其他 Think 的推理。

外部工具连接和授权凭据（如 MCP 服务器连接、第三方 API 密钥、OAuth 令牌等）以 Chats 父代理的绑定配置（Env bindings）或加密存储为宿主。Think 子代理通过以下模式安全使用共享凭据：（1）通过 RemoteContextProvider 读取凭据元数据（如服务端点、可用工具列表），凭据本身不流经 RemoteContextProvider 的字符串通道；（2）通过父代理暴露的专用 @callable 方法执行需要授权的操作（如调用第三方 API），子代理仅传递操作参数，凭据由父代理在服务端附加。此模式确保浏览器端或子代理无法绕过统一控制直接访问共享资源，即使某个 Think 子代理完全被攻陷，凭据也不会泄露。

### 可选实施方式

方案支持以下可选实施方式以满足不同场景需求：

（1）共享 Workspace 跨会话访问。在 Chats 父代理中挂载 Workspace 实例，各 Think 子代理通过 RemoteContextProvider 或专用 RPC 方法读写共享文件。父代理的 onChange 回调可触发 broadcast，实现多会话的文件变更实时同步。

（2）跨会话消息全文搜索。Chats 父代理的 searchMessages 方法以扇出（fanout）模式向所有活跃子代理并行发送 FTS5 搜索请求，合并结果并按相关度排序。在会话数量较小时（约 50 以内），扇出模式延迟可控；会话数量更大时，可引入父代理侧的聚合 FTS 索引，由各 Think 子代理在 onChatResponse 生命周期钩子中主动向父代理上报新消息索引。

（3）LLM 驱动的会话标题生成。Think 子代理可在 onChatResponse 钩子中调用父代理的 renameChat 方法，基于首条用户消息自动生成标题。此功能完全在子代理侧实现，框架层面不做强制。

（4）会话分支与再生。Session 层的树形消息结构（parent_id 字段 + 递归 CTE 遍历）天然支持从任意历史节点创建新分支。客户端发送再生请求时携带截断后的消息列表，系统找到分支点后在新分支上执行推理，旧分支保留完整不被删除。该功能与多会话架构正交——既可用于单会话内的响应再生，也可通过 SessionManager.fork 方法实现跨会话的会话分支。
