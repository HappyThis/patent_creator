## 技术方案

本方案提出一种面向 AI Agent 工作区的多模态文件读取系统，通过在现有文件读取工具层与底层存储之间插入文件类型感知的内容转换适配层，使 Agent 能够通过统一接口消费文本、图片、PDF 等异构文件类型。核心创新在于：基于工作区文件元数据中的 MIME 类型进行智能路由——文本文件保持现有的行号、分页、截断等读取体验；图片等可被多模态模型消费的文件自动转换为 base64 data URL 格式；不可传递的二进制文件返回结构化降级响应而非错误。同时，通过多级大小阈值、编码长度限制和后端抽象层，确保方案在 SQLite 内联存储、R2 对象存储及自定义文件后端上的一致可用性。

### 1. 总体技术构思

本方案提出一种面向 AI Agent 工作区的多模态文件读取方法，在现有文本文件读取工具的基础上，引入文件类型感知的内容转换层，使 Agent 能够通过统一的文件读取接口消费图片、PDF 等非纯文本文件内容。核心思路是：在工具调用层拦截文件读取请求，根据文件的 MIME 类型自动选择合适的内容编码与传递方式——对于可被多模态模型直接消费的类型（如图片），转换为模型可接收的结构化数据；对于不适合直接传递的类型（如大型二进制文件），返回结构化文件信息及限制原因，避免无效传递。同时，通过内容大小控制、后端抽象和兼容策略，确保对现有文本读取体验（行号、分页、截断）的完整保持。

### 2. 系统架构

本方案在现有 Agent 工作区文件工具架构之上新增一个多模态读取适配层。该适配层位于文件读取工具（如 createReadTool）与底层工作区存储（Workspace）之间，负责下列核心职责：(1) 文件类型判定——基于工作区元数据中的 MIME 类型字段和文件扩展名进行类型分类；(2) 内容转换——根据文件类型将原始字节数据转换为适合目标模型的表示形式；(3) 传递控制——对超出大小限制或不被支持的类型实施降级策略，返回结构化说明而非原始内容；(4) 后端兼容——通过统一接口适配 SQLite 内联存储、R2 对象存储及自定义文件后端。

### 3. 文件类型判定机制

文件类型判定是多模态读取的入口步骤。本方案采用三级判定策略：(1) 优先读取工作区文件元数据中的 mime_type 字段——该字段在文件写入时即被记录（如 writeFileBytes 调用时传入的 mimeType 参数），对 image/png、image/jpeg、application/pdf 等标准 MIME 类型提供精确判定；(2) 当 mime_type 为通用值（如 application/octet-stream 或 text/plain）时，通过文件扩展名映射表进行二次判定，覆盖常见图片（.png、.jpg、.gif、.webp、.svg）、文档（.pdf）等类型；(3) 对于前两步无法判定的文件，通过读取文件头部魔数（magic bytes）进行最终确认，防止扩展名伪装导致的误判。判定结果将文件归入三类之一：文本类（可直接按行读取）、多模态可传递类（需要内容转换后传递）、不可传递类（需降级处理）。

### 4. 多模态内容转换策略

对于判定为多模态可传递类的文件，本方案定义内容转换规则：通过调用 Workspace 的 readFileBytes 或 readFileStream 方法获取文件的原始字节数据，再根据 MIME 类型选择编码策略。对于图片类型（image/png、image/jpeg、image/gif、image/webp 及非 XML 模式的 image/svg+xml），将原始字节编码为 base64 字符串，并以符合多模态模型输入格式的 data URL 结构（data:{mime_type};base64,{encoded_content}）返回。对于 PDF 类型（application/pdf），提供两种可选模式：在具备 PDF 解析能力的模型环境中，直接传递 base64 编码的 PDF 内容；在仅支持图片的模型环境中，可配置为返回 PDF 首页的栅格化预览（通过服务端 PDF 渲染完成）并附带页数、文件大小等结构化元信息。所有转换后的内容均附带原始文件的 MIME 类型、字节大小及编码方式信息，供模型正确解释。

### 5. 内容大小与限制控制

多模态内容（尤其是图片的 base64 编码）体积显著大于原始文本，需要专门的内容大小控制机制。本方案设计两级限制：(1) 文件级大小阈值——对多模态可传递文件设置最大允许读取的原始字节数（默认 10 MB），超过该阈值的文件不进行内容转换，改为返回结构化元信息（文件类型、大小、MIME 类型、超限原因提示）；(2) 编码后内容截断——由于 base64 编码会使数据膨胀约 33%，对编码后内容长度设置上限（默认与模型上下文窗口限制对齐），超出部分截断并附加截断标记。对于 PDF 文件，额外设置页数上限（默认前 50 页），超出部分仅返回首页预览和总页数信息。大小阈值可通过 Workspace 选项或工具参数进行配置，以适应不同模型的能力边界。

### 6. 二进制文件降级策略

对于判定为不可传递类的文件（如编译后的二进制可执行文件、压缩包、数据库文件、加密文件等），本方案实施结构化降级策略而非简单地返回错误。读取工具返回一个标准化的降级响应，包含：(1) 文件基本信息——路径、名称、类型、MIME 类型、大小、修改时间；(2) 不可读取原因——根据类型给出明确说明，例如'二进制可执行文件，不包含模型可解析的内容'、'application/zip 压缩文件，请使用解压工具处理后读取'；(3) 可操作建议——当系统具备对应处理能力时，提示可用的替代工具或操作（如对压缩文件提示使用 exec_command 解压，对数据库文件提示使用 SQL 查询等）。降级响应的结构保持与成功读取响应一致的外层字段，确保调用方（模型）可统一解析。

### 7. 多后端兼容设计

本方案通过统一的 WorkspaceFsLike 接口抽象底层存储差异，使多模态读取能力在不同后端上一致可用：(1) SQLite 内联存储——对于不超过 inlineThreshold（默认 1.5 MB）的文件，字节内容以 base64 编码存储在 SQLite 的 content 列中，readFileBytes 通过 base64 解码还原原始字节；(2) R2 对象存储——对于超过阈值或显式写入 R2 的文件，readFileBytes 通过 R2 get 操作获取对象体，readFileStream 直接返回 R2 对象的可读流；(3) 自定义 SqlBackend——任何实现了 query 和 run 方法的 SQL 后端均可接入，不限于 Durable Object SqlStorage 和 D1Database。对于不提供 R2 后端的部署环境，通过设置 inlineThreshold 为较高值或依据配置自动禁用大文件存储，此时超过阈值的大文件读取降级为返回超限说明。

### 8. 文本读取体验保持

多模态读取能力不得破坏现有文本文件的读取体验。本方案通过类型路由确保向后兼容：当文件类型判定结果为文本类时，完全复用现有文本读取路径——按行分割、添加行号、应用 offset/limit 分页、截断超长行（保留 MAX_LINES=2000 和 MAX_LINE_LENGTH=2000 的现有约束），返回格式与当前 read 工具完全一致（包含 path、content、totalLines 及可选的 fromLine/toLine）。仅当文件被判定为多模态可传递类或不可传递类时，才走新增的内容转换或降级路径。文本文件的行号、分页和截断行为不受任何影响。

### 9. 读取工具接口扩展

本方案扩展 ReadOperations 接口，新增 readFileBytes 和 readFileStream 方法签名，使读取工具可以获取文件原始字节。扩展后的接口定义为：readFile(path) 保持返回 Promise&lt;string | null&gt;，用于文本文件；readFileBytes(path) 返回 Promise&lt;Uint8Array | null&gt;，用于多模态内容获取；stat(path) 返回包含 mimeType 字段的 FileInfo。工具层 createReadTool 在执行时：(1) 先通过 stat 获取文件的 MIME 类型和大小；(2) 若为文本 MIME 类型，走现有 readFile 路径，按行处理并返回带行号的文本；(3) 若为多模态可传递 MIME 类型，先校验大小阈值，再通过 readFileBytes 获取原始字节，执行内容转换（base64 编码 + data URL 封装），返回结构化多模态内容；(4) 若为不可传递类型，返回降级响应。返回结构统一包含 type 字段（'text' | 'multimodal' | 'degraded'）以区分响应类别。

### 10. 读取处理流程

完整的读取处理流程如下：(1) Agent 模型调用 read 工具，传入文件路径 path 及可选的 offset/limit 参数；(2) 工具层通过 Workspace 的 stat 方法获取文件的 mime_type、size 及 type 信息；(3) 若 type 为 directory，直接返回错误提示；(4) 执行文件类型判定（MIME 优先级 → 扩展名映射 → 魔数检测），确定文件类别；(5) 若为文本类，执行现有文本读取路径：调用 readFile，按换行符分割，应用 line-number 格式化，执行 offset/limit 窗口截取，超长行截断，返回标准文本响应；(6) 若为多模态可传递类：校验文件大小是否在阈值内（超限则走降级），调用 readFileBytes 获取原始字节，根据 MIME 类型选择编码策略执行转换，附加元信息，返回 multimodal 类型响应；(7) 若为不可传递类：构造降级响应，包含文件元信息、限制原因和可操作建议，返回 degraded 类型响应。整个流程对调用方透明——Agent 模型只需调用统一的 read 工具，无需感知内部的类型路由逻辑。

### 11. 异常与边界处理

多模态读取路径引入的异常场景需要精细化处理：(1) R2 不可用——当文件存储在 R2 但当前 Workspace 实例未配置 R2 bucket 时，readFileBytes 抛出明确错误，工具层捕获后返回降级响应，说明'文件存储在 R2 对象存储中，当前环境未配置 R2 访问'，同时提供文件的完整 SQLite 元数据；(2) 编码失败——当 base64 解码或字节到字符串转换失败时，返回包含原始字节长度的错误信息，不传递损坏内容；(3) 超大文件——当文件大小超过多模态阈值时，返回降级响应并包含精确的字节数、建议的分块读取方案（如适用）；(4) 未知 MIME 类型——当文件 MIME 类型不在已知映射表中时，默认按不可传递类处理，返回文件基本信息和建议用户显式指定读取方式。所有错误场景均通过结构化响应返回，不抛出未捕获异常，保持工具调用的稳定性。

### 12. 共享工作区与跨 DO 代理兼容

在共享 Workspace 场景（如多个 Agent 通过 RPC 代理访问父 Agent 的 Workspace）中，多模态读取需要保证跨 DO 调用的正确性。本方案要求 WorkspaceFsLike 接口扩展 readFileBytes 方法，使跨 DO 代理（如 SharedWorkspace）在转发 RPC 调用时能够将子 Agent 的 readFileBytes 请求完整转发到父 DO 的实际 Workspace，并将返回的 Uint8Array 通过 RPC 序列化传递。对于不支持 RPC 二进制传输的环境，提供 fallback 机制：服务端将字节编码为 base64 字符串后通过 RPC 传递，客户端再解码还原。同时，R2 对象的直接流式传输在跨 DO 场景下保持语义——R2 get 操作返回的对象体可通过 ReadableStream 在不同 DO 间传递。

### 13. 可配置参数

本方案引入以下可配置参数，支持不同部署环境和模型能力的灵活适配：(1) multimodalMaxSize——多模态文件最大读取字节数，默认 10 MB，可按模型上下文窗口调整；(2) multimodalEnabledTypes——允许进行内容转换的 MIME 类型白名单，默认包含常见图片和 PDF 类型，可按需扩展或收缩；(3) pdfRenderMode——PDF 处理模式，可选 'base64'（直接传递原始 PDF）、'rasterize'（栅格化首页预览）或 'metadata_only'（仅返回元信息）；(4) maxEncodedLength——base64 编码后内容的最大长度限制，默认与目标模型的上下文限制对齐；(5) magicBytesDetection——是否启用魔数检测作为 MIME 判定的兜底策略，默认开启。这些参数可通过 Workspace 构造选项或创建工具时的选项对象传入。

### 14. 技术效果总结

本方案通过上述技术手段，在不改变现有 Agent 工作区文件读取工具外部调用方式的前提下，实现了以下技术效果：(1) 统一的文件读取入口——Agent 模型通过同一个 read 工具即可消费文本、图片、PDF 等异构文件类型，无需学习多种读取方式；(2) 智能的内容路由——根据文件 MIME 类型自动选择最优的内容传递格式，文本文件保持带行号的阅读体验，图片以 base64 data URL 直接嵌入模型上下文，PDF 提供可配置的解析深度；(3) 透明的降级处理——对不可读取的二进制文件，不仅返回限制原因，还提供可操作的下一步建议，引导模型使用替代工具；(4) 可控的资源消耗——通过多级大小阈值和编码后长度限制，防止多模态内容超出模型上下文窗口或造成过度的内存与传输开销；(5) 完整的后端兼容——方案通过 WorkspaceFsLike 统一接口适配 SQLite 内联、R2 对象存储及自定义 SQL 后端，在真实 Workspace、共享 Workspace 代理和自定义文件后端上均一致可用；(6) 零破坏性升级——现有文本读取的所有行为（行号、分页、截断、长行处理）完全保持，已有 Agent 无需任何修改即可继续正常使用。
