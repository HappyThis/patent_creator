## 技术方案

本技术方案提出一种可扩展的本地 agent runtime 接入方法，使智能工作台能够在现有多种 runtime 管理能力基础上，以声明式配置驱动的方式接入新的本地 agent runtime，自动识别其已有的本地会话记录并在同一工作台中统一展示和管理，同时具备版本差异适配和未确认能力隔离机制。

### 整体架构

本方案的架构在现有智能工作台基础上引入三个核心组件：运行时描述符注册表、可配置会话扫描引擎、以及能力门控模块。运行时描述符注册表维护已注册 runtime 的声明式配置，取代现有硬编码的 RuntimeId 联合类型和 DETECTORS 映射。可配置会话扫描引擎根据描述符中指定的状态目录路径模式和会话文件格式，对本地文件系统中的会话记录进行发现和解析。能力门控模块根据探测结果控制各 runtime 可用能力的暴露范围。

运行时描述符注册表、可配置会话扫描引擎和能力门控模块三者协同运作。注册表是配置中心，存储所有 runtime 的声明式描述；扫描引擎是执行单元，依据描述执行实际的会话发现和解析；能力门控模块是安全边界，确保只有经过验证的能力对外暴露。三个组件通过统一的事件总线进行通信：注册表变更触发重新探测，探测结果更新能力门控状态，扫描完成事件通知工作台刷新展示。

对于现有已支持的 runtime（如 openclaw、hermes、claude、codex），系统将其现有的检测逻辑封装为对应的内置运行时描述符。内置描述符在系统启动时自动加载，其字段值由现有检测函数和会话扫描模块的参数转化而来，对外部注册的描述符和内置描述符采用完全相同的处理流程。这意味着新 runtime 的接入路径与已有 runtime 的管理路径在架构上是等价的，新增 runtime 不会引入特权路径或绕过既有安全审查。

### 运行时描述符定义

运行时描述符是一种声明式数据结构，用于刻画一个本地 agent runtime 的全部可探测特征，包括：运行时标识符、可执行二进制名称及常见安装路径列表、版本探测命令及版本号提取模式、本地状态目录的路径模板、会话文件的存储格式及解析策略、以及该 runtime 声称支持的能力清单。

描述符中的状态目录路径模板支持环境变量展开和通配符匹配，例如 ${HOME}/.newruntime/sessions 或 ${HOME}/.newruntime/v*/data，以适应不同版本可能使用不同目录名的情况。会话文件格式字段指定解析策略标识符，如 jsonl、sqlite、json_dir，并可附带格式版本号以区分同一格式的不同演进版本。

能力清单中的每一项能力均关联一个探测方法，该方法在运行时被调用来确认该能力是否确实可用。探测方法可以是执行特定命令并检查返回值、检查指定文件是否存在、或向 runtime 进程发送查询请求。只有探测结果为肯定的能力才在工作台中展示为可用状态，未探测或探测失败的能力被标记为未确认，不在操作界面中暴露。

描述符的核心字段 schema 定义如下：runtime_id（唯一标识符）、display_name（展示名称）、binary_probes（二进制探测配置列表，每项含 binary_names、version_flag、version_pattern）、state_dir（状态目录配置，含 path_template 和候选优先级）、session_format（格式类型及版本号）、capabilities（能力列表，每项含 capability_id、label、probe_method）、version_rules（版本适配规则列表，每项含 version_constraint 和 overrides）。该 schema 的字段均为声明式，不包含可执行代码，确保描述符本身可被安全地存储、传输和校验。

### 运行时描述符注册机制

系统提供描述符注册接口，支持通过配置文件、API 调用或插件目录扫描三种方式注册新的运行时描述符。注册接口接受符合描述符 schema 的声明式配置，将其存入运行时描述符注册表，并立即触发一次探测以获取该 runtime 的当前状态。

配置文件方式：系统在指定的配置目录中扫描符合命名约定的描述符文件，例如 *.runtime.json。每个文件解析为一个运行时描述符。管理界面可触发重新扫描以发现新增或更新的描述符。API 注册方式：通过 REST 接口提交描述符 JSON，用于程序化接入场景。插件目录扫描方式：扫描特定目录下的子目录，每个子目录包含一个描述符文件和可选的解析器脚本，用于处理该 runtime 特有的会话格式。

### 可配置会话扫描引擎

可配置会话扫描引擎是方案的执行核心，负责根据运行时描述符中定义的状态目录路径和会话格式策略，遍历本地文件系统中的会话数据，提取统一的会话摘要信息。其工作流程分为路径解析、文件发现、格式适配和摘要提取四个阶段。

路径解析阶段：将描述符中的路径模板展开为实际文件系统路径。模板中的变量引用（如 ${HOME}、${XDG_DATA_HOME}）按运行时环境解析，通配符模式（如 v*）通过文件系统 glob 匹配找到实际存在的目录。若指定了多个候选路径模板，按优先级依次尝试，选用第一个存在且可读的路径。

文件发现阶段：在已解析的状态目录中，根据描述符指定的文件匹配模式（如 *.jsonl、*.json、或单个数据库文件名如 state.db）收集候选会话文件。对每个文件记录其修改时间和大小，按修改时间降序排列，并对超过设定大小的文件予以跳过以避免影响扫描性能。

格式适配阶段：根据描述符声明的会话格式策略选择对应的解析器。系统内置多种通用解析器：JSONL 行解析器逐行读取 JSONL 文件提取每条消息记录的类型、时间戳、模型、token 用量等字段；SQLite 解析器以只读模式打开数据库文件，查询会话表和消息表，按统一 schema 映射字段；JSON 目录解析器遍历目录中的 JSON 文件分别解析。对于内置解析器无法覆盖的专有格式，描述符可指定外部解析器脚本路径，扫描引擎通过子进程调用该脚本并将结果通过标准输出以约定的 JSON 格式返回。

摘要提取阶段：各解析器将不同 runtime 的会话记录统一映射到系统定义的会话摘要模型。该模型包含：会话标识符、所属项目或工作区路径、使用的模型名称、用户消息数、助手消息数、工具调用次数、输入 token 总量、输出 token 总量、首条消息时间、末条消息时间、以及活跃状态判断。活跃状态根据末条消息时间与当前时间的间隔是否小于预设阈值判定，不同 runtime 可配置不同的活跃阈值以适应其会话特征。

### 版本感知的能力协商

针对新 runtime 不同版本可能存在的差异，方案引入版本感知的能力协商机制。扫描引擎在完成版本探测后，根据探测到的运行时版本号匹配描述符中声明的版本适配规则，确定适用的会话格式版本和有效能力集。

描述符中可定义版本匹配规则列表，每条规则包含版本约束表达式和对应的配置覆写。版本约束表达式支持语义化版本比较，如 ">=1.2.0 <2.0.0" 或 ">=2.0.0"。当探测到的运行时版本满足约束时，对应的配置覆写生效，可覆写字段包括：状态目录路径模板、会话格式版本号、能力探测命令、以及活跃判定阈值等。未匹配到任何版本规则时，使用描述符的默认配置。

### 未确认能力隔离与安全门控

未确认能力隔离是本方案的核心安全保障机制。对于新接入的 runtime，其能力清单中的每一项能力在未经探测确认之前，均不在工作台中展示为可用操作。能力清单的结构将能力分为三类：已确认、待探测和不可用。

已确认能力：经探测方法验证为可用的能力，在工作台界面中以正常态展示，用户可以触发对应操作。待探测能力：描述符中声明但尚未执行探测或探测结果为不确定的能力，仅在管理配置界面中可见，不暴露给日常操作界面。不可用能力：探测明确返回失败的能力，在工作台中不展示或明确标记为不可用状态。这种分类确保用户不会看到实际上不存在的功能入口，避免误操作。

能力探测在 runtime 注册时自动触发，并在后续每次系统启动或定时周期中重新执行。探测结果具有时效性：如果某能力的探测超过设定时间未刷新，该能力自动降级为待探测状态。这适应了新 runtime 版本升级后能力变化而探测尚未更新的场景。

以继续会话能力为例说明能力门控的具体运作：新 runtime 的描述符中声明了 "continue_session" 能力，其探测方法为执行 "newruntime session --resume --dry-run" 命令并检查退出码。若该版本不支持此命令，探测返回失败，该能力被标记为不可用，工作台中不展示"继续会话"按钮。若探测成功，该能力标记为已确认，工作台展示对应操作入口。当 runtime 升级到新版本后，定时探测重新执行，若新版本开始支持继续会话，能力状态自动从不可用变为已确认，操作入口随之出现。

### 与既有运行时管理流程的隔离兼容

为确保新 runtime 的接入不会破坏已有 runtime 的管理流程，方案在架构层面实现了严格的隔离机制。新 runtime 的描述符注册和会话扫描均在独立的执行上下文中运行，与已有 runtime 的检测和管理逻辑不共享可变状态。

具体而言，会话扫描引擎为每个 runtime 创建独立的扫描任务，各扫描任务的发现、解析和摘要生成互不干扰。扫描过程中的异常（如文件格式不符、解析失败、数据库锁定）被限制在当前 runtime 的扫描任务内，以日志记录和状态标记的形式反馈，不影响其他 runtime 的扫描结果和整体系统的可用性。即使新 runtime 的状态目录不存在或会话文件已损坏，系统仅将该 runtime 的状态标记为异常，其余 runtime 的会话展示和管理完全不受影响。

### 统一会话展示与管理

所有 runtime 的会话摘要经扫描引擎提取后，统一写入系统的会话摘要存储层。存储层按运行时标识符和会话标识符组织数据，在查询时按时间、项目、活跃状态等维度进行聚合和过滤。工作台的会话展示组件从统一的存储层读取数据，按 runtime 分组呈现，用户可在不同 runtime 的会话列表间切换，但感知到的交互模式和数据呈现格式保持一致。

### 运行时接入与会话发现的处理流程

系统在启动时执行以下流程完成所有 runtime 的接入和会话发现。第一步：加载已注册的运行时描述符，包括内置 runtime 描述符和外部注册的描述符。第二步：对每个描述符执行版本探测，确定实际安装的版本号和二进制路径。第三步：根据版本适配规则确定生效的配置。第四步：对每个 runtime 执行能力探测，将探测结果写入能力状态缓存。第五步：根据生效配置中的状态目录路径和会话格式策略，启动会话扫描任务。第六步：将扫描产生的会话摘要写入统一存储。后续运行中，定时任务或事件触发可驱动增量扫描。
