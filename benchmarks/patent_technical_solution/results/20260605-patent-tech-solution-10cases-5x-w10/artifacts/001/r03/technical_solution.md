## 技术方案

本方案提出一种可扩展的本地 agent runtime 接入方法，通过运行时适配器注册机制、多阶段能力探测协议和会话格式自动识别引擎，使智能工作台在不需要修改核心代码的前提下，接入任意新的本地 agent runtime，自动识别其已有的本地会话记录，并根据探测到的实际能力动态调整可用的交互选项。以下分别说明各组成部分。

### 整体架构

系统在现有 agent runtime 管理框架基础上，引入三层扩展架构。第一层为适配器注册层，提供运行时适配器的标准化接口和注册机制，新增 runtime 只需实现预设适配器接口并通过配置或自动发现完成注册。第二层为能力探测层，对已注册但尚未确认状态的 runtime，执行多阶段能力探测，逐步确定其安装状态、状态目录位置、会话文件格式和可支持的交互能力。第三层为格式识别与映射层，对已探明的会话存储文件，通过格式模式匹配引擎自动识别其数据结构，并映射为统一会话模型供工作台展示。三层之间通过明确的接口契约交互，上层依赖下层探测结果，探测失败自动传导，避免将未确认信息向上暴露。

### 运行时适配器接口

定义统一的运行时适配器接口（RuntimeAdapter），作为所有新增 runtime 接入的标准化契约。该接口包含四个必要方法：一是存在性检测方法，接收系统环境信息（如环境变量、PATH 路径、主目录路径），返回运行时是否已在本地安装的判定结果及版本号。该方法可通过二进制探测、候选路径搜索、配置文件检测等多种策略组合实现判定。二是状态目录发现方法，返回该运行时在本地文件系统中存储会话数据的候选目录路径列表，各路径按优先级排序。三是会话格式描述方法，返回格式描述符对象，包含文件扩展名、存储结构类型（JSONL、SQLite 数据库、JSON 键值映射或目录结构）、核心字段到统一模型的映射关系表，以及一个快速格式验证函数。四是能力枚举方法，返回该运行时支持的交互能力清单，包括是否支持会话继续、会话终止、实时消息推送、多会话并行等。

### 多阶段能力探测协议

对于新注册的运行时适配器，系统执行分阶段探测，每个阶段按依赖关系顺序执行，前一阶段失败则后续阶段自动跳过。

第一阶段为安装状态探测。调用适配器的存在性检测方法，结合系统环境变量和已知安装路径，判定运行时是否已安装。若未安装，记录状态为"未安装"并停止后续探测；若已安装，提取版本号并进入下一阶段。

第二阶段为状态目录验证。依次遍历适配器返回的候选状态目录路径列表，对每个路径检查其是否存在且可读。若找到有效目录，记录为主状态目录路径并进入下一阶段；若所有候选路径均无效，标记为"状态目录未确认"，后续会话扫描阶段自动跳过。

第三阶段为会话格式匹配。在已确认的状态目录下，扫描与格式描述符中文件扩展名匹配的文件。对每个候选文件，提取样本数据（如文件头部若干字节或首行 JSON 记录），通过格式描述符提供的验证函数快速检测格式是否匹配。若匹配成功，记录为"会话格式已确认"；若所有文件均无法匹配，标记为"会话格式未确认"。

第四阶段为能力动态校准。基于前三阶段的探测结果，对适配器声明的能力清单进行交叉验证。例如，适配器声明支持"会话继续"，但状态目录中未找到必要的会话恢复数据（如网关 PID 文件或运行进程锁），则将该能力动态降级为"未确认"。此外，系统在探测过程中记录每个阶段的耗时、异常原因和降级理由，形成完整的探测审计日志。

### 会话格式自动识别引擎

对于第三阶段探测到的会话文件，系统通过格式自动识别引擎完成深度解析，该引擎包含结构类型识别、字段映射与容错解析、版本兼容性处理三个子模块。

结构类型识别模块根据格式描述符中指明的存储结构类型，选择对应的解析器。SQLite 类型以只读模式打开数据库文件，先验证 sessions 表是否存在，再按时间倒序读取会话记录，对无结束时间的会话进一步查询 messages 表获取最后消息时间戳；JSONL 类型以流式方式逐行读取，每行独立解析为 JSON 对象，按消息类型（user、assistant）分类累计统计消息数、token 用量和工具调用次数，并跳过标记为副链（sidechain）的记录；JSON 键值映射类型一次性读取整个文件，按 session key 遍历条目，提取每个 session 的元数据；目录结构类型以子目录为会话单元，在每个子目录中查找标记文件（如 session.json、metadata.yaml）作为会话入口。

字段映射与容错解析模块中，格式描述符定义了核心字段到统一会话模型的映射关系。解析引擎按映射表逐字段提取数据，对标记为可选的字段若在源数据中缺失不阻塞解析流程，对应字段填充为空值；对标记为必需的字段若缺失则丢弃该条记录并记录解析异常。对于时间戳字段，解析引擎进行合理性校验，剔除未来时间、负值等异常时间戳，并将其钳制到合理范围。

版本兼容性处理模块中，格式描述符可包含版本区间映射表。该表将运行时版本号区间映射到对应的字段映射规则集合。当运行时版本落在已知区间内时，使用对应的映射规则；当版本超出已知区间时，尝试使用最接近版本的映射规则，并在解析出的会话记录上附加"格式兼容性警告"标记，提示用户该会话的解析结果可能不完全准确。

### 统一会话模型

所有运行时的会话记录经解析后映射到统一会话模型，该模型包含以下字段：会话标识符（sessionId），用于跨运行时唯一标识一条会话记录；来源运行时标识（runtimeId），标记该会话所属的 agent runtime；会话标题或摘要，优先取源数据中的标题字段，无标题时取会话标识符；消息数量统计三元组（用户消息数、助手消息数、工具调用次数）；Token 用量统计（输入 Token、输出 Token），可选包含缓存读取和缓存写入 Token 用于成本估算；首条消息时间戳与最后一条消息时间戳，用于排序和活跃度判定；活跃状态，基于最后消息时间与运行时运行状态的联合判定，若运行时网关或进程正在运行且最后消息时间在活跃阈值内，则标记为活跃；能力标记位图，按位标记该会话支持的操作类型，包括但不限于查看详情、继续会话、终止会话、导出记录，每一位仅在对应能力经探测确认为可用时才置位。

### 运行时管理流程的隔离保护

为确保新运行时的接入不破坏已有运行时的管理流程，系统采取以下隔离保护措施。

第一，适配器实例隔离。每个运行时适配器以独立实例运行，拥有独立的探测状态、会话缓存和错误计数器。一个适配器的初始化失败、探测超时或运行时异常不影响其他适配器的正常工作，也不影响已确认运行时的会话数据展示。

第二，探测超时与熔断机制。每个探测阶段设置独立超时时间（如安装检测 5 秒、目录扫描 10 秒、格式验证 30 秒），超过阈值自动跳过当前阶段并将该阶段标记为超时。同一适配器在连续多次探测（如连续 3 次）中全部阶段均失败时，触发熔断机制：将该适配器标记为"异常"状态，暂停后续自动探测周期，仅保留手动触发重置的能力。熔断状态持续一段时间（如 1 小时）后自动恢复，允许重新探测。

第三，能力展示门控。工作台前端在渲染每个运行时的会话列表和交互控件时，严格依据能力标记位图。仅当对应能力位已置位时才展示相应的操作按钮或交互入口。对于"会话格式未确认"状态的运行时，仅在运行时面板显示其名称、版本和安装状态，不渲染任何会话记录列表。对于附带"格式兼容性警告"标记的会话记录，在会话卡片上以非阻塞提示方式展示警告图标和说明文字，允许用户查看但提示解析结果可能存在偏差。

### 技术效果

本方案通过分层适配器架构、多阶段能力探测和格式自动识别，实现了对未知 agent runtime 的安全、渐进式接入，具有以下技术效果。

在扩展性方面，适配器注册机制将运行时特异性逻辑从核心系统中解耦，新增 runtime 仅需实现标准化适配器接口并完成注册，无需修改核心代码。多个运行时适配器的会话数据通过统一会话模型聚合到同一工作台，消除了不同 runtime 各自为政的信息孤岛。

在安全性方面，多阶段探测协议配合能力动态校准，确保系统只在能力经实际验证后才将其标记为可用，避免了将未确认能力（如不存在的"继续会话"按钮）展示给用户而导致的误操作和数据不一致。展示门控进一步在前端层面过滤未确认内容。

在兼容性方面，格式自动识别引擎通过结构类型识别、容错解析和版本区间映射三重机制，解决了不同版本 runtime 会话文件格式存在差异的问题。当运行时版本超出已知兼容范围时，系统以最接近版本的规则尝试解析并以警告标记提示用户，既不阻塞使用也不隐瞒风险。

在稳定性方面，适配器实例隔离和熔断机制确保任何一个 runtime 适配器的异常不会级联影响其他运行时的正常工作，也不会阻塞工作台整体会话列表的加载和渲染。
