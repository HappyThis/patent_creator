## 技术方案

本技术方案提出一种基于运行时描述符（Runtime Descriptor）与能力门控（Capability Gating）的可扩展本地 agent runtime 接入系统。该系统在不修改已有源代码的前提下，通过声明式配置发现、识别并接入新的本地 agent runtime，将其已有的本地会话记录映射为统一会话模型，并在同一智能工作台中展示和管理。方案的核心技术手段包括：运行时描述符模型、能力分级门控机制、可插拔会话格式适配器链、版本感知的格式探测与兼容性策略，以及隔离化的故障边界。

### 一、整体架构

系统在已有硬编码运行时检测机制（即每个已知 runtime 对应一个独立检测函数和会话扫描器的模式）之上，引入一个可扩展的运行时接入层。该接入层由运行时描述符注册表、能力门控管理器、会话格式适配器链和版本感知探测引擎四个核心模块组成。新增的 agent runtime 只需在工作台中放置一个符合预定义模式的描述符文件（例如 .mc-runtime.json 或 .mc-runtime.yaml），无需修改系统的任何源代码。系统启动时或按需触发扫描时，描述符注册表读取该文件，将其注册为一个新的运行时条目；能力门控管理器根据描述符中的能力声明决定哪些功能对外暴露；会话格式适配器链根据描述符中声明的格式信息，选择合适的解析策略将本地会话数据映射为统一会话模型。

### 二、运行时描述符模型

运行时描述符是一个结构化文档，用于声明新 runtime 的身份、可检测性、状态数据位置、会话格式和可操作能力。描述符包含以下关键字段：

- 运行时身份：包括运行时标识符（id）、显示名称、版本提取命令及正则表达式模板，用于通过命令行探测是否已安装及获取版本号；
- 状态目录声明：指定该 runtime 在本地文件系统中的状态数据根目录（如 ~/.newruntime/），系统据此定位会话文件、配置文件和其他持久化数据；
- 会话格式描述：声明会话数据的存储格式（如 SQLite 数据库、JSONL 文件、目录结构等）、格式版本号以及会话记录到统一会话模型的字段映射规则；
- 能力清单：以枚举方式声明该 runtime 支持的能力（如 session_list、session_detail、continue_session、memory_access、task_dispatch 等），每个能力标注置信度等级（confirmed 表示已由运行时开发者确认可用，detected 表示系统自动探测到但未经确认，unavailable 表示明确不支持）；
- 认证与安全声明：描述该 runtime 的认证方式（API Key、OAuth、配置文件等）及所需的系统权限。

### 三、能力分级门控机制

能力门控机制是本方案确保系统稳定性和正确性的关键手段。其核心原则是：系统仅向用户暴露置信度为 confirmed 的能力，对于 detected 和 unavailable 的能力不予展示或操作入口。能力门控分为三个层次运作：

- 能力注册层：运行时描述符中声明的每个能力都带有置信度标记。系统在解析描述符时建立能力-置信度映射表。对于未在描述符中声明的能力，默认视为 unavailable。
- 运行时验证层：系统在探测到 runtime 已安装后，对描述符中标记为 detected 的能力执行自动验证。验证方式包括：检查会话格式适配器是否能成功解析至少一条会话记录（验证 session_list 能力）；检测描述符中声明的继续会话命令是否存在且可执行（验证 continue_session 能力）。验证通过的能力自动提升为 confirmed。
- 界面渲染层：工作台的运行时面板和会话列表在渲染时，查询能力门控映射表，仅显示 confirmed 能力对应的操作入口。对于 detected 但尚未验证通过的能力，可在管理后台显示为待确认状态，但不向普通用户暴露。

### 四、可插拔会话格式适配器链

为解决不同 runtime 使用不同会话存储格式的问题，系统引入可插拔的会话格式适配器链。适配器链是一个有序的解析器序列，每个解析器声明自己能处理的格式特征（如存储类型、表结构模式、字段命名约定等），系统按优先级逐一尝试直到找到匹配的解析器。

适配器接口定义统一的解析方法：输入为运行时描述符中声明的状态目录路径，输出为标准化会话记录列表。每条标准化会话记录包含：会话标识、来源渠道、模型名称、消息数量、工具调用次数、输入/输出 Token 统计、首末消息时间戳和活跃状态标识。

系统内置一组通用适配器，包括：SQLite 数据库适配器（通过读取数据库 schema 探测表名和字段映射）、JSONL 流式适配器（逐行解析 JSON 对象并按字段名模糊匹配映射）、目录结构适配器（遍历子目录以目录名为会话标识、以文件修改时间推断活跃状态）。当描述符中声明了自定义字段映射规则时，通用适配器优先使用该映射；未声明时使用启发式匹配。

当描述符声明了一种未知格式且所有内置适配器均无法解析时，系统将该 runtime 的会话标记为格式不支持状态，不生成错误的会话数据，也不阻塞其他 runtime 的正常工作。

### 五、版本感知的格式探测与兼容性策略

针对同一 runtime 不同版本可能改变会话存储格式的问题，系统引入版本感知的格式探测与兼容性策略。运行时描述符支持声明多个格式版本条目，每个条目包含：适用的版本范围（如 >=2.1.0, <3.0.0）、对应的会话格式描述和字段映射规则。

系统在首次扫描某 runtime 的会话数据时，先通过运行时描述符中声明的版本提取命令获取实际安装版本，然后从描述符的格式版本列表中匹配对应的格式配置。若实际版本超出所有已声明版本范围，系统采用以下降级策略：优先尝试最新已声明版本的格式配置（假设向后兼容）；若解析失败，依次尝试较早版本的配置；全部失败后将 runtime 标记为格式变更待适配状态，同时记录实际版本号和样本数据特征，供管理员后续补充适配规则。

版本匹配采用语义化版本比较，支持范围表达式（>=、<、^、~）。对于无法获取版本号的 runtime（如二进制不响应版本查询），系统通过探测状态目录的实际文件结构和内容特征进行启发式匹配：读取少量样本数据，计算特征指纹（如表结构列名集合、JSONL 首行键名集合），与已注册适配器的特征指纹进行比对，选择匹配度最高的适配器。

### 六、运行时发现与代理机制

系统通过运行时描述符注册表实现新 runtime 的自动发现。注册表扫描一组预定义的搜索路径（如用户主目录下的 .mc-runtimes/ 目录、系统级 /etc/mc-runtimes/ 目录、项目工作区内的 .mc/runtimes/ 目录），收集所有符合描述符模式的配置文件。每个描述符文件解析后生成一个运行时代理对象（Runtime Proxy），该对象封装了该 runtime 的检测逻辑、会话扫描逻辑和能力查询接口。

运行时代理对象统一实现了与已有硬编码运行时相同的接口（包括检测安装状态、获取版本信息、扫描会话列表、获取内存/任务等扩展数据），但具体行为完全由描述符配置驱动。对于描述符中未声明的扩展能力（如内存扫描、定时任务扫描），代理对象返回空结果而不抛出异常，确保已接入的 runtime 即使功能不完整也不会影响系统整体稳定性。

代理对象的检测逻辑通过描述符中声明的二进制探测命令和版本正则表达式实现，无需编写代码。例如，描述符可声明 binary_probe.command 为 newruntime --version，version_pattern 为 v(\\d+\\.\\d+\\.\\d+)，系统据此执行命令并提取版本号。认证状态检测同样通过描述符声明的配置文件路径和内容匹配规则实现。

### 七、故障隔离与惰性初始化

为确保新增 runtime 的接入不会破坏已有 runtime 的管理流程，系统为每个运行时代理对象分配独立的故障边界。具体措施包括：每个代理对象的会话扫描操作在独立的 try-catch 块中执行，单个 runtime 的扫描失败不影响其他 runtime 的结果汇总；会话格式适配器的文件读取操作采用只读模式打开外部数据库或文件，避免与正在运行的 agent 进程产生锁冲突；代理对象的初始化延迟到首次访问时执行（惰性初始化），避免启动阶段因某个描述符配置错误而导致整个系统无法启动。

系统还维护一个运行时健康状态缓存，记录每次扫描的成功/失败状态和错误信息。连续多次扫描失败的 runtime 自动进入降级模式，系统以较低频率重试扫描并在界面上显示健康警告，而不反复尝试已知会失败的操作。当管理员更新描述符配置后，可通过手动触发重置操作清除缓存并重新探测。

### 八、协同工作流程

上述各组件的协同工作流程如下：

1. 管理员（或 runtime 安装程序）将新 runtime 的描述符文件放置到注册表搜索路径中。描述符文件声明了该 runtime 的身份、检测方式、状态目录、会话格式和能力清单。
2. 系统启动或按收到扫描指令时，注册表遍历所有搜索路径，解析每个描述符文件并生成对应的运行时代理对象。对于描述符格式不合法的文件，记录错误日志并跳过，不阻塞其他描述符的加载。
3. 每个代理对象惰性执行运行时检测：通过描述符声明的探测命令检查 binary 是否存在、提取版本号、检查认证配置。检测结果缓存至运行时状态对象。
4. 对于已安装的 runtime，系统读取其描述符中的会话格式声明，从适配器链中选择匹配的解析器。若涉及版本匹配，先获取实际版本号再选择对应的格式配置。适配器以只读模式打开会话数据源，将原始会话记录映射为统一模型。
5. 能力门控管理器根据描述符中的能力声明和自动验证结果，确定每个 runtime 当前可用的能力集合。仅 confirmed 能力对应的操作入口在工作台界面上展示。
6. 当用户在工作台中查看某个 runtime 的会话列表时，系统返回适配器解析后的标准化会话记录；当用户尝试执行继续会话等操作时，系统检查该能力是否为 confirmed 状态，若为 detected 或 unavailable 则返回不支持提示。
