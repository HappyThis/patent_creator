## 逐项结果

### Case 001

- 运行次数：5
- 产物成功：5 (100%)
- 已评分次数：5
- 状态分布：scored:5
- 分数：88, 88, 85, 88, 90
- 主要扣分点：
  - “接入任意新的本地 agent runtime”“无需修改核心代码”等效果表述偏绝对，实际依赖适配器接口实现和可确认格式规则。
  - “无需修改核心代码”表述偏绝对；若新 runtime 出现描述符内联规则无法覆盖的全新解析语义，仍可能需要新增解析器实现。
  - 可变形实施方式较多体现在文件格式和路径配置上，但对安全权限、只读访问、锁冲突、认证失败等实施约束的失败诊断粒度还可更细。
- 主要缺失机制：
  - 会话解析可信度分级及其向上层展示和交互控制的传递机制。
  - 单条会话级解析可信度标记：完整解析、部分解析、仅元数据、不可解析，并将该标记进入统一会话视图。
  - 对关联工作区等统一视图关键字段的处理，尤其是无法确认时的缺省与降级策略。

### Case 002

- 运行次数：5
- 产物成功：5 (100%)
- 已评分次数：5
- 状态分布：scored:5
- 分数：72, 75, 75, 70, 82
- 主要扣分点：
  - 任务状态模型与实际队列表混用。被评估方案声称队列表保存 queued/running/completed/failed/cancelled 等完整生命周期，但快照中的 cf_agents_queues 主要是待处理队列，成功或失败后会 dequeue，不能天然支持完成后查询或历史状态。
  - 取消与完成之间缺少条件终态更新规则；运行中的任务被取消后，迟到的执行成功或失败结果仍可能覆盖 cancelled/expired/cleaned 状态。
  - 取消和清理只描述删除队列或协作取消，没有说明已进入会话历史的任务如何避免误删、如何处理已取消状态与后续模型结果之间的竞争。
- 主要缺失机制：
  - 任务级输入应用 checkpoint，用于区分输入写入会话前崩溃和写入后崩溃。
  - 任务记录与会话消息之间的输入应用边界，包括 input_applied、applied_message_id、applied_at 或等价持久标记。
  - 任务记录中的 input_applied 或 message_application_checkpoint，用于标识外部输入是否已经写入会话消息。

  - 共享工作区、共享记忆和外部工具状态发生变化后的版本号、订阅或广播机制。
