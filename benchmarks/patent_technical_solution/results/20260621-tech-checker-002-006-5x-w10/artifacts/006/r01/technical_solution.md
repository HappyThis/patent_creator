## 技术方案

### 总体构思与分层模型

本方案将知识管理系统中的项目知识拆分为“共享知识内容层”和“本机运行时信号层”两类数据：共享知识内容层仍采用位于项目上下文树中的 Markdown 文件承载知识正文、标题、标签、关键词、摘要、关联关系等适合团队审阅、提交、合并和回滚的稳定信息；本机运行时信号层用于保存访问次数、检索命中次数、排序权重、近期使用时间、成熟度临时状态、衰减中间值、清理候选标记等高频变化信息。两层之间通过知识条目的稳定标识关联，而不是把每次访问、检索或排序产生的数值直接写回共享 Markdown 文件。

该分层模型的核心在于区分“知识内容是否发生变化”和“知识在本机环境中如何被使用”。当开发者整理一条项目约定、架构说明、接口限制或经验结论时，系统修改共享 Markdown 文件，使该知识可以被版本控制系统记录并在团队内共享；当检索服务命中该知识、代理读取该知识、排序算法调整该知识的热度或近期性时，系统仅更新本机运行时信号层。由此，版本控制差异主要反映真实知识内容的增删改，避免动态信号造成共享文件反复变更。

在一种实现中，共享知识内容层可对应项目目录下的 `.brv/context-tree`，每个知识节点以 Markdown 文件或索引文件表示，并可包含 YAML frontmatter 中的稳定元数据；本机运行时信号层可对应 `.brv` 下不进入 context-tree 版本控制的私有索引文件、轻量数据库或键值存储。运行时信号层只依赖共享层提供的稳定标识和必要摘要，不要求改变 Markdown 文件格式，因此可兼容既有 Markdown 知识库、已有搜索索引以及类似 Git 的分支、提交、合并、推送和拉取流程。

### 动态信号本机侧存储与稳定标识

动态信号本机侧存储单元为每个知识条目维护一条运行时记录，该记录至少包括知识稳定标识、来源分区、访问计数、检索命中计数、最近访问时间、最近命中时间、重要度或热度分、近期性分、成熟度状态、更新计数、衰减计算时间戳以及清理状态。运行时记录可以按项目、工作区、用户或知识源别名分区，使本地项目知识、跨项目只读知识源和云端共享知识源的动态信号互不覆盖。

知识稳定标识用于在共享 Markdown 文件和本机运行时记录之间建立可恢复的关联。该标识可以由 context-tree 相对路径、知识节点标题、内容摘要、创建时间或版本戳中的一种或多种组合生成。对于路径稳定的知识条目，可优先采用相对路径作为主键；对于可能重命名或移动的知识条目，可同时保存内容摘要和旧路径映射，以便在文件位置变化后识别其为同一知识条目并迁移动态信号。

本机侧运行时记录不作为共享知识内容提交，也不参与团队合并。系统可通过将运行时存储放置在 context-tree 之外、在 context-tree 的忽略规则中排除运行时文件、或由知识版本控制层显式过滤运行时文件等方式实现隔离。这样，访问次数递增、近期性衰减、排序权重变化等高频写入只影响本机排序效果，不会使共享 Markdown 文件产生无意义差异。

### 读取融合与排序计算

检索或上下文装配时，系统先从共享知识内容层读取 Markdown 文件并构建基础检索结果，例如根据标题、正文、摘要、标签和关键词计算文本相关性；随后根据每个结果的稳定标识读取本机运行时信号层中的对应记录，将访问热度、近期使用情况、成熟度状态和衰减信息与基础相关性融合，得到最终排序分、截断决策和上下文选择结果。读取融合发生在查询链路中，不要求把融合后的分数回写到 Markdown。

在一种评分实现中，系统可将 BM25 或其他文本相关性得分作为基础分，将本机运行时记录中的重要度、近期性和成熟度作为调节项，并按预设权重计算复合排序分。重要度可随访问、命中、人工整理或知识更新而上升，并随长时间未使用而衰减；近期性可依据最近访问时间或最近命中时间衰减；成熟度可表示 draft、validated、core 等层级，并对稳定核心知识给予适度加权。上述计算所需的计数、时间戳和衰减中间值均来自本机运行时信号层。

当一次检索命中或上下文读取完成后，系统将访问事件写入本机运行时信号层，例如增加命中计数、更新最近访问时间、记录本次查询与知识条目的关联，并根据策略调整重要度或成熟度临时状态。共享 Markdown 文件只作为知识内容来源保持不变。下一次查询时，融合模块再读取这些本机信号参与排序，从而既保留动态反馈对检索质量的改善作用，又避免每次检索都触发共享知识文件修改。

### 写入边界与版本控制隔离

本方案设置明确的写入边界：只有知识正文、摘要、标题、标签、关键词、关联关系、适用范围或人工确认的知识成熟结论发生变化时，才写入共享 Markdown 文件；仅由运行过程产生的访问次数、检索命中、排序权重、近期性衰减、临时成熟度判断、清理候选状态等变化，只写入本机运行时信号层。该边界使共享层表达团队需要共同维护的知识事实，本机层表达当前使用环境下的动态反馈。

在知识整理流程中，系统可先在本机层累积动态信号，再在满足人工确认、定期整理或后台合并策略时，将动态信号转化为低频的内容性结论。例如，某条知识长期被多个任务引用并经用户确认后，可将其从普通经验整理为核心约定；某条知识长期未被使用且内容已被替代时，可在知识整理操作中修改或归档共享 Markdown。该转化不是逐次访问回写，而是经策略门控后的低频内容更新。

版本控制隔离模块在提交、差异查看、合并、推送或拉取知识树时过滤本机运行时信号层，使版本控制结果只包含共享 Markdown 内容及被允许的稳定元数据。对于由系统自动生成的派生索引、摘要缓存、检索缓存或运行时 overlay，隔离模块可通过忽略规则或显式白名单防止其进入知识树差异。由此，团队成员看到的 diff 更接近真实知识内容变化，合并冲突主要发生在同一知识事实被多人编辑的场景，而不是访问计数或排序权重被不同机器反复改写的场景。

### 清理、迁移与一致性维护

为避免本机运行时信号层长期保留无效引用，系统可设置一致性维护流程。该流程扫描共享知识内容层得到当前仍存在的知识稳定标识集合，并与本机运行时记录集合比较：若运行时记录没有对应的 Markdown 知识条目，或对应条目的内容摘要、来源分区与记录不匹配，则将该记录标记为 stale；超过保留期或确认无迁移目标后，删除或归档该记录，避免检索、排序或清理流程继续引用已不存在的知识位置。

当共享 Markdown 文件发生重命名、移动或拆分时，一致性维护流程优先尝试迁移而非直接丢弃动态信号。系统可利用旧路径到新路径的变更记录、内容摘要相似度、标题匹配或前后版本戳，将旧稳定标识下的访问计数、近期性、重要度和成熟度迁移到新的稳定标识；对于一条知识拆分为多条知识的情况，可按内容片段匹配度或人工确认结果分配动态信号；对于多条知识合并为一条知识的情况，可对计数求和、对重要度和近期性取较高值或按策略加权合并。

清理决策本身也遵循分层原则。低重要度、长期未命中或近期性持续衰减的运行时记录可先在本机层被标记为归档候选，用于降低其排序权重或从本机缓存中移除；只有当知识内容确实失效、重复或被替代，并经过人工整理或后台知识合并策略确认后，才修改共享 Markdown 文件。这样可以将“本机不常用”与“团队知识应删除”区分开，避免个人使用习惯误伤共享知识库。

### 可选实施方式与边界

对于跨项目知识源或团队共享知识源，本方案可按 origin、alias 或来源仓库建立独立的运行时信号分区。只读来源的 Markdown 文件不被本机写回，但其被本机检索和使用产生的访问热度仍可保存在本机分区中，并在本机排序时参与融合。这样既保持只读知识源的写隔离，又允许不同项目、不同开发者根据自身任务形成差异化的知识排序。

在需要团队级热度或组织级知识治理的场景中，系统可以设置可选的低频聚合同步机制。该机制不上传每次访问事件，也不改写共享 Markdown 文件，而是按时间窗口对多台机器的动态信号进行聚合、脱敏和阈值过滤，生成团队级热度、稳定成熟度或归档建议等摘要信号。摘要信号可作为服务端排序参考，或者在人工确认后转化为共享知识内容层中的稳定结论。

本方案还可以兼容历史上已写入 Markdown frontmatter 的评分字段。迁移时，系统读取已有 frontmatter 中的访问计数、重要度、近期性、成熟度和更新时间等字段，将其导入本机运行时信号层，并在后续写入中停止因访问或检索而更新这些字段；对于仍需要随共享知识传播的少量稳定状态，可保留为人工确认后的知识属性。通过该兼容处理，既能利用已有评分数据，又能逐步消除高频动态字段对共享 Markdown 和版本控制状态的干扰。
