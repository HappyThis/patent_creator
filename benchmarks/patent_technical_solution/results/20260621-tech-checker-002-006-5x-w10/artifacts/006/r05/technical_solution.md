## 技术方案

### 分层存储总体架构

本方案将知识管理系统中的项目知识拆分为共享知识内容层、本机运行时信号层和派生融合视图层。共享知识内容层仍采用 Markdown 文件承载可审阅、可合并、可通过版本控制传播的知识正文，例如标题、摘要、标签、关键词、关联关系、事实、叙述说明、代码片段和经过人工确认的知识结构；该层只在知识被新增、修订、合并或审阅确认时发生内容变更，不承载因检索和访问而高频变化的运行统计。

本机运行时信号层用于保存与当前机器、当前工作区或当前用户使用行为相关的动态状态，包括访问次数、检索命中次数、最近使用时间、排序权重、重要度、近期性、成熟度调整、查询日志统计以及缓存命中情况等。该层可采用本地文件式键值存储、JSON 日志或其他不参与共享 Markdown 版本控制的派生存储实现，并与项目知识目录保持逻辑关联。这样，检索热度和排序反馈不会反复改写 Markdown 的 YAML frontmatter 或正文，避免版本控制状态被高频统计字段污染。

派生融合视图层在读取、搜索、排序或汇总时临时生成，用于把 Markdown 中的稳定知识内容与本机运行时信号组合成面向检索和问答的结果视图。该视图可包括 BM25 文本相关性分数、知识节点路径、来源标识、本机信号权重、成熟度层级、父子节点传播后的汇总分数以及查询日志聚合结果。派生融合视图不作为共享知识正文提交，只作为本机运行过程中的计算结果或可重建缓存。

### 运行时信号采集与稳定绑定

运行时信号的采集以知识文件的稳定标识为绑定基础。稳定标识可以由知识文件在 context tree 中的相对路径、知识节点类型、来源标识、本地工作区标识以及可选的内容摘要共同构成；当系统支持共享源或只读外部知识源时，稳定标识还包括 origin 或 originAlias，以区分本地知识与共享知识。对于访问命中、排序反馈和近期使用情况等事件，系统先在内存或本机信号层中按稳定标识累计，不直接把每次事件写回共享 Markdown。

在一种实现中，知识检索得到候选结果后，系统对实际返回或被用户采用的知识路径记录命中事件；命中事件被合并为批量计数，并与最近命中时间、查询任务标识、命中排名、返回分数等信息一起写入本机信号层。查询日志可以按时间生成独立 JSON 记录，并通过原子写入方式保存，以支持后续统计覆盖率、无命中查询、常用主题和高频召回文档。此类日志属于运行观测数据，默认按时间窗口和最大数量清理。

对于 Markdown frontmatter 中已经存在或历史版本兼容所需的 scoring 字段，本方案将其视为低频、可审阅的初始评分或人工确认状态，而不是唯一运行状态来源。系统可在读取时兼容这些字段，并把访问次数、近期性、重要度增量、成熟度升降等高频变化转存到本机运行时信号层；只有当动态信号经过整理、审阅或达到稳定阈值，需要沉淀为共享知识属性时，才以低频更新方式写入 Markdown。

### 读取融合与检索排序

读取知识时，系统先从共享 Markdown 内容层解析稳定内容和可审阅元数据，包括标题、摘要、标签、关键词、关联路径、事实段落和正文片段；再按知识稳定标识查询本机运行时信号层，取得访问计数、命中计数、最近使用时间、重要度、近期性和成熟度等动态状态。若某项动态状态不存在，则使用默认评分或仅采用文本相关性，保证从其他机器克隆或同步得到的 Markdown 知识仍可独立检索和阅读。

检索排序采用“文本相关性为主、运行时信号校正”的融合机制。系统可先通过 BM25 或同类全文索引在标题、路径和正文内容上获得原始相关性分数，并将该分数归一化；随后结合本机信号层中的重要度、近期性和成熟度层级计算融合分数。重要度可随访问命中或知识维护而上升，近期性可按距离上次使用或更新的时间惰性衰减，成熟度可设置 draft、validated、core 等层级并施加不同 boost，从而使常用且经过验证的知识在相同文本相关性下更靠前。

对于层级化知识目录，融合排序还可将子节点命中信号向父级摘要节点传播。具体地，当某个子知识文件在检索中获得较高文本相关性或较多访问命中时，父级目录、主题摘要或 overview 节点获得按层级距离衰减的间接信号；父级节点再结合自身的 Markdown 内容和本机信号计算排序分数。该机制使系统能够在结果中同时呈现具体知识条目和上层主题入口，而无需为了提升父级热度反复改写父级 Markdown 摘要文件。

查询日志汇总用于对融合结果进行闭环校正，但不直接改变共享知识正文。系统可周期性统计查询总量、覆盖率、缓存命中率、无命中查询、常见主题和高频召回文档；当发现某类查询长期无匹配或某些文档持续被高频召回时，仅先形成本机诊断信号或待审阅建议。经人工确认后，系统再将其转化为新增知识、摘要整理、标签修正或归档建议，从而区分“运行反馈”与“知识内容变更”。

### 清理一致性与版本控制边界

为保证共享知识文件变更后本机信号仍然一致，系统在知识删除、移动、重命名、归档、合并或来源切换时执行信号清理和迁移。若知识文件被删除或归档，系统按稳定标识查找对应的访问计数、命中历史、缓存项和查询日志引用，并将其删除、标记失效或改写为归档引用，防止已经不存在的知识继续出现在搜索或查询结果中。若知识文件移动或合并，系统可根据内容摘要、旧路径到新路径的映射、关联关系和审阅记录迁移动态信号，避免有价值的使用历史随路径变化丢失。

清理任务采用从共享内容层到本机信号层的单向一致性约束：Markdown 内容层的新增、删除、移动和归档会触发本机信号层更新；本机信号层中的高频统计和缓存失效不会反向触发共享 Markdown 的无审阅改写。对于后台整理任务生成的合并、摘要、归档或剪枝结果，系统可先放入待审阅状态，并保留撤销信息；只有经过确认的知识内容变更才进入共享 Markdown，相关本机信号则按变更映射同步迁移或清除。

版本控制边界上，共享 Markdown 内容层作为团队协作和代码审阅对象，可以继续使用分支、提交、合并和冲突检测机制；本机运行时信号层、派生索引、查询日志和缓存默认纳入本地派生目录或忽略规则，不进入共享知识提交。需要跨设备迁移个性化排序或团队级热度时，可以导出经过聚合、降采样和审阅的低频摘要，而不是同步每一次访问命中。由此，系统既保留动态信号对检索质量和知识维护的价值，又保持共享 Markdown 文件的稳定、清洁和可合并性。
