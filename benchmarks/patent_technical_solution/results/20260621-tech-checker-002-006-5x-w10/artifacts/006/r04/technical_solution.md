## 技术方案

### 分层存储总体结构

本方案将项目知识管理系统中的知识数据划分为共享知识文件层和本机运行态信号层。共享知识文件层用于承载适合团队共享、审阅和版本控制的稳定知识内容，例如主题、摘要、标签、关键词、关联关系、形成原因、原始概念、叙述性说明、事实项和代码片段等；本机运行态信号层用于承载随检索和使用频繁变化的访问次数、检索命中、近期使用时间、重要性、成熟度、排序权重和更新计数等信号。两层通过稳定知识条目标识建立对应关系，在读取和检索时融合，在写入和清理时分别维护。

上述划分使知识正文仍以 Markdown 文件保存在项目知识树中，便于开发人员以普通文本方式审阅、比较、提交、合并和同步；同时，运行过程中产生的高频动态信号不直接反复改写共享 Markdown 文件，而是优先写入本机侧表、缓存或运行目录中的信号记录。由此，知识正文的版本差异主要反映真实知识内容变化，动态信号仍可参与检索排序、清理决策和自动整理。

### 共享知识文件的稳定内容层

共享知识文件层可以采用按领域、主题、子主题和知识标题组织的目录树，每个知识条目对应一个 Markdown 文件。文件头部可包含低频且适合审阅的结构化元数据，例如标题、摘要、标签、关键词、关联条目和必要的初始评分字段；正文部分可包含形成原因、原始概念、叙述性说明、事实列表和片段等内容。该层的写入通常由新增、更新、合并、删除等知识整理操作触发，而不是由每次查询命中或每次阅读行为触发。

在一种实现中，Markdown 解析器读取 frontmatter 和正文区块时，将知识内容、关系、标签、关键词、事实、叙述文本和片段解析为统一的知识对象；生成器写回文件时只根据该知识对象生成稳定内容。对于访问次数、近期性、排序权重等高频变化字段，若需要在 Markdown 中保留，也应作为低频快照、人工确认后的成熟度结论或迁移兼容字段，而不作为每次检索立即写回的唯一状态源。

### 本机运行态信号层与更新策略

本机运行态信号层为每个知识条目建立运行记录。运行记录的主键可以由来源标识、规范化相对路径、知识条目标题、内容哈希或文件标识组合得到，以区分本地知识、共享来源知识和不同分支中的同名文件。运行记录中可以保存访问次数、命中次数、最近命中时间、最近打开时间、重要性分值、成熟度等级、近期性分值、更新次数、排序调节系数以及上次折叠到共享层的时间戳。

检索服务或阅读服务在返回结果后，不直接修改对应 Markdown 文件，而是先将命中事件累积在内存队列或本机运行记录中。系统可按时间窗口、命中数量阈值、索引重建、用户确认或提交前整理等条件批量更新运行态信号。对访问命中带来的重要性提升、近期性衰减和成熟度跃迁，可以在运行态信号层内按纯函数规则计算，使同一知识条目的排序状态随本机使用情况变化，但不造成共享文件的高频版本差异。

对于真正表示知识质量变化的信号，例如经过多次使用后确认某条知识已经从草稿成熟为核心知识，系统可以将运行态信号折叠为低频、可审阅的内容更新。折叠时生成摘要化的更新建议或成熟度调整，由知识整理流程写入 Markdown 的稳定元数据；未达到折叠条件的临时命中、短期热度和本机偏好则继续保留在运行态信号层。

### 检索读取时的融合排序

检索时，系统先从共享知识文件层读取 Markdown 内容并建立文本索引，得到标题、正文、路径等字段的文本相关性分数；随后根据知识条目标识读取本机运行态信号，将文本相关性、重要性、近期性、成熟度和来源权重融合为综合排序分数。这样，同一份共享知识文件在不同开发者本机可以根据各自使用历史形成不同排序，而文件本身保持一致。

在构建索引和执行查询时，系统还可以结合范围过滤、最低成熟度过滤、分数断崖过滤和查询词缺失检测来避免返回离题知识。对于领域、主题或索引摘要等父节点，子节点的相关性信号可以按传播系数汇总到父节点，使摘要类条目能够反映其下层知识的整体命中情况；但父节点的动态热度仍由运行态信号层记录，避免因子节点频繁命中而反复改写摘要 Markdown。

### 清理、合并和删除的一致性处理

知识条目发生删除、合并、重命名或归档时，系统同时处理共享知识文件层、本机运行态信号层和派生物之间的对应关系。删除知识文件时，删除或标记失效与该文件主键对应的运行记录，并删除该文件对应的摘要、概览等派生 sibling；合并知识文件时，将源条目的运行记录按访问次数求和、重要性取高值、近期性取高值、成熟度取更高等级等规则迁移到目标条目；重命名或移动知识文件时，将旧主键映射到新主键，避免历史使用信号丢失。

当系统无法确定某个运行记录是否仍对应现存知识文件时，可以采用孤儿信号清理策略：先根据内容哈希、旧路径重定向表或墓碑记录尝试重新绑定；重新绑定失败且超过保留期的记录再删除。派生摘要、概览文件、归档完整文件和可搜索 stub 可按是否属于核心知识、是否可搜索、是否需要同步分别处理：核心 Markdown 参与版本控制和团队合并，派生物和短期运行信号默认不参与同步，必要时可由本机重新生成。

为防止知识整理操作误删稳定内容，更新和合并 Markdown 前可以先解析旧文件与新文件的结构化内容，检测片段、关联关系、叙述字段和原始概念字段是否发生结构性丢失。若检测到丢失，系统在写回前自动合并保留旧结构，或者生成需要人工审阅的整理结果。该机制保证共享知识内容层的低频写入本身具有一致性，不因运行态信号分层而降低知识文件的可靠性。

### 可选实施方式与边界

运行态信号层可以实现为位于项目本机目录下的 SQLite 表、JSONL 日志、键值数据库或 sidecar 文件，也可以在进程内缓存近期命中并定期刷入本机持久化介质。运行记录的主键优选包含来源别名和规范化路径；对于来自共享来源的知识，系统可以将共享来源视为只读内容源，只在本机记录使用信号，不向共享来源反向写入高频命中。

在兼容已有 Markdown 评分字段的场景中，系统可以把 Markdown frontmatter 中已有的访问次数、重要性、近期性、成熟度和更新时间作为初始信号或低频快照导入运行态信号层；后续检索产生的短期变化优先保留在运行态信号层。需要提交给团队的评分变化，则通过知识整理操作折叠成少量可解释的元数据更新，而不是把每次检索产生的计数变化提交到版本控制系统。
