## 技术方案

本方案针对以 Markdown 文件承载项目知识的知识管理系统，设置“共享知识内容”和“本机运行时动态信号”分层处理机制。共享知识内容层保存适合审阅、协作和版本控制的稳定知识，例如标题、摘要、标签、关联路径、正文叙述、事实片段以及经确认的成熟度等低频元数据；本机运行时信号层保存由检索和使用过程持续产生的高频指标，例如访问次数、检索命中、近期使用情况、排序权重修正和临时热度。检索、排序、整理和清理时不单独依赖任一层，而是在读取阶段按统一身份键将两类数据融合为工作视图，从而既保留 Markdown 知识文件便于共享和追踪的优势，又避免因动态信号频繁变化导致版本控制差异被噪声淹没。

### 分层存储模型

在分层存储模型中，每个知识条目以其所在上下文树根、来源类型、来源别名和相对路径形成稳定身份键；共享源与本地源使用不同命名空间，避免不同项目中同名 Markdown 文件的运行时信号互相覆盖。共享 Markdown 文件只承载面向团队协作的知识内容和稳定元数据，派生摘要、索引清单、全文缓存和抽象文件等可再生成内容被划为派生产物，不作为动态信号的主存储位置。本机运行时信号层可以采用本地数据库、键值文件或内存加周期性落盘的方式实现，其记录至少包含知识身份键、信号类型、累计值、最近更新时间和来源版本指纹。

运行时信号层与共享知识内容层之间采用覆盖式读取关系，而非双向实时写入关系。读取知识条目时，系统先解析 Markdown frontmatter 和正文得到标题、标签、关联、关键词、知识片段及基础成熟度，再按身份键查询本机运行时信号，形成包含内容字段和信号字段的融合记录。若某知识条目来自只读共享源，本机仍可记录该条目的访问、命中和排序反馈，但这些信号仅保存在本机运行时信号层，不回写到共享源 Markdown 文件；若该条目属于本地可写源，也只有满足低频归并条件的稳定结果才允许进入共享知识内容层。

| 层级 | 主要内容 | 写入边界 | 版本控制关系 |
| --- | --- | --- | --- |
| 共享知识内容层 | Markdown frontmatter、正文叙述、事实、标签、关联和经确认的成熟度 | 由人工整理、知识合并或低频确认流程写入 | 纳入协作审阅和知识版本追踪 |
| 本机运行时信号层 | 访问次数、命中次数、近期使用、临时热度、排序反馈和衰减状态 | 由检索、阅读、整理任务在本机累积或批量更新 | 默认不进入共享 Markdown 差异 |
| 派生产物层 | 索引清单、摘要、抽象、缓存和 manifest 指纹 | 由源文件扫描或构建流程再生成 | 通过忽略规则或派生产物判定排除出协作差异 |

### 读取融合与排序计算

检索时，系统对共享知识内容层和本地知识内容层进行统一索引，并在索引文档中保留来源、相对路径、符号路径、修改时间和基础评分元数据。文本相关性可以采用 BM25 或同类全文检索分数，并对标题、路径等结构字段设置高于正文的权重；随后将原始相关性归一化，再与运行时信号层中的重要度、近期性、成熟度和访问反馈组合计算最终排序分。由此，真正匹配查询语义的知识仍由内容相关性主导，而常被使用、近期有效或已验证的知识能够在候选相近时获得合理提升。

对于层级化知识树，系统还可以将叶子知识条目的相关性向父级主题或领域摘要传播。传播时仅使用候选条目的文本相关性和父子路径关系生成父节点候选，再叠加父节点自身的成熟度和运行时信号，避免因单个子文件频繁访问而直接污染父级 Markdown 摘要。对共享来源结果，系统在输出中保留来源别名和上下文树根，排序时可给予本地结果可配置优先量，使本地项目知识在得分接近时优先出现，同时仍允许共享知识参与召回。

### 写入边界与信号归并

写入边界由“知识是否稳定”和“信号是否高频”共同决定。知识正文、事实片段、标签、关联、摘要以及经过确认的成熟度属于可共享内容，适合随 Markdown 文件提交、审阅和合并；访问次数、一次检索命中、会话内排序反馈、短期热度和由时间产生的衰减值属于运行时动态信号，默认仅写入本机运行时信号层。系统在检索返回、精确路径读取、自动整理或上下文注入时记录动态信号，但记录动作不直接触发 Markdown 文件改写。

为避免运行时信号丢失，本方案设置批量归并和阈值归并两类机制。批量归并用于将同一知识身份键上的多次访问、命中和排序反馈合并为一条累计记录，并以周期性刷新、索引重建前刷新或应用退出前刷新等方式落入本机存储；阈值归并用于判断某些动态信号是否已经转化为稳定知识属性，例如长期高频使用且多次检索命中的条目可提升基础重要度，经过人工整理或多次验证的条目可提升成熟度。阈值归并只写入低频、稳定、可解释的结果，不写入每一次访问事件。

当系统确需把稳定评分结果写回 Markdown frontmatter 时，写回流程只更新约定的低频评分字段，并保持正文内容不变；若目标文件没有可解析的 frontmatter，系统可以保持原文件不变或进入人工确认流程，避免自动重排旧格式正文。对只读共享源、外部来源或来源指纹不匹配的条目，写回流程被阻断，仅保留本机覆盖信号。通过上述边界，高频动态信号不会造成共享 Markdown 文件持续变脏，也不会在多人合并时制造大量与知识内容无关的冲突。

### 清理一致性与版本控制隔离

清理一致性以源文件身份和版本指纹为准。系统扫描上下文树时，对普通知识文件计算由相对路径、修改时间和文件大小等信息组成的源指纹，并在索引清单或 manifest 中记录当前可见知识集合；下一次索引验证、清单生成或上下文注入前，若发现源指纹变化，则重新扫描知识文件并使旧索引失效。运行时信号层也以该可见集合进行对账：身份键仍存在的信号继续保留并参与读取融合，源文件已删除、移动且无法映射或来源已移除的信号被标记为孤儿记录并清理或归档。

对派生产物和归档占位文件，系统采用独立判定规则处理。索引摘要、抽象、全文缓存和 manifest 等派生产物可由源 Markdown 再生成，因此不作为共享内容层的可信输入，也不作为运行时信号的主身份；归档占位文件可以参与检索提示，但其指向的完整内容和运行时信号应与真实源身份区分。读取融合时若发现派生产物缺失，可以回退读取原始 Markdown；若发现派生产物仍在而源 Markdown 已不存在，则以源指纹对账结果为准，避免检索结果出现已删除知识的死引用。

版本控制隔离通过两道边界实现：第一，具备协作意义的 Markdown 知识文件可以进入知识版本控制流程，而本机运行时信号库、缓存、manifest、摘要和抽象等文件通过忽略规则或派生产物过滤排除在普通差异之外；第二，共享来源按只读源处理，检索时可以融合其内容和本机信号，写入时不得把本机信号反向写入共享来源。这样，用户在查看知识版本差异时主要看到事实、叙述、关联和稳定元数据的变化，而访问热度、排序衰减、缓存重建等机器运行噪声被隔离在本机侧。
