## 技术方案

### 分层存储总体构思

本方案将项目知识管理拆分为“可共享的知识内容层”和“本机运行时动态信号层”，并在读取时生成临时融合视图。知识内容层以 Markdown 文件组织在项目的上下文树目录中，承载知识标题、标签、关键词、关联路径、摘要、正文片段、事实、规则、示例等适合人工审阅和版本控制的低频内容；动态信号层独立保存访问次数、检索命中、排序权重、成熟度状态、近期使用时间等高频变化数据。检索、查询、概览和整理流程均面向融合视图工作，而不是直接把每次访问或命中写回共享 Markdown 文件。

该分层方式的核心在于区分知识本体变化和使用行为变化：前者代表团队希望共享、评审和长期保留的项目认知，适合进入 Git 或云端同步；后者反映某一机器、某一使用者或某一阶段的检索习惯，更新频率高且具有局部性，若直接进入共享文件会造成无意义冲突、历史噪声和跨端排序污染。因此，系统以稳定标识把两层数据连接起来，在需要排序、过滤、清理或推荐时再合成可计算的运行视图。

### 共享知识文件的稳定内容边界

共享知识文件采用 Markdown 正文加结构化 frontmatter 的形式。frontmatter 可记录 title、tags、keywords、related、summary 等低频人工元数据；正文可按 Raw Concept、Narrative、Facts、Reason 或其他约定区段保存任务背景、变更说明、涉及文件、结构描述、依赖关系、规则、示例和事实条目。文件路径、归一化关系路径、标题和内容哈希共同构成知识条目的稳定定位依据，其中路径适合人工浏览和层级组织，内容哈希适合判断文件是否真实变更，标题或摘要适合检索展示。

在一种实现中，系统把可同步文件限定在上下文树内的普通知识文件，并把索引、摘要、归档全文、清单、概览等派生物排除在同步或快照之外；归档存根可作为可检索入口保留，但不作为主要同步内容。写入或合并知识时，系统优先保留已有结构化区段，避免新内容覆盖旧知识中的事实、文件引用或关系信息；仅当用户确实进行了知识内容更新时，才更新共享 Markdown。由此，共享层保持可读、可审阅、可合并，动态热度不会持续污染版本历史。

### 本机动态信号层及更新控制

本机动态信号层可采用位于本机工作区或用户配置目录中的轻量键值存储、JSON 日志、SQLite 表或等效本地持久化结构。每条动态记录至少包含知识稳定键、累计访问次数、检索返回命中次数、最近命中时间、近期性分值、重要度分值、成熟度状态和最后刷新时间。稳定键可以由来源标识、相对路径、标题指纹和内容哈希组合生成；当知识来自只读共享源时，稳定键还应包含来源别名或来源哈希，以避免不同项目中的同名路径互相覆盖。

动态信号的写入采用批量累积和延迟刷新机制。一次检索返回某知识条目时，系统先在内存计数器中累加命中，而不是立即改写文件；当索引重建、缓存过期、会话结束或达到写入阈值时，再把累积命中合并到本机动态层。重要度可随访问命中或人工更新增加，近期性可按距离最后使用时间进行指数衰减，成熟度可根据重要度阈值在 draft、validated、core 等层级之间带滞回地迁移，以避免条目在临界值附近频繁抖动。

为保证本机层可靠，动态记录写入时可使用临时文件替换、单写锁、版本号或比较更新时间等方式进行原子更新；对短时间内大量重复命中的条目可设置去抖窗口或上限，防止自动化查询把单一知识条目瞬时推高。动态层还可以保留 TTL 或衰减参数，使长期未被使用的知识逐步降低排序权重，而不删除共享 Markdown 中的知识正文。

### 读取融合与检索排序

读取融合流程包括索引构建、候选召回、动态叠加和结果回写隔离四个阶段。索引构建阶段扫描上下文树中的 Markdown 文件，解析标题、路径、正文、标签、关键词、关联路径、摘要和可选 frontmatter 字段，并过滤不应参与共享同步或检索指纹的派生物。候选召回阶段使用 BM25 或等效文本检索对标题、路径和正文建立相关性分值，并可根据路径作用域、知识类型、成熟度下限或层级节点进行过滤。

动态叠加阶段以候选条目的稳定键查询本机动态信号；若无记录，则使用默认重要度、默认成熟度和满近期性作为冷启动值。随后将文本相关性、重要度、近期性和成熟度提升因子组合为最终排序分值。例如，文本相关性用于保证结果与查询语义匹配，重要度反映长期使用价值，近期性反映最近上下文需求，成熟度提升用于优先呈现经验证或核心知识。该组合只生成检索响应中的临时分值，不改变共享 Markdown 文件。

当检索命中具体知识文件时，系统记录被返回条目的访问事件；当命中的是目录摘要或父级知识节点时，可将命中映射到对应摘要文件或代表性知识条目，也可按层级传播规则把子节点的相关性衰减传递给父节点。这样既能支持精确文件检索，也能让上层主题在其子知识频繁被使用时获得适度热度，但传播过程仍在本机动态层或融合视图中完成，避免对共享目录结构产生高频写入。

### 清理一致性与多端协同边界

清理一致性机制用于解决共享知识文件删除、重命名、归档或来源断开后，本机动态信号仍然存在的问题。系统在每次索引构建或同步完成后生成当前有效知识键集合，并与本机动态层中的键集合比较：对于当前文件系统和已配置共享源均无法解析的键，标记为孤儿记录；对于路径变化但内容哈希、标题指纹或归档指针能够匹配的记录，执行键迁移；对于归档存根指向的全文记录，保留存根可检索信号并降低或冻结全文信号。

孤儿动态记录不立即参与检索排序，可进入宽限队列；若在若干次扫描、若干天或若干次同步后仍无法与任何知识文件匹配，则删除或压缩为审计摘要。若共享 Markdown 文件被远端删除，本机信号也随之失效，检索结果不再返回死引用；若文件被重新拉取或通过内容哈希识别为同一知识，则可恢复其本机热度。该处理使运行时信号与知识文件生命周期保持一致，同时避免误删短暂不可达的共享源信号。

在多人或多机协同场景中，默认只同步共享知识文件及必要的低频人工元数据，本机动态信号不参与 Git 提交和云端共享源写入。需要团队级热度时，可另设聚合摘要通道，按较低频率输出匿名化或区间化的访问统计，并由人工或策略审核后写入共享层的低频字段；该聚合结果不替代各端本机动态层。由此，本方案同时获得可共享知识的一致性、运行排序的个性化以及清理过程的可控性。
