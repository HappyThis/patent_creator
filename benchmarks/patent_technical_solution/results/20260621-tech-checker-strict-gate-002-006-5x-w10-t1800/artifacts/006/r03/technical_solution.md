## 技术方案

### 总体分层架构

本方案面向以 Markdown 文件承载项目知识、并在检索和使用过程中产生动态评分信号的知识管理系统。系统将知识数据划分为“共享知识文件层”和“本机运行时信号层”：前者保存可人工审阅、可版本控制、适合团队同步的稳定内容；后者保存访问次数、检索命中、排序权重、成熟度、近期使用情况等高频变化信号。两层通过稳定标识建立关联，在读取和排序时临时融合，在存储和同步时保持隔离。

该分层结构的核心约束是：知识正文、标题、摘要、标签、关键词、关联关系等低频稳定信息仍由 Markdown 文件承担，便于使用 Git 类版本控制、云端同步和只读共享知识源；由搜索、阅读、排序、衰减、成熟度提升等运行行为产生的信号默认写入本机或非共享路径中的信号记录，不直接反复改写共享 Markdown 文件。这样既保留动态信号对检索质量的贡献，又避免共享文件因每次访问或排序更新而出现版本控制脏状态、合并冲突和无业务意义的元数据噪声。

### 共享 Markdown 知识层

共享 Markdown 知识层以项目的上下文知识目录为基本存储单元，每个知识条目对应一个 Markdown 文件或目录索引文件。该文件保存知识标题、摘要、标签、关键词、关联条目、事实描述、原因说明、叙述内容等可被团队成员理解和审阅的正文信息；必要时可在 frontmatter 中保留创建时间、更新时间、人工确认的重要性或成熟度基线等低频元数据，但不把每次检索命中、每次阅读访问或即时排序调整作为必须同步的文件内容。

对于来自其他项目或团队空间的共享知识源，系统在索引中记录来源类型、来源别名、来源根目录和条目路径，并将其作为只读知识源参与检索。共享知识文件层只承担跨机器、跨成员一致的知识表达；本机对共享条目的访问偏好、命中次数或近期热度不直接写回共享源文件。若共享源需要接受反馈，也应通过明确的提交、审核或低频摘要同步机制完成，而不是由普通检索过程自动修改共享 Markdown。

### 本机运行时信号层与稳定标识映射

本机运行时信号层设置在共享 Markdown 目录之外，例如设置为本机数据库、缓存文件或未纳入团队同步的状态目录。该层按知识条目记录动态信号，包括访问次数、检索命中次数、最近命中时间、由检索相关性与历史使用情况形成的排序权重、基于使用反馈推导的成熟度状态、近期使用衰减值以及待写回的增量命中计数。每条信号记录均带有更新时间和来源信息，用于区分本地知识、共享知识以及不同共享源中的同名条目。

为避免动态信号因文件名变化或共享源重名而错绑，系统为知识条目生成稳定标识。稳定标识可以由来源键、规范化相对路径、目录索引类型、内容摘要、条目标题或显式条目标识组合得到；对于本地条目可使用“本地来源键+规范化路径”作为基础键，对于共享条目可使用“共享来源键+来源别名+来源根目录+规范化路径”作为基础键。当文件内容摘要或路径发生变化时，系统可依据旧键、新键、摘要相似度和移动记录建立迁移关系，使原有访问热度在合理范围内延续，而不是简单丢弃或错误套用到无关文件。

### 检索读取融合与复合排序

检索时，系统先从共享 Markdown 知识层读取正文、标题、摘要、标签和关键词，构建或取得全文检索索引，并同时从本机运行时信号层按稳定标识读取对应动态信号。读取结果不要求反向修改 Markdown，而是在内存中形成临时融合视图：该视图包含 Markdown 的稳定内容、文件修改时间、来源信息、本机访问统计、近期衰减值、成熟度状态和排序权重。检索结束后，融合视图随本次请求释放或被索引缓存持有，动态变化仍回到本机信号层维护。

在一种实现中，检索排序采用复合评分：先由全文检索引擎计算查询与 Markdown 内容的相关性分数，再将该相关性分数与本机信号层中的重要性、近期使用值和成熟度状态进行加权融合。近期使用值可以依据文件修改时间、最近访问时间或最近命中时间做时间衰减；成熟度可以根据重要性阈值和人工确认状态在草稿、已验证、核心等等级间变化；本地知识和共享知识可以设置不同的轻量偏置，使本地项目知识在分数接近时优先展示。上述计算只改变本次排序结果或本机信号记录，不要求把每次计算后的分数写入共享 Markdown。

对于目录摘要、父节点或主题节点，系统可将叶子知识条目的检索相关性向上游节点传播，并在父节点层面再次结合对应摘要条目的动态信号计算排序分数。传播过程以原始相关性或归一化相关性作为输入，避免把已经融合过生命周期权重的分数重复叠加，从而减少父节点因子被二次放大的情况。返回结果确定后，系统仅把实际返回的条目标识计入本机待处理命中集合，为后续本机信号更新提供输入。

### 信号聚合写回与共享边界

运行时信号的写入采用增量聚合方式。系统在检索、精确路径访问或目录展开后，将被返回或被读取的知识条目标识加入待处理命中集合，并在满足触发条件时批量更新本机运行时信号层。触发条件可以是索引重建、缓存失效、进程退出、累计命中数达到阈值或时间窗口到期。批量更新时，系统对相同条目的多次命中先求和，再一次性更新访问次数、最近访问时间、重要性和成熟度，避免单次检索立即引发多次磁盘写入。

本机信号层与共享 Markdown 层之间设置写回边界。默认情况下，访问次数、命中次数、实时热度、衰减值和自动排序权重只保存在本机信号层；共享 Markdown 文件只在知识正文被整理、人工确认元数据被调整、条目被创建或结构被迁移时才发生内容写入。若需要把动态信号沉淀为团队共享信息，系统可以先按时间窗口、最小变化量和人工审核规则生成低频稳定摘要，例如“该条目长期高频使用”或“该条目已被验证为核心知识”，再通过普通知识更新流程写入 Markdown，而不是把原始访问计数逐次写入 frontmatter。

对于只读共享源，系统禁止运行时信号直接写入源文件；对于本地可写知识源，系统也可以将动态信号写回限制为显式整理操作或受控迁移操作。这样，检索行为和内容编辑行为在写路径上被分离：检索行为只更新本机状态，内容编辑行为才更新共享文件。版本控制系统因此主要呈现真实知识变更，而不会因搜索访问、排序衰减或成熟度自动波动产生大量无关差异。

### 清理一致性与异常处理

系统在索引构建或缓存有效性检查阶段执行清理一致性处理。处理时先扫描共享 Markdown 知识层得到当前有效条目集合，并与本机运行时信号层中的稳定标识集合比较：若某一信号记录对应的 Markdown 文件已删除且无法通过迁移规则匹配到新条目，则将该记录标记为孤儿记录并按策略删除、归档或快速衰减；若路径变化但内容摘要、标题或迁移记录表明其为同一条知识，则将旧信号记录迁移到新稳定标识下。

当 Markdown 内容发生较大变化时，系统不简单沿用全部历史信号，而是根据内容摘要差异、更新时间、人工确认标记和条目关系决定处理方式：若变化属于补充或重排，可保留访问热度并更新最近变化时间；若变化表示条目语义已替换，可重置部分重要性、成熟度或近期使用值；若一个条目拆分为多个条目，可按关联关系或人工迁移记录分配原信号。由此避免旧知识的热度误导新内容排序，同时避免因普通重命名或移动导致有价值的使用历史丢失。

在异常情况下，例如本机信号文件损坏、共享源暂时不可达、索引重建失败或并发检索同时产生命中，系统以共享 Markdown 知识层作为可恢复的基础事实，并将本机运行时信号视为可重建的辅助状态。信号写入可采用临时文件加原子替换、乐观版本号或追加日志后合并的方式保证本机状态一致；若信号读取失败，检索仍可退化为仅基于 Markdown 内容和默认评分的排序，待本机信号层恢复后再重新参与融合。
