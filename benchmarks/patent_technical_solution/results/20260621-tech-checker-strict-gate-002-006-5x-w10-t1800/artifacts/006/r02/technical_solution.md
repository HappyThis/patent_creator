## 技术方案

### 总体构思

本方案针对知识管理系统中“共享知识文件需要稳定可审阅”和“运行时动态信号需要持续累积”之间的冲突，采用共享知识层与本机动态信号层分离的技术构思。共享知识层继续以 Markdown 文件承载知识正文、标题、标签、关系、来源、人工确认的成熟度或稳定标识等低频变化内容，使其适合团队共享、代码审查和版本控制；本机动态信号层则承载访问次数、检索命中次数、排序补偿、最近使用时间、自动衰减热度、自动计算成熟度状态、清理标记等高频变化内容。

在系统运行时，知识内容的写入路径和动态信号的写入路径被明确隔离：只有知识正文、稳定关系或人工审阅后的稳定元数据发生变化时才更新 Markdown 文件；由检索、阅读、排序反馈、周期性衰减或自动整理产生的事件不直接改写 Markdown 文件，而是写入本机动态信号层。查询、排序、清理和自动整理等动作需要使用完整知识状态时，再以知识条目的稳定标识为连接点进行读时融合，由此既保留动态信号的技术价值，又避免共享 Markdown 文件因高频运行时变化而持续变脏。

### 共享知识层与本机动态信号层

共享知识层以项目上下文树中的 Markdown 条目为基本单元。每个条目可以包括正文内容、结构化 frontmatter、显式关系、来源信息和人工维护的标签，并通过相对路径、条目标识、内容哈希和模式版本中的至少一种或多种形成稳定引用。相对路径用于保持目录层级和人类可读性，条目标识用于在重命名或移动后维持逻辑连续性，内容哈希用于判断正文版本是否发生实质变化，模式版本用于在元数据结构升级时进行兼容读取。

本机动态信号层位于不参与团队共享提交的运行时存储区中，可以采用本地数据库、本地 JSON 文件、SQLite 表、追加式事件日志或被版本控制忽略的运行时目录实现。该层以共享知识层的稳定引用为键，保存访问计数、命中计数、最近访问时间、最近命中时间、自动更新计数、热度聚合值、衰减参数、自动成熟度状态、排序补偿值、索引指纹、清理状态和最近融合版本等信息。动态信号层的记录不替代 Markdown 条目，而是作为对应知识条目的本机 overlay 存在。

对于同一知识条目，系统在逻辑上形成“稳定知识状态”和“运行时信号状态”两个视图。稳定知识状态由 Markdown 文件直接给出，适合跨机器、跨成员保持一致；运行时信号状态由本机环境根据实际使用情况形成，允许不同机器、不同用户或不同工作区具有差异化排序和清理倾向。两层之间通过稳定引用关联，但任一运行时信号的变化均不改变共享层的内容哈希，从而使版本控制仅反映知识内容和人工审阅结果的真实变化。

### 动态信号采集、聚合与写入隔离

动态信号采集发生在知识检索、知识打开、知识引用、知识更新、排序反馈和周期性整理等运行节点。系统在这些节点生成轻量事件，例如 access、hit、select、update、decay、promote、demote、stale-check 等，并将事件写入本机动态信号层或事件日志。事件至少携带知识条目的稳定引用、事件类型、发生时间和来源上下文；对于需要区分内容版本的事件，还可以携带事件发生时的内容哈希或索引指纹。

动态信号层对事件进行增量聚合，形成可被检索和清理直接读取的指标快照。访问事件可以增加访问计数并刷新最近访问时间，检索命中事件可以增加命中计数并记录查询相关性，选择或引用事件可以提高排序补偿，周期性衰减事件可以降低长时间未使用条目的热度，自动整理事件可以依据聚合值更新本机成熟度状态或待清理状态。聚合结果可以采用阈值、滑动窗口、指数衰减或迟滞区间，避免单次事件导致排序和成熟度频繁抖动。

写入隔离规则限定为：自动产生且可能高频变化的信号只写入本机动态信号层，不写入共享 Markdown 的 frontmatter；人工确认的标签、关系、来源、重要性说明或成熟度结论属于低频稳定元数据，可以在审阅流程中写入共享 Markdown。若某一动态指标需要被团队共享，系统先将其转化为经确认的稳定结论或策略配置，再通过普通知识内容变更提交，而不是把本机事件计数直接同步到共享文件。

### 读取融合与排序决策

读取融合在查询或整理动作触发时执行。系统先按照共享知识层读取 Markdown 正文、稳定 frontmatter、关系、来源和内容哈希，再以条目标识、相对路径或内容哈希查找本机动态信号快照；若动态信号记录不存在，则在内存中使用默认值参与本次计算，必要时在动态信号层延迟创建记录，但不因缺失动态记录而回写 Markdown 文件。

融合后的知识视图包括静态相关性和动态使用价值两个部分。静态相关性可以由全文检索分数、关键词匹配、目录位置、显式关系或来源权重得到；动态使用价值可以由访问次数、命中次数、最近使用时间、衰减后热度、自动成熟度状态和本机排序反馈得到。系统基于融合视图生成检索排序、结果截断、知识推荐、清理候选和自动整理建议，而不把融合后的临时分数写回共享 Markdown。

### 清理一致性与跨源边界

清理一致性通过共享知识层扫描、动态信号层标记和索引清理协同实现。系统定期扫描或监听 Markdown 文件变化，得到当前有效条目的稳定引用集合，并与动态信号层中的记录集合进行比对。仍存在且内容哈希未变化的条目继续复用原有动态信号；已删除的条目对应动态记录被标记为 tombstone 或孤儿记录，并从检索索引、查询缓存和推荐候选中移除，避免源文件删除后仍出现死引用。

当 Markdown 条目发生重命名或移动时，系统优先根据条目标识迁移动态记录；没有条目标识或条目标识不可用时，可以根据内容哈希、原路径到新路径的文件系统事件或相似度阈值判断是否为同一知识条目。若判断为同一条目，则保留访问、命中和热度等累计使用信号，并更新动态层中的当前路径；若判断为新条目，则为其建立新的动态记录，原记录按孤儿记录进入清理流程。

当 Markdown 条目的内容哈希发生变化时，系统区分累计使用信号和内容版本绑定信号。访问计数、历史命中次数和长期热度等可反映知识条目持续价值的信号可以保留；与旧内容强绑定的摘要向量、索引片段、查询缓存、摘录位置或排序解释应被失效并重新生成。通过这种区分，系统既不会因正文小幅更新丢失长期使用价值，也不会把旧内容的索引和解释错误地应用于新内容。

跨源边界按照来源权限执行。对本地可写知识树，人工确认后的稳定知识变更可以写回 Markdown；对共享源、只读源或外部引用源，系统只读取其 Markdown 内容并在本机保存动态 overlay，不向源文件写入访问计数、命中次数、排序权重或自动成熟度。不同来源的动态 overlay 可以按来源标识隔离存储，防止同名路径在不同源之间混淆。

### 可选实施方式

在一种实现中，本机动态信号层采用追加式事件日志和聚合快照结合的方式：运行事件先顺序写入日志，后台任务按条目标识聚合为快照，查询时优先读取快照，必要时补算尚未聚合的日志片段。该方式适合高频写入场景，可以降低随机写入成本，并在异常退出后通过重放日志恢复动态信号。

在另一种实现中，本机动态信号层采用 SQLite 或键值数据库保存，每个知识条目对应一条或多条记录。事件写入时直接更新计数字段和时间字段，周期性任务计算热度、近期性和自动成熟度。该方式适合需要事务、并发访问或跨进程共享的本机运行环境。

在又一种实现中，系统允许用户将部分本机动态信号提升为共享知识层中的稳定结论。例如，某条知识长期被多个成员高频引用后，系统可以生成“建议提升为核心知识”的整理建议；只有在人工确认后，才把对应的标签、成熟度结论或说明写入 Markdown。提升后的共享结论不再携带具体访问计数和本机排序反馈，从而保持共享文件的可读性和审阅价值。
