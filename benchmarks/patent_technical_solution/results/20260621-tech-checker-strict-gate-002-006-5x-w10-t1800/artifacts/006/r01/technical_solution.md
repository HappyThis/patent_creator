## 技术方案

### 总体分层构思

本方案将知识文件的稳定内容与检索运行过程中产生的动态信号分层处理。稳定内容层以可审阅、可同步、可版本控制的 Markdown 文件承载领域知识、标题、标签、关键词、关联关系和摘要；动态信号层记录访问命中、更新次数、重要度、近期性、成熟度等会随检索和使用频率变化的状态。两层通过知识条目的规范化相对路径、符号路径及来源标识建立关联，使动态信号能够参与检索排序和生命周期管理，但不需要把每一次访问或排序变化都即时写入共享知识正文。

该分层结构的核心在于：Markdown 知识文件表达团队共同认可的语义内容，动态信号表达某一工作区、某一用户或某一运行周期内对知识条目的使用反馈。检索服务在建立索引或执行查询时读取两类数据并进行临时融合，排序结果可以反映当前使用偏好；共享文件在没有真实知识变更时保持稳定，从而减少无意义 diff、合并冲突和跨成员偏好污染。

### 共享 Markdown 知识层

共享 Markdown 知识层以 context tree 的目录层级表示领域、主题和子主题，以 Markdown frontmatter 表示可机器读取的结构化元数据。frontmatter 可以包括标题、标签、关键词、关联关系、摘要以及兼容性评分字段，正文部分记录事实、叙述、原始概念、原因说明或代码片段等稳定知识内容。检索索引以这些文件为基础提取标题、正文、路径和符号路径，形成既可供人工审阅又可供机器检索的知识载体。

对于来自本项目以外的知识源，系统为每个来源设置来源键、别名和来源根路径，并在符号路径中加入来源前缀，以避免同名主题在本地知识与共享知识之间发生路径冲突。外部来源可作为只读引用参与检索，本地 context tree 则作为可写入、可 curate、可提交的知识主体。该隔离边界使团队共享知识、其他项目知识和个人本地知识能够在同一检索界面中联合出现，但不会因本地访问反馈而直接改写只读来源。

### 本机动态信号层

本机动态信号层用于保存随使用过程变化的知识生命周期数据。动态信号可以包括访问次数、更新次数、重要度、近期性、成熟度层级、最后访问时间和最后更新时间等，其中访问次数反映知识条目被检索结果采用的频率，更新次数反映 curate 或合并等知识维护行为，重要度和近期性用于表达该条目在当前上下文中的排序价值，成熟度层级用于区分草稿、已验证和核心知识。

在一种实现中，动态信号可以作为 Markdown frontmatter 中的评分字段保存，以兼容纯文件形态的 context tree 和离线检索；在另一种实现中，也可以将动态信号写入本机状态文件、轻量数据库或索引缓存，并仅在需要迁移、备份或显式同步时导出到 Markdown。无论采用哪种持久化方式，动态信号均以知识条目的相对路径、来源键和符号路径作为关联键，从而保证评分状态能够随索引重建重新附着到对应知识条目。

动态信号层还可以设置默认评分和层级迟滞规则。新建或未评分知识条目获得默认访问次数、默认重要度、默认近期性和草稿层级；当访问反馈或 curate 更新提高重要度后，成熟度可以从草稿提升为已验证或核心；当条目长期未被使用时，近期性和重要度按时间衰减。成熟度升降采用不同阈值，以避免条目在临界分数附近因少量访问或少量衰减而频繁改变层级。

### 检索融合与排序控制

检索服务在执行查询时先基于 Markdown 文件构建文本索引，并从标题、正文和路径中取得文本相关性分数。对原始文本相关性进行归一化后，再与动态信号层中的重要度、近期性和成熟度层级进行复合计算，得到最终排序分。由此，查询词匹配程度仍是排序的主要依据，而高价值、近期被使用或已被验证的知识条目能够在相关性接近时获得优先展示。

复合排序可以采用加权模型，例如将文本相关性、重要度和近期性分别按预设权重组合，并对成熟度层级施加倍率修正。近期性衰减优先在检索时懒计算，不必因时间流逝而周期性写回文件；重要度也可以按天数施加温和衰减，使长期未使用的条目逐步让位于更活跃的知识。对于本地知识与共享来源知识分数接近的情形，还可以加入本地来源优先系数，使当前工作区的专属知识在不压倒明显更相关共享知识的前提下优先返回。

当检索结果命中子主题或普通知识条目时，系统还可以将子节点的相关性信号向父级领域节点、主题节点或摘要节点传播。父节点传播只传递文本命中和子树活跃度所代表的聚合信号，父摘要自身的生命周期评分单独计算，避免对子节点已经融合过的评分重复叠加。这样既能返回具体知识条目，也能在用户查询较宽泛时返回合适的上级主题入口。

### 访问反馈批处理与写放大控制

访问反馈不在每次结果展示时立即写入 Markdown 文件，而是先累积到内存中的待处理命中表。待处理命中表以知识条目的相对路径为键、以命中次数为值；同一检索周期或多个连续检索周期内对同一条目的命中被合并计数。只有在索引即将验证、重建、进程空闲、命中数量达到阈值或用户显式触发同步时，才将待处理命中批量刷新到持久化状态。

批量刷新时，系统读取目标条目的当前评分状态，将累计命中数一次性折算为访问次数增量和重要度增量，并重新计算成熟度层级。若采用 frontmatter 兼容模式，刷新过程只替换 frontmatter 中的评分字段，不改写 Markdown 正文，从而避免因访问反馈影响人工维护的知识内容；若采用独立本机状态模式，刷新过程只更新本机状态文件或数据库，不产生 context tree 文件改动。单个文件刷新失败时可以跳过该条目并继续处理其他条目，使检索反馈机制不阻塞正常查询。

对共享来源或只读来源的命中反馈，系统可以采用来源隔离策略：仅在本地动态信号层记录该来源条目的本机访问偏好，不向共享来源文件写回；当结果为本地 context tree 条目时，才允许按照配置写入本地评分字段。该策略保证团队成员可以从共享知识受益，同时各自的检索习惯不会直接改变他人看到的共享 Markdown 文件。

### 一致性清理与版本控制隔离

为避免检索结果返回已经失效的知识，系统可以在索引构建、空闲维护或知识整理阶段执行一致性清理。清理过程检查知识条目中记录的源文件路径、位置引用、摘要子节点哈希或清单信息；当源文件已删除、引用位置不存在或摘要所依赖的子节点发生变化时，将该条目标记为失效、降级为归档入口、重新生成摘要，或从可检索索引中移除。这样能够减少死引用进入查询结果，并使动态评分不会继续提升已经不可验证的知识。

为避免索引缓存、摘要清单、快照文件等派生产物污染知识版本历史，context tree 可以维护专用忽略规则。版本控制命令运行前检查该目录下的忽略配置，若缺少派生产物模式则自动补齐；检索索引构建时也跳过全文缓存、抽象文件、清单文件或其他不应作为知识正文的派生产物。通过该机制，版本控制 diff 主要反映人工确认的知识内容变化，而不是运行时缓存、访问反馈或工具生成物变化。

上述分层、批处理、检索时融合和一致性清理共同形成闭环：稳定知识负责表达可共享事实，动态信号负责表达本机使用反馈，检索阶段临时融合两者，维护阶段清除失效引用并隔离派生产物。由此可以在保留访问反馈、成熟度和近期性对排序价值的同时，降低共享 Markdown 文件的写放大和合并噪声，提高团队知识库的可审阅性、同步稳定性和检索结果可靠性。
