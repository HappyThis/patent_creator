## 技术方案

### 总体分层架构

本方案将基于 Markdown 的项目知识管理划分为“共享知识文件层”和“本机运行时信号层”。共享知识文件层仍以 `.brv/context-tree/` 等目录中的 Markdown 文件承载领域、主题、子主题和知识条目，文件内容包括标题、正文、标签、关联条目、来源、人工确认的低频状态等稳定知识信息，适合被审阅、同步和版本控制。本机运行时信号层独立保存访问次数、检索命中次数、最近使用时间、排序增益、热度、衰减值以及临时成熟度估计等高频变化数据，不直接改写共享 Markdown 文件。

上述两层在逻辑上共同形成知识条目的可用视图：Markdown 文件提供可共享、可追溯、可合并的静态知识事实，本机运行时信号提供与当前机器、当前工作区、当前使用者相关的动态反馈。系统在检索、排序、推荐、清理或自动整理时读取融合后的视图，而不是把所有运行反馈写回 Markdown frontmatter。由此，知识内容的真实变更与运行噪声在存储上被隔离，同时动态信号仍可参与本地智能化决策。

| 层级 | 主要内容 | 更新频率 | 版本控制关系 |
| --- | --- | --- | --- |
| 共享知识文件层 | Markdown 正文、标题、标签、关联关系、来源、人工确认状态 | 低频，通常由人工编辑或审阅触发 | 参与团队同步、审阅和合并 |
| 本机运行时信号层 | 访问次数、命中次数、最近使用时间、热度、排序增益、临时衰减或成熟度估计 | 高频，随检索、访问、整理任务变化 | 默认位于本机缓存或运行时目录，不参与普通提交和合并 |

### 写入隔离与标识绑定

每个知识条目配置稳定条目标识，用于把共享 Markdown 文件与本机运行时信号绑定。该稳定条目标识可以由 Markdown 文件的规范化相对路径、frontmatter 中的固定标识、内容指纹或其组合生成；当存在人工维护的固定标识时优先使用固定标识，当不存在固定标识时使用规范化路径和内容指纹形成可重建的派生标识。动态信号以该条目标识为键保存，避免仅依赖绝对路径导致跨工作区、worktree 或共享来源同步时无法匹配。

本机运行时信号可以存放在运行时数据库、JSONL 文件、键值索引或搜索索引伴生文件中，并置于 `.brv/runtime`、`.brv/cache` 或其他被忽略的本地目录。系统在发生知识访问、检索命中、排序反馈、自动整理或清理评估时，只更新该本地信号层；只有当用户显式编辑知识内容、审阅确认成熟度，或执行受控的统计回写任务时，才允许修改共享 Markdown 文件。该写入隔离机制使高频 accessCount、hitCount、lastUsedAt、rankWeight 等变化不会反复制造版本控制差异。

对于只读 shared source、外部 Markdown 目录或跨项目知识源，本机运行时信号进一步以来源别名、来源根路径指纹和条目标识组成命名空间。这样，同一个共享知识条目在不同机器或不同项目中可以积累各自的使用反馈，而不会要求使用者对只读来源产生写入权限，也不会把一个项目的临时热度错误传播为全团队的知识内容变更。

### 读取融合与排序计算

系统执行知识检索或上下文装配时，先从共享知识文件层读取候选 Markdown 条目的正文、标题、路径、标签和关联关系，并通过 MiniSearch 或 BM25 类全文索引得到文本相关性分数；随后按照条目标识读取本机运行时信号快照，将访问次数、命中次数、最近使用时间、热度、排序增益和成熟度权重合并为候选条目的运行时特征。融合过程只在内存视图或查询临时结果中完成，不要求把运行时特征写回 Markdown 文件。


在一种排序实现中，可以按照 [式(1)](formula:blk_000022) 计算候选条目 $i$ 的综合得分。其中，$BM25_i$ 来自共享 Markdown 内容的文本相关性，$Importance_i$、$UsageHotness_i$、$Recency_i$ 和 $MaturityWeight_i$ 来自融合视图中的本机动态信号或人工确认状态，$W_r$、$W_i$、$W_u$、$W_t$、$W_m$ 为可配置权重。若某个条目尚无本机动态信号，系统使用默认初始值参与计算，使共享 Markdown 文件在无本地历史的机器上仍能被正常检索和阅读。

融合后的运行时特征还可用于知识自动整理和清理决策。例如，长期未被命中且相关性较低的条目可进入候选清理队列；近期频繁命中但尚未审阅的条目可提示用户确认是否提升成熟度；与多个高热度条目存在显式关联的条目可在检索结果中获得层级传播增益。上述决策均基于融合视图输出建议或本机排序结果，只有经过人工确认或低频批处理后，才把稳定结论写入共享知识文件层。

### 同步共享边界与清理一致性

版本控制、代码审阅、团队同步和合并流程默认仅处理共享知识文件层。共享 Markdown 文件中保留的是知识正文、人工维护的标签、关联关系、来源信息和经确认的低频状态；本机运行时信号目录被排除在普通提交、拉取、合并和审阅之外。多人协作时，不同成员的访问历史、检索命中和临时排序权重不会相互覆盖，也不会在合并请求中淹没真正的知识内容变更。

当确有必要利用团队级运行反馈时，系统可以提供受控回写机制：先在本机或服务端对动态信号进行聚合、去标识化和阈值过滤，只保留达到稳定条件的低频统计或人工确认状态；再通过批处理任务生成可审阅的 Markdown 变更。该机制把“高频事件记录”和“可共享知识结论”分成两个阶段，避免每次检索或访问都触发共享文件变更。

为保持清理一致性，系统定期扫描共享知识文件层，生成当前有效条目标识集合，并与本机运行时信号层的键集合进行比对。若某一动态信号键已无对应 Markdown 条目，系统将该信号标记为孤立记录并按策略删除、归档或延迟保留；若检测到 Markdown 条目被重命名或移动，则通过固定标识、旧路径映射或内容指纹把原有动态信号迁移到新的条目标识下；若动态信号文件缺失或损坏，则丢弃该本机运行时反馈并回退为默认排序值，不影响共享知识文件的可读性和可同步性。
