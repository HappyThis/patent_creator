## 技术方案

### 总体分层架构

本方案将知识管理系统中的知识内容与运行时反馈信号解耦，形成“共享 Markdown 知识层—本机运行时动态信号层—读取融合视图层—清理整理执行层”的分层架构。共享 Markdown 知识层用于承载适合人工审阅、团队共享和版本控制的稳定知识；本机运行时动态信号层用于记录随查询、检索、访问和整理过程频繁变化的局部信号；读取融合视图层在查询或整理任务开始时临时合并两类数据；清理整理执行层只在满足整理触发条件并经过必要校验时，才把具有语义价值的变更写回 Markdown 文件。

上述架构的核心不是删除访问次数、检索命中、排序权重、近期使用情况等动态信号，而是改变其存储边界和生效方式：动态信号默认不直接改写共享 Markdown 文件，而是在本机侧按知识条目、来源和版本进行累积；当需要检索、排序、预取上下文、识别陈旧条目或生成整理候选时，再与 Markdown 中的正文、标签、关键词、关系和成熟度等稳定信息共同参与计算。由此，系统既保留动态信号对自动化处理的价值，又避免每次访问或命中都造成共享知识文件产生版本控制噪声。

### 共享 Markdown 知识层的稳定字段

共享 Markdown 知识层以项目上下文树中的 Markdown 文件作为主要载体，每个知识条目对应一个可读、可审阅、可随项目提交的文件。该层适合保存正文内容、标题、摘要、标签、关键词、相关条目、来源说明、人工确认的成熟度以及经整理后稳定下来的重要性等低频语义字段。这些字段描述知识本身的含义和结构关系，能够被代码审查、版本比较、团队合并和远端同步直接理解。

对于访问次数、查询命中次数、最近一次使用时间、短期热度、实时排序修正值等高频变化字段，系统默认不将其作为共享 Markdown 的持续写入内容。若某些动态结果已经经过一段时间聚合并被整理流程确认为知识生命周期属性，例如某条知识长期稳定处于核心知识或长期过期状态，则可以通过低频快照方式写入 Markdown frontmatter 或正文摘要；写入对象应是经确认的语义状态，而不是单次查询、单次命中或短周期波动计数。

### 本机运行时动态信号层

本机运行时动态信号层部署在使用者本地工作区或本机状态目录中，用于记录与当前机器、当前用户、当前项目工作流相关的变化信息。该层可以包括查询日志、检索结果摘要、命中文档路径、命中分数、访问事件、更新时间、最近使用窗口、排序反馈、未命中主题、清理候选标记以及自动整理执行状态等。其数据可以采用本机 JSON 日志、状态文件、轻量索引或内存批处理队列保存，并通过临时文件重命名、串行化锁或批量刷新方式降低并发覆盖和写放大风险。

为了使本机信号能够在知识文件重命名、移动、共享源接入或多提供者检索时仍然可用，动态信号记录不只依赖裸文件路径，而是关联知识条目的稳定标识、来源标识、相对路径、内容指纹或上下文树版本指纹。来源标识用于区分本地上下文树、共享上下文树和外部 Markdown 知识源；内容或版本指纹用于判断信号是否仍适用于当前文件内容。当路径变化但内容指纹或迁移映射仍可匹配时，系统可以迁移或合并对应信号；当条目删除、归档或指纹差异超过阈值时，系统将对应信号标记为失效、墓碑状态或仅保留为历史审计记录。

### 读取融合与排序评分

读取融合视图层在执行查询、搜索、上下文预取或整理候选生成时工作。系统首先从共享 Markdown 知识层读取正文、标题、标签、关键词、关系、成熟度和低频语义评分，并从本机动态信号层读取与同一知识条目及来源对应的访问、命中、近期使用和查询覆盖信号；然后构造仅在本次计算中生效的融合记录或内存索引。该融合记录可以被检索、排序和整理流程使用，但不会因为一次读取或一次排序变化而立即反向改写共享 Markdown。

在一种实现中，检索基础分数由 Markdown 正文、标题、标签和关键词经过 BM25 或同类全文检索算法得到；融合分数再叠加重要性、成熟度、近期使用、访问频次、命中频次和来源权重等因素。系统可以对文本相关性分数进行归一化，对近期使用信号设置时间衰减，对成熟度设置分层增益，对本机频繁使用但文本分数略低的条目提供有限提升，并对得分差距过大或明显越界的结果进行过滤。

当系统同时接入本地上下文树、共享上下文树和其他 Markdown 知识源时，各来源可以先独立生成候选结果，再通过倒数排名融合、加权排名融合或其他结果融合方式形成跨来源候选集。融合后仍以来源标识和条目标识保留贡献来源，随后再叠加本机动态信号进行个性化排序。这样能够使共享知识保持一致的文本基础，同时允许不同使用者基于各自的历史访问和查询需求形成不同的本机排序视图。

### 清理整理与一致性维护

清理整理执行层用于把动态信号转化为可审阅的知识维护动作，而不是把动态信号本身直接写入共享文件。系统可以根据本机动态信号识别高频命中但内容分散的条目、长期未命中或长期低使用的条目、查询日志中反复出现但未被覆盖的主题，以及成熟度与实际使用情况不匹配的条目，并据此生成合并、摘要、归档、补充或删除候选。候选动作只有在满足时间间隔、活动次数、任务队列空闲和互斥锁等触发条件后才进入整理流程。

在整理流程中，系统先建立整理前状态快照，再根据候选动作执行合成、合并、摘要刷新、陈旧传播或归档处理；对于会改变共享 Markdown 语义内容的操作，优先进入审阅、日志记录和可撤销路径。整理完成后，系统更新 manifest、摘要或索引指纹，使后续查询能够基于新的知识结构重建融合视图。若整理过程中发生部分失败、锁竞争或内容指纹不匹配，系统保留原 Markdown 内容和本机信号记录，并将对应候选标记为待复核或失效，避免把过期动态信号错误应用到已经变化的知识条目上。

对于共享源或只读知识提供者，清理整理执行层默认不直接写入来源文件，而是将本机观察到的访问、命中、排序和清理建议保存在消费者本机，并在需要时生成建议补丁、审阅任务或本地派生摘要。对于可写的本地上下文树，系统也应区分语义更新和运行时计数更新：语义更新可以进入版本控制和团队共享，运行时计数更新则继续留在本机信号层或以低频聚合快照形式固化。

### 可选实施方式与边界条件

在单机私有知识库场景下，可以配置较宽松的回写策略，例如将经过时间窗口聚合后的重要性、成熟度或长期热度快照写入 Markdown frontmatter，以便在备份或迁移后保留部分生命周期信息。在团队共享或远端同步场景下，回写策略应更严格：访问次数、短期命中、个人排序偏好和近期使用热度只保存在本机，只有经过整理确认并具有团队语义价值的摘要、标签、关系、成熟度或正文调整才进入共享 Markdown。

本方案还允许按信号类型设置不同保留期限和隐私边界。查询原文、用户偏好和本机访问序列可以仅在本机短期保存或脱敏聚合；命中文档频次、未覆盖主题和整理候选可以保存较长时间用于知识库维护；跨来源融合结果应保留来源、路径和版本指纹，以便在共享源更新、提供者只读、文件被归档或知识条目合并时进行一致性校验。通过上述边界设置，系统能够在保持 Markdown 知识库可共享、可审阅、可版本控制的同时，继续利用运行时动态信号提升检索、排序和自动整理质量。
