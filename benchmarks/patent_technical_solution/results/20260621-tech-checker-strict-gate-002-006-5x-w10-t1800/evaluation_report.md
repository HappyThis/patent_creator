### Case 002

- 状态分布：scored:5
- 分数：82, 94, 92, 93, 96
- 主要扣分点：
  - completed、failed、cancelled 等终态写入虽然有“终态优先”和取消晚于终态的表述，但缺少明确的条件终态更新规则，迟到完成事件不得覆盖已取消或已清理状态的保护机制不够硬。
  - 任务状态很多，但状态迁移保护规则不够完整，更多是顺序流程描述，而不是可防并发竞态的状态机。
  - 任务记录中的“输入是否已应用”边界在恢复章节有体现，但在字段模型中没有作为独立必要字段突出，导致接收记录与会话污染边界的专利特征还可更凝练。
- 主要缺失机制：
  - 任务领取的 compare-and-set 或事务更新规则：仅当任务仍为已接收/待执行且未被取消时，才能领取为执行中并绑定执行者或 requestId。
  - 对迟到完成事件与取消/清理竞争时的条件终态更新谓词可再具体化，例如仅从 running/cancelling 的允许前态转入终态。
  - 对长时间执行中但输入已应用任务的失败、诊断或人工介入状态边界还可更明确。
