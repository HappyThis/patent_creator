## 技术方案

### 总体构思与对象关系

本方案在既有服务端持久对象型 chat agent、子 agent 路由、流式输出和恢复机制之上，增加一层“保留式流式子 agent 工具编排”机制。用户仍只连接并观看一个主 agent 会话；主 agent 在一次请求处理中可以将研究、规划、比较、总结等子任务分派给一个或多个专门子 agent。每个子 agent 不是主会话中的临时函数，而是由主 agent 按运行标识创建或定位的独立持久子对象，具有独立消息、模型调用、工具集合、流式片段、存储和可恢复执行状态。

主 agent 与子 agent 之间采用“执行归子 agent、观察归主 agent”的分离结构。子 agent 负责实际推理、工具调用、消息持久化和流式片段保存；主 agent 仅维护轻量的子运行登记、转发子 agent 的流式事件、在父会话中合成生命周期状态，并在子 agent 完成后将摘要或结构化结果作为工具结果返回给主 agent 的后续推理。这样既保留了用户单一会话入口，又避免把长任务、并行任务和子任务上下文压入主 agent 的一次模型调用或内存态工具函数。

主 agent 可以通过两类入口启动子运行：其一是确定性编排入口，由应用代码在报告生成、批量比较、后台任务或多阶段流程中显式指定子 agent 类型、输入和显示顺序；其二是模型工具入口，将某个 chat-capable 子 agent 包装成可被主 agent 选择的工具，工具执行时自动继承父工具调用标识和取消信号。两类入口共享同一运行登记、事件协议、恢复、取消和清理机制，从而使模型驱动分派和程序化分派在同一父会话视图中呈现。

### 保留式子运行注册与上下文隔离

主 agent 在启动子 agent 前先写入父侧子运行登记项，登记项至少包含稳定运行标识、父工具调用标识、子 agent 类型、输入预览、显示顺序、状态、摘要、错误信息、显示元数据、开始时间和完成时间。该登记项不同于底层子对象存在性登记：底层登记回答“该子对象是否存在”，子运行登记回答“该子对象因父会话中的哪次工作而存在、其事件应渲染到哪个父工具调用下、恢复时应如何合成时间线”。

运行标识作为贯穿父侧登记、子 agent 名称、子侧执行映射、回放、钻取、取消和删除的稳定关联键。子 agent 内部另行保存运行标识到 chat 请求标识、流标识和子侧状态的映射，使编排层标识不必与一次 chat 请求或一个底层流强绑定。即使父 agent 在子 agent 启动后、记录内部请求标识前发生重启，也可以根据运行标识向子 agent 查询已持久化的映射并恢复父侧登记。

子 agent 的执行上下文与主会话隔离：子 agent 具有自己的消息历史、系统提示、工具能力、推理流和持久化表；主 agent 只接收经协议封装的流式片段、生命周期事件以及最终摘要或结构化输出。默认登记项只保存输入预览而不保存完整输入，完整输入、敏感文件内容或凭据是否另行保存由应用策略决定。通过该隔离方式，长时间研究任务和多子 agent 并行任务不会污染主 agent 的上下文窗口，也便于用户后续单独查看某个子 agent 的完整过程。

| 状态 | 是否终态 | 含义 |
| --- | --- | --- |
| starting | 否 | 父侧登记已写入，子 agent 尚未确认开始执行。 |
| running | 否 | 子 agent 已开始执行，父 agent 可实时观察或回放已保存片段。 |
| completed | 是 | 子 agent 正常完成，父侧可返回摘要或结构化输出。 |
| error | 是 | 子 agent 执行失败、流错误或结果校验失败。 |
| aborted | 是 | 父侧或用户显式取消该子运行。 |
| interrupted | 是 | 父侧恢复时无法安全继续观察或确认执行，保留已发生片段并标记中断。 |

### 流式事件桥接与恢复回放

子 agent 在执行 chat 任务时，将自身产生的聊天流片段作为权威持久事件源保存到子 agent 存储中；主 agent 作为观察者读取该流，并向父会话连接广播统一的子运行事件帧。事件帧包括开始、片段、完成、错误、取消和中断等类型，并携带运行标识、父工具调用标识、每个运行内单调递增的序号、是否为回放事件以及必要的显示元数据。片段体保持为子 agent 原生的 UI 消息片段编码，主 agent 不重新发明文本、推理、工具调用和工具结果的语义，从而降低协议转换造成的信息损失。

父会话客户端根据父工具调用标识将多个子运行分组，根据显示顺序排列同一父工具调用下的兄弟子运行，并以运行标识和序号进行去重。这样，当主 agent 同时启动多个研究或比较子 agent 时，先返回片段的子 agent 不会改变预期展示顺序；当页面刷新导致同一片段既通过实时连接到达又通过回放到达时，客户端也能稳定地只呈现一次。没有父工具调用标识的命令式或后台子运行被归入未绑定运行列表，仍可在同一主会话视图或任务面板中展示。

恢复时，主 agent 读取父侧非清理的子运行登记，先根据登记合成开始事件，再按运行标识从对应子 agent 读取已保存的流片段并逐片段回放，最后根据登记状态或子侧检查结果合成完成、错误、取消或中断事件。若子 agent 已完成，父侧登记更新为完成并返回已保存摘要；若子 agent 失败或被取消，父侧登记记录相应终态；若父 agent 丢失原始实时观察者且当前运行仍在执行，而运行环境尚不支持从任意序号重新实时追尾，则父侧将该运行标记为中断并保留已回放片段。由此，刷新页面或短暂断网后，用户仍能看到已经发生的子 agent 过程，并能区分真实失败、显式取消和观察链路中断。

### 幂等、并发、取消与清理控制

为处理重复请求和恢复重试，子运行启动操作按运行标识实现幂等。主 agent 如果发现父侧登记已有相同运行标识，则不再创建新的子对象或发起新的推理任务；若该运行已处于终态，直接返回已有结果；若仍处于非终态，则根据当前观察能力回放已保存片段或重新附着观察流。子 agent 侧的启动接口同样按运行标识检查已有子侧映射，存在时返回既有状态，避免因网络重试、父 agent 重启或多个浏览器标签同时触发而产生重复 LLM 调用。

并发控制采用“同一运行单执行、多运行可并行”的规则。一个运行标识对应的子 agent 在框架驱动的执行期间持有执行声明，同一运行的再次启动只返回既有检查结果，用户通过钻取界面向该子 agent 追加消息时被延迟或拒绝，以免与正在进行的框架驱动推理交错；不同运行标识对应不同子 agent 对象，可以由主 agent 并行启动并分别流式观察。父侧事件序号按子运行独立维护，兄弟子运行之间依靠父工具调用标识和显示顺序进行汇聚。

取消控制从父会话向子 agent 显式传播。父请求、父工具调用或用户停止操作产生取消信号后，主 agent 以运行标识调用子 agent 的取消接口；子 agent 将该取消转换为本次推理的中止控制信号并传入消息保存和模型推理流程，随后停止实时观察并把运行状态更新为取消。取消操作是幂等的，已完成或已失败的运行不会被迟到的取消请求改写为取消状态。

清理采用先终止后删除的保留策略。默认情况下，子运行完成后父侧登记和子 agent 存储继续保留，以支持刷新回放、钻取查看和后续审计；当应用清空聊天历史、执行保留期清理或用户删除某个子运行时，系统先检查运行状态，若仍为启动中或运行中则先发起取消并等待其进入终态，再删除父侧登记和对应子 agent 对象。该顺序避免出现无登记、无观察者但仍在消耗模型资源的孤儿子运行。

### 访问控制与后台子运行

子 agent 的网络可达性通过既有嵌套子 agent 路由实现，但运行标识本身不作为访问凭证。用户或开发者需要钻取查看某个子 agent 时，仍通过主 agent 的身份和路径进入，由主 agent 在转发到子 agent 前执行访问控制。主 agent 的子 agent 访问钩子检查请求中的子 agent 类型和运行标识是否存在于父侧子运行登记中，并结合当前用户、租户或会话权限决定放行、改写请求或拒绝访问。

对于没有直接父工具调用的后台子运行，主 agent 仍按相同机制生成运行标识、写入登记、启动子 agent 并保留流式片段，只是登记项中的父工具调用标识为空。客户端在父会话之外提供未绑定运行视图，按照开始时间或显示顺序展示该类后台任务。这样，定时恢复、外部 HTTP 请求、可调用方法或非聊天 UI 发起的子 agent 工作，不需要伪造一个聊天工具调用，也能在同一保留、回放、取消和清理体系下被管理。
