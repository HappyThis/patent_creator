## 技术方案

### 总体构思与对象边界

本方案在既有持久化 chat agent、子 agent 路由、流式输出和恢复机制之上，引入一种“保留式流式子 agent 工具编排”机制。用户仍只连接并操作一个主 agent；主 agent 在处理一次用户请求时，将研究、规划、比较、总结等可分解工作分派给一个或多个专门子 agent。每个子 agent 不是内存中的临时任务，而是通过既有子 agent 路由创建的独立持久对象，拥有独立的消息历史、模型配置、工具集合、流式响应日志和 SQLite 存储。主 agent 不复制子 agent 的完整执行状态，而是登记子运行、观察其流式输出并将其过程事件转发到主会话连接。

该机制将“执行”和“观察”分离：子 agent 运行由稳定的运行标识 $runId$ 表示，执行状态以子 agent 自身的持久聊天流为事实来源；主 agent 侧只维护足以回放、分组、鉴权、取消和清理的轻量登记信息。这样，主会话视图可以实时呈现多个子 agent 的过程，同时刷新页面、网络短暂断开或主连接重建后，仍可依据登记表和子 agent 已持久化的流式片段恢复已发生的过程，而不会因观察者消失而立即丢失子任务。

- 主 agent 作为用户会话入口和编排者，负责决定是否调用子 agent、生成或接收 $runId$、登记父侧运行记录、将子结果返回给主模型或主业务流程。
- 子 agent 作为可聊天的专门执行单元，负责在独立上下文中完成一次或多次推理、工具调用和结果生成，并将流式响应片段存入自身持久流。
- 父侧运行登记表负责保存 $runId$、父工具调用标识、子 agent 类型、输入预览、展示顺序、状态、摘要、错误和时间戳等元数据；该表不默认保存完整输入，以避免把敏感提示词、凭据或文件内容复制到编排层。
- 事件桥负责把子 agent 的聊天流片段和生命周期事件封装为主会话可识别的子运行事件，使浏览器在同一主会话中按父工具调用和展示顺序重建子 agent 时间线。

### 父侧运行登记与幂等调度

主 agent 在启动子 agent 之前先在自身存储中插入父侧运行记录，初始状态为 starting，并为该记录分配或校验稳定的 $runId$。记录字段至少包括父工具调用标识、子 agent 类型、输入预览、输入是否被脱敏、展示顺序、运行状态、摘要、错误信息、展示元数据、开始时间和完成时间。该父侧记录与既有子 agent 注册表分工不同：既有注册表回答某个子对象是否存在，父侧运行记录回答该子对象由哪一次主会话工作触发、应该在主视图何处渲染、重连时应合成哪些生命周期事件。

调度入口可以包括确定性编排接口和模型工具接口两类。确定性编排接口适用于后台任务、阶段化报告、并行扇出和由 HTTP 或 callable 方法触发的子运行；模型工具接口则把某一子 agent 类包装为主模型可选择的工具，工具执行时接收父工具调用标识和中止信号，再调用同一编排入口。两类入口共用父侧登记、子侧启动、流式观察和终态合成逻辑，因此无论子 agent 是由主模型选择还是由业务代码显式调用，主会话恢复、去重和清理行为保持一致。

为处理重复请求和并发执行，编排入口以 $runId$ 为幂等键。若调用方提供的 $runId$ 已对应终态记录，则主 agent 直接返回已有摘要、结构化输出或错误，而不重新启动子 agent；若已有非终态记录，则主 agent 不创建第二个同名子运行，而是基于已存储片段进行回放或按运行时能力重新附着观察。子 agent 侧也保存 $runId$ 到内部聊天请求标识和流标识的映射，使父 agent 即使在插入父侧记录后崩溃，也能通过 $runId$ 向子 agent 查询已启动的请求和流。

- starting 表示父侧记录已建立但尚未确认子 agent 已开始执行；running 表示子 agent 已启动聊天回合并可产生流式片段。
- completed、error 和 aborted 分别表示正常完成、执行失败和被显式取消，均为终态；终态一旦写入，迟到的取消或恢复检查不得覆盖该终态。
- interrupted 表示父侧在恢复时发现子运行无法安全继续观察或无法确认完整结果，该状态由父侧合成，子 agent 不主动声明自身为 interrupted。
- 每个父工具调用下可存在多个兄弟子运行，父侧通过 displayOrder 和 $runId$ 对并行子 agent 进行确定性排序与去重，而不是依赖各子运行返回的先后顺序。

### 子 agent 执行适配与流式转发

子 agent 侧设置聊天执行适配器，而不要求业务类继承额外的公开基类。适配器对已支持的 chat agent 基类提供统一能力：按 $runId$ 启动一次程序化聊天回合、记录 $runId$ 与聊天请求标识和流标识的对应关系、读取已存储的流式片段、检查当前运行状态、取消指定运行，并在需要时返回最终摘要或结构化输出。子 agent 的具体系统提示词、模型、工具集合和消息历史仍由该子 agent 自身拥有，从结构上隔离主 agent 的上下文和各子 agent 的上下文。

子 agent 启动后，通过自身已有的可恢复聊天流持续持久化输出片段。父 agent 作为观察者读取该流，并将每个片段作为不解释其内部语义的响应块转发；片段内容保持为聊天框架原生的 UI 消息增量格式，使文本、推理块、工具调用和工具结果等未来扩展均沿用同一装配逻辑。父 agent 只在片段外层增加运行标识、父工具调用标识、序号和是否回放等信封字段，避免在父侧重新定义一套子 agent 输出语义。

对于同一子运行，适配器在同步入口处设置执行占用标记或等价的排他声明，防止两个框架驱动的聊天回合同时写入同一子 agent 的当前流。若用户通过钻取视图连接到该子 agent，在框架驱动回合尚未结束时，可以允许只读查看其聊天过程；若要追加新的聊天输入，则应延后或返回明确错误，避免人工输入与主 agent 驱动的回合交错导致最终摘要、流标识或工具结果归属混乱。

当一次主请求需要比较多个主题或并行研究多个分支时，主 agent 可以为同一父工具调用分配多个子运行，并以 Promise.allSettled 或等价方式等待各分支结果。每个分支拥有独立 $runId$、独立子 agent 存储和独立终态；一个分支失败不会强制取消其他分支。主 agent 最终把各分支的摘要或错误结构化返回给主模型，使主模型能够基于“部分成功、部分失败”的真实状态继续回答，而不是把整个父工具调用视为单一成功或单一失败。

### 同一主会话视图中的事件协议与恢复

主 agent 向客户端发送 agent-tool-event 类型的子运行事件。事件包括 started、chunk、finished、error、aborted 和 interrupted 等种类；started 由父侧登记记录合成，用于在尚未产生输出片段时渲染子运行面板；chunk 承载子 agent 原生聊天增量；终态事件由父侧根据子 agent 检查结果、取消结果或恢复判断合成。事件信封包含父工具调用标识、$runId$、单运行递增序号和 replay 标记，客户端以父工具调用标识、$runId$ 和序号组成去重键。

客户端侧设置无样式的事件归约器或钩子，监听主 agent WebSocket 中的非聊天帧，过滤子运行事件后按父工具调用分组，并按 displayOrder 对兄弟子运行排序。对于 chunk 事件，客户端复用聊天框架的增量装配函数重建子 agent 的 UI 消息 parts；对于生命周期事件，客户端更新运行状态、摘要、错误和钻取所需的子 agent 地址。这样，主会话消息、主工具调用和多个子 agent 时间线在同一页面中形成一致视图，应用仍可自由决定面板样式和是否开放钻取。

当浏览器刷新或网络短暂断开后重新连接主 agent，主 agent 读取父侧运行登记表，按开始时间和展示顺序遍历已登记子运行。对每个子运行，主 agent 先发送 replay 标记的 started 事件，再通过子 agent 适配器按已记录流标识读取持久化片段并逐条发送 replay 标记的 chunk 事件，最后根据父侧终态或子侧检查结果发送 finished、error、aborted 或 interrupted 事件。由于原始输出片段保存在子 agent 自身存储中，父侧无需维护第二份长流日志，避免长任务下父侧状态膨胀。

对于无直接父工具调用的后台子运行，例如由 callable 方法、定时任务或外部 HTTP 处理触发的研究任务，父侧记录的 parentToolCallId 可以为空。此类运行仍沿用相同的 $runId$、状态、事件序号和回放机制；客户端将其归入未绑定运行列表或后台任务区域，而不是强行挂靠到某条主模型工具调用消息。该处理方式使后台子 agent 和聊天内子 agent 共用持久化、恢复、取消和清理能力。

主 agent 重启后的恢复逻辑不默认重跑存在歧义的子任务。若父侧记录存在而子侧未找到对应 $runId$，则标记 interrupted；若子侧已 completed、error 或 aborted，则回放已存储片段并同步为相应终态；若子侧仍 running 且当前运行时尚不支持晚到实时附着，则先回放已持久化片段，再将父侧记录标记为 interrupted 并给出明确原因。若后续运行时提供按序号重新附着子流的能力，则同一协议可从最后已转发序号继续观察，而不改变对外的编排接口。

### 取消、访问控制与清理保留

取消从主 agent 的活动操作显式传播到目标子运行，而不是由连接断开隐式触发。主请求、主工具调用或用户停止操作产生中止信号后，编排入口按 $runId$ 调用子 agent 取消接口；子 agent 将该信号绑定到当前聊天回合的中止控制器，并传入模型推理或消息保存流程，使推理循环和工具执行尽快终止。父侧随后停止对应观察流并写入 aborted 终态。若取消到达时子运行已 completed 或 error，则保持原终态不变。

访问控制沿用主 agent 的身份和租户边界，$runId$ 本身不作为能力令牌。对子 agent 钻取地址的外部请求必须先到达父 agent，由父 agent 的子 agent 访问前置检查确认请求的子 agent 类型和 $runId$ 在父侧运行登记表中存在且属于当前用户或会话；不存在匹配记录时返回拒绝响应，不允许仅通过猜测子 agent 名称创建新的子对象。内部编排调用可绕过外部访问检查，但其在广播 started 事件前必须已完成父侧登记，确保客户端获知的 $runId$ 一定可被访问控制逻辑识别。

保留策略以“默认保留、显式清理”为原则。子运行完成后，父侧运行记录和子 agent 持久对象均保留，以支持完成后的刷新回放、失败诊断、审计和后续钻取查看。应用在清空聊天历史、用户删除工作区或达到自定义保留条件时，调用统一清理接口，按状态、时间或会话范围筛选子运行；对于仍处于 starting 或 running 的记录，清理流程先取消子运行，再删除父侧记录和对应子 agent 持久对象，避免留下无人观察但仍消耗资源的后台推理。

为限制并行子 agent 带来的模型调用成本，父侧可设置最大并发子运行数或按用户、会话、工具类型配置配额。编排入口在插入或转为 running 前检查当前非终态运行数量，超过阈值时生成明确 error 事件并将失败返回给主模型或业务调用方。父侧还可在子运行开始和结束时触发生命周期钩子，把 $runId$、子 agent 类型、父工具调用标识和终态写入日志、计量或审计系统；这些钩子不改变子运行执行语义，只提供成本控制和可观测性的连接点。
