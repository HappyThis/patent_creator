## 技术方案

### 总体构思

本方案在现有智能工作台的网关会话、本地 Claude Code 会话、本地 Codex CLI 会话以及 Hermes 会话管理能力之上，增加面向新本地 agent runtime 的适配层。该适配层不要求新 runtime 预先暴露稳定接口，而是将“运行时存在性、状态目录候选、会话文件结构、可读记录、可继续会话能力”拆分为可独立验证的能力项，并把每一项的验证结果转化为工作台可消费的能力清单。工作台只根据已验证能力展示对应入口，例如仅发现历史记录时只展示只读会话列表和转写内容，只有继续会话命令、参数形式和鉴权状态均验证通过时才展示继续会话或控制类操作。

适配层与既有 runtime 流程之间采用统一会话视图解耦：各 runtime 的原始记录仍由各自扫描器按只读方式读取，扫描结果被规范化为包含会话标识、来源类型、项目或工作目录、模型、消息计数、工具调用计数、令牌统计、首次与最近活动时间、活动状态和可用操作集合的标准对象。标准对象再与已有网关会话、本地会话合并、去重和排序，形成同一工作台中的展示与管理数据源。由此，新 runtime 的接入边界被限制在新增适配器和能力清单内，不改变已有 OpenClaw、Claude Code、Codex CLI 或 Hermes 的扫描、控制和展示路径。

### 运行时探测与能力分级

针对新 runtime 的本地状态目录和版本差异，系统设置多级探测流程。第一级通过可配置环境变量、用户主目录下常见目录、应用数据目录以及容器内持久化数据目录生成候选根目录；第二级在候选根目录内检查特征文件、版本文件、认证文件、会话目录或本地数据库等轻量证据；第三级在不修改文件的前提下执行受限命令探测，例如版本命令、帮助命令或只读状态命令。每个探测步骤均设置超时、异常吞并和证据记录，任一失败仅降低对应能力置信度，不中断已有 runtime 的检测流程。

探测结果被划分为“未发现、已安装、已鉴权、可读取会话、可读取转写、可继续会话、可删除或控制”等能力等级。能力等级不由单一文件存在性直接推断，而由证据组合确定：例如会话展示至少要求存在可解析的会话记录且能提取稳定会话标识和最近活动时间；转写查看至少要求能够将原始记录转换为用户、助手、系统或工具结果等消息片段；继续会话至少要求确认可执行二进制、认证状态、继续命令模板和会话标识格式。对于尚未完全确定的能力，系统将其标记为待验证或不可用，使前端和 API 均不能把该能力误展示为可操作。

### 本地会话记录解析与统一映射

新 runtime 的会话解析器采用“候选文件枚举—格式识别—字段抽取—标准化映射”的流程。文件枚举阶段按最近修改时间限制扫描数量，并跳过超大文件或不可读文件，避免本地历史记录过多时阻塞工作台启动。格式识别阶段支持多种可能载体，例如按行 JSON 记录、普通 JSON 记录或只读 SQLite 状态库；解析器先识别会话元数据、消息记录、工具调用记录和令牌统计记录，再把缺失字段按可解释规则降级处理，例如无法取得项目路径时使用本地来源标识，无法取得模型时显示未知模型而不影响会话存在性判断。

标准化映射时，解析器为每条会话生成带来源前缀的复合键，合并时以“来源类型+会话标识”为去重基准，并保留最近活动时间较新的记录。活动状态不依赖进程常驻假设，而是结合记录时间、文件修改时间、运行时网关或进程状态形成；对于本地 CLI 型 runtime，可采用最近活动窗口判断活跃，对于数据库型 runtime，可结合结束时间和网关进程状态判断活跃。转写读取采用按会话标识过滤和时间排序的方式，仅输出有限数量的最近消息片段，并对工具输入、工具结果和长文本进行截断，从而在保护本地数据和控制内存占用的同时，使不同 runtime 的历史会话能够在统一工作台中被检索、查看和比较。

### 受限管理与安全隔离

对于管理类操作，系统采用受限执行和双重校验机制。API 层先根据标准会话对象中的能力清单判断该会话是否支持目标操作，再根据 runtime 适配器提供的命令模板构造参数；会话标识、提示文本和操作类型均进行格式校验、长度限制和权限校验。若新 runtime 仅确认具备本地记录读取能力，则删除、控制、继续会话等写操作不会进入命令执行路径；若继续会话能力已确认，也仅允许调用经适配器声明的固定命令和固定参数位置，不允许由前端传入任意 shell 片段。

该机制还为不同 runtime 维持独立的扫描缓存、错误日志和能力状态，新增适配器的异常只会使该 runtime 的状态降级为不可用或只读，不会影响已有 runtime 的会话合并和控制流程。对本地数据库采用只读连接，对文件型记录采用只读流式或限量读取，对安装或鉴权相关信息只记录是否满足能力条件而不暴露密钥内容。由此，系统能够在新 runtime 格式尚未完全稳定时先安全接入可确认的历史会话识别和展示能力，并在后续版本确认继续会话或控制能力后，通过更新适配器能力声明逐步开放管理能力。
