## 技术方案

### 总体接入架构

本方案在智能工作台现有的网关会话、本地 Claude Code 会话、Codex CLI 会话和 Hermes 会话管理能力之上，增加一个面向新本地 agent runtime 的“适配器—归一化—门控”接入层。该接入层不直接假定新 runtime 的状态目录、文件格式或继续会话命令已经稳定，而是把目录发现、格式识别、会话摘要抽取、能力验证和界面动作开放拆分为相互独立的技术环节；只有经探测确认的事实被写入统一会话模型，只有经验证的能力才被暴露为可操作项。

接入层包括运行时描述注册表、只读状态探测器、会话解析器、统一会话映射器、能力证明器和操作路由器。运行时描述注册表记录候选状态根目录、候选会话文件扩展名、可识别的结构特征、可选命令行能力及其验证方式；只读状态探测器按描述注册表扫描用户主目录、显式环境变量指定目录和应用配置目录，不创建、不修改新 runtime 的状态文件；会话解析器将命中的候选文件解析为统一字段；能力证明器对继续会话、读取完整转录、统计 token 等能力分别产生确认、未确认或不可用状态；操作路由器根据能力状态决定是否允许继续会话或仅允许查看。

### 会话记录探测与标准化

会话记录探测采用多候选路径和多版本格式识别机制。系统先根据显式配置的新 runtime 状态根目录进行扫描；未配置时，再按预设候选目录进行受限深度扫描。每个候选目录先通过轻量特征确认，例如存在会话索引、JSONL 记录、SQLite 状态库、元数据文件或运行时专有标识后才进入深度解析。该机制借鉴现有工作台对 Claude Code 的 JSONL 项目目录、Codex CLI 的会话 JSONL 文件以及 Hermes 的只读 SQLite 状态库的处理方式，但将这些处理方式抽象为可替换的格式探针，避免把某一 runtime 的目录结构硬编码为唯一事实。

对每一个被识别的候选会话，解析器输出统一会话摘要，至少包括 runtime 类型、会话标识、项目或工作目录标识、首条消息时间、末次活动时间、活动状态、模型名称、输入输出 token、用户消息数、助手消息数、工具调用数和最后用户提示摘要。若某字段在当前格式中不存在或无法可靠解析，则写入空值或未知状态，不用默认值伪装为已确认事实。活动状态以日志时间戳、文件修改时间和运行时进程状态共同判断；当日志时间存在未来时间或时钟偏移时，按当前时间容差钳制；当状态库正在被 runtime 使用时，以只读方式打开并在表结构缺失时返回空结果。

为降低本地扫描对工作台和用户机器的影响，探测过程设置文件数量、文件大小、扫描深度和扫描频率边界。超过阈值的单个会话文件被跳过并记录诊断信息；短时间内重复请求复用最近扫描结果；解析失败的文件只影响对应候选会话，不中断其他 runtime 的会话汇总。该边界使新 runtime 即使存在大文件、半写入文件、损坏 JSON 行或版本不一致的状态库，也不会拖慢或破坏已有会话列表。

### 能力置信分级与功能门控

本方案将“发现会话”和“可继续会话”分离处理。会话文件被识别只表示该 runtime 在本机存在历史记录；继续会话、读取完整转录、显示成本估算、显示在线状态等能力，需要由能力证明器分别确认。能力证明器可以通过检测可执行文件、版本输出、认证状态、命令帮助、最小无副作用探测命令、会话标识格式约束或配置文件特征来形成证明；无法确认时，将对应能力标记为未确认，工作台仅展示只读会话摘要，不显示继续按钮、终止按钮或其他会改变 runtime 状态的控制项。

能力状态按字段级别传递到统一会话模型，而不是按 runtime 整体开关粗粒度处理。例如同一版本的新 runtime 可能已经能读取会话摘要但尚不能安全恢复会话，或能够恢复会话但不能提供 token 统计。统一模型中为每类能力设置 canReadTranscript、canContinue、canEstimateCost、canReportActive 等布尔或枚举状态，并附带 reason 字段说明未启用原因。前端和 CLI 仅根据这些能力字段渲染动作和提示，从而避免把尚未确认的 runtime 能力展示为可用。

当用户发起继续会话时，操作路由器再次校验 runtime 类型、会话标识格式、认证状态和命令模板，且只允许使用经注册表声明并经证明器确认的命令路径。提示文本长度、会话标识字符集和调用超时时间均在路由层限制；调用结果只返回 stdout、stderr 或指定输出文件中的文本摘要。若新 runtime 的继续命令在某版本中变化，系统不会复用旧命令强行执行，而是将该能力降级为未确认并保留只读管理能力。

### 与既有工作台的合并展示和隔离管理

新 runtime 的会话摘要进入工作台前，先转换为与已有会话列表一致的规范对象：id 用于去重和操作路由，key 用于显示项目或会话标题，agent 表示来源 agent 或项目，kind 表示 runtime 类型，source 标记为 local，lastActivity 用于排序，active 表示活动状态，workingDir、model、token、消息数量和最后提示作为可选详情。合并器把网关会话、本地 Claude Code 会话、Codex CLI 会话、Hermes 会话和新 runtime 会话按 source 与 id 形成复合键去重，并按最近活动时间排序。

为不破坏已有 runtime 的管理流程，新适配器以插件式方式接入会话聚合链路。新增 runtime 的扫描、解析、转录读取和继续会话逻辑均封装在独立模块中；聚合接口只接收该模块输出的规范对象和能力描述。若新适配器抛出异常、路径不可读或格式不匹配，聚合器捕获该错误并返回其他 runtime 的结果，不改变已有 Claude、Codex、Hermes 或网关会话的查询、排序、控制和鉴权逻辑。

在权限和安全边界上，查看会话摘要和转录沿用 viewer 权限，触发扫描、继续会话或其他可能产生副作用的动作沿用 operator 权限，并进入现有审计或活动记录链路。状态扫描默认只读，敏感内容只保留必要摘要，长转录按条数和单条长度截断展示。该处理使新 runtime 的接入既能复用同一工作台的观察、筛选和管理体验，又能在能力未知、格式变化或认证状态不足时保持保守退化。
