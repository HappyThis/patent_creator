## 技术方案

### 总体接入架构

本方案在现有智能工作台的会话工作台和会话接口之间增加“运行时接入适配层”，将不同本地 agent runtime 的状态目录、会话文件和可控能力抽象为统一的只读发现接口与可选控制接口。适配层不直接改变既有 OpenClaw、Claude Code、Codex CLI、Hermes 等运行时的原始状态，而是分别执行本地探测、格式解析、字段归一化和能力声明，再由会话聚合接口输出统一会话对象供同一工作台展示。

适配层为每类 runtime 设置独立适配器，适配器包括发现器、解析器、归一化器、能力探测器和隔离执行器。发现器负责定位状态源，解析器负责读取 JSONL、JSON 或只读数据库等记录，归一化器将不同格式映射到工作台既有会话模型，能力探测器输出“可读、可继续、可删除、可设置标签、可控制参数”等能力位，隔离执行器仅在能力位被确认时才允许调用对应 runtime 的命令或网关。通过该结构，新 runtime 的接入不需要改动已有 runtime 的扫描逻辑和控制流程。

### 本地状态发现与格式探测

针对新 runtime 状态目录和文件格式尚未稳定的问题，适配层采用多候选目录探测与格式指纹识别相结合的方式工作。系统可以配置或内置若干候选根目录、文件后缀、数据库文件名和元数据文件名，扫描时先进行存在性、可读性、文件大小、修改时间和目录层级检查；随后仅对命中的候选文件执行轻量解析，例如读取 JSONL 前若干行、读取 SQLite 只读元信息、或解析会话元数据块，以确认其是否包含会话标识、时间戳、工作目录、模型、消息角色、token 统计等最小字段。

格式识别结果被划分为“已确认格式、兼容格式、未知格式、不可读格式”四类。已确认格式满足会话标识、时间信息和至少一种消息或统计字段；兼容格式仅满足最小展示字段，可进入只读展示但不启用控制能力；未知格式和不可读格式仅记录诊断状态，不写入统一会话列表。对超大文件、解析失败行、时钟漂移或运行中被改写的文件，解析器采用跳过、截断读取、时间戳夹取和错误隔离处理，保证新 runtime 的异常状态不会阻塞会话接口。

### 会话归一化、合并与展示

经确认的本地会话被转换为统一会话记录，至少包括会话标识、来源 runtime、项目或工作目录、模型、首末消息时间、活动状态、消息数量、工具调用数量、token 用量、摘要标题和原始能力标记。不同 runtime 的字段缺失时不作强行推断，而是填入空值、未知值或由文件修改时间推得的保守时间；活动状态根据最后消息时间、文件修改时间、runtime 进程状态和可配置活跃窗口综合判断，避免仅凭历史文件存在就将会话显示为正在运行。

会话聚合接口将新 runtime 会话与已有 gateway、本地 Claude、Codex、Hermes 会话合并时，以“来源类型+会话标识”作为去重键，以最后活动时间排序，并设置总数上限和扫描节流窗口。这样既能让同一工作台按统一筛选、排序、状态颜色和详情面板展示多来源会话，又能避免新 runtime 大量历史文件导致启动阻塞或覆盖已有 runtime 的同名会话。

| 归一化字段 | 来源或推导方式 | 缺失时处理 |
| --- | --- | --- |
| 会话标识 | runtime 元数据、文件名或数据库主键 | 缺失则不进入会话列表 |
| 最后活动时间 | 消息时间戳、结束时间或文件修改时间 | 采用保守时间并标记低置信 |
| 活动状态 | 最后活动时间、进程状态和活跃窗口 | 不能确认时显示为空闲或未知 |
| 控制能力 | 能力探测器的确认结果 | 默认只读，不展示控制入口 |

### 能力门控与既有流程隔离

新 runtime 的继续会话、删除、改标签、调整推理等级等能力通过能力声明表独立表达，声明项包括能力名称、触发条件、所需命令或 API、参数校验规则、权限等级和确认状态。工作台只在适配器明确探测到可执行入口且能力声明为已确认时展示相应操作；对于仅能读取本地记录但尚未确认继续会话协议的 runtime，仅展示会话详情、筛选、排序和只读统计，不提供继续或控制按钮。

控制类操作采用白名单路由和来源校验。既有 OpenClaw gateway 的会话控制仍沿用原有 RPC 方法；新 runtime 的操作请求必须携带 runtime 来源、会话标识和能力名称，并由对应适配器重新校验会话是否来自该 runtime、能力是否仍然有效、参数是否符合声明规则。校验失败时返回不可用状态而不是降级调用其他 runtime 的控制接口，从而避免新接入破坏已有 runtime 的管理流程。

### 缓存、审计与安全边界

为降低本地扫描成本，系统对每个适配器维护独立扫描缓存和节流时间。缓存内容只保存归一化后的会话摘要、能力声明和扫描时间，不保存完整对话正文；当用户主动刷新、文件修改时间变化、runtime 进程状态变化或缓存过期时才触发重新扫描。对于 SQLite 类状态源，采用只读连接和表结构存在性校验；对于日志文件类状态源，采用顺序读取、大小上限和逐行容错解析，避免与正在运行的本地 agent 产生锁冲突或写入竞争。

系统在本地会话接入链路中保留诊断和审计信息，包括适配器版本、命中的状态源、格式判定、跳过原因、能力确认依据和控制操作结果。诊断信息用于解释为什么某个 runtime 仅可只读或未显示，而不把未确认能力伪装成可用功能；控制操作仍受工作台既有角色权限、速率限制和活动日志约束，以保持新 runtime 与既有 runtime 在同一安全边界下运行。
