## 技术方案

### 总体构思与接入边界

本方案在智能工作台已有的网关会话、本地 Claude Code 会话、Codex CLI 会话和 Hermes 会话管理能力之上，增加面向新本地 agent runtime 的适配层。适配层不直接改变既有 runtime 的扫描、会话控制和展示链路，而是将新 runtime 作为独立来源接入统一会话聚合接口；每条会话记录均携带来源、runtime 类型、会话标识、项目或工作目录、时间戳、模型、消息数量、工具调用数量、令牌统计、活动状态以及可用能力标记。工作台根据该标准化记录进行排序、去重和展示，从而在同一工作台中呈现多 runtime 会话，同时避免不同 runtime 的文件结构、状态语义和控制能力相互污染。

接入边界采用“只读发现优先、可执行能力后置确认”的原则。对于尚未完全确定本地状态目录、会话文件格式和继续会话命令的新 runtime，系统首先仅提供目录探测、会话文件候选识别、转录内容读取和摘要统计等不破坏本地状态的能力；只有在探测结果证明本机存在对应命令、会话标识可被命令识别、继续会话参数格式已通过适配器声明或本地校验时，才向工作台暴露继续会话、发送提示、附加终端等主动操作入口。

### 本地状态探测与格式识别

适配层包括运行时描述表和探测器。运行时描述表记录候选状态目录、会话文件扩展名、递归深度、单次扫描数量上限、最大文件大小、支持的记录字段、会话标识提取规则和能力声明；探测器按照用户主目录、环境变量指定目录和配置目录的优先级查找候选根目录，并仅对最近修改的有限数量文件执行只读扫描。对于 JSONL、JSON、SQLite 或其他可能格式，探测器先判断文件存在性、大小、修改时间和最小结构特征，再进入对应解析器，避免因全盘扫描或误读大文件影响工作台性能。

解析器采用“宽容读取、证据分级”的机制处理版本差异。每个候选会话文件被逐行或只读查询解析，无法解析的行或字段被跳过而不使整个扫描失败；当记录中存在明确会话标识、时间戳和用户或助手消息时，标记为可信会话；当仅能从文件名、修改时间或部分元数据推导会话标识时，标记为待确认会话；当缺少会话活动证据时不进入展示列表。时间戳同时参考记录内时间和文件修改时间，并对未来时间或无效时间进行钳制，以减少系统时钟偏差或日志格式变化导致的错误活跃状态。

为降低重复扫描和竞争访问风险，探测结果设置短周期缓存和手动强制刷新通道。自动刷新使用节流窗口，读取失败、文件消失、权限不足或数据库锁定时返回空结果或部分结果并记录诊断信息，不抛出会中断工作台主会话列表的异常。对于已经确认的新 runtime 状态目录，系统可以保存最后成功扫描时间、命中的格式版本和解析器名称；当目录结构或文件特征发生变化时，系统回退到只读发现状态，而不是沿用旧能力假设。

### 会话记录标准化与聚合展示

新 runtime 的原始会话记录经适配器转换为工作台统一会话模型。该模型至少包括会话 $id$、来源 $source$、类型 $kind$、显示键 $key$、项目名或工作目录、开始时间、最后活动时间、是否活跃、模型名、消息计数、工具调用计数、令牌统计和最后用户提示摘要；其中无法确认的字段保持为空或未知，不用默认值伪装为已确认能力。聚合接口按 $source:id$ 形成去重键，避免新 runtime 的本地会话与网关会话或其他本地 runtime 使用相同会话号时相互覆盖，并按最后活动时间排序后输出给前端。

转录读取采用按 runtime 分派的读取器。读取器根据会话标识在候选文件集合或只读数据库中定位记录，将用户消息、助手消息、系统或工具结果转换为统一的消息片段结构，并限制单条文本和返回条数。对于新 runtime 可能存在的输入文本、输出文本、工具调用、工具结果或思考内容等不同字段命名，读取器通过字段映射表提取可展示内容；无法识别的内部事件不进入聊天正文。这样既能在同一会话详情界面查看不同 runtime 的历史记录，又不会将未识别的运行时事件误展示为用户或助手消息。

活动状态不直接依赖某一 runtime 的专有字段，而是由最后有效消息时间、会话文件修改时间和可选的运行时进程探测共同计算。若最后活动时间落入预设窗口，则可标记为活跃；若仅有文件修改但无有效消息，则只用于排序参考，不单独证明会话可继续。令牌和费用统计同样按证据来源标记精度：当日志提供累计令牌时采用累计值；仅提供增量或模型不明时，展示消息量或令牌数但不计算费用。

### 能力门控与运行隔离

系统为每个 runtime 维护独立的能力矩阵，能力项包括本地会话发现、转录读取、继续会话、终端附加、删除、标签修改和参数控制等。新 runtime 初次接入时默认只开启已由探测器确认的只读能力；继续会话能力需要同时满足命令可执行、会话标识合法、参数模板已知、工作目录安全和权限角色满足要求。前端和 API 均根据能力矩阵决定是否展示或接受操作请求，因而不会把尚未确认的继续会话能力展示为可用。

主动操作路径与只读扫描路径隔离。只读扫描仅访问新 runtime 的状态目录并生成标准化会话记录；继续会话或终端附加则通过单独的操作端点执行，并进行角色校验、会话标识白名单校验、提示长度限制、超时控制和临时输出文件清理。若命令执行失败、无输出或版本不支持恢复参数，系统只返回失败状态或“能力不可用”状态，不修改原会话记录，也不影响已有 OpenClaw、Claude Code、Codex CLI 或 Hermes 的会话管理流程。

通过上述机制，新 runtime 的接入点被限制在适配器、探测器、标准化映射和能力门控四个层面；统一会话列表只消费标准化结果，既有 runtime 的扫描器、数据库表、网关控制和会话控制 API 保持原有职责。该结构使系统能够在状态目录和日志格式尚有差异的情况下先识别已有本地会话并提供可审慎展示的管理信息，又能在后续版本确认更多能力时逐项开启操作能力，而无需重构工作台主体流程。
