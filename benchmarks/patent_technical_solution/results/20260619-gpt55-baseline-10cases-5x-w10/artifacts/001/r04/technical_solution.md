## 技术方案

### 总体构思与适配边界

本方案在已有智能工作台的网关会话、本地 Claude Code 会话、本地 Codex CLI 会话和 Hermes 会话展示能力之上，增加一个面向新本地 agent runtime 的适配层。该适配层不直接改造既有 runtime 的扫描、控制和删除流程，而是把新 runtime 作为独立来源接入统一会话汇聚链路：先对本机状态目录、可执行文件、认证状态、会话文件和可选的继续会话命令进行分级探测，再将被确认的记录转换为工作台已有会话视图可理解的规范化字段。由此，系统能够在同一工作台中展示新 runtime 的历史会话、最近活动、项目归属、模型信息和使用统计，同时避免因新 runtime 格式未稳定而影响原有 gateway、Claude、Codex 或 Hermes 的管理逻辑。

适配层采用“证据项—能力项—展示项”三层边界。证据项是从本机环境直接取得且可复验的信息，例如候选目录是否存在、候选文件是否为可读普通文件、文件修改时间、文件名中的会话标识、日志行中是否包含稳定字段、runtime 命令是否可在超时内返回版本或帮助信息。能力项是在证据项满足预设阈值后生成的内部结论，例如“可发现历史会话”“可读取转录片段”“可继续会话”“可估算 token 用量”。展示项只来源于已确认的能力项；未确认的能力不进入可操作按钮或自动执行路径，而是以未配置、只读、不可用或待确认状态呈现。该边界使系统可以逐步兼容不同版本的新 runtime，而不会把推测能力误展示为已可用能力。

### 会话记录发现与可信解析

针对新 runtime 的本地状态目录尚未完全确定的问题，系统设置可配置的候选目录集合和版本化探测规则。候选目录可以包括用户显式配置目录、环境变量指示目录、用户主目录下的默认隐藏目录以及操作系统配置目录；每个候选目录在扫描前先进行路径归一化、越界检查和存在性检查，仅在其为普通目录且不位于系统敏感路径时进入递归扫描。扫描过程按最近修改时间排序并设置最大文件数、最大单文件大小、最大递归深度和扫描节流窗口，以避免新 runtime 产生大量日志文件时造成工作台阻塞。

针对会话文件格式可能随版本变化的问题，适配层不依赖单一固定 schema，而是采用多模板容错解析。解析器以 JSONL、JSON、SQLite 或其他可识别文本记录为候选输入格式，对每条记录提取会话标识、时间戳、工作目录、模型名、消息角色、消息内容片段、工具调用标记和 token 用量等规范字段。对于字段命名差异，解析器通过字段别名表和类型校验进行映射；对于缺失字段，则按照“可推导才填充、不可推导则置空”的原则处理，例如可从文件名推导会话标识、可从文件修改时间推导最近活动时间，但不能凭空生成模型名或继续会话命令。解析失败的单行记录被跳过并记录诊断信息，不导致整个扫描失败。

在生成会话记录时，系统对同一会话的多来源证据进行去重和置信度合并。若多个文件或目录均指向同一会话标识，则保留最近活动时间较新的记录，并把项目路径、模型名和统计信息按可信来源优先级补齐；若仅存在低置信度证据，例如只有候选文件但无可解析消息，则该对象不作为可展示会话输出。活动状态不由 runtime 名称或目录存在性直接决定，而由最后消息时间、文件修改时间和可配置活动窗口共同推导，并对未来时间戳进行容差钳制，避免时钟偏差导致会话被长期误判为活动。

### 能力确认与降级展示

新 runtime 的能力确认采用分级门控机制。第一层为安装与身份状态确认，通过可执行文件探测、版本命令、配置文件存在性和认证状态命令等证据判断 runtime 是否存在、版本是否可识别、是否需要登录或配置。第二层为本地记录读取确认，只有在候选状态目录可读且至少解析出一条有效会话记录时，才声明“可展示历史会话”。第三层为操作能力确认，例如继续会话、读取完整转录、删除或重命名会话等能力，必须同时满足命令模板存在、版本规则匹配、参数校验通过和一次非破坏性 dry-run 或帮助命令确认；否则该能力在工作台中保持禁用。

继续会话能力单独处理，不与会话可发现能力绑定。适配层为新 runtime 维护带版本条件的命令模板，例如以会话标识、工作目录和用户输入作为参数的 resume 或 continue 命令；在未确认命令语义前，系统只允许只读展示会话记录，不在界面和 API 中暴露继续会话入口。确认继续会话后，执行路径仍需经过会话标识白名单校验、提示词长度限制、操作权限校验、命令超时和输出截断处理，并把返回内容作为一次新的交互结果展示，而不是直接修改已解析的历史记录。该机制能够防止因不同版本命令参数变化而误触发错误会话或破坏本地状态。

当某一能力无法确认或解析过程中出现版本差异时，系统采取局部降级而非整体失败：可展示的会话继续展示，缺失的模型、token、成本、分支或工作目录字段以空值或未知值输出；转录读取不可用时仅展示会话摘要；继续会话不可用时仅隐藏操作入口；扫描异常仅影响新 runtime 来源，不影响既有 runtime 的会话列表和控制接口。降级原因可以作为诊断信息提供给管理员，用于后续补充目录规则、字段别名或版本命令模板。

### 统一会话模型与既有流程隔离

适配层将新 runtime 的原始记录映射为统一本地会话模型。该模型至少包括会话 $id$、来源 $source$、类型 $kind$、项目键、项目路径、模型、开始时间、最后活动时间、活动标志、输入输出 token、消息数量、工具调用数量、最近用户提示摘要、可用能力集合和诊断状态。工作台的会话汇聚器只消费该统一模型，不直接读取新 runtime 的原始文件结构。这样，新增 runtime 的格式变化被限制在适配层内部，前端展示、分页排序、活动态标识、转录读取入口和权限判断可以复用现有本地会话处理逻辑。

统一汇聚时，系统把网关会话和各类本地会话作为并列来源处理。网关会话仍通过原有 gateway 接口执行标签、推理级别、删除等控制动作；本地 Claude、Codex、Hermes 和新 runtime 会话则分别通过各自适配器提供只读扫描、转录读取或已确认的继续会话能力。每条会话携带来源和能力集合，API 在执行操作前根据该集合选择对应处理器；若会话来源不支持某项操作，则直接返回不可用状态，而不会把请求转发到其他 runtime 的控制接口。该来源隔离使新增 runtime 不会污染已有 session key 命名空间，也不会误用 OpenClaw gateway 的会话控制能力。

为保证长期兼容，适配层的探测规则、字段别名、能力门控条件和命令模板可以按 runtime 版本进行配置或热更新。扫描结果可以暂存于工作台数据库或内存缓存，并带有扫描时间、来源版本和诊断摘要；下一轮扫描采用 upsert 方式更新同一会话，先标记旧活动态再写入新证据，避免重复记录和陈旧活动状态。由此，本方案在不修改探索环境文件和不破坏现有管理流程的前提下，使工作台能够识别新 runtime 的已有本地会话记录，并以谨慎、可验证、可降级的方式逐步开放更多管理能力。
