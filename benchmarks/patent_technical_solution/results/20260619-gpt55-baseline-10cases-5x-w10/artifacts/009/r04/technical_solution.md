## 技术方案

### 总体架构与隔离边界

本方案在现有 codemode“模型生成代码、隔离运行代码、由宿主执行工具”的模式基础上，将执行位置扩展到浏览器侧。系统包括主页面工具注册层、工具描述生成层、浏览器隔离执行层、受控调度协议层和结果汇聚层。主页面工具注册层保存只能在页面内执行的能力，例如读取当前页面状态、调用前端组件方法、访问浏览器授权能力或组合动态客户端工具；隔离执行层仅运行模型生成的编排代码，不直接持有这些页面私有对象。

浏览器隔离执行层可以采用 Web Worker、沙箱化 iframe 或其他与主页面全局对象分离的执行容器。系统在创建执行容器时只注入一个或多个工具命名空间代理以及必要的序列化接口，不注入主页面的 window、DOM 引用、组件实例或网络凭据。模型生成的代码通过代理发起工具调用，代理把工具名、参数、调用标识和上下文标识封装为协议消息发送给主页面；主页面校验后调用真实注册工具，并把结果或错误以同一调用标识返回。

该隔离边界使生成代码能够使用条件判断、循环、并发等待和错误处理来编排客户端工具，同时避免生成代码直接修改主页面变量、劫持页面事件或访问未授权浏览器能力。服务端仍可负责生成模型提示、接收最终结果或继续对话，但浏览器私有工具不需要迁移为服务端 execute 函数，从而保持客户端能力、页面状态和用户授权边界在浏览器本地闭环。

### 动态工具描述与名称映射

主页面在每次对话轮次或任务开始时收集当前可用的客户端工具集合，形成工具描述清单。每个工具描述至少包括原始工具名、自然语言说明、输入 JSON Schema、可选输出说明、权限或审批属性以及所属命名空间。对于页面组件临时暴露的能力、浏览器授权能力或由插件动态组合出的能力，工具描述可以在运行前即时生成并随会话上下文发送给模型，使模型看到的是当前页面实际可用的工具，而不是静态内置工具表。

为使生成代码能稳定调用动态工具，系统对工具名进行规范化映射：将连字符、点号、空格等分隔符转换为下划线，去除不符合 JavaScript 标识符的字符；当名称以数字开头时增加前缀；当名称与保留字冲突时增加后缀。模型提示和隔离执行容器中暴露规范化后的可调用名称，主页面调度表则保存规范化名称到原始工具记录的映射。由此，页面工具可以继续使用面向业务的原始命名，而生成代码获得合法、确定的函数入口。

系统根据工具输入模式生成类型化提示片段，例如把 JSON Schema 或标准 schema 转换为输入类型，并在工具注释中保留字段说明。对于需要用户审批或不适合自动执行的工具，可以在进入 codemode 工具集前过滤或标记为需外部审批，避免模型生成的编排代码绕过既有的人机确认流程。

### 浏览器侧代码执行与受控调度流程

执行时，模型输出的代码先经过规范化处理，去除代码围栏，并统一包装为异步箭头函数或可调用异步函数体。该处理允许模型输出表达式、函数声明或默认导出等不同形态，但最终进入隔离容器的执行入口保持一致。隔离容器启动后，为每个工具命名空间创建一个代理对象；当生成代码调用代理对象上的方法时，代理并不本地执行工具，而是构造受控调用消息。

受控调用消息包括命名空间、规范化工具名、参数序列化结果、调用标识、执行实例标识和可选超时信息。主页面收到消息后，先检查执行实例是否仍有效，再在调度表中查找对应工具；未注册、被过滤、名称冲突或参数不符合 schema 的调用直接返回结构化错误。合法调用由主页面在自身上下文中执行，因此可以访问当前 DOM 状态、前端组件实例、浏览器权限 API 或客户端缓存等页面私有资源。

主页面把工具返回值序列化为结果消息并传回隔离容器。代理解析结果消息：若包含结果字段，则将其作为对应调用的 Promise 解析值返回给生成代码；若包含错误字段，则在隔离容器内抛出异常，使生成代码可以使用 try/catch、重试或降级逻辑处理。对于需要位置参数的工具，代理按参数数组序列化；对于普通工具，代理按单个对象参数序列化，从而兼容前端组件方法和 AI SDK 风格工具两类调用习惯。

### 错误、超时、日志与资源释放机制

系统对一次浏览器侧 codemode 执行设置整体超时，并可对单个工具调用设置子超时。隔离容器内的用户函数与超时 Promise 竞争执行；超过时间仍未完成时，执行结果被标记为超时错误，后续未决工具调用通过执行实例失效机制被拒绝或忽略。该机制避免模型生成的循环、长等待或悬挂客户端工具占用页面资源。

隔离容器重写或包裹 console.log、console.warn 和 console.error，将日志按顺序写入执行日志缓冲区，并在成功结果或错误结果中一并返回。工具调用异常、参数校验失败、未注册工具调用和主页面执行异常均转换为结构化错误文本，既可向模型反馈以便其修正后续步骤，也可供开发者定位是生成代码问题、工具描述问题还是页面工具执行问题。

每次执行创建独立执行实例和临时调度表，并在完成、失败、取消或超时时执行释放流程：移除消息监听器，清空调用等待队列，终止 Worker 或销毁 iframe，关闭临时会话连接，并从主页面注册表中删除与该执行实例绑定的桥接对象。对于浏览器调试、页面会话或类似短生命周期资源，可以采用每次执行新建会话、finally 阶段关闭会话的方式，保证资源释放与结果返回解耦。
