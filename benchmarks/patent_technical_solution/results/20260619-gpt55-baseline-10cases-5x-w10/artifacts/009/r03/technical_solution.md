## 技术方案

### 总体构思与执行边界

本方案在现有代码模式能力的基础上，将“模型生成编排代码”和“浏览器私有能力真实执行”分离处理：模型仍只输出一段异步 JavaScript 编排代码，但该代码不进入主页面全局作用域执行，而是进入浏览器侧隔离运行单元；主页面仅保留工具注册表、页面状态访问能力、前端组件能力以及其他动态客户端工具的真实实现。隔离运行单元内的代码只能看到由系统注入的受控工具命名空间，不能直接读取主页面对象、修改 DOM、复用页面闭包或绕过工具协议调用浏览器私有能力。

隔离运行单元的执行入口限定为系统规范化后的异步函数。系统在执行前对模型生成代码进行语法解析和形态校验，使其满足可调用函数形式，并在运行时禁用或替换危险出口，例如直接网络访问、主页面全局对象访问、跨源窗口引用、任意模块加载以及长期定时任务。对于确需访问网络或浏览器协议的场景，也通过主页面或受控服务提供专门工具转发，而不是允许生成代码获得通用访问权。

该总体边界使模型能够利用代码的循环、条件分支、组合调用和局部异常处理能力编排多个浏览器工具，同时把页面真实状态和敏感能力限制在主页面受控执行侧。与把浏览器能力迁移到服务端相比，本方案保留了客户端工具对当前页面、用户会话、组件树和浏览器权限的原位访问；与直接在主页面执行生成代码相比，本方案降低了全局变量污染、DOM 误改、权限扩大和难以回收资源的风险。

### 动态客户端工具的描述与命名处理

主页面维护动态客户端工具注册表，每个工具记录原始工具名、描述、输入参数模式、是否需要批准、执行函数和当前可用状态。模型请求开始前，系统从注册表抽取可暴露给模型的工具描述，生成面向编排代码的类型声明或简化接口说明，并随本次执行上下文发送给模型；主页面的执行函数、组件实例引用、浏览器 API 权限对象等不随描述下发到隔离运行单元。由此，工具能力可以随页面、插件或组件状态动态变化，而服务端无需预先固化全部浏览器私有能力。

为解决动态工具名不适合作为 JavaScript 标识符的问题，系统在生成描述和建立调度表时执行双向命名规范化：将包含连字符、点号、空格、数字开头或保留字冲突的原始工具名转换为合法代理方法名，并保存规范化名称与原始名称的映射关系。隔离运行单元只允许调用规范化后的代理方法；主页面在执行前依据映射还原到原始工具，既保证模型代码可读、可写，又避免因工具名碰撞、非法字符或关键字导致调用歧义。

动态描述还可以携带工具版本、可用条件、批准策略和结果截断策略。每次执行会话固定一份工具快照，后续页面工具注册表即使发生变化，也不影响当前隔离运行单元的合法工具集合；如果编排代码调用已不在快照内的工具，系统按非法调用处理。该快照机制避免模型在长流程中受到页面动态变化影响，同时为审计和复现提供稳定依据。

### 浏览器侧隔离执行与受控调度协议

执行时，系统为每次代码模式调用创建独立的浏览器侧隔离运行单元，例如沙箱 iframe、专用 Worker、受限 JavaScript realm 或等效隔离容器，并向其中注入调度代理对象。调度代理通过 Proxy 或等效拦截机制暴露一个或多个命名空间，例如 `client.*`、`page.*` 或 `component.*`，拦截编排代码中的工具调用，将工具名、参数、调用序号和执行标识封装为协议消息发送给主页面。隔离运行单元不持有真实工具函数引用，主页面收到协议消息后在注册表中查找对应工具并执行，再把结构化结果返回给隔离运行单元。

协议消息至少包括执行会话标识、工具命名空间、规范化工具名、参数序列化文本、调用序号和超时配置。主页面对消息来源、会话标识和工具名进行校验，仅接受来自当前隔离运行单元且在本次描述集中声明的调用；未声明工具、已失效工具、需要批准但未获得批准的工具、参数不符合模式的工具调用均被拒绝并返回结构化错误。对于支持位置参数的客户端能力，协议可以保留参数数组；对于普通 AI 工具，则统一按单对象参数传递，以便与既有代码模式和 AI SDK 工具体系兼容。

当工具用于读取当前页面状态、调用前端组件方法或组合多个客户端工具时，主页面执行侧可按工具粒度实现最小权限封装。例如“读取页面摘要”工具只返回经过过滤的状态快照，“组件操作”工具只允许调用注册组件暴露的白名单方法，“组合工具”可以在主页面内部继续调用多个私有 API 但只向隔离运行单元返回合成结果。这样，生成代码只能编排工具级能力，不能直接枚举或操纵未注册的页面内部对象。

### 错误、日志、超时和资源释放机制

本方案对异常传播采用结构化错误通道：隔离运行单元内的语法错误、运行时错误、超时错误以及主页面工具执行错误均被转换为包含错误类型、消息、调用序号和可选调试信息的结果对象；调度代理收到工具错误时在编排代码中抛出异常，使模型生成代码可以通过 `try/catch` 处理局部失败。最终返回给上层模型调用的结果同时包含正常返回值、错误摘要和执行日志，避免浏览器控制台或主页面异常状态被不受控地泄露。

隔离运行单元内的 `console.log`、`console.warn`、`console.error` 被重定向到本次执行的日志缓冲区，并按级别、时间和调用上下文记录。主页面工具执行侧也可将协议收发、工具开始、工具结束、参数校验失败和资源清理事件写入同一执行日志。日志缓冲区设置最大条数、最大字节数或近端环形队列，返回给模型或开发者时可进行截断和脱敏，从而在支持调试的同时限制页面敏感信息和大体积结果进入模型上下文。

系统为整段生成代码设置总执行超时，并可为单个工具调用设置独立超时。任一超时触发时，隔离运行单元停止接受新的工具调用，未完成的协议请求被标记为取消，主页面执行侧中断可取消任务或忽略迟到结果。执行结束、出错、用户取消、页面卸载或会话失效时，系统统一移除隔离容器、注销消息监听器、清理定时器、释放待决 Promise 和工具调用队列，并将资源释放状态写入日志，从而避免生成代码残留在浏览器环境中持续运行。
