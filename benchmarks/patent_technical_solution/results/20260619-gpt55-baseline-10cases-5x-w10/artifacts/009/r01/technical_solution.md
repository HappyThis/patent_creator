## 技术方案

### 总体架构与隔离执行环境

本方案在既有代码模式的“模型生成异步代码、宿主在隔离执行器中运行代码、工具调用通过调度器回传宿主”的基础上，增加浏览器侧代码模式执行层。整体包括模型交互层、浏览器沙箱执行层、主页面工具注册层和受控调用桥接层。模型只看到可调用工具的规范化类型描述，并生成访问约定命名空间的 JavaScript 异步函数；该函数不在主页面全局环境中求值，而是在独立的 Worker、iframe sandbox 或等效隔离执行上下文中运行。隔离上下文默认不继承主页面对象、DOM 引用、应用状态容器和网络能力，主页面仅向其注入一个由代理对象构成的工具命名空间。

浏览器沙箱执行层对模型代码进行标准化和包裹：首先将输入限定为可立即执行的异步箭头函数或等效函数体，去除与执行入口无关的包装；然后为每个工具提供者生成独立命名空间，例如默认工具命名空间、页面状态命名空间或组件能力命名空间；最后在沙箱中通过 Proxy 拦截 namespace.toolName(args) 形式的调用。这样，模型代码可以用常规程序结构实现循环、条件、结果组合和错误处理，但每一次外部能力访问都被约束为一次显式工具调用，不能直接读取主页面变量或修改真实 DOM。

主页面工具注册层保存真实工具函数及其执行上下文，例如读取当前页面状态、调用前端组件方法、访问剪贴板或组合多个客户端能力。真实工具函数始终留在主页面或应用受控运行时内执行，沙箱只持有工具名、参数和调用标识。因此，浏览器私有能力无需搬迁到服务端，模型生成代码也不会获得对主页面对象图的直接引用；如果某些工具需要用户授权或应用态校验，该校验在主页面工具注册层完成后再返回结果。

### 动态客户端工具注册与描述生成

客户端在发起对话或更新页面能力时提交工具清单，每个工具清单项包括原始工具名、描述、JSON Schema 参数结构、可选的返回值说明、是否需要确认以及工具所属提供者。系统将该清单转换为模型可读的类型声明和工具说明，使模型在一次代码模式调用中可以编排多个浏览器工具。对于页面动态产生的工具，例如随当前路由、选中组件或已连接外部设备变化的工具，主页面可以在每个会话轮次重新上报清单；服务端或会话管理层仅保存工具描述和调用路由信息，不保存浏览器私有执行函数。

为避免动态工具名不适合作为 JavaScript 属性访问，本方案对工具名执行确定性规范化。规范化规则将连字符、点号、空格等非标识符字符映射为下划线，对数字开头的名称增加前缀，对保留字增加后缀，并建立“原始工具名—规范化工具名—提供者命名空间”的映射表。模型看到并调用规范化后的名称，桥接层在派发时再映射回真实工具。若不同原始工具名规范化后发生冲突，系统在工具描述生成阶段拒绝该清单或为冲突项分配带命名空间的唯一名称，从而避免沙箱代码把调用错误地路由到其他工具。

工具描述生成模块还区分普通对象参数工具和位置参数工具。普通客户端工具统一采用单对象参数，便于从 JSON Schema 生成类型并进行参数校验；对于已有前端能力已经暴露为位置参数接口的情况，可以通过适配器在主页面侧转换为对象参数，或在工具提供者元数据中标记为位置参数。该处理使模型代码中的调用形式稳定，同时允许浏览器应用逐步接入已有组件能力。

### 受控调用协议与异常处理

沙箱与主页面之间采用请求—响应式受控协议。沙箱代理对象在捕获工具调用后，生成包含执行会话标识、调用序号、提供者命名空间、规范化工具名和序列化参数的调用消息，并通过 postMessage、MessageChannel、Worker RPC 或等效安全通道发送给主页面桥接器。主页面桥接器先校验会话标识、调用序号、工具是否仍处于注册表、参数是否符合对应 JSON Schema，以及该工具在当前会话状态下是否允许执行；校验通过后才调用真实工具函数。

协议返回值统一封装为成功结果或错误结果。成功结果包含可结构化克隆或可 JSON 序列化的输出；错误结果包含错误类型、错误消息和可选的可恢复标记，不把主页面内部对象、堆栈中的敏感路径或闭包状态传回沙箱。沙箱收到错误结果后将其转换为 JavaScript 异常抛出，使模型生成代码可以在 try/catch 中处理；未处理异常则被执行器捕获并作为本次代码模式调用的错误返回给模型交互层。由此，非法工具名、参数不匹配、权限拒绝、工具运行失败和工具超时都沿同一异常传播链路处理。

对于非法工具调用，桥接器不尝试回退到任意主页面方法，也不允许沙箱通过字符串构造新的能力入口。若调用的规范化名称不存在、已过期、被当前策略禁用或与原始名称映射不一致，桥接器返回“工具不存在或不可用”的受控错误，并记录该调用。若参数结构超出工具声明，例如携带未允许字段、字段类型不匹配或超出可接受大小，桥接器在真实工具执行前拒绝。该前置校验使模型代码即便生成了错误调用，也只能获得明确错误反馈，不能越权触达未注册页面能力。

### 执行治理、日志与资源释放

执行器对每次浏览器侧代码模式调用建立独立执行会话，并配置最大运行时长、最大并发工具调用数、最大日志长度和最大返回数据量。沙箱侧通过 Promise.race 或运行时计时器实现整体超时；主页面桥接器对单个工具调用设置独立超时和取消信号。若整体会话超时，执行器停止接受新的沙箱调用，向未完成调用返回取消错误，并通知主页面释放与该会话相关的消息通道、事件监听器、临时对象引用和待处理定时器。

沙箱内的 console.log、console.warn 和 console.error 被重定向到会话日志缓冲区，日志条目带有时间、级别和调用序号，并按容量限制截断。主页面桥接器同时记录工具调用日志，包括工具名、参数摘要、执行耗时、结果大小和错误类型。两类日志在执行结束后合并返回给模型交互层或开发者调试界面，但默认不写入应用业务状态，也不暴露敏感参数全文。该机制既保留模型代码编排过程的可观察性，又避免生成代码污染主页面控制台和持久状态。

资源释放采用会话生命周期钩子完成。执行开始时创建沙箱、消息通道和临时工具映射；执行正常完成、异常结束、用户中止或页面卸载时均进入同一清理流程：关闭消息端口，移除事件监听器，清空待处理调用表，撤销临时对象 URL 或 Worker 实例，并将工具映射标记为不可再用。对于需要保持页面会话连续性的工具，真实页面状态仍由应用自身保存；代码模式执行会话只保存本次编排所需的短期引用，从而降低内存泄漏和跨轮次误调用风险。

通过上述结构，本方案把“代码编排能力”和“页面私有能力执行”拆分在不同信任边界内：模型代码只在隔离环境中表达控制流，主页面只按注册表和协议执行被允许的工具。该拆分使浏览器侧动态工具可以像服务端代码模式工具一样被组合调用，同时避免将页面能力复制到服务端，减少生成代码对主页面环境、网络访问和持久状态的直接影响。
