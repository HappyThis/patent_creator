## 技术方案

### 整体架构与隔离边界

本方案在既有代码模式能力的基础上，将浏览器侧生成代码执行拆分为“隔离代码运行环境”和“主页面工具执行环境”两个边界。模型仍只生成一段 JavaScript 异步函数，用于表达多步骤编排逻辑；该函数不在主页面全局上下文中直接运行，而是在独立的浏览器隔离执行单元中运行。隔离执行单元可以采用 Web Worker、沙箱化 iframe 或等效的独立 JavaScript realm，默认不暴露主页面的 window、DOM、应用状态对象、网络凭据和组件实例，只暴露由系统注入的工具代理对象、日志采集对象和终止信号。

主页面工具执行环境保留真实浏览器私有能力，包括页面状态读取、组件实例调用、用户会话上下文、动态客户端工具组合以及必要的浏览器协议连接。隔离执行单元只能通过受控协议请求这些能力，不能持有真实对象引用，也不能直接修改主页面原型链、全局变量或事件监听器。由此，模型生成代码可以使用循环、条件分支和结果组合来完成复杂客户端任务，同时将对页面的实际读写集中到可审计、可限权、可清理的工具调度层。

### 动态客户端工具注册与描述生成

主页面维护客户端工具注册表，注册项至少包括原始工具名、规范化后的脚本可调用名、工具描述、入参结构、可见性条件、执行函数、权限或确认策略以及可选的结果截断策略。工具可以来自页面状态读取器、前端组件能力、浏览器会话能力、扩展模块或远端返回的动态客户端能力；当页面状态、组件挂载状态或外部能力变化时，注册表重新生成当前会话可用的工具快照，并向模型提供与该快照对应的工具说明。

为适配代码调用语法，系统对动态工具名进行确定性规范化处理：将连字符、点号、空格等分隔符替换为下划线，去除不能作为 JavaScript 标识符的字符，数字开头的名称增加前缀，下游语言保留字增加后缀，并保存“原始工具名—规范化工具名”的映射。若两个原始工具名规范化后发生冲突，系统按命名空间、提供方标识或显式别名生成唯一名称，并在工具说明中只暴露最终可调用名。该处理使来自不同页面模块、MCP 服务或浏览器能力的动态工具能够被模型稳定引用，避免因工具名包含特殊字符而产生非法脚本。

工具描述生成模块根据当前工具快照生成面向模型的代码上下文，包括命名空间、可调用函数签名、参数字段、返回值含义、只读或写入属性、使用示例和禁止事项。对于类似浏览器协议规范、前端组件清单等体量较大的动态能力，系统不一次性暴露完整清单，而是提供搜索或查询型工具，使模型先查询当前可用命令、事件或组件能力，再生成后续执行代码。该方式减少提示上下文体积，并使工具描述与页面实时状态保持一致。

### 隔离执行与受控调用协议

隔离执行单元内不注入真实工具函数，而是为每个工具命名空间生成代理对象。代理对象拦截诸如 client.readPageState()、component.openPanel() 或 browser.capture() 的调用，将工具名、参数、调用序号和执行令牌序列化为协议消息，通过 MessageChannel、postMessage 或等效的受控通道发送给主页面调度器。主页面调度器只接受来源于当前隔离执行单元且携带有效执行令牌的消息，并在工具注册表中按规范化名称查找对应真实工具；未注册、不可见、需要确认但未获确认、参数不符合结构或命名空间非法的调用均被拒绝，并以结构化错误返回隔离执行单元。

主页面调度器在执行真实工具前对协议消息进行分层校验。第一层校验执行来源和令牌，防止其他窗口或过期执行上下文伪造调用；第二层校验命名空间和工具名，确保只能访问当前快照中声明的工具；第三层校验参数结构，将模型生成代码传入的参数解析为工具定义要求的对象参数或位置参数；第四层执行权限策略，例如只读工具可直接执行，可能改变页面状态的工具可要求用户确认、策略白名单或应用侧授权。只有通过全部校验的请求才被转发给真实工具函数。

一次执行的典型流程为：应用层收集当前可用客户端工具并形成工具快照；模型基于工具说明生成异步函数形式的代码；系统对代码进行语法归一化，去除代码围栏，并将普通表达式、函数声明或默认导出转换为可调用的异步函数；浏览器创建隔离执行单元并注入代理对象；代理对象把工具调用发往主页面调度器；调度器执行真实工具并返回序列化结果；隔离执行单元继续运行后续逻辑，直至返回最终结果或错误。

### 运行控制、异常传播与资源释放

每次浏览器侧代码运行均创建独立的执行上下文、调用通道和执行令牌，并配置总超时、单次工具调用超时、最大调用次数、最大日志长度和最大结果长度。隔离执行单元内部改写或包裹 console.log、console.warn、console.error 等日志接口，将日志按执行标识、时间顺序和级别写入缓冲区；工具调度器同时记录工具调用开始、完成、失败、超时和被拒绝事件。运行结束后，系统将函数返回值、结构化错误和日志摘要合并为一次执行结果，供模型继续推理或展示给应用层。

当隔离代码抛出异常、调用不存在的工具、工具函数返回错误、协议校验失败、单次调用超时或总执行超时时，系统不让异常穿透到主页面事件循环，而是将其转换为包含错误类型、工具名、调用序号和可读消息的结构化错误。隔离执行单元收到错误后以异常形式恢复到生成代码的 await 调用点，使代码中的 try/catch 可以处理；若未被处理，则作为本次代码运行的错误结果返回。该机制既保留了代码编排所需的异常语义，又避免浏览器私有能力或主页面内部堆栈不受控地暴露给模型。

资源释放由执行生命周期统一驱动。无论代码正常返回、抛出异常还是超时终止，系统均关闭消息通道，撤销执行令牌，移除隔离执行单元及其事件监听器，拒绝尚未完成的工具调用，并释放由工具层临时打开的浏览器连接、页面目标、组件订阅或调试日志缓冲区。对于需要访问浏览器会话或前端组件的工具，可采用“每次执行新建临时会话、结束后关闭”的策略；对于必须跨步骤复用的状态，可通过显式状态句柄和过期时间管理，而不是让生成代码直接持有主页面对象。
