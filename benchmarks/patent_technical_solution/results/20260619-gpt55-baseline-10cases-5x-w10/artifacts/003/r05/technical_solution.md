## 技术方案

### 总体架构与对象分层

本方案采用“用户级目录代理 + 会话级子代理”的组合架构来同时满足多会话隔离和用户级资源连续性。对于同一用户账号或同一工作区，系统设置一个用户级目录代理实例，用于保存聊天索引、共享上下文、共享工作区引用、外部工具连接和授权凭据引用；在该目录代理之下，每一个聊天会话对应一个独立的会话级子代理实例。会话级子代理负责维护该会话自己的消息历史、压缩摘要、当前系统提示快照、执行状态和面向该会话的工具调用过程，用户级目录代理不承载具体对话推理的热路径。

目录代理为每个会话维护至少包括会话标识、标题、创建时间、更新时间、最后消息摘要和删除标记的索引记录。会话标识不直接作为全局顶层代理名称使用，而是与用户级目录代理的身份共同形成层级地址，例如“用户目录/会话子代理”的路径。由此，同名会话在不同用户下自然落入不同父级命名空间，浏览器、服务端调度器和后台任务在寻址时均需先确定用户级目录，再进入目标会话，避免仅凭会话标识误连到其他用户或其他会话。

会话级子代理内部使用会话存储层保存树形消息、分支、全文检索索引和压缩摘要。消息历史从该子代理的本地持久化存储读取，跨会话共享信息则通过目录代理提供的远程上下文接口读取。这样，一个会话的上下文组装只包含自身消息历史以及被显式声明为用户级共享的上下文块，不会因为同一用户下存在其他活跃会话而自动混入其他会话的临时消息、工具结果或执行状态。

### 会话访问与资源控制机制

客户端访问会话时采用递归子路径或等价的层级连接参数，先连接到用户级目录代理，再指定待访问的会话级子代理。目录代理在转发 WebSocket 或 HTTP 请求之前执行父级访问控制钩子，校验请求是否属于该用户、目标子代理类别是否为允许的会话类别、会话索引中是否存在对应记录以及该记录是否处于可访问状态。校验失败时，目录代理直接返回拒绝响应，不唤醒会话级子代理，从入口处阻断浏览器或子会话绕过统一控制直接访问共享资源。

目录代理可以在通过校验的请求中注入用户身份、目录实例标识、请求追踪标识和资源访问范围等头信息或调用上下文，会话级子代理仅依据该父级传入的上下文使用共享工作区和外部工具连接。共享文件系统、MCP 或其他外部工具连接、授权凭据不直接暴露给任意会话地址，而是由目录代理或其受控的资源适配层统一持有；会话级子代理发起资源访问时携带自身会话标识和父级目录标识，由资源适配层进行二次校验、审计和限流。

为了避免多个会话串行阻塞在单一对话对象上，本方案不把同一用户的所有聊天作为一个对象内部的多个会话切片处理，而是让每个聊天成为独立子代理。子代理可以独立保持连接、流式响应、执行工具调用并持久化本会话消息；目录代理只在会话创建、列表查询、跨会话检索、共享上下文读写和子代理入口校验时参与。该结构既保留了按用户统一管理资源的控制点，又使不同会话的推理和执行状态在持久化边界、连接边界和运行边界上相互隔离。

### 共享上下文与跨会话能力

用户级共享信息通过远程上下文提供者接入会话，而不是复制到每个会话的本地上下文中。会话级子代理在组装系统提示时，为“用户记忆”“工作区状态”“共享技能索引”等需要跨会话连续的内容配置远程上下文块；该远程上下文块的读取、写入和追加请求通过父级目录代理的可调用接口完成，目录代理负责把内容持久化到用户级存储。会话级子代理只保存对共享上下文块的引用和当轮使用的冻结快照，从而避免会话本地状态与用户级共享状态混同。

当多个会话同时更新共享记忆时，目录代理利用自身单线程顺序执行的持久化特性对写入进行串行化。对于常见的增量型记忆更新，子代理优先调用追加接口，由目录代理在当前共享内容尾部附加增量，减少“先读后写”覆盖他人更新的风险；只有在明确需要整体替换时才使用设置接口。对于共享上下文在对话中的使用，子代理可在一轮推理开始时冻结系统提示快照，即使其他会话在本轮中途更新共享记忆，也只在下一轮刷新快照时生效，以保持单轮推理输入的一致性。

跨会话检索由目录代理统一编排。目录代理先根据会话索引确定该用户下可参与检索的会话集合，再对各会话级子代理发起消息检索调用，并按相关性、更新时间或预设限制合并结果；共享上下文检索则直接在用户级共享存储中完成。这样，单个会话可以获得同一用户下历史会话的可检索信息，但该能力通过目录代理的会话集合和权限边界实现，不需要把其他会话的完整消息历史注入当前会话上下文，也不会使一个会话任意枚举或读取不属于该用户目录的子代理。

### 会话删除与一致性处理

会话删除采用“索引软删除 + 子代理延迟清理”的方式处理。用户删除某一聊天时，目录代理首先在会话索引中写入删除时间或删除代次，并广播新的会话列表状态；客户端发现当前活跃会话已被删除后关闭或丢弃该会话连接。此时目录代理不删除用户级共享工作区、外部工具连接或授权凭据，也不立即硬删除子代理存储，以避免正在进行的流式响应、工具写入或消息持久化被中途截断。

后续来自浏览器或后台任务的重连请求仍需经过目录代理的子代理入口校验。若目标会话索引已被标记删除，目录代理返回终止性错误，使客户端停止重试而不是反复重连；若删除请求重复到达，目录代理根据会话标识和删除代次进行幂等处理。对于删除窗口内重新创建同名会话的情况，目录代理可以增加新的生成代次，使旧连接携带的会话代次无法通过校验，从而防止陈旧连接继续写入新会话。

当父级目录代理或共享上下文服务短暂不可用时，会话级子代理对远程共享上下文读取采用失败软化策略：当前轮次可将该共享块视为空或沿用已冻结快照继续处理，而不是把会话本身置为不可用；共享资源写入则保持通过父级接口提交，失败时不在会话本地伪造成功的用户级状态。通过上述生命周期边界，删除单个会话只影响该会话的消息历史和执行状态，不会误删或污染用户级工作区、授权凭据、工具连接以及其他会话的上下文。
