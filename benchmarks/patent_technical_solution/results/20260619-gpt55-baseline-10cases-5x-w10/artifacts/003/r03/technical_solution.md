## 技术方案

### 总体架构与身份分层

本方案采用“用户级目录代理 + 会话级子代理”的组合结构：同一用户账号或工作区对应一个用户级目录代理实例，该目录代理保存会话索引、共享工作区引用、外部工具连接、授权凭据索引和跨会话调度入口；每一个聊天会话对应一个独立的会话级子代理实例。浏览器侧先连接用户级目录代理以获得会话列表和可访问会话标识，再通过由目录代理路径派生的子代理地址连接目标会话，从而使“用户身份”和“会话身份”在路由层、存储层和执行层均被显式区分。

目录代理不承载具体会话的模型推理主循环，而是作为用户级资源的控制面。其内部维护会话注册表和会话元数据表，会话注册表以子代理类别和会话标识作为复合键，记录目录代理已经创建且未删除的会话；会话元数据表用于保存标题、更新时间、最后消息摘要等展示性信息。会话是否存在以注册表为准，元数据仅作为附加描述，避免因元数据残留导致系统误认为某个会话仍可访问。

### 会话级执行隔离

每个会话级子代理拥有独立的消息历史、上下文块、压缩摘要、全文检索索引和执行状态。用户在会话 A 中产生的消息树、工具调用结果、流式响应缓冲和自动续写状态仅写入会话 A 的子代理存储；会话 B 即使属于同一用户，也只能通过用户级目录代理读取共享资源，不能直接读取会话 A 的本地历史。这样既保留同一账号下多会话并行运行的能力，又避免将多个会话压入同一单线程对象而导致推理、工具调用和流式连接相互串行化。

会话上下文装配在会话级子代理内部完成。子代理在一次对话回合开始时，从自己的会话存储读取当前分支的历史消息、必要的压缩摘要和本会话上下文，并生成该回合使用的冻结提示上下文；同一回合中共享资源发生变化时，不强制改写已经冻结的提示上下文，而是在下一回合边界重新拉取。该处理方式使模型输入具有可复现的会话边界，避免一个会话的中途写入使另一个会话正在执行的推理上下文发生不可控漂移。

### 用户级共享资源连续性

用户级共享资源由目录代理统一持有或统一转接，包括共享工作区文件句柄、外部工具连接、授权凭据、用户记忆和跨会话搜索入口。会话级子代理需要使用这些资源时，不保存凭据副本，也不自行构造用户级资源地址，而是通过父代理引用或远程上下文提供器向目录代理发起受控调用。目录代理根据当前用户身份、会话注册状态和资源策略返回结果或拒绝访问，从而在保持资源连续性的同时避免子会话绕过统一控制。

对于可被多个会话共同累积的共享上下文，目录代理提供按标签寻址的读取、覆盖写入和追加写入接口。会话级子代理在装配系统提示或执行记忆工具时，通过远程上下文提供器调用目录代理的共享上下文接口；目录代理在单一用户级实例内顺序处理写入，优先采用追加写入保存新增事实，减少多个会话采用“先读后写”方式造成的覆盖丢失。对于非文本型或结构化共享状态，可以通过目录代理的专用可调用方法维护，而不混入会话本地消息历史。

跨会话调度任务也归属于用户级目录代理。目录代理可以维护用户级任务队列、工具连接池或后台索引子代理，并在需要时把任务派发给具体会话级子代理，或者将会话产出的摘要、索引片段写回用户级共享存储。由此，某一会话被关闭或删除时，用户的工作区文件、授权状态、工具连接配置以及跨会话后台任务不会随该会话的本地存储一并销毁。

### 跨会话访问控制与生命周期处理

外部连接访问会话级子代理时，必须经过目录代理的子代理路由入口。目录代理在转发 WebSocket 或 HTTP 请求之前执行前置检查：若目标子代理类别不是允许的会话类别，或会话标识未出现在会话注册表中，则直接返回拒绝响应，不唤醒目标子代理；检查通过时，目录代理才将请求转发至对应会话级子代理，并可在转发请求中注入用户标识、目录标识或请求标识等受控上下文。该路由机制使浏览器无法仅凭猜测会话地址访问未创建、已删除或不属于当前用户的会话。

创建会话时，目录代理先生成会话标识并创建对应子代理，使会话注册表成为可访问性的权威来源，再写入标题、摘要等元数据并广播新的会话列表。若元数据写入失败，后续列表刷新仍以注册表为准，不会暴露不存在的会话；若存在注册表项但元数据缺失，可以使用默认标题和创建时间补足展示信息。该顺序保证会话创建过程在网络中断或部分写入场景下仍保持可恢复状态。

删除会话时，目录代理仅删除目标会话级子代理及其会话元数据，或者先将会话标记为已删除并在安全窗口后清理子代理；无论采用立即删除还是软删除，删除操作的作用域均限定在会话注册项、会话本地消息、会话本地上下文和该会话的运行状态，不作用于目录代理保存的共享工作区、外部工具连接、授权凭据和用户级共享上下文。对于已经打开该会话的浏览器连接，目录代理广播更新后的会话列表，客户端在发现目标会话消失后关闭活动连接；后续重连再次经过目录代理检查并得到终止性拒绝，而不是重新创建同名会话。
