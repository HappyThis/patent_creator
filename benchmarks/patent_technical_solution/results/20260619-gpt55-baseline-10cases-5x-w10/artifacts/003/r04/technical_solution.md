## 技术方案

### 总体架构与隔离边界

本方案采用“用户级目录代理 + 会话级子代理”的组合式架构处理多会话隔离与用户级资源连续性的矛盾。对于同一用户账号或租户，系统设置一个用户级目录代理实例，作为该用户工作区、外部工具连接、授权凭据、共享记忆和会话索引的归属边界；对于每一个聊天会话，系统在该目录代理之下创建一个会话级子代理实例，作为独立对话执行单元。由此，用户级目录代理负责共享资源的持有、授权校验、会话列表和跨会话调度，会话级子代理负责单个会话的消息历史、上下文组装、推理执行、流式响应、工具调用状态和恢复状态。

会话级子代理具有独立的持久化存储和执行生命周期。其存储中保存该会话的消息树、分支关系、会话内上下文块、压缩摘要、全文检索索引、正在执行的请求标识以及可恢复流式输出片段；不同会话不共用上述会话内表项，也不通过同一个会话标识字段在单个执行对象内复用存储切片。这样可以避免在同一执行对象内串行化多个会话推理任务，也避免因客户端切换会话、页面恢复或子会话并发执行而把一个会话的历史消息、工具结果或系统提示混入另一会话。

目录代理维护会话索引表，表项至少包括会话标识、标题、创建时间、更新时间、最近消息摘要、删除标记和可选的代次标识。会话标识既用于在目录内定位子代理，也用于构造客户端到具体会话的嵌套路由；但会话标识不作为用户级共享资源的主键。共享工作区、授权凭据和外部工具连接以用户级目录代理或其上级租户代理为归属对象，从而使新增、切换或删除单个会话不会改变共享资源的所有权。

### 会话路由与访问控制

客户端访问会话时使用包含父级目录代理和目标会话子代理的嵌套路由，例如“目录代理/用户标识/子代理/会话标识”的路径形式。路由层先解析用户级目录代理，再由目录代理根据会话索引和子代理注册信息解析目标会话子代理。对于 WebSocket 聊天连接和 HTTP 或 RPC 请求均采用相同的路径链路，使客户端连接的叶节点是目标会话，但每次建立连接或访问子会话前均经过目录代理的统一入口。

目录代理在转发请求到会话级子代理之前执行父级中间件校验。该校验可以包括用户身份认证、租户匹配、会话是否存在、会话是否处于删除窗口、目标子代理类型是否允许、速率限制以及必要的请求头改写。校验通过时，目录代理才取得或创建对应的子代理句柄并转发请求；校验不通过时直接返回拒绝响应而不唤醒子代理。该机制使浏览器、脚本或某个子会话不能绕过目录代理直接访问共享工作区、凭据或其他会话。

子代理初始化时记录从根到父目录代理的祖先路径，并提供从子代理回到直接父目录代理的受约束访问方法。该方法在运行时校验调用方声明的父级类型是否与记录的直接父级一致，避免子代理因错误绑定、同名顶级代理或嵌套层级混淆而访问到错误的用户目录。会话内部需要读取共享记忆、请求跨会话检索或调度用户级工具时，只能通过该父级访问方法调用目录代理暴露的受控接口，而不是直接持有共享资源句柄。

### 共享资源连续性与跨会话协同

用户级目录代理设置共享上下文提供端，用于保存跨会话可复用的信息，例如用户偏好、项目级记忆、工作区摘要、长期任务状态或外部工具连接描述。会话级子代理在组装模型上下文时不复制这些共享信息，而是配置远程上下文提供器，通过父目录代理的受控接口读取指定标签的共享上下文，并将读取结果作为该会话当前轮次的系统上下文块注入。共享上下文的存储位置始终在目录代理侧，因而一个会话更新共享记忆后，其他会话在后续轮次可以读取到该更新。

对于共享上下文的写入，本方案区分追加型更新和替换型更新。目录代理提供追加接口和替换接口；常见的用户记忆、项目事实、跨会话任务记录等增量信息优先通过追加接口写入，以减少多个会话并发读改写导致的丢失更新；仅在需要整体重建共享上下文时使用替换接口。由于目录代理自身是单线程执行单元，同一用户下多个会话对子目录共享状态的写入在目录代理处被串行化处理，从而将跨会话一致性问题限制在用户级边界内。

跨会话检索由目录代理发起聚合。目录代理先根据会话索引确定候选会话，再通过子代理调用各会话自身的全文检索能力，获得命中消息、摘要片段和排序信息后进行合并返回。这样，每个会话的原始消息仍保留在各自子代理的存储中，目录代理只承担索引目录和结果汇聚职责；在会话数量较少时可采用并行扇出检索，在会话数量较多时可扩展为由目录代理维护共享索引或分批调度。

用户级工作区文件、外部工具连接和授权凭据由目录代理或其受控工具层统一持有。会话级子代理发起工具调用时，将会话标识、父级路径、请求类型和必要参数提交给目录代理进行鉴权和调度；目录代理依据用户级授权状态、会话状态和工具策略决定是否执行，并把结果返回给发起会话。该设计使多个会话可以连续使用同一工作区和同一授权资源，同时保留按会话记录调用来源、限制危险操作或暂停某个会话调度的能力。

### 删除与异常处理机制

删除会话时，目录代理先将会话索引表中的对应记录标记为已删除，并广播更新后的会话列表，使客户端关闭或切换正在使用的活动会话连接。系统不立即删除用户级工作区、外部工具授权、共享上下文或目录代理自身状态，也不把会话删除操作解释为用户资源回收操作。该软删除方式可避免会话仍有流式响应、工具回调或持久化写入尚未结束时发生存储竞争，同时防止误删同一用户下其他会话仍需使用的共享资源。

在软删除窗口内，目录代理对同一会话标识的重复删除保持幂等；若需要重新创建相同标识的会话，可以通过代次标识区分旧连接与新会话。客户端或浏览器尝试重连已删除会话时，请求再次经过目录代理校验，目录代理根据删除标记或代次不匹配返回永久性拒绝，客户端据此停止无限重试。对应的会话级子代理可在空闲、超时或清理任务触发后再删除其私有存储，且该删除仅作用于该子代理及其子层级，不级联删除目录代理持有的共享资源。

当目录代理临时冷启动、共享上下文读取失败或父级资源不可用时，会话级子代理采用降级机制继续处理会话内消息：远程上下文读取失败时返回空上下文或上一次冻结的提示快照，本轮推理不因共享记忆短时不可达而失败；在下一轮次边界重新刷新共享上下文。对于工具调用、凭据使用或跨会话调度等高风险操作，则不采用默认放行，而由目录代理明确授权后执行。由此，系统在保证单会话可用性的同时，不牺牲共享资源的统一控制边界。
