## 技术方案

### 总体架构与身份边界

本方案采用“用户级目录代理+会话级子代理”的组合架构处理多会话场景。系统为同一用户账号或租户建立一个用户级目录代理，该目录代理保存聊天会话索引、共享工作区入口、外部工具连接、授权凭据引用以及跨会话调度元数据；每一个聊天会话则由独立的会话级子代理承载，分别保存该会话的消息历史、上下文块、推理流恢复状态和执行中间状态。客户端进入某一会话时，通过用户级目录代理确定会话标识，再路由到对应会话级子代理建立聊天连接，从而使会话运行面向独立对象，而共享资源归属于用户级对象。

用户级目录代理不直接混合各会话的对话内容，而维护包含会话标识、标题、创建时间、更新时间、最后消息摘要和删除标记的目录表。会话级子代理可按需懒创建，且其地址由用户级目录代理、子代理类型和会话标识共同确定。这样，同一用户下多个会话可以并行运行，各自使用独立持久化存储和 WebSocket 广播通道；目录代理只承担列表、创建、重命名、软删除、共享状态读写和搜索聚合等职责，避免把所有会话串行压入单一 Durable Object 内部。

### 会话隔离与上下文装配

每个会话级子代理内部使用单会话 Session 存储该会话的消息树、上下文块、压缩摘要、工具调用结果和流式响应恢复信息。会话在装配模型输入时，只从自身 Session 读取消息路径和会话私有上下文，并在需要用户级记忆时通过远程上下文提供器向父级目录代理请求指定标签的共享上下文。共享上下文作为显式上下文块注入，而不是与会话消息表共表存储，因此一个会话的历史消息、分支、重生成结果或压缩摘要不会被另一个会话误读。

会话切换由客户端连接层完成，目录代理不保存全局 activeChatId；不同浏览器标签或设备可以同时连接不同会话。连接到会话子代理后，广播、流式恢复和工具状态只发送给该会话的连接集合，兄弟会话不能被动接收。若会话在一轮推理开始时冻结了系统提示词和共享记忆快照，则该轮使用冻结快照完成，下一轮再刷新共享上下文，既保证单轮推理输入稳定，又允许其他会话产生的共享记忆在轮次边界后生效。

### 用户级共享资源的受控访问

共享工作区、浏览器连接、外部工具连接和授权凭据不由会话子代理直接持有原始能力，而由用户级目录代理或与其同级的用户级资源管理器统一持有。会话子代理需要访问共享资源时，通过父级代理解析出的受控远程提供器、可调用方法或 loopback 绑定发起请求。该绑定只携带用户代理标识、资源标识、会话标识和权限范围等可序列化数据，调用发生时再由运行时解析到真实资源，从而避免把可绕过权限检查的活动对象、浏览器 WebSocket 或凭据句柄泄露给子会话或浏览器端代码。

对工作区文件的访问采用用户级命名空间模型：同一用户的共享工作区以独立命名空间存放在持久化文件系统中，小文件可内联保存于 SQLite，较大文件可按同一命名空间溢出到对象存储。各会话通过同一工作区服务执行 read、write、list、glob、diff、delete 等操作，请求中附带会话标识和授权后的访问模式。工作区服务负责路径规范化、命名空间校验、网络隔离和执行超时控制，并可在文件变更时向目录代理广播同步事件。这样删除或清理某个会话仅影响会话索引和该会话子代理状态，不会递归删除用户级工作区表、对象存储键或授权资源。

浏览器工具和动态代码执行工具也通过主控侧代理面暴露窄接口。以浏览器工具为例，真实 CDP WebSocket 和浏览器会话保持在主控侧，沙箱或会话子代理仅获得 cdp.send、attachToTarget 等受限 RPC 方法；以动态代码执行为例，沙箱通过状态适配器调用工作区方法，默认不具有任意网络访问能力。对于需要长期保存的工具绑定，系统保存资源定位参数而非活动句柄，并在每次调用时重新解析和校验，使浏览器页面、沙箱代码或某个子会话无法绕开目录代理直接访问共享资源。

### 会话生命周期与跨会话调度

会话创建由用户级目录代理作为权威写入完成：生成会话标识、写入目录行、初始化更新时间和摘要字段，并按需懒创建会话子代理。会话删除采用软删除和代际校验：目录行先写入 deleted_at 或 generation 变化并广播目录状态，客户端发现当前会话已删除后断开对应连接；子代理内仍在进行的流式响应或持久化写入允许自然结束，随后由空闲回收或显式清理机制处理会话级存储。删除流程不调用用户级工作区、共享记忆、外部工具连接或凭据库的删除接口，因此不会因移除一个会话而破坏同一用户其他会话仍需使用的共享资源。

跨会话搜索和调度由目录代理聚合而非由某一会话代理私自扫描共享状态。目录代理可以对标题和摘要建立本地全文索引；需要搜索消息正文时，按候选会话并行调用各会话子代理的会话搜索接口，并按相关度合并结果。对于跨会话任务、后台总结或共享记忆追加，目录代理根据会话目录、权限策略和资源锁定情况选择目标会话或用户级后台子代理执行，执行结果再写回共享上下文或工作区。该机制使跨会话能力建立在显式授权的父级编排之上，而不是让子会话互相读取对方存储。

为降低共享状态并发写入造成的丢失更新，用户级共享记忆优先提供 appendSharedContext 这类追加式原子接口；仅在需要整体替换时才使用 setSharedContext，并可由目录代理记录版本号或更新时间。工作区文件写入默认遵循持久化存储的串行提交语义，必要时可在资源管理器内增加路径级写入队列或版本检查。由此，本方案在保持多会话上下文隔离的同时，为同一用户连续使用同一工作区、同一外部工具连接和同一授权状态提供稳定的用户级资源边界。
