## 技术方案

### 总体架构与边界划分

本方案采用“用户级目录代理加会话级子代理”的组合式架构。针对同一用户账号或同一租户工作区，系统设置一个用户级目录代理作为共享资源和会话索引的归属对象；针对该用户创建的每一个聊天会话，系统分别创建一个会话级子代理。用户级目录代理保存会话列表、会话标识、标题、更新时间、最近消息摘要、共享记忆索引以及共享资源句柄；会话级子代理保存本会话的消息历史、上下文块、流式生成状态、工具调用中间状态和可恢复执行状态。

该架构将“会话隔离”和“用户资源连续性”分配到不同的持久化边界内实现：会话级子代理以独立持久对象承载单个对话，因此不同会话的消息表、上下文拼装、分支再生成、流式缓存和工具结果不会落入同一会话存储空间；用户级目录代理以单个用户为边界承载共享工作区、外部工具连接、授权凭据引用、跨会话检索和调度入口，因此同一用户下切换会话时仍能复用同一套文件和连接能力。

在一种实现中，会话级子代理通过框架的子代理路由机制挂载在用户级目录代理之下，外部访问路径包含父代理身份和子会话身份。浏览器端或客户端并不直接连接任意会话对象，而是基于“用户目录路径+会话子路径”建立到目标会话的 WebSocket 或 HTTP 连接；连接建立前由用户级目录代理执行会话存在性、用户身份、资源授权和路由策略检查，检查通过后再将连接转发到会话级子代理。这样既避免所有会话被强行复用同一个单线程执行对象，又保留了父级代理对会话入口的统一控制。

### 会话访问与上下文隔离机制

系统为每个会话分配稳定的会话标识，并将该会话标识同时写入用户级目录代理的会话索引和会话级子代理的实例名称。会话级子代理内部只读取和写入与本会话标识对应的消息、上下文块、压缩摘要、分支节点和流式恢复元数据；其系统提示词或模型输入由本会话私有上下文与经授权读取的用户级共享上下文共同拼装形成。由于私有上下文的存储和拼装均发生在会话级子代理内，其他会话的消息不会因会话切换、页面重连或后台任务恢复而进入当前会话的模型输入。

父级入口对会话访问执行两级约束。第一，外部路由必须经过用户级目录代理的子会话访问钩子，该钩子根据当前用户身份、会话索引、软删除状态和会话代际标记判断是否允许连接；若会话不存在、已删除或不属于当前用户，则直接返回终止性拒绝响应，不唤醒目标会话。第二，通过检查后，父级入口可向请求注入用户标识、工作区标识、请求追踪标识或能力范围标识，会话级子代理仅依据这些父级签发的上下文访问共享资源，而不是信任浏览器端传入的任意会话参数。

客户端侧维护活动会话选择，但活动会话选择不写入用户级目录代理的共享状态。不同浏览器标签页或不同设备可以同时连接同一用户下的不同会话；每条连接的重连键包含完整父子路径，而非仅包含会话名称，从而避免不同父目录下同名子会话发生连接缓存冲突。会话切换时客户端关闭旧会话连接并建立新会话连接，旧会话的未完成流可由其自身的恢复缓冲继续管理，不影响新会话上下文。

### 用户级共享资源连续性机制

用户级共享资源不随会话级子代理创建而复制，也不随单个会话删除而销毁。用户级目录代理维护共享工作区对象、外部工具连接管理器、授权凭据引用和跨会话调度器；会话级子代理需要读取或修改共享文件、调用浏览器工具、访问外部服务或发起跨会话任务时，必须通过用户级目录代理暴露的受控调用面完成。共享工作区可以采用虚拟文件系统实现，小文件以内联数据库方式保存，大文件通过对象存储溢出保存，并通过命名空间、路径规范化和变更事件隔离不同用户或不同工作区。

对于跨会话共享记忆，系统在用户级目录代理内保存共享上下文块，并向会话级子代理提供远程上下文提供器。会话级子代理在每轮对话开始或提示词刷新边界读取共享上下文，将其作为用户级背景信息拼入当前会话提示词；会话中产生的用户偏好、长期事实或跨会话可复用结论通过追加式接口写回用户级目录代理。追加式写入用于常见的增量记忆场景，可避免多个会话同时执行读-改-写时覆盖彼此更新；完整替换式写入仅用于明确需要重建共享上下文的场景。

对于浏览器执行、代码执行或其他外部工具，系统将真实连接和高权限能力保留在用户级或宿主侧资源管理器中，会话级子代理仅获得窄化后的远程过程调用接口。例如浏览器工具由宿主侧建立真实调试连接，沙箱代码或会话代理只能调用受限的命令发送、目标附着和日志读取方法；代码执行工具通过共享工作区适配器访问文件系统，网络访问和运行时权限由父级策略显式开启。这样可以防止浏览器页面、沙箱代码或某个子会话绕过统一控制直接持有共享资源连接或授权凭据。

跨会话检索和调度由用户级目录代理汇总实现。目录代理可先在本地索引中检索会话标题、摘要和共享上下文，再并行调用各会话级子代理的会话内检索接口，按相关度和时间合并结果返回。对于需要跨多个会话执行的后台任务，目录代理负责枚举目标会话、分发任务、汇总结果并写入共享工作区或共享上下文；会话级子代理只处理分配给本会话的上下文和执行状态，避免将跨会话调度状态散落在各会话内部。

### 会话删除、并发与故障处理

删除会话时，系统只对用户级目录代理中的目标会话记录和对应会话级子代理执行删除或软删除处理，不触碰用户级共享工作区、授权凭据、外部工具连接配置和共享上下文块。优选地，删除操作先将会话索引记录标记为已删除并递增会话代际标记，向目录状态订阅方广播会话列表变化，使已打开该会话的客户端停止重连；随后由系统在安全窗口内关闭或回收对应会话级子代理。该软删除窗口可以避免会话仍在写入消息、工具结果或流式缓存时发生硬删除导致的数据不一致。

在并发访问场景下，用户级目录代理作为共享资源的串行化控制点处理会话创建、会话删除、共享记忆写入和共享工作区元数据更新。会话级子代理可以并行执行模型推理和工具任务，但对共享上下文的增量更新通过父级追加接口提交；对同一路径文件的写入采用父级工作区的数据库序列化能力和必要的版本条件判断。对于父级资源暂时不可用的情况，会话级子代理采用失败软化策略：共享上下文读取失败时本轮以空共享上下文或上次缓存快照继续执行，下一轮在提示词刷新边界重试；共享资源写入失败时记录待提交项或向用户返回可恢复错误，而不是污染本会话私有历史。

通过上述机制，本方案在结构上形成三类明确边界：会话级边界用于隔离消息、上下文和执行状态，用户级边界用于维持工作区、授权和共享记忆的连续性，父级路由边界用于统一执行外部访问控制和资源能力分发。该边界划分使系统能够在同一用户下并行运行多个会话，同时避免上下文串扰、直接资源绕过以及删除单个会话时误删用户级共享资源的问题。
