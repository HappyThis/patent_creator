## 技术方案

### 总体架构与主从边界

本方案在智能工作台现有任务看板和应用数据库之外，增加一个可选的 Git-native 协作镜像层。应用数据库仍作为任务的主存储，任务创建、更新、拖拽改态、分配、评论通知和质量门禁等操作先在主存储内完成；Git 仓库、GitHub Issues 或等价的 Git 托管协作载体只作为外部可读、可协作的同步目标，使开发者工具和 agent 能够通过仓库原生对象理解任务队列，而不需要直接访问应用数据库。

系统可以按项目配置同步目标，例如在项目记录中保存仓库标识、默认分支和同步开关。未开启同步时，任务仍完全按原有方式在任务表、项目表、活动日志、通知和实时事件通道中运行；开启同步后，同步引擎监听或被任务变更流程触发，将主存储中的任务投影为仓库协作对象，并在后台维护任务标识与外部对象标识之间的对应关系。由此，外部协作能力被限定在项目维度内生效，不改变工作台作为主要工作入口的定位。

### 任务到仓库镜像的语义映射

同步引擎对任务对象进行字段级映射。工作台任务的标题和描述映射为仓库协作对象的标题和正文；任务编号、项目票据号、仓库名、外部 issue 编号、外部 URL 和最近同步时间作为关联字段保存；优先级映射为仓库标签；工作台内的标签在去除工作台保留标签后作为普通仓库标签保留。该映射使外部工具能从仓库对象直接读取任务主题、上下文、优先级和来源，同时使应用能够通过稳定关联字段找到镜像对象并执行幂等更新。

为避免状态语义偏差，系统不把工作台的六阶段看板状态简单压缩为仓库的 open/closed 二值状态，而是采用“仓库状态加保留标签”的组合表达：inbox、assigned、in_progress、review、quality_review 和 done 分别映射为带统一前缀的状态标签，例如 mc:inbox、mc:assigned、mc:in-progress、mc:review、mc:quality-review 和 mc:done；仅当工作台状态为 done 时才将外部协作对象置为 closed，其余阶段保持 open。这样既兼容 Git 托管平台的基础状态模型，又保留工作台内部排队、分配、开发中、复核和质量复核等细粒度状态。

在一种实现中，系统在仓库侧预初始化工作台专用标签集合，并在每次推送时替换旧的工作台状态标签和优先级标签，但保留非工作台标签。优先级可以映射为 priority:low、priority:medium、priority:high 和 priority:critical 等标签；若外部对象缺少可识别的优先级标签，则回落到中等优先级。通过区分“保留语义标签”和“用户自定义标签”，同步过程既能维护状态一致性，又不会覆盖开发者在仓库中附加的分类信息。

### 持续同步流程与冲突抑制

从主存储向仓库镜像同步时，任务变更事务先更新本地任务表、活动日志、订阅通知和实时事件，再异步触发外部推送。若任务尚未绑定外部对象且项目开启同步，则同步引擎在目标仓库中创建协作对象，并把外部编号、仓库标识和同步时间回写到任务记录；若任务已经绑定外部对象，则读取外部对象当前标签，保留非工作台标签后更新标题、正文、状态、优先级标签和 open/closed 状态。该流程使任务操作的完成条件只依赖主存储事务，不依赖外部仓库的网络可用性或平台响应时间。

从仓库镜像向主存储同步时，系统按项目的仓库配置和最近同步时间拉取发生变化的外部协作对象。对于未关联的外部对象，系统根据外部对象标题、正文、标签和状态创建新的工作台任务，并写入外部编号、仓库标识、同步时间、项目标识和工作区标识；对于已关联对象，系统先比较外部更新时间、本地更新时间和最近同步时间，只有在外部对象晚于本地任务且不属于刚由本地推送产生的回声更新时，才将外部标题、正文、状态标签和优先级标签回写到任务表。

为抑制双向同步中的 ping-pong，系统把每次成功创建或更新外部对象的时间作为同步水位写入任务记录，并在拉取外部变化时设置短时间窗口：若外部对象更新时间与该同步水位的差值落入预设窗口内，则判定为本地推送的镜像回写并跳过处理；若外部对象更新时间不晚于本地任务更新时间，也跳过处理。该规则使同一变更不会在两个系统之间反复传播，同时允许真正由仓库侧开发者或 agent 修改的任务状态被识别并回流。

### 故障隔离与可观测处理

本方案将外部同步故障隔离在同步引擎和同步历史记录中。任务创建、状态变更和批量拖拽更新完成后，即使仓库访问令牌缺失、仓库不可达、标签初始化失败或外部 API 返回错误，也只记录同步错误并终止本次镜像更新，不回滚已经完成的本地任务事务，不阻断看板展示和实时事件广播。对于后台拉取过程，系统把失败次数、错误原因、同步方向、项目、仓库、推送数量和拉取数量写入同步记录，供界面或运维逻辑展示和重试。

同步记录可以区分 inbound、outbound 或项目级双向同步，并标记 success、partial 或 error 等结果。对于单个外部对象处理失败的情况，系统继续处理同一批次中的其他对象，并将失败计入错误统计；对于整个仓库拉取失败的情况，系统写入错误记录后返回零变更结果。该批次级隔离方式避免一个异常任务或一次外部平台抖动导致整个工作台任务队列不可用。

通过上述主从边界、语义标签映射、同步水位和故障隔离机制，任务既能以开发者熟悉的仓库对象形式暴露给代码审查、命令行工具、自动化脚本和 agent，又不会把外部仓库提升为强一致主库。外部系统看到的是可理解、可追踪、可近实时更新的任务镜像；工作台内部仍保留完整任务状态、质量门禁、项目票据、通知和审计语义，从而降低跨系统协作时的状态歧义和耦合风险。
