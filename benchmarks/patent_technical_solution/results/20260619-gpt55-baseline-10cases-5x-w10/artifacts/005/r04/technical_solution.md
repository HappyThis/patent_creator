## 技术方案

### 总体构思与同步边界

本方案在现有智能工作台的任务看板和应用数据库之外，增加一个可选的 Git-native 协作镜像层。应用数据库仍作为任务事实源和主要操作入口，任务创建、拖拽更新、指派、质量评审、完成时间、评论订阅和实时推送等内部能力继续先在本地事务中完成；当项目启用外部同步并配置仓库标识后，同步引擎再将任务的可共享部分投影为仓库中的 Issue、标签、分支或等价协作对象，使开发者和 agent 能通过 Git 托管平台理解任务队列，而不需要直接读取应用数据库。

同步边界按“项目可配置、任务可追踪、失败可隔离”的原则设置。每个项目保存仓库地址、默认分支、同步开关和标签初始化状态；每个任务保存内部任务编号、项目票号、仓库标识、外部 Issue 编号、外部分支或合并请求状态以及最近同步时间。只有启用同步的项目会进入同步循环，未启用项目的任务完全停留在应用内部。这样既保留智能工作台对任务生命周期的统一管理，又为需要代码仓库上下文的工具提供稳定、可轮询、可审计的镜像对象。

### 任务镜像的数据映射

任务镜像采用字段级语义映射，而不是把数据库记录整体暴露给仓库。内部任务的标题和描述映射为外部协作对象的标题和正文；内部状态映射为带命名空间的状态标签，例如 inbox、assigned、in_progress、review、quality_review 和 done 分别映射为 mc:inbox、mc:assigned、mc:in-progress、mc:review、mc:quality-review 和 mc:done；优先级映射为独立优先级标签，例如 priority:low、priority:medium、priority:high 或 priority:critical。外部对象的 open/closed 状态只表达是否已完成，其中内部 done 对应 closed，其他内部状态保持 open，避免把代码托管平台较粗的状态模型误认为应用内部完整看板状态。

映射引擎在写入外部对象时保留非工作台标签，仅替换带有工作台命名空间的状态标签和优先级标签；在从外部对象回写时，仅解析受控标签集合，其他标签作为任务标签或上下文信息保存。对于从外部仓库首次发现且尚未存在内部记录的对象，同步引擎以仓库号和外部编号生成唯一匹配关系，在应用数据库中创建对应任务，并将创建来源标记为同步来源；对于已有映射的对象，则通过仓库标识和外部编号定位内部任务，避免标题变化、描述变化或标签变化导致重复建单。

### 持续同步与冲突抑制

持续同步包括出站投影和入站拉取两条链路。出站链路在应用完成任务创建或更新后触发，若任务所属项目开启同步，则根据任务是否已经记录外部编号决定创建新外部对象或更新既有外部对象，并在成功后写入外部编号、仓库标识和同步时间。该出站动作在数据库事务、活动记录、通知和实时广播之后以异步方式执行，因此外部仓库不可用、鉴权失败或网络超时不会回滚内部任务操作。

入站链路由后台轮询或人工触发同步执行。同步器按项目读取已启用同步的仓库，根据该项目最近一次成功或失败同步记录确定增量时间窗口，获取该窗口内发生变化的外部对象；对每个外部对象先通过仓库标识和外部编号查找内部任务，未命中则按受控标签创建任务，命中则比较外部更新时间、内部更新时间和最近同步时间。若外部更新时间不晚于内部更新时间，或者外部更新时间与最近一次出站同步时间处于预设容差窗口内，则判定为本系统刚刚投影出的回声更新并跳过，从而抑制双向同步中的 ping-pong 循环。

当外部对象确认为较新的有效变更时，入站链路只回写经过语义映射后的字段，例如标题、描述、受控状态、受控优先级和非受控标签，不直接覆盖内部的质量评审约束、订阅关系、通知记录、成本统计或 agent 运行痕迹。对于内部要求审批后才能完成的任务，外部 closed 状态可以先转换为待确认的完成意图或 review/quality_review 状态，待内部审批机制满足后再进入 done；在无需审批的配置下，也可以直接按 closed 映射为 done。由此保持外部仓库对开发者友好，同时避免外部平台绕过智能工作台内的任务治理规则。

### 故障隔离与可观测性

故障隔离机制把外部同步视为可恢复的旁路能力。同步引擎对项目级同步和单对象同步分别捕获异常：项目级失败仅记录该项目的同步状态、错误信息和时间戳，不影响其他项目继续同步；单个外部对象解析失败、字段冲突或 API 调用失败时，仅跳过该对象并记录日志，不终止整批任务处理。手动同步接口返回本次拉取、推送数量和部分失败信息；后台轮询器记录最近运行时间，使界面和运维流程能够识别同步滞后但不把同步滞后误判为任务系统不可用。

为便于审计和重试，系统维护同步历史表，记录仓库、项目、同步方向、同步状态、错误原因、处理对象数量、推送数量和拉取数量。该历史表与任务活动日志分离：任务活动日志说明任务语义发生了什么变化，同步历史说明这些变化是否已投影到外部仓库。后续重试可以依据任务上的外部编号和最近同步时间重新执行，而不需要重新扫描整个数据库或依赖外部工具访问内部数据。该设计使应用数据库、任务看板和 Git-native 镜像在职责上保持清晰分层，在外部协作能力不可用时仍能保证内部任务流转连续，在外部协作能力可用时又能向开发者和 agent 提供可读、可订阅、可引用的任务状态镜像。
