## 技术方案

### 总体架构与主从边界

本方案在智能工作台的任务主存储与 Git-native 协作镜像之间设置可选同步层。任务的创建、维护、看板展示、权限校验、质量门禁和通知仍以应用数据库为主入口；Git 仓库、GitHub Issue 或等价的 Git 托管协作载体仅作为面向开发者和 agent 的镜像端，用于让外部工具在不访问应用数据库的情况下读取任务队列、任务状态和必要上下文。

同步层包括任务变更捕获单元、语义映射单元、外部载体适配单元、同步账本和故障隔离单元。任务变更捕获单元在任务创建、字段更新、拖拽改状态或删除等主流程完成后取得任务快照；语义映射单元将工作台内部状态、优先级、项目票号、标签和描述转换为外部载体可理解的 issue、标签、正文或文件化记录；外部载体适配单元负责调用 Git 托管接口或写入仓库路径；同步账本记录镜像对象编号、仓库标识和最近同步时间；故障隔离单元把外部同步错误记录为同步状态而非业务事务错误。

项目维度配置外部镜像目标，至少包括仓库标识、默认分支或等价命名空间、是否启用同步以及最近同步记录。只有启用同步且存在有效目标的项目任务才进入外部镜像流程；未配置目标、目标不可用或同步被关闭时，任务仍在应用数据库和看板中完整运行，从而保持外部仓库的可选性。

### 同步镜像的数据模型与语义映射

任务在主存储中保留工作台完整语义，包括标题、描述、状态、优先级、项目、项目内票号、受派对象、创建者、更新时间、完成时间、标签、元数据以及质量评审相关字段。同步镜像不重新定义任务生命周期，而是为每个任务维护稳定外部键，例如仓库标识、外部 issue 编号或镜像文件路径、最近同步时间戳和同步状态，使同一任务在两个载体之间可被确定性匹配。

状态映射采用命名空间化标签或等价字段表达工作台看板列。例如将 inbox、assigned、in_progress、review、quality_review、done 分别映射为 mc:inbox、mc:assigned、mc:in-progress、mc:review、mc:quality-review、mc:done；其中 done 可同时映射为外部 issue 的 closed 状态，其余状态保持 open。优先级映射为 priority:low、priority:medium、priority:high、priority:critical 或与系统内部优先级等价的标签。通过带前缀的标签区分工作台语义和仓库原生标签，避免外部工具把普通仓库标签误解为任务生命周期状态。

当外部载体已有非工作台标签、评论或仓库维护信息时，语义映射单元只替换属于工作台命名空间的状态和优先级标签，保留其他标签和外部协作信息。由外部载体反向生成任务时，若未找到工作台状态标签，则按外部 open/closed 状态推导为 inbox 或 done，并把未识别标签作为任务标签保留；这样既能让开发者按仓库习惯补充上下文，又不会破坏工作台内部状态机。

### 持续同步流程与冲突抑制

从应用到 Git-native 镜像的同步采用业务事务后触发方式。创建任务时，系统先在数据库事务中分配项目内票号并写入任务，再记录活动、订阅和通知，随后以异步方式创建或更新外部镜像对象；更新任务时，系统先依据内部规则完成状态归一化、质量门禁校验、字段更新和活动日志，再根据标题、状态、优先级、指派对象等同步相关字段判断是否需要推送。外部推送失败只写入日志或同步账本，不回滚数据库中的任务变更。

从 Git-native 镜像到应用的同步采用轮询、手动触发或 webhook 触发的增量拉取方式。同步层按项目读取自上次同步时间之后发生变化的外部对象，利用仓库标识和外部对象编号查找本地任务；未匹配到的对象创建为新任务，已匹配对象则比较外部更新时间与本地更新时间，仅在外部对象更新更晚时覆盖标题、描述、状态和优先级等可映射字段。每次同步结束后写入同步账本，记录同步方向、结果、变化数量、错误信息和最近同步时间。

为避免双向同步产生回环，任务在成功推送到外部镜像时写入本地最近同步时间；随后拉取同一外部对象时，若外部更新时间与本地最近同步时间处于预设容差窗口内，则判定该变化源自本系统推送并跳过处理。若超过容差窗口，则继续比较外部更新时间和本地更新时间，只有更新的一侧作为本轮同步来源。该机制使系统不需要全局分布式锁即可抑制“推送—拉取—再推送”的 ping-pong 现象。

### 故障隔离与可观测恢复机制

故障隔离单元把外部仓库访问、鉴权、限流、网络超时、标签初始化失败和单个外部对象同步失败统一视为镜像通道故障，而不是任务业务故障。同步调用设置超时边界，并在项目粒度和单对象粒度分别捕获异常；一个项目同步失败不影响其他项目，一个 issue 或文件同步失败不终止本轮其他对象处理，任务创建、更新、删除接口仍按主存储结果返回。

系统通过同步账本和运行状态接口对镜像通道进行可观测化。同步账本保存仓库、项目、同步方向、成功或失败状态、错误摘要、变更数量和同步时间；运行状态接口可返回后台轮询器是否运行、轮询间隔和最近执行时间。运维人员或 agent 可以据此判断外部镜像是否滞后，而无需直接检查应用数据库。

在一种可选实现中，外部载体可以是 GitHub Issue，也可以是仓库内的结构化 Markdown、YAML 或 JSON 文件。无论采用哪种载体，均保持相同的主从边界、命名空间化状态映射、外部对象稳定键、最近同步时间和故障隔离规则。由此，外部开发工具和 agent 能以 Git-native 方式理解任务队列，同时应用内部任务看板不会因外部系统不可用或语义差异而失去一致性。
