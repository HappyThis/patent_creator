## 技术方案

### 总体分层架构

本方案面向以项目目录下 Markdown 文件承载知识的系统，将知识数据划分为“共享知识层”和“本机运行时信号层”。共享知识层仍采用可读、可审阅、可版本控制的 Markdown 文件及其稳定 frontmatter，保存标题、摘要、标签、关键词、关联路径、事实、叙述、示例、规则等低频知识内容；本机运行时信号层保存访问次数、检索命中次数、排序权重、成熟度、近期使用程度、衰减后的重要性、最后命中时间、清理候选状态等高频变化字段。两层之间不通过文件内容直接嵌套，而通过稳定知识标识建立映射，稳定知识标识可以由知识文件在 context-tree 中的相对路径、标题规范化结果、内容摘要或其组合生成。

共享知识层的写入边界限定为人工整理、curate 操作、合并、删除、摘要生成或经过审阅确认的知识内容变化；检索、查询、提示词装配、命中反馈和后台清理评估不得直接改写共享 Markdown。运行时信号层可以设置在项目工作区的本机隐藏目录、用户级缓存目录或数据库中，并加入版本控制忽略范围。由此，团队共享的 Markdown 保持语义稳定，动态信号仍可被本机检索、排序和清理逻辑持续利用。

### 动态信号采集与本机存储

当知识文件被创建或内容发生经确认的更新时，系统先从 Markdown frontmatter 和正文解析出稳定字段，生成或刷新该文件的知识标识，并在本机运行时信号层建立对应的信号记录。初始记录可以包含默认重要性、初始成熟度、创建时间、最近内容更新时间以及内容指纹；内容指纹用于区分“知识内容已变更”和“仅运行时信号变化”。若旧版本 Markdown 中已经存在访问次数、重要性、成熟度等字段，迁移时只读取一次并写入本机运行时信号层，随后从共享 Markdown 的常规写入模板中排除这些高频字段。

在查询、知识搜索、上下文装配或自动整理过程中，系统把每一次命中、读取、被选入上下文、被人工引用、被 curate 更新等事件转化为运行时信号增量。增量不立即写回 Markdown，而是以知识标识为键进行本机累积，例如累加访问次数和命中次数、记录最近使用时间、按照时间衰减计算近期使用程度，并根据命中或更新事件调整重要性分值。对于排序权重和成熟度，可以采用带阈值回滞的状态计算：重要性达到较高阈值时将知识从草稿态提升为验证态或核心态，低于较低阈值时才降级，从而避免短期波动导致状态频繁抖动。

### 读取融合与排序使用

读取知识时，系统采用先读共享内容、再叠加本机信号的融合流程。第一步递归扫描或索引 context-tree 中的 Markdown 文件，解析其标题、摘要、标签、关键词、关联路径、正文片段和内容指纹，形成候选知识项；第二步按照知识标识查询本机运行时信号层，取得该知识项的访问次数、命中次数、重要性、成熟度、近期使用程度等字段；第三步生成只存在于内存中的融合视图。融合视图对调用方表现为完整知识对象，但不改变 Markdown 原文，因此同一次查询可以利用最新运行时信号，而版本控制只感知真实知识内容变化。

### 清理、迁移与一致性控制

为保证清理和整理结果与共享知识层一致，系统在运行时信号记录中保存最近一次绑定的内容指纹和相对路径。当 Markdown 文件被删除、移动、重命名或合并时，清理过程先依据路径、标题和内容指纹匹配对应信号记录：能够确认同一知识项的，将信号记录迁移到新的知识标识；无法匹配的，将其标记为孤儿记录并延迟删除；合并多个知识文件时，可按访问次数求和、重要性和近期使用程度取较高值、成熟度取较高等级或按预设优先级合并，从而保留历史使用价值。

自动清理共享知识文件时，系统不以单一访问次数直接删除 Markdown，而是基于融合视图形成候选集合，并在执行前再次读取当前 Markdown 指纹进行一致性校验。若候选文件在评估后发生内容变更，则取消本轮清理或重新评分；若候选文件已不存在，则仅清理其本机信号记录；若候选文件仍存在且满足低重要性、低近期使用度、非核心成熟度等条件，则可以生成待审阅删除、归档 stub 或摘要压缩操作。实际删除或归档共享 Markdown 仍通过受控知识写入流程完成，并采用临时文件加重命名等原子写入方式，避免运行时信号更新与共享内容更新交叉造成半写入状态。
