## 技术方案

### 总体分层构思

本方案将知识管理系统中的项目知识划分为“共享知识层”和“本机运行态层”。共享知识层仍采用项目快照中已有的 Markdown 文件、目录树、标题、正文、标签、关键词、关联路径和摘要等内容，作为可审阅、可合并、可随代码仓库或团队空间共享的稳定知识载体；本机运行态层用于保存访问次数、检索命中、近期使用、排序权重、成熟度推导状态、待清理标记等高频变化信号，并默认放置在不参与团队共享或版本提交的本机数据区。两层通过稳定知识标识关联，而不是通过反复改写 Markdown 文件中的 YAML frontmatter 或正文来传播运行时变化。

共享知识层和本机运行态层之间设置字段分级规则：表示知识事实、工程约束、示例、关联主题和可人工审阅摘要的字段属于共享字段；表示访问次数、命中次数、最近访问时间、临时排序分、会话反馈、衰减后的热度、自动清理候选状态等字段属于运行态字段；表示重要度、成熟度等同时具有知识生命周期含义和运行时推导含义的字段拆分为共享基准值与本机推导值。共享基准值仅在人工整理、导入或明确更新知识时写入 Markdown，本机推导值由访问和检索行为实时更新，并在读取时与共享基准值组合使用。

在一种实现中，共享知识根目录可对应项目中的上下文树，Markdown 文件通过 frontmatter 和正文承载标题、标签、关键词、关联文件、事实、叙述结构、代码片段和摘要；本机运行态层可位于同一工作区的本机隐藏目录、用户数据目录或与会话存储相同的本地存储空间，并通过忽略规则排除在 Git 或团队同步之外。这样，团队成员看到和评审的是同一份稳定知识内容，而每台机器可以根据自身查询习惯形成个性化排序和清理建议。

### 运行时信号的本机侧记录

本机运行态层可以采用轻量索引文件、嵌入式数据库或追加日志实现，每条运行态记录至少包含知识项稳定标识、共享文件相对路径、共享文件内容摘要或修改时间、信号类别、信号值、更新时间和来源会话。知识项稳定标识可由共享知识根目录标识、文件相对路径和标题规范化结果生成；当文件发生移动或重命名时，可结合内容摘要、标题和关联路径进行一次性重绑定。运行时产生的访问命中先写入内存计数器或追加日志，在达到时间窗口、数量阈值或进程退出检查点时批量落入本机运行态层，从而避免每次查询都触发文件系统写入。

为降低写放大并保证故障恢复，本机运行态层可以采用“事件日志加聚合快照”的方式保存动态信号。检索命中事件、展开阅读事件、人工收藏事件和清理反馈先以追加记录写入；后台任务周期性将同一知识项的事件聚合为当前访问次数、最近使用时间、命中分布和反馈分。聚合完成后保留检查点，并可删除已合并的旧事件。即使系统在聚合前中断，下一次启动也可从最近检查点重放事件日志，恢复运行态信号，而不会影响共享 Markdown 文件的版本状态。

运行态记录还可区分信号来源和作用范围。例如，搜索结果被返回但未展开阅读时，仅增加较小的曝光信号；用户展开、引用或基于该知识生成后续内容时，增加较高的有效使用信号；人工标记为关键知识时，写入稳定度较高的本机偏好信号。系统可以为不同信号设置衰减周期，使近期访问对排序影响较大，长期未访问的临时热点逐渐回落。该衰减计算在本机运行态层或内存视图中完成，不需要周期性改写共享 Markdown。

### 读取融合与排序计算

读取知识时，系统先扫描共享 Markdown 树建立基础索引，基础索引包含标题、正文、路径、标签、关键词、关联关系、摘要文件以及 Markdown 文件的修改时间；随后按知识项稳定标识查询本机运行态层，将动态信号覆盖或补充到基础索引的内存视图中。该融合只发生在检索、排序、清理评估或自动整理任务的执行视图内，不反向写入共享 Markdown 文件。对于来自外部共享源或只读 Markdown 文件夹的知识，系统仍可读取其稳定内容并参与检索，但本机运行态信号只记录在当前机器的本地记录中，以保持共享源的只读性和团队一致性。

排序计算采用“文本相关性为基础、运行态信号为调节”的方式。共享 Markdown 内容经关键词或全文检索得到基础相关性分数，系统再读取本机运行态层中的重要度、近期使用、访问命中和成熟度推导值形成动态调节项，并对不同成熟度层级施加稳定的提升或抑制系数。对于命中的子主题，系统还可以将一部分相关性向父级主题或摘要节点传播，使目录级知识在其子项高相关时获得合理曝光。上述计算结果只作为本次检索响应和内存缓存中的排序分，不作为共享 Markdown 的持久字段。

为避免读取融合导致多端结果不可解释，检索结果中可同时保留基础相关性、共享基准成熟度、本机动态调节项和最终排序分，并在需要审阅时显示来源说明。若用户关闭个性化运行态信号，系统可仅使用共享 Markdown 内容和共享基准值生成结果；若用户启用本机优化，则在相同共享知识基础上叠加本机信号。由此，同一知识库既能提供团队可复现的基础检索结果，又能支持不同开发者在本机获得更符合近期任务的知识排序。

### 清理、合并与一致性控制

清理和自动整理不直接依据单次检索结果修改共享知识文件，而是基于融合视图生成候选集。系统可将长期未命中、低重要度、低成熟度或与其他文件高度重复的知识项标记为候选清理对象，并将该标记保存在本机运行态层；只有当用户确认清理、团队评审通过或触发明确的整理命令时，才对共享 Markdown 文件执行删除、合并、摘要再生成或结构调整。由此，运行时噪声与知识内容变更之间形成确认边界，既能利用动态信号发现过期知识，又避免本机使用习惯自动污染共享知识库。

为保持清理一致性，系统在执行共享文件删除、合并或重命名前，先读取对应知识项的本机运行态记录并建立迁移计划。删除时，将运行态记录标记为已失效或归档，并保留原稳定标识到删除时间的审计信息；合并时，将源知识项的访问次数、命中记录、最近使用时间和成熟度推导状态按预定规则合并到目标知识项；重命名或移动时，只更新稳定标识到新路径的映射，不丢弃历史信号。若检测到共享文件的内容摘要或修改时间与运行态记录不匹配，则暂停自动清理并重新建立索引，避免依据过期信号处理已经被团队修改的知识文件。

当需要把运行态信号转化为共享知识变化时，系统采用显式提升机制，而不是自动回写机制。满足阈值的本机信号可以生成“建议将该知识提升为核心知识”“建议合并重复知识”“建议删除长期未用草稿”等待审阅操作；经用户确认后，系统才将相应结果写入共享 Markdown 的稳定字段或执行结构调整。写入时只写入经确认的知识生命周期结论，不写入原始访问次数、临时命中次数或会话级热度，从而使共享文件保持低噪声、可审阅和适合版本控制。
