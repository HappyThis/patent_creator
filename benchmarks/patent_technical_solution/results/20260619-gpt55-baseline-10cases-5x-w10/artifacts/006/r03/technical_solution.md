## 技术方案

### 总体分层架构

本方案将项目知识管理系统划分为共享稳定知识层、本机运行时信号层以及查询融合层。共享稳定知识层以项目目录中的 Markdown 文件承载可人工审阅的知识内容，例如标题、摘要、标签、关键词、关联关系、事实片段、叙述说明和代码片段引用，并保持适合团队同步、审阅和版本控制的文本形态。本机运行时信号层用于保存随检索和使用频繁变化的访问次数、命中次数、近期使用度、临时排序权重、成熟度候选值和清理候选标记。查询融合层在读取知识时按稳定标识关联两层数据，生成供检索、排序、整理和清理使用的运行视图，而不要求每次运行都改写共享 Markdown 文件。

该分层结构的关键在于区分“知识事实发生变化”和“知识被系统使用过”两类事件。前者包括人工整理、知识合并、关系调整或摘要更新，属于需要进入共享文件历史的稳定内容变化；后者包括一次搜索命中、一次上下文引用、一次排序加权或一次衰减计算，属于本机运行过程中的动态状态。系统仅在稳定内容变化或达到预设整理条件时更新 Markdown 文件，在普通检索、排序和访问统计过程中优先更新本机运行时信号层，从而保留动态信号价值，同时降低版本控制噪声。

### 稳定知识层与本机运行时信号层

稳定知识层中的每个 Markdown 知识文件具有可重复计算或可持久保存的知识标识。该标识可以由知识库根目录下的规范化相对路径、文件创建时生成的稳定编号、标题与路径的组合摘要，或上述信息的组合得到。Markdown 文件的 frontmatter 和正文用于保存低频、可审阅字段，例如知识标题、摘要、标签、关键词、相关知识路径、事实列表、原始概念、形成原因和人工整理后的叙述内容。对于重要性、成熟度等可能同时具有稳定含义和运行含义的字段，可以在共享文件中仅保存经人工确认或经阈值稳定后的基准值。

本机运行时信号层以侧车存储方式保存与知识标识对应的动态记录。侧车存储可以是本机键值库、轻量索引文件或本地数据库，其记录至少包括知识标识、最近访问时间、访问累计值、检索命中累计值、近期衰减状态、临时重要性、候选成熟度、最后融合时间和记录版本戳。侧车记录位于共享 Markdown 目录之外，或者位于版本控制忽略的本机目录中，使运行时信号可被检索和整理流程使用，但不会因每次访问、命中或衰减而形成共享文件差异。

### 读取融合与排序计算

检索时，系统先从共享稳定知识层读取 Markdown 文件，解析标题、正文、关键词、关联关系和基准评分等稳定信息，并构建全文索引或符号路径索引；随后按知识标识从本机运行时信号层读取对应的动态记录。若未找到动态记录，则使用默认运行时状态参与计算，并可在查询结束后按需创建侧车记录。由此，Markdown 文件提供可复核的知识事实，本机动态记录提供当前机器上的使用反馈，两者在内存中合成为一次查询的候选知识集合。

候选知识的最终排序分数可以由文本相关度、稳定重要性、近期使用度和成熟度共同确定。例如，系统可先将 BM25 或其他文本检索得分归一化，再与稳定知识层中的基准重要性、本机运行时信号层中的近期使用度进行加权融合，并根据成熟度层级施加增益或限制。近期使用度可按文件修改时间、最后访问时间或最后整理时间进行惰性衰减，衰减结果在查询期间参与排序，但不因每次计算立即写回 Markdown 文件。

对于层级化的知识目录，子知识命中还可以向父级摘要传播部分相关度，使父级主题在多个子知识同时命中时获得合理展示机会。该传播使用原始文本相关度或归一化相关度作为输入，再在父级知识自身的基准评分和本机动态信号上进行一次融合，避免把子级生命周期权重重复计入父级。通过上述方式，系统能够在不污染共享文件历史的情况下，同时利用知识内容、目录结构和运行反馈完成排序。

### 写回、整理与清理一致性

运行时信号的写入采用分级写回策略。普通检索命中和访问统计首先累加到本机侧车记录中，并可在内存中批量合并后落入本机存储；当某一知识的访问累计、重要性增量、成熟度变化或整理候选状态超过预设阈值时，系统才将其作为低频整理事件处理。低频整理事件可以触发 Markdown 文件中的基准重要性、成熟度或摘要关系更新，也可以进入人工审阅队列，由审阅结果决定是否提交到共享知识层。

成熟度状态可采用具有滞回区间的分层规则，以避免知识在 draft、validated、core 等层级之间因短期访问波动反复切换。例如，晋升阈值高于降级阈值，只有当融合后的重要性、近期使用度或人工确认状态持续满足晋升条件时才形成共享层更新；当短期热度下降但仍处于保持区间时，仅调整本机运行时视图，不改写 Markdown 文件。该规则使成熟度既能反映知识生命周期，又不会把短期排序波动误认为稳定知识变化。

当知识文件被删除、重命名、移动或合并时，系统同步维护本机运行时信号层的一致性。删除文件时，系统可为对应知识标识写入墓碑记录或立即删除侧车记录，并在下一次索引扫描时清除找不到 Markdown 文件的孤儿动态记录；重命名或移动文件时，系统可记录旧标识到新标识的映射，将访问累计、近期状态和候选成熟度迁移到新记录；合并知识时，系统可将多个动态记录按最大重要性、最大近期度、访问次数求和和较高成熟度等规则合成为目标知识的运行时记录。

### 兼容与可选实施方式

为兼容已有将评分字段写入 Markdown frontmatter 的实现，本方案可以设置迁移和兼容读取规则。读取时，若 Markdown frontmatter 中存在访问次数、更新时间、重要性、近期度或成熟度字段，系统将其作为共享层基准值或初始动态值导入本机侧车记录；写入时，默认只更新本机运行时信号层，并保留 Markdown 中的原有字段不随每次访问变化。对于确需继续暴露在 Markdown 中的字段，可以仅在人工整理、批量提交或达到稳定阈值后回写。

在一种实现中，共享 Markdown 目录可以继续使用受限文件系统和原子写文件机制，以保证知识文件只在知识库目录内被创建、修改或删除，并在稳定内容更新时通过临时文件重命名方式降低写入中断风险。本机运行时信号层则可采用与共享目录分离的存储位置，并通过知识库根目录、相对路径和文件版本戳限定作用范围。不同团队成员或不同机器可共享同一组 Markdown 知识文件，同时保留各自的本机访问历史和排序偏好。

本方案还可以根据部署需要配置不同的共享边界：仅共享 Markdown 稳定知识内容；共享经过批量整理后的成熟度基准；或者在团队明确需要统一排序策略时共享脱敏后的聚合信号。无论采用哪种边界，高频访问命中、短期衰减和临时排序权重均优先保留在本机运行时信号层，只有被认定为稳定知识状态变化的结果才进入共享 Markdown 文件，从而在知识可共享、可审阅、可版本控制与动态信号可利用之间形成平衡。
