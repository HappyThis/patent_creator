## 技术方案

### 总体分层架构

本方案在以 Markdown 文件承载知识条目的知识管理系统中，将“适合共享和审阅的知识内容”与“仅反映本机运行状态的动态信号”拆分为两个存储层，并在读取时进行按需融合。共享知识层继续采用项目目录下的上下文树结构，每个知识条目为可读、可审阅、可版本控制的 Markdown 文件，文件内容包括标题、摘要、标签、关键词、关系、原始概念、叙述结构和代码片段等稳定信息；运行时信号层设置在本机私有存储区或派生索引区中，用于保存访问次数、检索命中、近期使用时间、排序权重、成熟度状态、清理候选状态等高频变化信号。

系统为每个知识条目生成稳定条目标识，条目标识可以由上下文树相对路径、文件内容指纹、标题规范化结果或其组合得到。共享 Markdown 文件只保存能够被团队共同认可的知识事实和人工或模型整理后的结构化内容；运行时信号层以条目标识为主键记录本机观察到的事件流和聚合值。由此，查询、排序和自动整理所需的动态依据不会直接回写共享文件，团队成员仍可通过 Git 等版本控制系统只审查真实知识内容的增删改。

### 共享知识层与运行时信号层

共享知识层中的 Markdown 条目被限定为低频变化对象。系统在写入知识条目时，可以保留 YAML frontmatter 或同等元数据区，但其中只写入可共享的静态元数据，例如标题、摘要、标签、关键词、显式关联路径、来源文件、作者和创建时间；对于访问计数、命中次数、检索排名分、最近访问时间、由本机查询行为推导出的重要度变化等运行时信号，则不写入该 Markdown 文件。对于已有条目中已经包含动态字段的情况，系统可以在迁移或下一次整理时将动态字段抽取到运行时信号层，并在共享文件中保留兼容读取所需的基础字段。

运行时信号层可以采用本机数据库、JSONL 日志、键值文件或内存缓存加落盘快照实现，其记录至少包括条目标识、信号类型、增量值、事件时间、数据来源和可选的衰减参数。访问或检索事件发生时，系统先将事件追加到本机信号日志，再由聚合器周期性或在索引重建前合并为条目级状态，例如累计访问次数、最近命中时间、更新次数、重要度分值、成熟度等级和清理候选标记。该聚合过程只更新运行时信号层，不修改共享知识层中的 Markdown 文件。

### 检索读取融合机制

检索时，系统先从共享知识层构建文本索引和符号树。文本索引用于对标题、路径、摘要和正文进行 BM25 或同类全文检索；符号树用于按照“领域、主题、子主题、条目”的层级进行路径解析、范围过滤和父级传播。随后，读取融合器依据检索结果中的条目标识，从运行时信号层取回对应的本机动态状态，并在内存中临时形成融合视图。该融合视图只参与本次检索、排序、摘要选择或上下文注入，不反向覆盖共享 Markdown 文件。

为避免高频访问事件导致存储放大，读取融合器不在每次命中后立即写入共享知识文件，而是将命中事件写入本机信号缓冲区，并在缓存过期、索引重建、进程空闲或显式刷新时批量合并。对于来自外部共享知识源或只读知识源的条目，系统仍可记录本机运行时信号，但信号记录被标注为本机来源，不改变远端或只读源的文件内容；对于本地项目条目，可以在排序时给予本地知识轻微优先级，以减少共享源噪声对当前项目检索结果的影响。

### 清理与一致性维护机制

清理机制以共享知识层为事实源，以运行时信号层为辅助判断源。系统在启动、索引重建、上下文树整理或定时任务中扫描共享 Markdown 文件，生成当前有效条目标识集合；随后将运行时信号层中的主键与该集合比对。若某一信号记录对应的共享条目已删除、移动或被归并，系统不再将其用于检索排序，并根据映射关系执行迁移、合并或删除：能够通过内容指纹、历史路径或合并日志确认新条目的，将旧信号迁移到新条目标识；无法确认归属的，将该信号记录标记为孤儿并在保留期后清除。

自动整理或清理知识条目时，整理器只把动态信号作为候选排序和风险评估依据，而不把本机访问次数等噪声写回共享正文。例如，长期未命中且静态质量较低的条目可以被列为归档候选，近期频繁命中但内容分散的条目可以被列为合并候选，成熟度较高且被多个查询稳定命中的条目可以被列为核心知识候选。真正改变共享 Markdown 文件的操作仍需满足内容层条件，例如重复内容确认、来源可追溯、摘要可解释或人工审阅通过；仅有本机动态信号不足以直接删除或改写共享知识。

为保证读写一致性，系统在每次构建索引时记录共享知识层的快照指纹，并将运行时信号聚合结果与该快照版本关联。查询过程中若发现条目文件的修改时间、内容指纹或路径映射与信号聚合版本不一致，则先使用共享文件的最新内容并对动态信号执行惰性重绑定；重绑定失败时降级为无动态信号排序。该处理方式使知识文件的共享版本保持干净，同时避免因动态信号滞后导致死引用、错误排序或清理误删。
