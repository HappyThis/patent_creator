## 技术方案

### 总体构思与运行记录层

本方案在智能工作台的既有任务、agent、会话、事件、成本和评估能力之上，新增统一的 agent 执行运行记录层。该运行记录层不替代原有任务表、agent 表、会话表、活动事件、token 用量记录、质量评审记录或评估记录，而是以一次可追踪的 agent 执行为单位生成 $run\_id$，将上述分散事实映射到同一条运行主线中，形成可查询、可审计、可评估和可复用的结构化沉淀。

一次运行可以由任务自动派发、队列领取、CLI 连接心跳返回的工作项、MCP 工具调用、人工指派、周期任务或 agent spawn 事件触发。运行记录在触发点被幂等创建，并在后续 gateway 或 direct API 调用、token 上报、活动事件写入、质量评审、agent eval 以及完成或失败处理过程中持续补全。由此，系统能够在不改变既有任务生命周期的情况下，将“谁在什么 workspace 和项目中、因为什么触发、使用哪个模型或会话、执行了哪些步骤、产出了什么结果、消耗了多少资源、经过何种评估”沉淀为同一视图。

### 结构化数据模型

运行记录层包括运行主记录、运行事件、运行产物、运行指标、运行评估附件和外部引用索引。运行主记录保存 $run\_id$、workspace、project、task、agent、session、connection、trigger、模型、状态、开始时间、结束时间、重试序号和幂等键等字段；运行事件按时间追加状态变化、工具调用、调度决策、heartbeat、token 上报、评审结论、异常和人工反馈；运行产物保存 agent 输出摘要、任务 resolution、文件或外部对象引用、可复用片段和结果校验信息。

运行指标用于吸收既有 token 用量、耗时、成本估算、工具调用次数、失败次数、重试次数和模型路由结果，并保留与原始记录的引用关系。运行评估附件用于关联质量评审、输出评估、trace 评估、component 评估、drift 评估、反馈评分和 golden set 结果。外部引用索引保存任务编号、会话标识、spawn 记录、SSE 事件标识、MCP 调用标识和 CLI connection 标识，使运行记录既可以从任务维度进入，也可以从 agent、会话、外部工具或审计日志维度反向定位。

### 采集、溯源与状态推进机制

在采集侧，系统在任务创建、任务状态切换、自动派发选取、模型路由、gateway 或 direct API 调用、CLI connect、heartbeat、token report、spawn start 和 spawn finish、activity 写入以及 SSE 事件发布等既有入口处设置运行记录适配器。适配器根据 workspace、taskId、agentId、sessionId、connectionId、spawnId 和触发类型计算幂等键；当同一执行已存在主记录时追加事件和指标，当不存在时创建新的运行主记录。该方式避免把运行沉淀做成人工填写日志，并减少对既有任务和会话模型的侵入。

运行状态可以包括 created、queued、running、waiting_review、reviewed、completed、failed、cancelled 和 retried。状态推进以事件追加为准，主记录只保存当前状态和关键时间点。自动派发开始时写入 running 事件，agent 返回结果时写入 output 事件并关联任务 resolution，Aegis 或其他评审完成时写入 review 事件，批准后写入 completed，拒绝重试时写入 retried 并记录父子 $run\_id$ 或 revision，超过阈值失败时写入 failed。异常、超时、工具错误和人工取消均作为独立事件保存，便于后续审计和故障归因。

为保证溯源完整性，运行记录中的每个外部事实均保存来源类型和来源标识。例如 token 用量来自 token 上报或模型调用返回，会话上下文来自 agent 会话或 CLI 连接，评审结论来自质量评审记录，评估分数来自 eval run，执行主体来自 agent 身份与连接状态，触发来源来自任务、周期调度、人工指令或 MCP 调用。查询时可以从运行记录跳转到原始任务、评论、活动、会话、spawn 记录和评估记录，也可以从这些原始对象反查相关运行。

### 评估附着、聚合分析与工具化查询

评估机制采用异步附着方式。运行完成或进入评审阶段后，系统可以将质量评审、四层 agent eval、人工反馈、成本统计和耗时统计分别写入运行评估附件，而不阻塞原任务流转。每个评估附件记录评估层级、评估来源、输入范围、评分、是否通过、明细和生成时间；同一运行可以附着多个评估结果，以支持先完成任务、后补充质量判断或漂移检测的工作方式。

聚合分析以运行记录为事实粒度，可以按 agent、任务、项目、workspace、模型、触发来源、时间窗口和评估层级生成统计。统计项包括完成率、通过率、拒绝率、平均重试次数、平均耗时、token 消耗、成本估算、工具调用成功率、trace 收敛度、反馈评分和漂移幅度。排行榜不直接依赖单一任务状态，而是综合运行状态、评估附件和资源消耗，因而能够区分高产出但高成本、低成本但低通过率、频繁重试或质量稳定等不同 agent 表现。

工具化查询层向 REST、MCP、CLI 和 dashboard 提供同一组运行视图，包括运行列表、运行详情、时间线、成本与 token、评估附件、产物索引、异常事件和 agent 归因。外部工具可以按 $run\_id$ 精确查询，也可以按 taskId、agentName、sessionId、workspace、project、时间窗口或状态过滤。查询接口保持 workspace 隔离和权限校验，并通过时间、workspace、agent、task、session、状态和评估结果等索引支持审计、排行榜刷新、外部报告生成和自动化测试回放。
