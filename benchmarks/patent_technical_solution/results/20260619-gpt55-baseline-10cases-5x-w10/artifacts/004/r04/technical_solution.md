## 技术方案

### 总体构思与运行记录对象

本方案在已有智能工作台能够派发 agent 任务、展示执行结果并记录部分历史信息的基础上，引入以单次 agent 执行为中心的结构化运行记录对象。该运行记录对象不是由人工补写的日志，而是在任务队列、会话网关、流水线运行、调度任务或外部工具连接等执行入口触发时自动创建或关联，用于把一次 agent 执行所涉及的触发来源、执行主体、上下文对象、过程事件、产出结果、资源消耗和评估状态沉淀为可查询的统一事实。

运行记录对象可以包括运行标识、工作区标识、触发类型、触发者或触发系统、agent 标识、agent 名称、关联任务标识、关联会话标识、关联流水线运行标识、外部连接标识、开始时间、结束时间、当前状态、结果摘要、结果或制品引用、错误信息、成本汇总、评估状态以及可扩展元数据。上述字段中的关联标识用于连接既有任务、会话、流水线、审计、token 用量、工具调用和评估数据，使系统无需改变原有执行体系即可形成围绕单次运行的结构化视图。

### 执行触发与溯源绑定

当 agent 执行由不同入口触发时，系统在入口侧生成同一语义的运行标识或关联标识。对于任务队列触发，运行记录绑定任务标识、领取任务的 agent 以及任务状态变化；对于会话或网关触发，运行记录绑定会话标识、消息标识和网关返回的工具事件；对于流水线触发，运行记录绑定流水线运行标识、当前步骤和步骤快照；对于调度、Webhook 或外部 CLI/工具连接触发，运行记录绑定触发配置、连接标识和外部工具元数据。

该溯源绑定机制使一次执行可以回答“为何被触发、由谁触发、哪个 agent 执行、服务于哪个任务或会话、是否属于某个流水线步骤”等问题。触发入口只需在原有任务派发、消息处理、流水线运行或连接登记流程中附加运行标识，不需要另建与执行体系割裂的人工台账；后续审计、成本、评估和查询均围绕该运行标识进行归并。

### 执行过程事件归并与状态沉淀

运行过程中，系统将分散在现有执行链路中的事件按运行标识或关联标识归并。可归并的事件包括任务状态变更、流水线步骤推进、会话消息、工具调用事件、外部连接活动、审计记录、错误或取消事件以及最终完成事件。对于不同来源的工具调用结构，系统先进行名称、类型、输入摘要、输出摘要、耗时、成功状态和错误信息的标准化，再作为运行过程事件挂接到对应运行记录。

运行记录的状态可以随事件流从待执行、执行中、等待外部响应、已完成、失败、取消等状态间转移。状态沉淀时保留关键时间点、当前步骤、最近事件、失败原因和恢复线索，使系统不仅保存最终结果，还能复原执行经过。对于流水线类执行，步骤快照可以作为运行记录的子状态；对于会话类执行，消息和工具调用可以作为运行记录的过程片段；对于安全或权限相关操作，审计事件可以作为运行记录的审计片段。

### 结果、成本与评估附着

在运行完成或阶段性结束时，系统将 agent 产出结果与运行记录绑定。结果可以表现为文本回复、任务状态更新、流水线步骤输出、文件或制品引用、外部工具返回摘要等形式；运行记录保存结果摘要和可追溯引用，而不强制复制全部大体量内容。这样既能支持工作台快速展示“本次执行产出了什么”，也能通过引用回到原任务、会话、流水线或制品位置查看完整结果。

成本附着通过复用 token 用量和成本计算链路实现。系统将一次运行期间产生的模型、输入 token、输出 token、总 token、调用耗时和费用记录按运行标识、agent、任务或会话维度聚合，得到单次运行成本、单任务成本、单 agent 成本以及按模型拆分的成本明细。对于缺少直接运行标识的既有记录，可通过会话标识、任务标识、时间窗和 agent 标识进行补充关联，并把关联置信度写入扩展元数据。

评估附着通过将输出评估、轨迹评估、组件评估和漂移评估等评估结果与运行记录关联实现。在一种实现中，评估引擎可以继续按 agent 名称产生评估结果，同时在评估触发时写入运行标识、任务标识或会话标识；运行记录据此保存是否已评估、评估层级、评分、是否通过、评估详情引用和评估时间。由此，系统能够区分“已执行但未评估”“已评估且通过”“已评估但未通过”等状态，并可将失败原因与具体过程事件、工具调用或成本异常一并呈现。

### 工具化查询、复用与审计扩展

基于结构化运行记录，系统提供面向工作台、内部工具和外部系统的查询接口。查询条件可以包括运行标识、agent、任务、会话、流水线、触发来源、时间范围、运行状态、成本范围、是否评估、评估层级、评估是否通过、工具名称以及工作区。查询结果返回稳定结构，至少包括运行基础信息、溯源对象、状态摘要、结果引用、成本摘要、评估摘要和审计摘要；需要展开时再按引用读取过程事件、工具调用明细或完整评估详情。

该查询接口还可服务于导出、搜索、告警、排行榜和优化建议。导出时，运行记录作为索引行，关联导出审计、流水线、token 用量和评估详情；搜索时，系统可按 agent、触发来源、工具名称、错误摘要或结果摘要定位具体运行；告警时，系统可基于失败状态、成本阈值、评估未通过或工具失败率触发通知；排行榜和优化建议则可基于运行级成功率、平均耗时、单次成本、单任务成本、评估分数和工具失败率进行聚合。

为避免跨工作区或跨系统误关联，运行记录在存储和查询时保留工作区标识、触发入口类型和关联置信信息。系统可对运行标识、agent 标识、任务标识、会话标识、流水线运行标识、创建时间、状态和评估状态建立索引，并在审计日志中记录查询、导出或外部复用行为。这样，结构化沉淀的执行过程既能被其他工具复用，又能保持权限边界、留存策略和审计要求的一致性。
