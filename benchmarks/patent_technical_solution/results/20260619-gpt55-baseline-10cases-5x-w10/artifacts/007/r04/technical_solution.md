## 技术方案

### 总体构思：解耦本地清理与服务端取消

本方案将长时间 agent 对话中的“客户端本地消费生命周期”和“服务端 agent turn 生命周期”拆分为两个相互关联但不相互等同的控制面。客户端的页面刷新、组件卸载、页面切换、流 reader 关闭或短暂网络断开，仅表示当前浏览器观察者不再继续消费本地流，默认不直接表示用户希望终止服务端正在执行的 agent turn；只有用户明确点击停止、应用业务逻辑主动取消，或配置策略判定断开事件应当转化为语义取消时，才向服务端发送与该 turn 绑定的取消请求。

在该解耦结构下，服务端 agent turn 持续产生的流式响应、工具调用状态和最终消息更新，可被视为服务端侧事实流；客户端浏览器连接只是该事实流的一个观察通道。观察通道断开时，客户端可丢弃本地 reader 和 UI 消费过程，但服务端继续记录该 turn 的输出片段、完成状态和错误状态，后续同一会话、同一聊天标识或具备权限的其他标签页可以重新建立观察通道并恢复消费。

### 客户端取消意图分类与传递

客户端 transport 为每个 agent turn 分配或接收可唯一关联的请求标识，并在本地维护该标识与当前流消费者、恢复握手、显式停止动作之间的状态关系。客户端事件首先被归类为本地分离事件、恢复等待事件或语义取消事件：本地分离事件只关闭本地 ReadableStream、移除监听器、释放 resolver 并更新 UI 状态；恢复等待事件保留可恢复标识，等待后续连接重新接管服务端流；语义取消事件才发送携带请求标识的取消帧。

在一种实现中，transport 对来自 abort signal、reader cancel、WebSocket close、React 组件卸载、页面可见性变化和用户停止按钮的事件设置来源标签。来源标签为本地清理类时，transport 执行 detach：本地 stream 进入关闭或错误状态，当前连接从活动消费者集合移除，但不发送取消帧；来源标签为显式停止或应用主动取消时，transport 执行 cancel：向服务端发送包含请求标识的取消帧，并在本地将该请求标识标记为已取消或等待服务端取消完成。

### 服务端 agent turn 管理与恢复

服务端以 agent turn 为单位登记取消控制对象，例如为每个请求标识建立 abort signal 或等效取消令牌，并将该信号传入模型调用、工具调用编排及后续 continuation 流程。服务端仅在收到与请求标识匹配的语义取消帧后触发该取消控制对象；普通连接关闭、观察者离线或未完成恢复握手，不直接触发取消。这样可以避免浏览器生命周期事件误伤仍在执行且可被恢复的服务端任务。

服务端还维护可恢复流状态，用于保存已产生但客户端可能尚未消费完成的响应片段，并记录 active、complete、error 等状态。当新的连接进入同一会话时，服务端可以先发送恢复提示，客户端确认后再回放历史片段并继续推送实时片段；在客户端确认之前，服务端将该连接暂时排除在实时广播之外，以避免恢复片段与实时片段乱序。

### 工具 continuation 与多标签页兼容

对于包含客户端工具结果、工具审批或自动 continuation 的 agent turn，方案将工具 continuation 视为同一 turn 生命周期的一部分。客户端在等待 continuation 恢复握手期间发生组件卸载或本地 stream cancel 时，可以仅关闭本地等待对象；当 continuation 已经绑定到服务端请求标识且用户执行显式停止时，才发送对应取消帧。由此，工具结果已提交但页面短暂断开的场景不会导致服务端 continuation 被错误中止。

多标签页或多连接场景下，方案区分发起连接、恢复连接和观察连接。发起连接可拥有本地请求标识并直接消费当前流；恢复连接通过恢复握手接管已有服务端流；观察连接可以接收服务端广播但不必拥有取消权限。客户端侧通过本地请求标识集合或等效去重机制，避免同一消息既被 transport stream 消费又被广播处理器重复写入；服务端侧对重复 ACK、重复取消和迟到片段进行幂等处理。

### 可配置策略与边界处理

本方案保留取消策略的可配置空间。默认策略可以采用“断开即分离、显式停止才取消”的模式，以支持长对话、流式恢复和移动网络抖动；在对资源占用更敏感或任务不可恢复的应用中，也可以配置为断开后经过超时窗口仍未恢复则取消，或对特定事件来源启用断连即取消。策略判断可以综合事件来源、是否存在可恢复流、任务是否已进入不可安全继续阶段、是否存在其他观察连接以及业务层用户意图。

为避免竞态，取消帧、恢复确认和流式片段均与请求标识绑定。服务端收到取消帧后，可以停止继续向模型或工具链传递执行信号，并将后续迟到片段丢弃或标记为已取消状态；客户端在已经发起取消后，对同一请求的迟到 done、error 或 chunk 只进行状态收敛，不再恢复为正常流。若断连后又恢复而服务端已完成 turn，则恢复流程回放完成状态；若服务端已按策略取消，则恢复流程返回取消或无可恢复流状态。
