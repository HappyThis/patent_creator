## 技术方案

### 总体架构与读取入口

本方案在既有 agent 持久化 workspace 文件工具之上增加“多模态读取编排层”。该编排层不替代原有 read、list、find、grep、write、edit、delete 等工具，而是在读取工具内部或其相邻入口处统一接收路径、分页参数和模型能力参数，先通过 workspace 的 stat、readDir、readFile、readFileBytes 等接口取得文件元数据和必要内容，再根据文件类型与大小选择文本分页、模型可消费附件或结构化降级信息。由此，文本文件仍按现有行号、offset、limit、截断和长行控制返回；图片、PDF 等可被多模态模型消费的文件则尽量形成模型输入部件；普通二进制或超限文件不再被误解码为乱码，而是返回可解释的文件信息和不能直接传递的原因。

读取入口的输入可以保持与现有文本读取工具兼容，包括 path、offset 和 limit；同时增加可选的目标用途参数，例如是否允许生成多模态附件、调用模型可接受的最大字节数、模型支持的 MIME 类型集合以及是否只返回元数据。读取入口输出采用统一结果结构，至少包含 path、fileType、mimeType、size、readMode、content 或 parts、totalLines、fromLine、toLine、truncated、reason 等字段。这样，调用方不需要区分真实 Workspace、共享 Workspace 或自定义后端，只要后端满足基本的文件接口，就能获得一致的读取语义。

### 文件识别与分级读取策略

文件识别流程采用“元数据优先、内容校验补充”的分级方式。系统先读取 stat 或目录项中的 type、size、mimeType、path 和 name；若 MIME 类型缺失或为 application/octet-stream，则根据扩展名、文件头魔数和少量字节采样进行二次判断。例如 PNG、JPEG、GIF、WebP、PDF 等格式可以通过文件头快速识别；UTF-8、JSON、Markdown、TypeScript 等文本内容可以通过解码成功率、控制字符比例和扩展名共同确认。该识别结果不直接等同于读取策略，而是作为后续选择文本模式、多模态模式或降级模式的依据。

在文本模式下，系统沿用现有读取体验：通过 readFile 获取字符串内容，按换行拆分，依据 offset 和 limit 返回从指定行开始的片段，对每行附加行号，并对超过单行长度阈值的内容进行行内截断；当返回行数超过最大行数或调用方给定 limit 时，在结果中标记 truncated、fromLine、toLine 和 totalLines。该路径保证已有文本文件读取、代码定位和长内容控制不受多模态能力引入的影响。

在多模态模式下，系统仅对同时满足三个条件的文件生成模型可消费内容：文件类型属于模型支持的图片、PDF 或其他可接收格式；文件大小不超过系统阈值和当前模型阈值；后端能够通过 readFileBytes 或等价接口安全取得原始字节。满足条件时，系统将字节编码为模型所需的输入部件，例如 data URL、带 MIME 类型的二进制部件或 SDK 支持的 file part，并在结果中保留文件名、MIME 类型、字节数和来源路径，供模型在后续回答中关联引用。

### 模型内容转换与结果表达

多模态读取结果不直接暴露为普通文本，而是先转换为模型输出或消息协议能够承载的结构化内容。对于文本文件，转换器生成 text 类型内容，并将带行号的片段作为工具结果返回；对于可传递的图片或 PDF，转换器生成文件部件并附带一段简短文本说明，说明该部件对应的 workspace 路径、文件类型和大小；对于不适合传递的文件，转换器只生成结构化说明，不附带原始字节。该转换层使模型既能继续像读取文本一样获得可解释上下文，又能在支持多模态输入时真正看到文件内容。

当模型返回包含多模态文件理解结果的回答时，系统可以将模型输出与读取结果的结构化元数据建立映射，避免把二进制内容写入对话日志或工具结果文本。映射关系包括 toolCallId、path、mimeType、size、contentHash 或临时引用标识。前端或上层会话只展示模型对文件内容的解释、摘要或引用，不展示原始 base64 内容；需要复读文件时再由读取入口按相同策略重新取数。这样既降低消息体体积，又避免持久化日志中保存过大的二进制副本。

### 限制控制、错误降级与多后端兼容

限制控制采用多层阈值组合。第一层是 workspace 后端级限制，用于避免读取不存在的路径、目录、符号链接循环或缺失外部对象；第二层是工具级限制，用于控制单次读取最大字节数、最大行数、单行最大字符数和搜索文件最大尺寸；第三层是模型级限制，用于判断当前模型是否支持对应 MIME 类型以及可接受的最大附件大小。任一层不满足时，系统不抛出难以理解的底层异常，而是在结果中返回 error 或 skipped 状态，并给出 fileTooLarge、unsupportedMimeType、binaryNotRenderable、backendMissingBytes、r2Unavailable 等限制原因。

对于普通二进制文件或无法直接被当前模型消费的文件，系统执行降级读取：返回路径、名称、类型、MIME 类型、字节大小、创建或更新时间、可选的内容哈希、检测到的文件头摘要以及限制原因；必要时还返回建议动作，例如使用专门解析工具、压缩或拆分文件、转换为图片或文本后再次读取。该降级结果保证 agent 能知道文件存在、文件大致属性和无法理解的边界，而不是得到空内容或错误的乱码文本。

为兼容真实 workspace、共享 workspace 和自定义文件后端，本方案将读取能力抽象为最小接口和增强接口两级。最小接口包括 stat、readDir 和 readFile，可完整支持现有文本读取；增强接口增加 readFileBytes、mimeType 或等价元数据，可支持图片、PDF 等多模态文件。共享 workspace 可通过代理把上述接口转发到父级真实 workspace，自定义后端也只需实现相同语义即可接入。若后端暂不支持字节读取，系统自动退回文本读取或元数据降级，不影响原有工具集合的可用性。
