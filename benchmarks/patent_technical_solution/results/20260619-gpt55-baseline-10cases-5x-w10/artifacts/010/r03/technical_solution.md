## 技术方案

### 总体构思与工具接口扩展

本方案在现有持久化工作区文件工具的基础上，将“读取文件”从单一文本读取扩展为面向模型上下文的分级文件读取机制。该机制仍以工作区抽象作为唯一文件入口，复用已有的路径、目录、统计信息和文本读写能力，同时在读取工具内部增加文件画像、内容适配和结果封装三个处理层，使模型在面对文本、图片、PDF 以及普通二进制文件时得到一致、可解释且受控的工具返回。

读取工具的输入保持与现有文本读取体验兼容，仍接收文件路径、起始行号和读取行数等参数；工具执行时先调用工作区的 `stat` 获取文件类型、大小、MIME 类型和时间信息，再根据文件类型决定后续读取路径。对于文本文件，继续调用文本读取操作并按行号分页、长行截断和总行数返回；对于可被多模态模型消费的文件，调用字节读取操作取得受限范围内的原始内容，并转换为模型消息可接收的附件部件；对于无法直接消费或超过限制的文件，仅返回结构化文件信息和未传递原因。

为避免把多模态能力绑定到某一种存储实现，读取层定义的工作区接口可以在既有最小接口上可选扩展 `readFileBytes` 或等价的字节流读取能力。真实工作区、跨会话共享工作区代理和自定义文件后端只需提供相同语义的统计、文本读取和字节读取方法，即可接入同一套工具逻辑；未实现字节读取的后端仍可完成文本读取，并对非文本文件返回“后端不支持字节读取”的降级说明。

### 文件识别与分级读取流程

本方案将待读取文件划分为文本可分页类、多模态可直传类和不可直传类。分类时优先使用工作区保存的 MIME 类型，其次结合扩展名和文件头魔数进行校验，必要时抽取文件前若干字节判断是否为有效 UTF-8 文本。文本可分页类包括源码、Markdown、JSON、配置文件和其他可稳定解码为文本的文件；多模态可直传类包括常见图片、PDF 以及当前模型声明支持的其他媒体类型；不可直传类包括压缩包、可执行文件、未知二进制、过大文件、目录和符号链接异常目标等。

读取流程包括：首先对路径进行规范化并查询文件状态，若文件不存在、目标为目录或符号链接无法解析，则直接返回明确错误；其次依据文件大小与工具配置进行预算检查，超过文本读取上限的文本文件进入分页读取，超过多模态直传上限的非文本文件不读取字节而返回元数据；再次选择文本解码或字节读取路径，文本路径输出带行号内容，多模态路径输出附件部件和文件摘要，不可直传路径输出文件画像、限制项和建议的替代操作。

对于文本文件，工具不改变现有行为：从 1 开始计算行号，根据 `offset` 和 `limit` 截取片段，对超长行进行局部截断，对超过最大输出行数的结果标记截断，并返回 `totalLines`、`fromLine`、`toLine` 等字段。对于疑似文本但解码失败或包含大量不可打印字符的文件，工具不强行把乱码传给模型，而是转入二进制降级路径，返回字节大小、推断类型、是否可重试为字节读取以及降级原因。

### 模型可消费内容的转换与返回结构

多模态文件的返回结果采用“工具可读元数据 + 模型可消费内容部件”的双层结构。工具结果中保留路径、文件名、MIME 类型、字节数、读取策略、是否截断、限制原因等结构化字段；同时把符合条件的文件字节编码或引用为模型消息中的图片、PDF 或其他媒体部件，使模型不需要从 base64 文本中自行还原文件，而是直接通过模型提供方的多模态输入通道理解内容。

模型输出转换层负责把读取工具的内部结果映射为会话消息可承载的统一格式。对于文本读取结果，转换层生成普通文本部件，内容继续包含行号和分页提示；对于图片、PDF 等直传结果，转换层生成文件部件，并在相邻文本部件中写入路径、大小、类型和读取限制，便于模型在引用该文件时保持可追溯；对于降级结果，仅生成说明性文本和结构化对象，不把不可消费字节暴露为大段文本。

该转换层还根据模型能力进行二次筛选：如果当前模型不支持某类媒体，即使文件本身属于图片或 PDF，也不会直接附加到模型输入，而是返回“模型不支持该媒体类型”的原因；如果当前模型支持媒体但存在单文件大小、总附件数量或总上下文预算限制，则按配置选择拒绝直传、压缩摘要或仅返回元数据。由此，读取工具能在不同模型之间保持同一调用方式，同时避免把模型无法处理的内容伪装成成功读取。

### 限制控制、降级与多后端兼容

为控制大文件和异常文件对推理上下文、内存和存储后端的影响，本方案在读取工具中设置分层限制：文本读取限制最大输出行数、单行长度和单次返回字符量；搜索类读取限制单文件大小和最大命中数；多模态直传限制单文件字节数、单次工具调用附件数量和总字节预算；字节读取还设置超时和后端错误捕获。任何限制触发时，工具均返回可解释的限制字段，而不是静默丢弃或返回不完整文件。

普通二进制文件采用安全降级策略。工具返回文件路径、名称、类型、大小、MIME 推断结果、是否命中已知媒体白名单、是否超过大小限制、是否缺少字节读取能力等信息，并给出限制原因，例如“未知二进制类型”“超过多模态直传上限”“当前模型不支持 PDF”或“自定义后端未提供字节读取”。该降级结果使模型能够了解文件存在及其边界条件，但不会把不可解释的二进制内容压入文本上下文。

多后端兼容通过操作接口适配实现。对于真实工作区，工具直接使用已有的 SQLite 元数据、内联内容和可选 R2 大文件存储能力；对于共享工作区，子 agent 的代理对象把 `stat`、`readFile`、`readFileBytes`、`readDir` 等调用转发到父级工作区，使不同会话读取到同一份文件内容；对于自定义后端，适配器只需满足统计、文本读取、目录读取和可选字节读取的契约，即可获得相同的分类、限制和降级行为。

通过上述机制，系统在不破坏既有文本读取体验的情况下，将图片、PDF 等文件纳入 agent 的可理解上下文；同时对无法直传的文件给出明确的结构化反馈。模型因此能够基于真实工作区中的多模态材料进行分析，而工具层仍保持分页、截断、错误说明和后端无关性，降低大文件、乱码和不受支持媒体类型导致的推理失败风险。
