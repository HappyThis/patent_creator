## 技术方案

### 总体构思与读取链路

本方案在现有 agent workspace 的持久化文件系统之上增加“多模态读取适配层”。该适配层不替代原有 `readFile`、`readFileBytes`、`stat`、`readDir`、`glob` 等能力，而是在模型请求文件内容时，先通过统一的工作区文件接口取得文件元数据、字节流或文本内容，再根据文件类型、文件大小、模型可消费能力和当前上下文预算生成标准化读取结果。由此，文本文件仍按照既有文本读取路径返回，图片、PDF 等可被多模态模型消费的文件被转换为模型消息可接收的文件部件，普通二进制或受限文件则返回结构化说明和未传递原因。

一次读取请求可以包括目标路径、期望读取模式和分页参数。系统首先对路径执行规范化和安全校验，并解析符号链接；随后调用工作区的 `stat` 获取类型、大小、媒体类型和修改时间等信息。若目标不是普通文件，返回目录或符号链接的结构化状态；若目标是文件，则进入分类读取流程。分类读取流程以“优先保留原有文本体验、在安全范围内尽量提供多模态内容、不可消费时提供可诊断信息”为原则，输出统一结果对象，结果对象至少包括路径、文件名、文件类型、大小、内容载荷、分页或截断信息、限制标记和错误说明。

### 文件类型识别与多模态封装

文件类型识别采用元数据与内容特征结合的方式。系统优先使用工作区记录的 `mimeType`、文件扩展名和调用端写入时携带的媒体类型；当这些信息缺失或为通用二进制类型时，读取文件头部有限字节并识别常见魔数，例如 PNG、JPEG、GIF、WebP、PDF 等格式标识。识别结果被归一为文本、可直接传递的多模态文件、可提取预览但不宜直接传递的文件、普通二进制文件四类，并记录识别依据，避免仅因扩展名伪装而将不可用内容传入模型。

对于被识别为图片、PDF 或其他模型支持的多模态文件，系统通过 `readFileBytes` 或流式读取接口取得受限大小内的字节内容，并将其封装为模型消息中的文件部件，文件部件包含媒体类型、文件名、字节数据或可访问引用以及供模型理解的说明文本。若底层模型接口要求特定表示形式，适配层负责在工具结果与模型消息之间转换，例如将字节编码为数据引用、将 PDF 标记为文档部件，或将图片标记为图像部件；转换后的部件与用户问题、工具调用结果或系统提示一起进入 `convertToModelMessages`、`streamText` 等模型调用链路，使模型在后续推理中能够直接消费工作区内的非文本内容。

### 文本兼容、分页与限制控制

文本文件继续沿用原有读取语义。系统对文本内容按行切分并保留行号，读取请求可以指定起始行、最大行数或最大字符数；当文件超出单次返回限制时，结果中给出 `truncated`、下一页起点和已返回范围，使 agent 可以按需继续分页读取。对于 UTF-8 文本、由 base64 存储的文本以及 R2 溢出存储的文本，均统一解码为同一格式的带行号内容，从而保持现有文件读取、搜索、长内容控制和模型上下文裁剪体验不变。

限制控制分为文件级、片段级和会话级三层。文件级限制根据大小、媒体类型和后端存储位置判断是否允许读取全部字节；片段级限制控制文本返回的行数、字符数以及多模态文件的最大字节数；会话级限制结合当前模型上下文预算和历史消息裁剪策略，决定是否直接传递文件、只传递缩略或摘要信息，或要求 agent 分页继续读取。当文件超过阈值、模型不支持该媒体类型、字节读取失败或安全策略禁止传递时，系统不返回不可解释的空内容，而是返回包含大小、媒体类型、可用操作和限制原因的结构化结果。

### 后端适配与错误降级

为兼容真实 workspace、共享 workspace 和自定义文件后端，多模态读取适配层只依赖稳定的工作区抽象接口，而不直接绑定具体存储实现。对于本地或单 agent 工作区，适配层可直接调用 `Workspace` 的元数据、文本和字节读取方法；对于共享工作区，子 agent 通过代理对象将同一组调用转发到父 agent 持有的真实工作区，使跨会话共享文件仍然只有一个事实来源；对于自定义后端，只需实现读取文本、读取字节、读取目录和获取文件状态等最小接口，即可接入同一分类和封装流程。

错误降级采用可解释结果而非异常外泄。文件不存在时返回明确的未找到状态；目标为目录时返回目录项概览而不是尝试按文件读取；目标为普通二进制时返回哈希、大小、媒体类型、前缀识别信息和“不可直接传递给模型”的原因；R2 等外部大文件存储未配置或对象缺失时，返回后端限制说明和可重试条件。上述降级结果仍可被模型作为结构化事实使用，使 agent 能够向用户说明限制、选择其他读取方式或请求用户提供可支持格式，而不会破坏文本读取工具的既有调用习惯。
