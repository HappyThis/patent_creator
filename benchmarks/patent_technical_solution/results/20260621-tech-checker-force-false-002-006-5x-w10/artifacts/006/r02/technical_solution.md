## 技术方案

### 总体分层构思

本方案采用“共享知识文件层 + 本机动态信号层 + 查询时融合层”的分层结构。共享知识文件层以 Markdown 文件承载可被团队审阅、同步和版本控制的稳定知识；本机动态信号层承载访问次数、检索命中、近期使用、局部排序权重、运行时成熟度调整等高频变化信息；查询时融合层在读取阶段把两层数据按同一知识标识进行合成，并只将融合结果用于本次检索、排序和展示。由此，Markdown 文件不再因每次查询、命中或排序权重微调而产生版本噪声，同时运行时信号仍可持续影响本机检索质量。

该分层结构的核心不是简单禁止写入元数据，而是区分“需要共享审阅的知识事实”和“随本机使用过程变化的运行反馈”。前者包括标题、正文、标签、关键词、关联关系、上下文摘要、知识所在的领域或主题路径等；后者包括某一机器或某一使用者的查询命中次数、最近命中时间、衰减后的热度、针对本机偏好的加权分、临时成熟度提升或降级等。系统在写入知识时优先更新稳定内容层，在查询或阅读知识时更新动态信号层，在需要生成检索结果时临时融合两层，从而把协作共享和个性化优化解耦。

### 共享 Markdown 知识层

共享 Markdown 知识层按照上下文树组织知识文件，可采用类似“领域/主题/标题.md”的层级路径，也可以在领域或主题目录下设置上下文说明文件和自动生成的摘要文件。每个知识文件的正文描述可复用的项目事实、约束、规则、设计背景或操作经验，文件头部可记录标题、标签、关键词、关联路径、摘要等低频元数据。由于该层文件直接参与团队共享、审阅、云端同步或 Git 类版本控制，其内容应保持可读、可合并和可追溯。

共享层为每条知识生成稳定定位信息，定位信息可以由规范化相对路径、来源标识、标题以及内容指纹中的一种或多种组合得到。对于来自本项目的知识，稳定定位信息指向本项目的上下文树文件；对于只读共享源或外部 Markdown 文件夹，稳定定位信息还包含来源别名或来源根目录标识，以避免不同来源下相同相对路径的知识发生混淆。该定位信息作为动态信号层的主键或外键，使运行时反馈能够关联到正确知识项，而无需改写 Markdown 正文。

### 本机动态信号层

本机动态信号层以独立于 Markdown 文件的本地索引、侧车文件或轻量数据库保存运行反馈。每条动态记录至少包括知识稳定标识、信号更新时间和信号值集合，信号值集合可以包括访问次数、查询命中次数、最近访问时间、最近命中时间、由使用频率计算得到的热度、由长时间未使用产生的衰减值、局部排序权重、成熟度候选状态以及来源优先级等。动态记录可以按知识项粒度保存，也可以按目录摘要、领域节点或共享来源粒度保存聚合值。

动态信号可以采用可解释的更新规则。例如，访问次数和检索命中次数按照事件发生次数幂等累加；最近访问时间和最近命中时间保留最新时间戳；热度可以由命中次数、访问次数和距离当前时间的衰减系数组合得到；近期性可以随未使用天数增加而逐步降低。这样，频繁且近期使用的知识能够在本机排序中得到适度提升，而长时间未使用的知识会自然回落，但其共享 Markdown 内容和团队审阅状态不因本机热度变化而改写。

动态信号的写入采用与知识文件写入不同的触发条件。新增、合并或显式修订知识内容时，才更新共享 Markdown 层；检索命中、阅读访问、结果点击、排序反馈和近期使用衰减等高频事件仅更新本机动态信号层，并可采用异步批量写入、幂等累加和时间窗口合并，避免每一次查询都触发共享文件变更。对于成熟度这类既可能反映团队共识、又可能受本机使用习惯影响的信号，本方案将其拆分为共享基线成熟度和本机运行时成熟度候选值：前者通过显式整理或审阅流程写入共享层，后者只作为本机排序和提示依据。

### 读取融合与排序

读取融合层在查询时分别访问两类数据源：一方面从共享 Markdown 知识层解析正文、标题、标签、关键词、关联关系、层级路径和共享基线成熟度，并通过全文索引或关键词索引得到相关性得分；另一方面以知识稳定标识为键，从本机动态信号层读取访问次数、最近命中时间、热度、局部排序权重、来源偏好和成熟度候选值。融合层不把两类数据预先合并回 Markdown 文件，而是在一次查询、一次推荐或一次上下文装配过程中生成临时的知识视图。

融合排序可以将文本相关性作为基础分，再叠加重要性、近期性、成熟度、热度和来源权重等因子。文本相关性用于保证结果与查询意图匹配，重要性和成熟度用于提高稳定核心知识的优先级，近期性和热度用于反映本机最近频繁使用的知识，来源权重用于在本地项目知识、只读共享知识源和外部 Markdown 文件夹之间形成可配置偏好。在一种实现中，各因子先归一化到相同区间，再按可配置权重求和或分段调整，得到仅在本次检索结果中使用的综合分。

### 清理一致性与冲突抑制

为保证动态信号与共享知识文件一致，本方案在索引或读取阶段为每个 Markdown 文件维护文件状态签名。文件状态签名可以由规范化相对路径、文件修改时间、文件大小、内容指纹和来源标识中的一种或多种组成。当签名未变化时，可以复用已有索引和动态信号映射；当签名变化时，系统重新解析该知识文件，并根据稳定标识和内容指纹判断其属于内容更新、移动重命名还是新增知识，进而决定动态记录是继续绑定、降权保留还是创建新记录。

当稳定定位信息出现多个候选绑定时，可以采用确定性的冲突处理顺序。优先以来源标识或来源根目录区分命名空间，使相同相对路径但来源不同的知识分别维护动态记录；在同一来源内，优先使用内容指纹和规范化路径共同确认同一知识项；若内容指纹相同但标题不同，可以视为复制或派生知识，默认分别建立动态记录，只有在显式合并或重命名确认后才迁移历史信号；若路径、标题和内容指纹之间无法形成一致判断，则保留原动态记录并对其逐步降权，同时为新知识创建新的动态记录。

当共享 Markdown 文件被删除、移动或从某个只读共享源中移除时，动态信号层可能遗留不再对应有效知识项的孤儿记录。本方案可以在检索索引重建、目录扫描、知识清理任务或动态记录读取失败时执行孤儿检测：若稳定标识对应的文件不存在，且无法通过内容指纹或重命名记录重新绑定，则将该动态记录标记为失效并在本机清理；若能够确认是路径移动或来源别名变更，则将动态记录迁移到新的稳定标识下。由此可以避免查询结果出现失效引用，同时保留合理的历史使用反馈。

冲突抑制方面，本机动态信号层默认不进入共享 Markdown 的版本控制、云同步审阅或团队合并流程，因此访问次数、最近命中时间、热度衰减等本地运行事件不会形成反复变化的文件差异。对于只读共享知识源，系统仅允许读取其 Markdown 内容并在本机保存派生动态信号，不向该来源写回访问反馈。对于可写项目知识源，只有知识正文、共享标签、关联关系、摘要和经确认的共享成熟度等低频稳定内容才通过显式整理动作写回共享层，从而将多人协作冲突限制在真正需要审阅的知识事实上。

### 可选实施方式与边界

本机动态信号层的物理形态可以根据部署环境选择。桌面或命令行工具可以采用知识目录旁的侧车文件、用户主目录下的本地索引文件或嵌入式数据库；服务端环境可以采用按用户、项目或工作区分区的轻量数据表；资源受限场景也可以采用内存缓存结合周期性落盘。无论采用何种形态，动态层均以共享知识稳定标识为连接点，并与 Markdown 文件的共享审阅链路保持解耦。

在需要团队共享运行反馈的场景中，可以将本机动态信号先在本地累计，再按照时间窗口、最小变化幅度或人工确认条件汇总为低频共享指标，而不是把每次检索命中直接写回 Markdown。对于成熟度提升、核心知识标记、跨项目来源优先级等会影响团队共同认知的变化，应通过显式整理、审阅或发布动作写入共享层；对于仅反映个人工作流的访问偏好、近期使用热度和临时排序权重，则保留在本机动态层。该边界使系统同时具备 Markdown 知识文件的可共享、可审阅和可版本控制能力，以及运行时信号的连续学习能力。
