## 技术方案

### 总体架构与分层边界

本方案面向以 Markdown 文件承载项目知识的知识管理系统，将“可共享、可审阅、可版本控制的知识内容”与“随本机运行不断变化的检索和使用信号”分层处理。系统包括共享知识文件层、本机运行时信号层、读取融合层和一致性清理层。共享知识文件层保存知识条目的标题、摘要、标签、关联关系、来源、正文叙述、代码片段和经审阅后适合固化的生命周期信息；本机运行时信号层保存访问次数、检索命中次数、近期使用时间、热度、排序权重、懒衰减后的临时分值、索引缓存状态等高频变化数据；读取融合层在检索、展开知识或整理知识时同时读取两类数据并计算有效排序结果；一致性清理层在知识文件删除、移动、来源变化或版本同步后清理孤立信号、索引和缓存。

上述分层的核心边界是：Markdown 文件表达知识本身及其稳定关系，本机运行时信号表达某一项目、分支、用户或机器在一段时间内对该知识的使用状态。检索或排序所需的动态信号不直接作为共享知识内容的一部分频繁回写到 Markdown 中，从而避免一次搜索、一次命中或一次排序权重变化即造成版本控制脏状态、多人合并冲突，或者使真正的知识内容变更被大量计数类噪声淹没。

### 稳定知识文件与本机动态信号层

共享知识文件层采用人类可读的 Markdown 条目作为基本存储单元，每个条目可以通过 YAML frontmatter 和正文区域描述知识标题、摘要、标签、关键词、关联条目、来源、原始概念、叙述说明、事实列表和代码片段。该层适合由开发者或智能体审阅、提交、分支、合并和跨机器同步，因此只承载相对稳定、能够代表项目知识内容和结构关系的信息。对于重要度、成熟度等生命周期字段，只有当其来源于人工审阅、整理操作或低频确认过程，并且具有共享价值时，才可选择固化到 Markdown 文件中。

本机运行时信号层采用 overlay、sidecar 文件、本地数据库或键值存储记录高频动态信号。该层可以记录知识条目的访问计数、搜索命中计数、最近命中时间、近期使用衰减值、热度、排序临时权重、按查询类型形成的局部反馈、索引构建时间、文件修改时间快照和缓存有效性信息。运行时信号层的存储位置被配置为不进入共享提交和同步，例如通过 context tree 内的忽略规则、派生产物排除规则或本机状态目录隔离，使本机检索活动不会污染共享 Markdown 文件的版本差异。

当检索、阅读、展开上下文或排序过程产生新的访问事件时，系统先在内存中累计事件，再按照节流、批处理或异步落盘策略写入本机运行时信号层。该过程可以与知识内容写入解耦：知识整理、合并、删除等操作仍通过 Markdown 写入器生成或修改共享条目；访问命中、近期热度和临时排序权重则不触发 Markdown 文件内容更新。

### 条目映射与来源隔离

为使本机动态信号能够在不改写 Markdown 的情况下准确作用于对应知识条目，本方案为每个知识条目建立稳定映射键。该映射键可以包括规范化后的 context tree 相对路径、frontmatter 中的稳定标识、条目内容摘要、来源标识和符号路径中的一种或多种。对于本地知识条目，映射键指向本项目的 Markdown 文件；对于只读共享来源，映射键还包括来源别名或 origin 标识，以区分同名路径在不同来源中的知识。

当知识文件发生重命名、移动或由同步合并引起路径变化时，系统先使用规范化路径进行直接匹配；若直接匹配失败，则可依据稳定标识、内容摘要、标题与关联关系组合进行迁移匹配，将原动态信号转移到新的映射键下。若知识文件被删除或共享来源被移除，则对应动态信号被标记为 orphan，并在清理周期内删除或归档。对于无法确认归属的 orphan 信号，系统不将其写回任何 Markdown 文件，而是使用默认评分继续处理现存知识条目。

迁移匹配存在多个候选条目时，系统可按稳定标识一致、内容摘要相似度、规范化路径相近度、标题一致性和关联关系重合度计算候选置信度。仅当最高置信度超过预设阈值且与第二候选之间的差值满足安全间隔时，才迁移动态信号；若候选之间难以区分，则放弃自动迁移，将原信号保留为 orphan 记录并等待后续清理或人工确认，避免把本机热度、访问计数错误地附着到无关知识条目。

动态信号还可以按照项目、分支、用户、机器和来源进行隔离。同一共享 Markdown 条目在不同开发者机器上可以具有不同访问热度和近期使用状态，但这些差异仅影响各自本机的检索排序，不改变共享知识文件本身。对于来自其他项目的只读知识源，本机可以为检索结果记录本地命中和阅读信号，但不会把这些信号写入对方项目的 Markdown 条目。

### 检索融合与排序计算

检索请求到达后，读取融合层先扫描或读取缓存中的 Markdown 条目，解析标题、正文、路径、标签、关键词、关联关系、成熟度等稳定内容，并基于文本相关性模型生成基础相关性分数。其中，context tree 是指按照领域、主题、子主题和上下文条目组织的文件化知识目录；symbol tree 是指由路径、标题或符号标识构成的轻量索引树，用于快速定位条目及其父子关系。例如可以采用 BM25 或 MiniSearch 类索引对标题、正文和路径分别赋权，得到查询与各知识条目的文本匹配程度；同时根据 symbol tree、关系索引和层级目录将子条目的命中分数向上级主题或摘要节点传播，使检索结果能够覆盖直接命中的上下文及其相关父级知识。

在获得基础相关性分数后，读取融合层再按映射键读取本机运行时信号，形成有效排序分。有效排序分可以由文本相关性、稳定重要度、成熟度、近期使用衰减值、访问热度和本地来源偏置加权得到；其中近期使用衰减值可根据当前时间与最近访问或更新时间的间隔懒计算，访问热度可根据累计访问次数或命中次数计算，成熟度可对 draft、validated、core 等层级设置不同增益。懒计算得到的临时分值仅参与本次排序或更新本机信号层，不在搜索请求过程中回写共享 Markdown。

检索返回结果时，系统可对结果应用作用域过滤、知识类型过滤、成熟度过滤、最低相关性阈值和分数间隙过滤，输出路径、标题、摘录、符号路径、来源、关联条目和融合后的排序分。对被返回或被用户展开的条目，系统只在内存或本机运行时信号层累计访问事件；后续索引重建或批处理周期再更新本机动态信号，而不因单次搜索改变 Markdown frontmatter 中的计数字段。

### 写入边界与清理一致性

本方案将知识内容写入与运行时信号写入设置为不同触发条件。新增、更新、合并或删除知识条目时，系统通过受控的知识整理操作修改 Markdown 文件，并可采用临时文件写入后原子重命名的方式避免部分写入造成文件损坏。搜索命中、阅读访问、排序反馈、缓存刷新和临时衰减计算不属于知识内容变更，只更新本机运行时信号层或内存状态。

本机运行时信号层的落盘可以采用事件数量、时间窗口和进程生命周期组合触发。例如访问事件累计达到设定数量、距离上次落盘超过设定时间、索引重建前、切换项目或进程关闭前，系统将内存中的访问命中和排序反馈批量写入本机信号层。批处理期间对同一映射键的多次事件先合并为一次增量更新，从而减少磁盘写入次数，并避免因高频检索导致共享知识文件反复变化。

一致性清理层在索引构建、版本同步、来源刷新或文件系统扫描时执行校验。校验内容包括：Markdown 条目是否仍存在，派生产物、摘要文件、概览文件和归档 stub 是否应排除同步，动态信号的映射键是否仍能命中现存条目，缓存中的文件修改时间是否与磁盘一致，以及共享来源是否新增、删除或变更。若发现 Markdown 条目已删除，则删除对应索引项、缓存项和本机动态信号；若发现动态信号缺失，则按默认访问次数、默认重要度和默认近期值参与排序；若发现信号记录没有对应条目，则延迟回收或归档而不生成新的知识文件。

在并发读写或索引重建场景下，读取融合层可为索引缓存和本机信号层设置版本号或构建时间戳。检索开始时记录所使用的 Markdown 快照版本、信号层版本和索引版本；若检索结束前检测到 Markdown 文件修改时间、共享来源清单或信号层版本发生变化，则可继续返回基于旧快照的结果并触发后台重建，也可在强一致模式下重新读取并计算。写入本机信号时，对同一映射键采用短时锁、乐观版本校验或追加日志合并，避免并发 flush 覆盖访问计数增量。

通过上述写入边界，系统能够在保留运行时动态信号价值的同时维持共享知识文件的稳定性。团队成员仍可基于 Markdown 文件进行审阅、提交、分支、合并和云端同步；每台机器又能根据自身的近期访问、搜索命中和使用习惯获得差异化排序。只有当动态信号经过整理并被确认具有跨用户共享意义时，才可由知识整理操作将其转化为稳定元数据写入 Markdown，否则该信号保持在本机运行时层。
