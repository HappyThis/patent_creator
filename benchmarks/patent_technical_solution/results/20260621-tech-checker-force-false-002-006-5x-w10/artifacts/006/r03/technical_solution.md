## 技术方案

### 总体构思：共享知识层与运行时信号层分离

本方案面向以 Markdown 文件作为项目知识载体的知识管理系统。系统将可共享、可审阅、可进行版本控制的稳定知识内容，和访问次数、检索命中、排序权重、成熟度、近期使用情况、查询日志等高频变化的运行时动态信号分层存储。稳定知识层继续使用 Markdown 正文及必要 frontmatter 表达标题、摘要、标签、关联路径、关键词、事实说明、设计理由等适合团队共享和代码审阅的内容；运行时信号层则使用本机或用户范围内的独立存储保存随检索、查询、整理任务频繁变化的反馈信号。

该分层结构的关键在于：Markdown 文件不再因为一次搜索命中、一次查询访问或一次排序衰减而被直接改写。检索排序、热度提升、近期性衰减和成熟度临时判断在读取路径上即时融合，或者在本地运行时信号层批量累计；只有当知识本身发生真实内容变更、人工审阅确认某一信号已经转化为稳定知识评价，或系统执行明确的摘要固化策略时，才允许更新共享 Markdown 文件。由此，版本控制差异主要反映知识内容和结构的真实变化，而不是运行时计数器的抖动。

### 数据分层与知识条目标识

稳定知识层中的每个知识条目以 Markdown 文件表示，并可包括 YAML frontmatter 和结构化正文区段。frontmatter 适合保存标题、摘要、标签、相关条目、关键词、来源、知识类型、人工确认的成熟度等低频变化字段；正文区段适合保存原始概念、叙述说明、事实列表、原因说明、示例片段等可被审阅的知识内容。对于摘要文件、概览文件、归档桩文件和清单文件等派生物，系统使用类型、后缀或目录规则标识其是否参与全文索引、摘要传播、快照同步或版本控制差异。

运行时信号层以知识条目的稳定标识为键保存动态信号。该稳定标识可以包括知识条目的规范化相对路径、所在知识源标识、内容哈希、摘要层级、归档桩指向关系或版本标记中的至少一种。对于本地知识条目，路径标识用于快速定位文件，内容哈希用于判断文件是否发生实质变化；对于共享只读知识源，标识中加入来源别名或来源根标识，防止不同项目中的同名路径相互覆盖。对于被移动、合并、删除或归档的条目，系统依据路径映射、归档桩的原始路径和指向字段、合并记录或快照差异，将原有动态信号迁移到新条目、标记为失效，或按照保留策略删除。

### 读取融合与检索排序

检索时，系统先从稳定知识层构建或读取索引。普通知识 Markdown 作为可检索正文进入 BM25 或其他文本相关性索引；摘要文件可以作为目录或主题级知识参与父级传播；概览文件、全文归档文件、清单文件等派生物根据规则仅用于缓存失效、展开读取或一致性校验，而不作为普通正文重复参与检索。索引构建时保留本地来源和共享来源的来源标识，使同一检索请求能够同时覆盖本项目知识和只读共享知识，并在结果中区分 local、shared 或其他 provider。

在得到文本相关性分数后，系统再按知识条目标识读取运行时信号层中的动态信号，并生成仅用于本次检索或本地缓存周期的综合分。综合分可以融合 BM25 归一化分数、人工或历史形成的重要性、近期性衰减值、成熟度层级、访问命中次数、查询日志中的匹配质量、来源优先级、父级摘要传播分以及本地使用热度。对于近期性和重要性，可采用指数衰减或分段衰减；对于成熟度，可设置 draft、validated、core 等层级增益；对于父级摘要，可将子条目的文本命中信号向父级传播，但避免将生命周期权重重复计算。

一次检索或展开读取产生的命中反馈先写入运行时信号层的待处理集合或查询日志，而不是立即改写 Markdown frontmatter。待处理集合按知识条目标识累计访问命中次数、最后命中时间、查询语义、命中文档路径、结果分数和缓存指纹等信息，并可在索引重建、后台整理或空闲时批量折算为本地排序信号。这样既保留了“经常被访问的知识应更靠前”的自适应排序能力，又避免每次搜索都产生共享文件差异。

### 动态信号固化与协作边界

运行时动态信号的写入采用本地优先和可审阅固化两级边界。本地优先是指访问次数、命中次数、查询历史、缓存命中率、top topics、最近使用时间等短周期数据存入本机运行目录或用户级数据目录，并可采用 JSON 文件、轻量数据库或追加日志保存；写入时使用临时文件加重命名等原子写策略，防止进程中断造成半写入。可审阅固化是指系统只在满足明确条件时将动态信号转化为稳定知识层内容，例如将长期高频查询抽象为新的知识条目、将多次命中的主题写入人工确认的标签或摘要，或者将低价值条目归档为可展开的桩文件。

对于多人协作和多源检索场景，系统对共享知识源设置写保护。来自只读 source、远端 context tree、其他 provider 或团队共享目录的 Markdown 文件，只参与读取、索引和结果排序；其访问反馈记录在本地运行时信号层，并通过来源标识与具体知识条目绑定，不反向写入共享源文件。对于本地可写知识源，也可设置同步策略：默认不同步动态信号文件，或者仅同步经审阅的稳定摘要；派生摘要、概览、清单、归档全文等可通过 `.gitignore`、快照过滤或同步排除规则避免进入共享差异。

### 清理、归档与一致性维护

系统在知识整理、归档、删除、合并和摘要传播时，同步维护稳定知识层和运行时信号层的一致性。后台整理任务可以按变更文件集合执行相关文件合并、时间线更新、交叉引用补充、跨域综合和低价值条目归档；其中合并、删除、归档等破坏性操作先保留审阅备份或操作日志，再原子写入目标文件、删除源文件或生成归档桩。对被归档的条目，系统保留可检索的桩文件和指向完整归档内容的字段，使常规检索仍能发现该知识，但完整内容通过展开读取获得。

一致性维护包括三类规则。第一，文件级规则：当知识 Markdown 被删除、合并、移动或归档时，系统删除或迁移其动态信号记录，并同步删除对应的概览、摘要、抽象等派生兄弟文件，防止后续检索出现已删除知识的死引用。第二，索引级规则：索引缓存通过文件修改时间、来源清单、摘要文件和派生物状态判断是否失效，重建前清理或折算待处理命中，重建后只保留仍能映射到现存知识条目的信号。第三，日志级规则：查询日志按最大数量、最大保留时间和异常处理中断状态进行裁剪或修复，避免本地运行时信号无限膨胀。

在一种实现中，系统将动态信号层划分为访问命中表、查询日志表、来源映射表和失效队列表。访问命中表保存条目级热度和最近访问时间；查询日志表保存查询语句、命中文档、分数、耗时和状态；来源映射表保存本地或共享来源到稳定标识的映射；失效队列表记录因删除、合并、归档、摘要更新或来源清单变化产生的待清理键。清理任务按失效队列逐项处理，并在处理后重建必要的摘要、清单或索引缓存，从而保证读取融合使用的动态信号始终与当前可见知识集合一致。
