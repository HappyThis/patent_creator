## 技术方案

本方案将项目知识文件的协作属性与运行时动态信号解耦处理：Markdown 文件作为共享知识层，承载可审阅、可版本控制、适合多人协作的稳定知识正文、层级路径、标签、关键词、关联关系、摘要以及经确认的成熟度等低频元数据；访问次数、检索命中、近期使用、排序权重、衰减结果、清理候选原因等高频变化信息不再直接写入共享 Markdown，而是写入本机运行时信号层。系统在检索、展示、整理和清理时按需融合两层数据，形成仅在本机内存、索引或本地缓存中生效的融合视图，从而既保留动态信号对排序和生命周期管理的价值，又避免因每次查询或访问反复改写共享知识文件。

### 分层存储模型

共享知识层中的每个知识文件记为 $D_i$，其稳定标识可以由规范化相对路径、层级节点标识和内容摘要中的一种或多种组合得到。规范化相对路径用于保持人类可读的目录结构，层级节点标识用于表达 domain、topic、subtopic、entry 等知识树位置，内容摘要或版本指纹用于在文件改名、移动或合并后辅助识别同一知识对象。Markdown frontmatter 中保留标题、标签、关键词、关联关系、摘要、创建时间、人工确认的成熟度等协作所需字段；若需要记录重要度，也优先记录低频、经整理确认的基线值，而不是把每次访问形成的即时热度写入该文件。

本机运行时信号层以知识标识为主键保存覆盖数据 $O_i$，至少可以包括访问计数、最近访问时间、检索命中次数、命中查询摘要、排序用重要度增量、近期性得分、衰减基准时间、候选清理原因和本机确认状态。该层可以存放在项目本地的隐藏目录、用户本机缓存或工作区专用数据库中，并默认排除在共享同步和 Git 提交之外。对于外部 Markdown 文件夹或 Obsidian 类知识库，本方案同样以文件相对路径、索引签名和可选内容摘要建立关联，不要求第三方 Markdown 文件被系统写入动态评分字段。

### 运行时信号采集与本地聚合

系统把检索、结果展开、知识写入、知识合并、后台整理和清理评估抽象为运行时事件。一次查询命中某个知识文件时，仅在本机信号层追加或累加访问事件；知识被用户采纳、展开、引用或由整理任务更新时，记录相应的使用事件或整理事件；后台清理任务发现低重要度、长期未使用或内容重复时，记录候选事件和候选原因。事件写入可以采用追加日志、键值覆盖表或轻量数据库事务实现，先将高频事件缓存在内存中，再按时间窗口、数量阈值或进程退出前进行批量落盘。

- 事件记录可以包括事件类型 $event\_type$、知识对象标识 $object\_id$、发生时间 $timestamp$、动作来源 $action\_source$、查询摘要 $query\_digest$、命中得分 $hit\_score$、结果位次 $rank$、用户动作 $user\_action$ 和可选会话标识。事件类型至少可区分 query_hit、open、adopt、curate_update、prune_candidate、archive、restore、rename、split、merge 等，以便后续聚合器按不同权重处理。
- 对于检索类事件，$query\_digest$ 可以采用截断摘要或哈希摘要保存，避免把完整用户查询无差别写入共享知识层；对于整理类事件，$action\_source$ 用于区分人工确认、后台整理和自动清理评估，使成熟度调整、归档建议和低频固化可以依据来源设置不同可信度。

本机信号聚合器从事件中计算当前可用的动态字段。例如，访问命中事件使访问次数增加并提高本机重要度增量；整理更新事件提高更新次数并重置近期性；长时间未访问时，近期性按时间衰减，重要度增量按预定衰减因子降低；成熟度状态采用带滞回的阈值规则，避免知识条目在 draft、validated、core 等状态之间因短期访问波动频繁跳变。聚合结果只更新 $O_i$，不触发对 $D_i$ 的 Markdown 重写，因此查询频率越高，越能体现热度信号，同时不会制造 Git 脏状态或合并冲突。

### 读取融合与检索排序

读取知识时，系统先解析共享 Markdown 得到稳定文档对象 $D_i$，再根据 $D_i$ 的稳定标识查询本机覆盖数据 $O_i$，合成临时元数据 $F_i$。$F_i$ 中的正文、标题、标签、关键词、关联关系来自共享层；访问次数、近期性、排序权重、衰减后的重要度和本机成熟度修正来自运行时信号层；当两层存在同名字段时，以共享层作为协作基线，以本机层作为运行时覆盖值，并在融合视图中标注来源。该融合过程发生在索引构建、检索排序、概览展示或清理评估阶段，融合结果可以写入本机索引缓存，但不反向写入共享 Markdown。


在一种排序实现中，系统使用 [式(1)](formula:blk_000022) 计算基础得分，其中 $B_i$ 为文本相关性得分，$I_i$ 为由共享基线重要度与本机重要度增量融合后的重要度，$R_i$ 为本机近期性得分，$w_b$、$w_i$、$w_r$ 为可配置权重。基础得分再结合成熟度系数、来源优先级、最小成熟度过滤和分数差距过滤得到最终结果。对于层级知识树，子节点的文本相关性可以向父级 summary 节点传播，但父级的生命周期权重只在父级融合视图上应用一次，避免既在子节点得分中计算动态权重，又在父级传播时重复放大同一信号。

本机成熟度修正不直接覆盖共享层的人工确认成熟度，而是在融合视图中形成运行时可见的候选状态。例如，共享 Markdown 中某知识条目为 validated 时，本机长期高频命中可以使 $F_i$ 在本机排序中按 core 候选处理，但共享文件仍保持 validated；只有在低频固化流程中经人工确认后，才把该成熟度提升写回共享层。相反，若共享层已确认 core，本机短期未访问仅降低近期性和排序热度，不将共享基线降级，从而避免单机使用偏好破坏团队共识。

### 清理、归档与一致性维护

清理、归档和自动整理均基于融合视图而不是单独依赖共享 Markdown 的静态字段。系统先读取 $D_i$ 的成熟度、层级位置、关联关系和更新时间，再叠加 $O_i$ 中的近期访问、检索命中、重要度衰减、候选原因和本机使用状态，得到清理判定输入。core 类或人工确认的核心知识默认不进入自动删除流程；draft 类知识只有在重要度低、长期未被访问且缺少有效引用时才进入候选列表；validated 类知识可以采用更长的滞留周期或要求人工复核。归档时保留原始全文或可恢复指针，并生成可检索的摘要线索，使被清理知识仍可通过 drill-down 或恢复流程找回。

当共享知识文件发生删除、改名、移动、拆分或合并时，本机信号层通过一致性维护流程处理覆盖数据。索引器扫描 Markdown 文件并生成由相对路径、修改时间、文件大小和可选内容摘要组成的索引签名；签名变化时重建索引并尝试将旧标识下的 $O_i$ 迁移到新标识。若路径变化但内容摘要高度一致，则视为改名或移动并迁移动态信号；若多个文件合并，则按照访问次数求和、重要度取较高值、近期性取较新值、成熟度取较高等级的规则合并覆盖数据；若文件已删除且无法匹配新对象，则将对应覆盖数据标记为孤儿信号并在保留期后回收。该流程使共享层的结构变更与本机动态信号保持一致，同时不会阻塞正常检索。

对于文件拆分场景，系统先比较拆分前文件与拆分后各文件的标题、关键词、引用关系和内容片段相似度，再按相似度比例分配访问计数、近期性和重要度增量；无法稳定匹配的部分保留在原对象的孤儿信号中，等待后续人工确认或自动回收。若拆分操作由整理任务产生，整理任务可以输出旧片段到新文件的映射关系，信号层优先依据该映射迁移覆盖数据；若拆分由外部编辑造成且缺少映射，则仅迁移置信度最高的动态信号，避免把原文件全部热度错误赋给无关的新文件。

### 可选实施方式与边界

本机运行时信号层可以采用 JSONL 事件日志、SQLite、LevelDB 或项目本地键值文件实现；小型项目可以使用追加日志加周期性压缩，大型项目可以使用带事务的本地数据库。为避免并发写入造成覆盖丢失，信号写入可以采用单进程队列、文件锁或原子重命名策略；检索路径读取到旧信号时仍可使用共享 Markdown 完成基本检索，待下一次索引刷新后再应用最新覆盖值。因此，本方案在信号层不可用或损坏时可以退化为仅基于共享层的检索，不影响知识文件本身的可读性和可版本控制性。

在需要把本机经验反馈给团队共享知识库时，本方案不将每次访问形成的原始信号直接同步，而是设置低频固化机制：只有当知识成熟度提升、长期高频命中、长期无人使用、归档建议等结论满足阈值并经过人工确认，或在后台整理任务生成可审阅变更后，才把相应稳定结论写回 Markdown frontmatter 或生成 review 记录。多设备之间默认隔离本机信号；若需要跨设备统计，可以只同步脱敏后的聚合计数或按时间窗口汇总的热度摘要，并保留用户关闭该同步的配置项。
