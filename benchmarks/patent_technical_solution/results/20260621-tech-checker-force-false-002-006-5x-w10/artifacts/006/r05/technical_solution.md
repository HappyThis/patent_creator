## 技术方案

### 总体分层构思

本方案将项目知识管理划分为“共享 Markdown 知识层”和“本机动态信号层”两个相互关联但写入边界不同的层次。共享 Markdown 知识层用于承载经整理、审阅或适合团队协作的稳定知识内容，使其可以随项目仓库、版本控制、云端同步或只读知识源进行共享；本机动态信号层用于承载检索、访问、排序和清理过程中持续变化的运行时信号，使这些信号可以参与本机检索优化和知识生命周期管理，但默认不反复改写共享 Markdown 文件。

上述分层不是简单地丢弃评分字段，而是将知识内容和运行时反馈按稳定性拆分。Markdown 文件仍作为知识事实、关系和可审阅摘要的来源；访问命中、排序权重、成熟度推断、近期使用衰减等动态数据仍被保留，并在查询、排序、自动整理和清理时被读取使用。由此，系统既能维持知识文件的可共享性和版本控制友好性，又能利用本机历史行为提升检索质量。

### 共享 Markdown 知识层

共享 Markdown 知识层以项目上下文树中的 Markdown 文件为基本知识单元。每个知识单元包括标题、正文段落、事实、叙述性说明、代码片段引用、标签、关键词、关联路径、摘要、人工确认的理由或审阅信息等相对稳定内容，并可通过 YAML frontmatter 或约定章节保存适合团队共同理解和审阅的元数据。该层的文件保持普通文本形态，便于差异审查、分支合并、云端同步以及作为只读 source 被其他工作区引用。

对于成熟度等可能兼具团队共识和本机使用状态的属性，系统将其拆分为稳定属性和动态属性。经人工确认的知识等级、知识类型或审阅状态可以作为稳定属性写入 Markdown；由访问热度、近期检索命中、排序反馈或自动衰减计算得到的成熟度推断则写入本机动态信号层。查询结果展示时可以同时显示二者，但共享文件的版本差异仅反映稳定知识变化。

### 本机动态信号层

本机动态信号层保存与具体工作区、使用者或近期运行状态相关的可变信息，包括访问次数、检索命中次数、最近命中时间、近期使用热度、临时排序权重、衰减后的重要度、清理候选标记、摘要或索引缓存状态等。该层可以设置在项目本地的运行状态目录中，采用 SQLite、JSONL、键值文件或其他本地状态文件实现；无论采用何种载体，其写入对象均为本机状态记录，而不是团队共享的 Markdown 正文文件。

本机动态信号记录以知识单元标识为主键。知识单元标识可以由规范化相对路径、frontmatter 中的稳定标识、内容哈希、来源类型和来源别名组合形成；对于本地知识文件和共享只读 source 中的知识文件，标识中还包括 origin 或 originAlias，以避免不同来源中同名路径的信号相互覆盖。本机层还记录信号版本和最后校验时间，用于在索引重建或同步后判断信号是否仍与当前知识文件匹配。

| 字段示例 | 含义 | 用途 |
| --- | --- | --- |
| knowledgeId | 由规范化路径、稳定 id 或内容哈希形成的知识单元标识 | 作为动态信号与 Markdown 知识文件的关联主键 |
| originAlias | 知识来源别名或来源键 | 区分本地知识、共享 source 和不同外部知识源 |
| hitCount | 累计或窗口内检索命中次数 | 计算访问热度和排序反馈 |
| lastHitAt | 最近一次被检索或访问的时间 | 计算近期使用度和时间衰减 |
| decayScore | 经衰减函数处理后的热度或重要度分值 | 参与融合排序和清理候选判断 |
| signalVersion | 动态信号记录的结构版本 | 支持本机状态迁移和兼容性判断 |
| checksumAtLastSeen | 上次关联时的内容校验值 | 在文件同步、移动或覆盖后判断信号是否仍可复用 |

### 读取融合与排序计算

检索时，系统先从共享 Markdown 知识层读取稳定知识文件，解析标题、正文、标签、关键词、关联路径和摘要等内容，构建或更新基础文本索引；再根据知识单元的稳定标识从本机动态信号层读取对应信号，并在查询阶段进行内存级或索引级融合。基础相关度可以由 BM25 等文本匹配算法给出，动态信号则用于补充近期使用情况、重要度、成熟度、访问热度和衰减状态。

在一种实现中，融合评分可以表示为文本相关度、稳定重要度、近期使用度和成熟度因子的组合。文本相关度来自 Markdown 正文索引；稳定重要度来自人工确认的知识属性或默认初始值；近期使用度由本机动态层中的访问次数、最近命中时间和时间衰减计算得到；成熟度因子根据稳定成熟度和本机反馈成熟度共同确定。系统按照融合后的分数返回结果，但不因一次查询命中而更新 Markdown frontmatter。


其中，$S(q,k)$ 表示查询 $q$ 与知识单元 $k$ 的融合评分，$R(q,k)$ 表示文本相关度，$I(k)$ 表示稳定重要度，$U(k)$ 表示本机近期使用度，$M(k)$ 表示成熟度因子，$w_r$、$w_i$、$w_u$、$w_m$ 为可配置权重。上述公式中的 $U(k)$ 和由本机反馈得到的 $M(k)$ 来自本机动态信号层，因此其变化只影响本机排序结果，不触发共享 Markdown 文件重写。

为避免缺失动态信号导致新知识无法被检索，融合计算设置默认值和归一化边界。未建立本机记录的知识单元，其访问次数默认为 0，近期使用度采用预设基线或 0，成熟度优先采用共享 Markdown 中的稳定属性；各分项分值在参与加权前归一化到相同区间，时间衰减函数设置最小下限，避免长期未访问但文本强相关的知识被完全排除。当某一分项不存在时，系统可以跳过该分项并对剩余权重重新归一化。

### 写入边界与更新控制

本方案限定两类写入路径：稳定知识写入路径和动态信号写入路径。稳定知识写入路径由 curate、review、merge、update 或人工确认流程触发，写入对象为 Markdown 文件中的正文、标题、标签、关键词、关联关系、摘要以及团队共识类元数据；动态信号写入路径由 query、search、排序反馈、访问命中、清理扫描或后台摘要任务触发，写入对象为本机动态信号层。两类路径使用同一知识标识建立关联，但不共享同一物理写入目标。

动态信号更新采用增量、节流或批处理方式进行。检索命中时，系统先在内存中聚合本轮命中的知识标识和命中次数，再按时间窗口或批次写入本机动态信号层；后台任务可以周期性执行热度衰减、成熟度推断和清理候选更新。即使同一知识文件在短时间内被多次检索，也只会形成本机状态记录的合并更新，不会在共享 Markdown 文件中产生连续的访问计数差异。

对于并发查询或后台批处理场景，本机动态信号层采用幂等更新规则。每次更新以知识标识、事件类型和时间窗口形成去重键，对同一窗口内的重复命中进行合并；批量写入时先生成待提交增量，再通过事务或原子文件替换提交。提交失败时保留未提交增量并按退避策略重试，已提交的增量不会再次累加，从而避免并发访问导致访问次数膨胀或状态文件损坏。

### 清理一致性与共享源处理

当共享 Markdown 知识层中的文件发生删除、移动、重命名、同步覆盖或只读 source 变更时，本机动态信号层执行一致性维护。系统以规范化相对路径、frontmatter 中的稳定 id、内容哈希或其组合定位知识单元；当路径变化但 id 或内容哈希可匹配时，将动态信号迁移到新的知识标识；当目标知识已不存在且无法匹配时，将对应信号标记为孤儿记录并清理，避免检索结果和清理建议继续引用失效文件。

对于只读知识源或团队共享源，本方案在读取时允许将源文件纳入本机索引，并允许在本机动态信号层为其附加访问热度、排序权重和清理提示；但动态信号不得写回共享源文件本体。若共享源同步到新版本，本机层通过来源别名、源根路径、规范化相对路径和内容校验重新关联信号；无法关联的记录仅在本机清理，不对共享源执行写操作。

### 可选实施方式与边界条件

本机动态信号层的具体存储介质可以根据部署场景选择。单用户本地模式可以采用项目目录下的状态文件或键值文件；并发查询较多的模式可以采用 SQLite 或具备事务能力的轻量数据库；需要跨进程共享检索服务的模式可以采用本机服务管理的状态表。无论采用何种实现，均应满足按知识标识快速读取、批量更新、可清理孤儿记录以及不进入共享 Markdown 版本差异的要求。

派生摘要、概览文件、索引缓存和任务队列状态可按运行或派生产物处理。它们可以引用共享 Markdown 知识层中的稳定内容，也可以读取本机动态信号层中的热度或清理状态，但默认不作为新的共享知识事实进入版本控制。若团队需要共享某一摘要或成熟度判断，应通过人工确认或审阅流程将其转化为稳定知识内容后再写入 Markdown。
