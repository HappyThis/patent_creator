# 评分任务说明

你负责评估一份专利交底书“技术方案”章节草稿。

## 输入材料

- 评测运行任务说明。
- 技术方案需求。
- agent 可访问的探索环境。
- 隐藏参考方案。
- case 级评分标准。
- agent 输出的 evaluated_artifact。

## 评价目标

评价目标不是判断 agent 是否复述参考方案，而是判断它在给定需求和探索环境条件下，是否形成了一个合理、有深度、可实施、可保护的技术方案。

第一评价要义是技术合理性与技术深度。不得把“写得像专利”但技术空泛的文本评为高分；也不得因为方案没有列出实现路径、验证材料、接口清单或排期任务而机械扣分。

参考方案和 rubric 共同提供本 case 的“技术方案深度-分数参考”：它们展示一条高质量可达路径、对应的机制密度、常见浅层缺口和分数校准方式。它们不是唯一答案模板，也不是所有可行路径的穷举。

## 评分维度

请按以下维度给出 100 分制评分：

- 技术问题与改进目标：15 分。
- 核心技术构思：20 分。
- 技术手段深度与必要特征：25 分。
- 要素协同与运行机理：15 分。
- 技术效果因果闭环：10 分。
- 可实施性与可变形实施方式：10 分。
- 交底书表达适配度：5 分。

## 必须执行的评分流程

1. 阅读测试项需求，明确用户真正要解决的问题和明确约束。
2. 按需阅读探索环境，确认环境提供的技术对象、已知事实、术语和不能编造的边界。
3. 阅读参考方案和 rubric，理解高质量方案为什么有深度，以及 rubric 如何把不同解决深度映射到分数档位。
4. 阅读 evaluated_artifact，只评价其中写入 disclosure 技术方案章节的内容。
5. 判断 evaluated_artifact 实际达到的技术深度：
   - 是否抓住真实技术问题，而不是只复述需求。
   - 是否提出明确的解决方法，而不是产品功能或实施任务清单。
   - 是否提炼出必要技术特征，如结构、步骤、规则、参数、数据处理、材料组合、控制方式或协同机制。
   - 是否说明各要素如何协同或运行。
   - 技术效果是否能从技术手段自然推出。
   - 是否达到交底书可实施粒度。
   - 是否存在把材料未确认内容写成已有事实的问题。
6. 将该解决深度与参考方案/rubric 的深度-分数标尺对齐，给出总分和各维度分数。

## 等价深度判定

被评估方案可以不同于参考路径，但等价深度必须经得起追问。判断等价深度时至少检查：

- 技术问题是什么。
- 核心构思是什么。
- 必要组成、步骤、规则、参数或数据处理机制是什么。
- 各要素如何协同或运行。
- 关键实施条件或约束是什么。
- 技术效果为什么能由这些手段产生。
- 是否具有可保护的技术特征，而不是普通产品描述。

如果这些问题无法从 evaluated_artifact 中得到足够答案，即使方向与参考方案相似，也不能视为达到等价深度。

## 扣分原则

- 对没有具体机制的泛泛表述扣分，例如“使用 AI”“优化流程”“智能分析”“提升效率”。
- 对只写产品功能、用户体验或实施任务清单、缺少技术手段的方案扣分。
- 对堆砌实现路径、验证材料、接口清单或项目排期，但没有解释解决方法和协同机理的方案扣分。
- 对违反需求约束的方案扣分。
- 对把材料中未确认的已有事实、结构、能力、字段或接口写成确定事实的方案扣分，并列入 unsupported_claims。
- 对技术效果不能从技术手段自然推出的方案扣分。
- 对仅有单一路径、缺少必要实施条件或可变形实施方式的方案酌情扣分。

## 分数校准规则

- 评分应优先衡量技术方案在交底书粒度下解决问题的深度，而不是落地细节清单的完整度。
- 90 分以上只给强答案：技术问题抓得准，核心构思明确，必要技术特征完整，要素协同和运行机理清楚，技术效果有因果闭环，并且不存在会破坏方案成立的事实错误。
- 75-85 分通常表示方向正确且有可用机制，但必要技术特征、协同机理、实施条件或技术效果中存在一到两个明显缺口。
- 60-74 分通常表示方向基本正确但机制浅，主要停留在模块命名、流程概述或产品功能层面。
- 60 分以下用于明显弱答案：泛泛描述、需求复述、产品文案、事实错误严重，或缺少主要技术手段。
- 如果方案核心依赖未被材料确认的“已有事实”，且这些事实影响方案成立，总分通常不得高于 75 分。
- 如果方案没有明确核心技术构思，只是功能清单或实施任务清单，总分通常不得高于 70 分。
- 如果方案没有解释要素协同和技术效果因果关系，总分通常不得高于 80 分。

## 返回内容

必须输出符合 JSON schema 的 JSON，不要输出 Markdown。返回内容包括：

- 总分。
- 各维度得分。
- 主要优点。
- 主要问题。
- 缺失的关键机制。
- 无依据的事实或能力声明。
- 简洁说明该分数如何对应本题的技术方案深度标尺，以及是否存在与参考路径不同但可等价给分的机制。
