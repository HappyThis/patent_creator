# 隐藏参考方案

## 技术问题

知识管理系统使用 Markdown 文件保存可共享的项目知识，适合版本控制、审阅和团队协作。稳定语义字段可以随知识内容共同提交，但访问次数、检索命中、排序权重、成熟度、近期使用等运行时信号会在查询、整理、剪枝或自动维护过程中频繁变化。若这些动态信号继续写入 Markdown frontmatter，会造成大量无意义 diff 和合并冲突；若完全丢弃，又会削弱检索排序和知识维护效果。

因此，需要一种将共享知识内容与本机动态运行信号分离，同时在读取时融合使用的技术方案。

## 核心技术构思

方案建立“稳定语义 frontmatter、运行时信号 sidecar、路径键映射、原子更新、读取融合、写入剥离、迁移兼容和失败隔离”组合机制。Markdown 文件只保存标题、摘要、标签、关联关系等适合共享的语义字段；高频变化的动态信号写入本机 sidecar 存储。系统在检索、排序、知识树展示和自动整理时，同时读取 Markdown 语义内容和 sidecar 信号，并融合为完整知识对象。新写入路径不再把动态信号写回 Markdown，旧文件中的遗留动态字段可被兼容读取、懒迁移或按需初始化。

## 必要技术特征

1. 字段分层：区分稳定语义字段和运行时动态信号字段。
2. sidecar 存储：按知识文件建立旁路运行时信号记录，保存访问、重要性、成熟度、近期性、更新计数等动态信息。
3. 路径键映射：以知识文件相对路径或稳定知识标识定位 sidecar 记录，并支持批量读取。
4. 原子更新：对动态信号提供原子读改写、版本检查或单写队列，避免并发访问互相覆盖。
5. 读取融合：检索、排序、知识树和自动整理读取时，将 Markdown 语义字段与 sidecar 动态信号合并。
6. 写入剥离：知识写入器和自动整理流程只写稳定语义字段，不把高频动态信号写回共享文件。
7. 迁移兼容：旧 Markdown 文件仍可解析，遗留动态字段可按缺省值、懒初始化或迁移策略进入 sidecar。
8. 失败隔离：sidecar 读写失败时记录诊断并尽量 fail-open，不阻断知识内容保存和读取。
9. 清理一致性：归档、删除、剪枝、合并或重命名知识文件时，同步清理或迁移对应 sidecar 记录。

## 运行流程

知识写入时，系统将稳定语义字段写入 Markdown，并将动态信号写入或更新 sidecar。检索时，系统先读取 Markdown 内容和 frontmatter，再批量读取对应 sidecar 信号，融合后计算排序权重和成熟度。访问命中或自动整理需要更新动态信号时，只更新 sidecar，不改写 Markdown。迁移期遇到旧文件中已有动态字段时，系统仍能读取内容，并可将动态字段懒初始化到 sidecar。删除或归档知识文件时，系统同时处理 sidecar，避免孤儿信号影响后续排序。

## 技术效果

该方案减少共享 Markdown 文件的无意义改动和合并冲突，同时保留动态信号对检索、排序和自动整理的价值。字段分层使知识内容变化与本机使用痕迹分离；读取融合保证上层功能仍能获得完整知识对象；失败隔离避免 sidecar 故障破坏核心知识读写；清理一致性降低孤儿信号带来的排序污染。

## 高质量深度标尺

高分方案应说明哪些字段留在 Markdown，哪些进入 sidecar；sidecar 如何定位、批量读取和原子更新；检索排序如何融合两类数据；新写入和旧文件如何兼容迁移；sidecar 失败如何不阻断主流程；删除、归档、剪枝或合并时如何保持清理一致。只提出“把元数据放数据库”或“删除动态字段”的方案深度不足。

## 常见弱方案

- 直接丢弃动态信号，导致检索排序和整理能力下降。
- 将全部知识内容迁入私有数据库，破坏 Markdown 可共享性。
- 只改写入器，不处理检索、排序、整理和清理流程。
- sidecar 写入失败阻断知识保存。
- 没有路径映射、批量读取或并发更新机制。

## 等价机制说明

本参考方案不限定 sidecar 的具体存储形态。只要被评估方案能将共享语义内容与本机动态信号分层存储，并通过读取融合、原子更新、迁移兼容、失败隔离和清理一致性解决上述矛盾，即可视为等价深度方案。
