# 隐藏参考方案

## 技术问题

固定统计窗口在周期到期时一次性清空全部请求、成功和失败计数。两个发生时间非常接近的异常批次只因跨越窗口边界就可能被分别稀释；而窗口开始时发生的异常又会在整个周期中保持相同权重。这种不连续的遗忘方式使跳闸判断依赖绝对时间边界，而不是最近一段时间的真实请求结果。

把固定周期简单缩短会增加抖动并减少样本量；定时扫描所有请求记录会增加存储和计算成本。断路器还必须处理跨时间片完成的请求、状态切换造成的统计代际变化、半开请求上限、并发访问以及分布式共享状态，因而需要一种与现有状态机协同的增量滚动统计机制。

## 核心技术构思

方案把总统计时长划分为固定宽度的时间桶，以定长循环数组保存每个桶的请求、成功、失败和连续结果计数，并在窗口对象中同时维护所有有效桶的聚合计数。系统不依赖独立定时线程，而是在读取状态或处理请求时，根据当前时间计算逻辑桶年龄并按需推进窗口。每推进一个桶，只需从聚合计数中减去即将被覆盖的最老桶并清空该槽位；若一次跨越了整个窗口，则直接清空全部桶和聚合值。

请求获准时同时记录断路器统计代际和请求开始时的桶年龄。请求完成后，先检查状态切换是否已创建新代际：旧代际结果不得污染新状态；仍属当前代际的结果按照明确的跨桶规则写入统计。断路器的闭合、断开和半开转换沿用现有语义，但每次状态转换创建新代际并重置滚动统计。

为保持兼容，在未启用滚动粒度或总窗口只形成一个桶时，继续使用原有固定窗口清空行为。分布式断路器的共享状态除聚合计数和状态代际外，还需要保存当前桶年龄与各桶计数，使其他实例恢复后能够继续正确轮转，而不是仅复制一个失去时间位置的总计。

## 数学关系与变量定义

设用户配置的总统计时长为 \(I>0\)，单桶时长为 \(B>0\)。为了让窗口由完整时间桶组成，实际窗口时长向上取整到桶宽的整数倍：

\[
I'=\left\lceil\frac{I}{B}\right\rceil B
=\left\lfloor\frac{I+B-1}{B}\right\rfloor B
\]

桶数量为：

\[
N=\frac{I'}{B}
\]

离散时间实现中应保证 \(N\ge1\)，并避免 \(B\le0\)、除零和时长加法溢出。若未配置有效桶宽，则令 \(N=1\) 并退化为固定窗口。

设当前统计代际开始时间为 \(t_0\)，当前时间为 \(t\)，逻辑桶年龄为：

\[
a(t)=\max\!\left(0,\left\lfloor\frac{t-t_0}{B}\right\rfloor\right)
\]

年龄 \(a\) 对应的循环槽位为：

\[
j(a)=a\bmod N
\]

设第 \(j\) 个有效桶的计数向量为 \(C_j=(R_j,S_j,F_j)\)，分别表示请求、成功和失败数，则当前滚动聚合为：

\[
C(t)=\sum_{j\in W(t)}C_j
\]

窗口从年龄 \(a\) 推进到 \(a+1\) 时，槽位 \(j(a+1)\) 中保存的是即将过期的最老桶，故可增量更新：

\[
C_{new}=C_{old}-C_{j(a+1)},\qquad C_{j(a+1)}\leftarrow 0
\]

若新旧年龄差 \(\Delta a\ge N\)，说明旧桶全部过期，可直接令所有桶和聚合计数为 0。减法必须采用不下溢的安全语义，并分别处理连续成功和连续失败：只有连续序列确实完全落在被移除的桶中时，才能从聚合连续计数中扣除，否则应保留跨桶连续关系。

跳闸函数仍由调用方配置。例如以最近窗口失败率判断时：

\[
\rho(t)=\frac{F(t)}{R(t)},\qquad
\operatorname{trip}(t)=\bigl(R(t)\ge R_{min}\bigr)\land\bigl(\rho(t)\ge\theta\bigr)
\]

其中必须先保证 \(R(t)>0\)，并定义最小样本数 \(R_{min}\) 和阈值 \(\theta\)。滚动窗口负责提供时间语义正确的计数，不应把固定失败率写死在断路器内部。

## 必要技术特征

1. 配置兼容：增加时间桶粒度配置；无效或未配置粒度保持固定窗口，启用时把总时长向上调整为桶宽整数倍。
2. 桶与聚合双层状态：每个桶保存请求、成功、失败、连续成功和连续失败，窗口对象同时保存有效桶聚合，避免每次判断全量扫描。
3. 逻辑年龄和循环定位：以代际开始时间计算年龄，以年龄模桶数定位槽位，不依赖永久增长的数组。
4. 惰性推进：状态读取、请求进入或结果处理时按当前时间推进窗口，无需每个断路器常驻定时器。
5. 增量过期：逐桶推进时减去最老桶并清空；跨越整个窗口时一次清空，复杂度受桶数而非历史请求数限制。
6. 请求上下文：请求开始返回代际和桶年龄；结果回报携带二者，避免跨状态代际或跨桶完成时写错统计。
7. 状态机协同：闭合状态用滚动计数执行跳闸判断；断开超时进入半开；半开失败回到断开，达到允许探测请求的连续成功条件后闭合；状态切换清空计数并增加代际。
8. 两阶段接口：先允许请求、后回调结果的接口与包裹执行接口使用相同的代际和年龄校验。
9. 并发保护：状态、代际、窗口推进和计数更新位于同一互斥边界，回调和外部存储操作不能破坏内部一致性。
10. 分布式状态：共享结构保存状态、代际、过期时间、当前年龄、聚合计数和桶数组；注入和提取时进行完整复制并校验桶数量与配置。

## 运行流程

创建断路器时，系统校验总时长和桶宽，计算调整后的窗口时长及桶数，分配循环桶，并进入新的闭合代际。若未启用滚动模式，则保留单桶及原固定窗口到期清空路径。

请求到来时，断路器获取互斥锁，根据当前时间检查状态。在闭合状态下，若启用多桶窗口，则计算年龄并推进所有已经跨过的桶；在断开状态下，超时后切换到半开。若当前状态允许请求，系统增加请求总计和当前桶请求数，并把当前代际与年龄随本次执行返回。

请求完成时再次取得锁并刷新状态。若代际已变化，说明该结果属于旧状态，不再计入新代际。否则按请求开始年龄和当前窗口位置记录成功或失败；成功和失败同时更新聚合与仍有效的对应桶，并维护连续结果计数。闭合状态中的失败触发调用方跳闸函数；半开状态失败立即断开，连续成功达到探测上限后恢复闭合。

分布式断路器从共享存储读取时，把年龄、桶数组和聚合值一并恢复，再根据本地当前时间继续推进；写回时保存同一组状态。实例不能只共享聚合 Counts，否则无法知道下一次应淘汰哪个时间段。

## 异常与边界

- 总时长非正时保持“不在闭合状态周期清空”的既有语义；桶宽非正时不启用滚动模式。
- 桶宽大于总时长时，调整后形成一个桶，行为等价于固定窗口。
- 系统时间早于代际开始时间时年龄按 0 处理，避免无符号下溢。
- 长时间无请求后第一次访问若跨越至少 \(N\) 个桶，直接清空而不是循环处理无限历史。
- 迟到结果若所属代际已失效则丢弃；若仍在同一代际但原桶已过期，应采用一致的迟到结果规则，不能让桶总和、聚合计数或连续计数下溢。
- 分布式恢复时桶数组长度不匹配必须拒绝、重建或按版本迁移，不能直接按错误模数轮转。

## 验证方式

应使用可控时钟构造桶边界前后请求，验证数据逐桶过期而非整体清空；验证跨越一桶、多个桶和整个窗口时的聚合值；验证总时长不能整除桶宽时的向上取整；验证未配置桶宽和单桶时与旧行为一致。

状态机测试应覆盖闭合失败率跳闸、断开超时进入半开、半开失败再次断开、足够连续成功恢复闭合，以及旧代际异步结果不污染新状态。还应覆盖并发请求、两阶段回调、负时长、时间倒退和分布式状态保存恢复。

## 技术效果

时间桶逐步过期使统计结果随时间连续变化，降低固定边界对跳闸判断的影响。循环桶和增量聚合使内存固定为 \(O(N)\)，常规单桶推进为 \(O(1)\)，不需要保存每条请求历史。代际和请求年龄把异步完成与状态转换隔离；完整共享桶状态使多个实例能在同一时间语义上延续统计。单桶退化路径则保证新增能力不破坏原有用户。

## 高质量深度标尺

高分方案应同时说明窗口如何对齐桶宽、年龄如何映射循环槽位、最老桶如何从聚合中移除、跨越整窗为何可直接清空、请求为何要携带代际和开始年龄，以及滚动统计如何与三个断路器状态和共享状态协同。只写“使用滑动窗口统计最近失败率”而没有桶状态、轮转、跨边界结果和兼容路径，不能达到等价深度。

## 常见弱方案

- 仅缩短固定周期，仍在边界一次性清空全部计数。
- 保存全部请求时间戳并每次全量扫描，没有固定空间和增量统计机制。
- 只维护聚合总计，不保存桶年龄和桶内容，无法知道应淘汰哪些数据。
- 用物理数组下标代替逻辑年龄，循环覆盖后无法判断槽位属于哪个时间段。
- 请求完成时总写入当前桶，未处理请求开始后跨桶或状态代际变化。
- 状态转换后仍接受旧代际结果，污染半开或新闭合状态。
- 分布式共享只复制总计，不复制年龄和桶数组。
- 失败率公式未处理零请求、最小样本数或统计单位。

## 等价机制说明

本参考方案不限定循环数组、链表或其他有界时间桶容器，也不要求固定的跳闸阈值。使用单调时钟、时间轮、分段队列或按需合并桶均可，只要具有有界状态、渐进过期、可判定的时间映射、代际隔离、固定窗口兼容和可恢复的共享状态，即可视为等价方案。
