# 前端交互规范

## 文档定位

本文档定义 Web 前端三栏界面的交互方式。

产品形态为：

1. `目录区域`
2. `渲染区`
3. `Agent Chat 区`

相关文档：

- [API 设计规范](api-design.md)
- [render_ast Schema](render-ast-schema.md)
- [Agent 基本设计原则](../core/agent-principles.md)

## 目标

前端交互需要让用户完成三件事：

1. 看清交底书结构
2. 看清当前文稿内容和修改结果
3. 看清 agent 的执行过程，而不是只看最终一句回复

## 一、总体原则

### 1. 目录区域只负责导航

目录区域用于：

- 展示交底书目录树
- 高亮当前聚焦章节
- 标记最近修改章节

目录区域不承担正文编辑功能。

### 2. 渲染区只负责预览

渲染区用于展示当前交底书的 `render_ast`。

它应支持：

- 整篇预览
- 章节定位
- 最近修改位置高亮

渲染区不提供正文手动编辑器。

### 3. Agent Chat 区同时承担“对话”和“执行轨迹”

Agent Chat 区不应只是普通聊天窗口。

它还应展示：

- 主 agent 当前回复
- 子 agent 启动过程
- tool 调用过程
- 等待状态
- 返回结果

也就是说，用户在 Chat 区里应能看见 agent “做了什么”，而不仅是“最后说了什么”。

## 二、三栏交互规则

## 1. 目录区域

目录区域至少支持以下行为：

1. 点击章节
2. 高亮当前章节
3. 高亮最近修改章节

点击章节后：

- 不触发 agent 请求
- 只触发前端定位
- 渲染区滚动到对应 `anchor`
- Chat 区保留当前对话上下文

## 2. 渲染区

渲染区至少支持以下行为：

1. 渲染整篇 `render_ast`
2. 根据目录点击滚动到目标章节
3. 根据本轮改动自动滚动到最近修改章节
4. 对最近修改章节做短暂高亮

建议规则：

- 文档没有真正修改前，不要频繁重绘整页
- 收到文档变更事件后再刷新

## 3. Agent Chat 区

Agent Chat 区至少支持以下能力：

1. 用户发送文本消息
2. 用户在消息文本中附带参考资料
   - URL
   - 绝对路径
   - 粘贴文本
3. 展示主 agent 的自然语言输出
4. 展示执行过程
5. 展示回合完成状态
6. 运行中取消当前 round
7. 切换历史 session 或新建 session
8. 展示当前 session 的上下文用量
9. 导出当前交底书 Markdown

## 三、执行轨迹展示规则

这是关键交互规则。

Agent Chat 区需要把执行过程展示为一系列“过程节点”。

这些节点至少包括：

1. 主 agent 输出
2. 启动子 agent
3. 调用工具
4. 等待结果
5. 收到结果
6. 文档已修改
7. 回合完成

### 1. 子 agent 启动时

应展示一条过程节点，例如：

- `已启动 solution_refiner`
- `已启动 section_writer`

### 2. tool 调用时

应展示一条过程节点，例如：

- `调用 document_read`
- `调用 document_edit`
- `调用 exec_command`
- `调用 execute_subagent`

### 3. 等待结果时

应展示等待状态。

例如：

- loading 样式
- 旋转图标
- “等待返回结果”

### 4. 收到结果后

等待状态应结束，并展示“已完成”状态。

例如：

- `document_read 已返回`
- `document_edit 已完成`
- `section_writer 已完成`

### 5. 结果详情的折叠与展开

收到结果后，过程节点应默认折叠显示摘要。

用户可以展开查看详细结果。

例如：

- 默认显示：`section_writer 已完成`
- 展开后显示：
  - tool 返回内容
  - 子 agent 返回结果
  - 错误信息
  - 结果摘要

### 6. 为什么要折叠

因为：

- 过程信息很重要
- 但全部展开会让 Chat 区过于嘈杂

因此建议默认策略为：

- 进行中：展开显示状态
- 已完成：默认折叠
- 用户可手动展开查看详细结果

## 四、SSE 事件与前端行为映射

### 0. `assistant_delta`

用途：

- 展示模型正在生成的自然语言回复

前端行为：

- 累加到当前 assistant 流式消息中
- 等 `round_finished`、`round_failed` 或 `round_cancelled` 到达后，以最终 reply 收束当前流式消息

### 1. `tool_call_started`

用途：

- 表示某个工具或子 agent 已开始执行

前端行为：

- 在 Chat 区追加一条执行节点
- 节点处于进行中状态

### 2. `tool_call_finished`

用途：

- 表示某个工具或子 agent 已返回结果

前端行为：

- 更新对应执行节点状态为已完成
- 默认折叠结果摘要
- 允许用户展开查看详细结果

### 3. `document_changed`

用途：

- 表示文档已发生修改

前端行为：

- 刷新目录区
- 刷新渲染区
- 定位最近修改章节
- 高亮最近修改章节或 block

事件数据至少包含：

```json
{
  "changed": true,
  "changed_section_ids": ["sec_000007"],
  "changed_block_ids": ["blk_000014"],
  "active_section_id": "sec_000007",
  "active_block_id": "blk_000014"
}
```

### 4. `round_finished`

用途：

- 表示本轮用户请求已处理完成
- 携带本轮最终回复、文档变更信息和版本提交状态

前端行为：

- 结束回合加载状态
- 显示本轮最终回复
- 如有 commit，展示轻量提示
- 如 `commit_error` 非空，展示“文档已修改但版本提交失败”的轻量状态

### 5. `round_failed`

用途：

- 表示本轮请求已被接受，但执行过程中失败。

前端行为：

- 关闭当前 SSE 流
- 结束运行中状态
- 显示失败回复或兜底失败提示
- 刷新 project 状态

### 6. `round_cancelled`

用途：

- 表示用户取消了当前运行中的 round。

前端行为：

- 关闭当前 SSE 流
- 结束运行中和取消中状态
- 以最终取消提示收束当前 assistant 消息
- 刷新 project 与 session 列表

### 7. `stream_attached` / `stream_closed`

用途：

- 页面刷新、重新进入或运行中重建连接时，恢复订阅当前 session 的 SSE。

前端行为：

- `stream_attached`：记录当前 `round_id`，继续消费后续 SSE 事件。
- `stream_closed`：关闭本地流并刷新 project 状态。

## 五、必要交互细节

### 目录区域

- 支持点击章节定位
- 支持最近修改章节高亮
- 支持当前章节高亮

### 渲染区

- 支持整篇预览
- 支持 anchor 滚动
- 支持最近修改章节或 block 自动定位
- 支持最近修改章节或 block 短暂高亮

### Agent Chat 区

- 支持普通聊天消息
- 支持执行轨迹节点
- 支持等待状态
- 支持运行中取消当前 round
- 支持结果折叠/展开
- 支持一轮完成后的状态收束
- 支持历史 session 菜单和新建 session
- 支持上下文用量展示
- 支持导出 Markdown

## 六、不支持范围

前端不支持：

- 渲染区手动编辑正文
- 目录区域拖拽重排
- Chat 区多会话并行切换
- block 级 diff 视图

## 七、设计结论

前端不是“目录 + 文稿 + 聊天”这么简单。

更准确地说，它是：

1. `目录导航`
2. `文稿预览`
3. `对话 + 执行轨迹`

其中，Agent Chat 区必须明确展示：

- 启动了哪个子 agent
- 调用了哪个 tool
- 当前是否在等待结果
- 收到结果后如何折叠展示
- 用户如何展开查看结果详情
