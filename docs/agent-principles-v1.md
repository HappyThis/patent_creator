# Agent 基本设计原则 v1

## 文档定位

本文档定义 agent 系统的总体架构与职责边界。

阅读前建议先了解交底书文档结构：

- [专利交底书结构方案 v1](/Users/yangchaoqun/myProj/patent_creator/docs/patent-disclosure-structure-v1.md)

相关文档：

- [Agent Prompt 与上下文规范 v1](/Users/yangchaoqun/myProj/patent_creator/docs/agent-prompt-context-spec-v1.md)

## 目标

本文档用于明确本项目中 agent 系统的基础设计原则。

这些原则用于约束：

- 主 agent 的职责边界
- 子 agent 的职责边界
- 上下文管理方式
- 文档读取与修改方式
- session 日志的作用

本文档不讨论具体有哪些子 agent，只讨论整体架构原则。

## 一、总体架构

本项目采用如下基础架构：

- `主 agent`
- `子 agent`
- `上下文管理器`
- `执行器`
- `当前交底书文档`
- `session 事件日志`

其中：

- 主 agent 负责决策
- 子 agent 负责执行局部任务
- 上下文管理器负责上下文装配与维护
- 执行器负责真正执行工具调用、子 agent 调用和落盘动作
- 当前交底书文档是真正的文档内容
- session 事件日志负责记录过程

## 二、主 agent 的职责

主 agent 只负责决策，不负责状态管理。

主 agent 的职责包括：

1. 理解用户当前请求
2. 决定下一步需要调用什么能力
3. 决定是否需要读取某些章节或子章节
4. 决定是否需要调用某个子 agent
5. 向子 agent 下发具体任务
6. 判断子 agent 返回结果是否可采纳
7. 决定是否继续调用其他能力或反馈给用户

主 agent 不负责：

- 加载交底书文档
- 加载 session 事件日志
- 管理运行时上下文
- 维护上下文压缩结果
- 记录事件日志
- 保存文档状态

## 三、子 agent 的职责

子 agent 只负责执行明确、局部的任务。

子 agent 的职责包括：

1. 接收主 agent 分配的具体任务
2. 基于提供的最小上下文完成任务
3. 返回结构化结果
4. 必要时返回修改说明、候选内容或 patch

子 agent 不负责：

- 决定全局流程
- 决定是否落盘
- 自行管理上下文
- 自行调用其他子 agent
- 直接承担用户交互职责

## 四、上下文管理器的职责

上下文管理器是系统代码逻辑的一部分，不是 agent。

上下文管理器负责：

1. 加载当前交底书文档
2. 加载当前 session 事件日志
3. 将读取结果、执行结果组织进本轮上下文
4. 维护本轮运行时上下文
5. 在需要时进行上下文压缩

换句话说：

- agent 负责决定“要不要读”
- 执行器负责真正去读
- 上下文管理器负责把读取结果放进上下文

同理：

- agent 负责决定“要不要改”
- 执行器负责真正执行修改
- 上下文管理器负责把修改结果放进上下文

## 五、执行器的职责

执行器是系统代码逻辑的一部分，不是 agent。

执行器负责：

1. 执行具体工具调用
2. 执行对子 agent 的同步调用
3. 执行文件读取与文件修改
4. 执行 git 相关版本操作
5. 将执行结果返回给上下文管理器和主流程

换句话说：

- agent 负责决定“调用什么”
- 执行器负责真正“去执行”
- 上下文管理器负责“把执行结果纳入上下文”

## 六、当前交底书文档与 session 日志

系统中有两类核心持久化对象：

1. `当前交底书文档`
2. `session 事件日志`

### 当前交底书文档

当前交底书文档就是磁盘上的真实文档内容。

它负责表达：

- 当前交底书有哪些章节
- 每个章节当前的内容是什么
- 子章节、段落、列表、图片、表格等文档本体内容

它不负责表达：

- agent 的推理过程
- 审查意见
- 待确认问题
- 任务调度信息

交底书文档的历史版本建议通过 `git` 管理。

也就是说：

- 当前文件表达“现在的正文是什么”
- 历史版本、差异与回退能力交给 `git`

### Session 事件日志

session 事件日志不是普通聊天记录，而是结构化事件流。

它负责记录：

- 用户输入
- 主 agent 的决策
- 子 agent 的调用
- 子 agent 的返回结果
- 文档修改动作
- 上下文摘要或压缩结果

它的作用包括：

- 重建 session 过程
- 重建历史 UI
- 追踪某次决策路径

它不用于恢复当前文档正文，因为当前文档正文直接以文件形式存在。

## 七、上下文中默认不注入完整交底书

本项目的重要原则是：

**完整交底书默认不进入上下文。**

原因：

1. 全文注入成本高
2. 容易引入无关噪音
3. 不利于局部修改和局部写作
4. 不适合主 agent 与子 agent 的协同模式

因此，默认上下文只注入最小必要信息。

## 八、默认上下文内容

默认情况下，可以注入以下信息：

1. 交底书目录
2. 当前用户任务
3. 最近少量修改摘要
4. 当前 session 中与本轮任务强相关的少量上下文

这里的“交底书目录”指：

- 有哪些一级章节
- 某些章节下有哪些子章节

而不是整篇正文内容。

关于 agent 提示词和上下文的更细粒度组成，另见：

- [agent-prompt-context-spec-v1.md](/Users/yangchaoqun/myProj/patent_creator/docs/agent-prompt-context-spec-v1.md)

## 九、正文内容按需读取

正文内容采用按需读取策略。

也就是说：

- agent 默认只看目录
- 需要具体内容时，再读取具体章节或子章节

例如：

- 要写“技术方案”，则读取 `technical_solution`
- 要确认流程描述，则读取 `processing_flow`
- 要检查某张附图说明，则读取 `drawings.figure_1`

这个原则同时适用于主 agent 和子 agent。

## 十、修改后的处理原则

每次修改发生后：

1. 修改动作会进入当前上下文
2. 修改动作会记录到 session 日志
3. 如有必要，可重新读取目标章节进行确认
4. 正文历史版本通过 `git` 进行版本管理

因此：

- 上下文中不需要常驻完整交底书
- 只需要在必要时回读目标章节确认结果

## 十一、辅助信息不进入交底书文档

以下内容不属于交底书文档结构：

- 审查意见
- 待确认问题
- agent 假设
- 术语约束
- 子 agent 临时结果
- patch 候选

这些内容属于：

- 当前 session 的运行时上下文
- 或 session 日志中的事件内容

它们不应污染交底书文档本体。

## 十二、同步子 agent 调用原则

v1 先采用同步子 agent 调用模型。

也就是说：

1. 主 agent 决定调用某个子 agent
2. 上下文管理器执行调用
3. 子 agent 返回结果
4. 主 agent 决定是否采纳

第一版先不引入异步调度复杂度。

## 十三、最终原则总结

本项目的 agent 基础原则如下：

1. 主 agent 只负责决策，不负责上下文管理
2. 子 agent 只负责执行局部任务
3. 上下文由上下文管理器负责装配和维护
4. 执行器负责真正的工具调用、子 agent 调用与文件修改
5. 当前交底书文档是真正的文档内容真相源
6. session 事件日志负责记录过程，而不是保存正文真相
7. 正文历史版本通过 `git` 管理
8. 默认上下文只注入目录和最小必要信息
9. 正文内容按需读取，不默认注入全文
10. 修改后只在必要时回读目标章节确认
11. 辅助信息属于 session 运行态或事件日志，不属于交底书文档
12. v1 先采用同步子 agent 模型

这套原则构成了本项目 agent 设计的基础约束。
